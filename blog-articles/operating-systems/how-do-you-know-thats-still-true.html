How do you know that's still true?

An operating system's network stack is mostly not a pipe. It is a filing cabinet of answers to questions asked earlier — where a neighbour is, how big a packet fits, what a name means, whether a flow was seen before — and every one of those answers can be quietly overtaken by events. This is a catalogue of what the stack remembers, and of the six ways it can find out that it was wrong.

1The question

An operating system's network stack looks, from the outside, like a pipe. Bytes go in at a socket and come out on a wire. Almost nothing about that description survives contact with the code. The stack is not mostly a pipe; it is mostly a filing cabinet. A single packet leaving a laptop consults, in order, a socket's four-tuple, a congestion window, a round-trip estimate, a routing table, a set of policy rules, a firewall ruleset, a connection-tracking entry, a neighbour cache, an interface MTU and a list of things the network card has promised it can do. Exactly one of those is computed from the packet. The rest are answers to questions asked earlier and written down.

That is not an accident or a wart. It is the design. Asking again is expensive: a name lookup costs a round trip to a server, address resolution costs a broadcast to every machine on the segment, and measuring a path costs the time it takes to be wrong about it once. So the stack remembers. And because it remembers, every one of those stored answers has the same latent defect: the world it describes can change without telling it.

This article reads the operating system's networking machinery as a catalogue of remembered facts, and asks one question of each: how do you know that is still true? The answers turn out to be surprisingly few in kind, and they order themselves. Some answers are not remembered at all, and so cannot be stale. Some are confirmed by the next exchange with the very party they describe. Some are bounded by a timer. Some wait for an external event that may never arrive. Some wait for a person. And some have no mechanism at all, so that the host stays confidently wrong until something entirely different breaks.

Six answers, one ladder. Placing thirty-eight pieces of retained state on it produces the map in this article, and two results that are not obvious in advance. The first is that the same table entry can sit at the top of the ladder and at the bottom depending only on whether anyone happens to be talking. The second concerns who chooses the numbers. Where a bound exists at all, it is a timer, and in a default configuration the host sets roughly half of those timers itself and inherits the rest. The ones it sets for itself have a median of 120 seconds. The ones set for it by somebody else have a median of 7,440 seconds, 62 times longer. The party that chooses how long the lie may run is usually not the party that will be standing in it.

The scope here is the host stack as an operating system provides it: interfaces, addressing, neighbour discovery, routing, transport, sockets, names, configuration, filtering, namespaces, virtual interfaces and tunnels. Router internals, switching silicon and control-plane protocols appear only where a host depends on them. The examples lean on Linux because its defaults are published and its documentation is specific, and on the standards that every stack implements, because the numbers in them are the ones everybody inherited.

2A short history of not asking again

The first internetwork did not cache anything, because it barely had anything to cache. The 1974 protocol that defined the approach put addressing, sequencing and flow control in one specification and assumed a small number of cooperating hosts that knew about each other1. The split into a datagram layer and a transport layer came later, and with it the first pieces of state that could go out of date: a host now had to decide where to send a packet before it knew whether the destination existed.

The transition that made this concrete happened on 1 January 1983, when the ARPANET cut over from its original host protocol to TCP and IP on a single announced date. The transition plan is worth reading as an artefact of a network small enough to be rebooted2. Nothing that size has been possible since, and the reason is exactly the subject of this article: once a fact about the network is written down in thousands of places, there is no moment at which all the copies can be corrected.

It is worth naming the priority list that produced this shape, because the authors wrote it down. Survivability came first, support for several types of service second, accommodation of a variety of networks third; accountability came last, and a footnote in the same paper observes that a design ordered differently would have looked very different3. A stack that must keep working while pieces of it disappear is a stack that must be able to act on incomplete and possibly outdated information, which is a design decision and not an oversight. The direction of travel was set early: reverse address resolution, which let a machine ask the network who it was, arrived in 1984 and was already a cache with a server behind it4. When the address space ran short a decade later, the recommendation that produced IPv6 explicitly kept the model and changed the numbers5.

The caches arrived one at a time, each solving a real cost. Address resolution, in 1982, replaced a static table mapping protocol addresses to hardware addresses with a broadcast question and a remembered answer6. Ethernet had made broadcasting cheap and made the number of machines on a segment large, and those two facts together turned a configuration file into a cache7. The domain name system, in 1983 and then properly in 1987, did the same thing to the hand-maintained host table that the network had outgrown8,9,10. Its designers were explicit that caching was the mechanism that made a distributed database affordable, and that the time to live was the knob that made caching safe11.

Configuration followed. The bootstrap protocol let a diskless machine learn its own address from a server, and the dynamic host configuration protocol that grew out of it added the crucial idea that the grant is temporary: not an address, but a lease, with a clock12,13,14. That is the pattern in its purest form, and everything later in this article is a variation on it.

Meanwhile the transport layer was learning to remember things about the path. Congestion collapse in 1986 produced, two years later, the set of algorithms that made a sender maintain an estimate of what the network could take and update it from evidence15. The round-trip estimator picked up a rule about which samples to believe16. Path MTU discovery, in 1990, added a per-destination cache of the largest packet that had been observed to survive17. Each of these is a measurement of something nobody owns, kept because measuring it again costs a round trip.

The operating system's own structures moved in parallel. Berkeley's networking work gave the field the socket as a programming abstraction and, with it, the idea that a conversation is a kernel object with a lifetime18,19. Packet capture got a virtual machine in the kernel so that filters could run without copying every packet to userspace20. Interrupt-driven reception got a polling mode after it was shown that a machine could be driven into a state where it received packets at full rate and delivered none21,22. Stateful filtering arrived as a product of the same decade that gave the network address translator, and for the same reason: the address space had run out and the fiction of end-to-end reachability was being maintained by boxes with tables in them23,24.

Two more layers of memory arrived recently enough to still feel new. Network namespaces, merged in the late 2000s, made every table described in this article plural: one routing table per namespace, one neighbour cache, one set of rules25. And the modern tunnel made a quiet correction to a very old pattern. Where address resolution learns a peer's location from an unauthenticated broadcast, a cryptographic tunnel learns it from the source address of the last packet that decrypted correctly, which makes the location a consequence of a check the design already performs26. That is the whole of the difference between the top of the ladder and the middle, and it took about thirty-five years.

3What the stack keeps, and where

Start with the inventory. A conventional host stack keeps, at minimum: per-socket state, per-connection transport state, a forwarding table and a set of rules selecting between tables, a neighbour cache per interface, a path MTU cache, an interface configuration including addresses and an MTU, a set of feature flags describing what the hardware will do, and, if the machine filters, a ruleset and a connection-tracking table. Containers multiply all of it. Tunnels add security associations and peer endpoints.

The useful thing about laying it out this way is that the layering stops being about headers and starts being about ownership. Some of these facts are about the host itself and nobody else can contradict them: which port a socket holds, which namespace an interface is in. Some are about the other endpoint of a conversation, and the other endpoint is right there and can be asked. Some are about the path, which is not a party at all and cannot be asked anything. And some are about a third party — a server, a router, an operator — who knows the truth, has no obligation to tell this host when it changes, and in several important cases has no way to.

The physical layer is where the exception lives. An Ethernet frame carries a 32-bit cyclic redundancy check computed over its own contents, and the receiver recomputes it from scratch27. Nothing is kept between frames. This is the one place in the stack where the question does not arise, and the price is that the check has no memory either: a frame that passes says nothing about the next one.

It is worth being precise about what the checksums in a packet can and cannot see, because the article's whole argument turns on the difference between recomputing and remembering. A frame carries a CRC; an IP header and a TCP or UDP segment carry a one's-complement sum of 16-bit words28. These are not the same kind of object. Running both over four thousand synthetic headers gives the separation cleanly: permuting the 16-bit words of a header changes the CRC in 100% of cases and changes the internet checksum in 0%. Moving a value up in one word and down by the same amount in another, where neither wraps, is undetected in every one of 4,000 trials. Every single-bit flip, across 160,000 of them, is caught. The sum is exactly as good as its arithmetic: blind to the ordering of the fields it protects, and blind to compensating errors, because addition is commutative and associative and does not care28,29.

That matters operationally because the two checks are computed by different parties. The link CRC is generated and verified hop by hop, usually in silicon. The transport checksum is end to end, and on modern hardware the operating system frequently does not compute it either: it sets a flag, hands the packet down, and trusts the card. Measured against real traffic, the two disagree often enough to matter, at rates once estimated between one in 1,100 and one in 32,000 packets failing the end-to-end check30. The end-to-end argument survives that finding intact — the transport check is the only one that covers the whole path, including the memory the packet sat in — but the offload flag is itself a remembered promise, and it sits low on the ladder31,32.

There is a growing category of software that responds to all this by leaving the stack out. A program can attach code at the driver's receive path and make a verdict before any of the kernel's tables are consulted, or map the card's rings into userspace and consult nothing at all33,34. Both approaches are fast for the same reason: they skip the lookups. Both then have to rebuild whichever pieces of remembered state they actually needed, in userspace, with the same staleness problem and usually less documentation about the defaults.

None of this inventory is obscure. It is documented at length in the standard implementation literature — the Berkeley lineage in one pair of volumes, the current Berkeley-derived kernel in another, the Linux structures in two more — and the socket interface itself has been a formal standard for decades35,36,37,38,39,40. What that literature organises by layer, this article organises by ownership, and the reorganisation is the only novelty on offer here. A related shift shows up in how applications wait: the move from scanning a set of descriptors to registering interest once and being told what changed was itself a recognition that keeping a list is cheaper than rebuilding one, with the same consequence that the list can be wrong41.

Finally, a note on how these tables are changed, because it decides the shape of several plates below. On Linux the kernel does not discover routes, leases or associations. Userspace does, and writes the result in over a netlink socket42,43. The kernel's forwarding table is therefore a cache with no expiry policy of its own; all the freshness lives in a daemon. That split is what makes it possible to say, precisely, which of the host's beliefs are maintained by the host and which are maintained on its behalf.

4Who is next door

Everything above the link layer depends on one primitive: turning an address into a place to put a frame. On a broadcast segment that means asking, and the asking is unauthenticated. Address resolution sends a question to everyone and believes the first answer, and the protocol has no way to distinguish the machine that owns an address from one that would like to6,54. What saves it in practice is not the protocol but the cache management around it.

Linux does not simply time address-resolution entries out. It runs them through a reachability state machine with named states, and — this is the part that lifts the entry two rungs — it accepts confirmation from above. When a transport connection makes forward progress, that is evidence the neighbour is where the cache says it is, and no packet needs to be sent to establish it. IPv6 wrote this into the specification rather than leaving it to implementations, with a documented reachable time of thirty seconds and a defined sequence of probes before an entry is declared failed55,56,57.

The comparison with the layer below is instructive. A learning bridge builds its forwarding table purely from the source addresses of frames it happens to see, corrects it purely by seeing the same address somewhere else, and bounds it with an ageing timer whose default has been five minutes for decades58,59. A host that moves and then speaks is found immediately. A host that moves and stays silent is unreachable for up to the ageing time, and nothing anywhere reports that fact. Wireless association, by contrast, sits higher than either, because 802.11 acknowledges every unicast frame individually: the medium was unreliable enough that per-frame confirmation was unavoidable, and continuous revalidation came along with it47. The current amendment, published in July 2025 after board approval the previous autumn, spends its complexity on throughput and on operating several links at once rather than on the association state itself, which has not needed it48,49. The successor amendment, still in draft and aimed at 2028, is named for reliability rather than throughput, and much of what it proposes is about holding an association together through interference and movement60.

Address configuration is where the third parties appear. A lease is a bounded grant from a server, and the bound is enforced by the client's own clock: renewal starts at half the lease and the client is on its own if the server has gone14. A router advertisement is not addressed to anyone, is not acknowledged, and carries two lifetimes that govern how long an autoconfigured address may be used and how long it may be preferred55,61. Withdrawal exists — a later advertisement with a lifetime of zero — but it is a revocation delivered by unauthenticated multicast to hosts that may have been asleep. The lifetimes are the mechanism; the withdrawal is a courtesy.

Worth a paragraph of its own: the address family question is finally moving, which changes which of these entries a host actually depends on. Google's measurement of its own users crossed half of traffic over IPv6 for a single day on 28 March 2026, up from around 46% a year earlier, while other vantage points put the figure closer to 40%62,63,64. A dual-stack host holds both sets of entries at once, which is not a doubling of risk but a change in its shape: the autoconfigured side takes its bounds from advertisements, the stateful side from a server, and the two disagree about who is authoritative for the same machine65. Interface identifiers themselves became a stored fact with a policy attached once stable-privacy generation replaced deriving them from the hardware address66.

Two entries in this group deserve attention because they never revalidate at all. Duplicate address detection asks, once, whether anybody else is using the address, and then stops asking67,61. A machine that boots while its rival is powered off will claim the address and keep it, and the resulting intermittent failure is famously hard to see from either host. And source address selection, which is specified in careful, rule-ordered detail — including a preference for addresses that are still preferred rather than merely valid — is consulted once, at connect time, and never again68,69. A long-lived connection therefore outlives the reasoning that placed it, sourced from an address that the rules, if re-run, would no longer choose.

5Which way out

A forwarding table is a set of prefixes with next hops, resolved by taking the most specific match. That resolution rule is doing more work than it appears to, and the cleanest way to see it is to hold the same predicates two ways.

Take twelve prefixes with real nesting: a default route, a /8 with two /16s inside it, a /24 inside one of those and a /25 inside that, and so on. 22 of the 66 unordered pairs stand in a containment relation. Now sample 180,000 addresses and resolve them twice — once as a set, by longest prefix, and once as an ordered list, by first match — and permute the input fifty times. As a set, the verdict changes 0 times: specificity is a property of the prefixes, not of the file. As a list, a random ordering changes the verdict for a mean of 46.48% of addresses, at worst 83.41%, and 0 of the fifty orderings reproduce the set's answers everywhere75.

This is the structural difference between routing and filtering, and it has a direct consequence for staleness. A stale route is frequently harmless, because a more specific entry overrides it without anyone intervening; the table degrades gracefully by construction. A stale rule in an ordered list is not overridden by a better one, it overrides the better one, because position and not specificity decides. That asymmetry is why firewall rulesets rot in a way that routing tables do not, and it is the strongest argument for the move from numbered chains to named sets and maps, which put the matching back into a data structure where order is not semantic76.

The freshness of a forwarding entry mostly does not live in the kernel. A route installed by a routing daemon is correct exactly as long as the daemon's own protocol state says it is, and the kernel has no opinion; it holds the entry until a netlink message replaces it77,78,43. On a host rather than a router, the entry that matters most is the default route, and in the common configuration its lifetime is set by a device on the local segment that the host cannot authenticate. It is the single entry in this whole catalogue whose blast radius is everything the machine was going to do55,75.

Path MTU discovery is the routing-adjacent cache that fails most instructively. The mechanism depends on routers sending an error message back when a packet is too large and the do-not-fragment bit is set17,79. Many operators filter those messages, so the mechanism fails by omission: the connection completes its handshake on small packets and then hangs on the first full-sized segment, which is the most confusing possible failure signature80,81,51. The replacement inverts the design. Rather than depend on anyone's cooperation, it probes with real data and infers the answer from what arrives, which moves the entry two rungs up the ladder by removing the dependency82,83. Note what that says about ladder position in general: it is a property of the mechanism, not of the fact. The same question — how big a packet fits — is answered at rung 3 by one design and rung 5 by another.

Behind several of the corrections in this group stands one protocol, and it is worth noticing how much weight it carries. Unreachability, fragmentation-needed, time-exceeded and redirect are all carried by the internet control message protocol, in both address families84,85. That is the stack's principal revocation channel, it is unauthenticated, it is unacknowledged, and filtering it wholesale is common enough that the standards body had to publish guidance on which messages a firewall must not drop86. A correction channel that operators routinely disable is why so many entries in this catalogue fall back on a timer.

One entry in this group sits at the top of the ladder for the same reason. When a host has several equal next hops, the choice of which to use is made by hashing the packet's own header fields, so there is no per-flow state to become stale56. What the design trades away is not staleness but consistency: when the set of next hops changes, the hash's output changes for flows that did not ask for anything, and a memory problem becomes a reordering problem.

6Keeping a conversation

Transport state is where the ladder's top and bottom meet in a single table entry. An established connection is a belief that a peer exists, is willing, and has received up to a given byte88. While data is flowing that belief is confirmed continuously, and by the strongest evidence anywhere in the stack: the acknowledgement, which exists to make delivery reliable and delivers liveness as a by-product. The clock belongs to the peer and it only ticks when somebody is talking.

Stop talking and the same entry drops to the bottom. Keepalive exists, it is off unless the application asks for it, and when enabled it waits two hours before the first probe — a figure the host requirements chose in 1989 and Linux still ships89,56,90. Between those two states nothing about the table entry changes. What changes is whether anyone is generating evidence. Two plates below record the same connection twice for exactly this reason, and the pair is the clearest demonstration in the article that the ladder measures a mechanism and not a fact.

The estimators are better behaved and still slow to forget. Feeding a standard smoothed round-trip estimator a run of 20 ms samples, one 400 ms excursion, and then 20 ms again, the retransmission timeout rises to 448 ms — 2.24 times its floor — and takes 6 further samples to come back within a tenth of where it started. A loss occurring inside that window waits up to 248 ms longer than it should. This is deliberate: the variance term is weighted to be slow, because a timer that reacts quickly to a single slow sample produces spurious retransmissions, which is a worse failure91,15. It is also worth noting what the standard's own minimum does to the picture. With the recommended one-second floor the excursion is invisible, because the estimate never leaves the floor at all; the effect only appears at Linux's 200 ms minimum. Two conforming stacks can therefore have completely different memories of the same event.

Two neighbouring pieces of state deserve a mention because they are sized by the same guesswork. The maximum segment size a connection announces is derived from the interface MTU, which as established above is a number nobody measured, and the specification that fixed the conventions around it dates from 198392. And the 16-bit identification field, which exists so that fragments can be reassembled, was formally restricted after it became clear that at modern rates it is reused far faster than the reassembly timer assumes — the same arithmetic as the sequence-space wrap, on a field sixteen bits wide93.

Karn's rule sits underneath all of this and deserves its own sentence. When a segment has been retransmitted, an arriving acknowledgement is ambiguous about which transmission it refers to, so the estimator takes no sample at all16. That is the correct answer to an unanswerable question, and it means the estimator stops taking readings during precisely the interval in which the path is misbehaving.

The congestion window is a hypothesis about a resource nobody measures. Loss as the signal was a 1988 expedient that lasted thirty years and remains the default in the standard algorithms15,94,95. The two live alternatives disagree about what to believe instead: an explicit mark set by the router, which requires the network to participate, or a model of bandwidth and round-trip time built entirely from the sender's own observations, which does not96,97. Both are, in the terms of this article, attempts to move the entry up the ladder — one by adding a notification, the other by making the estimate self-checking. The analytic result that throughput falls with the square root of loss rate is what made the loss signal legible enough to argue about98, and the measurement work that catalogued what real paths do to packets is what showed the estimate had to survive reordering, duplication and delay spikes as well as loss99.

There is one more piece of remembered state on the path that the host does not own and cannot see: the queue. A buffer sized generously in the belief that dropping packets is always bad holds a sender's own history against it, so the round-trip estimate measures the queue rather than the path, and the control loop is fed a number it partly created100. The response was a queue discipline that measures how long packets are resident rather than how many there are and drops on that basis, which is the same move as everything else here: replace a stored quantity with a measured one101,102.

Two extensions worth naming turn a remembered fact into a performance feature outright. Fast open lets a client keep a cookie from an earlier connection and send data in the opening segment, trading a round trip for a credential that may have been issued by a server that no longer recognises it103. Session resumption in the current transport security protocol does the same thing one layer up, with a ticket whose lifetime the server chooses104. Both are the lease pattern again: a bounded grant from a party who will not be present when it is used. And a connection can now have several paths at once, each with its own estimates and its own idea of what the network is doing, which multiplies every entry in this group by the number of subflows105.

Then there is the plate that sits at the bottom for a reason that has nothing to do with the host. Window scaling is negotiated by an option carried in one segment of the handshake, and it multiplies every window value for the rest of the connection106. A middlebox that strips or rewrites that option leaves both ends confidently wrong, permanently, with no error anywhere. The measured prevalence of exactly this behaviour is what turned transport extensibility from a theoretical concern into an engineering constraint, and eventually into an argument for encrypting transport headers and moving the transport into userspace where the network cannot reach it107,108,109,110,111.

The numbers are worth stating plainly. Without the option, a connection is capped at 65,535 bytes per round trip: 10.49 Mb/s at 50 ms. With it at maximum shift the advertisable window is 1,073,725,440 bytes, which at the same round-trip time caps a single connection at 171.8 Gb/s — so the option that rescued the protocol has a ceiling of its own, and 400 Gb/s at 50 ms would need a shift of 16. Separately, the 32-bit sequence space wraps in one maximum segment lifetime at 286 Mb/s, which means a 100 Gb/s flow recycles its entire sequence space 349 times per assumed segment lifetime. The only thing distinguishing a fresh segment from a very old one at that rate is a timestamp option carried in every segment — and it travels in the same option space that middleboxes have been observed to mangle106,88.

Two smaller optimisations compose into the stack's most famous own goal. A sender withholds a small segment while an unacknowledged one is outstanding, to avoid filling the network with tinygrams112. A receiver withholds an acknowledgement briefly, hoping to carry it on a reply, to avoid sending bare acknowledgements113. Each is correct alone. Composed, on a write-write-read workload, each waits for the other. A stylised model of 4,000 bytes followed by 100 bytes, repeated 200 times over a 10 ms path with a 40 ms delayed-acknowledgement timer, takes 12200 ms against 2200 ms when the small write is pushed out at once — a factor of 5.55, with 65.6% of the elapsed time spent waiting for a timer whose purpose is to save a packet.

Ports and sockets close the group, and they behave differently from everything else here because they are local facts. A port reservation cannot be wrong; it can only run out. The interesting arithmetic is what the closing state does to the range. Linux's default ephemeral range holds 28,232 ports, and a closed connection occupies its four-tuple for the TIME-WAIT period, which the kernel fixes at 60 seconds56,114,115. To a single destination address and port, that caps new connections at 470.5 per second — at which rate the entire range is in the closing state and none of it is carrying data. Randomising the choice of port, adopted to make blind attacks harder, costs probes as the range fills: at 99% occupancy the predicted 100 attempts per allocation match the simulated 99.4116,117. And the registry's recommended dynamic range and the range Linux actually ships have never agreed, which is a small standing reminder that even the local facts are conventions118,119.

Datagram sockets, by contrast, are honest. A connected datagram socket keeps a default destination and a filter on what will be delivered, and promises nothing120,121,122. It cannot hold a stale belief on the application's behalf because it holds almost no belief at all. What happens instead is that the belief moves up a layer, which is why every long-lived protocol built on datagrams grows its own liveness check — and why the modern transport that replaced TCP for much of the web is a datagram protocol carrying all of this machinery in userspace, where the application can see it111,123.

7Names

The name system is the largest cache in the world and the one whose expiry policy is set furthest from the point of failure. A record carries a time to live chosen by the zone's operator; a resolver may serve the answer until it elapses; and there is no invalidation message in the protocol9,10,126. A change made now becomes visible when the last copy of the old answer expires, and the schedule for that was fixed in advance by somebody guessing how often the record would move.

The classical measurement result is that hit rate depends only weakly on the time to live beyond a few minutes, because the distribution of name popularity is heavy-tailed: a small number of names are asked for constantly and are cached whatever the value, and the long tail is asked for so rarely that no plausible value keeps it resident127. Simulating 10,000 names drawn from a Zipf distribution over 200,000 queries reproduces the shape. Hit rate goes from 0.5709 at 30 seconds to 0.7903 at five minutes to 0.9424 at one hour, and then to 0.9518 at one day. The corresponding mean lie window — how long a change made at a random instant stays invisible, averaged over names weighted by how often they are asked for — goes from 7.5 seconds to 82,846. The last 0.93 points of hit rate cost 59 times the exposure.

That curve is the reason operational advice about the time to live is always about timing rather than value: lower it before the change and raise it after, because the number in effect when the record is fetched is the number that governs, and there is no way to reach back128. It is also the reason the value is a security parameter as much as a performance one. Measurements of real deployments find operators routinely holding values far from anything the cache-efficiency argument would recommend, in both directions, and find resolvers that do not honour them either128.

Negative answers are cached too, and the bound comes from the zone rather than the record, because there is no record to carry it129. This turns deployment into a scheduling problem in the other direction: a name created now may be invisible for as long as the previous denial said it would be. The stub resolver adds its own small pathology. The classic list of servers has no health checking; a dead server is discovered per query, per timeout, and the list is retried from the top each time130. This is why name resolution feels slow rather than broken when a server dies, and it is most of the reason the job has migrated to a local caching daemon on almost every modern system.

There is one design in this area that answers the staleness question by refusing to answer it. Rather than resolve a name, pick the best-looking address and commit, a client can start connections to several of the addresses at once, staggered, and keep whichever one completes131. The current revision extends the idea to service records so that the racing covers protocols and ports as well as address families132. This is the same move as probing for a path MTU with real data: stop trusting a preference computed in advance, and let the attempt itself be the measurement. The cost is a small amount of wasted work, and it buys immunity to a whole class of stale-preference failures. Local name resolution took a different route again, replacing the server with a multicast question on the segment, which trades the third party for the neighbour and inherits the neighbour's problems133.

What the name system does not have is any of the corrective machinery found elsewhere in the stack. There is no equivalent of a gratuitous announcement, no equivalent of a lifetime set to zero, no equivalent of a probe. The transport the query rides on has changed several times — to TLS, to HTTPS, to QUIC — and every one of those changes was about confidentiality and integrity of the answer in flight rather than about revoking an answer already delivered134,135,136. Validation of the answer's authenticity is a separate mechanism again, and it too says nothing about freshness137,138. The name system's lie window is, by design, a number somebody typed.

8Policy with a memory

A stateless packet filter is the second entry in this article that cannot go stale, and for the same reason as the frame check: it keeps nothing. A verdict is a function of the packet's own fields20,76. The weakness is at the other end. With no memory, a filter cannot tell a reply from an unsolicited packet, and that distinction is precisely what operators want, which is why the stateless filter is almost never deployed alone.

Connection tracking supplies the memory, and with it the whole vocabulary of established, related and new139,24. It is also where the stack's arithmetic of occupancy becomes visible, because a tracking table is sized in entries but filled by timers. Occupancy is the arrival rate multiplied by how long the entry is held, which has nothing to do with how long the flow lasts. A name lookup over a datagram takes about twenty milliseconds and is held for thirty seconds by default, an inflation of 1,500 times; classified as a stream, 6,000 times. A short web request that is not closed cleanly is held under the established timeout, which defaults to five days, an inflation of 1,234,286140.

The practical consequence is a failure mode that looks nothing like its cause. A host opening 100 connections a second of which 1% are abandoned leaks one entry per second, and fills a 262,144-entry table in 3.03 days — 1.97 days before the first of those entries would have expired on its own. The symptom is that new connections are refused while the machine is almost idle, and the number that needs changing is a timeout nobody has looked at since the distribution shipped it.

Address translation makes all of this somebody else's table. The endpoint has no view of the middlebox's state and no way to ask; it infers that the mapping still exists from the fact that traffic worked, and discovers otherwise only by one-way silence23,141. The behavioural requirements respond to this by specifying floors — a datagram mapping must not expire in under two minutes and should default to five, an established connection must be held for over two hours — which is an explicit admission that endpoints cannot find out and must be given a number to guess with141,142,143. Carrier-grade deployments add their own constraints on top144. An entire industry of keepalive traffic exists to keep these invisible entries alive, and encapsulation standards specify the keepalive packet formally because the alternative is a tunnel that stops working for no observable reason145.

It is worth remembering why any of this exists. Private address ranges were reserved in 1996 on the explicit assumption that the hosts using them did not need global reachability, and their IPv6 equivalent kept the idea146,147. Translation then quietly extended those ranges to hosts that did need reachability, which is how a scheme for isolated networks became the default connectivity model for most of the internet. The transition machinery between address families is built the same way, out of state held in a box in the middle148. Every one of those boxes holds an entry that neither endpoint can see, and the endpoints' only recourse is to keep talking. On the diagnostic side the tooling has improved considerably: the in-kernel filtering machinery that began as a packet-capture accelerator is now a general instrumentation layer, and the state described in this section can be read out of a running kernel directly rather than inferred149,20.

The ruleset itself belongs on the ladder for a different reason from everything else here. It is not a belief about the world; it is a statement of intent. It decays because the network changes around a rule that keeps matching exactly what it always matched, and the decay is invisible because a rule that no longer expresses anybody's intent still evaluates correctly. Ingress filtering has been best current practice since 2000150, which does not make a given deployment's implementation of it current with a network that has been re-addressed twice since.

9Copies of the stack

Network namespaces did not add a kind of state. They made every kind plural. A namespace has its own interfaces, its own addresses, its own routing table and rules, its own neighbour cache, its own tracking table and its own ruleset152,25. That is what makes container isolation credible, and it means a misconfiguration is now a misconfiguration in a place nobody is watching.

Virtual interfaces are where the ownership question comes out unusually well. A virtual ethernet pair has both ends inside the same kernel, so the state of one end is known synchronously and exactly to the other153. This is one of the very few entries in the catalogue whose owner and holder are the same piece of software, and it is most of why container networking is debuggable at all. The trust does not extend past the pair: what the bridge on the other side does is a separate question with separate state, learned from overheard frames and aged out on a timer like any other bridge.

One level lower, the interface a virtual machine sees is itself a negotiated fiction. The paravirtualised device model that became the de facto standard describes a ring of buffers and a set of feature bits agreed between guest and host at initialisation154. Those feature bits are the offload contract again, one layer of indirection further from anything physical, and they are agreed once.

Overlays add a layer of the same pattern one level up. Encapsulating a link-layer frame in a datagram means that somewhere there is a table mapping inner addresses to outer ones, and whether that table is learned from traffic or programmed by a controller is exactly the difference between rung 3 and rung 1155,156. The choice recurs at every level of virtualisation, and it is always the same trade: learning is self-maintaining and slow to notice change, programming is prompt and depends on something outside the data path being correct.

Tunnels close the catalogue with its sharpest contrast. A security association holds keys, sequence numbers and selectors for one direction, and it is bounded by a negotiated lifetime in seconds or bytes157,158. What it does not intrinsically have is a way to notice that the peer has forgotten: the classic failure is a half-open tunnel after one side reboots, encrypting into a machine that threw the keys away. Detecting this needed a separate mechanism added years later, and its own specification is explicit that the point is to avoid probing peers that are obviously alive, which is to say that the liveness question and the traffic question were deliberately separated159.

The modern tunnel makes the opposite choice and gets a rung for it. A cryptographic peer's outer address and port is not configured and not negotiated; it is set to the source of the last packet that authenticated correctly26,160. Roaming therefore works as a consequence of a check the design already performs, and a forged move fails because it fails to decrypt. Compare the neighbour cache, which learns the same kind of fact — where a peer currently is — from an unauthenticated broadcast. The difference between the two is not caching. Both cache. The difference is what counts as evidence.

10The lab

Everything quoted so far comes from the same place: a single deterministic program, standard library only, seed 20260912, run when this page was built. It has nine experiments. Four of them measure properties of published defaults and specifications rather than of any implementation, which is deliberate — the argument is about what the documents commit a host to, not about how any particular kernel version behaves on any particular day.

Two things the run does not do are worth stating. It does not send packets, so nothing here is a measurement of a real network; the round-trip times, loss patterns and traffic mixes are stipulated, and the figures they produce are illustrations of arithmetic rather than observations. And where a default is representative rather than specified — a 24-hour lease, a one-hour name record — the table says so, because those numbers are conventions and not requirements.

Two experiments were rebuilt after their first version was wrong in a way that mattered. The compensating-error test in E2 originally added and subtracted a delta with plain 16-bit wraparound, which is not the arithmetic the checksum uses; end-around carry means a wrap changes the sum, so the first version reported 68% undetected where the correct statement is that a compensating pair in which neither word wraps is undetected in all 4,000 trials. The name-cache experiment in E9 first computed its staleness figure from a single snapshot taken at the end of the run, which made short-lived entries look permanently absent; it now samples two hundred instants in the second half of the run and weights names by how often they are asked for.

One number in the run is noisier than its neighbours and should be read as such. The two-word corruption test in E2 observed 8 undetected cases against 6.1 expected over 400,000 trials; at that count the sampling error is comparable to the effect, and the honest statement is that the measurement is consistent with the theoretical one in 65,535 and does not independently establish it.

11The ledger

Placing all thirty-eight entries on the ladder gives a distribution with a long tail at the bottom. 3 are recomputed and cannot be stale. 7 are confirmed by the next exchange with the party they describe. 10 are bounded by a timer. 3 wait for an external event. 10 change only when a person changes them. 5 have no mechanism at all. The mean rung is 2.34, and 10 of 38 sit at rung 4 or above against 15 at rung 1 or below.

The second axis is how much breaks while the host is wrong. Here the intuition that the stack guards its most consequential beliefs most carefully does not survive contact with the matrix. The correlation between rung and blast radius is -0.18: essentially nothing, and what little there is runs the wrong way. Of the 9 entries whose failure reaches a whole segment or a whole site, 5 sit at rung 2 or below. The entries that are checked continuously are almost all per-flow, because the thing that checks them is the flow. Nothing checks the default route, the ruleset, the prefix length or the cached name, and those are precisely the four whose failure takes everything else with them.

The third reading is the one this article was written for. 23 of the 38 entries are copies of a fact that somebody else owns: the other endpoint, the path, or a third party such as a server or a router. Of those 23, 7 can be corrected over a channel that is acknowledged or authenticated, 9 depend on an unacknowledged datagram that may be filtered, lost, or arrive while the host is asleep, and 7 have no correction channel of any kind. Put the other way round: for 16 of the 23 facts a host holds on somebody else's authority, the owner has no reliable way to say that it changed.

That is the finding, and it explains the shape of the mechanisms that exist. Every serious improvement to this catalogue over forty years has taken one of two forms. Either it removed the dependency — probing the path with real data rather than waiting for an error message, hashing a next hop rather than storing one, deriving a peer's location from a signature check that was happening anyway — or it added a bound the holder enforces itself, which is what a lease, a time to live and a security association lifetime all are. Almost nothing in the stack succeeded by building a reliable revocation channel, because between parties who do not otherwise talk, there is nothing for a revocation to ride on.

Two smaller results fall out of the matrix, and the first runs backwards. The mean rung of the entries the host owns outright is 2.00, below the 2.57 of the entries it holds on somebody else's authority. Owning a fact turns out to be no protection at all, because the facts a host owns are mostly configuration, and configuration is the one category with no revalidation of any kind: a host is perfectly capable of being permanently wrong about itself, and nothing in the stack is arranged to tell it. And of the 10 timed entries, 6 take their bound from outside, which is what makes the median-length result from the first experiment more than a curiosity. A host's own timers are set to protect the host. The ones it inherits are set to reduce load on somebody else.

12Who sets the clock

The catalogue suggests three things worth carrying into a design review, none of which is about performance.

The first is that the rung is a property of the mechanism, not of the fact. Path MTU is answered at rung 3 by a design that waits for an error message and at rung 5 by a design that probes with data. A peer's current location is learned at rung 4 by a neighbour cache and at rung 4 by a cryptographic tunnel, but the tunnel's evidence is a signature and the cache's is a broadcast anyone can send. When a piece of state is causing trouble, the question is not whether to cache it — everything is cached — but whether the check it depends on can be made a by-product of something the system was already doing. The acknowledgement is the model. It exists for reliability, and liveness falls out of it for free.

The second is that an entry with no traffic has no evidence. The single sharpest pair in the matrix is the established connection recorded twice, at rung 4 while data flows and rung 0 while idle, with nothing about the table entry different between them. The same is true of a bridge entry for a silent host, a translation mapping for an idle flow and a neighbour entry for a machine nobody is talking to. Any design whose correctness depends on state being validated should ask what validates it when the system is quiet, and the usual honest answer is nothing.

The third is about who is allowed to choose the number. Where a bound exists it is almost always a timer, and the timers a host sets for itself are short while the ones set for it are long, by a median factor of 62 across the published defaults in the first experiment. This is not carelessness. A name server operator raising a time to live is reducing load on their own infrastructure; a router advertising a month-long prefix lifetime is reducing multicast on a segment; a translator holding a mapping for hours is avoiding a table churn it would otherwise pay for. In each case the cost of the longer window lands on a party who is not in the room. Wherever a protocol lets one party set another party's staleness budget, expect the budget to be generous, and expect the failure to be attributed to the wrong machine.

None of this argues for less caching. The alternative to a stale answer is a round trip, and a stack that asked every question again would not be usable. What the ladder argues for is knowing which rung a given piece of state is on, because that determines what a failure will look like and where it will be reported. A rung-4 entry fails loudly, quickly, and at the party responsible. A rung-0 entry fails somewhere else entirely, weeks later, as somebody else's timeout.
