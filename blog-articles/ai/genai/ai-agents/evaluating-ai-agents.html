1The number and the run behind it

An agent evaluation ends in a number, and the number looks like the numbers that come out of model evaluation. Both are proportions. Both are printed to one decimal place. Both go into the same table in the same release note. The resemblance is the problem: the two numbers are estimates of different things, computed from samples with different structure, and only one of them is supported by the evidence that produced it.

A model evaluation scores a call. Something goes in, something comes out, and a scorer compares the output to a reference. The observational unit and the thing being scored are the same object. There is no interior. When the score says 62%, it says that on 62% of a sample of prompts the output matched, and the only sources of variation are which prompts were sampled and how the decoder was configured. Both are controllable and both are routinely controlled.[1,2]

An agent evaluation scores a trajectory. The system takes an action, the world answers, it takes another action, and after somewhere between three and three hundred of these the run stops and a checker looks at the end state.[3,4] The unit of observation is the whole run. The unit of behaviour is the step. A single number over runs is therefore a statistic over a sample of trajectories, each of which is itself a sample path, and almost every published agent score is computed from exactly one draw per task.

Two properties of a measurement decide what such a number can support, and they are independent of one another. The first is where in the run a verdict is able to land: at the end only, at a phase boundary, at every action, or as a difference between two executions. The second is how many runs the quantity needs before it means what its name says. Metrics get discussed as though these were one axis, with per-step scoring treated as simply better and repeated runs as simply more expensive. They are not one axis. Some of the most informative measurements in use deliver a single verdict per run, and some of the finest-grained ones are worthless without a matched control.

This article takes twenty-seven measurements — five that belong to model evaluation, eight metrics defined over agent runs, eight methods of taking a reading, and the six benchmarks that most agent claims are made against — and places each of them on those two axes. A small computational lab, described in clause 7 onward and reproduced in full at the end, supplies every quantitative claim that is not attributed to a published source. The organising question throughout is the plainest one available: given a reported number, what does one run tell you?

The question is not new and the field is not unaware of it. There are surveys of agent evaluation[5], boards that report progress-rate diagnostics alongside final success[6], open harnesses with trajectory viewers built in[7], and an explicit statement from one of the larger laboratories that evaluating these systems is harder than the published numbers make it look.[8] What is comparatively rare is the arithmetic: how wide the interval actually is, how many runs the comparison actually needed, how much of the result the harness contributed. Long-horizon capability trends are now estimated by fitting time-to-completion curves across benchmark families[9], which makes the precision of the underlying scores load-bearing rather than a methodological footnote.

2One metric survives the change of horizon

It is worth being precise about what breaks when a metric moves from a call to a run, because the usual claim — that agent evaluation is harder because agents are more complicated — is true but not useful. What actually breaks is coverage.

Accuracy on a single call is a terminal measurement. It looks at the end of the process and reports one verdict. That is not a weakness, because a single call has no interior for the verdict to miss: the terminal state and the complete state are the same state, and coverage is total. Take the identical definition, keep the identical scorer, and apply it to a run of ten actions, and the definition now observes one position in ten. Nothing about the metric changed. The system it is pointed at grew an inside.

Four of the five standard model metrics have this shape and do not transfer. Accuracy, reasoning and factuality all score a final artefact; instruction following scores a response against a constraint list. Each is a legitimate measurement of a call and each becomes a terminal measurement of a run, keeping its name and losing nine tenths of its field of view.

Tool calling is the exception, and it is the exception for a structural reason rather than an empirical one. Its unit is an action: a state, a catalogue, and one emitted call that is either well formed and appropriate or is not.[10,11,12] That unit does not change when the horizon lengthens; there are simply more of them. This is why function-calling benchmarks were the first model evaluations to survive contact with agents, and why per-step tool metrics are the cheapest route to attribution that anyone has found.

3Where a verdict is able to land

Metrology has a word for what is being asked here. The measurand is the quantity intended to be measured, and the first requirement of a defensible measurement is that the measurand be specified well enough that the result can be compared with another laboratory's.[13,14] In agent evaluation, the specification that is almost always missing is the one that says which part of the run the number is about.

The scale below answers that. It runs from a verdict that localises nothing to a verdict that localises a single decision causally. It is deliberately not a quality ranking. A0, at the top, is where the most trustworthy verdicts in the whole field sit: a test suite that runs against a produced artefact is closer to ground truth than anything a judge or a rater will give you. It is also the verdict that tells you least about why.

Alongside the rung, each measurement declares a replication demand: how many runs the quantity needs before its name is honest. Four values are enough. A quantity is single if one run per task supports it as written. It is repeated if it is undefined without k runs of the same task, as any reliability measure is. It is paired if the same task set must be run under both conditions being compared. It is matched if the harness, environment and scorer have to be held identical across arms for the comparison to mean anything at all.

The gauge that appears in every entry below draws one run as a rail of positions. A solid tooth is a position at which the measurement delivers a verdict; a dotted stub is a position it cannot see. A bar underneath is a quantity accumulated over the whole run, and a dashed return beneath that is a second execution the verdict is differenced against. The fraction printed at the right is coverage: verdicts delivered over positions available.

4Eight numbers about a trajectory

These are the quantities that get reported about agents. Read as a set, they divide into three shapes. Task success and goal completion ask whether the world ended up right. Tool selection accuracy, planning quality and recovery ability ask whether the agent behaved well. Steps, cost and latency ask what the run consumed. Only the first group is what anybody actually wants to know, and it is the group with the least attribution.

Two of these deserve to be flagged before the arithmetic starts. Recovery ability is the only quantity on the ordinary list whose definition requires two executions of the same task: to say that an agent recovered, you need to know what would have happened had it not, and that is a counterfactual, not an observation.[15,16] No amount of care with a single trajectory produces it. It is also, on the evidence, worth having: the largest published standardised study of agent traces found that an agent which successfully repairs a failed tool call or a missed instruction mid-run is between 1.5 and 4 times more likely to finish the task.[17]

Latency is the opposite case. It is the easiest quantity to define and the one a large evaluation is least able to measure, because the parallelism that makes a large evaluation affordable is exactly what destroys wall-clock timing. The authors of that same study say so directly, noting that defending their latency data would have required serial execution and turned hours into weeks.[17] A number that can only be measured by giving up the thing that made the measurement possible is a number that will keep being reported badly.

5Eight ways of taking the measurement

A method is a commitment about where verdicts can land, made before any agent is run. Choosing unit tests is choosing A0; choosing simulation is choosing A3 and accepting a fidelity gap in exchange. The choice is usually made on grounds of cost and convenience and then forgotten, after which the resulting number is discussed as though its granularity were a property of the agent.

The measurand is a maximum, not a mean, so the usual logic inverts: more effort can only ever lower an estimate of safety, never raise it. A clean result is a statement about the search, not about the system.

The oldest of these methods carry the oldest known problem with them. Testing has understood for fifty years that a test can show the presence of defects but not their absence[18] and that the hard part is not running the program but knowing what the right answer was — the oracle problem, which has its own substantial literature and no general solution.[19,20] Agent evaluation has inherited the problem and, so far, comparatively little of the literature. Metamorphic testing, which sidesteps the missing oracle by asserting relations between outputs rather than the outputs themselves, is standard practice for untestable numerical programs[21] and is barely used on agents at all.

Two further inheritances have direct agentic analogues that are not being used. Mutation testing asks how many deliberately introduced defects a suite catches, which measures the scorer's discriminating power rather than the thing being scored[22]; the agentic version would be to introduce known errors into a trajectory and ask what share of them the evaluation flags. Flaky tests, which pass and fail on the same input, are a studied phenomenon with measured base rates[23], and any benchmark whose environment involves a live network or a simulated user is flaky by construction. Coverage-guided fuzzing is the mature form of the search that red teaming performs by hand.[24,25,26]

The judge deserves separate treatment because it is the method that scaled. It is cheap, it can be pointed at any granularity, and its ratings correlate respectably with human preference on the tasks it was validated on.[27] It also has documented and specific pathologies: sensitivity to the order in which candidates are presented[28,29], a measurable preference for text the judging model itself produced[30], and a general sensitivity to rubric wording that no amount of averaging removes.[31,32] The deeper issue is structural rather than any one bias: a judge built from the same technology as the system under test has correlated failure modes with it, which is precisely the condition under which an instrument's errors stop averaging out. Clause 8 puts numbers on what that costs even for a judge with no bias at all.

Red teaming is worth flagging for the opposite reason. Its measurand is a maximum, not a mean.[33,34] More search effort can only ever lower an estimate of safety and never raise it, so a clean red-team result is a statement about how hard people looked, not about the system. The adversarial-robustness literature learned this the expensive way, through a decade of defences that held against the attack set they were tuned on and fell to an adaptive one.[35,36] The agent equivalent is already visible: published prompt-injection defences report large reductions in attack success against static injection sets, and those numbers should be quoted with that qualifier attached.[37,38]

The problem is sharper where the behaviour being searched for is one the system has reason to conceal. A model can be constructed to behave normally under evaluation and differently under a trigger, and to survive standard safety training while doing so[39]; evaluations designed to detect deliberate underperformance have to be built on the assumption that the system is aware it is being measured.[40] No terminal metric addresses this, because the whole point of the behaviour is that the terminal state looks ordinary.

6Six instruments in general use

Read as measuring instruments rather than as league tables, the six benchmarks that carry most agent claims have more in common than their coverage of different domains suggests. Five of the six deliver exactly one verdict per run. One of the six defines its headline metric over repeats. One is not a scoreboard at all.

The original figures are worth keeping in view because they show what these instruments were built to detect. AgentBench evaluated 29 models across eight environments under a deliberately minimal scaffold, and reported a gap between the best commercial model and the best open model of roughly four to one on its own composite scale.[4] GAIA put 466 questions to human respondents and to a tool-equipped model and found 92% against 15%.[41] WebArena's 812 tasks, instantiated from 241 templates across four self-hosted applications, gave the best available agent 14.41% against a human baseline of 78.24%.[42] In each case the instrument was designed for a regime in which agents failed almost everything, and a coarse, terminal, single-run verdict was entirely adequate to detect that.

They are now used in a regime where the leading systems succeed at most of the set and differences between them are a few points wide. That is a different measurement problem, and it is the problem the rest of this article is about. BrowserGym is the one entry that responds to it structurally rather than by adding tasks: it fixes a common observation and action space so that results obtained under different scaffolds become comparable, which is a contribution to attribution rather than to difficulty.[43,44]

These six are a sample rather than a census, and the wider population has the same shape. The standardised harness study covered nine benchmarks spanning software engineering[45,46], web navigation and computer use[47,48,49], and scientific work[50,51,52]; security evaluation has its own family[53,54]; and the recommended replacement for the contaminated coding benchmark is a longer-horizon successor drawn from different repositories.[55] A re-examination of web-agent results found that a substantial share of apparent progress on live-web benchmarks was attributable to evaluation design rather than to capability.[56] The scoring shape is terminal in almost every case.

Scaffolds are the other half of the instrument and are reported as though they were not part of it. The same model can be wrapped in a plain reason-and-act loop[3,57], a verbal self-critique loop[58], a purpose-built code-editing interface[59], a general open platform[60], or in no agent loop at all — and the last of these, a fixed localise-repair-validate pipeline with no autonomous decision-making, proved competitive with the agentic systems it was compared against at a fraction of the cost.[61] A benchmark score is a measurement of a model and a scaffold together, and is quoted as a measurement of a model.

τ-bench is the one whose headline metric is defined over repeated runs. Its passk reports the probability that an agent solves the same task on all of k independent trials, and the original paper's finding was that the curve falls steeply: a function-calling agent above 60% on a single attempt dropped below 25% at k = 8.[62] Clause 7 takes that pair of numbers seriously and asks what task population would produce it.

7The arithmetic of a single run

Everything from here is computed. The lab is stdlib Python, deterministic under a fixed seed, and listed in full after the references; each experiment is identified below by its number in that listing.

Start with the least interesting question, which turns out to have the most immediately useful answer. A benchmark reports that an agent solved 24 of 50 tasks. Inverting the binomial gives an exact two-sided 95% interval of [0.3366, 0.6258][63,64] — 28.92 percentage points wide. Two agents reported at 48% and 55% on such a suite are not distinguishable by that suite, and the second one's release note will say it improved the state of the art.

Sample size for a comparison is the harder version of the same question. Separating a true 45% from a true 55% at the conventional 5% level with 80% power needs 392 tasks in each arm if the arms are independent draws — 784 runs. Running both agents on the same task set instead, and testing the discordant pairs, brings that to 236 tasks at a discordant rate of 30%[65,66]. At a fixed budget of a hundred tasks the same shift moves the minimum detectable effect from 19.81 points to 15.34. Pairing is close to free and it is not what most agent leaderboards do, because most agent leaderboards accumulate submissions run at different times under different harnesses.

Two technical notes on the intervals. Inverting the binomial is conservative by construction, and for most purposes an adjusted-Wald interval is both shorter and closer to its nominal coverage[67]; nothing here turns on the choice, and the exact form is used because it never undercovers. Where the score is not a simple proportion — partial credit, a weighted composite, a cost-adjusted figure — the bootstrap is the general answer[68] and a hierarchical model the principled one, since tasks within a suite are exchangeable but not independent.[69] Whichever is used, an interval is a statement about a procedure's long-run behaviour[70], and a benchmark run once is not exercising a procedure. The variance of benchmark scores under nothing but reordering, reformatting and reseeding has been measured directly, and it is not small.[71]

Underpowered comparisons do not merely fail to detect real differences; they distort the ones they do report. When power is low, an effect that clears a significance threshold is systematically larger than the truth and carries an appreciable chance of pointing the wrong way.[72] A leaderboard is a machine for surfacing exactly those effects, because what it publishes is the maximum over many comparisons.

The question everyone actually faces is whether to spend the next dollar on another task or another run of an existing one. Model a suite as tasks with heterogeneous latent solve probabilities, so that the variance of the suite mean has a between-task component that repeats cannot touch and a within-task component that they can. At a hundred tasks, with between-task variance 0.07 and mean within-task variance 0.14, the standard error of the reported mean is 4.583 points at one run per task and 3.742 at two. Doubling the compute buys the same precision as running 150 tasks once. The second run is worth 50 tasks and costs 100.

More importantly the sequence has a floor. Repeats only attack the within-task term, so as k grows the standard error converges to 2.646 points — 57.7% of the single-run figure and no lower, however many times each task is run. If a suite is too small, no quantity of repetition rescues it. This is the same structure as clustered sampling, where precision is bounded by the number of clusters rather than the number of observations[73,74,75], and it is the reason the recommendation to report clustered standard errors on model evaluations[66] applies with more force, not less, to agents.

Now the harder use of repeats. τ-bench's published curve puts a function-calling agent at roughly 61% on one attempt and 25% on eight.[62] If every task in the suite were equally hard, pass8 would be 0.618 = 1.92%. The reported figure is 13.0 times larger. That gap is not noise; it is a measurement of how unlike each other the tasks are.

Fitting a Beta distribution over per-task solve probability to both ends of the curve pins the population down. The fit is Beta(0.836, 0.534), with a standard deviation of 0.3168. For a mean of 0.61 the largest standard deviation any distribution on [0,1] could have is 0.4877, so the implied spread is 65.0% of the theoretical maximum. Roughly 17.9% of tasks are solved on essentially every attempt and 4.7% on essentially none.

The number worth carrying away is that only 16.1% of tasks have a solve probability within ten points of the reported 61%. The headline is an average over a population that it describes badly, and the fraction of the suite it describes well is smaller than the fraction it is wrong about by more than thirty points. This is not a criticism of τ-bench, which published the curve that makes the calculation possible. It is a criticism of every benchmark that publishes the mean and not the curve.

One further correction applies to any attempt to buy attribution cheaply by scoring each step. A twenty-step run scored per action yields twenty observations, but an agent in a bad state tends to remain in one, so consecutive verdicts are correlated. For a two-state chain with lag-1 autocorrelation φ, the effective sample size of L steps is L(1−φ)/(1+φ). Simulating four thousand runs of 200 steps at φ = 0.6 gives an empirical effective size of 49.5 against a predicted 50.0: the variance of the run mean is 4.04 times what independence would predict.[76,73]

8What the terminal bit does not report

Consider a run of twenty actions in which each action has a 12% chance of being wrong, and each wrong action is recovered from with probability ρ and is otherwise fatal to the run. At ρ = 0.7 the task success rate is 0.4803, which is a perfectly ordinary-looking benchmark number. Two hundred thousand simulated runs say what it conceals: 83.80% of the successful runs contain at least one wrong action, with a mean of 1.74 per successful run.

The share of error events that reach the score has a closed form, and it is startlingly simple. Expected recovered errors per run work out to ρS/(1−ρ) where S is the probability of failure, so the fraction of errors the terminal bit reports is exactly 1 − ρ, independent of run length, of the per-step error rate, and of everything else. At ρ = 0.7 that is 30%, and the simulation returns 29.99%. An agent that recovers well is an agent whose score reports less of what it did.

This is not a hypothetical. The standardised trace study cited earlier found that on two of three benchmarks examined, agents almost never completed a run without at least one tool-calling failure, including runs they went on to pass, and that agents encountered an environmental barrier such as a crashed browser or an unavailable import in roughly 40% of failed tasks.[17] None of that is visible in a success rate. The multi-agent failure taxonomy built from 1,600 annotated traces reaches the same conclusion from the other direction: the failure modes that matter are distributed across specification, inter-agent misalignment and verification, and they are identifiable only from the trace.[77,78]

Now the second source of missing signal, which is the scorer itself. Suppose a judge with 90% sensitivity and 90% specificity — better than most reported inter-rater agreement figures for the same task.[79,27] Its observed rate is a linear function of the true rate that crosses the diagonal at exactly one point. Below that point it flatters the agent and above it penalises it; the direction of the bias reverses as the agent improves, which is the worst possible property for an instrument used to track progress over time.

A true ten-point gap between agents at 40% and 50% is recorded as 8.00 points, attenuated by exactly the Youden index of the judge. The cost in evidence is larger than the cost in signal: detecting that gap needs 387 tasks per arm with an exact scorer and 608 through the judge, a factor of 1.57. At 80% sensitivity and specificity the factor is 2.80. This is the classical misclassification-attenuation result[80,81,82], and its practical consequence is that judge quality should be reported as a sample-size multiplier rather than as an agreement percentage, because the multiplier is what a reader needs in order to know whether the comparison was powered.

There is a way out that the field has mostly not taken up. If a small subset of items is scored by both the judge and a reference standard, the judge's error rates can be estimated and the bias removed, with valid intervals, from an estimate that uses the judge on everything else.[83] That converts a cheap noisy scorer into a cheap unbiased one at the cost of a calibration set, which is exactly the trade a calibration laboratory makes as a matter of routine.[84]

9When the instrument is the thing that is broken

Everything so far assumed the tasks were sound. In February 2026 the organisation that built the curated version of the most-cited coding benchmark published an audit saying they were not, and stopped reporting the score.[85] The finding has two parts and both matter.

The first part is task validity. An audit of 138 problems — 27.6% of the 500-problem set, selected as ones a strong model failed to solve consistently across 64 runs, each reviewed by at least six engineers — found that 59.4% contained material defects in test design or problem description. 35.5% had tests enforcing implementation details the problem statement never mentioned, so that functionally correct patches failed on import errors; 18.8% had tests checking functionality outside the stated problem.[85] This is the same failure the curated set was built to remove: its own construction reviewed 1,699 problems with three experts each and discarded 68.3% of them.[86]

Take the audit at face value and assume, generously, that no defective task exists anywhere outside the audited subset. That still puts at least 16.39% of the set beyond reach, so no agent can score above 83.61%. Against that ceiling the reported state of the art of 80.9% is 96.76% of everything attainable, and the remaining headroom on solvable tasks is 2.71 points. The six-month improvement from 74.9% that prompted the audit consumed most of what was left.

Broken tasks also make every comparison harder, and by more than the obvious amount. Two agents whose true skill on solvable tasks is 85% and 90% are observed at 71.06% and 75.25%, a gap of 4.18 rather than 5.00 points. The tasks needed per arm rise by a factor of 2.571. The naive expectation from the shrunken gap alone would be 1.431; the rest comes from deflating both scores toward 50%, where the binomial variance is largest. Defective tasks cost twice, once in signal and once in noise.

The second part of the audit is contamination, and it is the part with no statistical remedy. Every frontier model tested could reproduce, from the task identifier alone or from a fragment of the problem statement, the human-written reference patch: the exact class and method changed, the exact new guard clause, in one case the verbatim inline comment in the diff.[85] Worse, exposure and score are linked, because a model that has seen the repository's release notes has the information needed to pass precisely the underspecified tests that defeat an uncontaminated model. Improvement on the benchmark and exposure to the benchmark became the same measurement.[87,88,89]

This is Goodhart's law with a specific mechanism[90,91,92], and the response the auditors recommend — privately authored tasks, held-out solutions, canary strings, password-protected distribution[93] — is a response to the mechanism rather than to the law. Public benchmarks built from public artefacts have a shelf life measured in model generations. That is not a flaw in any particular benchmark; it is a property of the construction.

Neither is it new. Constructing a fresh test set with the same distribution as an overexposed one and re-measuring is a standard diagnostic; done for grade-school arithmetic, it showed accuracy drops of up to thirteen points for some model families and none at all for others.[94] Vision benchmarks had the argument two decades ago, when a classifier trained to identify which dataset an image came from performed far above chance[95], and the general phenomenon of a model learning a shortcut that satisfies the benchmark without satisfying the task has a name and a literature.[96]

The audit is the loudest instance but not an isolated one. An independent checklist applied to ten widely used agentic benchmarks found seven violating task validity, seven violating outcome validity, and all ten with reporting gaps, with the resulting misestimates reaching 100% in relative terms; a trivial agent passed 38% of one benchmark's airline tasks without any knowledge of the domain rules it was supposedly being tested on.[97] The same standardised-harness study found that the official few-shot agent shipped in a benchmark's own repository contained test-set examples in its demonstration file, invalidating every result obtained with it — discovered only by automated inspection of the logs, after the runs had been paid for.[17,98] The maintainers of that benchmark have since revised dozens of task specifications, removing incorrect expected actions and impossible constraints.[99]

The pattern across all of these is that the defects were found by looking at traces, not at scores. That is worth stating as a general principle, because it is the operational consequence of everything in clause 8: a number at rung A0 cannot reveal that the instrument producing it is broken, and no amount of statistical care applied to that number will help.[100,101,102]

10Budget, harness, and the ranking that follows

Two agents can be compared only under conditions held equal, and in agent evaluation the conditions include several constants that nobody thinks of as part of the measurement. The step budget is one. The cost cap is another.

Take two agents that differ in both ceiling and speed: one eventually solves more but takes longer to get there, the other converges quickly on a lower ceiling. Modelling success as a capability ceiling times the probability of finishing within the budget, and sweeping the budget from 10 to 50 actions, gives a result that should be uncomfortable. The curves cross at 26.2 steps. Below it one agent leads by up to 8.45 points; above it the other leads by up to 6.43. Total swing from a single harness constant: 14.88 points, with neither agent changing in any way.

Decomposing the variation across the two-by-five grid puts a number on the imbalance: 93.33% of the total variation is attributable to the step budget, 0.78% to the model, and 5.89% to their interaction. That is a stylised model and the exact split is a property of its parameters, but the direction is corroborated by measurement. The standardised harness study found that on one web benchmark two scaffolds around comparable models differed nine-fold in cost for a two-point difference in accuracy, that task-specific scaffolds beat a generalist scaffold on 9 of 12 and 11 of 12 model comparisons on two benchmarks, and — the finding hardest to square with intuition — that in 21 of 36 model-scaffold-benchmark combinations, raising the reasoning effort produced equal or lower accuracy.[17]

Reporting cost alongside accuracy was proposed for exactly this reason, on the argument that unbounded inference budgets let a complex agent buy small accuracy gains at large expense, and that simple baselines frequently dominate elaborate ones once price is on the axis.[103,104] The measured version of that argument is blunt: across nine benchmarks, the most expensive model reached the accuracy-cost Pareto frontier on exactly one, and fewer than a third of tested models were on the frontier for a given benchmark.[17,105]

There is a subtlety in cost-capped comparison that is easy to get wrong, and it is worth the arithmetic. Take a published pair: one agent scoring 30% at cost c, another scoring 27% at c/5. Under an equal per-task budget the cheaper agent gets five attempts, which cover 79.27% of tasks in the sense that at least one attempt is correct.[106] That number gets quoted as though it were an accuracy. It is not, because somebody has to choose which of the five to submit.

Choosing uniformly at random returns exactly the single-shot rate, as it must. To match the expensive agent, a selector must pick correctly 37.85% of the time when a correct attempt is present, against the 34.06% that chance delivers. The required lift over chance is 1.1111 — and it is exactly the ratio of the two agents' single-shot rates at every value of k. Retries lower the absolute bar a verifier must clear and never lower the relative one.

The practical reading is that a fixed-quality verifier does clear the bar eventually: a selector with 50% precision needs three attempts, at 60% of the expensive agent's budget. But the verifier is now part of the system under test, and its errors are subject to everything in clause 8. Resampling against an imperfect verifier has a known ceiling and known failure modes[107,108], and reporting coverage without reporting the selector is the single most common way an inference-scaling result overstates itself.[109,110]

The structure being described — a cheap detector run first, an expensive one reserved for what the cheap one cannot settle — is a cascade, and it has been the standard answer to this shape of problem since long before language models.[111,104] What decision theory adds is the reminder that the quantity to minimise is expected loss under a stated cost structure, not error rate[112,113], and that a benchmark reporting accuracy alone has silently asserted that all errors cost the same. They do not. An agent that abstains and an agent that books a flight against the wrong credit card both score zero, and only one of those outcomes is recoverable.[17]

Placing all twenty-seven measurements on the two axes gives the table below. Two features of it are worth stating plainly.

The first is the concentration at the top. Of the 22 measurements whose observational unit is a whole run, 12 deliver exactly one verdict, and mean coverage across all of them is 0.336. Restricted to the six benchmarks, coverage is 0.267 and 4 of the six deliver a single terminal bit. The field's default instrument observes one position in ten and reports it to one decimal place.

The second is the empty row. Nothing on this list — not one metric, not one method, not one benchmark — scores an action against the alternatives that were available in that state. Tool selection accuracy comes closest and stops short: it compares the emitted call to a reference call, which answers whether the agent matched a recorded choice, not whether the choice was good among those on offer. The distinction is the difference between imitation and evaluation, and it is the gap that process supervision in reasoning was built to close[110] without an agentic equivalent having been built yet. It is also where the honest answer to why did this run fail would have to come from, since a step can only be wrong relative to something else the agent could have done.[114,115]

Both observations are instances of a distinction that measurement theory settled long ago. A score has construct validity to the extent that the inference drawn from it is warranted, which is a property of the inference and not of the instrument[116,117]; and establishing it requires showing both that the measure tracks what it should and that it fails to track what it should not.[118] Agent evaluation has a good deal of the first kind of evidence and almost none of the second. What follows from all of this is a reporting schedule rather than a new metric. Nothing in this article argues that task success should be abandoned; it is the only measurement in the table that is unambiguously about the thing anyone cares about. The argument is that a score reported without the following is not a measurement result, in the sense that a calibration laboratory would recognise[84,119,14], but a point estimate with the uncertainty deleted:

  • the number of tasks and the number of runs per task, separately, because they buy different things and one of them has a floor
  • an interval, computed by inversion or by the bootstrap, and clustered where the task set has structure
  • the whole reliability curve where repeats were run, since the mean of a bimodal-enough population describes almost none of it
  • the harness constants — step budget, retry policy, timeout, reasoning-effort setting — because they can decide the ranking on their own
  • cost and tokens beside accuracy, since the frontier is usually steep and usually sparse
  • the scorer: its version, and where a judge is used, its measured error rates against a reference subset, expressed as a sample-size multiplier
  • what the traces showed, because defective tasks, leaked answers and catastrophic-but-passing behaviour have been found only that way

Older experimental fields arrived at versions of this list after their own reproducibility reckonings. Reinforcement learning went through one, and the recommendations that came out of it — multiple seeds, reported variance, uncertainty-aware aggregate statistics, clear separation of tuning from evaluation — are the same recommendations, in a different vocabulary, arrived at ten years earlier.[120,121,122,123] The reason agent evaluation cannot simply import them is cost. A single agentic benchmark can cost thousands of dollars per model to run; one standardised study spent about $40,000 on 21,730 rollouts across nine models and nine benchmarks and reported, as a limitation, that it was forced to rely on single runs without statistical validation for most of its evaluations.[17]

That is the real constraint, and it is worth being honest about where it leads. If statistically adequate agent evaluation costs more than most institutions can spend, then the evaluations that are adequate will be run by the organisations that build the systems, and external validation becomes partial by arithmetic rather than by choice. The responses available are the ones this article has been circling: measure at a rung where each run yields more than one bit, so that fewer runs are needed; pair every comparison; calibrate cheap scorers against small expensive ones instead of trusting or discarding them; and report the harness as part of the result rather than as an implementation detail.

None of which changes the answer to the question in the title. One run tells you the value of one draw from a distribution whose shape you did not measure, at one setting of constants you did not report, scored by an instrument whose error rate you did not estimate, on a task set whose validity you did not check. Every one of those four gaps has now been quantified by somebody, on real systems, and none of the four is expensive to close relative to the cost of the runs themselves. The reason they stay open is that the number looks finished without them.

There is one further reason to care, and it is not about publication. These systems are being given authority over consequential actions, and the fields that already do that have settled views about what evidence that requires. Reliability engineering does not accept a point estimate of failure rate without a confidence bound and a stated duty cycle[124]; safety engineering treats an accident as a property of a system's control structure rather than of a component's failure probability[125]; and the study of how complex systems actually fail is largely a study of interactions between components that were each individually within specification.[126,127] None of that is legible in a success rate.

The human-factors literature supplies the sharpest version of the warning. Automation that works most of the time reshapes the behaviour of the people supervising it, degrading precisely the skills needed when it fails, and whether the pairing is safe depends on whether their trust is calibrated to its actual reliability.[128,129,130] Calibrated trust requires a reliability figure worth calibrating to. An agent reported at 80% on a suite whose ceiling is 84%, scored by a judge of unmeasured accuracy, under a step budget nobody wrote down, from one run per task, does not supply one.

def binom_cdf(k, n, p):
    """P(X <= k) for X ~ Bin(n, p), summed in log space so large n is safe."""
    if k < 0:
        return 0.0
    if k >= n:
        return 1.0
    if p <= 0.0:
        return 1.0
    if p >= 1.0:
        return 0.0
    lp, lq = math.log(p), math.log1p(-p)
    lgn = math.lgamma(n + 1)
    tot = 0.0
    for i in range(0, k + 1):
        lpmf = lgn - math.lgamma(i + 1) - math.lgamma(n - i + 1) + i * lp + (n - i) * lq
        tot += math.exp(lpmf)
    return min(1.0, tot)


def binom_sf_ge(k, n, p):
    """P(X >= k)."""
    return 1.0 - binom_cdf(k - 1, n, p) if k > 0 else 1.0


def bisect(f, lo, hi, tol=1e-12, it=200):
    """Root of monotone f on [lo, hi]."""
    flo = f(lo)
    for _ in range(it):
        mid = 0.5 * (lo + hi)
        fm = f(mid)
        if (fm > 0) == (flo > 0):
            lo, flo = mid, fm
        else:
            hi = mid
        if hi - lo < tol:
            break
    return 0.5 * (lo + hi)


def clopper_pearson(k, n, alpha=0.05):
    """Exact (Clopper-Pearson) two-sided interval, by bisection on the binomial CDF."""
    lo = 0.0 if k == 0 else bisect(lambda p: binom_sf_ge(k, n, p) - alpha / 2, 0.0, 1.0)
    hi = 1.0 if k == n else bisect(lambda p: binom_cdf(k, n, p) - alpha / 2, 0.0, 1.0)
    return lo, hi


def norm_ppf(q):
    """Inverse standard normal CDF (Acklam's rational approximation, refined)."""
    a = [-3.969683028665376e+01, 2.209460984245205e+02, -2.759285104469687e+02,
         1.383577518672690e+02, -3.066479806614716e+01, 2.506628277459239e+00]
    b = [-5.447609879822406e+01, 1.615858368580409e+02, -1.556989798598866e+02,
         6.680131188771972e+01, -1.328068155288572e+01]
    c = [-7.784894002430293e-03, -3.223964580411365e-01, -2.400758277161838e+00,
         -2.549732539343734e+00, 4.374664141464968e+00, 2.938163982698783e+00]
    d = [7.784695709041462e-03, 3.224671290700398e-01, 2.445134137142996e+00,
         3.754408661907416e+00]
    pl, ph = 0.02425, 1 - 0.02425
    if q < pl:
        u = math.sqrt(-2 * math.log(q))
        x = (((((c[0]*u+c[1])*u+c[2])*u+c[3])*u+c[4])*u+c[5]) / ((((d[0]*u+d[1])*u+d[2])*u+d[3])*u+1)
    elif q <= ph:
        u = q - 0.5
        r = u * u
        x = (((((a[0]*r+a[1])*r+a[2])*r+a[3])*r+a[4])*r+a[5])*u / (((((b[0]*r+b[1])*r+b[2])*r+b[3])*r+b[4])*r+1)
    else:
        u = math.sqrt(-2 * math.log(1 - q))
        x = -(((((c[0]*u+c[1])*u+c[2])*u+c[3])*u+c[4])*u+c[5]) / ((((d[0]*u+d[1])*u+d[2])*u+d[3])*u+1)
    # one Newton refinement against the CDF
    e = 0.5 * math.erfc(-x / math.sqrt(2)) - q
    x -= e * math.sqrt(2 * math.pi) * math.exp(x * x / 2)
    return x


Z_A = norm_ppf(0.975)     # two-sided alpha = 0.05
Z_B = norm_ppf(0.80)      # power = 0.80


def n_unpaired(p1, p2, za=Z_A, zb=Z_B):
    """Per-arm sample size, two independent proportions."""
    pbar = 0.5 * (p1 + p2)
    num = (za * math.sqrt(2 * pbar * (1 - pbar)) + zb * math.sqrt(p1*(1-p1) + p2*(1-p2))) ** 2
    return num / (p2 - p1) ** 2


def mde_unpaired(n, p=0.50, za=Z_A, zb=Z_B):
    """Minimum detectable effect at per-arm n, around baseline p (normal approx)."""
    return (za + zb) * math.sqrt(2 * p * (1 - p) / n)


def mde_paired(n, pdisc, za=Z_A, zb=Z_B):
    """MDE for a paired design with discordant-pair rate pdisc (McNemar, normal approx)."""
    return (za + zb) * math.sqrt(pdisc / n)


def beta_moment_k(a, b, k):
    """E[p^k] for p ~ Beta(a, b) = prod_{j<k} (a+j)/(a+b+j)."""
    out = 1.0
    for j in range(k):
        out *= (a + j) / (a + b + j)
    return out


def beta_pdf(x, a, b):
    if x <= 0 or x >= 1:
        return 0.0
    lb = math.lgamma(a + b) - math.lgamma(a) - math.lgamma(b)
    return math.exp(lb + (a - 1) * math.log(x) + (b - 1) * math.log(1 - x))


def beta_mass(a, b, lo, hi, n=20000):
    """Simpson integration of the Beta density over [lo, hi]."""
    if n % 2:
        n += 1
    h = (hi - lo) / n
    s = 0.0
    for i in range(n + 1):
        x = lo + i * h
        w = 1 if i in (0, n) else (4 if i % 2 else 2)
        s += w * beta_pdf(x, a, b)
    return s * h / 3
