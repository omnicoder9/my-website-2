Search, Planning, and Problem Solving

How intelligent programs find their way through spaces of possibilities: from breadth-first search and A* to constraint solvers, game-tree search, planners, and theorem provers.

Abstract

A large share of artificial intelligence reduces to one move: describe a problem as a set of states and actions, then search that space for a sequence of actions, an assignment of values, or a proof that reaches a goal. This article develops that idea across eight connected topics. It begins with uninformed search (breadth-first, depth-first, uniform-cost, and iterative deepening), adds heuristic guidance (greedy best-first search and A*), and then examines how heuristics are designed and how local search handles pure optimization. It then treats constraint satisfaction, adversarial search in games, classical planning and scheduling, hierarchical task network planning, and automated theorem proving. Each section gives the history, the formal definitions, a worked example, and a short Python implementation whose printed output is reproduced verbatim. Sixteen exercises with full solutions close the article.

1Problem solving as search

A problem-solving agent is an agent that, before acting, considers sequences of actions that lead to a goal and picks one of them [1]. The idea goes back to Newell and Simon’s studies of human and machine problem solving, which modelled thinking as movement through a problem space of knowledge states [2]. To make the idea computable, a problem is written down formally.

Definition 1 · Search problem

A search problem consists of [1]:

  • a set of states S and an initial state s0 ∈ S;
  • for each state s, a set of applicable actions A(s);
  • a transition model Result(s, a) giving the state reached by doing a in s;
  • a goal test, a predicate that is true of goal states;
  • an action cost function c(s, a, s′) > 0.

A solution is a sequence of actions leading from s0 to a goal state. An optimal solution has the lowest total path cost among all solutions.

States and actions together define a directed graph, the state space. Search algorithms build a search tree over that graph. The root is the initial state, and each node records a state, its parent, the action that produced it, and the path cost so far, written g(n). The set of generated but not yet expanded nodes is the frontier. Search algorithms differ only in which frontier node they expand next [1]. Algorithms are judged on four criteria: completeness (is a solution found whenever one exists?), cost optimality (is the solution found the cheapest?), and time and space complexity, which are measured using the branching factor b, the depth of the shallowest solution d, and the maximum depth of the space m [1].

The same frame covers more than route finding. In constraint satisfaction the states are partial assignments of values to variables. In game playing the tree alternates between two opponents. In planning the states are sets of logical facts and the actions are operator schemas. In theorem proving the “states” are sets of derived formulas and the goal is a contradiction. The remainder of the article follows that progression.

3Uninformed search: BFS, DFS, and uniform-cost search

An uninformed (or blind) strategy uses only the information in the problem definition. It can generate successors and recognise a goal, but it has no idea whether one non-goal state is “closer” to the goal than another [1]. The strategies differ in the data structure that holds the frontier.

Breadth-first search

Breadth-first search (BFS) keeps the frontier in a first-in, first-out queue, so it expands all nodes at depth k before any node at depth k+1. Moore described it in 1959 as a way to find the shortest route through a maze [6]. BFS is complete whenever b is finite. Because the first goal it reaches is the shallowest, it is optimal when every action costs the same. Its weakness is memory: in the worst case it generates b + b2 + … + bd = O(bd) nodes and keeps them all [1]. Applying the goal test when a node is generated, rather than when it is expanded, saves one full layer of work [1].

Depth-first search

Depth-first search (DFS) keeps the frontier in a last-in, first-out stack and so always expands the deepest node. On a tree it needs only O(bm) memory, since it stores one path plus the unexpanded siblings along it. It is neither complete in infinite spaces nor cost-optimal, and its time is O(bm), which can be far worse than O(bd) [1]. Depth-limited search imposes a cut-off ℓ. Iterative deepening (IDDFS) runs depth-limited search with ℓ = 0, 1, 2, …. Korf showed that iterative deepening is asymptotically optimal in time, space, and solution cost among brute-force tree searches [22]. The repeated work near the root is small because most nodes of a tree lie at the bottom level.

Uniform-cost search

When actions have different costs, the shallowest goal need not be the cheapest. Uniform-cost search (UCS) orders the frontier as a priority queue on the path cost g(n) and always expands the cheapest node. It is Dijkstra’s algorithm [7] stopped as soon as the goal is selected for expansion. Testing for the goal on expansion, not generation, is essential to optimality: a goal found by generation may still be reached more cheaply by a path not yet explored. With every action costing at least ε > 0 and optimal cost C*, UCS runs in O(b1 + ⌊C*/ε⌋) time and space [1].

Worked example

Run each strategy on Figure 2 from S to G, breaking ties alphabetically. BFS expands S, A, B and C. While expanding C it generates G and stops with S–A–C–G, three edges but cost 9. UCS expands S (g=0), A (1), B (3), C (4) and G (7). It skips the stale queue entries for C at cost 6 and for B at cost 4, and returns the optimal S–A–B–C–G. DFS happens to find the same route because its alphabetical order dives through A and B first. That is luck: with the children ordered differently it would return S–B–D–G at cost 11. Iterative deepening, like BFS, minimises the number of edges, not the cost.

from collections import deque
import heapq

# Undirected weighted graph from Figure 2: GRAPH[u] = {v: step cost}
EDGES = [("S", "A", 1), ("S", "B", 4), ("A", "B", 2), ("A", "C", 5),
         ("B", "C", 1), ("B", "D", 6), ("C", "G", 3), ("D", "G", 1)]
GRAPH = {}
for u, v, w in EDGES:
    GRAPH.setdefault(u, {})[v] = w
    GRAPH.setdefault(v, {})[u] = w


def path_cost(path):
    return sum(GRAPH[a][b] for a, b in zip(path, path[1:]))


def bfs(start, goal):
    """Breadth-first graph search with the goal test on generation."""
    if start == goal:
        return [start], [start]
    frontier = deque([[start]])
    reached = {start}
    expanded = []
    while frontier:
        path = frontier.popleft()
        node = path[-1]
        expanded.append(node)
        for child in sorted(GRAPH[node]):
            if child not in reached:
                if child == goal:
                    return path + [child], expanded
                reached.add(child)
                frontier.append(path + [child])
    return None, expanded


def dfs(start, goal):
    """Depth-first search; a node is skipped if it is already on the current path."""
    frontier = [[start]]                # a LIFO stack
    expanded = []
    while frontier:
        path = frontier.pop()
        node = path[-1]
        expanded.append(node)
        if node == goal:
            return path, expanded
        # push in reverse so the alphabetically first child is popped first
        for child in sorted(GRAPH[node], reverse=True):
            if child not in path:       # cycle check
                frontier.append(path + [child])
    return None, expanded


def ucs(start, goal):
    """Uniform-cost search (Dijkstra's algorithm with an early stop at the goal)."""
    frontier = [(0, [start])]          # priority queue ordered by g(n)
    best_g = {start: 0}
    expanded = []
    while frontier:
        g, path = heapq.heappop(frontier)
        node = path[-1]
        if g > best_g.get(node, float("inf")):
            continue                    # stale queue entry
        expanded.append(node)
        if node == goal:                # goal test on expansion => optimal
            return path, expanded
        for child, w in sorted(GRAPH[node].items()):
            g2 = g + w
            if g2 < best_g.get(child, float("inf")):
                best_g[child] = g2
                heapq.heappush(frontier, (g2, path + [child]))
    return None, expanded


def depth_limited(path, goal, limit):
    node = path[-1]
    if node == goal:
        return path
    if limit == 0:
        return "cutoff"
    cut = False
    for child in sorted(GRAPH[node]):
        if child in path:
            continue
        result = depth_limited(path + [child], goal, limit - 1)
        if result == "cutoff":
            cut = True
        elif result is not None:
            return result
    return "cutoff" if cut else None


def iddfs(start, goal, max_depth=50):
    """Iterative deepening: depth-limited DFS with limits 0, 1, 2, ..."""
    for limit in range(max_depth + 1):
        result = depth_limited([start], goal, limit)
        if result != "cutoff":
            return result, limit
    return None, max_depth

    path, depth = iddfs("S", "G")
    print(f"IDDFS: path={'-'.join(path)} cost={path_cost(path)} found at limit {depth}")

4Informed search: greedy best-first search and A*

Informed strategies use domain knowledge in the form of a heuristic function h(n), an estimate of the cheapest cost from the state at node n to a goal [1,40]. Most informed algorithms are instances of best-first search, which expands the frontier node with the lowest value of an evaluation function f(n). UCS is the special case f = g.

Greedy best-first search

Greedy best-first search sets f(n) = h(n) and expands whichever node looks closest to the goal. It is often fast, but it ignores the cost already paid, so it is not optimal, and its tree-search form can loop forever [1]. On Figure 2 it expands S, then B (h=3, preferred to A’s h=5), then D (h=1), then G. The route it returns, S–B–D–G, costs 11, four more than the optimum.

A* search

A* combines both sources of information: f(n) = g(n) + h(n), the estimated cost of the cheapest solution through n. A* grew out of the Shakey robot project at SRI [1]. Hart, Nilsson and Raphael published it in 1968 and proved that it returns optimal solutions when the heuristic never overestimates [14].

Definition 2 · Admissibility and consistency

A heuristic is admissible if h(n) ≤ h*(n) for every node, where h*(n) is the true cost of an optimal path from n to a goal.

A heuristic is consistent (or monotone) if h(G) = 0 for goals and, for every node n and every successor n′ reached by action a, h(n) ≤ c(n, a, n′) + h(n′). This is a triangle inequality.

Every consistent heuristic is admissible (Exercise 3). With an admissible heuristic, A* tree search is optimal. With a consistent heuristic, A* graph search is optimal and the values of f along any path never decrease, so the first time A* expands a node it has already found the cheapest path to that node [1,14]. A* is also optimally efficient for a given consistent heuristic. Up to tie-breaking, no other optimal algorithm that extends search paths from the root can guarantee to expand fewer nodes, because any node with f(n) < C* must be expanded to rule out a cheaper solution [1,40].

The values in Figure 2 are consistent; Exercise 3 asks you to check every edge. A* expands S (f=0+6=6), A (1+5=6), B (3+3=6), C (4+3=7) and G (7+0=7), and returns the optimal path of cost 7. It never expands D, whose f = 9 + 1 = 10 exceeds C* = 7. On a graph this small the saving over UCS is modest. The 8-puzzle experiment in Section 5 shows how large it becomes on real problems.

import heapq
from uninformed import GRAPH, path_cost

# Admissible and consistent estimates of the distance to G (Figure 2)
H = {"S": 6, "A": 5, "B": 3, "C": 3, "D": 1, "G": 0}


def best_first(start, goal, f):
    """Generic best-first graph search; f(g, node) gives the priority."""
    frontier = [(f(0, start), 0, [start])]
    best_g = {start: 0}
    expanded = []
    while frontier:
        _, g, path = heapq.heappop(frontier)
        node = path[-1]
        if g > best_g.get(node, float("inf")):
            continue
        expanded.append(node)
        if node == goal:
            return path, expanded
        for child, w in sorted(GRAPH[node].items()):
            g2 = g + w
            if g2 < best_g.get(child, float("inf")):
                best_g[child] = g2
                heapq.heappush(frontier, (f(g2, child), g2, path + [child]))
    return None, expanded


def greedy(start, goal):
    return best_first(start, goal, lambda g, n: H[n])        # f = h


def astar(start, goal):
    return best_first(start, goal, lambda g, n: g + H[n])    # f = g + h

The main drawback of A* is memory, since it keeps every generated node. Iterative-deepening A* (IDA*) applies Korf’s iterative-deepening idea with a threshold on f instead of depth. It needs only memory linear in the solution depth and remains optimal with an admissible heuristic [22].

5Heuristics and optimization

Designing admissible heuristics

The quality of a heuristic largely determines the cost of informed search. The 8-puzzle shows how to obtain good heuristics systematically [1,40]. Two classic heuristics are h1, the number of misplaced tiles, and h2, the sum of the Manhattan (city-block) distances of the tiles from their goal squares. Both are admissible, because every misplaced tile needs at least one move, and in fact at least its Manhattan distance in moves.

Three ideas explain where such heuristics come from and how to compare them [1,40]:

  • Relaxed problems. The cost of an optimal solution to a relaxed problem, one with fewer restrictions on the actions, is an admissible and consistent heuristic for the original. If a tile could move anywhere in one step, the optimal cost would be h1. If a tile could slide onto an occupied neighbouring square, it would be h2.
  • Dominance. If h2(n) ≥ h1(n) for all n and both are admissible, A* with h2 never expands more nodes than with h1, apart from ties. Given several admissible heuristics, max(h1, …, hk) is admissible and dominates each one.
  • Pattern databases. Store the exact solution cost of every configuration of a subset of the tiles, computed by searching backward from the goal. Culberson and Schaeffer introduced pattern databases for the 15-puzzle [41], and Korf used them to find the first optimal solutions to random instances of Rubik’s Cube [30].

The program below measures the effect of dominance. It draws 30 random instances at each of four solution depths and counts the nodes A* expands with no heuristic (which is uniform-cost search), with h1, and with h2.

Listing 3puzzle8.py
import heapq
import random

GOAL = (1, 2, 3, 4, 5, 6, 7, 8, 0)          # 0 is the blank
MOVES = {0: (1, 3), 1: (0, 2, 4), 2: (1, 5), 3: (0, 4, 6), 4: (1, 3, 5, 7),
         5: (2, 4, 8), 6: (3, 7), 7: (4, 6, 8), 8: (5, 7)}


def neighbours(state):
    z = state.index(0)
    for j in MOVES[z]:
        s = list(state)
        s[z], s[j] = s[j], s[z]
        yield tuple(s)


def h_zero(state):                          # A* with h = 0 is uniform-cost search
    return 0


def h_misplaced(state):                     # h1: number of misplaced tiles
    return sum(1 for i, t in enumerate(state) if t and t != GOAL[i])


def h_manhattan(state):                     # h2: sum of city-block distances
    total = 0
    for i, t in enumerate(state):
        if t:
            g = GOAL.index(t)
            total += abs(i // 3 - g // 3) + abs(i % 3 - g % 3)
    return total


def astar(start, h):
    """Return (solution depth, number of nodes expanded)."""
    frontier = [(h(start), 0, start)]
    best_g = {start: 0}
    expanded = 0
    while frontier:
        f, g, s = heapq.heappop(frontier)
        if g > best_g[s]:
            continue
        if s == GOAL:
            return g, expanded
        expanded += 1
        for n in neighbours(s):
            if g + 1 < best_g.get(n, 1 << 30):
                best_g[n] = g + 1
                heapq.heappush(frontier, (g + 1 + h(n), g + 1, n))


def scramble(depth, rng):
    """Random walk away from the goal (always yields a solvable instance)."""
    s, prev = GOAL, None
    for _ in range(depth):
        options = [n for n in neighbours(s) if n != prev]
        prev, s = s, rng.choice(options)
    return s


if __name__ == "__main__":
    rng = random.Random(2026)
    print("depth  instances   UCS(h=0)   A*(h1)   A*(h2)   mean nodes expanded")
    for depth in (8, 12, 16, 20):
        buckets = {"zero": [], "h1": [], "h2": []}
        n = 0
        while n < 30:
            s = scramble(60, rng)
            d, _ = astar(s, h_manhattan)
            if d != depth:
                continue
            n += 1
            for key, h in (("zero", h_zero), ("h1", h_misplaced), ("h2", h_manhattan)):
                buckets[key].append(astar(s, h)[1])
        mean = {k: sum(v) / len(v) for k, v in buckets.items()}
        print(f"{depth:>5}  {n:>9}  {mean['zero']:>9.0f}  {mean['h1']:>7.0f}  {mean['h2']:>7.0f}")

Local search and optimization

In many problems the path does not matter, only the final state does. Examples are the n-queens puzzle, chip layout, and timetabling. Local search keeps a single current state and moves to neighbouring states, using very little memory. The problem is then to optimize an objective function over a state-space landscape (Figure 4) [1].

  • Hill climbing repeatedly moves to the best neighbour and stops when no neighbour is better. It gets stuck on local maxima, ridges and plateaux. From a random 8-queens state, steepest-ascent hill climbing solves only about 14% of instances [1]. Our own run below gives the same figure.
  • Simulated annealing accepts a worsening move of size Δ with probability e−Δ/T, where the temperature T is lowered gradually. Kirkpatrick, Gelatt and Vecchi took the idea from the annealing of metals and applied it to circuit placement and the travelling salesman problem [21].
  • Tabu search forbids recently visited moves to escape cycles. Glover introduced it and gave it its name [23].
  • Genetic algorithms keep a population of states and combine them by selection, crossover and mutation, after Holland [42].
  • Branch and bound is the systematic counterpart. It explores a tree of subproblems and prunes any subproblem whose bound shows it cannot beat the best solution found so far [43].
Listing 4local_search.py
import math
import random


def conflicts(board):
    """Number of attacking queen pairs; board[c] is the row of the queen in column c."""
    n = len(board)
    return sum(1 for a in range(n) for b in range(a + 1, n)
               if board[a] == board[b] or abs(board[a] - board[b]) == b - a)


def hill_climb(n, rng):
    """Steepest-ascent hill climbing; stops at the first local minimum."""
    board = [rng.randrange(n) for _ in range(n)]
    while True:
        current = conflicts(board)
        best, move = current, None
        for col in range(n):
            for row in range(n):
                if row != board[col]:
                    trial = board[:col] + [row] + board[col + 1:]
                    c = conflicts(trial)
                    if c < best:
                        best, move = c, (col, row)
        if move is None:
            return board, current       # no improving neighbour
        board[move[0]] = move[1]


def simulated_annealing(n, rng, t0=2.0, cooling=0.995, steps=20000):
    board = [rng.randrange(n) for _ in range(n)]
    cost, t = conflicts(board), t0
    for _ in range(steps):
        if cost == 0:
            break
        col, row = rng.randrange(n), rng.randrange(n)
        trial = board[:col] + [row] + board[col + 1:]
        delta = conflicts(trial) - cost
        # always accept improvements; accept a worse move with prob e^(-delta/T)
        if delta <= 0 or rng.random() < math.exp(-delta / t):
            board, cost = trial, cost + delta
        t = max(t * cooling, 1e-3)
    return board, cost


if __name__ == "__main__":
    rng = random.Random(7)
    trials = 200
    hc = sum(hill_climb(8, rng)[1] == 0 for _ in range(trials))
    sa = sum(simulated_annealing(8, rng)[1] == 0 for _ in range(trials))
    print(f"8-queens, {trials} random starts")
    print(f"  steepest-ascent hill climbing solved {hc} ({100 * hc / trials:.0f}%)")
    print(f"  simulated annealing solved          {sa} ({100 * sa / trials:.0f}%)")

6Constraint satisfaction problems

Many problems are naturally described not by actions but by variables that must take mutually compatible values. Examples are timetables, Sudoku, frequency assignment and map colouring. Montanari formalized such networks of constraints in 1974 for picture processing [17], and constraint programming has since become a field of its own [44,45].

Definition 3 · Constraint satisfaction problem

A CSP is a triple (X, D, C): variables X = {X1, …, Xn}, a domain Di of values for each variable, and constraints C, each of which names a subset of variables and the combinations of values allowed for them. A solution is a complete assignment that satisfies every constraint [1].

The standard teaching example is colouring the seven states and territories of Australia with three colours so that no two neighbours share a colour [1]. A binary CSP can be drawn as a constraint graph (Figure 5), with an edge for each constraint. Mainland and island are separate components, so Tasmania can be solved independently.

Constraint propagation

A CSP solver can infer before it searches. A variable Xi is arc-consistent with respect to Xj if every value in Di has some supporting value in Dj. Mackworth’s AC-3 algorithm keeps a queue of arcs and deletes unsupported values. Whenever a domain shrinks, it re-queues the arcs pointing into that variable [18]. For n variables with domains of size at most d and c binary constraints, AC-3 runs in O(cd3) time [1]. Stronger notions such as path consistency and k-consistency trade more inference for less search [17,44].

Backtracking search and its heuristics

Backtracking search assigns one variable at a time and undoes the last choice when a constraint fails. Haralick and Elliott showed that looking ahead pays off. Forward checking removes inconsistent values from the domains of unassigned neighbours as soon as a value is assigned, and the “fail-first” principle chooses the variable most likely to fail next [46]. Modern solvers combine several such heuristics [1,44]:

  • Minimum remaining values (MRV): pick the variable with the fewest legal values left. This is the fail-first principle.
  • Degree heuristic: break ties by picking the variable involved in the most constraints on unassigned variables.
  • Least-constraining value: try first the value that rules out the fewest choices for the neighbours.
  • Maintaining arc consistency (MAC): run AC-3 after each assignment, starting from the arcs into the assigned variable.

With these heuristics the solver below colours Australia with seven assignments and no backtracking. MRV first chooses SA because it has the highest degree.

Listing 5csp.py
from collections import deque

# Map colouring of Australia's states and territories (Figure 5)
VARIABLES = ["WA", "NT", "SA", "Q", "NSW", "V", "T"]
NEIGHBOURS = {
    "WA": ["NT", "SA"], "NT": ["WA", "SA", "Q"], "SA": ["WA", "NT", "Q", "NSW", "V"],
    "Q": ["NT", "SA", "NSW"], "NSW": ["Q", "SA", "V"], "V": ["SA", "NSW"], "T": [],
}
COLOURS = ["red", "green", "blue"]


def consistent(x, vx, y, vy):
    return vx != vy                 # binary "different colours" constraint


def revise(domains, x, y):
    """Delete values of x that have no supporting value in y's domain."""
    removed = False
    for vx in list(domains[x]):
        if not any(consistent(x, vx, y, vy) for vy in domains[y]):
            domains[x].remove(vx)
            removed = True
    return removed


def ac3(domains, queue=None):
    """Mackworth's AC-3. Returns False if some domain becomes empty."""
    queue = deque(queue if queue is not None else
                  [(x, y) for x in domains for y in NEIGHBOURS[x]])
    while queue:
        x, y = queue.popleft()
        if revise(domains, x, y):
            if not domains[x]:
                return False
            for z in NEIGHBOURS[x]:
                if z != y:
                    queue.append((z, x))
    return True


def select_variable(assignment, domains):
    """MRV, with the degree heuristic as tie-breaker."""
    unassigned = [v for v in VARIABLES if v not in assignment]
    return min(unassigned, key=lambda v: (len(domains[v]),
               -sum(1 for n in NEIGHBOURS[v] if n not in assignment)))


def order_values(var, assignment, domains):
    """Least-constraining value first."""
    def ruled_out(value):
        return sum(value in domains[n] for n in NEIGHBOURS[var] if n not in assignment)
    return sorted(domains[var], key=ruled_out)


def backtrack(assignment, domains, stats):
    if len(assignment) == len(VARIABLES):
        return assignment
    var = select_variable(assignment, domains)
    for value in order_values(var, assignment, domains):
        stats["assignments"] += 1
        local = {v: list(d) for v, d in domains.items()}
        local[var] = [value]
        # maintain arc consistency (MAC) after each assignment
        if ac3(local, [(n, var) for n in NEIGHBOURS[var]]):
            result = backtrack({**assignment, var: value}, local, stats)
            if result:
                return result
    return None


if __name__ == "__main__":
    domains = {v: list(COLOURS) for v in VARIABLES}
    stats = {"assignments": 0}
    solution = backtrack({}, domains, stats)
    print(solution)
    print("value assignments tried:", stats["assignments"])

Local search for CSPs

The min-conflicts heuristic starts from a complete but inconsistent assignment. It repeatedly picks a conflicted variable and gives it the value that violates the fewest constraints. Minton and colleagues showed that it solves very large n-queens problems quickly. The run time is roughly independent of n, and the million-queens problem takes about 50 steps on average after the initial assignment. They also applied it to scheduling observations for the Hubble Space Telescope [1,24].

Map colouring also links CSPs to theorem proving. Appel and Haken proved that every planar map can be coloured with four colours. Their proof relied on a computer to check a large set of unavoidable configurations [47]. Gonthier later verified a complete proof in the Coq proof assistant [48].

7Adversarial search and game trees

In a two-player, zero-sum game of perfect information, such as chess, checkers, Go or tic-tac-toe, an agent must plan against an opponent who wants the opposite outcome. Von Neumann’s minimax theorem supplies the solution concept [3]. The minimax value of a position is its utility for MAX at terminal positions. Otherwise it is the maximum of the children’s values when MAX is to move and the minimum when MIN is to move:

Minimax(s) = Utility(s) if Terminal(s); maxa Minimax(Result(s,a)) if MAX moves; mina Minimax(Result(s,a)) if MIN moves.

Shannon estimated that chess has about 10120 possible games, far too many to search [4]. He therefore proposed cutting the search off at a fixed depth and scoring the frontier positions with a heuristic evaluation function. Samuel went further and let his checkers program learn its evaluation function from play [8].

Alpha-beta pruning

Alpha-beta pruning returns the same value as minimax while skipping branches that cannot affect the decision. It carries two bounds: α, the best value MAX can guarantee so far on the current path, and β, the best value MIN can guarantee. When α ≥ β at a node, its remaining children are pruned. Knuth and Moore gave the definitive analysis [19]. With perfect move ordering, alpha-beta examines b⌈d/2⌉ + b⌊d/2⌋ − 1 leaf positions of a uniform tree of depth d instead of bd. In effect this doubles the depth that can be searched in the same time.

Tic-tac-toe is small enough to search exhaustively. The program below confirms the well-known result that perfect play gives a draw. It also counts how much of the tree alpha-beta avoids with the naive move order (cells 0 to 8).

    w = winner(board)
    if w:
        return 1 if w == "X" else -1
    return 0 if "." not in board else None

    return [i for i, cell in enumerate(board) if cell == "."]

    return board[:i] + player + board[i + 1:]

    counter[0] += 1
    u = terminal_utility(board)
    if u is not None:
        return u
    values = [minimax(play(board, i, player), "O" if player == "X" else "X", counter)
              for i in moves(board)]
    return max(values) if player == "X" else min(values)

    counter[0] += 1
    u = terminal_utility(board)
    if u is not None:
        return u
    if player == "X":                       # MAX node
        value = -math.inf
        for i in moves(board):
            value = max(value, alphabeta(play(board, i, "X"), "O", alpha, beta, counter))
            alpha = max(alpha, value)
            if alpha >= beta:
                break                       # beta cut-off: MIN will avoid this branch
        return value
    value = math.inf                        # MIN node
    for i in moves(board):
        value = min(value, alphabeta(play(board, i, "O"), "X", alpha, beta, counter))
        beta = min(beta, value)
        if alpha >= beta:
            break                           # alpha cut-off
    return value

Monte Carlo tree search

For games with very large branching factors and no good hand-written evaluation function, such as Go, Monte Carlo tree search (MCTS) estimates the value of a position by the average outcome of simulated playouts. Each iteration has four steps: selection down the tree, expansion of a new node, simulation to the end of the game, and back-propagation of the result. Kocsis and Szepesvári’s UCT rule selects the child that maximizes X̄j + C√(ln n / nj), which balances exploiting good moves against exploring rarely tried ones. They proved that it converges to the minimax move [36]. AlphaGo replaced random playouts with policy and value networks trained on expert games and self-play, and defeated the European Go champion 5 games to 0 [38]. AlphaZero then learned chess, shogi and Go from self-play alone, given only the rules [39].

8Classical planning and scheduling

Planning is search in which states and actions are described in a structured, logical language, so that domain-independent algorithms can exploit that structure [1,49]. Classical planning assumes a fully observable, deterministic, static world with a known initial state and goals of reaching a set of states.

The STRIPS representation and PDDL

Fikes and Nilsson’s STRIPS was built at SRI to plan actions for a mobile robot [15]. Its representation has outlived the program. A state is a set of ground atoms, with every atom not in the set taken to be false (the closed-world assumption). An action schema has a precondition list, an add list and a delete list. An action a is applicable in state s if Pre(a) ⊆ s, and its result is

Result(s, a) = (s − Del(a)) ∪ Add(a).

The Planning Domain Definition Language (PDDL) standardized this notation for the 1998 planning competition and has been extended many times since [32]. The blocks-world move action looks like this:

Blocks-world move in PDDLaction schema
(:action move
  :parameters (?b ?x ?y)
  :precondition (and (on ?b ?x) (clear ?b) (clear ?y)
                     (block ?b) (block ?y) (not (= ?b ?y)))
  :effect (and (on ?b ?y) (clear ?x)
               (not (on ?b ?x)) (not (clear ?y))))

Planning as state-space search

The simplest planner is forward (progression) search from the initial state. Backward (regression) search starts from the goal and considers only relevant actions. Plan existence for propositional STRIPS is PSPACE-complete in general [27], so practical planners depend on good domain-independent heuristics. The most influential idea is the delete relaxation, which ignores every action’s delete list. Bonet and Geffner’s HSP derived heuristics from it [33]. Hoffmann and Nebel’s FF extracted an explicit relaxed plan and combined it with enforced hill-climbing [34]. Helmert’s Fast Downward translates tasks into a multi-valued representation and searches with heuristics computed from its causal graph [35]. Two other families compile planning into different problems. Graphplan builds a layered planning graph with mutual-exclusion relations [29]. SATPLAN encodes “is there a plan of length k?” as a propositional formula and hands it to a SAT solver [25].

The program below grounds the two blocks-world schemas for three blocks and runs breadth-first progression search. It finds the optimal three-step plan, and the visited set confirms that the three-block world has 13 states.

Listing 7strips.py
from collections import deque, namedtuple
from itertools import permutations

Action = namedtuple("Action", "name pre add delete")
BLOCKS = ["A", "B", "C"]


def blocks_world_actions(blocks):
    """Ground the STRIPS schemas Move(b, x, y) and MoveToTable(b, x)."""
    actions = []
    for b, x, y in permutations(blocks + ["Table"], 3):
        if b == "Table" or y == "Table":
            continue
        pre = {f"On({b},{x})", f"Clear({b})", f"Clear({y})"}
        add = {f"On({b},{y})"} | ({f"Clear({x})"} if x != "Table" else set())
        actions.append(Action(f"Move({b},{x},{y})", frozenset(pre), frozenset(add),
                              frozenset({f"On({b},{x})", f"Clear({y})"})))
    for b, x in permutations(blocks, 2):
        actions.append(Action(f"MoveToTable({b},{x})",
                              frozenset({f"On({b},{x})", f"Clear({b})"}),
                              frozenset({f"On({b},Table)", f"Clear({x})"}),
                              frozenset({f"On({b},{x})"})))
    return actions


def progress(state, action):
    """STRIPS progression: s' = (s - Del(a)) | Add(a)."""
    return (state - action.delete) | action.add


def forward_bfs(initial, goal, actions):
    """Forward state-space search; returns a shortest plan."""
    start = frozenset(initial)
    frontier = deque([(start, [])])
    seen = {start}
    while frontier:
        state, plan = frontier.popleft()
        if goal <= state:
            return plan, len(seen)
        for a in actions:
            if a.pre <= state:
                nxt = progress(state, a)
                if nxt not in seen:
                    seen.add(nxt)
                    frontier.append((nxt, plan + [a.name]))
    return None, len(seen)


if __name__ == "__main__":
    # Sussman anomaly: C is on A; A and B are on the table. Goal: A on B on C.
    init = {"On(C,A)", "On(A,Table)", "On(B,Table)", "Clear(C)", "Clear(B)"}
    goal = {"On(A,B)", "On(B,C)"}
    plan, states = forward_bfs(init, goal, blocks_world_actions(BLOCKS))
    for step, name in enumerate(plan, 1):
        print(step, name)
    print("distinct states generated:", states)

Scheduling

A planner decides which actions to take. A scheduler decides when they happen and which resources they use, subject to durations, precedence constraints, deadlines and capacity limits [1,49]. The critical-path method (CPM) of Kelley and Walker handles the case of precedence constraints with no resource limits [9]. A forward pass over the precedence graph gives each task’s earliest start (ES) and finish (EF). A backward pass from the project’s makespan gives the latest start (LS) and finish (LF). Tasks with zero slack (LS − ES) form the critical path, and delaying any of them delays the whole project.

Listing 8cpm.py
# Critical-path method for a small assembly project (durations in days)
TASKS = {            # name: (duration, predecessors)
    "A Design":     (3, []),
    "B Order parts": (5, ["A Design"]),
    "C Build frame": (3, ["A Design"]),
    "D Fit parts":  (2, ["B Order parts", "C Build frame"]),
    "E Wiring":     (2, ["C Build frame"]),
    "F Test":       (2, ["D Fit parts", "E Wiring"]),
}


def critical_path(tasks):
    order, done = [], set()
    while len(order) < len(tasks):          # topological order of the precedence DAG
        for t, (_, preds) in tasks.items():
            if t not in done and all(p in done for p in preds):
                order.append(t)
                done.add(t)
    es, ef = {}, {}
    for t in order:                          # forward pass: earliest start / finish
        es[t] = max((ef[p] for p in tasks[t][1]), default=0)
        ef[t] = es[t] + tasks[t][0]
    makespan = max(ef.values())
    ls, lf = {}, {}
    for t in reversed(order):                # backward pass: latest start / finish
        succs = [s for s in tasks if t in tasks[s][1]]
        lf[t] = min((ls[s] for s in succs), default=makespan)
        ls[t] = lf[t] - tasks[t][0]
    return order, es, ef, ls, lf, makespan


if __name__ == "__main__":
    order, es, ef, ls, lf, makespan = critical_path(TASKS)
    print(f"{'task':<14}{'ES':>4}{'EF':>4}{'LS':>4}{'LF':>4}{'slack':>7}")
    for t in order:
        slack = ls[t] - es[t]
        print(f"{t:<14}{es[t]:>4}{ef[t]:>4}{ls[t]:>4}{lf[t]:>4}{slack:>7}"
              + ("   critical" if slack == 0 else ""))

9Hierarchical task networks

People rarely plan at the level of primitive actions. They decompose “travel to the conference” into “book flight”, “get to airport” and so on. Hierarchical task network (HTN) planning captures this. The input is not a goal state but a network of tasks to perform, together with methods that say how each compound task can be decomposed into subtasks [26,49]. Planning proceeds by repeatedly replacing a compound task with the subtasks of an applicable method until only primitive tasks remain. Each primitive task corresponds to a STRIPS-style operator.

Sacerdoti’s NOAH introduced hierarchical, partially ordered plans in the 1970s [20]. O-Plan developed the approach into a practical planning architecture [52]. Erol, Hendler and Nau gave HTN planning a formal semantics. They showed that it is strictly more expressive than STRIPS-style planning and that plan existence is undecidable in general, though decidable under restrictions such as requiring every task network to be totally ordered [26]. SHOP2 decomposes tasks in the same order they will be executed. It therefore always knows the complete current state and can evaluate rich preconditions, including numeric ones [53].

The program below is a minimal total-order HTN planner in the style of SHOP. Its operators and methods are ordinary Python functions. It plans a short trip on foot and a long trip by taxi.

        return s

    s = deepcopy(state); s["loc"]["taxi"] = a
    return s

        s = deepcopy(state); s["loc"]["taxi"] = b; s["loc"][who] = b
        s["owe"][who] = 1.5 + 0.5 * state["dist"][a][b]
        return s

        return s

            result = seek_plan(state, subtasks + rest, plan, depth + 1, trace)
            if result is not None:
                return result
    return None

10Automated theorem proving

Theorem proving was one of the first problems attacked in AI. The Logic Theory Machine of 1956 searched for proofs of theorems from Principia Mathematica, guided by heuristics modelled on human problem solving [5]. The modern field rests on a different, machine-oriented foundation [54].

Resolution and unification

Robinson’s resolution principle uses a single inference rule. From clauses (A ∨ L) and (B ∨ ¬L′), where L and L′ are made identical by a substitution θ, infer (A ∨ B)θ [13]. The substitution is computed by unification, and Robinson showed how to find the most general unifier. To prove that a knowledge base KB entails φ, a prover converts KB ∧ ¬φ to clausal form and derives the empty clause, a contradiction. Resolution is refutation-complete for first-order logic: if the clauses are unsatisfiable, the empty clause can be derived [1,13]. First-order entailment is only semi-decidable, so a prover may run forever on a non-theorem.

Satisfiability and DPLL

For propositional logic, proving φ amounts to showing that ¬φ is unsatisfiable. Davis and Putnam gave an elimination procedure [11]. Davis, Logemann and Loveland replaced its memory-hungry elimination step with backtracking search on variable assignments, combined with unit propagation and pure-literal elimination [12]. The result, DPLL, is a depth-first search of exactly the kind described in Section 3. Cook proved that satisfiability is NP-complete, which links theorem proving to the whole class NP [16]. Modern conflict-driven clause learning (CDCL) solvers, beginning with GRASP, analyse each conflict and add a learned clause that prevents the same failure from recurring [55]. Satisfiability modulo theories (SMT) solvers such as Z3 extend SAT with theories of arithmetic, arrays and bit-vectors [56]. First-order provers such as Vampire combine resolution and superposition with careful indexing and strategy selection [57].

The program below implements propositional resolution by saturation, a small DPLL solver, and first-order unification with the occurs check. The resolution log lists every new resolvent in the order it was generated, so it includes some steps that the final proof does not use.

Listing 10prover.py
from itertools import combinations

# ---------- Propositional resolution ----------
# A clause is a frozenset of literals; a literal is "P" or "~P".

def negate(lit):
    return lit[1:] if lit.startswith("~") else "~" + lit


def resolve(c1, c2):
    """All resolvents of two clauses (tautologies are discarded)."""
    out = []
    for lit in c1:
        if negate(lit) in c2:
            r = (c1 - {lit}) | (c2 - {negate(lit)})
            if not any(negate(x) in r for x in r):
                out.append(frozenset(r))
    return out


def resolution_refutation(kb, query):
    """Prove KB |= query by deriving the empty clause from KB + {~query}."""
    clauses = set(kb) | {frozenset({negate(query)})}
    derivation = []
    while True:
        new = set()
        for c1, c2 in combinations(sorted(clauses, key=sorted), 2):
            for r in resolve(c1, c2):
                if r not in clauses and r not in new:
                    derivation.append((set(c1), set(c2), set(r)))
                if not r:
                    return True, derivation
                new.add(r)
        if new <= clauses:
            return False, derivation          # saturated: no proof exists
        clauses |= new


# ---------- DPLL satisfiability ----------

def dpll(clauses, model=None):
    model = dict(model or {})
    clauses = [set(c) for c in clauses]
    while True:                                # unit propagation
        units = [next(iter(c)) for c in clauses if len(c) == 1]
        if not units:
            break
        lit = units[0]
        model[lit.lstrip("~")] = not lit.startswith("~")
        clauses = [c - {negate(lit)} for c in clauses if lit not in c]
        if any(not c for c in clauses):
            return None
    if not clauses:
        return model
    lit = next(iter(clauses[0]))               # branch on some literal
    for choice in (lit, negate(lit)):
        result = dpll(clauses + [{choice}], model)
        if result is not None:
            return result
    return None

# Variables are strings starting with a lower-case letter, e.g. "x".
# Compound terms are tuples: ("Knows", "John", "x").

def is_var(t):
    return isinstance(t, str) and t[0].islower()


def substitute(t, theta):
    while is_var(t) and t in theta:
        t = theta[t]
    if isinstance(t, tuple):
        return tuple(substitute(a, theta) for a in t)
    return t


def occurs(v, t, theta):
    t = substitute(t, theta)
    return t == v or (isinstance(t, tuple) and any(occurs(v, a, theta) for a in t))


def unify(x, y, theta=None):
    """Most general unifier of x and y (Robinson, 1965), or None."""
    theta = {} if theta is None else theta
    x, y = substitute(x, theta), substitute(y, theta)
    if x == y:
        return theta
    if is_var(x):
        return None if occurs(x, y, theta) else {**theta, x: y}
    if is_var(y):
        return unify(y, x, theta)
    if isinstance(x, tuple) and isinstance(y, tuple) and len(x) == len(y):
        for a, b in zip(x, y):
            theta = unify(a, b, theta)
            if theta is None:
                return None
        return theta
    return None

Notable results

In 1996 McCune’s prover EQP found a proof that every Robbins algebra is Boolean. This settled a question that had been open since the 1930s and that mathematicians had been unable to resolve [31]. Gonthier’s machine-checked proof of the four-colour theorem shows the complementary approach. There a human guides an interactive proof assistant, and the machine checks every step [48].

Connections

The topics in this article form one family. Planning, scheduling and CSPs can be compiled into satisfiability [25]. Theorem proving and DPLL are search. STRIPS was originally conceived as an application of theorem proving to problem solving [15]. Game-tree search and planning meet in Monte Carlo tree search, which Kocsis and Szepesvári presented as a planning algorithm [36]. In each case, the questions are how to represent the space, how to estimate which parts of it are promising, and how to avoid exploring the rest.

Exercise 1 Uninformed search

Run breadth-first search on Figure 2 from S to G with the goal test applied when a node is expanded instead of generated. Which nodes are expanded, and which path is returned?

Solution

The queue evolves as S → A, B → B, C → C, D → D, G → G. Expanding S adds A and B. Expanding A adds C (B is already reached). Expanding B adds D. Expanding C adds G. Expanding D adds nothing new, because G is already reached. G is then expanded and recognised as the goal. Expanded nodes: S, A, B, C, D, G. Path: S–A–C–G, cost 9. The result is the same as before, but one extra layer of work is done. That is why BFS normally tests on generation [1].

Exercise 2 Iterative deepening

For a uniform tree with b = 10 and a goal at depth d = 5, compare the number of nodes generated by iterative deepening with the number generated by BFS, counting the root once and ignoring the goal test.

Solution

Iterative deepening generates nodes at depth i exactly d − i + 1 times, for i ≥ 1: N(IDS) = 5·10 + 4·100 + 3·1,000 + 2·10,000 + 1·100,000 = 123,450. BFS generates 10 + 100 + 1,000 + 10,000 + 100,000 = 111,110. The overhead is about 11%, which is why iterative deepening is the preferred uninformed method when the search space is large and the solution depth is unknown [1,22].

Exercise 3 Heuristics · proof

(a) Prove that every consistent heuristic is admissible. (b) Verify that the heuristic in Figure 2 is consistent.

Solution

(a) Induction on the number of steps k in an optimal path from n to a goal. If k = 0, n is a goal and h(n) = 0 = h*(n). Otherwise let n′ be the next node on an optimal path. By consistency h(n) ≤ c(n, a, n′) + h(n′). By the induction hypothesis h(n′) ≤ h*(n′). So h(n) ≤ c(n, a, n′) + h*(n′) = h*(n).

(b) Check h(u) ≤ c(u,v) + h(v) in both directions of each edge. S–A: 6 ≤ 1+5, 5 ≤ 1+6. S–B: 6 ≤ 4+3, 3 ≤ 4+6. A–B: 5 ≤ 2+3, 3 ≤ 2+5. A–C: 5 ≤ 5+3, 3 ≤ 5+5. B–C: 3 ≤ 1+3, 3 ≤ 1+3. B–D: 3 ≤ 6+1, 1 ≤ 6+3. C–G: 3 ≤ 3+0, 0 ≤ 3+3. D–G: 1 ≤ 1+0, 0 ≤ 1+1. All hold. C–G and D–G hold with equality, so h is exact there.

Exercise 4 Greedy versus A*

Replace the heuristic in Figure 2 with the exact remaining cost, h = h*. Which path does greedy best-first search return, and which nodes does A* expand?

Solution

The exact costs are S=7, A=6, B=4, C=3, D=1, G=0. Greedy expands S, then B (h=4, preferred to A’s 6). Expanding B puts C (h=3) and D (h=1) on the frontier, so greedy expands D, then G, and returns S–B–D–G at cost 11. Even a perfect heuristic does not make greedy search optimal, because h* ranks states by distance to go, while greedy needs to rank paths by total cost, and it ignores the cost already paid. A* with h* computes f = 7 exactly for every node on an optimal path. It expands S, A, B, C and G and nothing else [1].

Exercise 6 Combining heuristics

Is max(h1, h2) admissible for the 8-puzzle? Is h1 + h2?

Solution

The maximum of admissible heuristics is admissible, since each is at most h* [1]. Here it simply equals h2, because h2 ≥ h1 always. The sum is not admissible. Figure 3 gives a counterexample: h1 + h2 = 5 + 10 = 15, but the optimal solution takes only 14 moves.

Exercise 7 Simulated annealing

A move increases the number of attacking queen pairs by Δ = 2. What is the probability that simulated annealing accepts it at T = 1, T = 0.5 and T = 5?

Solution

The acceptance probability is e−Δ/T [21]. At T = 1: e−2 ≈ 0.135. At T = 0.5: e−4 ≈ 0.018. At T = 5: e−0.4 ≈ 0.670. High temperatures allow exploration, and as T → 0 the algorithm behaves like hill climbing.

Exercise 8 Constraint propagation

In the Australia CSP, assign WA = red and Q = green. Show that forward checking leaves every domain non-empty, but arc consistency detects that the partial assignment cannot be extended.

Solution

Forward checking removes red from NT and SA (neighbours of WA), and green from NT, SA and NSW (neighbours of Q). That leaves NT = {blue}, SA = {blue} and NSW = {red, blue}, with no domain empty. Arc consistency then checks the arc NT–SA. NT’s only value, blue, has no support in SA, whose only value is also blue. NT’s domain becomes empty, so the assignment fails without further search [1,18].

Exercise 9 Modelling

Formulate 9×9 Sudoku as a CSP. How many binary “not equal” constraints are needed if each all-different constraint is expanded into pairs?

Solution

Use 81 variables, one per cell. Each domain is {1,…,9}, reduced to a single value for each given clue. There are 27 all-different constraints: 9 rows, 9 columns and 9 boxes. Each cell shares a row, column or box with 8 + 8 + 4 = 20 distinct peers. The number of binary constraints is therefore 81 × 20 / 2 = 810.

Exercise 10 Alpha-beta

In Figure 6, reorder the leaves under the third MIN node so that alpha-beta prunes as much as possible. How many leaves are evaluated in total?

Solution

Put the 2 first (2, 14, 5, or 2, 5, 14). After seeing 2, that MIN node is worth at most 2, which is less than α = 3, so its remaining two leaves are pruned. In total 3 + 1 + 1 = 5 of the 9 leaves are evaluated. The root value is still 3. Good move ordering is what brings alpha-beta close to its best case [19].

Exercise 11 Complexity

Chess has an average branching factor of roughly 35 [1]. How many leaf positions does a 4-ply minimax search evaluate, and how many does alpha-beta evaluate with perfect ordering?

Solution

Minimax evaluates 354 = 1,500,625 leaves. By the Knuth–Moore formula, alpha-beta with perfect ordering evaluates 352 + 352 − 1 = 2,449 [19]. That is about 0.16% of the minimax total.

Exercise 13 Planning

Explain why a planner that achieves goals one at a time and never undoes an achieved goal cannot solve the Sussman anomaly.

Solution

If it achieves On(A,B) first, it must clear A by moving C to the table and then stack A on B. To achieve On(B,C) it must then move B, which requires removing A and undoing the first goal. If it achieves On(B,C) first, B sits on C, which sits on A, so A cannot be moved onto B without dismantling the stack and undoing the second goal. Either order of goals fails. The only solutions interleave steps for the two goals. Planners that search the whole state space or work with partially ordered plans avoid the problem [1,20].

Exercise 14 Code · scheduling

In the CPM example, task C slips by 3 days, so its duration becomes 6. What is the new makespan, and what is the new critical path?

Solution

C now finishes on day 3 + 6 = 9. D can start only after both B (day 8) and C (day 9) finish, so D runs from 9 to 11 and F from 11 to 13. The makespan grows from 12 to 13 days. C had 2 days of slack, so 3 days of slip delays the project by 1 day. Wiring (E) now also runs from day 9 to 11 with no slack, so there are two critical paths, A–C–D–F and A–C–E–F. B now has 1 day of slack. Changing the duration in cpm.py confirms this.

Exercise 16 Theorem proving

(a) Prove R from P ∨ Q, P ⇒ R and Q ⇒ R by resolution. (b) Unify Knows(John, x) with Knows(x, Elizabeth). What goes wrong, and how is it fixed?

Solution

(a) The clauses are {P, Q}, {¬P, R}, {¬Q, R} and the negated goal {¬R}. Resolving {¬P, R} with {¬R} gives {¬P}. Resolving {¬Q, R} with {¬R} gives {¬Q}. Resolving {P, Q} with {¬P} gives {Q}. Resolving {Q} with {¬Q} gives the empty clause.

(b) Unification fails, because x would have to be both John and Elizabeth. The two sentences are separate universally quantified clauses, so their variables are unrelated. Standardizing apart renames them, for example to Knows(x1, Elizabeth). Unification then succeeds with {x/Elizabeth, x1/John} [1,13].
