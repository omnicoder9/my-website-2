Evolutionary Computation and Nature-Inspired AI

How variation, selection, inheritance and collective behaviour, borrowed from biology, became a family of general-purpose search and learning algorithms. The article covers the theory, history, working Python code, diagrams and exercises with solutions.

Introduction

Evolutionary computation (EC) is the study of algorithms that solve problems by imitating the process Darwin described: a population of candidates varies, the fitter ones leave more descendants, and useful traits accumulate over generations[1]. Nature-inspired AI widens the frame to other natural processes that produce intelligent-looking behaviour without central control, such as bird flocks, ant trails and developing organisms[2].

These methods are black-box or zeroth-order optimisers. They need only a way to score a candidate, not a gradient, a convex objective or a closed-form model. That makes them useful for rugged, discontinuous, noisy, combinatorial or multi-objective problems, and for designing structures such as programs, circuits, antennas and neural network architectures[3–5]. The price is cost: they usually need many more evaluations than a gradient method on a smooth problem, and the No Free Lunch theorems show that no optimiser beats every other one when performance is averaged over all possible problems[6]. In practice the value of EC comes from matching the representation and operators to the structure of a problem.

Every program in this article is plain Python 3 using only the standard library and NumPy. Each was run as printed, and its output appears beneath it.

A short history

The idea that evolution could be used as a computing method appeared almost as soon as there were computers. Turing suggested in 1950 that a learning machine could be found by a process resembling evolution, with "mutations" judged by an experimenter acting as natural selection[7]. Barricelli ran numerical evolution experiments on the von Neumann computer at Princeton in the early 1950s[8], and Fraser simulated genetic systems in 1957[9]. Box proposed "evolutionary operation" for improving industrial processes in the same year[10], and Bremermann applied evolution and recombination to optimisation by 1962[11].

Three independent schools then formed. In the United States, Lawrence Fogel and colleagues introduced evolutionary programming, evolving finite-state machines to predict symbol sequences[12]. In Berlin, Ingo Rechenberg and Hans-Paul Schwefel developed evolution strategies to optimise physical engineering designs, first by hand and then on computers[13–15]. At Michigan, John Holland developed genetic algorithms as a theory of adaptive systems[16], popularised later by Goldberg's textbook[17]. The schools merged into the single field of evolutionary computation during the 1990s[3,18].

The common framework

Nearly every algorithm in this article fits one loop, shown in Figure 1. A representation (genotype) encodes a candidate solution (phenotype). A fitness function scores phenotypes. Parent selection chooses who reproduces, variation operators (recombination and mutation) create offspring, and survivor selection decides who enters the next generation[3]. Two forces are in tension throughout: exploitation (concentrating search near good solutions, driven by selection) and exploration (maintaining diversity, driven by variation).

SECTION 1Genetic algorithms

Holland's genetic algorithm (GA) represents candidates as fixed-length strings, classically binary, and emphasises recombination as the main search operator, with mutation as a background operator that restores lost alleles[16,17,39]. A canonical GA uses fitness-proportional ("roulette-wheel") selection, one-point crossover and bitwise mutation. Modern practice prefers tournament or rank selection because they are insensitive to the scale of the fitness function[3].

Operators

The schema theorem

Holland explained GA behaviour through schemata, templates over the alphabet {0, 1, *} where * matches either symbol. The schema 1**0*1 has order o(H) = 3 (fixed positions) and defining length δ(H) = 5 (distance between the outermost fixed positions). Under fitness-proportional selection, one-point crossover with probability pc and mutation rate pm, the expected number of instances m(H, t) of schema H satisfies[16,17]:

(1)E[m(H, t+1)] ≥ m(H, t) · (f(H) / f̄) · [ 1 − pc · δ(H) / (L − 1) − o(H) · pm ]

Short, low-order, above-average schemata (building blocks) therefore receive exponentially increasing trials. The theorem is a lower bound that ignores schema creation by crossover, and it does not by itself prove that a GA finds optima. Rudolph showed that a canonical GA without elitism does not converge to the global optimum with probability one, while an elitist variant does[38].

Worked example: the 0/1 knapsack problem

Choose a subset of 10 items to maximise total value without exceeding a weight capacity of 80. A bit string is a natural genotype: bit i = 1 means item i is packed. Infeasible strings receive fitness 0 (a "death penalty"; repair operators and graded penalties are common alternatives[3]).

ga.py
"""Genetic algorithm for the 0/1 knapsack problem."""
import random

VALUES  = [60, 100, 120, 80, 30, 70, 90, 40, 50, 110]
WEIGHTS = [10,  20,  30, 15,  5, 12, 25,  8, 10,  28]
CAPACITY = 80

def fitness(bits):
    w = sum(wi for wi, b in zip(WEIGHTS, bits) if b)
    v = sum(vi for vi, b in zip(VALUES, bits) if b)
    return v if w <= CAPACITY else 0          # death penalty for overweight

def tournament(pop, fits, k=3):
    best = max(random.sample(range(len(pop)), k), key=lambda i: fits[i])
    return pop[best]

def one_point_crossover(a, b):
    cut = random.randint(1, len(a) - 1)
    return a[:cut] + b[cut:], b[:cut] + a[cut:]

def mutate(bits, pm):
    return [1 - b if random.random() < pm else b for b in bits]

def ga(pop_size=40, generations=60, pc=0.9, seed=1):
    random.seed(seed)
    n = len(VALUES)
    pop = [[random.randint(0, 1) for _ in range(n)] for _ in range(pop_size)]
    for g in range(generations):
        fits = [fitness(ind) for ind in pop]
        elite = pop[fits.index(max(fits))]          # elitism: keep the best
        children = [elite[:]]
        while len(children) < pop_size:
            p1, p2 = tournament(pop, fits), tournament(pop, fits)
            c1, c2 = one_point_crossover(p1, p2) if random.random() < pc else (p1[:], p2[:])
            children += [mutate(c1, 1 / n), mutate(c2, 1 / n)]
        pop = children[:pop_size]
    best = max(pop, key=fitness)
    return best, fitness(best)

if __name__ == "__main__":
    best, value = ga()
    print("best:", best, "value:", value,
          "weight:", sum(w for w, b in zip(WEIGHTS, best) if b))
Output
best: [1, 1, 0, 1, 1, 1, 0, 1, 1, 0] value: 430 weight: 80

Exhaustive enumeration of all 210 = 1024 subsets confirms that 430 is the optimum, so the GA found the global solution using about 2,400 fitness evaluations, which here is more than brute force. The advantage appears at scale: with 100 items there are 2100 ≈ 1.3 × 1030 subsets, and the GA's cost grows only with the number of generations and the population size.

SECTION 2Genetic programming

Genetic programming (GP) evolves computer programs. Cramer described tree-structured program evolution in 1985[21], and Koza developed it into a general method in 1992, representing programs as LISP-style expression trees whose internal nodes come from a function set and whose leaves come from a terminal set[27]. Crossover swaps randomly chosen subtrees between parents; mutation replaces a subtree with a newly generated one (Figure 3)[40].

The classic application is symbolic regression: finding a formula, not just coefficients, that fits data. Schmidt and Lipson used GP-based symbolic regression to recover conservation laws and Lagrangians of physical systems from motion-capture data[41]. Koza's work and its successors also produced patentable circuit designs, which helped establish GP as an automated invention method[40].

Worked example: symbolic regression

The program below evolves an expression for y = x³ − 2x + 1 from 21 sample points using the function set {+, −, ×} and terminal set {x, 1}. It uses tournament selection, subtree crossover and mutation, elitism, a depth-limited random initialisation, and a size limit plus a small parsimony term to discourage bloat.

gp.py
"""Tree-based genetic programming: symbolic regression of x**3 - 2x + 1."""
import random, operator, math

FUNCS = [(operator.add, 2, "+"), (operator.sub, 2, "-"), (operator.mul, 2, "*")]
TERMS = ["x", 1.0]

def random_tree(depth):
    if depth == 0 or (depth < 3 and random.random() < 0.3):
        return random.choice(TERMS)
    f = random.choice(FUNCS)
    return [f] + [random_tree(depth - 1) for _ in range(f[1])]

def evaluate(tree, x):
    if tree == "x":
        return x
    if not isinstance(tree, list):
        return tree
    f, _, _ = tree[0]
    return f(*(evaluate(c, x) for c in tree[1:]))

def show(tree):
    if not isinstance(tree, list):
        return str(tree)
    return "(" + f" {tree[0][2]} ".join(show(c) for c in tree[1:]) + ")"

def size(tree):
    return 1 + sum(size(c) for c in tree[1:]) if isinstance(tree, list) else 1

def subtrees(tree, path=()):
    yield path
    if isinstance(tree, list):
        for i, c in enumerate(tree[1:], 1):
            yield from subtrees(c, path + (i,))

def get(tree, path):
    for i in path:
        tree = tree[i]
    return tree

def put(tree, path, new):
    if not path:
        return new
    tree = list(tree)
    tree[path[0]] = put(tree[path[0]], path[1:], new)
    return tree

XS = [i / 5 for i in range(-10, 11)]
TARGET = [x ** 3 - 2 * x + 1 for x in XS]

def error(tree):
    try:
        e = sum(abs(evaluate(tree, x) - y) for x, y in zip(XS, TARGET))
    except OverflowError:
        return math.inf
    return e + 0.01 * size(tree)          # parsimony pressure against bloat

def crossover(a, b):
    pa = random.choice(list(subtrees(a)))
    pb = random.choice(list(subtrees(b)))
    return put(a, pa, get(b, pb))

def mutation(a):
    return put(a, random.choice(list(subtrees(a))), random_tree(2))

def gp(pop_size=300, generations=40, seed=4):
    random.seed(seed)
    pop = [random_tree(4) for _ in range(pop_size)]
    for g in range(generations):
        scored = sorted(pop, key=error)
        if error(scored[0]) < 0.2:       # exact fit plus a small parsimony term
            break
        nxt = scored[:5]                                   # elitism
        while len(nxt) < pop_size:
            p1 = min(random.sample(scored, 7), key=error)  # tournament
            if random.random() < 0.8:
                p2 = min(random.sample(scored, 7), key=error)
                child = crossover(p1, p2)
            else:
                child = mutation(p1)
            if size(child) <= 40:
                nxt.append(child)
        pop = nxt
    best = min(pop, key=error)
    return best, g

if __name__ == "__main__":
    best, g = gp()
    print("generation", g, "best:", show(best), "error:", round(error(best), 3))
Output

The evolved expression simplifies to (1 − x) − x + x³ = x³ − 2x + 1, the exact target. Note the redundant (1.0 * 1.0), a small example of the non-functional code (introns) that GP accumulates. Uncontrolled growth of such code is called bloat, and parsimony pressure and size limits are standard countermeasures[40].

2.2Why does bloat occur, and what does the term 0.01 * size(tree) in error() do? What could go wrong if the coefficient were 1.0?

Show solution

Crossover at a random point in a large tree is likely to land in non-functional code, so offspring of big trees with introns are more likely to keep their parents' fitness. Size therefore grows without improving fitness[40]. The parsimony term breaks ties in favour of smaller trees. With a coefficient of 1.0, the exact 11-node solution would pay a penalty of 11, comparable to the error of a crude three-node approximation, so selection would favour short, inaccurate programs. The coefficient must be small relative to typical fitness differences.

SECTION 3Evolution strategies

Evolution strategies (ES) were created by Rechenberg and Schwefel at the Technical University of Berlin in the 1960s, first for experimental optimisation of physical objects such as jointed plates in a wind tunnel[13,15]. ES operate on real-valued vectors and rely mainly on Gaussian mutation:

(2)x′ = x + σ · N(0, I)

The notation (μ, λ) means μ parents create λ offspring and the best μ offspring become the new parents. In (μ + λ) selection the parents also compete, which makes the strategy elitist[15]. The central question is how to set the step size σ. Rechenberg's 1/5 success rule, derived from progress-rate analysis on the sphere and corridor models, increases σ when more than one in five mutations improves fitness and decreases it otherwise[13]. Schwefel introduced self-adaptation, in which σ is part of the genome and is mutated log-normally before it is used, so good step sizes hitchhike with the good solutions they produce[14]:

(3)σ′ = σ · exp(τ · N(0, 1)),   τ ∝ 1/√n

The most successful descendant is CMA-ES (covariance matrix adaptation), which adapts a full covariance matrix C so that the mutation distribution N(m, σ²C) learns the local shape of the objective (Figure 4). It is invariant to rotations and order-preserving transformations of the objective and is a standard benchmark method for continuous black-box problems of moderate dimension[32,42].

Worked example: step-size control on the sphere

es.py
"""(1+1)-ES with the 1/5 success rule, and a self-adaptive (mu, lambda)-ES."""
import numpy as np

def sphere(x):
    return float(np.sum(x ** 2))

def one_plus_one_es(f, x, sigma=1.0, iters=2000, seed=0):
    rng = np.random.default_rng(seed)
    fx, successes = f(x), 0
    for t in range(1, iters + 1):
        y = x + sigma * rng.standard_normal(x.size)
        fy = f(y)
        if fy <= fx:
            x, fx = y, fy
            successes += 1
        if t % 20 == 0:                      # Rechenberg's 1/5 success rule
            rate = successes / 20
            sigma *= 1.22 if rate > 0.2 else 0.82
            successes = 0
    return x, fx, sigma

def mu_comma_lambda_es(f, n=10, mu=5, lam=35, iters=300, seed=0):
    rng = np.random.default_rng(seed)
    tau = 1 / np.sqrt(n)                     # learning rate for step sizes
    parents = [(rng.uniform(-5, 5, n), 1.0) for _ in range(mu)]
    for _ in range(iters):
        offspring = []
        for _ in range(lam):
            x, s = parents[rng.integers(mu)]
            s_new = s * np.exp(tau * rng.standard_normal())   # mutate sigma first
            offspring.append((x + s_new * rng.standard_normal(n), s_new))
        offspring.sort(key=lambda o: f(o[0]))
        parents = offspring[:mu]             # comma selection: parents die
    return parents[0][0], f(parents[0][0])

if __name__ == "__main__":
    x, fx, s = one_plus_one_es(sphere, np.full(10, 3.0))
    print(f"(1+1)-ES      f = {fx:.2e}  final sigma = {s:.2e}")
    x, fx = mu_comma_lambda_es(sphere)
    print(f"(5,35)-ES     f = {fx:.2e}")
Output
(1+1)-ES      f = 1.76e-16  final sigma = 5.33e-09
(5,35)-ES     f = 7.83e-29

Both variants converge linearly, meaning the error shrinks by a roughly constant factor per generation, because σ shrinks in step with the distance to the optimum. With σ fixed, progress would stall once σ became large relative to that distance[15].

Exercises: evolution strategies

3.1In the (1+1)-ES above, 7 of the last 20 mutations succeeded. What happens to σ? What if only 2 succeeded? Why might a factor of 1.22 up and 0.82 down be a sensible pair?

Show solution

7/20 = 0.35 > 0.2, so σ is multiplied by 1.22: steps are too cautious and can be larger. 2/20 = 0.1 < 0.2, so σ is multiplied by 0.82. Because 1.22 × 0.82 ≈ 1.0, alternating up and down leaves σ unchanged, so the rule does not drift when the success rate sits near 1/5. Schwefel recommended a factor of about 0.82 for decreases[14,15].

3.2Self-adaptation works well with comma selection but poorly with plus selection. Explain why.

Show solution

With (μ + λ), a parent that got lucky with an unsuitable σ (for example, a large σ that produced one excellent jump) can survive indefinitely, so its bad σ is never replaced. With (μ, λ) every individual lives one generation, and the strategy parameters must keep producing good offspring to persist. Comma selection lets the population forget maladapted step sizes[15].

SECTION 4Differential evolution

Differential evolution (DE), introduced by Storn and Price, is a simple and very effective optimiser for continuous problems[31,43]. Its key idea is to build mutations from differences between population members. For each target vector xi, the classic scheme DE/rand/1/bin picks three other distinct members r1, r2, r3 and forms a mutant:

(4)vi = xr1 + F · (xr2 − xr3)

Binomial crossover then mixes vi and xi component-wise: component j comes from the mutant if a uniform random number is below the crossover rate CR or if j = jrand, a randomly chosen index that guarantees at least one mutant component. Finally the trial vector replaces the target only if it is at least as good (one-to-one greedy selection)[31].

Typical settings are F ∈ [0.4, 1.0] and CR ∈ [0.1, 1.0], with NP around 5 to 10 times the dimension; low CR suits separable problems and high CR suits problems with strong variable interaction[31,43]. Many variants adapt F and CR automatically or use different base vectors, such as DE/best/1 and DE/current-to-best/1[44].

Worked example: the Rastrigin function

The Rastrigin function f(x) = 10n + Σ(xj² − 10 cos 2πxj) has a global minimum of 0 at the origin and roughly 10n local minima on the domain [−5.12, 5.12]n, which makes it a standard test of global search.

de.py
"""DE/rand/1/bin (Storn and Price) on the Rastrigin function."""
import numpy as np

def rastrigin(x):
    return 10 * x.size + float(np.sum(x ** 2 - 10 * np.cos(2 * np.pi * x)))

def differential_evolution(f, bounds, NP=40, F=0.5, CR=0.9, gens=500, seed=0):
    rng = np.random.default_rng(seed)
    lo, hi = np.array(bounds).T
    D = lo.size
    pop = lo + rng.random((NP, D)) * (hi - lo)
    fit = np.array([f(p) for p in pop])
    for _ in range(gens):
        for i in range(NP):
            r1, r2, r3 = rng.choice([j for j in range(NP) if j != i], 3, replace=False)
            mutant = np.clip(pop[r1] + F * (pop[r2] - pop[r3]), lo, hi)
            cross = rng.random(D) < CR
            cross[rng.integers(D)] = True        # at least one gene from mutant
            trial = np.where(cross, mutant, pop[i])
            ft = f(trial)
            if ft <= fit[i]:                     # one-to-one greedy selection
                pop[i], fit[i] = trial, ft
    best = fit.argmin()
    return pop[best], fit[best]

if __name__ == "__main__":
    x, fx = differential_evolution(rastrigin, [(-5.12, 5.12)] * 5)
    print("best f =", round(fx, 6), "x =", np.round(x, 4))
Output
best f = 0.0 x = [ 0. -0. -0.  0. -0.]

4.1Let xr1 = (1, 2), xr2 = (3, 1), xr3 = (2, 4), target xi = (0, 0), F = 0.5 and CR = 0.9. The uniform draws for the two components are 0.30 and 0.95, and jrand is the first component. Compute the mutant and the trial vector.

4.2DE has no explicit step-size parameter like σ in an ES. Explain how its step size still adapts, and name one situation where this mechanism fails.

Show solution

Mutation steps are scaled differences between current members, so their size and direction follow the spread and shape of the population. Early on, members are far apart and steps are large; as the population converges into a basin, steps shrink automatically[31,43]. The mechanism fails when the population collapses prematurely (for example with a very small NP or F), because then all differences are near zero and the search stagnates even though no optimum has been found.

SECTION 5Swarm intelligence and particle swarm optimization

Swarm intelligence is the collective behaviour of decentralised, self-organising systems. Beni and Wang introduced the term for cellular robotic systems[45], and Bonabeau, Dorigo and Theraulaz developed it into a design approach drawing on social insects[2]. Its common features are many simple agents, local interactions, no central controller, and global patterns that emerge from those interactions.

Particle swarm optimisation (PSO) was proposed by Kennedy and Eberhart in 1995, inspired by models of bird flocking and social behaviour[30]. Each particle has a position xi and velocity vi, remembers its own best position pi, and knows the best position g found by its neighbourhood (the whole swarm in the "global best" variant). With the inertia weight w introduced by Shi and Eberhart[46], the update for each dimension is:

(5)vi ← w vi + c1r1(pi − xi) + c2r2(g − xi),    xi ← xi + vi

Here r1, r2 ~ U(0, 1) are drawn fresh for each dimension. The three terms are momentum, a cognitive pull toward the particle's own memory, and a social pull toward the group's best (Figure 6). Clerc and Kennedy analysed the swarm's dynamics and derived a constriction coefficient that guarantees convergent trajectories; with φ = c1 + c2 = 4.1 it gives χ ≈ 0.7298, equivalent to w = 0.7298 and c1 = c2 ≈ 1.496[47]. Those are the values used in the code below.

Worked example: the Rosenbrock valley

pso.py
"""Global-best particle swarm optimisation with inertia weight."""
import numpy as np

def rosenbrock(x):
    return float(np.sum(100 * (x[1:] - x[:-1] ** 2) ** 2 + (1 - x[:-1]) ** 2))

def pso(f, dim, n=30, iters=3000, w=0.7298, c1=1.49618, c2=1.49618,
        lo=-5.0, hi=5.0, seed=0):
    rng = np.random.default_rng(seed)
    x = rng.uniform(lo, hi, (n, dim))
    v = rng.uniform(-(hi - lo), hi - lo, (n, dim)) * 0.1
    pbest, pbest_f = x.copy(), np.array([f(p) for p in x])
    g = pbest[pbest_f.argmin()].copy()
    for _ in range(iters):
        r1, r2 = rng.random((n, dim)), rng.random((n, dim))
        v = w * v + c1 * r1 * (pbest - x) + c2 * r2 * (g - x)
        x = np.clip(x + v, lo, hi)
        fx = np.array([f(p) for p in x])
        better = fx < pbest_f
        pbest[better], pbest_f[better] = x[better], fx[better]
        g = pbest[pbest_f.argmin()].copy()
    return g, f(g)

if __name__ == "__main__":
    g, fg = pso(rosenbrock, dim=5)
    print("best f =", f"{fg:.3e}", "x =", np.round(g, 3))

SECTION 6Ant colony optimization

Many ant species find short paths between nest and food by laying and following pheromone trails. In the double-bridge experiment of Goss and colleagues, Argentine ants given two routes of different length to a food source came to use mostly the shorter one, because ants on the short branch return sooner and reinforce it faster (Figure 7)[48]. This is stigmergy: indirect coordination through modifications of the shared environment[2].

Dorigo turned this into an optimisation algorithm in his 1992 doctoral thesis, the Ant System, applied first to the travelling salesman problem (TSP)[28,49]. Artificial ants construct tours city by city. An ant at city i moves to an unvisited city j with probability

(6)pij = τijα ηijβ / Σl ∈ allowed τilα ηilβ

where τij is the pheromone on edge (i, j), ηij = 1/dij is a heuristic desirability, and α, β weight the two. After all ants finish, pheromone evaporates and each ant deposits an amount inversely proportional to its tour length Lk:

(7)τij ← (1 − ρ) τij + Σk Δτijk,   Δτijk = Q/Lk if ant k used (i, j), else 0

Evaporation (rate ρ) lets the colony forget poor early choices. Ant Colony System added a pseudo-random proportional rule, local pheromone updates and a global update by the best ant only, and was competitive with other TSP heuristics of its time[50]. The framework was later generalised as the ACO metaheuristic for routing, scheduling, assignment and network problems[51].

Worked example: a 12-city tour

To make the answer checkable, the cities lie on a unit circle in shuffled order. The optimal tour visits them around the circle and has length 12 × 2 sin(π/12) ≈ 6.2117.

aco.py
"""Ant System (Dorigo et al.) for a small travelling salesman problem."""
import numpy as np

def ant_system(coords, n_ants=20, iters=200, alpha=1.0, beta=3.0, rho=0.5,
               Q=1.0, seed=0):
    rng = np.random.default_rng(seed)
    n = len(coords)
    d = np.linalg.norm(coords[:, None] - coords[None, :], axis=2) + np.eye(n)
    eta = 1.0 / d                                    # heuristic visibility
    tau = np.ones((n, n))                            # pheromone
    best_tour, best_len = None, np.inf
    for _ in range(iters):
        tours = []
        for _ in range(n_ants):
            tour = [rng.integers(n)]
            unvisited = set(range(n)) - {tour[0]}
            while unvisited:
                i, cand = tour[-1], np.array(sorted(unvisited))
                p = tau[i, cand] ** alpha * eta[i, cand] ** beta
                j = rng.choice(cand, p=p / p.sum())  # random-proportional rule
                tour.append(j)
                unvisited.remove(j)
            L = sum(d[tour[k], tour[(k + 1) % n]] for k in range(n))
            tours.append((tour, L))
            if L < best_len:
                best_tour, best_len = tour, L
        tau *= 1 - rho                               # evaporation
        for tour, L in tours:                        # deposit
            for k in range(n):
                a, b = tour[k], tour[(k + 1) % n]
                tau[a, b] += Q / L
                tau[b, a] += Q / L
    return best_tour, best_len

if __name__ == "__main__":
    # 12 cities on a circle: the optimal tour is the circle, length ~ 2*pi*r
    ang = np.linspace(0, 2 * np.pi, 12, endpoint=False)
    rng = np.random.default_rng(42)
    perm = rng.permutation(12)
    coords = np.c_[np.cos(ang), np.sin(ang)][perm]
    tour, L = ant_system(coords)
    print("tour length =", round(L, 4), "optimum =", round(24 * np.sin(np.pi / 12), 4))

SECTION 7Neuroevolution

Neuroevolution uses evolutionary algorithms to design artificial neural networks: their weights, their topology, their learning rules, or all three[52,53]. It needs no differentiable loss, so it applies naturally to reinforcement learning with sparse or delayed rewards, to non-differentiable architectures, and to open-ended design.

Three families

  • Fixed-topology weight evolution. The network's weights are flattened into a real vector and optimised with a GA or ES. Salimans and colleagues showed that a simple natural-gradient ES, parallelised over many CPUs, was competitive with deep reinforcement-learning methods on MuJoCo locomotion and Atari tasks[35], and Such and colleagues showed that a plain GA could train deep convolutional policies with millions of parameters[36].
  • Topology and weight evolving networks (TWEANNs). NEAT, by Stanley and Miikkulainen, starts from minimal networks and adds nodes and connections over time[33]. It addresses three problems: it aligns genes during crossover using historical markings (innovation numbers, Figure 8), it protects new structures with speciation so they are not eliminated before their weights are tuned, and it searches small networks first through complexification.
  • Indirect encodings and architecture search. HyperNEAT evolves a compositional pattern-producing network that paints connection weights onto a geometric substrate, so large regular networks can be described compactly[54]. Evolutionary neural architecture search, such as regularised ("aging") evolution, found image classifiers competitive with the best hand-designed and reinforcement-learning-designed models of the time[5].

Worked example: evolving an XOR network

XOR is not linearly separable, so it needs a hidden layer. The program evolves all nine parameters of a 2-2-1 tanh/sigmoid network with truncation selection, elitism and Gaussian mutation, without computing any gradient.

neuro.py
"""Neuroevolution: evolve the weights of a 2-2-1 network to solve XOR."""
import numpy as np

X = np.array([[0, 0], [0, 1], [1, 0], [1, 1]], float)
Y = np.array([0, 1, 1, 0], float)
N_W = 2 * 2 + 2 + 2 * 1 + 1                     # weights + biases = 9

def forward(w, x):
    W1, b1 = w[:4].reshape(2, 2), w[4:6]
    W2, b2 = w[6:8], w[8]
    h = np.tanh(x @ W1 + b1)
    return 1 / (1 + np.exp(-(h @ W2 + b2)))

def fitness(w):
    return -float(np.mean((forward(w, X) - Y) ** 2))   # higher is better

def evolve(pop_size=50, gens=300, sigma=0.4, n_elite=5, seed=0):
    rng = np.random.default_rng(seed)
    pop = rng.standard_normal((pop_size, N_W))
    for g in range(gens):
        fit = np.array([fitness(w) for w in pop])
        order = np.argsort(-fit)
        elite = pop[order[:n_elite]]
        if fit[order[0]] > -0.01:
            break
        parents = elite[rng.integers(n_elite, size=pop_size - n_elite)]
        children = parents + sigma * rng.standard_normal(parents.shape)
        pop = np.vstack([elite, children])            # truncation + elitism
    best = pop[np.argmax([fitness(w) for w in pop])]
    return best, g

if __name__ == "__main__":
    w, g = evolve()
    print("generations:", g, "outputs:", np.round(forward(w, X), 3))

SECTION 8Artificial life and emergent behavior

Artificial life (ALife) studies "life as it could be" by synthesising life-like behaviour in software, hardware and chemistry. Langton named the field and organised its first workshop at Los Alamos in 1987[25]. Its roots are older: von Neumann designed a cellular automaton capable of self-reproduction to show that machines could, in principle, build copies of themselves[19].

The central theme is emergence: global structure that arises from local rules none of which describes it. Three classic examples follow.

  • Conway's Game of Life. Each cell of a grid is alive or dead. A dead cell with exactly three live neighbours is born; a live cell with two or three survives; all others die (rule B3/S23). From these rules arise gliders, oscillators and "guns" that emit gliders forever[20].
  • Boids. Reynolds produced realistic flocking with three steering rules applied by each bird to its local neighbours: separation (avoid crowding), alignment (match heading) and cohesion (move toward the local centre)[23]. Try them in the demo below.
  • Digital evolution. In Ray's Tierra, self-replicating machine-code programs competed for CPU time and memory, and parasites, hosts and hyper-parasites evolved without being designed[29]. In Avida, Lenski and colleagues showed that a complex logic function (EQU) evolved by building on simpler functions that were rewarded, and did not evolve when those intermediate steps were not rewarded[55]. Sims evolved both the bodies and neural controllers of virtual creatures that swam, walked and competed in a physics simulation[56].

Recent work connects ALife with deep learning. Neural cellular automata learn local update rules, by gradient descent, that grow a target image from a single cell and regenerate it after damage[57]. Open-ended search methods also come from ALife thinking: novelty search rewards behaviour that differs from what has been seen, not progress toward an objective, and can outperform objective-driven search on deceptive mazes[58]. MAP-Elites keeps the best solution in each cell of a grid of behaviour descriptors, producing a diverse archive of high-performing solutions[59].

SECTION 9Evolutionary multi-objective optimization

Real design problems usually involve conflicting objectives, such as cost against reliability or accuracy against model size. For minimisation, solution a dominates b (a ≺ b) if it is no worse in every objective and strictly better in at least one. The non-dominated solutions form the Pareto set, and their objective vectors form the Pareto front. Because a population holds many solutions at once, an evolutionary algorithm can approximate the whole front in a single run[34,60].

Schaffer's VEGA (1985) was the first multi-objective GA, selecting sub-populations by each objective in turn[22]. Fonseca and Fleming's MOGA ranked individuals by how many others dominate them[61], and Zitzler and Thiele's SPEA added an external archive of non-dominated solutions[62]. The most widely used algorithm became NSGA-II by Deb and colleagues, which introduced three ideas[34]:

  1. Fast non-dominated sorting splits the population into fronts F1, F2, … in O(MN²) time for M objectives and population size N.
  2. Crowding distance measures how isolated a solution is within its front (the perimeter of the cuboid formed by its neighbours) and is used to keep the front evenly spread without a sharing parameter.
  3. Elitism: parents and offspring are merged, and the best N are kept by front rank and then by crowding distance.

Decomposition-based methods such as MOEA/D instead split the problem into many scalar subproblems with different weight vectors and optimise them together[63].

Worked example: NSGA-II on ZDT1

ZDT1 is a standard two-objective benchmark with 30 variables in [0, 1]. Its Pareto front is f2 = 1 − √f1, reached when x2 = … = x30 = 0[60]. The implementation below follows the NSGA-II procedure with simulated binary crossover (SBX)[34].

nsga2.py
"""Core of NSGA-II (Deb et al. 2002) applied to the ZDT1 benchmark."""
import numpy as np

def zdt1(x):
    f1 = x[0]
    g = 1 + 9 * np.mean(x[1:])
    return np.array([f1, g * (1 - np.sqrt(f1 / g))])

def fast_non_dominated_sort(F):
    n = len(F)
    S = [[] for _ in range(n)]
    count = np.zeros(n, int)
    fronts = [[]]
    for p in range(n):
        for q in range(n):
            if np.all(F[p] <= F[q]) and np.any(F[p] < F[q]):
                S[p].append(q)            # p dominates q
            elif np.all(F[q] <= F[p]) and np.any(F[q] < F[p]):
                count[p] += 1
        if count[p] == 0:
            fronts[0].append(p)
    while fronts[-1]:
        nxt = []
        for p in fronts[-1]:
            for q in S[p]:
                count[q] -= 1
                if count[q] == 0:
                    nxt.append(q)
        fronts.append(nxt)
    return fronts[:-1]

def crowding_distance(F):
    n, m = F.shape
    dist = np.zeros(n)
    for k in range(m):
        order = np.argsort(F[:, k])
        dist[order[0]] = dist[order[-1]] = np.inf
        span = F[order[-1], k] - F[order[0], k] or 1.0
        dist[order[1:-1]] += (F[order[2:], k] - F[order[:-2], k]) / span
    return dist

def sbx_and_mutate(a, b, rng, eta=15, pm=None):
    u = rng.random(a.size)
    beta = np.where(u <= 0.5, (2 * u) ** (1 / (eta + 1)),
                    (1 / (2 * (1 - u))) ** (1 / (eta + 1)))
    child = 0.5 * ((1 + beta) * a + (1 - beta) * b)        # SBX crossover
    pm = pm or 1 / a.size
    mask = rng.random(a.size) < pm
    child[mask] += rng.normal(0, 0.1, mask.sum())           # Gaussian mutation
    return np.clip(child, 0, 1)

def nsga2(n_var=30, N=100, gens=200, seed=0):
    rng = np.random.default_rng(seed)
    P = rng.random((N, n_var))
    for _ in range(gens):
        FP = np.array([zdt1(x) for x in P])
        rank, crowd = np.empty(N, int), np.empty(N)
        for r, fr in enumerate(fast_non_dominated_sort(FP)):
            rank[fr], crowd[fr] = r, crowding_distance(FP[fr])
        def pick():                                         # crowded tournament
            i, j = rng.integers(N, size=2)
            return i if (rank[i], -crowd[i]) < (rank[j], -crowd[j]) else j
        Q = np.array([sbx_and_mutate(P[pick()], P[pick()], rng) for _ in range(N)])
        R = np.vstack([P, Q])                               # elitist merge
        FR = np.array([zdt1(x) for x in R])
        chosen = []
        for fr in fast_non_dominated_sort(FR):
            if len(chosen) + len(fr) <= N:
                chosen += fr
            else:
                cd = crowding_distance(FR[fr])
                chosen += [fr[i] for i in np.argsort(-cd)[:N - len(chosen)]]
                break
        P = R[chosen]
    return np.array([zdt1(x) for x in P])

if __name__ == "__main__":
    F = nsga2()
    gap = np.mean(np.abs(F[:, 1] - (1 - np.sqrt(F[:, 0]))))
    print("mean distance to true front:", round(gap, 4),
          "f1 range:", F[:, 0].min().round(3), "-", F[:, 0].max().round(3))
Output
mean distance to true front: 0.0341 f1 range: 0.0 - 1.0

The final population spans the whole front (f1 from 0 to 1) and lies on average about 0.03 above it in f2. Longer runs or polynomial mutation, as in the original paper, close the remaining gap.

SECTION 10Hybrid evolutionary and gradient-based methods

Evolutionary search is good at global exploration and at handling discrete or non-differentiable structure; gradient methods are much more efficient at local refinement of smooth, high-dimensional parameters. Hybrids try to combine the two.

Memetic algorithms and the Baldwin effect

Moscato coined memetic algorithms for evolutionary algorithms in which individuals improve themselves by local search during their lifetime[26]. There are two ways to use the improved individual (Figure 11):

  • Lamarckian: the locally improved solution is written back into the genome, so acquired traits are inherited.
  • Baldwinian: only the improved fitness is used for selection, and the genome is unchanged. Hinton and Nowlan showed in a simple model that learning can still guide evolution this way, by smoothing a needle-in-a-haystack landscape so that genotypes near the solution are rewarded[24].

Whitley and colleagues compared both on function optimisation and found that Lamarckian search often converged faster while Baldwinian search was sometimes less prone to premature convergence[64].

Worked example: memetic search on Rastrigin

The program compares a plain real-coded GA with Lamarckian and Baldwinian memetic versions that apply 20 gradient-descent steps to every individual, on the 10-dimensional Rastrigin function. All three use the same budget of generations and the same random seed.

memetic.py
"""Hybrid (memetic) search: evolution for exploration, gradient steps for refinement."""
import numpy as np

A = 10.0
def rastrigin(x):
    return A * x.size + float(np.sum(x ** 2 - A * np.cos(2 * np.pi * x)))

def grad_rastrigin(x):
    return 2 * x + 2 * np.pi * A * np.sin(2 * np.pi * x)

def local_search(x, steps=20, lr=0.002):
    for _ in range(steps):
        x = x - lr * grad_rastrigin(x)          # plain gradient descent
    return x

def memetic(dim=10, pop=30, gens=100, lamarckian=True, seed=0):
    rng = np.random.default_rng(seed)
    P = rng.uniform(-5.12, 5.12, (pop, dim))
    for _ in range(gens):
        refined = np.array([local_search(x) for x in P])
        fit = np.array([rastrigin(x) for x in refined])
        if lamarckian:
            P = refined                          # write learned traits back
        # Baldwinian variant: keep P, but select on the refined fitness
        order = np.argsort(fit)
        parents = P[order[: pop // 2]]
        a = parents[rng.integers(len(parents), size=pop)]
        b = parents[rng.integers(len(parents), size=pop)]
        mask = rng.random((pop, dim)) < 0.5
        children = np.where(mask, a, b) + rng.normal(0, 0.3, (pop, dim))
        children[0] = P[order[0]]                # elitism
        P = children
    best = min((local_search(x) for x in P), key=rastrigin)
    return rastrigin(best)

def plain_ga(dim=10, pop=30, gens=100, seed=0):
    rng = np.random.default_rng(seed)
    P = rng.uniform(-5.12, 5.12, (pop, dim))
    for _ in range(gens):
        fit = np.array([rastrigin(x) for x in P])
        order = np.argsort(fit)
        parents = P[order[: pop // 2]]
        a = parents[rng.integers(len(parents), size=pop)]
        b = parents[rng.integers(len(parents), size=pop)]
        mask = rng.random((pop, dim)) < 0.5
        children = np.where(mask, a, b) + rng.normal(0, 0.3, (pop, dim))
        children[0] = P[order[0]]
        P = children
    return min(rastrigin(x) for x in P)

if __name__ == "__main__":
    print("plain GA    :", round(plain_ga(), 3))
    print("Lamarckian  :", round(memetic(lamarckian=True), 3))
    print("Baldwinian  :", round(memetic(lamarckian=False), 3))
Output
plain GA    : 39.15
Lamarckian  : 0.0
Baldwinian  : 0.0

The comparison is not equal in cost, because each memetic generation also computes 20 gradients per individual, but gradients are often cheap relative to fitness evaluations in simulation-heavy problems.

Evolution strategies as gradient estimators

The link also runs the other way. Smoothing the objective with Gaussian noise, J(θ) = Eε~N(0,I)[F(θ + σε)], gives a function whose gradient can be estimated from function values alone[35,65]:

(8)∇θJ(θ) = (1/σ) · E[F(θ + σε) · ε] ≈ (1/(nσ)) Σi=1n F(θ + σεi) · εi

The estimate can be fed to any gradient-based optimiser such as Adam. Natural evolution strategies make this formal by following the natural gradient of expected fitness with respect to the parameters of the search distribution[65], and CMA-ES can be interpreted in a similar information-geometric way[42].

Other hybrids in modern machine learning

  • Population-based training trains a population of networks with gradient descent and periodically copies the weights of good members to poor ones (exploit) while perturbing their hyperparameters (explore), so hyperparameter schedules are discovered during a single training run[66].
  • Evolutionary architecture search evolves network structures while gradient descent trains each candidate's weights[5].
  • Large language models as variation operators. Evolution through large models uses a code-trained language model to propose intelligent mutations to programs[67]. FunSearch keeps an evolving database of programs, asks a language model to propose improved programs from the best ones, and scores them automatically; it found new constructions for the cap set problem in extremal combinatorics[37].

Show solution

The line P = refined, which overwrites genomes with their refined versions. Without it, selection uses the refined fitness but breeds the unrefined genomes. If local search always reaches the basin floor, every genome in a basin gets the same fitness, so selection judges basins, not points. The landscape seen by evolution becomes a flat-stepped version of the original, which removes local ruggedness. Keeping unrefined genomes also preserves more genetic diversity, which can reduce premature convergence[24,64].

10.2Show that equation (8) is correct by using the identity ∇θ log p(z; θ) for z ~ N(θ, σ²I). Why is the estimator often used with antithetic pairs ε and −ε?

Show solution

Write J(θ) = ∫ F(z) p(z; θ) dz. Then ∇J = ∫ F(z) ∇θp dz = E[F(z) ∇θ log p(z; θ)]. For the Gaussian, ∇θ log p = (z − θ)/σ² = ε/σ with z = θ + σε, which gives (1/σ) E[F(θ + σε) ε]. Antithetic sampling evaluates F(θ + σε) and F(θ − σε) and uses their difference, which cancels the constant part of F and greatly reduces the variance of the estimate[35,65].

Practical checklist

Benchmark against random search and a simple local search. Report results over many independent seeds, since one run says little about a stochastic algorithm. Count fitness evaluations, not generations, when comparing methods. Use established implementations when you can, and design the representation so that small genotype changes usually cause small phenotype changes[3].
