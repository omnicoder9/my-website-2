1Introduction: one toolkit, many fields

Computer graphics is the creation, manipulation and display of images by computer. Its history as an interactive discipline is usually dated to Ivan Sutherland's Sketchpad (1963), a light-pen drawing system that already contained hierarchical drawings, geometric constraints and direct manipulation of on-screen objects, and which is regarded as an ancestor of both CAD and the graphical user interface1,2. Six decades later the same core ideas (geometric models, transformations, visibility, shading and sampling) run in almost every industry.

The applications in this article differ mainly in what they optimise for. A game must produce a new frame in a few milliseconds; a film frame may take hours but must be indistinguishable from photography; a CAD model must be geometrically exact; a medical image must be faithful to measured data; a VR display must respond to head motion with minimal delay. Understanding the trade-off each field makes is the fastest way to understand why its algorithms look the way they do.

The common pipeline

Most applications use some variant of the same conceptual pipeline. A model describes geometry and appearance in object coordinates. Modelling transforms place it in a world; a viewing transform and projection map it to the image plane; visibility determines what is in front; shading computes colour from materials and lights; and sampling and reconstruction turn a continuous image into pixels2,3. Points are usually handled in homogeneous coordinates, so that translation, rotation, scaling and perspective all become 4×4 matrix multiplications:

pclip = P · V · M · pobject

Two families of rendering algorithm implement visibility and shading. Rasterisation projects each primitive and determines which pixels it covers, using a depth buffer for visibility; it is the basis of real-time GPU pipelines3. Ray tracing works from the pixel outward, finding the first surface each ray hits. When extended with Monte Carlo sampling of light paths it estimates Kajiya's rendering equation, the integral equation that describes equilibrium light transport4,5:

Lo(x, ωo) = Le(x, ωo) + ∫Ω fr(x, ωi, ωo) Li(x, ωi) (n·ωi) dωi

Outgoing radiance equals emitted radiance plus reflected incoming radiance, weighted by the surface's bidirectional reflectance distribution function (BRDF) and the cosine of the incident angle. Every photorealistic application in this article, from film to architectural daylighting, is ultimately approximating this equation.

2Video games

Games are the most demanding real-time graphics application. At 60 frames per second the entire frame (simulation, animation, audio, and rendering) must finish in 1000/60 ≈ 16.7 ms; at 120 Hz the budget is about 8.3 ms. Everything about game graphics follows from this fixed budget3,6.

The game loop

A game engine runs a loop that reads input, advances the world simulation, and renders. Because rendering time varies from frame to frame, robust engines decouple a fixed simulation time step from the variable rendering rate, and interpolate between the last two simulation states when drawing, so that physics behaves deterministically regardless of frame rate6.

JavaScript — fixed-timestep loop with interpolation

const DT = 1 / 120;            // simulation step: 120 Hz
let accumulator = 0, last = performance.now() / 1000;
let prev = initialState(), curr = prev;

function frame(nowMs) {
  const now = nowMs / 1000;
  let elapsed = Math.min(now - last, 0.25);  // clamp to avoid the "spiral of death"
  last = now;
  accumulator += elapsed;

  while (accumulator >= DT) {          // zero, one or many steps per frame
    prev = curr;
    curr = simulate(curr, readInput(), DT);
    accumulator -= DT;
  }
  const alpha = accumulator / DT;        // fraction of the way to the next step
  render(lerpState(prev, curr, alpha));
  requestAnimationFrame(frame);
}

The real-time rendering pipeline

Modern GPUs implement a programmable pipeline. Application code submits vertex buffers and draw calls; a vertex shader transforms each vertex to clip space; fixed-function hardware clips, rasterises and interpolates attributes; a fragment (pixel) shader computes colour; and the output-merger stage performs depth testing and blending3,7. Since the mid-2000s GPUs have used a unified array of programmable processors for all shader stages, which is also what made general-purpose GPU computing practical8.

Shading

The classic local illumination model is Phong's: a sum of ambient, diffuse (Lambertian) and specular terms9. Modern engines use physically based shading with energy-conserving microfacet BRDFs, but the Blinn–Phong form remains the clearest teaching example and is still used where cost matters3,5.

GLSL — Blinn–Phong fragment shader (WebGL 2 / GLSL ES 3.00)

#version 300 es
precision highp float;
in  vec3 vNormal;      // world-space normal, interpolated
in  vec3 vWorldPos;
uniform vec3 uLightPos, uCameraPos, uAlbedo;
uniform float uShininess;
out vec4 fragColor;

void main() {
  vec3 N = normalize(vNormal);
  vec3 L = normalize(uLightPos  - vWorldPos);
  vec3 V = normalize(uCameraPos - vWorldPos);
  vec3 H = normalize(L + V);                    // Blinn half-vector
  float diff = max(dot(N, L), 0.0);
  float spec = diff > 0.0 ? pow(max(dot(N, H), 0.0), uShininess) : 0.0;
  vec3 colour = 0.05 * uAlbedo + diff * uAlbedo + spec * vec3(1.0);
  fragColor = vec4(colour, 1.0);
}

Doing less work: level of detail, culling and mipmaps

Because the budget is fixed, much of game graphics is about avoiding work. Clark's 1976 paper proposed hierarchical models in which distant objects are drawn with simpler levels of detail and whole sub-trees outside the view volume are culled10. Texture mipmapping pre-filters each texture into a pyramid of half-resolution images so that a minified texture can be sampled with a few lookups instead of averaging many texels, which avoids aliasing shimmer11. More recently, neural and point-based scene representations such as 3D Gaussian splatting have shown that captured real scenes can be rendered at interactive rates12.

Key idea. Real-time graphics is a budgeting problem: every technique trades image quality for milliseconds, and the best engines spend their budget where the player is looking.

Exercises: video games

  1. A game targets 90 Hz. The CPU simulation takes 4.1 ms and the GPU rendering takes 9.6 ms, and the two run in parallel on consecutive frames (pipelined). Does the game hit its target? What if they ran serially?
    Show solution

    The budget at 90 Hz is 1000/90 ≈ 11.1 ms. When CPU and GPU work are pipelined, throughput is limited by the slower stage: max(4.1, 9.6) = 9.6 ms < 11.1 ms, so the target is met (with one extra frame of latency). Serially, 4.1 + 9.6 = 13.7 ms > 11.1 ms, so the game would drop to about 73 Hz, or to 45 Hz if locked to vertical sync.

  2. In the fixed-timestep loop above, why is elapsed clamped to 0.25 s, and what visible artefact would appear if interpolation (alpha) were removed?
    Show solution

    If a frame takes very long (for example after a breakpoint or a disk stall), the accumulator could require hundreds of simulation steps, which takes even longer, so the next frame needs more steps still: the "spiral of death". Clamping bounds the catch-up work. Without interpolation, rendered positions only change at simulation steps, so when the display rate and step rate are not multiples of each other, motion shows temporal aliasing: objects visibly judder because some frames show two steps of movement and others one or none.

3Film and visual effects

Film rendering inverts the game trade-off: a frame may take hours across a render farm, but the result is projected at large size next to live-action photography and must hold up. Visual effects (VFX) combine computer-generated imagery (CGI) with filmed plates through a pipeline of modelling, look development, layout, animation, simulation, lighting, rendering and compositing13.

From Reyes to path tracing

For two decades the dominant production architecture was Reyes, introduced at Lucasfilm and the basis of Pixar's RenderMan, which dices surfaces into sub-pixel "micropolygons", shades them, and then samples them stochastically, giving efficient motion blur and depth of field14. During the 2010s, studios moved largely to Monte Carlo path tracing, which estimates the rendering equation directly by tracing random light paths. Christensen and Jarosz describe the reasons: simpler artist workflows (fewer hand-placed fake lights and caches), physically based materials, and enough compute and denoising to make the noise manageable5,15.

The core of a path tracer is a Monte Carlo estimator. To estimate the diffuse reflection integral, directions are sampled in proportion to the cosine term, which cancels part of the integrand and reduces variance (importance sampling)5:

Python — cosine-weighted hemisphere sampling for a Lambertian surface

import math, random

def cosine_sample_hemisphere():
    """Return a direction (x, y, z), z up, with pdf = cos(theta)/pi."""
    u1, u2 = random.random(), random.random()
    r, phi = math.sqrt(u1), 2 * math.pi * u2       # Malley's method: sample a disk...
    x, y = r * math.cos(phi), r * math.sin(phi)
    z = math.sqrt(max(0.0, 1 - x*x - y*y))          # ...and project up to the hemisphere
    return x, y, z

def estimate_diffuse(albedo, incoming_radiance, n=1024):
    # f_r = albedo/pi, pdf = cos/pi  =>  f_r * L * cos / pdf = albedo * L
    total = 0.0
    for _ in range(n):
        d = cosine_sample_hemisphere()
        total += albedo * incoming_radiance(d)
    return total / n

# Under a uniform white sky (L = 1 everywhere), the answer is exactly the albedo.
print(estimate_diffuse(0.8, lambda d: 1.0))   # 0.8

Integrating CG with photography

To place a CG object convincingly in a filmed scene, three things must match the plate: camera, lighting and edges. Camera tracking ("matchmoving") recovers the motion and lens of the physical camera from the footage13. Image-based lighting captures the real illumination by photographing a mirrored sphere or panorama at several exposures, combining them into a high-dynamic-range radiance map, and using that map as the light source for the CG render16,17. Finally, rendered layers are combined with the plate by compositing.

Porter and Duff formalised digital compositing by storing an alpha (coverage) channel with every pixel and defining an algebra of operators. Their most used operator, over, is simplest with premultiplied colour (colour already multiplied by alpha)18:

Cout = CA + (1 − αA) CB,    αout = αA + (1 − αA) αB

Python (NumPy) — Porter–Duff over with premultiplied RGBA

import numpy as np

def over(fg, bg):
    """fg, bg: float arrays (..., 4) holding premultiplied RGBA in [0, 1]."""
    a_fg = fg[..., 3:4]
    return fg + (1.0 - a_fg) * bg

def premultiply(rgba):
    out = rgba.copy()
    out[..., :3] *= rgba[..., 3:4]
    return out

# A 50%-transparent red element over an opaque blue plate
red  = premultiply(np.array([1.0, 0.0, 0.0, 0.5]))
blue = np.array([0.0, 0.0, 1.0, 1.0])
print(over(red, blue))        # [0.5 0.  0.5 1. ]

Large productions exchange scene data between dozens of tools. Pixar's open-source Universal Scene Description (USD) provides a layered scene format in which departments contribute non-destructive "opinions" that are composed into a final scene19.

4Animation

Animation is the art of making images change over time so that they appear alive. Thomas and Johnston codified twelve principles developed at the Disney studio (including squash and stretch, anticipation, staging, slow in and slow out, arcs, follow-through and overlapping action, timing, and exaggeration)20. Lasseter showed in 1987 how these hand-drawn principles carry over to 3D computer animation21.

Keyframes and interpolation

In keyframe animation an artist sets values at chosen times and the computer interpolates between them, usually with cubic splines so that velocity is continuous; editing the tangents implements "slow in and slow out"22. Rotations need special care: interpolating Euler angles component-wise gives uneven motion and can suffer gimbal lock. Shoemake introduced spherical linear interpolation (slerp) of unit quaternions, which moves at constant angular velocity along the shortest arc23:

slerp(q0, q1; t) = [sin((1−t)θ) q0 + sin(tθ) q1] / sin θ,   cos θ = q0·q1

JavaScript — quaternion slerp

// Quaternions as [w, x, y, z], assumed unit length.
function slerp(a, b, t) {
  let dot = a[0]*b[0] + a[1]*b[1] + a[2]*b[2] + a[3]*b[3];
  if (dot < 0) { b = b.map(v => -v); dot = -dot; }  // q and -q are the same rotation: take the short way
  if (dot > 0.9995) {                                 // nearly parallel: lerp and renormalise
    const r = a.map((v, i) => v + t * (b[i] - v));
    const n = Math.hypot(...r);
    return r.map(v => v / n);
  }
  const theta = Math.acos(dot), s = Math.sin(theta);
  const wa = Math.sin((1 - t) * theta) / s, wb = Math.sin(t * theta) / s;
  return a.map((v, i) => wa * v + wb * b[i]);
}

Skeletal animation and skinning

Characters are animated by a hierarchy of joints (a skeleton). A rig binds the mesh to the skeleton, and each vertex is deformed by a weighted blend of the transforms of the joints that influence it. The standard method, linear blend skinning, computes

v′ = Σj wj · Mj · Bj−1 · v,    Σj wj = 1

where Bj is joint j's bind-pose transform and Mj its current transform. It is fast and GPU-friendly but averaging rotation matrices shrinks volume at strongly twisted joints, the well-known "candy-wrapper" artefact; dual-quaternion skinning was proposed to blend rigid transforms without this collapse3,24.

Procedural and physically based animation

Not all motion is keyframed. Particle systems, introduced by Reeves for the "Genesis" sequence of Star Trek II: The Wrath of Khan, model fire, smoke and explosions as clouds of short-lived particles whose birth, motion and death are governed by stochastic rules25. Cloth, hair, fluids and rigid bodies are simulated physically (see Section 14), and motion capture records performers' movement directly22.

5Computer-aided design (CAD)

CAD systems create precise digital definitions of parts and products that drive analysis, documentation and manufacture. Sketchpad's constraint-based drawing is the field's ancestor1. Unlike games and film, a CAD model is not just something to look at: it is the authoritative definition of a physical object, so representations must be exact and topologically valid.

Solid representations

Requicha's classic survey identified the main schemes for representing solids unambiguously26:

  • Constructive solid geometry (CSG): a tree of Boolean operations (union, intersection, difference) on primitives such as blocks and cylinders. Compact and always valid, but faces and edges must be computed when needed.
  • Boundary representation (B-rep): explicit faces, edges and vertices with their adjacency (topology) and the surfaces that carry them (geometry). Most commercial mechanical CAD kernels are B-rep based, often recording the CSG-like feature history used to build the model.
  • Spatial enumeration (voxels), which is approximate but simple, and is widely used in additive manufacturing preparation and analysis.

Free-form curves and surfaces

Car bodies, turbine blades and consumer products need smooth free-form shapes. The standard tools are Bézier curves, B-splines, and their rational generalisation NURBS (non-uniform rational B-splines), which can represent conic sections such as circles exactly, a requirement for engineering geometry27,28. A degree-n Bézier curve with control points P0…Pn is

C(t) = Σi=0..n Bi,n(t) Pi,   Bi,n(t) = (n choose i) ti (1−t)n−i,  t ∈ [0,1]

It is most robustly evaluated with de Casteljau's algorithm: repeated linear interpolation between neighbouring control points. Because each step is a convex combination, the curve lies inside the convex hull of its control points, a property CAD systems use for fast intersection tests27.

JavaScript — de Casteljau evaluation

function deCasteljau(points, t) {          // points: [{x, y}, ...]
  let p = points.map(q => ({ ...q }));
  for (let k = 1; k < points.length; k++)
    for (let i = 0; i < points.length - k; i++)
      p[i] = { x: (1 - t) * p[i].x + t * p[i + 1].x,
               y: (1 - t) * p[i].y + t * p[i + 1].y };
  return p[0];
}

6Architecture and engineering

Architecture, engineering and construction (AEC) use graphics for design, coordination, analysis and communication with clients. The most important shift has been from drawings to Building Information Modelling (BIM): a building is represented as a database of semantic objects (walls, doors, slabs, ducts) with geometry, properties and relationships, from which plans, sections, schedules and 3D views are all generated consistently29. The open exchange schema for BIM is the Industry Foundation Classes (IFC), published as ISO 1673930.

Lighting simulation and radiosity

Architects need not only pretty images but predictive ones: how bright will this office be at noon in December? Radiosity, adapted from heat-transfer engineering, solves light exchange between diffuse surfaces by dividing the scene into patches and solving a linear system31:

Bi = Ei + ρi Σj Fij Bj

where B is radiosity (outgoing flux density), E emission, ρ reflectance and Fij the form factor, the fraction of energy leaving patch i that reaches patch j. Because the result is view-independent, a solved model can be walked through interactively. Physically based lighting simulation tools such as Ward's RADIANCE system are used for daylighting and glare analysis32.

Python — Jacobi iteration for a small radiosity system

import numpy as np

def solve_radiosity(E, rho, F, iters=100, tol=1e-9):
    """E, rho: (n,) arrays; F: (n, n) form factors with row sums <= 1."""
    B = E.copy()
    for _ in range(iters):
        B_new = E + rho * (F @ B)        # each patch gathers light from all others
        if np.max(np.abs(B_new - B)) < tol:
            break
        B = B_new
    return B

# Two facing patches: patch 0 is a lamp, patch 1 a wall, each sees half of the other.
E   = np.array([10.0, 0.0])
rho = np.array([0.0, 0.6])
F   = np.array([[0.0, 0.5],
                [0.5, 0.0]])
print(solve_radiosity(E, rho, F))     # [10.  3.]  wall: 0.6 * 0.5 * 10 = 3

Convergence is guaranteed because each row of ρF sums to less than one (surfaces absorb some light), so the iteration is a contraction.

7Scientific visualization

Scientific visualization turns measured or simulated data into images that support insight. The field was named and given its agenda in the 1987 US National Science Foundation report Visualization in Scientific Computing, which argued that the flood of data from supercomputers and instruments needed visual methods to be understood33. The standard architecture is a dataflow pipeline: data sources pass through filters (resampling, contouring, streamline integration) to mappers that produce geometry, which is then rendered. The open-source Visualization Toolkit (VTK) embodies this design34.

Contouring: marching squares and marching cubes

The workhorse technique for scalar fields is the isocontour: the curve (2D) or surface (3D) where the field equals a chosen value. Lorensen and Cline's marching cubes visits each cell of a 3D grid, classifies its eight corners as inside or outside, looks up which of the 28 = 256 configurations it is in (reducible by symmetry to 15 basic cases), and emits triangles whose vertices are found by linear interpolation along the cell edges35. Its 2D analogue, marching squares, has 24 = 16 cases.

Python — marching squares (line segments for one iso-value)

def marching_squares(f, iso):
    """f: 2D list/array of samples f[j][i]. Returns a list of segments ((x0,y0),(x1,y1))."""
    def lerp(p, q, a, b):                     # point on edge p-q where field == iso
        t = (iso - a) / (b - a)
        return (p[0] + t*(q[0]-p[0]), p[1] + t*(q[1]-p[1]))
    segs = []
    for j in range(len(f) - 1):
        for i in range(len(f[0]) - 1):
            c = [(i, j), (i+1, j), (i+1, j+1), (i, j+1)]          # corners, counter-clockwise
            v = [f[j][i], f[j][i+1], f[j+1][i+1], f[j+1][i]]
            pts = []
            for k in range(4):                                     # each of the 4 edges
                a, b = v[k], v[(k+1) % 4]
                if (a < iso) != (b < iso):                         # sign change => crossing
                    pts.append(lerp(c[k], c[(k+1) % 4], a, b))
            if len(pts) == 2:
                segs.append((pts[0], pts[1]))
            elif len(pts) == 4:                                    # saddle (ambiguous) case
                centre = sum(v) / 4                                # resolve with the cell-centre value
                if (centre < iso) == (v[0] < iso):              # corners 0 and 2 joined: cut off 1 and 3
                    segs += [(pts[0], pts[1]), (pts[2], pts[3])]
                else:                                             # corners 1 and 3 joined: cut off 0 and 2
                    segs += [(pts[3], pts[0]), (pts[1], pts[2])]
    return segs

Colour mapping

Colour maps encode scalar values as colour, and the choice matters. Borland and Taylor documented how the ubiquitous rainbow colour map introduces false boundaries, is not perceptually ordered, and obscures fine detail36. Perceptually ordered sequential maps are preferred for magnitudes, and diverging maps, with a neutral centre and two contrasting hues, for data with a meaningful midpoint such as zero37,38.

8Medical imaging

Medical imaging produces images of the inside of the body from measurements: X-ray attenuation in computed tomography (CT), nuclear magnetic resonance in MRI, acoustic echoes in ultrasound, and emitted radiation in PET and SPECT39. Graphics enters at two points: reconstruction of images from raw measurements, which is a signal-processing problem, and display and analysis of the resulting 2D slices and 3D volumes, which is a graphics and visualization problem.

CT numbers and windowing

Hounsfield's CT scanner, described in 1973, reconstructed cross-sections from many X-ray projections40. CT values are reported in Hounsfield units (HU), a linear rescaling of attenuation in which water is 0 HU and air is −1000 HU; dense bone reaches roughly +1000 HU and above39. That range of 2000+ values cannot be shown at once on a display with a few hundred perceptible grey levels, so radiologists apply a window: a window width W and level (centre) L map the HU interval [L − W/2, L + W/2] linearly to black…white and clamp outside it39. A narrow window around soft-tissue values gives high contrast between similar tissues; a wide window shows lung and bone together.

Python (NumPy) — window/level mapping to 8-bit display values

import numpy as np

def window_level(hu, width, level):
    lo = level - width / 2.0
    out = (hu - lo) / width                     # 0..1 inside the window
    return (np.clip(out, 0.0, 1.0) * 255).astype(np.uint8)

# Raw CT pixels are stored as integers; DICOM tags give the linear rescale to HU.
def to_hu(raw, rescale_slope, rescale_intercept):
    return raw * rescale_slope + rescale_intercept

Images, patient metadata and acquisition parameters (including the rescale slope and intercept used above) are stored and exchanged with the DICOM standard41.

Volume rendering

Beyond slices, CT and MRI volumes can be rendered in 3D. Surface extraction with marching cubes was developed with exactly this data in mind35. Direct volume rendering instead casts rays through the volume and accumulates colour and opacity assigned to each sample by a user-designed transfer function, so that soft tissue can be semi-transparent while bone is opaque42,43. Front-to-back compositing along each ray allows early ray termination once accumulated opacity is close to one44:

JavaScript — front-to-back ray compositing

function castRay(volume, origin, dir, step, transfer) {
  let C = [0, 0, 0], A = 0;
  for (let s = 0; s < volume.maxDistance(origin, dir); s += step) {
    const v = volume.sampleTrilinear(add(origin, scale(dir, s)));
    const [r, g, b, a] = transfer(v);          // HU -> colour + opacity
    const w = (1 - A) * a;                     // remaining transparency x this sample's opacity
    C[0] += w * r; C[1] += w * g; C[2] += w * b;
    A += w;
    if (A > 0.99) break;                     // early ray termination
  }
  return [...C, A];
}

9Geographic information systems (GIS)

A GIS captures, stores, analyses and displays data referenced to locations on the Earth45. Geographic data come in two main models: vector (points, lines and polygons such as roads, rivers and parcels, with attributes) and raster (grids such as satellite imagery and elevation models). Graphics problems in GIS include map projection, cartographic symbolisation, terrain rendering and interactive display of very large datasets.

Map projections

The Earth is (approximately) an ellipsoid and a screen is flat, so every map uses a projection, and no projection preserves area, shape, distance and direction simultaneously46. The Mercator projection is conformal (it preserves local angles, which is why it suits navigation) but greatly exaggerates area toward the poles. Its spherical form is

x = R λ,    y = R ln tan(π/4 + φ/2)

for longitude λ and latitude φ in radians46. Most web maps use "Web Mercator", which applies these spherical formulas to WGS 84 coordinates; Battersby and colleagues describe how this differs from a true ellipsoidal Mercator and the consequences for measurement47.

Tiled map rendering

Interactive web maps are fast because the world is pre-cut into a tile pyramid. At zoom level z the square Web Mercator world is divided into 2z × 2z tiles (commonly 256×256 pixels each), and the client fetches only the tiles covering the viewport; the OGC Tile Matrix Set standard formalises such schemes48. This is the same idea as mipmapping (Section 2) applied to geographic data.

JavaScript — longitude/latitude to tile and pixel coordinates

const MAX_LAT = 85.05112878;           // where the square Web Mercator world ends

function lonLatToTile(lon, lat, z, tileSize = 256) {
  lat = Math.max(-MAX_LAT, Math.min(MAX_LAT, lat));
  const n = 2 ** z;
  const phi = lat * Math.PI / 180;
  const xNorm = (lon + 180) / 360;                                       // 0..1
  const yNorm = (1 - Math.log(Math.tan(phi) + 1 / Math.cos(phi)) / Math.PI) / 2; // 0..1, north at 0
  const px = xNorm * n * tileSize, py = yNorm * n * tileSize;           // global pixel coords
  return { tileX: Math.floor(px / tileSize), tileY: Math.floor(py / tileSize),
           pixelX: px % tileSize, pixelY: py % tileSize };
}

console.log(lonLatToTile(0, 0, 1));   // equator/prime meridian: { tileX: 1, tileY: 1, pixelX: 0, pixelY: 0 }

Note that ln(tan φ + sec φ) equals ln tan(π/4 + φ/2), the Mercator y formula above, in a form that is cheaper to evaluate.

10Virtual reality (VR)

Virtual reality replaces the user's view of the world with a computer-generated one that responds to head and body movement. Sutherland built the first head-mounted display with head tracking in 1968, presenting wireframe graphics that stayed fixed in space as the user turned49. Room-scale projection systems such as the CAVE, which surrounds the user with stereo projection walls, followed in the early 1990s50. Brooks's 1999 survey of working VR systems identified display, tracking, rendering and latency as the critical technologies51.

Stereo rendering

Each eye gets its own image rendered from a viewpoint offset by half the interpupillary distance (IPD). Because the two eyes look through the same physical display region, the correct projection for each eye is an asymmetric (off-axis) frustum, not two symmetric frusta rotated toward each other, which would introduce vertical parallax and discomfort3.

JavaScript — off-axis frustum bounds for one eye

// Screen of size w x h centred on the z axis at distance d; eye displaced by eyeX (= ±IPD/2).
function eyeFrustum(eyeX, w, h, d, near, far) {
  const k = near / d;                         // similar triangles: scale screen edges to the near plane
  return {
    left:   (-w / 2 - eyeX) * k,
    right:  ( w / 2 - eyeX) * k,
    bottom: (-h / 2) * k,
    top:    ( h / 2) * k,
    near, far                                   // feed to a glFrustum-style projection matrix,
  };                                            // and translate the view by -eyeX
}
const ipd = 0.063;                             // metres; a typical adult value
const L = eyeFrustum(-ipd / 2, 1.0, 0.6, 1.5, 0.1, 100);
const R = eyeFrustum(+ipd / 2, 1.0, 0.6, 1.5, 0.1, 100);

Tracking, latency and comfort

Head pose must be estimated continuously, typically by fusing fast inertial sensors (gyroscopes and accelerometers) with slower drift-free references such as cameras. LaValle and colleagues describe the approach used for the Oculus Rift: integrate the gyroscope, correct tilt drift with the accelerometer's gravity estimate, correct yaw drift with the magnetometer, and predict head orientation a few tens of milliseconds ahead to compensate for rendering and display latency52. Fusion of this kind often builds on the Kalman filter53.

Comfort also depends on optics. In a headset the eyes converge on virtual objects at various depths but must focus at the fixed optical distance of the display. Hoffman and colleagues showed experimentally that this vergence–accommodation conflict degrades visual performance and causes fatigue54. Finally, because the eye's acuity is highest only in the fovea, foveated rendering spends full resolution only where the user is looking; Guenter and colleagues demonstrated large savings with no perceived quality loss55.

11Augmented reality (AR)

Augmented reality overlays virtual content on the user's view of the real world. Azuma's widely cited survey defines AR by three properties: it combines real and virtual, is interactive in real time, and is registered in 3D (virtual objects stay attached to real locations)56. Milgram and Kishino placed AR on a reality–virtuality continuum running from the real environment to a fully virtual one, with "mixed reality" covering everything in between57.

Registration: knowing where the camera is

The central technical problem is pose estimation: to draw a virtual object at a real location, the system must know the camera's intrinsic parameters (focal length and principal point) and its pose (rotation R and translation t) relative to the world, every frame. Early systems such as ARToolKit tracked printed square fiducial markers of known size58. Markerless systems use simultaneous localisation and mapping (SLAM), building a map of natural features while tracking the camera against it; MonoSLAM showed this was possible in real time with a single camera59. Once pose is known, a world point X projects to pixel coordinates with the pinhole model

s·[u, v, 1]T = K [R | t] [X, Y, Z, 1]T,    K = [[fx, 0, cx], [0, fy, cy], [0, 0, 1]]

Python (NumPy) — projecting a virtual anchor into the camera image

import numpy as np

def project(X_world, K, R, t):
    X_cam = R @ X_world + t              # world -> camera coordinates
    if X_cam[2] <= 0:
        return None                       # behind the camera: don't draw
    uvw = K @ X_cam
    return uvw[:2] / uvw[2]              # perspective divide

K = np.array([[800.0,   0.0, 640.0],
              [  0.0, 800.0, 360.0],
              [  0.0,   0.0,   1.0]])   # 1280x720 camera
R = np.eye(3)
t = np.array([0.0, 0.0, 2.0])           # world origin is 2 m in front of the camera
print(project(np.array([0.25, 0.0, 0.0]), K, R, t))   # [740. 360.]

Visual coherence

Correct placement is necessary but not sufficient. Virtual objects must also be occluded by real objects in front of them (requiring depth of the real scene), lit consistently with the real environment, and composited without visible lag. Azuma singled out registration error and latency as the hardest problems because the human visual system is very sensitive to virtual objects that slide relative to the real world56. The lighting techniques used in film (image-based lighting, Section 3) are applied in real time for the same reason17.

12User interfaces

The graphical user interface is the application of computer graphics that almost everyone uses every day. Sketchpad demonstrated pointing at and manipulating on-screen objects in 19631; the Xerox Star (1981) brought together windows, icons, a desktop metaphor and what-you-see-is-what-you-get editing in a commercial product60. Shneiderman named the underlying principle direct manipulation: continuous visible representation of the objects of interest, physical actions (pointing, dragging) instead of commands, and rapid, reversible operations whose results are immediately visible61.

Rendering a modern UI

A UI is rendered from a tree of components (a scene graph) into layers that are combined by a compositor using the same alpha-compositing algebra used in film18. Resolution-independent vector formats such as SVG let interfaces and icons scale crisply across display densities62. On the GPU, shapes such as rounded rectangles are commonly drawn analytically with signed distance functions (SDFs), which give smooth anti-aliased edges at any scale63,64:

GLSL — anti-aliased rounded rectangle from a signed distance function

// Signed distance from p to a box of half-size b with corner radius r (negative inside).
float sdRoundedBox(vec2 p, vec2 b, float r) {
  vec2 q = abs(p) - b + r;
  return length(max(q, 0.0)) + min(max(q.x, q.y), 0.0) - r;
}

void main() {
  vec2 p = gl_FragCoord.xy - uCentre;               // pixel relative to the button centre
  float d = sdRoundedBox(p, uHalfSize, uRadius);
  float aa = fwidth(d);                              // ~1 pixel in distance units
  float coverage = 1.0 - smoothstep(-aa, aa, d);    // fractional coverage => anti-aliasing
  fragColor = vec4(uFill * coverage, coverage);      // premultiplied, ready for "over"
}

Designing for human performance

Interface layout can be quantified. Fitts' law predicts the time to point at a target from its distance D and width W65. In the Shannon formulation recommended by MacKenzie for HCI66:

MT = a + b · log2(D/W + 1)

where a and b are empirically fitted constants and the logarithm is the index of difficulty in bits. The law explains why large targets and targets at screen edges (which have effectively infinite depth for a mouse) are fast to hit.

JavaScript — Fitts' law and hit testing

const fittsMT = (D, W, a = 0.1, b = 0.15) => a + b * Math.log2(D / W + 1); // seconds

// Hit test: walk the component tree front-to-back, return the topmost hit.
function hitTest(node, x, y) {
  if (!node.visible || !node.contains(x, y)) return null;
  for (let i = node.children.length - 1; i >= 0; i--) {   // last drawn = on top
    const c = node.children[i];
    const hit = hitTest(c, x - c.x, y - c.y);               // into child's local space
    if (hit) return hit;
  }
  return node;
}

13Digital art

Digital art covers work made with digital tools, from painting software and 3D sculpture to generative and algorithmic art, where the artist writes a process and the computer carries it out67. Graphics techniques give digital artists three things: tools (brushes, layers, blend modes, which are compositing operators18), procedures that generate form, and new media such as real-time, interactive and immersive pieces.

Procedural texture and noise

Perlin's 1985 "image synthesizer" introduced a band-limited pseudo-random noise function and a language for composing it into textures such as marble, fire and clouds68. Summing octaves of noise at doubling frequencies and halving amplitudes produces fractional Brownian motion (fBm), whose self-similar detail resembles natural terrain and clouds, an idea connected to Mandelbrot's fractal geometry of nature68,69.

JavaScript — 2D value noise and fBm

function hash(ix, iy) {                         // deterministic pseudo-random value in [0,1)
  let h = (ix * 374761393 + iy * 668265263) | 0;
  h = Math.imul(h ^ (h >>> 13), 1274126177);
  return ((h ^ (h >>> 16)) >>> 0) / 4294967296;
}
const smooth = t => t * t * (3 - 2 * t);           // smoothstep fade curve

function valueNoise(x, y) {
  const ix = Math.floor(x), iy = Math.floor(y), fx = smooth(x - ix), fy = smooth(y - iy);
  const a = hash(ix, iy), b = hash(ix + 1, iy), c = hash(ix, iy + 1), d = hash(ix + 1, iy + 1);
  return (a + (b - a) * fx) + ((c + (d - c) * fx) - (a + (b - a) * fx)) * fy;
}

function fbm(x, y, octaves = 5) {
  let sum = 0, amp = 0.5, freq = 1;
  for (let o = 0; o < octaves; o++) {
    sum += amp * valueNoise(x * freq, y * freq);
    freq *= 2; amp *= 0.5;                         // "lacunarity" 2, "gain" 0.5
  }
  return sum;                                      // in [0, 1)
}

(Perlin's original gradient noise interpolates random gradients rather than random values, which gives less grid-aligned structure; value noise is shown here because it is shorter.)

The Mandelbrot set, the set of complex c for which iterating z → z2 + c from z = 0 stays bounded, became an emblem of computer art because an extremely short rule produces unbounded visual complexity69. 14Simulation and digital twins

Simulation uses graphics in two ways: to compute physically plausible motion (cloth, fluids, crowds, vehicles) and to present simulated worlds for training, analysis and entertainment. Graphics research has favoured methods that are stable at large time steps, even at some cost in accuracy, because interactive applications cannot afford to blow up. Stam's "stable fluids" uses a semi-Lagrangian advection step that is unconditionally stable70, and Baraff and Witkin made cloth simulation practical with implicit integration that tolerates large steps on stiff springs71.

A mass–spring system with Verlet integration

The simplest deformable model is a set of particles joined by springs. Position-based Verlet integration stores the current and previous positions, so velocity is implicit and constraints can be enforced by directly moving positions, an approach generalised as position-based dynamics and widely used in games72:

JavaScript — Verlet cloth step with distance constraints

function step(particles, constraints, dt, gravity = -9.81, iterations = 8) {
  for (const p of particles) {
    if (p.pinned) continue;
    const vx = p.x - p.px, vy = p.y - p.py;          // implicit velocity * dt
    p.px = p.x; p.py = p.y;
    p.x += vx * 0.99;                                 // 0.99 = simple damping
    p.y += vy * 0.99 + gravity * dt * dt;
  }
  for (let k = 0; k < iterations; k++) {            // relax constraints (Gauss-Seidel style)
    for (const { a, b, rest } of constraints) {
      const dx = b.x - a.x, dy = b.y - a.y;
      const dist = Math.hypot(dx, dy) || 1e-9;
      const diff = (dist - rest) / dist;
      const wa = a.pinned ? 0 : 1, wb = b.pinned ? 0 : 1, s = wa + wb;
      if (!s) continue;
      const k = diff / s;                       // free ends share the correction
      a.x += dx * k * wa; a.y += dy * k * wa;
      b.x -= dx * k * wb; b.y -= dy * k * wb;
    }
  }
}

Digital twins

A digital twin is a virtual representation of a specific physical asset (a jet engine, a production line, a building, a city) that is kept synchronised with it by data from sensors, and that can be used to monitor, predict and optimise the real thing. Grieves and Vickers describe the concept as three parts: the physical product, the virtual product, and the data and information connections between them73. Tao and colleagues review industrial applications including product design, production planning, and prognostics and health management74. Graphics provides the twin's human interface: a 3D view in which live sensor values, simulation results and predicted failures are shown in spatial context, often reusing BIM or CAD geometry (Sections 5 and 6) and, increasingly, VR and AR displays (Sections 10 and 11).

class PumpTwin:
    def __init__(self, model, renderer):

        self.state = model.initial_state()

        # 3. Present: colour the 3D geometry by temperature, flag predicted hot spots

        return forecast.recommended_actions()
