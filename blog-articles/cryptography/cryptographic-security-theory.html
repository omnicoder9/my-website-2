Cryptographic Security Theory

What it means for a scheme to be “secure”, how we model the attacker, how we prove security, and which hard problems those proofs ultimately rest on.

Prerequisites: probability, modular arithmetic, basic complexity theory. Companion articles in this series cover fundamentals, mathematical foundations and classical ciphers. Last checked November 2026.

Introduction and notation

Before the late 1970s, a cipher was considered “secure” if nobody had yet broken it. Modern cryptography replaces that folklore with a three-part discipline: a precise definition of what the adversary is allowed to do and what counts as a break, a precisely stated assumption about some problem being hard, and a proof that any efficient break of the scheme yields an efficient solution to the hard problem[1,2]. This article is about all three. Following Kerckhoffs, we always assume the adversary knows the full algorithm; only the key is secret[3].

The ideas go back to Shannon’s information-theoretic treatment of secrecy[4] and, decisively, to Goldwasser and Micali’s Probabilistic Encryption, which introduced semantic security, indistinguishability and the reduction-based proof style[5]. Goldwasser and Micali received the 2012 ACM A.M. Turing Award largely for this work[6].

Notation used throughout
  • \(\lambda\) (or \(n\)) is the security parameter, given to all algorithms in unary as \(1^\lambda\).
  • \(x \getsr S\) samples \(x\) uniformly from a finite set \(S\); \(y \leftarrow \A(x)\) runs a (possibly randomised) algorithm.
  • A function \(\nu(\lambda)\) is negligible if for every polynomial \(p\) there is \(N\) with \(\nu(\lambda) \lt 1/p(\lambda)\) for all \(\lambda \gt N\). Example: \(2^{-\lambda}\) is negligible; \(1/\lambda^{10}\) is not.
  • PPT = probabilistic polynomial time. \(\A^{\mathcal{O}}\) means \(\A\) has oracle access to \(\mathcal{O}\).
  • A symmetric scheme is \(\Pi = (\Gen, \Enc, \Dec)\); a signature scheme is \((\Gen, \Sign, \Vrfy)\).

1Security models

A security model fixes two things: how powerful the adversary is (computationally and in what it can observe or influence), and what quantitative guarantee we demand. The three classical levels differ in what they assume about the adversary’s running time.

1.1 Perfect (information-theoretic) security

Definition 1.1 (Perfect secrecy, Shannon 1949)

An encryption scheme over message space \(\M\) is perfectly secret if for every distribution over \(\M\), every message \(m\) and every ciphertext \(c\) with \(\Pr[C=c] \gt 0\): \[\Pr[M = m \mid C = c] = \Pr[M = m].\] Equivalently, for all \(m_0, m_1 \in \M\) and all \(c\): \(\Pr[\Enc_K(m_0)=c] = \Pr[\Enc_K(m_1)=c]\), where the probability is over \(K \leftarrow \Gen\)[1,4].

The ciphertext carries zero information about the plaintext, even to an adversary with unlimited computing power. The one-time pad over \(\{0,1\}^\ell\), with \(c = m \oplus k\) and \(k\) uniform, achieves it: for any \(m, c\) there is exactly one key \(k = m \oplus c\), so \(\Pr[C = c \mid M = m] = 2^{-\ell}\) independently of \(m\).

Theorem 1.2 (Shannon’s key-length bound)

If a scheme is perfectly secret then \(|\K| \ge |\M|\)[1,4].

Proof sketch. Fix a ciphertext \(c\) that occurs. Let \(\M(c) = \{\Dec_k(c) : k \in \K\}\), so \(|\M(c)| \le |\K|\). If \(|\K| \lt |\M|\) there is some \(m' \notin \M(c)\), giving \(\Pr[M = m' \mid C = c] = 0 \ne \Pr[M=m']\) under the uniform distribution. \(\square\)

This is why perfect secrecy is impractical for bulk data: keys must be as long as all traffic and never reused. Reusing a pad leaks \(c_1 \oplus c_2 = m_1 \oplus m_2\). Perfect security is practical for some primitives: Shamir secret sharing, one-time MACs over finite fields, and many information-theoretic MPC protocols.

1.2 Statistical security

Statistical security relaxes “identical” to “almost identical”, still against unbounded adversaries. The distance measure is the statistical (total-variation) distance: \[\Delta(X, Y) = \tfrac12 \sum_{v} \bigl|\Pr[X=v] - \Pr[Y=v]\bigr| = \max_{T} \bigl|\Pr[X \in T] - \Pr[Y \in T]\bigr|.\] The second form shows that \(\Delta(X,Y)\) is exactly the best advantage any distinguisher, however powerful, can have in telling one sample of \(X\) from one sample of \(Y\)[2,7]. A scheme is \(\varepsilon\)-statistically secure if the relevant distributions (for example, encryptions of \(m_0\) and of \(m_1\)) are at distance at most \(\varepsilon\), and statistically secure if \(\varepsilon(\lambda)\) is negligible.

Worked example 1.3 (modular reduction bias)

To sample \(x \in \Z_q\) one often draws a uniform \(k\)-bit integer \(r\) and outputs \(r \bmod q\). Write \(2^k = aq + b\) with \(0 \le b \lt q\). Residues below \(b\) occur \(a+1\) times, the rest \(a\) times. Then \(\Delta(r \bmod q,\ U_{\Z_q}) = b(q-b)/(q \cdot 2^k) \lt q/2^{k}\). For \(q \approx 2^{255}\) and \(k = 384\), the distance is below \(2^{-129}\): statistically negligible, which is why FIPS-style generators oversample by 64 or more bits.

A key tool is the leftover hash lemma: hashing a source with min-entropy \(k\) through a universal hash family to \(m\) bits gives output within distance \(2^{-(k-m)/2}\) of uniform[8]. It underpins randomness extraction, key derivation and the security proof of Regev’s LWE encryption (Section 5.5)[9].

1.3 Computational security

Shannon’s bound forces us to weaken the model if keys are to be short. Computational security, made rigorous by Yao and by Goldwasser and Micali, accepts two relaxations[1,5,10]:

  1. security holds only against adversaries running in some feasible time;
  2. such adversaries may succeed with some tiny probability.

Two distribution ensembles \(\{X_\lambda\}\) and \(\{Y_\lambda\}\) are computationally indistinguishable, written \(X \approx_c Y\), if for every PPT distinguisher \(D\), \[\bigl|\Pr[D(1^\lambda, X_\lambda) = 1] - \Pr[D(1^\lambda, Y_\lambda) = 1]\bigr| \le \negl(\lambda).\] Every modern practical cipher, MAC, signature and key exchange is only computationally secure. A 128-bit key is \(2^{128}\) possibilities. A brute-force attacker testing \(t\) keys succeeds with probability exactly \(t/2^{128}\), which is negligible for any feasible \(t\).

1.4 Asymptotic versus concrete security

There are two ways to state “feasible time” and “tiny probability”.

Asymptotic securityConcrete (exact) security
AdversaryAny PPT algorithm in \(\lambda\)Any algorithm with running time \(\le t\), at most \(q\) oracle queries
GuaranteeAdvantage is \(\negl(\lambda)\)Advantage is \(\le \varepsilon\) for explicit \((t, q, \varepsilon)\)
Statement form“\(\Pi\) is secure if problem \(P\) is hard”\(\Adv_\Pi(t,q) \le c \cdot \Adv_P(t') + \delta(q)\), with explicit \(c\), \(t'\), \(\delta\)
StrengthsRobust and clean; closed under polynomial compositionGives actual parameter sizes; exposes loose reductions
OriginGoldwasser and Micali; Yao[5,10]Bellare and Rogaway and coauthors[11,12]

A scheme is called \((t, \varepsilon)\)-secure if every adversary with running time at most \(t\) achieves advantage at most \(\varepsilon\). We say it offers \(\kappa\) bits of security when \(t/\varepsilon \gtrsim 2^\kappa\) for all \(t\). NIST SP 800-57 maps key sizes onto such strengths. For example, AES-128, 3072-bit RSA and 256-bit elliptic curves are all rated at 128 bits[13].

Worked example 1.4 (why concrete bounds matter)

The PRP/PRF switching lemma says a random permutation on \(n\)-bit blocks and a random function differ, to a \(q\)-query adversary, by at most \(q(q-1)/2^{n+1}\)[1,14]. Asymptotically this is negligible for any polynomial \(q\), so “CTR mode with a PRP is IND-CPA” holds for both AES (\(n=128\)) and 3DES (\(n=64\)). Concretely, after \(q = 2^{32}\) blocks (32 GiB) the bound is about \(2^{-65}\) for AES but about \(2^{-1}\) for a 64-bit block. The Sweet32 attack turned that collision bound into practical plaintext recovery against 3DES and Blowfish in TLS and OpenVPN[15].

Asymptotic statements are not empty. They say how security scales, and they compose cleanly. But Koblitz and Menezes argued persuasively that asymptotic theorems can hide reductions so loose that the “proved” parameters are meaningless in practice[16]. Section 4.8 returns to this point.

1.5 Adversarial models

The adversary is modelled as an algorithm. Each modelling choice below strengthens or weakens the result:

  • Computational power: unbounded (information-theoretic setting), PPT (uniform), non-uniform polynomial-size circuits (models precomputation or advice), or quantum polynomial time. Shor’s algorithm breaks factoring and discrete logarithms in quantum polynomial time[17]. Grover search gives a quadratic speed-up for exhaustive key search[18].
  • Interface: which oracles the adversary may query (encryption, decryption, signing, hash, leakage), how many times, and whether it can choose queries adaptively. This is the subject of Section 2.
  • Corruption (protocols): static (parties are corrupted before execution) versus adaptive (parties are corrupted during it). Corrupted parties may be semi-honest, meaning they follow the protocol but try to learn more, or malicious, meaning they deviate arbitrarily[19,20].
  • Network: the Dolev–Yao model gives the attacker full control of the network. It can read, drop, reorder, replay and inject messages, but it treats cryptography as perfect black boxes[21]. The computational analogue for key exchange is the Bellare–Rogaway model[22].
  • Physical access: standard models treat algorithms as black boxes. Leakage and side-channel models (Section 2.9) let the adversary see timing, power or electromagnetic traces.

1.6 Security games and security experiments

A security experiment, also called a game, is a probabilistic program played between a challenger, who runs the scheme with secret keys and a hidden random choice, and an adversary, who interacts through oracles and finally outputs something. The definition of security is a bound on the probability of a defined winning event[1,14,23].

There are two kinds of game.

  • Decisional (indistinguishability) games hide a bit \(b\). The advantage is \[\Adv(\A) = \bigl|2\Pr[b' = b] - 1\bigr| = \bigl|\Pr[b'=1 \mid b=1] - \Pr[b'=1 \mid b=0]\bigr|.\] The two expressions are equal, a fact used constantly in proofs. Random guessing gives advantage 0. (Some texts omit the factor 2 and write \(\Pr[b'=b] - \tfrac12\).)
  • Search (computational) games ask the adversary to produce a value: a forgery, a preimage, a factor, a discrete logarithm. The advantage is simply \(\Pr[\A \text{ wins}]\).

Writing games as explicit pseudocode was popularised by Shoup’s sequences of games[23] and Bellare and Rogaway’s code-based game-playing framework[14]. Precise code makes proofs checkable, and machine-checkable in tools such as EasyCrypt (Section 7).

2Attack models

Attack models describe what the adversary can see and do before and during the attack. They form a rough hierarchy. Security against a stronger attack implies security against every weaker one[1,24].

2.1 Ciphertext-only attack (COA)

The adversary sees only ciphertexts. Classical ciphers fall to COA by frequency analysis (covered in the classical-cryptography article of this series). For a modern scheme, resisting only COA is far too weak. An eavesdropper on a real network nearly always knows or can guess some plaintext, such as protocol headers.

2.2 Known-plaintext attack (KPA)

The adversary has pairs \((m_i, c_i)\) that it did not choose. Matsui’s linear cryptanalysis of DES is the canonical KPA. It recovers the key from about \(2^{43}\) known plaintexts[25].

2.3 Chosen-plaintext attack (CPA)

The adversary obtains encryptions of plaintexts of its choice. In the public-key setting, CPA access is automatic, because anyone can encrypt under the public key. Differential cryptanalysis of DES needs about \(2^{47}\) chosen plaintexts[26]. In the formal IND-CPA game the adversary has an encryption oracle throughout (Section 3.2).

2.4 Adaptive chosen-plaintext attack

The adversary chooses each query after seeing earlier answers, including after the challenge. A non-adaptive (batch) CPA adversary must commit to all queries in advance. Modern definitions such as IND-CPA are adaptive by default[1,11]. Adaptivity matters in practice. CBC mode whose IV is predictable, for example the last ciphertext block of the previous record, is secure against non-adaptive queries but falls to an adversary who chooses its next plaintext knowing the next IV[1,7].

2.5 Chosen-ciphertext attack (CCA1, “lunchtime”)

The adversary may also obtain decryptions of ciphertexts of its choice, but only before it receives the challenge. The picture is an attacker with access to a decryption box during the lunch break. The notion was formalised by Naor and Yung[27].

2.6 Adaptive chosen-ciphertext attack (CCA2)

The decryption oracle remains available after the challenge. The only restriction is that the adversary may not ask for the challenge ciphertext itself. Rackoff and Simon introduced the notion[28]. It became the accepted standard for public-key encryption after Bleichenbacher’s “million-message” attack on RSA PKCS #1 v1.5. In that attack, a server that merely reported whether a decrypted message was correctly padded acted as a partial decryption oracle, enough to decrypt any ciphertext[29]. Vaudenay’s CBC padding-oracle attack is the symmetric counterpart[30]. In practice, any error message, timing difference or behavioural change that depends on the plaintext can serve as a decryption oracle.

2.7 Related-key attacks (RKA)

The adversary obtains encryptions under keys \(\phi(k)\) for functions \(\phi\) of its choice applied to the unknown key, for example \(k \oplus \Delta\). Biham introduced the attack class[31]. Bellare and Kohno formalised it as security relative to a class \(\Phi\) of related-key-deriving functions, and showed that no block cipher can resist every class[32]. Biryukov and Khovratovich gave related-key attacks on the full AES-256 using four related keys with time and data about \(2^{99.5}\)[33]. That is well below \(2^{256}\), but it does not affect AES used normally, because properly derived keys are not related in this way.

2.8 Multi-user (multi-key) attacks

Real deployments have millions of users, each with its own key. The adversary wins if it breaks any one of them. A generic hybrid argument shows that \(u\)-user advantage is at most \(u\) times single-user advantage[34]. This loss is real for generic attacks. Exhaustive search against \(u\) keys simultaneously succeeds \(u\) times faster: with \(2^{30}\) keys, a \(2^{80}\)-step search on 128-bit keys hits some key with probability about \(2^{-18}\) instead of \(2^{-48}\). Bellare and Tackmann analysed AES-GCM in TLS 1.3 in the multi-user setting. They showed that TLS 1.3’s per-connection nonce randomisation measurably improves multi-user security[35].

2.9 Side-channel attacks

Side channels break the black-box assumption. The attacker observes physical properties of the computation: time, power, electromagnetic emanations, cache state, acoustic noise or faults. Kocher’s timing attacks recovered RSA and Diffie–Hellman exponents from running-time variations[36]. Differential power analysis extracts keys from smart cards with statistical analysis of power traces[37]. Brumley and Boneh showed that timing attacks work remotely over a network against OpenSSL[38]. Spectre showed that speculative execution can leak secrets across security boundaries[39].

Theory meets practice

A scheme proved IND-CCA2 secure can still be broken by side channels, because the proof models \(\Dec\) as an ideal oracle that reveals nothing but its output. Countermeasures include constant-time code (no secret-dependent branches or memory indices), masking, blinding, and formal leakage-resilient models in which the adversary receives a bounded function of the secret state.

3Formal security definitions

A security definition is a pair (attack model, security goal). Notions are named GOAL-ATTACK, so IND-CCA2 means the goal of indistinguishability under adaptive chosen-ciphertext attack[24].

3.1 Indistinguishability

Indistinguishability (IND), originally “polynomial security”[5], asks that no efficient adversary can tell an encryption of \(m_0\) from an encryption of \(m_1\), even when it chose both messages itself. The messages must have equal length, because encryption generally reveals length. The definition is deliberately worst-case: the adversary picks the most informative pair of messages it can find.

3.2 IND-CPA security

Definition 3.1 (IND-CPA)

For a scheme \(\Pi\) and adversary \(\A\), the experiment \(\Exp^{\text{ind-cpa}}_{\Pi}(\A)\) is:

k ← Gen(1^λ);  b ←$ {0,1}
(m0, m1, st) ← A^{Enc(k,·)}(1^λ)          // |m0| = |m1|
c* ← Enc(k, m_b)
b' ← A^{Enc(k,·)}(st, c*)
return [b' = b]

\(\Pi\) is IND-CPA secure if every PPT \(\A\) has \[\Adv^{\text{ind-cpa}}_\Pi(\A) = |2\Pr[\Exp = 1] - 1| \le \negl(\lambda)\][1,11]. For public-key schemes, \(\A\) receives \(pk\) in place of the oracle.

Fact 3.2

No deterministic, stateless encryption scheme is IND-CPA secure. The adversary queries \(c_0 \leftarrow \Enc(k, m_0)\) and outputs \(b' = 0\) iff \(c^* = c_0\), winning with probability 1[1,5]. IND-CPA therefore requires randomised (or stateful, nonce-based) encryption. Goldwasser and Micali took exactly this step in 1984. See Code lab 6.1.

Standard constructions: \(\Enc_k(m) = (r, F_k(r) \oplus m)\) for a PRF \(F\), CTR and CBC modes with random IVs, and ElGamal under DDH.

3.3 IND-CCA1 and IND-CCA2 security

Definition 3.3 (IND-CCA) 
k ← Gen(1^λ);  b ←$ {0,1}
(m0, m1, st) ← A^{Enc(k,·), Dec(k,·)}(1^λ)
c* ← Enc(k, m_b)
b' ← A^{Enc(k,·), Dec*(k,·)}(st, c*)
return [b' = b]
     CCA1:  Dec* returns ⊥ on every query           (no decryption after the challenge)
     CCA2:  Dec*(c) = Dec(k,c) for c ≠ c*, ⊥ for c = c*

The scheme is IND-CCA\(i\) secure if every PPT adversary has negligible advantage[24,27,28].

Bellare, Desai, Pointcheval and Rogaway mapped the relations between these notions and non-malleability (NM). The adversary in NM must turn \(c^*\) into a ciphertext of a related plaintext. The key results are:

  • IND-CCA2 \(\Leftrightarrow\) NM-CCA2. Under adaptive chosen-ciphertext attack, hiding and non-malleability coincide.
  • IND-CCA2 \(\Rightarrow\) IND-CCA1 \(\Rightarrow\) IND-CPA, and both implications are strict (assuming any secure scheme exists)[24].
Worked example 3.4 (malleability kills CCA2)

The IND-CPA-secure scheme \(c = (r, F_k(r) \oplus m)\) is malleable. Flipping bit \(i\) of the second component flips bit \(i\) of the plaintext. A CCA2 adversary submits \(m_0 = 0^\ell\) and \(m_1 = 1^\ell\), flips one bit of \(c^*\) to get \(c' \ne c^*\), and asks the decryption oracle for \(\Dec(c')\). The answer is \(m_b\) with one bit flipped, revealing \(b\) with advantage 1. Code lab 6.2 runs this attack. Textbook RSA (\(c = m^e\)) and plain ElGamal are malleable in the same way.

Practical IND-CCA2 public-key encryption comes from RSA-OAEP in the random oracle model[40], from the Fujisaki–Okamoto transform[41,42] (used by ML-KEM[43]), or in the standard model from Cramer–Shoup under DDH[44].

3.4 Semantic security

Semantic security formalises Shannon’s idea computationally: whatever an efficient adversary can compute about the plaintext from the ciphertext, it could compute without the ciphertext[5].

Definition 3.5 (Semantic security, simplified)

For every PPT \(\A\) there is a PPT simulator \(\S\) such that, for every efficiently sampleable message distribution \(\mathcal{D}\) and all functions \(f\) (what is learned) and \(h\) (prior information, such as length), \[\Bigl|\Pr\bigl[\A(1^\lambda, \Enc_k(m), h(m)) = f(m)\bigr] - \Pr\bigl[\S(1^\lambda, |m|, h(m)) = f(m)\bigr]\Bigr| \le \negl(\lambda),\] with \(m \leftarrow \mathcal{D}\)[1,2].

Theorem 3.6 (Equivalence)

A scheme is semantically secure (under CPA) if and only if it is IND-CPA secure. Goldwasser and Micali proved IND \(\Rightarrow\) SS[5]. Micali, Rackoff and Sloan completed the equivalence[45].

Semantic security says what we want. Indistinguishability is what we prove, because it is far easier to work with. This simulation-flavoured definition is the template for Section 3.8.

3.5 Ciphertext integrity (INT-CTXT) and authenticated encryption

Definition 3.7 (INT-CTXT) 
k ← Gen(1^λ);  S ← ∅
c ← A^{Enc'(k,·)}            // Enc' encrypts m and adds the result to S
return [Dec(k,c) ≠ ⊥  and  c ∉ S]

The scheme has ciphertext integrity if every PPT adversary wins with negligible probability[46]. The weaker INT-PTXT only forbids valid ciphertexts of new plaintexts.

Theorem 3.8 (Bellare–Namprempre)

IND-CPA \(\wedge\) INT-CTXT \(\Rightarrow\) IND-CCA2. Generic Encrypt-then-MAC with an IND-CPA cipher and a strongly unforgeable MAC achieves both. Encrypt-and-MAC and MAC-then-Encrypt do not achieve them in general[46].

Schemes meeting both notions are called authenticated encryption (AE). Examples are AES-GCM and ChaCha20-Poly1305, both used in TLS 1.3. Proof sketch of Theorem 3.8: by INT-CTXT, the decryption oracle returns \(\bot\) on every query the adversary did not get from the encryption oracle, except with negligible probability. Ciphertexts it did get from the encryption oracle have plaintexts it already knows. So the decryption oracle is useless and can be simulated, which reduces CCA2 to CPA. This is a two-game hop.

3.6 Unforgeability, existential unforgeability and EUF-CMA

For authentication (MACs and signatures) the goal is unforgeability: the adversary cannot produce a valid tag or signature it was not given. Goldwasser, Micali and Rivest set out the taxonomy[47]:

  • Total break: recover the signing key.
  • Universal forgery: forge on any message given to the adversary.
  • Selective forgery: forge on a message the adversary chose before the attack.
  • Existential forgery: forge on some message, possibly meaningless. This is the weakest goal for the adversary, so ruling it out gives the strongest guarantee.

Attacks range from key-only, through known-message, to adaptive chosen-message attack (CMA).

Definition 3.9 (EUF-CMA) 
(pk, sk) ← Gen(1^λ);  Q ← ∅
(m*, σ*) ← A^{Sign(sk,·)}(pk)        // each query m is added to Q
return [Vrfy(pk, m*, σ*) = 1  and  m* ∉ Q]

The scheme is EUF-CMA secure if every PPT adversary wins with negligible probability[1,47]. For MACs the same game, with a tag oracle and no public key, is called UF-CMA.

Worked example 3.10 (textbook RSA is not EUF-CMA)

Textbook RSA signs with \(\sigma = m^d \bmod N\). It is multiplicatively homomorphic: \(\sigma_1\sigma_2\) is a valid signature on \(m_1 m_2\). Without any query, \((\sigma, \sigma^e)\) for random \(\sigma\) is already an existential forgery. With one query on the blinded message \(m^* r^e\), the adversary computes \(\sigma^* = \sigma \cdot r^{-1}\), a forgery on any target \(m^*\) (Code lab 6.5). Hashing first, as in Full-Domain Hash \(\sigma = H(m)^d\), blocks this attack. FDH is EUF-CMA in the random oracle model[12,48].

3.7 Strong unforgeability (SUF-CMA)

Strong unforgeability changes the win condition to \((m^*, \sigma^*) \notin Q\), where \(Q\) is now the set of message-signature pairs returned. A fresh signature on an already-signed message counts as a forgery[49]. SUF-CMA matters when signatures act as identifiers, and it is needed in generic CCA2 constructions. ECDSA is EUF-CMA but not SUF-CMA, because \((r, -s \bmod n)\) is also valid whenever \((r, s)\) is. This kind of signature malleability let attackers change Bitcoin transaction IDs without invalidating them, a problem studied in connection with the MtGox collapse[50].

3.8 Simulation-based security

Game-based definitions list specific bad events. Simulation-based definitions instead compare the real world with an ideal world in which a trusted party computes the desired function. A protocol \(\pi\) securely realises functionality \(\mathcal{F}\) if for every real-world adversary \(\A\) there is an ideal-world simulator \(\S\) such that the joint output of the honest parties and the adversary is computationally indistinguishable between the two worlds[19,20]: \[\{\text{REAL}_{\pi,\A}(x)\} \approx_c \{\text{IDEAL}_{\mathcal{F},\S}(x)\}.\] Intuitively, anything the adversary achieves in the real protocol it could also have achieved by attacking the ideal party, which leaks nothing beyond the prescribed outputs. Semantic security (Definition 3.5), zero-knowledge proofs and secure multiparty computation are all simulation-based. The paradigm captures privacy and correctness at once, and it extends to composition through universal composability (Section 4.7). The price is that simulation-based definitions are often harder to satisfy, and some are impossible without setup assumptions[51].

3.9 Map of relations

4Security proofs

4.1 Reduction-based proofs

A security reduction proves “if problem \(P\) is hard then scheme \(\Pi\) is secure” by contraposition. Given any adversary \(\A\) that breaks \(\Pi\), we build an algorithm \(\B\), the reduction, that solves \(P\) using \(\A\) as a subroutine. \(\B\) must simulate \(\A\)’s security game faithfully, using only its own \(P\)-instance, and then extract a solution from \(\A\)’s output[1,2].

Worked example 4.1 (PRG ⇒ secure one-message encryption)

Let \(G : \{0,1\}^\lambda \to \{0,1\}^\ell\) be a PRG and \(\Enc_s(m) = G(s) \oplus m\). Given an eavesdropper \(\A\) with advantage \(\varepsilon\), the distinguisher \(\B(y)\) picks \(b \getsr \{0,1\}\), gets \((m_0, m_1)\) from \(\A\), gives it \(y \oplus m_b\), and outputs 1 iff \(\A\) answers \(b\).

  • If \(y = G(s)\), \(\A\)’s view is exactly the real game, so \(\Pr[\B = 1] = \tfrac12 + \tfrac{\varepsilon}{2}\).
  • If \(y\) is uniform, \(y \oplus m_b\) is a one-time pad, so \(\Pr[\B = 1] = \tfrac12\).

Therefore \(\Adv^{\text{prg}}_G(\B) = \varepsilon/2\), that is, \(\Adv^{\text{ind}}_\Pi(\A) \le 2\,\Adv^{\text{prg}}_G(\B)\). \(\B\) runs in essentially the same time as \(\A\), so the reduction is tight[1].

4.2 Hybrid arguments

The hybrid argument, which goes back to Goldwasser–Micali and Yao[5,10], handles indistinguishability of distributions that differ in many places. Define a chain \(H_0, H_1, \ldots, H_q\) where \(H_0\) and \(H_q\) are the two distributions of interest and adjacent hybrids differ in one “position”. By the triangle inequality, \[\bigl|\Pr[D(H_0)=1] - \Pr[D(H_q)=1]\bigr| \le \sum_{i=1}^{q} \bigl|\Pr[D(H_{i-1})=1] - \Pr[D(H_i)=1]\bigr|.\] If each adjacent pair is \(\varepsilon\)-indistinguishable, the extremes are \(q\varepsilon\)-indistinguishable. In the reduction, \(\B\) picks \(i \getsr \{1,\dots,q\}\) at random, embeds its challenge at position \(i\), and fills positions before \(i\) with one distribution and those after with the other. This gives advantage at least \((\text{total})/q\)[1,2].

Classic applications. (i) Single-message IND for public-key encryption implies multi-message IND, losing a factor \(q\). (ii) A PRG with 1-bit stretch can be iterated into one with polynomial stretch. (iii) Single-user security implies multi-user security, losing a factor \(u\)[34]. The factor \(q\) or \(u\) is exactly the tightness loss discussed in Section 4.8.

4.3 Game hopping (sequences of games)

Shoup’s game-hopping methodology[23], formalised as code by Bellare and Rogaway[14], structures a proof as a sequence \(G_0, G_1, \dots, G_n\). \(G_0\) is the real attack game, \(G_n\) is a game in which the adversary’s success probability is obviously trivial, and each hop changes one thing. Let \(S_i\) be the event that the adversary wins in \(G_i\). Shoup identifies three kinds of transition:

  1. Indistinguishability hop. If a distinguisher between \(G_i\) and \(G_{i+1}\) would break an assumption, then \(|\Pr[S_i] - \Pr[S_{i+1}]| \le \Adv_{P}(\B)\).
  2. Failure-event hop. If \(G_i\) and \(G_{i+1}\) are identical unless a bad event \(F\) occurs, the difference lemma gives \[(S_i \wedge \neg F) \Leftrightarrow (S_{i+1} \wedge \neg F) \;\Longrightarrow\; |\Pr[S_i] - \Pr[S_{i+1}]| \le \Pr[F].\]
  3. Bridging hop. The change is purely syntactic, so \(\Pr[S_i] = \Pr[S_{i+1}]\).
Theorem 4.2 (IND-CPA of PRF-based encryption)

For \(\Enc_k(m) = (r, F_k(r) \oplus m)\) with \(r \getsr \{0,1\}^n\), and any \(\A\) making \(q\) encryption queries, there is a PRF adversary \(\B\) of about the same running time with \[\Adv^{\text{ind-cpa}}_\Pi(\A) \le 2\,\Adv^{\text{prf}}_F(\B) + \frac{2q}{2^n}.\]

Proof. In \(G_1\), replace \(F_k\) by a truly random function \(f\). \(\B\) simulates with its own oracle, so \(|\Pr[S_0]-\Pr[S_1]| \le \Adv^{\text{prf}}_F(\B)\). In \(G_2\), let \(F\) be the event that the challenge nonce \(r^*\) equals one of the at most \(q\) nonces used in oracle queries. Then \(\Pr[F] \le q/2^n\), and \(G_1\) and \(G_2\) agree unless \(F\) occurs. When \(F\) does not occur, \(f(r^*)\) is uniform and independent of everything else the adversary sees, so \(c^*\) is independent of \(b\) and \(\Pr[S_2] = \tfrac12\). Summing gives \(|\Pr[S_0]-\tfrac12| \le \Adv^{\text{prf}}_F(\B) + q/2^n\), and doubling gives the claim[1,23]. \(\square\)

4.4 The random oracle model (ROM)

Bellare and Rogaway proposed modelling a hash function \(H\) as a random oracle: a uniformly random function that all parties, the adversary included, can access only by queries[52]. Proofs in the ROM exploit three powers that a real hash function does not give the reduction:

  • Observability: the reduction sees every query the adversary makes to \(H\).
  • Programmability: the reduction chooses the answers, for example setting \(H(m) = y \cdot r^e\) to embed an RSA challenge \(y\) in FDH[12,48].
  • Rewinding with fresh answers: the forking lemma reruns the adversary with a different value for one query, to extract two related signatures and, from them, a Schnorr secret key[53,54].

The ROM yields efficient schemes such as OAEP, FDH/PSS, Schnorr signatures and the Fujisaki–Okamoto transform[12,40,41,54]. But it is a heuristic. Canetti, Goldreich and Halevi constructed (contrived) schemes that are secure in the ROM yet insecure under every concrete instantiation of the hash function[55]. A related refinement is indifferentiability[56]. Plain Merkle–Damgård hashes are not indifferentiable from a random oracle, which is why length-extension attacks on SHA-256 exist even though SHA-256 is believed collision-resistant.

4.5 The standard model

A proof in the standard model (or “plain model”) assumes only that specified computational problems are hard. No component is idealised. Examples include the GMR signature scheme[47], Cramer–Shoup IND-CCA2 encryption under DDH[44] and the Boneh–Shen–Waters strongly unforgeable signatures under CDH[49]. Standard-model proofs give stronger evidence, but the schemes are usually less efficient, or rely on stronger or less-studied assumptions. Many practitioners treat a ROM proof for a simple scheme as an acceptable trade-off. Theorists value standard-model results as existence proofs.

4.6 The ideal cipher model (ICM)

The ICM models a block cipher \(E : \K \times \{0,1\}^n \to \{0,1\}^n\) as a family of independent uniformly random permutations, one per key. The adversary has oracle access to both \(E\) and \(E^{-1}\). The idea goes back to Shannon[4]. It is the natural model for constructions that use a block cipher with adversarially chosen keys, such as Davies–Meyer and the other PGV compression functions, whose collision resistance Black, Rogaway and Shrimpton proved in the ICM[57]. Holenstein, Künzler and Tessaro proved the ICM and ROM equivalent in the indifferentiability sense, by showing that a 14-round Feistel network on a random oracle is indifferentiable from an ideal cipher[58]. The ICM is a strong idealisation. AES-256’s related-key weaknesses[33] show that a real cipher can be secure as a pseudorandom permutation and still be far from “ideal” when keys are under attacker control.

4.7 Universal composability (UC)

Traditional definitions guarantee security only when a protocol runs in isolation. Canetti’s universal composability framework adds an environment \(\mathcal{Z}\): an interactive distinguisher that chooses the parties’ inputs, sees their outputs, and talks freely with the adversary throughout the execution[59]. Protocol \(\pi\) UC-realises ideal functionality \(\mathcal{F}\) if for every adversary \(\A\) there is a simulator \(\S\) such that no environment can tell whether it is interacting with \((\pi, \A)\) or with \((\mathcal{F}, \S)\).

UC composition theorem (informal)

If \(\pi\) UC-realises \(\mathcal{F}\), and protocol \(\rho\) is secure when it uses \(\mathcal{F}\) as a subroutine, then \(\rho\) remains secure when every call to \(\mathcal{F}\) is replaced by a run of \(\pi\), even with arbitrarily many concurrent instances[59].

The guarantee is strong, and so is the price. Canetti and Fischlin proved that UC-secure commitment is impossible in the plain model with two parties. Setup assumptions, such as a common reference string, are necessary[51].

4.8 Tight versus loose reductions

Suppose a reduction shows: if \(\A\) breaks \(\Pi\) in time \(t\) with advantage \(\varepsilon\), then \(\B\) solves \(P\) in time \(t'\) with advantage \(\varepsilon'\). The tightness loss is \[L = \frac{t'/\varepsilon'}{t/\varepsilon}.\] The reduction is tight if \(L\) is a small constant, and loose if \(L\) grows with \(q\), \(u\) or \(\lambda\). To guarantee \(\kappa\) bits of security for \(\Pi\), \(P\) must offer roughly \(\kappa + \log_2 L\) bits[12,16].

4.9 Assumption-based security

Almost every proof is conditional: “\(\Pi\) is secure if assumption \(X\) holds.” Unconditional proofs of computational security would imply \(\mathsf{P} \ne \mathsf{NP}\), and indeed the existence of one-way functions. Good assumptions are:

  • Simple and falsifiable: a non-interactive problem with an efficient way to check a claimed solution, such as factoring, DLP or LWE.
  • Long-studied: decades of cryptanalysis without significant progress.
  • Minimal: one-way functions suffice for PRGs, PRFs, symmetric encryption, MACs and signatures. Public-key encryption seems to need more structure (trapdoors)[2,8].
  • Robust to the threat model: LWE is believed quantum-hard, while factoring and DLP are not[9,17].

Idealised models sit between assumptions and proofs. The generic group model bounds algorithms that use only group operations, and shows that DLP takes \(\Omega(\sqrt{p})\) group operations in a prime-order-\(p\) group[61].

5Cryptographic hardness assumptions

Each assumption below is stated as a game against a PPT adversary. The mathematical background (groups, lattices, number theory) is covered in the maths-foundations article of this series. Here we focus on the precise statements, the known relations between them, and the best attacks.

5.1 The integer factorisation assumption

Assumption 5.1 (Factoring)

Let \(\mathsf{GenModulus}(1^\lambda)\) output \(N = pq\) for random \(\lambda\)-bit primes \(p, q\). For every PPT \(\A\), \(\Pr[\A(N) \in \{p, q\}] \le \negl(\lambda)\)[1].

The best classical algorithm is the general number field sieve, with heuristic running time \(L_N[1/3, (64/9)^{1/3}]\), where \(L_N[\alpha, c] = \exp\bigl((c+o(1))(\ln N)^\alpha (\ln\ln N)^{1-\alpha}\bigr)\). The record computations by Boudot and colleagues factored the 795-bit RSA-240 for about 900 core-years and solved a 795-bit prime-field discrete logarithm for about 3100 core-years[62]. Rabin showed that computing square roots modulo \(N\) is equivalent to factoring[63]. Shor’s algorithm factors in quantum polynomial time[17].

5.2 The RSA assumption

Assumption 5.2 (RSA)

Given \(N = pq\), an exponent \(e\) with \(\gcd(e, \varphi(N)) = 1\), and \(y \getsr \Z_N^*\), no PPT adversary can find \(x\) with \(x^e \equiv y \pmod N\) except with negligible probability[1,64].

Factoring \(N\) yields \(\varphi(N)\), then \(d = e^{-1} \bmod \varphi(N)\), then \(x = y^d\). So RSA is at least as easy as factoring. Whether the converse holds is open. Boneh and Venkatesan showed that for small \(e\), any “algebraic” (straight-line program) reduction from factoring to low-exponent RSA would itself yield a factoring algorithm. That is evidence that breaking RSA might be strictly easier than factoring[65]. The RSA function is a trapdoor permutation, the abstraction behind RSA-OAEP and RSA-FDH[12,40].

5.3 Discrete logarithm, CDH and DDH

Let \(\mathcal{G}(1^\lambda)\) output a cyclic group \(\G = \langle g \rangle\) of order \(q\) (with \(q\) usually prime, \(\log q \approx 2\lambda\)).

Assumptions 5.3 to 5.5
  • DL: given \((\G, q, g, h = g^x)\) with \(x \getsr \Z_q\), finding \(x\) is hard[1,66].
  • CDH: given \((g, g^x, g^y)\), computing \(g^{xy}\) is hard[66].
  • DDH: \((g, g^x, g^y, g^{xy}) \approx_c (g, g^x, g^y, g^z)\) for \(x, y, z \getsr \Z_q\)[67].

Clearly DL-easy \(\Rightarrow\) CDH-easy \(\Rightarrow\) DDH-easy. Equivalently, the assumptions get stronger in the order DL \(\Leftarrow\) CDH \(\Leftarrow\) DDH. Maurer and Wolf showed that DL and CDH are equivalent in many groups, given suitable auxiliary elliptic curves[68]. DDH, however, can be easy while CDH is hard:

  • In \(\Z_p^*\), whose order \(p-1\) is even, the Legendre symbol of \(g^{xy}\) can be computed from those of \(g^x\) and \(g^y\). This gives a DDH distinguisher with advantage \(1/2\) (Code lab 6.3). The usual fix is to work in the prime-order subgroup of quadratic residues[67].
  • In groups with an efficient bilinear pairing \(e\), the check \(e(g^x, g^y) = e(g, g^{xy})\) decides DDH outright, while CDH may still be hard. These are the “gap” groups used in pairing-based cryptography[67].

Generic attacks. Pollard’s rho method solves DL in \(O(\sqrt{q})\) group operations[69]. Shoup proved that in the generic group model, \(\Omega(\sqrt{q})\) operations are also necessary for DL and for DDH[61]. In \(\Z_p^*\), index-calculus attacks are subexponential, which is why finite-field groups need 3072-bit moduli for 128-bit security[13]. DDH is the basis of ElGamal’s IND-CPA security and of Cramer–Shoup’s IND-CCA2 security[44].

5.4 The elliptic curve discrete logarithm problem (ECDLP)

Miller and Koblitz independently proposed using the group of points \(E(\mathbb{F}_p)\) of an elliptic curve[70,71]. ECDLP asks: given points \(P\) and \(Q = [x]P\), find \(x\). For well-chosen curves, no attack better than generic \(O(\sqrt{q})\) Pollard rho is known. So a 256-bit curve gives about 128-bit security, comparable to 3072-bit RSA[13]. Weak classes exist. The MOV attack uses the Weil pairing to move ECDLP on supersingular (low embedding degree) curves into a finite field, where index calculus applies[72]. Like DL, ECDLP falls to Shor’s algorithm[17].

5.5 Learning with errors (LWE)

Assumption 5.6 (Decision-LWE, Regev 2005)

Fix dimension \(n\), modulus \(q\), number of samples \(m\), and an error distribution \(\chi\) on \(\Z\) (a discrete Gaussian of width \(\alpha q\), or a small uniform or binomial distribution). Then \[(\mathbf{A},\ \mathbf{A}\mathbf{s} + \mathbf{e} \bmod q) \;\approx_c\; (\mathbf{A},\ \mathbf{u}),\qquad \mathbf{A} \getsr \Z_q^{m \times n},\ \mathbf{s} \getsr \Z_q^n,\ \mathbf{e} \leftarrow \chi^m,\ \mathbf{u} \getsr \Z_q^m.\] Search-LWE asks to recover \(\mathbf{s}\). For polynomial \(q\), the search and decision versions are equivalent[9,73].

Without the error \(\mathbf{e}\), Gaussian elimination recovers \(\mathbf{s}\). With it, the problem becomes as hard as worst-case lattice problems. Regev gave a quantum reduction: for \(\alpha q \gt 2\sqrt{n}\), solving LWE on average implies quantumly approximating GapSVP and SIVP to within \(\tilde O(n/\alpha)\) on any \(n\)-dimensional lattice[9]. Peikert[74] and then Brakerski, Langlois, Peikert, Regev and Stehlé[75] gave classical reductions. Regev received the 2018 Gödel Prize for this work[76].

Regev’s encryption scheme. The public key is \((\mathbf{A}, \mathbf{b} = \mathbf{A}\mathbf{s} + \mathbf{e})\). To encrypt a bit \(\mu\), pick a random subset \(S\) of rows and output \(\mathbf{u} = \sum_{i \in S} \mathbf{a}_i\) and \(v = \sum_{i \in S} b_i + \mu\lfloor q/2 \rceil\). Decryption computes \(v - \langle \mathbf{u}, \mathbf{s}\rangle = \mu\lfloor q/2 \rceil + \sum_{i\in S} e_i\) and rounds. IND-CPA security follows in two hops: (1) by decision-LWE, replace \(\mathbf{b}\) with uniform; (2) by the leftover hash lemma, \((\mathbf{u}, v)\) is then statistically close to uniform[8,9]. See Code lab 6.4.

5.6 Ring-LWE and Module-LWE

Plain LWE keys are large, since \(\mathbf{A}\) has \(mn\) entries. Ring-LWE replaces \(\Z_q^n\) with the ring \(R_q = \Z_q[x]/(x^n + 1)\) for \(n\) a power of two. Samples are \((a, a\cdot s + e)\) with \(a \getsr R_q\) and \(s, e\) having small coefficients[77]. One ring element stands in for \(n\) correlated LWE samples, and multiplication costs \(O(n \log n)\) with the number-theoretic transform. Lyubashevsky, Peikert and Regev reduced worst-case problems on ideal lattices to Ring-LWE, again quantumly[77].

Module-LWE interpolates between the two. Secrets are vectors \(\mathbf{s} \in R_q^k\) and public matrices are \(\mathbf{A} \in R_q^{k \times k}\). Rank \(k = 1\) is Ring-LWE. Taking \(R = \Z\) recovers LWE. Langlois and Stehlé gave worst-case to average-case reductions for module lattices[78]. Module-LWE lets one ring (\(n = 256\)) and one fast NTT implementation serve several security levels by changing only \(k\). This is the design of NIST’s standards:

5.7 Short integer solution (SIS)

Assumption 5.7 (SIS, Ajtai 1996)

Given uniform \(\mathbf{A} \in \Z_q^{n \times m}\), find a nonzero \(\mathbf{z} \in \Z^m\) with \(\mathbf{A}\mathbf{z} \equiv \mathbf{0} \pmod q\) and \(\|\mathbf{z}\| \le \beta\)[80].

Ajtai’s breakthrough was the first worst-case to average-case reduction in cryptography: solving random SIS instances is as hard as approximating short-vector problems on every lattice[80]. Micciancio and Regev tightened it using Gaussian measures[81]. SIS directly gives a collision-resistant hash \(f_\mathbf{A}(\mathbf{z}) = \mathbf{A}\mathbf{z} \bmod q\) on \(\{0,1\}^m\) for \(m \gt n \log_2 q\). A collision \(\mathbf{z} \ne \mathbf{z}'\) gives the short SIS solution \(\mathbf{z} - \mathbf{z}' \in \{-1,0,1\}^m\). SIS and LWE are dual. An SIS solution \(\mathbf{z}\) for \(\mathbf{A}^\top\) distinguishes LWE, because \(\langle \mathbf{z}, \mathbf{A}\mathbf{s} + \mathbf{e}\rangle = \langle \mathbf{z}, \mathbf{e}\rangle\) is small[73,81]. Lattice signatures such as ML-DSA rely on (Module-)SIS for unforgeability[79].

6.1 IND-CPA: deterministic versus randomised encryption

This demonstrates Fact 3.2. The “repeat-query” adversary wins every time against deterministic encryption, and does no better than chance against \((r, F_k(r) \oplus m)\).

ind_cpa.py

"""IND-CPA game simulator: deterministic vs randomised encryption."""
import hmac, hashlib, secrets

def prf(key: bytes, x: bytes) -> bytes:
    """HMAC-SHA256 used as a stand-in pseudorandom function."""
    return hmac.new(key, x, hashlib.sha256).digest()

def xor(a: bytes, b: bytes) -> bytes:
    return bytes(x ^ y for x, y in zip(a, b))

class DeterministicScheme:          # Enc_k(m) = F_k(0) XOR m   (insecure)
    def keygen(self): return secrets.token_bytes(32)
    def enc(self, k, m): return xor(prf(k, b"\x00" * 16), m)

class RandomisedScheme:             # Enc_k(m) = (r, F_k(r) XOR m)
    def keygen(self): return secrets.token_bytes(32)
    def enc(self, k, m):
        r = secrets.token_bytes(16)
        return r + xor(prf(k, r), m)

def ind_cpa_game(scheme, adversary) -> bool:
    """Returns True iff the adversary guesses the hidden bit b."""
    k = scheme.keygen()
    oracle = lambda m: scheme.enc(k, m)          # encryption oracle
    m0, m1, state = adversary.choose(oracle)
    b = secrets.randbelow(2)
    c_star = scheme.enc(k, (m0, m1)[b])          # challenge ciphertext
    return adversary.guess(oracle, c_star, state) == b

class RepeatQueryAdversary:
    """Asks the oracle for Enc(m0) and compares it with the challenge."""
    def choose(self, oracle):
        m0, m1 = b"A" * 32, b"B" * 32
        return m0, m1, oracle(m0)
    def guess(self, oracle, c_star, c0):
        return 0 if c_star == c0 else 1

def advantage(scheme, adversary, trials=2000) -> float:
    wins = sum(ind_cpa_game(scheme, adversary) for _ in range(trials))
    return abs(2 * wins / trials - 1)            # Adv = |2 Pr[win] - 1|

if __name__ == "__main__":
    A = RepeatQueryAdversary()
    print("deterministic:", advantage(DeterministicScheme(), A))
    print("randomised   :", round(advantage(RandomisedScheme(), A), 3))
deterministic: 1.0
randomised   : 0.017

The randomised scheme’s nonzero estimate is sampling noise. With 2000 trials, the standard error of the advantage estimate is about \(2\sqrt{0.25/2000} \approx 0.022\).

6.2 IND-CCA2: the bit-flipping attack

This shows that the same IND-CPA-secure scheme falls to a single decryption query (Worked example 3.4).

cca_malleable.py

"""IND-CCA2 attack on the IND-CPA-secure randomised scheme (r, F_k(r) XOR m)."""
import secrets
from ind_cpa import RandomisedScheme, prf, xor

def dec(k, c):
    r, body = c[:16], c[16:]
    return xor(prf(k, r), body)

def ind_cca2_game(adversary) -> bool:
    S = RandomisedScheme(); k = S.keygen()
    enc = lambda m: S.enc(k, m)
    m0, m1 = adversary.choose()
    b = secrets.randbelow(2)
    c_star = S.enc(k, (m0, m1)[b])
    def dec_oracle(c):
        if c == c_star:                       # the single forbidden query
            raise ValueError("cannot decrypt the challenge itself")
        return dec(k, c)
    return adversary.guess(enc, dec_oracle, c_star) == b

class BitFlipAdversary:
    def choose(self):
        return b"\x00" * 32, b"\xff" * 32
    def guess(self, enc, dec_oracle, c_star):
        mask = b"\x00" * 16 + b"\x01" + b"\x00" * 31   # flip one body bit
        m_prime = dec_oracle(xor(c_star, mask))         # legal: c' != c*
        return 0 if m_prime[1:] == b"\x00" * 31 else 1

if __name__ == "__main__":
    A, n = BitFlipAdversary(), 1000
    wins = sum(ind_cca2_game(A) for _ in range(n))
    print("IND-CCA2 advantage:", abs(2 * wins / n - 1))

6.3 DDH fails in \(\Z_p^*\)

This uses the Legendre-symbol leak from Section 5.3, in the full group modulo the Mersenne prime \(2^{127}-1\).

ddh_zp.py

"""DDH is FALSE in the full group Z_p^*: the Legendre symbol leaks one bit."""
import secrets

p = 2**127 - 1                 # a Mersenne prime; Z_p^* has even order p-1
g = 3                          # 3 is a quadratic non-residue mod p (checked below)

def legendre(a: int) -> int:   # Euler's criterion: a^((p-1)/2) mod p in {1, p-1}
    return 1 if pow(a, (p - 1) // 2, p) == 1 else -1

assert legendre(g) == -1       # so g has even order and is a non-residue

def ddh_sample(real: bool):
    x, y, z = (secrets.randbelow(p - 1) for _ in range(3))
    return pow(g, x, p), pow(g, y, p), pow(g, x * y if real else z, p)

def distinguisher(X, Y, Z) -> bool:
    """g^xy is a QR iff x or y is even. Guess 'real' iff Z's QR-ness matches."""
    x_even, y_even = legendre(X) == 1, legendre(Y) == 1
    return (legendre(Z) == 1) == (x_even or y_even)

if __name__ == "__main__":
    n = 4000
    real = sum(distinguisher(*ddh_sample(True)) for _ in range(n)) / n
    rand = sum(distinguisher(*ddh_sample(False)) for _ in range(n)) / n
    print(f"Pr[1 | real] = {real:.3f}   Pr[1 | random] = {rand:.3f}")
    print(f"advantage ~ {abs(real - rand):.3f}   (theory: 1/2)")

6.4 Toy Regev (LWE) encryption

This implements the scheme from Section 5.5 with tiny parameters. The noise bound is chosen so decryption is always correct: \(m \cdot B = 512 \lt q/4 \approx 832\). Real parameters must be chosen with the lattice estimator (Section 7).

toy_lwe.py

"""Toy Regev-style LWE public-key encryption (one bit). NOT secure parameters."""
import secrets, random

n, q, m = 32, 3329, 256          # dimension, modulus (Kyber's q), number of samples
B = 2                            # error drawn uniformly from {-B, ..., B}

def small():   return secrets.randbelow(2 * B + 1) - B
def uniform(): return secrets.randbelow(q)

def keygen():
    s = [uniform() for _ in range(n)]                         # secret
    A = [[uniform() for _ in range(n)] for _ in range(m)]     # m x n public matrix
    e = [small() for _ in range(m)]
    b = [(sum(A[i][j] * s[j] for j in range(n)) + e[i]) % q for i in range(m)]
    return (A, b), s

def encrypt(pk, bit):
    A, b = pk
    S = [i for i in range(m) if secrets.randbelow(2)]         # random subset
    u = [sum(A[i][j] for i in S) % q for j in range(n)]
    v = (sum(b[i] for i in S) + bit * (q // 2)) % q
    return u, v

def decrypt(s, ct):
    u, v = ct
    d = (v - sum(u[j] * s[j] for j in range(n))) % q          # = bit*q/2 + small
    return 1 if q // 4 < d < 3 * q // 4 else 0

if __name__ == "__main__":
    pk, sk = keygen()
    bits = [random.getrandbits(1) for _ in range(500)]
    ok = sum(decrypt(sk, encrypt(pk, x)) == x for x in bits)
    print(f"correct decryptions: {ok}/500")
    # worst-case accumulated noise is m*B = 512 < q/4 = 832, so decryption never fails
correct decryptions: 500/500

6.5 EUF-CMA: forging textbook RSA signatures

This is the blinding attack from Worked example 3.10. The forged message is never submitted to the signing oracle.

rsa_forgery.py

"""Textbook RSA signatures are not EUF-CMA: a 1-query multiplicative forgery."""
from math import gcd
import secrets

def keygen():
    # small demo primes; real RSA uses >= 2048-bit moduli
    p, q, e = 1000000007, 998244353, 65537
    N, phi = p * q, (p - 1) * (q - 1)
    assert gcd(e, phi) == 1
    return (N, e), pow(e, -1, phi)

pk, d = keygen(); N, e = pk
queried = set()
def sign_oracle(m):
    queried.add(m)
    return pow(m, d, N)

def verify(m, s): return pow(s, e, N) == m % N

# Adversary: wants a signature on target m* without querying it.
m_star = 123456789
r = secrets.randbelow(N - 2) + 2
while gcd(r, N) != 1: r = secrets.randbelow(N - 2) + 2
s1 = sign_oracle((m_star * pow(r, e, N)) % N)   # blinded query
s_star = (s1 * pow(r, -1, N)) % N               # unblind
print("forgery valid:", verify(m_star, s_star), "| m* queried:", m_star in queried)
forgery valid: True | m* queried: False

Hand-written proofs are long and error-prone. Several tools now check proofs or protocols mechanically, or estimate concrete parameters.

Symbolic vs computational tools

Symbolic tools (ProVerif, Tamarin) assume perfect cryptography and search for logical protocol flaws: replay, reflection, missing bindings. They are highly automated. Computational tools (EasyCrypt, CryptoVerif) prove probabilistic bounds against PPT adversaries, matching the definitions in this article, but they need more user guidance[86–88].

8Exercises

Exercises are tagged by difficulty: ★ is routine, ★★ needs an idea, ★★★ is a short research-style argument. Click to reveal each solution.

Exercise 1 ★

Show that the one-time pad used to encrypt two messages under the same key is not perfectly secret, in the sense that \((C_1, C_2)\) is not independent of \((M_1, M_2)\).

Solution

\(C_1 \oplus C_2 = M_1 \oplus M_2\). Take \(M_1, M_2\) independent and uniform. Conditioned on \(C_1 = C_2\), we must have \(M_1 = M_2\), an event of prior probability \(2^{-\ell} \ne 1\). The posterior differs from the prior, so secrecy fails. This is consistent with Shannon’s bound: two \(\ell\)-bit messages need \(2\ell\) bits of key[4].

Exercise 2 ★

Prove that, for a uniformly random bit \(b\), \[|2\Pr[b'=b] - 1| = |\Pr[b'=1 \mid b=1] - \Pr[b'=1 \mid b=0]|.\]

Solution

\[\begin{aligned}\Pr[b'=b] &= \tfrac12\Pr[b'=1\mid b=1] + \tfrac12\Pr[b'=0\mid b=0]\\ &= \tfrac12\bigl(\Pr[b'=1\mid b=1] + 1 - \Pr[b'=1\mid b=0]\bigr).\end{aligned}\] Therefore \(2\Pr[b'=b]-1\) equals \(\Pr[b'=1\mid b=1] - \Pr[b'=1\mid b=0]\). Take absolute values.

Exercise 3 ★

Show that CBC mode with a fixed, public IV is not IND-CPA secure.

Solution

With a fixed IV, CBC is deterministic. Query \(m_0\) to get \(c_0\), submit \((m_0, m_1)\) with \(m_1 \ne m_0\), and output 0 iff \(c^* = c_0\). The advantage is 1, as in Fact 3.2. Even a predictable IV is fatal: if the next IV \(v\) is known, query \(m_0 \oplus v \oplus v'\) where \(v'\) is the IV of an earlier ciphertext, so that the first block cipher input repeats[1].

Exercise 4 ★★

Give an IND-CCA2 attack on textbook RSA encryption \(c = m^e \bmod N\), and on ElGamal \((g^r, m\cdot h^r)\).

Solution

RSA. Given \(c^*\), query \(\Dec(c^* \cdot 2^e)\), which differs from \(c^*\). The answer is \(2m_b \bmod N\). Divide by 2 to get \(m_b\). (Textbook RSA is deterministic, so it is not even IND-CPA.) ElGamal. Given \(c^* = (c_1, c_2)\), query \((c_1, 2c_2)\) to receive \(2m_b\). Both attacks exploit malleability (homomorphism). This is why Cramer–Shoup and FO-style transforms add a validity check[24,41,44].

Exercise 5 ★★

Let \(\mathsf{Mac}\) be UF-CMA secure. Build \(\mathsf{Mac}'_k(m) = \mathsf{Mac}_k(m) \| 0\), whose verifier ignores the last bit. Is \(\mathsf{Mac}'\) UF-CMA? Is it strongly unforgeable?

Solution

It is UF-CMA: a forgery on a new message \(m^*\) under \(\mathsf{Mac}'\) yields one under \(\mathsf{Mac}\) by dropping the last bit. It is not strongly unforgeable: given a tag \(t\|0\) on \(m\), the pair \((m, t\|1)\) verifies and is new. This is the MAC analogue of ECDSA’s \((r, -s)\) malleability[49,50].

Exercise 6 ★★

Using a hybrid argument, prove that if a public-key scheme is IND-CPA for one challenge, then for \(q\) left-or-right challenges \(\Adv_q \le q \cdot \Adv_1\).

Solution

Let \(H_i\) answer the first \(i\) challenge queries with \(m_1\) and the rest with \(m_0\). \(H_0\) is \(b=0\) and \(H_q\) is \(b=1\). \(\B\) picks \(i \getsr \{1..q\}\), answers queries \(\lt i\) by encrypting \(m_1\) itself with \(pk\), and those \(\gt i\) by encrypting \(m_0\). It forwards query \(i\) to its own challenger. If the challenger’s bit is 0, \(\B\) simulates \(H_{i-1}\); if it is 1, \(H_i\). The sum telescopes, so \(\Adv(\B) = \Adv_q(\A)/q\). The step requires the public key, which lets \(\B\) encrypt by itself. For symmetric schemes it uses the encryption oracle instead[1,34].

Exercise 7 ★

RSA-2048 is rated at 112-bit security[13]. Suppose an RSA-FDH proof has loss \(L \approx q_S\) and an adversary may obtain \(q_S = 2^{30}\) signatures. What security level does the theorem actually guarantee?

Solution

About \(112 - 30 = 82\) bits. To get a provable 112 bits you would need RSA rated at about 142 bits, which means a modulus well above 3072 bits, or a tighter scheme such as RSA-PSS, whose randomness avoids Coron’s lower bound[48,60]. This is the practical meaning of tightness.

Exercise 8 ★★

In Code lab 6.4, why does decryption never fail? What breaks if \(B\) is raised to 4?

Solution

\(v - \langle \mathbf{u}, \mathbf{s}\rangle = \mu\lfloor q/2\rfloor + \sum_{i\in S} e_i\), and \(|\sum e_i| \le |S|B \le mB = 512 \lt q/4 \approx 832\). The value therefore stays in the correct half of \(\Z_q\). With \(B = 4\) the worst case is \(1024 \gt 832\). Failures become possible but stay rare, because \(\sum e_i\) concentrates around 0 with standard deviation about \(\sqrt{|S|\cdot 20/3} \approx 29\). Real schemes such as ML-KEM accept a tiny, analysed failure probability[43].

Exercise 9 ★★

Explain why the DDH distinguisher of Code lab 6.3 stops working in the subgroup of quadratic residues of \(\Z_p^*\) when \(p = 2q+1\) is a safe prime.

Solution

Every element of \(QR_p\) has Legendre symbol \(+1\), so the symbol is constant and leaks nothing. More generally, the subgroup has prime order \(q\), so it has no small subgroups that could leak \(x \bmod\) small factors. DDH is conjectured to hold there[67].

Exercise 10 ★★★

Show that IND-CCA1 does not imply IND-CCA2. Start from an IND-CCA1 scheme \(\Pi\) and build \(\Pi'\) that is still IND-CCA1 but trivially CCA2-insecure.

Solution

Let \(\Enc'(m) = \Enc(m)\|0\), and let \(\Dec'(c\|\beta) = \Dec(c)\), ignoring \(\beta\). A CCA2 adversary queries \(\Dec'(c^*_{\text{body}}\|1) \ne c^*\) and learns \(m_b\). Any CCA1 adversary against \(\Pi'\) can be simulated by one against \(\Pi\) by stripping or appending the bit, because before the challenge no query can relate to \(c^*\). Bellare, Desai, Pointcheval and Rogaway use separations of this kind to show that the notions are strictly ordered[24].

Exercise 11 ★★

Prove that SIS for \(\mathbf{A} \in \Z_q^{n\times m}\) with \(m \gt n\log_2 q\) and \(\beta = \sqrt{m}\) always has a solution. (Hardness is about finding it.)

Solution

There are \(2^m \gt q^n\) vectors in \(\{0,1\}^m\) but only \(q^n\) possible values of \(\mathbf{A}\mathbf{z}\). By pigeonhole, two distinct \(\mathbf{z}, \mathbf{z}'\) collide. Then \(\mathbf{z}-\mathbf{z}' \in \{-1,0,1\}^m\setminus\{\mathbf{0}\}\) satisfies \(\mathbf{A}(\mathbf{z}-\mathbf{z}') = \mathbf{0}\) and \(\|\mathbf{z}-\mathbf{z}'\| \le \sqrt{m}\)[73,80].

Exercise 12 ★

How many SHA-256 evaluations does a generic collision attack need for a 50% success chance? How many does a generic preimage attack need?

Solution

Collision: \(q \approx \sqrt{2\ln 2 \cdot 2^{256}} \approx 1.18 \cdot 2^{128}\) by the birthday bound. Preimage: \(\approx 2^{256}\cdot\ln 2\), on the order of \(2^{256}\). The square-root gap is why 256-bit hashes are paired with 128-bit security[1,82].

9Trivia

1. Which paper introduced both semantic security and the idea that encryption must be randomised?

Goldwasser and Micali, “Probabilistic Encryption”, JCSS 1984 (conference version STOC 1982)[5]. They received the 2012 ACM Turing Award[6].

2. Why is CCA1 nicknamed the “lunchtime attack”?

The attacker gets to use the decryption box while its owner is at lunch, before the challenge ciphertext arrives, and never afterwards[1,27].

3. What was the “million-message attack”?

Bleichenbacher’s 1998 adaptive chosen-ciphertext attack on RSA PKCS #1 v1.5 in SSL. Padding-error responses acted as an oracle, and roughly \(2^{20}\) queries sufficed to decrypt a ciphertext[29].

4. Who won the 2018 Gödel Prize, and for what?

Oded Regev, for introducing the Learning With Errors problem and its quantum worst-case hardness reduction[9,76].

5. What is special about ML-KEM’s modulus 3329?

\(3329 = 13 \cdot 256 + 1\) is a prime congruent to 1 modulo 256. \(\Z_{3329}\) therefore contains 256th roots of unity, which enable a fast number-theoretic transform for \(n = 256\)[43].

6. What did the name “Sweet32” refer to?

The birthday bound for 64-bit block ciphers: collisions appear after about \(2^{32}\) blocks, the “sweet spot” exploited against 3DES and Blowfish in TLS and OpenVPN[15].

7. Which paper coined the “random oracle model” as a design paradigm, and where was it published?

Bellare and Rogaway, “Random oracles are practical”, presented at the first ACM CCS in 1993[52].

8. Roughly how many SHA-1 computations did the first full SHA-1 collision require?

About \(2^{63.1}\), announced as “SHAttered” in 2017[84].

9. Which 1883 principle says a system should be secure even if everything but the key is public?

Kerckhoffs’s principle, from “La cryptographie militaire”[3].

10. Can UC-secure commitments be built in the plain model?

No. Canetti and Fischlin proved that two-party UC commitments are impossible without setup, such as a common reference string[51].

11. Which Turing Award recognised public-key cryptography itself?

Rivest, Shamir and Adleman received the 2002 award for RSA. Diffie and Hellman received the 2015 award for public-key cryptography and key exchange[6].

12. Why does an ECDSA signature have a twin?

Verification depends on \(s\) only up to sign, so if \((r, s)\) is valid, so is \((r, n - s)\). That makes ECDSA EUF-CMA but not SUF-CMA, and caused Bitcoin transaction malleability[50].
