Angular Material

Angular Material is Google’s supported Material Design component library for Angular. The Angular CDK is the lower-level toolkit beneath many of those components: accessibility, overlays, portals, tables, scrolling, layout observation, drag-and-drop, and other interaction primitives without a prescribed visual language. A robust application uses Material for standardized product UI and the CDK when it needs custom presentation with proven behavior.

1. What Angular Material is

The Angular Components team maintains @angular/material for Material Design UI, @angular/cdkangular/components repository. The project’s stated goals include accessibility, internationalization, predictable APIs, broad use-case coverage, testing, theming within Material Design, and minimized performance cost.[3]

Material

Opinionated, themed components such as buttons, form fields, dialogs, sidenavs, menus, and tables.

CDK

Mostly unstyled behavior and infrastructure for overlays, focus, virtual scrolling, layout, selection, tables, drag-and-drop, and testing.[3][31]

Application layer

Domain-specific screens, validation, routing, authorization, responsive layout, data access, and content strategy remain the application’s responsibility.

As of 4 August 2026, npm lists Angular Material 22.0.6 as the production latest release, with 22.1.0 release candidates on the prerelease channel. Angular Material and the CDK follow the Angular framework’s support and release policy.[4][3]

The package also includes generators for navigation, tables, dashboards, address forms, trees, and CDK drag-and-drop examples.[5][6]

A component library is not an application architecture Angular Material does not decide your feature boundaries, state-management approach, API contracts, route authorization, error model, responsive information hierarchy, or accessibility requirements. Components make those decisions easier to implement consistently; they do not replace them.

2. Historical development

2014: Material Design

Google introduced Material Design at Google I/O 2014 as a cross-platform design approach grounded in tactile metaphors, motion, hierarchy, and consistency. Google describes Material as an open-source design system of guidance, components, and tools.[1][2]

AngularJS Material

The earlier angular-material package implemented Material Design for AngularJS 1.x. It is deprecated, and AngularJS Material support ended with the AngularJS ecosystem; active Angular applications use @angular/material and @angular/cdk.[39]

Angular Material for Angular 2+

The modern library was built for the rewritten Angular framework and evolved alongside Angular’s component model, dependency injection, forms, router, and build tooling. The official repository centralizes both visual components and component infrastructure.[3]

CDK separation

The Component Dev Kit exposed reusable interaction primitives independently of Material styling. Material tables, dialogs, menus, and other components use or parallel CDK foundations such as table rendering, overlays, portals, focus management, scrolling, and selection.[15][25][26][31]

MDC-based internals

Angular Material migrated many components to implementations aligned with Material Design Components for the web, while preserving Angular-facing APIs through migrations and compatibility work.

Material 3 and design tokens

Material 3 became Angular Material’s modern design system. Current theming APIs, introduced in Angular Material 19, generate design-token CSS variables through the mat.theme Sass mixin. Material 2 prebuilt themes remain for compatibility but are planned for future removal.[7][38]

3. Material Design

Material Design 3 is Google’s current open-source design system for building usable, expressive products. It supplies guidance for color, typography, shape, motion, layout, and component behavior across platforms. Angular Material is one implementation for Angular; it does not reproduce every platform component or automatically make an interface conformant.[2]

3.1 Design-system concerns

ConcernApplication implication
Color rolesUse semantic roles such as primary, surface, on-surface, error, and containers rather than hard-coded brand shades throughout component CSS.
Typography rolesMap hierarchy to display, headline, title, body, and label purposes instead of selecting sizes ad hoc.
ShapeUse shape to communicate hierarchy and product personality while maintaining recognizable controls.
MotionUse motion to explain change and focus, not as decoration that delays tasks.
Adaptive layoutNavigation and content structure should change with available space and ergonomics, not merely shrink.[2][43]
AccessibilityMaintain semantics, focus order, keyboard behavior, labels, contrast, touch targets, and error communication.

3.2 Material is not “make everything a card”

Material Design establishes a visual and behavioral system, but excessive surfaces, shadows, dialogs, and competing emphasis weaken hierarchy. Choose the least visually forceful component that still communicates the task.

3.3 Component semantics come first

action versus navigation
<!-- Action on the current page. -->
<button
  matButton="filled"
  type="button"
  (click)="save()">
  Save
</button>

<!-- Navigation to another URL. -->
<a
  matButton="text"
  routerLink="/settings">
  Settings
</a>

Angular Material’s button guidance retains native button and a elements. Use a button for an action and an anchor for navigation so native semantics and assistive-technology expectations remain intact.[10]

Build tooling can eliminate unused JavaScript, but broad imports obscure architectural dependencies and can encourage accidental component coupling. Theme CSS also needs explicit attention: prebuilt themes style all Material components, while component-specific Sass can reduce generated CSS.[7]

5. Material 3 themes

Angular Material’s current Sass API uses mat.theme to emit CSS custom properties based on Material design tokens. The input can configure color, typography, and density. These APIs were introduced in Angular Material 19 and are the recommended path for current applications.[7][38]

5.1 Minimal Material 3 theme

styles.scss
@use '@angular/material'
  as mat;

html {
  color-scheme:
    light dark;

  @include mat.theme((
    color:
      mat.$violet-palette,
    typography:
      Roboto,
    density:
      0,
  ));
}

body {
  background:
    var(
      --mat-sys-surface
    );

  color:
    var(
      --mat-sys-on-surface
    );
}

The light-dark()-based color variables respond to the CSS color-scheme value. color-scheme: light dark allows the user agent’s preference to choose a mode; a class or saved preference can instead force one mode.[7]

5.2 Explicit palette, typography, and density

custom M3 configuration
@use '@angular/material'
  as mat;

html {
  @include mat.theme((

      tertiary:
        mat.$orange-palette,

        light,

      medium-weight:
        500,

        400,

Current density values range from 0 to −5, where lower values reduce affected component spacing. The theming guide warns that excessive density can reduce accessibility and make interaction harder, and some task-oriented popup components intentionally do not accept density reduction.[7]

The official theming guidance strongly discourages styling internal component structure outside supported theming and override APIs because those selectors are implementation details.[7]

6. Typography

Material typography uses semantic text roles rather than one undifferentiated scale. Angular Material’s current theme configuration accepts a single font family or separate plain and brand families plus regular, medium, and bold weights. Component text such as dialog titles, labels, and menu items consumes the generated typography tokens.[7][9]

6.1 Configure families and weights

brand and plain typography
@use '@angular/material'
  as mat;

html {

    color:
      mat.$violet-palette,

      plain-family:
        'Inter',
      brand-family:
        'Source Serif 4',
      regular-weight:
        400,
      medium-weight:
        500,
      bold-weight:
        700,
    ),

    density:
      0,
  ));
}

6.2 Load the actual fonts

font assets
<link
  rel="preconnect"

6.3 Generate utility classes when useful

optional system classes

  @include mat.theme((
    color:
      mat.$violet-palette,
    typography:
      Roboto,
    density:
      0,
  ));

  @include mat.system-classes();
}

The current theming API can emit utility classes backed by system design tokens. Use semantic application classes and HTML structure rather than scattering type sizes inline.[7]

6.4 Typography is content hierarchy

semantic content hierarchy

    </p>

      Revenue and retention
    </h1>

Do not use heading size as a substitute for heading structure A visually small heading can still be an h2. Screen-reader document structure and visual type roles are related but distinct concerns.

7.4 Disabled-interactive behavior

focusable disabled styling
<button
  matButton="filled"
  type="submit"
  [disabled]="form.invalid"
  [disabledInteractive]="true"
  (click)="submitIfValid()">
  Submit
</button>

disabledInteractive can allow focus and events while the control is visually and accessibly disabled. Because it no longer relies on native disabled behavior to block actions, the event handler must guard the command explicitly.[10]

guard an interactive-disabled action
submitIfValid(): void {
  if (
    this.form.invalid ||
    this.form.pending
  ) {
    this.form
      .markAllAsTouched();

    return;
  }

  this.save();
}

7.5 Avoid ambiguous icon-only actions

Use text labels for unfamiliar, destructive, or high-consequence actions. Tooltips can supplement an accessible name but should not be the only way to understand a critical control.

8. Forms and form fields

mat-form-field provides Material text-field structure around a compatible control: label, filled or outline appearance, hints, errors, prefix/suffix content, and theme integration. 8.4 ErrorStateMatcher

custom error display policy
@Injectable()
export class SubmittedOrDirtyMatcher
  implements ErrorStateMatcher {

  isErrorState(
    control:
      FormControl |
      null,

    form:
      FormGroupDirective |
      NgForm |
      null,
  ): boolean {
    const submitted =
      form?.submitted ??
      false;

    return Boolean(
      control?.invalid &&
      (
        control.dirty ||
        submitted
      ),
    );
  }
}

ErrorStateMatcher controls when a compatible Material control displays its error state. Validation still belongs to Angular Forms; the matcher changes presentation timing, not validity.[12][35]

9.2 Focus and keyboard behavior

MatDialog creates an ARIA dialog, traps focus, focuses the first tabbable element by default, closes on Escape by default, and restores focus to the previously focused element when possible. Disabling Escape breaks the expected dialog interaction pattern and should be reserved for exceptional workflows.[14][37]

9.3 Global defaults replace rather than merge

safe dialog defaults
import {
  MAT_DIALOG_DEFAULT_OPTIONS,
  MatDialogConfig,
} from '@angular/material/dialog';

{
  provide:
    MAT_DIALOG_DEFAULT_OPTIONS,

  useValue: {
    ...new MatDialogConfig(),

    autoFocus:
      'first-header',

    restoreFocus:
      true,
  },
}

A provided MAT_DIALOG_DEFAULT_OPTIONS value replaces the built-in defaults rather than merging with them. Spread a new MatDialogConfig when overriding selected fields.[14]

9.4 Dialog anti-patterns

  • Do not use a modal for information that can remain inline.
  • Do not nest dialogs.
  • Do not place long multi-step workflows in a small modal when a route would be clearer.
  • Do not use disableClose merely to force a business decision.
  • Do not pass mutable application state into a dialog and let both caller and dialog edit it concurrently; pass a snapshot or controlled form model.

export class ServerUsersDataSource
  extends DataSource<UserRow> {

  private readonly rowsSubject =
    new BehaviorSubject<
      readonly UserRow[]
    >([]);

  private readonly loadingSubject =
    new BehaviorSubject(
      false,
    );

  private readonly totalSubject =
    new BehaviorSubject(
      0,
    );

  readonly loading$ =
    this.loadingSubject
      .asObservable();

  readonly total$ =
    this.totalSubject
      .asObservable();

  constructor(
    private readonly api:
      UsersApi,
  ) {
    super();
  }

  connect():
    Observable<
      readonly UserRow[]
    > {
    return this.rowsSubject
      .asObservable();
  }

  disconnect(): void {
    this.rowsSubject
      .complete();

    this.loadingSubject
      .complete();

    this.totalSubject
      .complete();
  }

  load(
    query:
      UserQuery,
  ): void {
    this.loadingSubject
      .next(true);

    this.api
      .list(query)
      .pipe(
        finalize(() => {
          this.loadingSubject
            .next(false);
        }),
      )
      .subscribe({
        next: page => {
          this.rowsSubject
            .next(page.rows);

          this.totalSubject
            .next(page.total);
        },

        error: () => {
          this.rowsSubject
            .next([]);

          this.totalSubject
            .next(0);
        },
      });
  }
}

The table calls connect() to receive the rendered-row stream and disconnect() when destroyed. A production data source can combine sort, page, and filter streams with switchMap so stale requests are cancelled.[15][31]

          origin,
        )

            originX:
              'end',
            originY:
              'bottom',
            overlayX:
              'end',
            overlayY:
              'top',
            offsetY:
              8,

15. Production architecture and performance

15.1 Build domain components over Material primitives

application-specific Material wrapper
@Component({
  selector:
    'app-save-button',
  standalone: true,
  imports: [
    MatButtonModule,
    MatIconModule,
    MatProgressSpinnerModule,
  ],
  template: `
    <button
      matButton="filled"
      type="submit"
      [disabled]="disabled()"
      [showProgress]="saving()">

      <mat-icon>
        save
      </mat-icon>

      {{ label() }}

      <mat-progress-spinner
        progressIndicator
        diameter="20"
        mode="indeterminate"
        tabindex="">
      </mat-progress-spinner>
    </button>
  `,
})
export class SaveButtonComponent {
  readonly label =
    input('Save');

  readonly saving =
    input(false);

  readonly disabled =
    input(false);
}

A domain wrapper is useful when it standardizes repeated semantics—loading, permissions, analytics, confirmation, accessible naming, or error policy. Avoid wrappers that merely rename every Material input and make library upgrades harder.

15.2 Keep table and form logic outside templates

Filtering, sorting, pagination, validation, and server calls should be testable in TypeScript. Templates should declare columns, labels, actions, and state presentation rather than implement algorithms.

15.3 Prefer CSS layout to imperative measurement

Use Grid, Flexbox, container queries, and responsive CSS for ordinary layout. Use BreakpointObserver only when component behavior—not just styling—must change.

15.4 Avoid excessive overlays

Dialogs, menus, selects, autocomplete panels, tooltips, and snack bars all use overlay infrastructure. Repeatedly opening overlays, placing very large trees inside them, or coupling them to high-frequency streams can increase DOM, focus, and layout cost.

15.5 Virtualize only when needed

Virtual scrolling adds constraints to measurement, semantics, sticky content, and test behavior. Profile the actual row count and cell complexity before adopting it.

15.6 Theme narrowly when bundle CSS matters

A prebuilt theme includes styles for every Material component. The current Sass API can emit only the component tokens needed by an application, which can reduce CSS for focused libraries or constrained deployments.[7]

15.7 Internationalization

Paginator labels, date adapters, directionality, number/date formatting, and translated component content require explicit locale strategy. Material components support infrastructure, but application strings and domain formatting remain your responsibility.

19. Conclusion

Angular Material provides a supported Angular implementation of Material Design components, while the Angular CDK supplies the interaction infrastructure beneath both Material and custom design systems. Material 3 theming now centers on design-token CSS variables generated by mat.theme, with color, typography, density, light/dark behavior, and component override APIs.[3][7][38]

Effective use is compositional: native semantics under Material buttons, Angular Forms inside form fields, typed data and results around dialogs, Router-aware navigation inside adaptive shells, and DataSource abstractions behind tables. When Material’s visual opinion is not appropriate, CDK overlays, focus utilities, scrolling, layout, selection, and harnesses provide lower-level foundations. The result should be a coherent product system—not merely a collection of visually matching controls.
