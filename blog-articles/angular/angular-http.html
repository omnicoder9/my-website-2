HTTP Communication in Angular

A production-oriented guide to HttpClient, REST APIs, CRUD operations, request options, functional interceptors, error handling, authentication tokens, and file upload/download.

Targets Angular 22-era APIs Standalone-first examples Vancouver citations Updated 4 August 2026

HTTP is the boundary between an Angular application and most remote backends. Correct code at this boundary must align three systems: HTTP semantics, the browser security model, and Angular's reactive API. This article develops that boundary from first principles and then assembles a reusable implementation.

Version scope Angular's current documentation is built at version 22.1.x. In Angular v21 and later, HttpClient is injectable by default; provideHttpClient(...) remains the configuration point for features such as interceptors, XSRF customization, and switching from the default Fetch backend to XHR. [5]

1. Mental model: what an Angular HTTP call actually does

HTTP is a stateless application-level protocol. A request identifies a target resource, names a method, carries fields and optional content, and produces a response with a status code, fields, and optional content. HTTP semantics are shared across protocol versions such as HTTP/1.1, HTTP/2, and HTTP/3. [1]

Angular does not replace HTTP. HttpClient is a typed, injectable abstraction over the browser or server runtime's networking backend. It constructs requests, serializes bodies, exposes responses as RxJS Observables, normalizes failures as HttpErrorResponse, and permits middleware-like interception. [4–8]

An HttpClient method returns a cold-style request Observable: subscribing dispatches the request, and each independent subscription can dispatch another request. The stream generally emits a body, a full response, or a sequence of HTTP events and then completes; interceptor behavior can modify that flow. [6]

Important consequence Do not casually subscribe twice to the same HttpClient observable. Two subscriptions can produce two network requests. Share or cache deliberately when multiple consumers must observe one result.

2. Historical context

2.1 From HTTP to REST-style APIs

Roy Fielding described Representational State Transfer (REST) in his 2000 doctoral dissertation as an architectural style for distributed hypermedia. REST is defined by constraints—including client-server separation, stateless interaction, cacheability, a uniform interface, layered systems, and optional code-on-demand—not merely by mapping database CRUD operations to HTTP verbs. [2]

Many practical “REST APIs” use resource-oriented URLs and HTTP methods, but an endpoint is not fully RESTful solely because it exposes GET /products and POST /products. This distinction matters because Angular's job is to speak HTTP correctly; API architecture remains a server-and-contract concern. [1,2]

2.2 Angular's HTTP evolution

Angular 4.3, released on 14 July 2017, introduced the new HttpClient API under @angular/common/http. The older @angular/http package was subsequently deprecated in favor of it and later removed. [3]

The modern API added typed JSON responses, immutable request objects, interceptors, progress events, testing utilities, and built-in XSRF support. Current Angular favors provider-based configuration and functional interceptors; the documentation recommends functional interceptors because their ordering is more predictable in complex configurations. [4,5,8]

3. Configuring and injecting HttpClient

In a modern standalone application, configure HTTP features in app.config.ts. Although basic injection works by default in Angular v21+, calling provideHttpClient is how the application installs interceptors or changes backend/security features. [5]

app.config.ts
import { ApplicationConfig } from '@angular/core';
import {
  provideHttpClient,
  withInterceptors,
} from '@angular/common/http';

import {
  authInterceptor,
  correlationIdInterceptor,
  apiErrorInterceptor,
} from './core/http/interceptors';

export const appConfig: ApplicationConfig = {
  providers: [
    provideHttpClient(
      withInterceptors([
        correlationIdInterceptor,
        authInterceptor,
        apiErrorInterceptor,
      ]),
    ),
  ],
};

The configured interceptors form a chain in declaration order for outgoing requests. Each interceptor receives an immutable HttpRequest and a next handler, and may clone the request or transform the returned event stream. [8]

Inject HttpClient into a service rather than scattering endpoint details through components. Angular's guide recommends reusable injectable services to isolate data-access logic. [6]

config-api.service.ts
import { inject, Injectable } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import { Observable } from 'rxjs';

export interface AppConfig {
  apiVersion: string;
  featureFlags: Record<string, boolean>;
}

@Injectable({ providedIn: 'root' })
export class ConfigApiService {
  private readonly http = inject(HttpClient);

  getConfig(): Observable<AppConfig> {
    return this.http.get<AppConfig>('/api/config');
  }
}
TypeScript generics are not runtime validation http.get<AppConfig>(...) tells TypeScript what the application expects; Angular does not verify that the received JSON actually conforms to AppConfig. Validate untrusted or evolving payloads at runtime before treating them as trusted domain objects. [6]

4. REST APIs and HTTP method semantics

Resource-oriented APIs commonly map creation, retrieval, replacement, partial modification, and deletion to HTTP methods. The mapping is conventional, while the method semantics come from HTTP standards. [1,10]

OperationTypical requestHTTP propertyCommon successful response
ListGET /products?page=1Safe and idempotent200 OK
ReadGET /products/42Safe and idempotent200 OK
CreatePOST /productsNot inherently idempotent201 Created plus Location
ReplacePUT /products/42Idempotent200 OK or 204 No Content
Partial updatePATCH /products/42Not inherently idempotent200 OK or 204 No Content
DeleteDELETE /products/42Idempotent204 No Content

A safe method is intended to be read-only from the client's perspective. An idempotent method has the same intended server effect when an identical request is repeated. These properties guide retry logic: automatic retries are much safer for GET, HEAD, PUT, and DELETE than for an arbitrary POST or PATCH. [1,10]

5.2 Service implementation

HttpClient exposes convenience methods for standard verbs and chooses a return type from the generic type, observe, and responseType options. Plain objects are serialized as JSON; FormData, Blob, ArrayBuffer, text, and URL-encoded parameter bodies have specialized serialization behavior. [6,7]

product-api.service.ts
import { inject, Injectable } from '@angular/core';
import {
  HttpClient,
  HttpHeaders,
  HttpParams,
  HttpResponse,
} from '@angular/common/http';
import { Observable } from 'rxjs';

import {
  CreateProductRequest,
  Page,
  PatchProductRequest,
  Product,
  ProductQuery,
  UpdateProductRequest,
} from './product.models';

@Injectable({ providedIn: 'root' })
export class ProductApiService {
  private readonly http = inject(HttpClient);
  private readonly baseUrl = '/api/products';

  list(query: ProductQuery = {}): Observable<Page<Product>> {
    let params = new HttpParams();

    if (query.q) params = params.set('q', query.q);
    if (query.active !== undefined) {
      params = params.set('active', query.active);
    }
    if (query.page !== undefined) params = params.set('page', query.page);
    if (query.pageSize !== undefined) {
      params = params.set('pageSize', query.pageSize);
    }
    if (query.sort) params = params.set('sort', query.sort);
    if (query.direction) {
      params = params.set('direction', query.direction);
    }

    return this.http.get<Page<Product>>(this.baseUrl, { params });
  }

  get(id: string): Observable<Product> {
    return this.http.get<Product>(
      `${this.baseUrl}/${encodeURIComponent(id)}`,
    );
  }

  create(
    request: CreateProductRequest,
  ): Observable<HttpResponse<Product>> {
    return this.http.post<Product>(this.baseUrl, request, {
      observe: 'response',
    });
  }

  replace(
    id: string,
    request: UpdateProductRequest,
    version: number,
  ): Observable<Product> {
    const headers = new HttpHeaders({
      'If-Match': `"${version}"`,
    });

    return this.http.put<Product>(
      `${this.baseUrl}/${encodeURIComponent(id)}`,
      request,
      { headers },
    );
  }

  patch(
    id: string,
    request: PatchProductRequest,
    version: number,
  ): Observable<Product> {
    return this.http.patch<Product>(
      `${this.baseUrl}/${encodeURIComponent(id)}`,
      request,
      {
        headers: {
          'If-Match': `"${version}"`,
          'Content-Type': 'application/merge-patch+json',
        },
      },
    );
  }

  delete(id: string, version?: number): Observable<void> {
    const headers =
      version === undefined
        ? undefined
        : new HttpHeaders({ 'If-Match': `"${version}"` });

    return this.http.delete<void>(
      `${this.baseUrl}/${encodeURIComponent(id)}`,
      { headers },
    );
  }
}

HttpParams and HttpHeaders are immutable: methods such as set and append return new instances. Failing to reassign the return value is a common source of silently missing parameters or headers. [6]

Optimistic concurrency The example sends an entity version through If-Match. Conditional requests can prevent one client from unknowingly overwriting another client's newer representation. HTTP defines entity tags and precondition fields such as If-Match; the server must implement the version/ETag contract. [1]

6. Request options in depth

6.2 JSON, text, Blob, and ArrayBuffer

responseType examples
const healthText$ = this.http.get('/health', {
  responseType: 'text',
});

const reportBlob$ = this.http.get('/api/reports/monthly.pdf', {
  responseType: 'blob',
});

const keyBytes$ = this.http.get('/api/public-key.der', {
  responseType: 'arraybuffer',
});

Angular assumes JSON by default. For non-JSON responses, set responseType explicitly. Do not combine a JSON generic such as get<string> with responseType: 'text'; the response type overload already determines the TypeScript result. [6,7]

6.3 Timeouts

Angular's timeout option applies to the backend request, not time spent in interceptor logic. A timed-out request is surfaced through the observable's error channel as an HttpErrorResponse. [6]

timeout example
return this.http.get<Product[]>('/api/products', {
  timeout: 8_000,
});

6.4 Credentials and CORS

Cross-origin access is controlled by the browser's CORS implementation and server response headers; Angular cannot “fix” a server-side CORS policy. Credentialed cross-origin requests require compatible server headers, including an explicit allowed origin rather than the * wildcard. [15]

credentialed request
return this.http.get<CurrentUser>(
  'https://api.example.com/me',
  {
    credentials: 'include',
  },
);

For a credentialed cross-origin response, the API typically needs Access-Control-Allow-Credentials: true, an explicit Access-Control-Allow-Origin, and an allowlist that includes any non-simple methods or headers. Authentication and authorization must still be enforced by the API; CORS is a browser sharing policy, not an authorization system. [14,15]

6.5 HttpContext: metadata that is not transmitted

HttpContext carries typed metadata through Angular's interceptor pipeline without serializing that metadata into HTTP headers or the request body. It is useful for flags such as “skip authentication,” “disable caching,” or “suppress global loading UI.” [8]

request context
import {
  HttpContext,
  HttpContextToken,
} from '@angular/common/http';

export const SKIP_AUTH =
  new HttpContextToken<boolean>(() => false);

this.http.post('/api/auth/refresh', null, {
  context: new HttpContext().set(SKIP_AUTH, true),
});

7. Interceptors

Interceptors are middleware for cross-cutting concerns such as authentication, retrying, caching, logging, timing, loading indicators, and response transformation. Functional interceptors are configured with withInterceptors and are recommended by Angular for predictable behavior. [8]

7.1 Correlation ID interceptor

correlation-id.interceptor.ts
import {
  HttpHandlerFn,
  HttpRequest,
} from '@angular/common/http';

export function correlationIdInterceptor(
  request: HttpRequest<unknown>,
  next: HttpHandlerFn,
) {
  const correlationId = crypto.randomUUID();

  return next(
    request.clone({
      setHeaders: {
        'X-Correlation-ID': correlationId,
      },
    }),
  );
}

Requests and responses are immutable in Angular's HTTP pipeline. An interceptor changes a request by cloning it, then forwards the clone to next. This supports safe re-entry when a request is retried, although interceptor code must still avoid mutating nested body objects in place. [8]

7.2 Timing and logging without leaking secrets

timing.interceptor.ts
import {
  HttpEventType,
  HttpHandlerFn,
  HttpRequest,
} from '@angular/common/http';
import { tap } from 'rxjs';

export function timingInterceptor(
  request: HttpRequest<unknown>,
  next: HttpHandlerFn,
) {
  const started = performance.now();

  return next(request).pipe(
    tap((event) => {
      if (event.type === HttpEventType.Response) {
        const elapsedMs = performance.now() - started;
        console.info('HTTP', {
          method: request.method,
          url: request.urlWithParams,
          status: event.status,
          elapsedMs: Math.round(elapsedMs),
        });
      }
    }),
  );
}
Logging rule Do not log bearer tokens, cookies, passwords, API keys, complete sensitive payloads, or URLs containing secrets. OWASP recommends keeping sensitive information out of HTTP requests where possible and protecting REST endpoints with HTTPS. [14]

7.3 Ordering

Outgoing requests pass through interceptors in configured order; response events return through the chain in reverse nesting order. Put metadata/authentication interceptors before logic that depends on the resulting headers, and place global error mapping where it can observe failures from the downstream chain. [8]

8. Error handling

Angular represents network failures, configured timeouts, and non-success backend responses with HttpErrorResponse. Network and timeout failures use status 0; backend failures preserve the server's failing status and response error content. [6]

8.1 Normalize transport errors into a domain error

A central error mapper prevents every component from understanding Angular's transport-specific error structure. APIs can use the standardized Problem Details format, which defines fields such as type, title, status, detail, and instance. [11]

api-error.ts
export interface ProblemDetails {
  type?: string;
  title?: string;
  status?: number;
  detail?: string;
  instance?: string;
  [extension: string]: unknown;
}

export class ApiError extends Error {
  constructor(
    message: string,
    readonly status: number,
    readonly code?: string,
    readonly problem?: ProblemDetails,
    options?: ErrorOptions,
  ) {
    super(message, options);
    this.name = 'ApiError';
  }

  get isNetworkFailure(): boolean {
    return this.status === 0;
  }

  get isUnauthorized(): boolean {
    return this.status === 401;
  }

  get isForbidden(): boolean {
    return this.status === 403;
  }

  get isConflict(): boolean {
    return this.status === 409 || this.status === 412;
  }
}
api-error.interceptor.ts
import {
  HttpErrorResponse,
  HttpHandlerFn,
  HttpRequest,
} from '@angular/common/http';
import { catchError, throwError } from 'rxjs';

import { ApiError, ProblemDetails } from './api-error';

function isProblemDetails(value: unknown): value is ProblemDetails {
  return (
    typeof value === 'object' &&
    value !== null &&
    ('title' in value || 'detail' in value || 'status' in value)
  );
}

function mapHttpError(error: HttpErrorResponse): ApiError {
  if (error.status === 0) {
    return new ApiError(
      'The server could not be reached or the request timed out.',
      0,
      'NETWORK_OR_TIMEOUT',
      undefined,
      { cause: error },
    );
  }

  const problem = isProblemDetails(error.error)
    ? error.error
    : undefined;

  const message =
    problem?.detail ??
    problem?.title ??
    error.message ??
    `Request failed with status ${error.status}`;

  return new ApiError(
    message,
    error.status,
    typeof problem?.['code'] === 'string'
      ? problem['code']
      : undefined,
    problem,
    { cause: error },
  );
}

export function apiErrorInterceptor(
  request: HttpRequest<unknown>,
  next: HttpHandlerFn,
) {
  return next(request).pipe(
    catchError((error: unknown) => {
      const mapped =
        error instanceof HttpErrorResponse
          ? mapHttpError(error)
          : error;

      return throwError(() => mapped);
    }),
  );
}

8.3 Bounded retry for transient failures

Retrying is a policy decision, not a generic cure. Bound the attempt count, add delay and jitter in high-volume systems, restrict automatic retries to transient failures, and respect method idempotency or an explicit idempotency-key contract. [1]

retry-transient.ts
import { HttpErrorResponse } from '@angular/common/http';
import {
  MonoTypeOperatorFunction,
  retry,
  throwError,
  timer,
} from 'rxjs';

const TRANSIENT_STATUSES = new Set([0, 502, 503, 504]);

export function retryTransient<T>(
  count = 2,
): MonoTypeOperatorFunction<T> {
  return retry({
    count,
    delay: (error: unknown, retryCount: number) => {
      if (
        !(error instanceof HttpErrorResponse) ||
        !TRANSIENT_STATUSES.has(error.status)
      ) {
        return throwError(() => error);
      }

      const backoffMs = 300 * 2 ** (retryCount - 1);
      return timer(backoffMs);
    },
  });
}

// Appropriate for an idempotent read:
return this.http
  .get<Product[]>('/api/products')
  .pipe(retryTransient(2));

8.4 Cancellation and stale searches

Unsubscribing from an active HttpClient observable aborts the in-progress request. Operators such as switchMap therefore work well for type-ahead search: a new search term unsubscribes from the prior request so stale responses do not overwrite newer results. [6]

type-ahead search
readonly searchResults$ = this.searchControl.valueChanges.pipe(
  debounceTime(250),
  distinctUntilChanged(),
  switchMap((term) =>
    this.products.list({
      q: term?.trim() || undefined,
      pageSize: 20,
    }),
  ),
);

9. Authentication tokens

OAuth bearer tokens are normally transmitted in the HTTP Authorization field using the Bearer scheme. Possession is sufficient to use a bearer token, so the token must be protected in storage, logs, URLs, browser history, and transit. RFC 6750 recommends the authorization header method, and OWASP requires HTTPS for protected REST services. [12,14]

9.1 Token service

auth-session.service.ts
import { Injectable, signal } from '@angular/core';

@Injectable({ providedIn: 'root' })
export class AuthSessionService {
  private readonly tokenState = signal<string | null>(null);

  accessToken(): string | null {
    return this.tokenState();
  }

  setAccessToken(token: string): void {
    this.tokenState.set(token);
  }

  clear(): void {
    this.tokenState.set(null);
  }
}

9.2 Bearer-token interceptor

auth.interceptor.ts
import { inject } from '@angular/core';
import {
  HttpHandlerFn,
  HttpRequest,
} from '@angular/common/http';

import { AuthSessionService } from './auth-session.service';
import { SKIP_AUTH } from './http-context';

export function authInterceptor(
  request: HttpRequest<unknown>,
  next: HttpHandlerFn,
) {
  if (request.context.get(SKIP_AUTH)) {
    return next(request);
  }

  const token = inject(AuthSessionService).accessToken();

  if (!token) {
    return next(request);
  }

  return next(
    request.clone({
      setHeaders: {
        Authorization: `Bearer ${token}`,
      },
    }),
  );
}

Keep access-token attachment narrowly scoped. An interceptor should not send an API token to arbitrary third-party origins. Check the target origin or use relative API URLs behind a trusted same-origin gateway before attaching credentials.

origin-restricted variant
const apiOrigin = new URL(
  '/api/',
  document.baseURI,
).origin;

const requestOrigin = new URL(
  request.url,
  document.baseURI,
).origin;

if (requestOrigin !== apiOrigin) {
  return next(request);
}

9.3 Where should tokens live?

There is no Angular-specific storage location that makes a token safe from malicious JavaScript executing in the same origin. OWASP warns against storing session identifiers or sensitive information in localStorage because JavaScript—and therefore successful XSS—can read it. [13]

For higher-security browser applications, consider a backend-for-frontend design with an HttpOnly, Secure, appropriately scoped cookie, so JavaScript does not directly handle the upstream access token. Cookie-based authentication introduces CSRF concerns and requires server-side CSRF/XSRF defenses. Angular implements the client half of a common XSRF mechanism for same-origin mutating requests, but the backend must issue and verify the token. [5,9,13]

9.4 Angular XSRF configuration

custom XSRF names
import {
  provideHttpClient,
  withXsrfConfiguration,
} from '@angular/common/http';

provideHttpClient(
  withXsrfConfiguration({
    cookieName: 'MY-XSRF-TOKEN',
    headerName: 'X-MY-XSRF-TOKEN',
  }),
);

By default, Angular's XSRF interceptor reads the XSRF-TOKEN cookie and sends it as X-XSRF-TOKEN on eligible mutating requests to relative or same-origin URLs; it does not add the header to GET or HEAD. The server must set and verify the token for the mechanism to be effective. [9]

10. File upload

FormData is the browser-native way to construct multipart form submissions containing strings, files, or blobs. Angular detects a FormData body and serializes it as multipart data. Do not manually set the multipart Content-Type; the browser must add the boundary parameter that separates parts. [6,16]

10.1 Basic upload

file-transfer.service.ts — upload
import { inject, Injectable } from '@angular/core';
import {
  HttpClient,
  HttpEvent,
} from '@angular/common/http';
import { Observable } from 'rxjs';

export interface UploadedFile {
  id: string;
  originalName: string;
  mediaType: string;
  size: number;
}

@Injectable({ providedIn: 'root' })
export class FileTransferService {
  private readonly http = inject(HttpClient);

  upload(
    file: File,
    description?: string,
  ): Observable<UploadedFile> {
    const form = new FormData();
    form.append('file', file, file.name);

    if (description) {
      form.append('description', description);
    }

    // Do not set Content-Type manually.
    return this.http.post<UploadedFile>('/api/files', form);
  }
}

10.2 Upload progress and the Fetch/XHR choice

Angular currently uses Fetch by default. The Fetch backend does not report upload progress events, so applications that require upload progress must configure HttpClient with withXhr(). Angular cautions against XHR in server-side rendering environments; the default Fetch backend should remain in use for SSR. [5,6]

app.config.ts — XHR for upload progress
import {
  provideHttpClient,
  withInterceptors,
  withXhr,
} from '@angular/common/http';

provideHttpClient(
  withXhr(),
  withInterceptors([
    authInterceptor,
    apiErrorInterceptor,
  ]),
);
progress-aware upload
import {
  HttpEvent,
  HttpEventType,
} from '@angular/common/http';
import { filter, map, Observable } from 'rxjs';

export type UploadState<T> =
  | { kind: 'progress'; percent: number }
  | { kind: 'complete'; body: T };

uploadWithProgress(
  file: File,
): Observable<UploadState<UploadedFile>> {
  const form = new FormData();
  form.append('file', file, file.name);

  return this.http
    .post<UploadedFile>('/api/files', form, {
      observe: 'events',
      reportUploadProgress: true,
    })
    .pipe(
      map((event: HttpEvent<UploadedFile>) => {
        if (event.type === HttpEventType.UploadProgress) {
          const total = event.total ?? event.loaded;
          const percent =
            total === 0
              ? 0
              : Math.round((100 * event.loaded) / total);

          return {
            kind: 'progress',
            percent,
          } as const;
        }

        if (event.type === HttpEventType.Response) {
          return {
            kind: 'complete',
            body: event.body as UploadedFile,
          } as const;
        }

        return null;
      }),
      filter(
        (state): state is UploadState<UploadedFile> =>
          state !== null,
      ),
    );
}

Progress streams can emit sent, upload-progress, response-header, download-progress, final-response, and interceptor-defined user events. Inspect event.type rather than assuming every event is a response. [6]

10.3 Upload security and reliability

  • Enforce size limits on both client and server; client checks improve UX but are not security controls.
  • Validate the actual file type server-side; filenames and browser-provided MIME types are untrusted.
  • Generate server-side storage names rather than trusting a supplied path or filename.
  • Scan or quarantine untrusted uploads where the threat model requires it.
  • Use resumable/chunked protocols for very large files rather than holding one fragile request open.
  • Return an opaque file ID and metadata rather than a server filesystem path.

OWASP recommends input validation, content-type validation, access control at every non-public endpoint, and HTTPS for REST services. [14]

11. File download

Download binary content with responseType: 'blob'. Use observe: 'response' when the filename or other metadata is carried in response headers. Content-Disposition can communicate an attachment disposition and advisory filename. [6,17]

11.1 Download service

file-transfer.service.ts — download
import { HttpResponse } from '@angular/common/http';
import { map, Observable, tap } from 'rxjs';

export interface DownloadedFile {
  blob: Blob;
  filename: string;
}

download(fileId: string): Observable<DownloadedFile> {
  return this.http
    .get(
      `/api/files/${encodeURIComponent(fileId)}/content`,
      {
        observe: 'response',
        responseType: 'blob',
        reportDownloadProgress: false,
      },
    )
    .pipe(
      map((response: HttpResponse<Blob>) => ({
        blob: response.body ?? new Blob(),
        filename: this.extractFilename(response) ?? 'download.bin',
      })),
    );
}

private extractFilename(
  response: HttpResponse<Blob>,
): string | null {
  const disposition =
    response.headers.get('Content-Disposition');

  if (!disposition) return null;

  const utf8Match =
    /filename\*=UTF-8''([^;]+)/i.exec(disposition);

  if (utf8Match) {
    return this.sanitizeFilename(
      decodeURIComponent(utf8Match[1]),
    );
  }

  const basicMatch =
    /filename="?([^";]+)"?/i.exec(disposition);

  return basicMatch
    ? this.sanitizeFilename(basicMatch[1])
    : null;
}

private sanitizeFilename(filename: string): string {
  return filename
    .replace(/[\/\\?%*:|"<>]/g, '_')
    .replace(/[\u0000-\u001F\u007F]/g, '')
    .trim()
    .slice(0, 180) || 'download.bin';
}

RFC 6266 treats the server-provided filename as advisory and warns recipients not to permit path traversal or overwrite arbitrary locations. Prefer filename* for UTF-8 names and treat any received filename as untrusted input. [17]

11.2 Trigger the browser download

save-blob.ts
export function saveBlob(
  blob: Blob,
  filename: string,
): void {
  const objectUrl = URL.createObjectURL(blob);
  const anchor = document.createElement('a');

  anchor.href = objectUrl;
  anchor.download = filename;
  anchor.rel = 'noopener';
  anchor.style.display = 'none';

  document.body.appendChild(anchor);
  anchor.click();
  anchor.remove();

  // Defer revocation until the click has been processed.
  setTimeout(() => URL.revokeObjectURL(objectUrl), 0);
}

A blob URL gives URL-based browser APIs temporary access to an in-memory Blob. Each object URL retains a reference to its backing object until it is revoked or the document unloads, so call URL.revokeObjectURL when the URL is no longer needed. [18]

Cross-origin filename header JavaScript can read only CORS-exposed response headers. If the file API is cross-origin, the server may need to include Content-Disposition in Access-Control-Expose-Headers; otherwise Angular will receive the blob but cannot read that header. [15]

download event stream
downloadWithProgress(fileId: string) {

12. Consuming HTTP services from a component

Keep HTTP orchestration in services or stores and keep components focused on user interaction and rendering. Prefer the async pipe, signals derived from observables, or lifecycle-aware subscription helpers so results do not update destroyed views. Angular's HTTP observables generally complete, but teardown still prevents callbacks from interacting with destroyed components and cancels in-flight work. [6]

product-list.component.ts
import {
  ChangeDetectionStrategy,
  Component,
  inject,
} from '@angular/core';
import { AsyncPipe, CurrencyPipe } from '@angular/common';
import { catchError, map, of, startWith } from 'rxjs';

import { ProductApiService } from './product-api.service';

@Component({
  selector: 'app-product-list',
  standalone: true,
  imports: [AsyncPipe, CurrencyPipe],
  changeDetection: ChangeDetectionStrategy.OnPush,
  template: `
    @if (vm$ | async; as vm) {
      @if (vm.loading) {
        <p>Loading products…</p>
      } @else if (vm.error) {
        <p role="alert">{{ vm.error }}</p>
      } @else {
        <ul>
          @for (product of vm.products; track product.id) {
            <li>
              {{ product.name }} —
              {{ product.priceCents / 100 | currency }}
            </li>
          }
        </ul>
      }
    }
  `,
})
export class ProductListComponent {
  private readonly products = inject(ProductApiService);

  readonly vm$ = this.products.list({ pageSize: 25 }).pipe(
    map((page) => ({
      loading: false,
      products: page.items,
      error: '',
    })),
    startWith({
      loading: true,
      products: [],
      error: '',
    }),
    catchError((error: unknown) =>
      of({
        loading: false,
        products: [],
        error:
          error instanceof Error
            ? error.message
            : 'Unable to load products.',
      }),
    ),
  );
}

This separation establishes a narrow transport layer: components do not construct URLs, interceptors do not contain feature-specific business rules, and API services expose domain-relevant operations rather than raw networking details. The structure is an engineering recommendation, not an Angular runtime requirement.

14. Common pitfalls

  1. Subscribing twice: each subscription can create another request. [6]
  2. Believing the generic validates JSON: it is a TypeScript assertion, not runtime schema validation. [6]
  3. Mutating HttpParams or HttpHeaders without reassignment: both are immutable. [6]
  4. Setting multipart Content-Type manually: this prevents the browser from generating the correct boundary. [16]
  5. Expecting Fetch upload progress: current Angular requires the XHR backend for upload progress. [5,6]
  6. Retrying every failure: retry only transient failures and account for method idempotency. [1]
  7. Attaching tokens to every URL: restrict credential propagation to trusted API origins. Bearer-token possession grants use. [12]
  8. Using CORS as authorization: the API must authenticate and authorize every protected operation. [14,15]
  9. Storing session identifiers in localStorage without accepting XSS exposure: JavaScript can read them. [13]
  10. Trusting a download filename: sanitize it and treat it as advisory. [17]
  11. Forgetting to revoke blob URLs: object URLs retain backing objects until released. [18]

15. Production checklist

  • Use HTTPS for every authenticated or sensitive API endpoint. [14]
  • Centralize base URLs, error mapping, authentication, and correlation metadata.
  • Keep feature endpoints in injectable API services.
  • Validate important response payloads at runtime.
  • Use safe/idempotent semantics to decide retry behavior. [1]
  • Bound timeouts and retries; surface actionable errors.
  • Use HttpContext for interceptor flags instead of ad hoc magic headers. [8]
  • Never log authorization headers, cookies, or sensitive payloads.
  • Restrict CORS origins, methods, headers, and credentials on the server. [14,15]
  • Implement server-side authorization at every protected endpoint. [14]
  • Pair cookie authentication with server-verified CSRF/XSRF protection. [9]
  • Do not manually set multipart boundaries. [16]
  • Sanitize advisory filenames and revoke object URLs. [17,18]

16. Summary

Modern Angular HTTP code is strongest when it preserves the meaning of the underlying protocol. Use HttpClient as a typed reactive transport, REST-style resource contracts as an API convention, services as the domain-facing boundary, and functional interceptors for carefully scoped cross-cutting behavior. Handle errors by status and contract, attach bearer tokens only to trusted origins, let the server enforce authorization and CSRF controls, use FormData correctly for uploads, and treat downloaded metadata as untrusted.

The most consequential current implementation detail is the backend choice: Angular's default Fetch backend is appropriate for most browser and SSR traffic, but upload-progress events require XHR. Design that choice explicitly rather than discovering it after the UI's progress indicator never moves. [5,6]
