Angular Templates

An Angular template is compiled HTML that declares a component’s rendered structure and its connections to application state. The template compiler understands bindings, event listeners, variables, directives, components, pipes, fragments, and control-flow blocks, then translates them into JavaScript instructions that create and update views.

1. What an Angular template is

Every Angular component has a template that defines the DOM it renders. A template may be inline in the component’s template metadata or stored in a separate file referenced by templateUrl. Angular templates are based on HTML but extend it with binding punctuation, control-flow blocks, variables, components, directives, pipes, and template fragments.[1][2]

Structure

HTML elements, components, ng-container, template fragments, content projection, and embedded views define what may be rendered.

Data flow

Interpolation and property-like bindings move values into rendering targets; event bindings move notifications back into component logic; two-way binding combines both directions.[3][4][5]

Execution context

Expressions run against the component instance plus variables and special locals visible in the current template scope.[6][10]

Angular compiles templates rather than treating them as strings interpreted on every update. Compilation provides framework-specific rendering optimization, static input/output matching, and template type checking.[1][22]

1.1 Inline and external templates

inline template
import { Component } from '@angular/core';

@Component({
  selector: 'app-inline-message',
  standalone: true,
  template: `
    <h2>{{ title }}</h2>
    <p>{{ message }}</p>
  `,
})
export class InlineMessageComponent {
  title = 'Status';
  message = 'The operation completed.';
}
external template
import { Component } from '@angular/core';

@Component({
  selector: 'app-product-page',
  standalone: true,
  templateUrl: './product-page.component.html',
  styleUrl: './product-page.component.css',
})
export class ProductPageComponent {
  // ...
}

Inline templates are convenient for small, cohesive components. External files are often easier to navigate when markup is substantial. Both are compiled by the same Angular template compiler.

1.2 Differences from ordinary HTML

  • Characters such as [], (), [()], #, and @ have Angular meanings.
  • Component and directive elements may use self-closing syntax.
  • Angular removes template comments from rendered output and may use comment anchors for dynamic views.
  • Angular normally collapses whitespace it considers unnecessary.
  • <script> elements are not supported in Angular templates.[1][24]

2. Historical development

AngularJS: HTML enhanced by directives

AngularJS templates used HTML with framework-specific elements and attributes. The AngularJS compiler traversed the DOM, matched directives such as interpolation and ng-repeat, and linked expressions to scope values. Its template language combined interpolation, directive attributes such as ng-click, filters, and ng-model synchronization.[27][28][29][30]

Angular 2: directional binding syntax

The rewritten Angular framework formalized interpolation, property binding, event binding, two-way binding, template expressions, local references, and component/directive inputs as a compiled component-template contract.[31]

Ivy and stronger template checking

Angular’s compiler evolved to infer embedded-view context, component and directive generic types, input assignability, DOM reference types, and event payload types under strictTemplates.[22]

Angular 17: built-in control flow

Angular added @if, @for, and @switch as built-in template syntax. These blocks require no directive import and provide explicit branches, loop tracking, and empty-list handling.[11]

Signal-aware component contracts

Modern components can expose read-only signal inputs, typed outputs, and writable model inputs. Template signal reads become tracked reactive dependencies, and model inputs integrate directly with two-way binding.[18][19][20]

Angular 20–22: control-flow migration and expression alignment

The historical NgIf, NgFor, and NgSwitch directive families are deprecated from Angular 20 in favor of built-in control flow. Angular 22 aligns template optional chaining with JavaScript by returning undefined when the left operand is nullish; migration tooling can temporarily preserve the earlier null-returning behavior.[10][15][16][17]

3. Interpolation

Interpolation uses double curly braces to evaluate an expression, convert the result to text, and insert it into a text position. Angular keeps the rendered value synchronized with the source values that the binding reads.[3]

interpolation with signals
import {
  Component,
  computed,
  signal,
} from '@angular/core';

@Component({
  selector: 'app-order-summary',
  standalone: true,
  template: `
    <h1>Order {{ orderNumber() }}</h1>
    <p>Customer: {{ customerName() }}</p>
    <p>Items: {{ itemCount() }}</p>
    <p>Total cents: {{ totalCents() }}</p>
  `,
})
export class OrderSummaryComponent {
  readonly orderNumber = signal('A-1042');
  readonly customerName = signal('Ada Lovelace');
  readonly itemPrices = signal<readonly number[]>(
    [1299, 5000],
  );

  readonly itemCount = computed(
    () => this.itemPrices().length,
  );

  readonly totalCents = computed(
    () => this.itemPrices().reduce(
      (sum, price) => sum + price,
      0,
    ),
  );
}

Bindings that read signals are reactive consumers. Updating a writable signal through set or update invalidates the relevant template consumers and schedules rendering.[3][20]

3.1 Expressions inside interpolation

interpolation expressions
<p>{{ quantity() * unitPriceCents() }}</p>
<p>{{ user()?.displayName ?? 'Anonymous' }}</p>
<p>{{ active() ? 'Enabled' : 'Disabled' }}</p>
<p>{{ orderNumber().toUpperCase() }}</p>

Interpolation accepts Angular template expressions, not arbitrary program blocks. Keep calculations inexpensive and side-effect free; move complex derivation into a computed signal, component property, or pure pipe.

3.2 Pipes in interpolation

pipes in template expressions
import {
  CurrencyPipe,
  DatePipe,
  TitleCasePipe,
} from '@angular/common';

@Component({
  standalone: true,
  imports: [
    CurrencyPipe,
    DatePipe,
    TitleCasePipe,
  ],
  template: `
    <p>{{ productName() | titlecase }}</p>
    <p>{{ price() | currency:'USD' }}</p>
    <p>{{ createdAt() | date:'medium':'UTC' }}</p>
  `,
})
export class ProductPriceComponent {
  // ...
}

The pipe operator is an Angular-specific expression operator. Pipes transform display values declaratively, can accept colon-separated arguments, and may be chained from left to right.[21]

3.3 Interpolation is textual

text versus property state
<!-- Produces text inside the element. -->
<p>{{ product }}</p>

<!-- For typed DOM state, bind a property instead. -->
<button [disabled]="saving()">Save</button>

Interpolation stringifies values. Use property binding when the target expects a number, boolean, object, class instance, or other non-string value.[3]

4. Property binding

Property binding places a target inside square brackets and assigns the evaluated expression result to that target. The target may be a native DOM property, component input, directive input, class binding, style binding, or explicit attribute binding.[3]

4.1 Native DOM properties

native property binding
@Component({
  selector: 'app-save-control',
  standalone: true,
  template: `
    <button
      type="button"
      [disabled]="saving() || invalid()"
      [title]="tooltip()">
      {{ saving() ? 'Saving…' : 'Save' }}
    </button>

    <img
      [src]="imageUrl()"
      [alt]="imageDescription()"
      [width]="320"
      [height]="240">
  `,
})
export class SaveControlComponent {
  readonly saving = signal(false);
  readonly invalid = signal(false);
  readonly imageUrl = signal('/images/product.webp');
  readonly imageDescription =
    signal('Product preview');

  readonly tooltip = computed(() =>
    this.invalid()
      ? 'Correct validation errors'
      : 'Save the document',
  );
}

On native elements, bracket syntax normally targets properties on the live DOM object. This matters for typed state such as the boolean disabled property. HTML attributes initialize elements, while DOM properties represent current runtime state; although many properties reflect attributes, they are not universally identical.[3][25][26]

4.2 Explicit attribute binding

attribute binding
<table>
  <tr>
    <th
      [attr.colspan]="headingSpan()"
      [attr.aria-sort]="sortDirection()">
      Product
    </th>
  </tr>
</table>

<svg viewBox="0 0 100 100" aria-hidden="true">
  <circle
    cx="50"
    cy="50"
    [attr.r]="radius()" />
</svg>

Prefix a target with attr. when attribute semantics are required or when no corresponding property exists, including many ARIA, SVG, and table attributes. A null binding value removes the attribute.[3]

4.3 Component and directive inputs

child input contract
import {
  Component,
  input,
} from '@angular/core';

export interface UserSummary {
  readonly id: string;
  readonly displayName: string;
}

@Component({
  selector: 'app-user-card',
  standalone: true,
  template: `
    <article>
      <h2>{{ user().displayName }}</h2>
    </article>
  `,
})
export class UserCardComponent {
  readonly user =
    input.required<UserSummary>();

  readonly selected = input(false);
}
parent input bindings
<app-user-card
  [user]="selectedUser()"
  [selected]="selectedUser()?.id === activeId()" />

The compiler matches bracketed targets against declared component and directive inputs. Required inputs, generic input types, nullability, aliases, and transforms participate in template type checking.[18][22]

4.4 Class and style bindings

individual class and style bindings
<article
  class="card"
  [class.card--selected]="selected()"
  [class.card--disabled]="disabled()"
  [style.opacity]="disabled() ? 0.55 : 1"
  [style.max-width.px]="maximumWidth()">
  ...
</article>
aggregate class and style maps
readonly classes = computed(() => ({
  'card--selected': this.selected(),
  'card--disabled': this.disabled(),
}));

readonly styles = computed(() => ({
  borderWidth: this.selected() ? '2px' : '1px',
  transform: `scale(${this.selected() ? 1.02 : 1})`,
}));
aggregate bindings
<article
  [class]="classes()"
  [style]="styles()">
  ...
</article>

For collection-style class and style bindings, replace the object or collection when its contents change. Identity-preserving mutation can prevent Angular from recognizing a new bound value.

4.5 Literal attribute versus expression

literal and bound input values
<!-- Literal text supplied to the input. -->
<app-avatar size="48" />

<!-- Evaluated number expression. -->
<app-avatar [size]="48" />

<!-- Evaluated component expression. -->
<app-avatar [size]="preferredSize()" />

5. Event binding

Event binding places a native event or component output name in parentheses and executes a template statement when that event occurs. Native event bindings may use the special $event variable to access the DOM event object.[4]

5.1 Native events

native event bindings
@Component({
  selector: 'app-search',
  standalone: true,
  template: `
    <label for="search">Search</label>

    <input
      #searchInput
      id="search"
      type="search"
      [value]="query()"
      (input)="updateQuery($event)"
      (keydown.enter)="submit()"
      (keydown.escape)="clear()">

    <button
      type="button"
      (click)="submit()">
      Search
    </button>
  `,
})
export class SearchComponent {
  readonly query = signal('');

  updateQuery(event: Event): void {
    const input =
      event.currentTarget as HTMLInputElement;

    this.query.set(input.value);
  }

  submit(): void {
    // Execute search.
  }

  clear(): void {
    this.query.set('');
  }
}

Angular supports native event names and key modifiers such as keydown.enter. The DOM event target can be affected by bubbling; currentTarget refers to the element whose listener is currently running.[4][25]

5.2 Template statements

event listener statements
<button
  type="button"
  (click)="selectedId = product.id">
  Select
</button>

<button
  type="button"
  (click)="save(product.id)">
  Save
</button>

Event listeners use statements rather than ordinary value expressions. Statements support assignment operators but do not support pipes. Declarations, arrow functions, and many full JavaScript constructs remain unavailable.[10]

5.3 Child component outputs

child output
import {
  Component,
  input,
  output,
} from '@angular/core';

@Component({
  selector: 'app-product-row',
  standalone: true,
  template: `
    <button
      type="button"
      (click)="selected.emit(productId())">
      Select
    </button>
  `,
})
export class ProductRowComponent {
  readonly productId = input.required<string>();
  readonly selected = output<string>();
}
listen for a component output
<app-product-row
  [productId]="product.id"
  (selected)="openProduct($event)" />

For a custom output, $event is the value emitted by the child. Angular custom outputs are case-sensitive and do not bubble through the DOM.[19]

5.4 Keep event logic in TypeScript

focused event handling
<!-- Prefer a focused statement. -->
<button (click)="deleteProduct(product.id)">
  Delete
</button>

<!-- Avoid a workflow embedded in markup. -->
<button
  (click)="selectedId = product.id;
           deleting = true;
           audit('delete');
           deleteProduct(product.id)">
  Delete
</button>

6. Two-way binding

Two-way binding uses [()] to combine a value binding with a corresponding change event. It is shorthand for two directional contracts, not a separate mutation mechanism.[5]

6.1 Native form controls with ngModel

two-way form binding
import { Component } from '@angular/core';
import { FormsModule } from '@angular/forms';

@Component({
  selector: 'app-profile-name',
  standalone: true,
  imports: [FormsModule],
  template: `
    <label for="name">Name</label>

    <input
      id="name"
      type="text"
      [(ngModel)]="name">

    <p>Hello, {{ name }}.</p>
  `,
})
export class ProfileNameComponent {
  name = 'Ada';
}

For native controls, NgModel from FormsModule bridges the control’s view value with component state. The expanded form binds ngModel and listens for ngModelChange.[5][30]

expanded ngModel binding
<input
  [ngModel]="name"
  (ngModelChange)="name = $event">

6.2 Custom component two-way binding

model input component
import {
  Component,
  model,
} from '@angular/core';

@Component({
  selector: 'app-counter',
  standalone: true,
  template: `
    <button
      type="button"
      (click)="count.update(value => value - 1)">
      −
    </button>

    <output>{{ count() }}</output>

    <button
      type="button"
      (click)="count.update(value => value + 1)">
      +
    </button>
  `,
})
export class CounterComponent {
  readonly count = model(0);
}
parent two-way binding
@Component({
  selector: 'app-order-editor',
  standalone: true,
  imports: [CounterComponent],
  template: `
    <app-counter [(count)]="quantity" />
    <p>Quantity: {{ quantity() }}</p>
  `,
})
export class OrderEditorComponent {
  readonly quantity = signal(1);
}

A model input can receive a parent value and write changes back through an automatically generated output whose name ends in Change. A parent may bind either a writable signal or an assignable property.[5][18]

6.3 Classic input/output convention

classic value/valueChange pair
@Input() value = 0;

@Output()
readonly valueChange =
  new EventEmitter<number>();

increment(): void {
  this.valueChange.emit(this.value + 1);
}
classic custom two-way binding
<app-legacy-counter
  [(value)]="quantity" />

7. Template expressions

Angular expressions resemble JavaScript but are intentionally constrained and include template-specific operators. They execute against the component, current template variables, special locals, and the supported Angular globals.[10]

7.1 Lexical context

component members and loop locals
@Component({
  template: `
    <p>{{ title }}</p>

    @for (
      product of products();
      track product.id;
      let index = $index
    ) {
      <p>
        {{ index + 1 }}.
        {{ product.name }}
      </p>
    }
  `,
})
export class CatalogComponent {
  title = 'Catalog';
  readonly products = signal<readonly Product[]>([]);
}

Component members are implicitly referenced through this. A template variable can shadow a component member; explicit this.member accesses the class member when disambiguation is needed.[10]

7.2 Common supported forms

supported expression forms
{{ quantity() * unitPrice() }}
{{ user()?.profile?.displayName ?? 'Anonymous' }}
{{ selected() ? 'Selected' : 'Not selected' }}
{{ 'id' in record ? record.id : 'missing' }}
{{ item instanceof ProductModel }}
{{ {...defaults, page: currentPage()} }}
{{ [...selectedIds(), item.id] }}
{{ format(...argumentsList()) }}

Current Angular expressions support arithmetic, logical and comparison operators, nullish coalescing, property access, conditional expressions, typeof, void, in, instanceof, assignment operators, and selected spread/rest forms. Angular also adds the pipe operator, optional chaining, and the TypeScript non-null assertion operator.[10]

7.3 Important unsupported forms

unsupported expression constructs
<!-- Not supported in ordinary template expressions: -->
{{ new Product() }}
{{ (() => total())() }}
{{ const value = total() }}
{{ [a, b] = values }}
{{ flags & mask }}

Templates do not support declarations, class definitions, arrow functions, new, destructuring, the comma operator, or bitwise operators. Put complex imperative logic in TypeScript.[10]

7.4 Globals

Angular exposes undefined and $any as general expression globals. Ordinary JavaScript globals such as Number, parseInt, NaN, and Infinity are not automatically available unless exposed through the component.[10]

$any type escape hatch
<!-- Escape hatch from strict template typing. -->
<p>{{ $any(legacyValue).unknownProperty }}</p>

Use $any sparingly. It suppresses useful type checking rather than improving the data contract.

7.5 Optional chaining in Angular 22

optional chaining
<p>{{ account()?.owner?.displayName }}</p>

From Angular 22, optional chaining follows standard JavaScript behavior and produces undefined when the left operand is nullish. During migration, Angular may insert a temporary $safeNavigationMigration(...) compiler marker into expressions that depended on the earlier null-returning behavior. The marker is not a callable TypeScript function and should be removed after the expression no longer depends on the distinction.[10]

7.6 Keep expressions deterministic and inexpensive

computed derivation for templates
<!-- Avoid repeating expensive work. -->
@for (
  product of products()
    .filter(expensivePredicate)
    .sort(expensiveComparator);
  track product.id
) {
  ...
}

<!-- Prefer memoized derivation. -->
readonly visibleProducts = computed(() =>
  [...this.products()]
    .filter(expensivePredicate)
    .sort(expensiveComparator),
);

8. Template variables with @let

Angular distinguishes local template variables declared with @let from template reference variables declared with #name. An @let variable stores the current value of an Angular expression and is automatically reevaluated as its dependencies change.[6]

8.1 Basic @let

@let declarations
@let currentUser = user();
@let fullName =
  currentUser.firstName + ' ' + currentUser.lastName;
@let formattedTotal = total() | currency:'USD';

<h1>Hello, {{ fullName }}</h1>
<p>Total: {{ formattedTotal }}</p>

Each @let declaration defines one variable and ends with a semicolon. Unlike JavaScript let, the template variable cannot be assigned by an event statement; Angular updates it from its defining expression.[6]

8.2 Scope and views

@let scope
@let catalogTitle = title();

@if (showCatalog()) {
  @let itemCount = products().length;

  <h1>{{ catalogTitle }}</h1>
  <p>{{ itemCount }} items</p>
}

<!-- itemCount is not visible here. -->

An @let declaration is visible after its declaration in the current view and descendant views. Control-flow blocks, deferred blocks, structural directives, and component boundaries create view scopes. Variables are not hoisted from child views to parents or siblings.[6]

8.3 Shadowing a class member

explicit this for shadowed members
@let user = user();

@if (user) {
  <p>Local value: {{ user.displayName }}</p>
  <p>Signal function: {{ this.user()!.displayName }}</p>
}

Explicit this. can distinguish a component member from a same-named local variable, which is useful for signal narrowing and long expressions.[10]

9. Template reference variables

A template reference variable starts with # and refers to a value associated with a template node. Depending on the host, it may refer to a DOM element, component instance, exported directive instance, or TemplateRef.[6]

9.1 DOM element reference

DOM reference variable
<label for="task">Task</label>
<input
  #taskInput
  id="task"
  type="text">

<button
  type="button"
  (click)="addTask(taskInput.value);
           taskInput.value = ''">
  Add task
</button>

On an ordinary native element, the variable refers to the corresponding DOM object. Under strict template checking, Angular infers the element type from the tag name—for example, HTMLInputElement for an input reference.[6][22]

9.2 Component reference

component reference variable
<app-video-player #player />

<button
  type="button"
  (click)="player.play()">
  Play
</button>

<button
  type="button"
  (click)="player.pause()">
  Pause
</button>

On a component host, an unqualified reference points to the component instance. Use imperative component methods only for exceptional host actions such as focusing or controlling media; ordinary data flow should remain input/output based.

9.3 Directive reference with exportAs

exported directive
@Directive({
  selector: '[appDropZone]',
  exportAs: 'dropZone',
  host: {
    '[class.drag-active]': 'active()',
  },
})
export class DropZoneDirective {
  readonly active = signal(false);
  readonly files = signal<readonly File[]>([]);
}
directive reference
<section
  appDropZone
  #zone="dropZone">
  <p>{{ zone.files().length }} files</p>
</section>

A directive must declare an exportAs name before a template reference can request that directive instance by name.[6]

9.4 TemplateRef reference

template fragment reference
<ng-template #emptyState>
  <p>No records are available.</p>
</ng-template>

A reference on <ng-template> refers to its TemplateRef, an object that can create embedded views while retaining the fragment’s declaration binding and injection context.[7][8][32]

9.5 Scope

reference-variable scope
@if (showEditor()) {
  <input #editorInput>
}

<!-- Invalid: editorInput exists only in the @if child view. -->
<!-- <button (click)="editorInput.focus()">Focus</button> -->

Reference variables are scoped to the view that declares them. Inner views can access outer references, but parents and siblings cannot access references declared inside a child embedded view.[6]

10. Template fragments with ng-template

<ng-template> defines content that Angular does not render by default. The fragment becomes a TemplateRef and can be rendered by control-flow directives, NgTemplateOutlet, a structural directive, or programmatic view creation.[7][8][32]

10.1 Render a fragment with NgTemplateOutlet

NgTemplateOutlet and context
import { NgTemplateOutlet } from '@angular/common';

@Component({
  selector: 'app-state-panel',
  standalone: true,
  imports: [NgTemplateOutlet],
  template: `
    <ng-template #loading>
      <p>Loading…</p>
    </ng-template>

    <ng-template #ready let-data>
      <h2>{{ data.title }}</h2>
      <p>{{ data.summary }}</p>
    </ng-template>

    <ng-container
      [ngTemplateOutlet]="
        state().status === 'ready'
          ? ready
          : loading
      "
      [ngTemplateOutletContext]="{
        $implicit: state().data
      }" />
  `,
})
export class StatePanelComponent {
  // ...
}

NgTemplateOutlet renders the selected fragment at its location. Context properties become variables declared by let-; $implicit is read by an unassigned let declaration.[7][34]

10.2 Fragment declaration context

Expressions in a fragment are evaluated against the component and lexical template scope where the fragment was declared, even if the fragment is rendered at another location. A supplied context adds local values but does not change the declaring component context.[7][32]

10.3 Programmatic view creation

structural directive using TemplateRef
@Directive({
  selector: '[appRepeat]',
})
export class RepeatDirective {
  private readonly template =
    inject(TemplateRef<RepeatContext>);

  private readonly container =
    inject(ViewContainerRef);

  readonly count = input(1, {
    alias: 'appRepeat',
  });

  constructor() {
    effect(() => {
      this.container.clear();

      for (
        let index = 0;
        index < this.count();
        index++
      ) {
        this.container.createEmbeddedView(
          this.template,
          {
            $implicit: index,
            index,
          },
        );
      }
    });
  }
}

interface RepeatContext {
  $implicit: number;
  index: number;
}
custom structural directive usage
<p *appRepeat="3; let index">
  Repetition {{ index + 1 }}
</p>

ViewContainerRef owns attached views and can create, insert, move, detach, remove, or clear embedded and component views.[12][33]

11. Grouping with ng-container

<ng-container> groups template content or marks an insertion location without rendering a real DOM element. It is useful when a wrapper would interfere with semantic HTML, CSS layout, table structure, or list structure.[9]

group without a DOM wrapper
<ul>
  @for (user of users(); track user.id) {
    <ng-container>
      <li>{{ user.displayName }}</li>

      @if (user.isAdministrator) {
        <li class="role-note">
          Administrator
        </li>
      }
    </ng-container>
  }
</ul>

Angular ignores property/attribute bindings and event listeners placed directly on ng-container. Directives applied to it may provide dependency-injection context to descendants, but they cannot rely on a rendered host element.[9]

12. Structural directives and modern control flow

Structural directives change view structure by creating or removing embedded views. Their asterisk shorthand expands to an <ng-template> that hosts the directive. Angular’s built-in control-flow blocks now cover ordinary conditions, loops, and switches without directive imports.[11][12]

12.1 Modern blocks

modern template control flow
@if (user(); as currentUser) {
  <app-user-card [user]="currentUser" />
} @else {
  <app-sign-in-prompt />
}

@for (
  product of products();
  track product.id;
  let index = $index
) {
  <app-product-row
    [product]="product"
    [position]="index + 1" />
} @empty {
  <p>No products found.</p>
}

@switch (status()) {
  @case ('loading') {
    <app-spinner />
  }

  @case ('ready') {
    <app-results />
  }

  @default {
    <app-error-message />
  }
}

@for requires a tracking expression that identifies logical items and exposes special locals such as $index, $count, $first, and $last. @empty provides a zero-item fallback.[11]

12.2 Legacy structural directives

deprecated control-flow directives
<div *ngIf="visible">
  Visible
</div>

<li
  *ngFor="
    let item of items;
    trackBy: trackById;
    index as index
  ">
  {{ index }} — {{ item.name }}
</li>

<section [ngSwitch]="status">
  <p *ngSwitchCase="'ready'">Ready</p>
  <p *ngSwitchDefault>Unknown</p>
</section>

NgIf, NgFor, and NgSwitch are deprecated from Angular 20 and should be migrated to the built-in blocks in new code.[15][16][17]

12.3 Asterisk expansion

structural microsyntax expansion
<!-- Shorthand -->
<li
  *ngFor="
    let item of items;
    index as index
  ">
  {{ item.name }}
</li>

<!-- Conceptual expanded form -->
<ng-template
  ngFor
  let-item
  [ngForOf]="items"
  let-index="index">
  <li>{{ item.name }}</li>
</ng-template>

Structural microsyntax maps its naked expression to the directive’s primary input, prefixes key-expression inputs with the selector name, and maps let variables to exported context properties.[12]

12.4 One asterisk per host element

nested structural directives
<!-- Invalid -->
<li
  *ngIf="visible"
  *ngFor="let item of items">
</li>

<!-- Explicit nesting -->
<ng-container *ngIf="visible">
  <li *ngFor="let item of items">
    {{ item.name }}
  </li>
</ng-container>

Only one shorthand structural directive can occupy a physical element because the shorthand creates one implicit template host. Nest ng-container or explicit ng-template layers to define ordering.[12]

13. Attribute directives

Attribute directives attach reusable behavior to an existing element, component, or directive. They may expose inputs and outputs, listen for host events, bind host properties, inject co-located services or directives, and participate in lifecycle hooks.[13][14]

13.1 Built-in attribute behavior

class and style attribute behavior
<!-- Individual bindings are usually clearest. -->
<article
  [class.selected]="selected()"
  [style.opacity]="disabled() ? 0.5 : 1">
  ...
</article>

<!-- NgClass and NgStyle remain available. -->
<article
  [ngClass]="classMap()"
  [ngStyle]="styleMap()">
  ...
</article>

13.2 Custom directive

highlight.directive.ts
import {

For one-off properties, styles, classes, and listeners, ordinary template bindings are simpler. A directive is useful when the behavior deserves a reusable named contract.[13]

14. Strict template type checking

With strictTemplates, Angular checks binding assignability, nullability, component and directive generic types, embedded-view contexts, DOM reference types, and event payloads. This makes templates part of the application’s compile-time type system rather than an unchecked string surface.[22]

tsconfig.json
{
  "angularCompilerOptions": {
    "strictTemplates": true
  }
}

14.1 Input type mismatch

nullable parent and required child
export class UserDetailComponent {
  readonly user =
    input.required<User>();
}

export class ParentComponent {
  readonly selectedUser =
    signal<User | null>(null);
}
template narrowing
<!-- Compile-time error under strict templates. -->
<app-user-detail
  [user]="selectedUser()" />

<!-- Narrow first. -->
@if (selectedUser(); as user) {
  <app-user-detail [user]="user" />
}

14.2 Event inference

event payload inference
<input
  (input)="onInput($event)">

<app-selector
  (selected)="onSelected($event)">

Strict mode infers native DOM event types and component output types. It also infers local reference types from native tag names and context types for correctly annotated structural directives.[22]

14.3 Escape hatches

template type escape hatches
<!-- Non-null assertion when justified. -->
<app-user-card [user]="user()!" />

<!-- Disable checking for one expression. -->
<p>{{ $any(legacyObject).property }}</p>

Use assertions only when the invariant is established elsewhere. Repeated assertions usually indicate that state should be narrowed, normalized, or modeled more accurately.

15. Template security

Angular treats values inserted through interpolation and bindings as untrusted and escapes or sanitizes them according to their rendering context. Angular templates themselves are trusted executable code and must never be generated by concatenating untrusted input with template syntax.[23]

15.1 Text versus HTML contexts

untrusted content
readonly content =
  '<img src=x onerror="alert(1)"><b>Hello</b>';
text and HTML bindings
<!-- Markup appears as text. -->
<p>{{ content }}</p>

<!-- Angular sanitizes the HTML context. -->
<div [innerHTML]="content"></div>

Interpolation produces text. innerHTML requests HTML interpretation, so Angular sanitizes the value for the HTML context and removes unsafe content.[23]

15.2 Context-sensitive sanitization

Angular distinguishes HTML, style, URL, and resource-URL security contexts. It can sanitize untrusted HTML and URL values, but a resource URL may execute code and cannot be made safe through generic sanitization.[23]

15.3 Templates are code

template-injection anti-pattern
<!-- Never construct and compile this from user content. -->
const template =
  `<button (click)="${userInput}">
     Run
   </button>`;

Use fixed AOT-compiled templates and bind data into them. Content Security Policy and Trusted Types can provide additional browser-enforced protections.[23]

16. Whitespace and generated DOM

Angular normally removes whitespace between elements and collapses collapsible text whitespace during compilation, reducing unnecessary text nodes. A component can request preserveWhitespaces: true, but Angular advises avoiding it unless necessary because it can increase rendered nodes and work.[24]

preserve template whitespace
@Component({
  selector: 'app-code-sample',
  standalone: true,
  preserveWhitespaces: true,
  template: `
    <pre>Preserved     spacing</pre>
  `,
})
export class CodeSampleComponent {}

Angular also recognizes &ngsp; as a space entity preserved in compiled output.[24]

import {
  Component,
  computed,
  signal,
} from '@angular/core';
import { FormsModule } from '@angular/forms';
import { TitleCasePipe } from '@angular/common';

import {
  HighlightDirective,
} from './highlight.directive';
import {
  ProductCardComponent,
} from './product-card.component';

@Component({
  selector: 'app-product-catalog',
  standalone: true,
  imports: [
    FormsModule,
    TitleCasePipe,
    HighlightDirective,
    ProductCardComponent,
  ],
  templateUrl: './product-catalog.component.html',
})
export class ProductCatalogComponent {
  readonly products =
    signal<readonly Product[]>([]);

  query = '';
  category = 'all';

  readonly categories = computed(() => [
    'all',
    ...new Set(
      this.products().map(
        product => product.category,
      ),
    ),
  ]);

  readonly visibleProducts = computed(() => {
    const query =
      this.query.trim().toLowerCase();

    return this.products().filter(product => {
      const matchesQuery =
        !query ||
        product.name
          .toLowerCase()
          .includes(query);

      const matchesCategory =
        this.category === 'all' ||
        product.category === this.category;

      return matchesQuery && matchesCategory;
    });
  });

  clearSearch(
    input: HTMLInputElement,
  ): void {
    this.query = '';
    input.focus();
  }

  openProduct(
    event: ProductSelected,
  ): void {
    console.log('Selected', event);
  }
}

19. Production template architecture

19.1 Keep templates declarative

A template should describe structure and connect state to behavior. Move expensive derivation, validation rules, HTTP orchestration, and workflows into component logic, computed state, forms, services, or domain functions.

19.2 Maintain one source of truth

Do not maintain several local values synchronized by effects or event chains. Derive display values with computed or @let, pass state downward through inputs, and emit semantic events upward.

19.3 Track repeated content by domain identity

stable loop identity
@for (
  order of orders();
  track order.id
) {
  <app-order-row [order]="order" />
}

Stable keys preserve DOM and component identity across insertions, deletions, and reordering. Avoid random or time-dependent tracking expressions.

19.4 Preserve semantic HTML

Use native elements for their intended roles and use ng-container when an extra wrapper would break valid structures such as tables, lists, and definition lists. Bind native state and accessibility attributes from the same source.

19.5 Use fragments to remove structural duplication

Template fragments are appropriate when the same markup shape must be rendered with different contexts inside one component. Promote the fragment to a component when it needs independent behavior, lifecycle, styling, reuse across files, or a stable public API.

20. Common pitfalls

PitfallConsequenceBetter approach
Confusing attributes and properties Boolean or live DOM state behaves incorrectly. Use property binding by default and attr. for explicit attribute semantics.[3][25][26]
Forgetting brackets for a typed input The child receives a literal text value. Use [input]="expression" for evaluated values.
Complex logic in interpolation Templates become hard to read and work may repeat. Use computed values or pure pipes.
Calling functions with side effects from bindings Rendering changes state and becomes unpredictable. Use side-effect-free expressions and event handlers for commands.
Accessing a child-view reference from its parent The reference is out of scope. Move the reference outward or keep the consumer in the same child view.[6]
Writing new *ngIf, *ngFor, or ngSwitch code The application adopts deprecated control-flow directives. Use built-in blocks.[15][16][17]
Unstable @for tracking Views are recreated and local state is lost. Track stable business keys.[11]
Expecting ng-template to render by itself Its content remains absent. Render it through a directive, outlet, or view container.[7][8]
Generating templates from user input Untrusted input becomes executable template code. Use fixed compiled templates and bind data values.[23]
Disabling strict templates globally to hide one error Many real binding and event type errors go undetected. Fix or narrowly assert the exceptional expression.[22]

23. Conclusion

Angular templates form a compiled, typed interface between component state and rendered views. Interpolation and property bindings move values toward the view; event bindings move notifications toward component logic; two-way binding combines a value contract with a change contract; variables give names to expression values and template nodes; fragments and structural behavior create embedded views; and attribute directives package reusable host behavior.[1][3][4][5][6][7][12][13]

Modern Angular templates are most maintainable when they remain declarative: use signals and computed values for reactive state, built-in blocks for ordinary control flow, stable identities for repeated views, strict template checking for contracts, and fixed AOT-compiled markup for security. Keep imperative workflows in TypeScript and treat every component input, output, reference, and variable scope as an explicit part of the view architecture.
