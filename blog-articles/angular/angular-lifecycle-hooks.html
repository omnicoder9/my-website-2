Angular Lifecycle Hooks

A component lifecycle is the ordered sequence from JavaScript construction, through input initialization and repeated change-detection passes, to final destruction. Hooks are framework callbacks at specific points in that sequence. They are best used for work that genuinely depends on lifecycle timing—not as general containers for business logic or derived state.

1. Lifecycle mental model

Angular creates a component instance, initializes bound inputs, constructs and checks its projected content and own view, revisits it during future change-detection traversals, and eventually destroys the instance and its view. Angular walks the component tree from top to bottom during a traversal and intends to visit each component once, so changing already-checked state in the middle of the pass can create inconsistent results.[1][2]

Instance hooks

Methods such as ngOnInit, ngOnChanges, and ngOnDestroy belong to one directive or component instance.[1]

afterNextRender and afterEveryRender are standalone functions that run after application rendering rather than class-method hooks on one instance.[14][15]

Lifecycle scope

DestroyRef binds cleanup callbacks to the component, directive, service, or injector context from which it is injected.[12]

Angular’s style guide recommends implementing the lifecycle interfaces because their TypeScript contracts catch misspellings and incorrect signatures. It also recommends keeping hook methods small and delegating meaningful work to named methods or services.[21]

2. Historical development

AngularJS directive linking and scope destruction

Early AngularJS directives used compile/link functions and scope events for setup and cleanup. Direct DOM listeners or service listeners not tied to a destroyed element or scope required explicit cleanup to avoid leaks.[25]

AngularJS 1.5 component lifecycle

AngularJS 1.5 introduced the component helper and lifecycle methods including $onInit, $onChanges, $doCheck, $postLink, and $onDestroy. Its documentation describes $postLink as only approximately analogous to modern Angular’s content/view initialization hooks because the compilation models differ.[24][26]

Angular 2 formalizes lifecycle interfaces

The rewritten Angular framework exposed TypeScript interfaces for initialization, changes, checking, content, view, and destruction moments. The archived Angular 2 guide established the hook order and interface-based authoring style still recognizable today.[23]

Signal queries and reactive composition

Modern Angular query functions such as viewChild and contentChild return signals, letting query results participate in computed state and effects. Decorator queries remain supported.[18]

DestroyRef and lifecycle-scoped utilities

DestroyRef enables cleanup registration without concentrating all teardown in ngOnDestroy. Angular’s RxJS interop package builds takeUntilDestroyed on that lifecycle scope.[12][13]

Stable render callbacks

afterNextRender and afterEveryRender provide browser-only, post-render phases for imperative DOM integration and are stable from Angular 20.[14][15][17]

3. Hook execution order

3.1 Initial creation

OrderHook or phaseMeaning
1constructorJavaScript instance construction and injection-context initialization.
2ngOnChangesRuns when initial bound inputs are assigned, if the class implements it.
3ngOnInitRuns once after all initial inputs are initialized.
4ngDoCheckFirst custom check, after ngOnInit.
5ngAfterContentInitProjected content and content queries are initialized.
6ngAfterContentCheckedProjected content has completed its check.
7ngAfterViewInitThe component’s own view and view queries are initialized.
8ngAfterViewCheckedThe component view has completed its check.
9Render callbacksAfter Angular has committed application rendering to the DOM.

During initialization, the first ngOnChanges precedes ngOnInit, and the first ngDoCheck follows ngOnInit. Content initialization precedes view initialization.[1]

3.2 Subsequent input update

OrderHook
1ngOnChanges, when at least one input changed
2ngDoCheck
3ngAfterContentChecked
4ngAfterViewChecked
5Eligible render callbacks

3.3 Destruction

Immediately before Angular destroys the directive/component instance, it invokes ngOnDestroy and registered DestroyRef callbacks within the associated destruction scope.[11][12]

3.4 Hook logging utility

development hook logger
export function logHook(
  name: string,

Ordering on one host element is not a public contract When a component and one or more directives share the same element, Angular does not guarantee an ordering between equivalent lifecycle hooks on those colocated types. Do not build cross-directive coordination around observed order.[1]

4. Constructor versus ngOnInit

The constructor is standard JavaScript/TypeScript object construction. Angular’s injection context is available during component construction, so field initializers can call inject(). Inputs, content queries, and view queries generally are not yet initialized. ngOnInit runs once after initial inputs are available and before the component’s own template is initialized.[1][3]

inject during construction, use initial input in ngOnInit
@Component({
  selector: 'app-report',
  standalone: true,
  template: `...`,
})
export class ReportComponent
  implements OnInit {

  private readonly api =
    inject(ReportApi);

  readonly reportId =
    input.required<string>();

  readonly state =
    signal<ReportState>({
      status: 'idle',
    });

  ngOnInit(): void {
    this.loadReport(
      this.reportId(),
    );
  }

  private loadReport(
    id: string,
  ): void {
    // ...
  }
}

4.1 Prefer field initialization for simple defaults

simple construction-time initialization
readonly expanded = signal(false);

readonly pageSize = 25;

private readonly logger =
  inject(Logger);

4.2 Use ngOnInit when initial inputs matter

input-dependent initialization
readonly locale =
  input.required<string>();

readonly formatter =
  signal<Intl.DateTimeFormat | null>(
    null,

ngOnInit(): void {

4.3 Avoid unnecessary ngOnInit

derived state belongs in computed
// No lifecycle timing is required.
readonly fullName = computed(
  () =>
    `${this.firstName()} ${this.lastName()}`,
);

If state can be expressed as a computed signal, field initializer, provider factory, or service responsibility, a hook is unnecessary.

5. ngOnChanges

ngOnChanges runs after Angular changes one or more bound inputs and before Angular checks the component’s own template and descendants. It receives a SimpleChanges record whose entries contain previous value, current value, and first-change status.[1][4][5][6]

5.1 Inspect input changes

typed SimpleChanges
import {
  Component,
  OnChanges,
  SimpleChanges,
  input,
} from '@angular/core';

@Component({
  selector: 'app-user-profile',
  standalone: true,
  template: `
    <h1>{{ displayName() }}</h1>
  `,
})
export class UserProfileComponent
  implements OnChanges {

  readonly user =
    input.required<User>();

  readonly displayName =
    signal('');

  ngOnChanges(
    changes:
      SimpleChanges<
        UserProfileComponent
      >,
  ): void {
    if (changes.user) {
      this.displayName.set(
        changes.user
          .currentValue
          .displayName,
      );
    }
  }
}

5.2 First-change logic

isFirstChange
ngOnChanges(
  changes: SimpleChanges,
): void {
  const change =
    changes['recordId'];

  if (!change) {
    return;
  }

  if (
    change.isFirstChange()
  ) {
    this.initializeRecord(
      change.currentValue,
    );
  } else {
    this.replaceRecord(
      change.previousValue,
      change.currentValue,
    );
  }
}

5.3 Input aliases use property names in SimpleChanges

alias behavior
readonly accountId =
  input.required<string>({
    alias: 'id',
  });

ngOnChanges(
  changes: SimpleChanges,
): void {
  // Key is "accountId", not "id".
  const change =
    changes['accountId'];
}

Even when an input has a public alias, the SimpleChanges key is the TypeScript property name.[1]

5.4 Multiple inputs and atomic derivation

coordinate changed inputs
readonly start =
  input.required<Date>();

readonly end =
  input.required<Date>();

readonly durationMs =
  signal(0);

ngOnChanges(
  changes: SimpleChanges,
): void {
  if (
    changes['start'] ||
    changes['end']
  ) {
    this.durationMs.set(
      this.end().getTime() -
      this.start().getTime(),
    );
  }
}

5.5 Prefer computed state when possible

computed replacement for ngOnChanges
readonly durationMs =
  computed(
    () =>
      this.end().getTime() -
      this.start().getTime(),
  );

Use ngOnChanges when the transition itself matters—such as comparing old and new IDs, resetting an imperative integration, or invoking a command exactly when an input binding changes. Use computed state when only the current relationship matters.

5.6 Dynamically created components

setInput preserves OnChanges semantics
const ref =
  container.createComponent(
    UserProfileComponent,
  );

ref.setInput(
  'user',
  user,
);

ComponentRef.setInput() marks an OnPush component and ensures ngOnChanges runs when the dynamically created component is checked. Direct assignment to the instance’s input property does not provide the same input-binding semantics.[22]

6. ngOnInit

ngOnInit runs exactly once after Angular initializes all bound inputs and before the component’s own template and its ordinary view/content children have been checked. It is a natural point for one-time setup based on initial inputs.[1][3]

6.1 Initial data loading

load from an initial input
@Component({
  selector: 'app-order-page',
  standalone: true,
  template: `...`,
})
export class OrderPageComponent
  implements OnInit {

  readonly orderId =
    input.required<string>();

  protected readonly store =
    inject(OrderStore);

      this.orderId(),
    );
  }
}

6.2 Initialize a third-party non-DOM object

one-time model initialization

  EditorModel | null = null;

      this.initialDocument(),

6.3 Static decorator query exception

static decorator query in ngOnInit
@Component({
  selector: 'app-card',
  standalone: true,
  template: `
    <app-card-header />
  `,
})
export class CardComponent
  implements OnInit {

  @ViewChild(
    CardHeaderComponent,
    {
      static: true,
    },
  )
  header!:
    CardHeaderComponent;

  ngOnInit(): void {
    console.log(
      this.header.title,
    );
  }
}

A single decorator query with static: true is available in ngOnInit only when the target is guaranteed to exist and is not conditionally rendered. Static results do not update after initialization. Signal query functions provide a different reactive timing model and are recommended for new projects.[18]

6.4 Keep the hook readable

delegate named initialization tasks
ngOnInit(): void {
  this.initializeFilters();
  this.loadInitialPage();
  this.startTelemetry();
}

Named methods make the purpose testable and legible; the hook name describes timing, not the business meaning of the work.[21]

7. ngDoCheck

ngDoCheck runs before Angular checks the component’s template and is invoked very frequently. The interface exists for custom change detection beyond ordinary input binding checks, including specialized collection or mutable-object observation. Angular advises avoiding it whenever another reactive design is possible.[1][6]

Performance-sensitive hook Do not perform network calls, large collection scans, DOM access, or expensive logging in ngDoCheck. Its cost can multiply across every relevant change-detection pass.

7.1 Detect a mutable object field

manual mutable-field observation
@Component({
  selector: 'app-legacy-user',
  standalone: true,
  template: `
    <p>{{ displayName }}</p>
  `,
})
export class LegacyUserComponent
  implements DoCheck {

  readonly user =
    input.required<
      MutableLegacyUser
    >();

  displayName = '';

  private previousName = '';

  ngDoCheck(): void {
    const currentName =
      this.user().name;

    if (
      currentName ===
      this.previousName
    ) {
      return;
    }

    this.previousName =
      currentName;

    this.displayName =
      normalizeName(
        currentName,
      );
  }
}

7.2 Prefer immutable input replacement

better state boundary
user.update(current => ({
  ...current,
  name: 'Ada Byron',
}));

7.3 Prefer computed state

reactive derivation
readonly displayName =
  computed(
    () =>
      normalizeName(
        this.user().name,
      ),
  );

7.4 Custom iterable diff

legacy mutable collection differ
export class LegacyListComponent
  implements DoCheck {

    this.differ =
      this.differs.find(

      );
  }

  ngDoCheck(): void {
    const changes =
      this.differ?.diff(
        this.items(),
      );

    if (changes) {
      this.rebuildIndex();
    }
  }

  private rebuildIndex(): void {
    // ...
  }
}

The DoCheck API points to IterableDiffers and KeyValueDiffers for specialized custom collection checking. Prefer immutable replacement or signal state in new code because it produces clearer ownership and avoids repeated scans.[6]

7.5 OnPush does not eliminate directive DoCheck

The current API notes that a directive’s ngDoCheck may be invoked even when the directive’s own component view is skipped under OnPush. Do not assume OnPush makes an expensive custom hook harmless.[6]

8. ngAfterContentInit

Content is the set of nodes placed between a component’s opening and closing tags in the parent template and projected through ng-content. ngAfterContentInit runs once after this projected content and its content-query results are initialized.[1][7][19]

8.3 Decorator content query

@ContentChildren timing
export class ToolbarComponent
  implements AfterContentInit {

  @ContentChildren(
    ToolbarActionComponent,
  )
  actions!:
    QueryList<
      ToolbarActionComponent
    >;

  ngAfterContentInit(): void {
    this.actions.forEach(
      action =>
        action.register(),
    );
  }
}

Decorator content-query results become available in ngAfterContentInit. Signal content queries update reactively and can be composed with computed signals or effects, but the initialization hook remains useful for a one-time imperative setup after the first projected content exists.[18]

8.4 Do not mutate bound state here

late-state mutation hazard
ngAfterContentInit(): void {
  // Avoid changing a value that was already
  // checked in this same traversal.
  // this.title.set('Changed');
}

Angular warns that changing bound state from this hook can produce ExpressionChangedAfterItHasBeenCheckedError. Read initialized query results here; perform state derivation earlier or through reactive expressions.[1][28]

9. ngAfterViewInit

A component’s view is the DOM and child components declared by its own template. ngAfterViewInit runs once after the view and view-query results are initialized.[1][8][18]

9.3 Prefer render callbacks for DOM work

post-render focus
@Component({
  selector: 'app-autofocus',
  standalone: true,
  template: `
    <input
      #input
      type="text">
  `,
})
export class AutofocusComponent {
  readonly input =
    viewChild.required<
      ElementRef<
        HTMLInputElement
      >
    >('input');

  constructor() {
    afterNextRender({
      write: () => {
        this.input()
          .nativeElement
          .focus();
      },
    });
  }
}

Angular’s DOM guidance says direct DOM manipulation should occur in render callbacks rather than ordinary lifecycle hooks because DOM completeness is only guaranteed in those callbacks and mixed layout reads/writes in hooks can cause layout thrashing. Render callbacks do not run during server rendering or build-time prerendering.[14][20]

9.4 Avoid bound-state mutation

ExpressionChanged risk
ngAfterViewInit(): void {
  // Avoid:
  // this.ready.set(true);
}

Reading query results is valid in ngAfterViewInit; changing already-checked state in the same pass can cause an expression-changed error.[1][28]

9.5 Queries do not pierce component boundaries

View queries search the component’s own template. Content queries search projected nodes declared by the parent. Neither type traverses into another component’s private template.[18]

10. Checked hooks

ngAfterContentChecked runs after projected content is checked, and ngAfterViewChecked runs after the component’s own view is checked. Both can execute many times and should be avoided unless no better reactive or render-callback design exists.[1][9][10]

checked hooks
export class DiagnosticsComponent
  implements
    AfterContentChecked,
    AfterViewChecked {

  ngAfterContentChecked(): void {
    // Keep empty or extremely small.
  }

  ngAfterViewChecked(): void {
    // Keep empty or extremely small.
  }
}

10.1 Common anti-pattern

layout thrashing risk
ngAfterViewChecked(): void {
  // Avoid repeated layout reads:
  const width =
    this.host.nativeElement
      .getBoundingClientRect()
      .width;

  this.chart.resize(width);
}

10.2 Render-aware replacement

phased render callback
constructor() {
  afterEveryRender({
    read: () =>
      this.host.nativeElement
        .getBoundingClientRect()
        .width,

    write: width => {
      this.chart.resize(
        width,
      );
    },
  });
}

Current render callbacks offer explicit earlyRead, write, mixedReadWrite, and read phases. Angular recommends separating reads and writes where possible to reduce browser layout cost.[14][15]

11.4 What Angular often cleans up automatically

  • AsyncPipe unsubscribes when its host view is destroyed.
  • Angular-managed output subscriptions are cleaned up with the component.
  • Effects normally follow their injection context’s destruction.
  • Views and component references destroy their associated Angular data structures.

Cleanup remains your responsibility for native listeners, timers, observers, workers, sockets, third-party instances, and manually managed subscriptions or effects.

12. DestroyRef

DestroyRef registers callbacks in the current destruction scope. Injected in a component or directive, its callbacks run when that instance is destroyed; injected elsewhere, the scope follows the corresponding injector. The API also exposes a destroyed flag and returns an unregister function from onDestroy().[12]

12.1 Colocate setup and cleanup

setup beside teardown
@Component({
  selector: 'app-resize-aware',
  standalone: true,
  template: `...`,
})
export class ResizeAwareComponent {
  private readonly destroyRef =
    inject(DestroyRef);

  constructor() {
    const observer =
      new ResizeObserver(
        entries => {
          this.handleResize(
            entries,
          );
        },
      );

    observer.observe(
      inject(
        ElementRef<
          HTMLElement
        >,
      ).nativeElement,
    );

    this.destroyRef.onDestroy(
      () => {
        observer.disconnect();
      },
    );
  }

  private handleResize(
    entries:
      ResizeObserverEntry[],
  ): void {
    // ...
  }
}

12.2 Unregister a destroy callback

unregister onDestroy callback
const destroyRef =
  inject(DestroyRef);

const unregister =
  destroyRef.onDestroy(
    () => {
      releaseResource();
    },
  );

// Resource was transferred elsewhere;
// prevent this callback.
unregister();

12.3 Check whether the scope is already destroyed

guard delayed completion
const destroyRef =
  inject(DestroyRef);

async function load(): Promise<void> {
  const value =
    await fetchValue();

  if (
    destroyRef.destroyed
  ) {
    return;
  }

  applyValue(value);
}

The destroyed property is useful for avoiding work against a view or context that has already been torn down, including errors such as attempting to use a destroyed view.[1][12]

12.4 Pass lifetime into a helper

lifecycle-aware helper
export function observeElementSize(
  element: Element,
  destroyRef:
    DestroyRef,
  callback:
    (
      rect:
        DOMRectReadOnly,
    ) => void,
): void {
  const observer =
    new ResizeObserver(
      entries => {
        const entry =
          entries[0];

        if (entry) {
          callback(
            entry.contentRect,
          );
        }
      },
    );

  observer.observe(element);

  destroyRef.onDestroy(
    () => {
      observer.disconnect();
    },
  );
}
use the helper
constructor() {
  observeElementSize(
    this.host.nativeElement,
    inject(DestroyRef),
    rect => {
      this.width.set(
        rect.width,
      );
    },
  );
}

13. RxJS subscription cleanup

takeUntilDestroyed is an Angular RxJS operator that completes an Observable when the calling component, directive, service, or other injection context is destroyed. It can inject the current DestroyRef or receive one explicitly outside an injection context.[13]

13.1 Component subscription

automatic subscription lifetime
import {
  takeUntilDestroyed,
} from '@angular/core/rxjs-interop';

@Component({
  selector: 'app-route-title',
  standalone: true,
  template: `...`,
})
export class RouteTitleComponent {
  private readonly route =
    inject(ActivatedRoute);

  private readonly title =
    inject(Title);

  constructor() {
    this.route.data.pipe(
      map(data =>
        String(
          data['title'] ??
          'Application',
        ),
      ),
      takeUntilDestroyed(),
    ).subscribe(value => {
      this.title.setTitle(
        value,
      );
    });
  }
}

    this.searchControl
      .valueChanges
      .pipe(
        debounceTime(250),
        takeUntilDestroyed(
          this.destroyRef,
        ),
      )

        this.search(query);
      });
  }

  private search(
    query: string,

    // ...
  }

13.3 Prefer AsyncPipe for rendered values

template-managed subscription
@if (state$ | async; as state) {
  <app-view [state]="state" />
}

Use a manual subscription when an imperative side effect is required. Use AsyncPipe when the value is rendered, because the pipe owns subscription switching, marking, and destruction cleanup.

13.4 Avoid the destroy-Subject boilerplate in new code

legacy notifier pattern
// Older pattern:
private readonly destroy$ =
  new Subject<void>();

ngOnDestroy(): void {
  this.destroy$.next();
  this.destroy$.complete();
}

The Subject pattern remains valid but adds mutable infrastructure and a hook solely for notification. takeUntilDestroyed expresses the Angular lifecycle directly.[13]

14. Render callbacks and afterRenderEffect

afterNextRender runs once after the next application render. afterEveryRender runs after every render. These functions require an injection context unless an injector is supplied and are not invoked during server-side rendering or build-time prerendering.[14][15][20]

14.1 One-time focus

afterNextRender
constructor() {
  afterNextRender({
    write: () => {
      this.input()
        .nativeElement
        .focus();
    },
  });
}

14.2 Repeated measurement

afterEveryRender
constructor() {
  afterEveryRender({
    read: () => {
      this.height.set(
        this.host
          .nativeElement
          .getBoundingClientRect()
          .height,
      );
    },
  });
}

14.3 Pass phase results

write then read
constructor() {
  afterNextRender({
    write: () => {
      const element =
        this.panel()
          .nativeElement;

      element.style.padding =
        `${this.padding()}px`;

      return element;
    },

    read: element => {
      this.height.set(
        element
          .getBoundingClientRect()
          .height,
      );
    },
  });
}

14.4 Automatic cleanup through DestroyRef

By default, render callback registration is automatically cleaned up through the current DestroyRef. AfterRenderOptions can specify an injector or opt into manual cleanup.[17]

14.5 Reactive DOM effects

afterRenderEffect
constructor() {
  afterRenderEffect({
    write: () => {
      drawProgress(
        this.canvas()
          .nativeElement,
        this.progress(),
      );
    },
  });
}

afterRenderEffect combines signal dependency tracking with post-render timing. Use it for signal-dependent DOM integration; use computed signals for state derivation and normal effects for non-DOM external systems.

17. Complete example: lifecycle-safe chart component

This example initializes input-derived configuration, reacts to input transitions, waits for the rendered canvas, updates a third-party chart, responds to container size, and releases every resource through DestroyRef.

  readonly x: number;
  readonly y: number;

  readonly animated: boolean;

chart factory
export function createChart(
  canvas:
    HTMLCanvasElement,
  options:
    ChartOptions,
): ChartAdapter {
  const instance =
    thirdPartyChartLibrary
      .create(
        canvas,
        options,
      );

  return {
    setData(points) {
      instance.setData(
        points,
      );

data-chart.component.ts
@Component({
  selector: 'app-data-chart',
  standalone: true,
  template: `
    <figure>
      <canvas #canvas></canvas>

      <figcaption>
        {{ options().title }}
      </figcaption>
    </figure>
  `,
  styleUrl:
    './data-chart.component.css',
})
export class DataChartComponent
  implements
    OnChanges,
    OnInit {

  readonly data =
    input.required<
      readonly ChartPoint[]
    >();

  readonly options =
    input.required<
      ChartOptions
    >();

  readonly initialized =
    output<void>();

  private readonly destroyRef =
    inject(DestroyRef);

  private readonly canvas =
    viewChild.required<
      ElementRef<
        HTMLCanvasElement
      >
    >('canvas');

  private chart:
    ChartAdapter |
    null = null;

  private resizeObserver:
    ResizeObserver |
    null = null;

  ngOnInit(): void {
    this.validateOptions(
      this.options(),
    );
  }

  ngOnChanges(
    changes:
      SimpleChanges<
        DataChartComponent
      >,
  ): void {
    if (
      changes.options &&
      !changes.options
        .firstChange
    ) {
      this.recreateChart();
      return;
    }

    if (
      changes.data &&
      this.chart
    ) {
      this.chart.setData(
        this.data(),
      );
    }
  }

  constructor() {
    afterNextRender({
      write: () => {
        this.createChart();
        this.observeSize();
        this.initialized.emit();
      },
    });

    this.destroyRef.onDestroy(
      () => {
        this.resizeObserver
          ?.disconnect();

        this.chart
          ?.destroy();

        this.resizeObserver =
          null;

        this.chart =
          null;
      },
    );
  }

  private createChart(): void {
    this.chart =
      createChart(
        this.canvas()
          .nativeElement,
        this.options(),
      );

    this.chart.setData(
      this.data(),
    );
  }

  private recreateChart(): void {
    if (!this.chart) {
      return;
    }

    this.chart.destroy();
    this.createChart();
  }

  private observeSize(): void {
    const canvas =
      this.canvas()
        .nativeElement;

    this.resizeObserver =
      new ResizeObserver(
        entries => {
          const rect =
            entries[0]
              ?.contentRect;

          if (
            !rect ||
            !this.chart
          ) {
            return;
          }

          this.chart.resize(
            rect.width,
            rect.height,
          );
        },
      );

    this.resizeObserver
      .observe(canvas);
  }

  private validateOptions(
    options:
      ChartOptions,
  ): void {
    if (
      !options.title.trim()
    ) {
      throw new Error(
        'Chart title is required.',
      );
    }
  }
}

The constructor registers post-render setup and cleanup. ngOnInit validates initial input state. ngOnChanges handles meaningful transitions after initialization. The chart is created only when the browser DOM is rendered, and DestroyRef keeps teardown adjacent to resource ownership.

19. Production patterns and best practices

19.1 Use hooks only for timing-sensitive work

NeedPreferred mechanism
Simple default stateField initializer.
Derived synchronous stateComputed signal.
Initial action based on inputsngOnInit.
Compare previous and current input valuesngOnChanges.
Read projected-child query oncengAfterContentInit.
Read view-child query oncengAfterViewInit.
Manipulate or measure rendered DOMRender callback.
Release resourcesDestroyRef or ngOnDestroy.
Observable follows Angular lifetimetakeUntilDestroyed.

19.2 Keep hooks small

named lifecycle tasks
ngOnInit(): void {
  this.initializeDraft();
  this.loadReferenceData();
}

ngOnDestroy(): void {
  this.disposeEditor();
  this.stopBackgroundWork();
}

19.3 Keep setup and cleanup symmetrical

symmetrical resource ownership
const controller =
  new AbortController();

window.addEventListener(
  'pointermove',
  this.onPointerMove,
  {
    signal:
      controller.signal,
  },
);

inject(DestroyRef)
  .onDestroy(() => {
    controller.abort();
  });

19.4 Prefer reactive query APIs for ongoing changes

If children can appear and disappear under control flow, a signal query plus computed/effect logic is often clearer than repeatedly handling QueryList.changes or checked hooks.

19.5 Avoid parent-child writes during checks

Inputs should flow downward and outputs/events upward. Direct writes through queried child or parent references make hook order significant and are prone to expression-changed errors.[18][28]

19.6 Cleanup belongs to the owner

The code that creates a timer, observer, subscription, worker, or third-party instance should also define or register its cleanup. Passing DestroyRef into helpers preserves this ownership across abstraction boundaries.

23. Conclusion

Angular lifecycle hooks are precise timing contracts. ngOnChanges observes input transitions; ngOnInit performs one-time input-dependent setup; ngDoCheck is a high-cost escape hatch for custom checking; content and view initialization hooks expose their corresponding query boundaries; and ngOnDestroy provides final teardown.[1][3][4][6][7][8][11]

Modern Angular reduces the need for many traditional hooks. Computed signals replace copied derived state, signal queries react to changing children, render callbacks provide a safer DOM boundary, DestroyRef colocates resource ownership and cleanup, and takeUntilDestroyed binds Observable lifetime to Angular destruction. Use hooks when the timing itself is the requirement, keep them small, and make every acquired resource’s cleanup explicit.
