Angular Pipes

An Angular pipe is a named template transformation. The value to the left of the pipe operator becomes the first argument to a pipe class’s transform() method; colon-separated parameters become later arguments; the returned value participates in the surrounding binding. Pipes should normally be deterministic display transformations with no externally visible side effects.

1. The pipe model

Angular pipes transform values declaratively inside template expressions. A pipe class is marked with @Pipe, implements PipeTransform, and exposes a transform() method. Angular passes the expression value as the first argument and any pipe parameters as subsequent arguments.[1][2][3]

The expression immediately left of | becomes the first transform argument.

Parameters

Colon-separated expressions configure the transformation and are evaluated as normal template expressions.[1]

Result

The pipe result can be interpolated, bound to a property, passed to another pipe, or used in a larger expression.

Pipes are presentation adapters Keep domain state in the component, service, or store. Use a pipe to derive a display value without mutating its input or hiding business operations.

2. Historical development

AngularJS filters

AngularJS called template transformations “filters” and used the same vertical-bar syntax. Filters could be chained, parameterized, injected into controllers and services, and marked $stateful when their output depended on hidden state. AngularJS strongly discouraged stateful filters because they ran during each digest and reduced optimization opportunities.[23][24]

Angular 2 introduces pipes

The rewritten Angular framework renamed filters to pipes and formalized them as decorated classes with a transform() method. The early guide established the modern pure-versus-impure model and reference-change behavior.[25]

Standalone pipes

Standalone components, directives, and pipes removed the requirement that every template dependency be declared through an NgModule. A standalone component can import the exact pipe classes its template uses.[2][26]

Modern template and zoneless integration

Pipes remain compiled template dependencies. AsyncPipe also acts as a scheduling bridge by marking its view when an Observable or Promise produces a new value, which is important in OnPush and zoneless applications.[5]

Current guidance outside templates

Angular’s current pipes guide recommends sharing a plain formatting function between a pipe and other TypeScript code rather than injecting a custom pipe into services. For locale-aware built-ins, it recommends standalone functions such as formatDate, formatCurrency, formatNumber, and formatPercent.[1][18][19][20][21]

3. Syntax, parameters, chaining, and precedence

3.1 Basic syntax

one pipe
{{ value | pipeName }}

3.2 Parameters

parameterized pipe
{{ amount
  | currency:
      currencyCode:
      'symbol':
      '1.2-2':
      locale
}}

Every parameter after the pipe name is separated by a colon and becomes another argument to transform(). Parameters may be literals, fields, signal reads, or other valid template expressions.[1][3]

3.3 Chaining

pipe chaining
{{ purchasedOn
  | date:'fullDate'
  | uppercase
}}

Angular evaluates a chain from left to right: the output of one pipe becomes the input of the next.[1][23]

3.4 Operator precedence

clear precedence
<!-- Addition happens before the pipe. -->
{{ firstName + ' ' + lastName
  | titlecase
}}

<!-- Parenthesize ternaries. -->
{{ (
    authorized
      ? 'access granted'
      : 'access denied'
  ) | uppercase
}}

The pipe operator has lower precedence than arithmetic, logical, and nullish-coalescing operators, but higher precedence than the conditional operator. Parentheses prevent ambiguous ternary expressions.[1]

3.5 Import dependencies explicitly

standalone template imports
@Component({
  selector: 'app-summary',
  standalone: true,
  imports: [
    CurrencyPipe,
    DatePipe,
    PercentPipe,
  ],
  templateUrl:
    './summary.component.html',
})
export class SummaryComponent {}

Built-in pipes are exported from @angular/common. A standalone component can import individual pipe classes; NgModule-based components can receive them through CommonModule or another exporting module.[1][27]

5. AsyncPipe

AsyncPipe subscribes to an Observable or Promise, returns the latest emitted or resolved value, marks its component for checking when a new value arrives, replaces its subscription when the bound reference changes, and unsubscribes when the component is destroyed.[5]

5.1 Observable rendering

Observable with AsyncPipe
import {
  AsyncPipe,
} from '@angular/common';
import {
  Component,
} from '@angular/core';
import {
  interval,
} from 'rxjs';

@Component({
  selector: 'app-clock',
  standalone: true,
  imports: [AsyncPipe],
  template: `
    <p>Tick: {{ tick$ | async }}</p>
  `,
})
export class ClockComponent {
  readonly tick$ =
    interval(1_000);
}

5.2 Promise rendering

Promise with AsyncPipe
@Component({
  selector: 'app-version',
  standalone: true,
  imports: [AsyncPipe],
  template: `
    <p>
      Version:
      {{ versionPromise | async }}
    </p>
  `,
})
export class VersionComponent {
  readonly versionPromise =
    Promise.resolve('22.1');
}

5.3 Bind once and narrow the value

AsyncPipe with @if
@if (user$ | async; as user) {
  <app-user-card [user]="user" />
} @else {
  <app-user-skeleton />
}

5.4 Explicit loading and error state

state stream
type LoadState<T> =
  | { readonly status: 'loading' }
  | {
      readonly status: 'ready';
      readonly value: T;
    }
  | {
      readonly status: 'error';
      readonly message: string;
    };

readonly state$ = this.api.load().pipe(
  map(value => ({
    status: 'ready',
    value,
  } satisfies LoadState<Data>)),

  startWith({
    status: 'loading',
  } satisfies LoadState<Data>),

  catchError(error =>
    of({
      status: 'error',
      message: toMessage(error),
    } satisfies LoadState<Data>),
  ),
);
render state with one subscription
@if (state$ | async; as state) {
  @switch (state.status) {
    @case ('loading') {
      <p>Loading…</p>
    }

    @case ('ready') {
      <app-data-view
        [value]="state.value" />
    }

    @case ('error') {
      <p role="alert">
        {{ state.message }}
      </p>
    }
  }
}

5.5 Keep the Observable reference stable

stable property
// Preferred:
readonly product$ =
  this.api.getProduct(
    this.productId,
  );
unstable source anti-pattern
<!-- Avoid constructing a new cold stream
     during template evaluation. -->
<p>
  {{ loadProduct() | async }}
</p>

Because AsyncPipe switches subscriptions when its input reference changes, repeatedly constructing a cold Observable in a template can restart work such as an HTTP request.[5]

5.6 Why AsyncPipe is impure

The current display value can change even when the Observable object reference remains identical. AsyncPipe must therefore participate in repeated checks and update its cached latest value as asynchronous notifications arrive.[5]

6. CurrencyPipe

CurrencyPipe formats numeric input according to locale rules and currency metadata. Its template signature is currency:currencyCode:display:digitsInfo:locale.[6]

6.1 Common forms

currency variants
<p>
  {{ total
    | currency
  }}
</p>

<p>
  {{ total
    | currency:'EUR'
  }}
</p>

<p>
  {{ total
    | currency:'JPY':'code'
  }}
</p>

<p>
  {{ total
    | currency:'USD':'symbol':'1.2-2'
  }}
</p>

6.2 Display parameter

ValueMeaning
'symbol'Currency symbol, such as $.
'symbol-narrow'Narrow symbol where the locale provides one.
'code'ISO currency code, such as USD.
Custom stringUses that string as the currency marker.

6.3 Digits information

whole-dollar output
{{ amount
  | currency:
      'USD':
      'symbol':
      '1.0-0'
}}

digitsInfo uses {minIntegerDigits}.{minFractionDigits}-{maxFractionDigits}. When omitted, CurrencyPipe uses the currency’s standard minor-unit information where available.[6][18]

6.4 Default currency code

configure the default currency
import {
  ApplicationConfig,
  DEFAULT_CURRENCY_CODE,
} from '@angular/core';

export const appConfig:
  ApplicationConfig = {
  providers: [
    {
      provide:
        DEFAULT_CURRENCY_CODE,
      useValue: 'EUR',
    },
  ],
};

DEFAULT_CURRENCY_CODE controls CurrencyPipe when no explicit code is supplied. Angular documents USD as the default when the token is not configured; this token is independent of LOCALE_ID.[16]

6.5 No exchange-rate conversion

Formatting is not conversion Changing the CurrencyPipe code changes the label, symbol, fraction digits, and locale formatting. It does not retrieve exchange rates or mathematically convert the amount. Convert monetary values in domain/application logic using a defined rate and timestamp, then format the result.

6.6 Use a function outside templates

formatCurrency in TypeScript
import {
  formatCurrency,
} from '@angular/common';
import {
  LOCALE_ID,
  inject,
} from '@angular/core';

export class InvoiceFormatter {
  private readonly locale =
    inject(LOCALE_ID);

  formatTotal(
    value: number,
  ): string {
    return formatCurrency(
      value,
      this.locale,
      '$',
      'USD',
      '1.2-2',
    );
  }
}

Angular recommends the standalone formatting function rather than injecting CurrencyPipe into non-template code.[1][18]

7. DatePipe

DatePipe accepts a Date, milliseconds since the UTC epoch, or a date-time string, and formats it using a named or custom format, timezone, and locale. Its template signature is date:format:timezone:locale.[7][19]

7.1 Named formats

predefined date formats
<p>
  {{ createdAt | date }}
</p>

<p>
  {{ createdAt
    | date:'short'
  }}
</p>

<p>
  {{ createdAt
    | date:'mediumDate'
  }}
</p>

<p>
  {{ createdAt
    | date:'fullDate'
  }}
</p>

<p>
  {{ createdAt
    | date:'shortTime'
  }}
</p>

Predefined formats include short, medium, long and full date-time forms, plus date-only and time-only variants. The exact output depends on locale rules.[7]

7.2 Custom format fields

custom date pattern
{{ createdAt
  | date:
      'yyyy-MM-dd HH:mm:ss'
}}

7.3 Timezone override

UTC formatting
{{ createdAt
  | date:
      'medium':
      'UTC'
}}

Without an explicit timezone or configured default, DatePipe uses the end user’s local system timezone.[7][17]

7.4 Configure defaults

application-wide DatePipe defaults
import {
  DATE_PIPE_DEFAULT_OPTIONS,
} from '@angular/common';

export const appConfig = {
  providers: [
    {
      provide:
        DATE_PIPE_DEFAULT_OPTIONS,
      useValue: {
        dateFormat:
          'mediumDate',
        timezone:
          'UTC',
      },
    },
  ],
};

DATE_PIPE_DEFAULT_OPTIONS configures default date format and timezone. A parameter passed directly to the pipe takes precedence. The older DATE_PIPE_DEFAULT_TIMEZONE token is deprecated in favor of this options token.[17][30]

7.5 Date mutation and pure execution

replace the Date reference
readonly timestamp =
  signal(
    new Date(),
  );

advanceOneMinute(): void {
  this.timestamp.update(current =>
    new Date(
      current.getTime() +
      60_000,
    ),
  );
}

DatePipe is pure. Mutating one Date object does not create a pure input change; create a new Date reference when the displayed value should be reformatted.[7]

formatDate

8. PercentPipe

PercentPipe multiplies the input by 100 for display and applies locale-sensitive grouping, decimal, spacing, and percent-sign rules. Its signature is percent:digitsInfo:locale.[8]

percentage formatting
@Component({
  selector: 'app-metrics',
  standalone: true,
  imports: [PercentPipe],
  template: `
    <p>
      Conversion:
      {{ conversionRate
        | percent
      }}
    </p>

    <p>
      Precise:
      {{ conversionRate
        | percent:'1.2-2'
      }}
    </p>

    <p>

            '1.1-1':

9. SlicePipe

SlicePipe creates a subset of an Array or String using JavaScript-style start and optional end indices. The returned Array is a new array even when the requested range contains the entire input. The built-in pipe is marked impure.[9]

9.1 Array slicing

first page of an array
@for (
  product of products
    | slice:0:pageSize;
  track product.id
) {
  <app-product-row
    [product]="product" />
}

9.2 String slicing

string excerpt
<p>
  {{ description
    | slice:0:120
  }}…
</p>

9.3 Negative indices

negative start
<!-- Last three characters. -->
{{ trackingCode | slice:-3 }}

9.4 Avoid using SlicePipe as full pagination

SlicePipe can render a small client-side window, but server pagination, virtual scrolling, filtering, stable identity, and total-count state belong in the data/UI architecture rather than a pipe. Because SlicePipe is impure and produces arrays repeatedly, large collections can create avoidable allocation and rendering work.[9]

computed pagination window
readonly visibleProducts =
  computed(() => {
    const start =
      this.page() *
      this.pageSize();

    return this.products().slice(
      start,
      start +
        this.pageSize(),
    );
  });

A computed signal can cache a slice until page, page size, or products changes, making ownership and update conditions explicit.

10. JsonPipe

JsonPipe converts a value to JSON text and is intended for debugging. It is an impure built-in pipe.[10]

debug rendering
@Component({
  selector: 'app-debug-panel',
  standalone: true,
  imports: [JsonPipe],
  template: `
    <details>
      <summary>
        Debug state
      </summary>

      <pre>{{ state() | json }}</pre>
    </details>
  `,
})
export class DebugPanelComponent {
  readonly state =
    input.required<unknown>();
}

10.1 Appropriate uses

  • Temporary inspection of component state during development.
  • Educational examples that need to display a plain object.
  • Internal diagnostic panels with controlled data.

10.2 Limitations

  • JSON serialization omits or transforms values that JSON cannot represent directly.
  • Circular references cause serialization failure.
  • The output is not a secure redaction mechanism.
  • The impure pipe runs frequently and should not serialize large graphs in production views.
Do not expose secrets Never render authentication tokens, personal information, server responses, or internal configuration merely because JsonPipe makes inspection convenient. Remove development debug panels from production or strictly constrain their data.

11.5 Locale and currency are different dimensions

The locale controls punctuation, grouping, symbol placement, names, and date conventions. The currency code identifies the monetary unit. A French locale can format USD, and a US locale can format EUR.

12. Custom pipes

12.1 Minimal custom pipe

initials.pipe.ts
import {
  Pipe,
  PipeTransform,
} from '@angular/core';

@Pipe({
  name: 'initials',
  standalone: true,
})
export class InitialsPipe
  implements PipeTransform {

  transform(
    value:
      string |
      null |
      undefined,
  ): string {
    if (!value) {
      return '';
    }

    return value
      .trim()
      .split(/\s+/)
      .map(part => part[0])
      .join('')
      .toUpperCase();
  }
}
use the custom pipe
@Component({
  selector: 'app-person',
  standalone: true,
  imports: [InitialsPipe],
  template: `
    <span class="avatar">
      {{ name() | initials }}
    </span>
  `,
})
export class PersonComponent {
  readonly name =
    input.required<string>();
}

The decorator name is the template identifier. Pipe names typically use lower camel case and cannot contain hyphens. PipeTransform defines the transform method contract.[2][3]

12.2 Parameterized custom pipe

truncate.pipe.ts
@Pipe({
  name: 'truncate',
  standalone: true,
})
export class TruncatePipe
  implements PipeTransform {

  transform(
    value:
      string |
      null |
      undefined,
    maximum = 80,
    suffix = '…',
  ): string {
    if (!value) {
      return '';
    }

    if (
      value.length <= maximum
    ) {
      return value;
    }

    const retained =
      Math.max(
        0,
        maximum -
          suffix.length,
      );

    return (
      value.slice(
        0,
        retained,
      ) +
      suffix
    );
  }
}
custom parameters
<p>
  {{ article.summary
    | truncate:120:'...'
  }}
</p>

12.3 Generic collection pipe

typed generic pipe
@Pipe({
  name: 'pluck',
  standalone: true,
})
export class PluckPipe
  implements PipeTransform {

  transform<
    T extends object,
    K extends keyof T,
  >(
    values:
      readonly T[] |
      null |
      undefined,
    key: K,
  ): T[K][] {
    return values
      ?.map(
        value =>
          value[key],
      ) ??
      [];
  }
}

12.4 Share a pure formatting function

kebab-case.ts
export function toKebabCase(
  value: string,
): string {
  return value
    .trim()
    .replace(
      /([a-z0-9])([A-Z])/g,
      '$1-$2',
    )
    .replace(
      /[^a-zA-Z0-9]+/g,
      '-',
    )
    .replace(
      /^-+|-+$/g,
      '',
    )
    .toLowerCase();
}
pipe adapter
@Pipe({
  name: 'kebabCase',
  standalone: true,
})
export class KebabCasePipe
  implements PipeTransform {

  transform(
    value: string,
  ): string {
    return toKebabCase(
      value,
    );
  }
}
reuse the function outside templates
export class SlugService {
  createSlug(
    title: string,
  ): string {

      title,
    );
  }
}

Angular recommends extracting reusable transformation logic rather than injecting a pipe class into services or unrelated classes.[1]

12.5 Null behavior is part of the contract

Define whether nullish inputs return an empty string, null, a placeholder, or an error. Match built-in style when practical and encode the behavior in overloads or explicit types.

13. Pure versus impure pipes

Pipes are pure by default. Angular calls a pure pipe when a primitive input changes or an object, array, function, or Date reference changes. It does not call the pipe merely because an internal property or array element was mutated.[1][2][25]

13.1 Pure pipe execution

pure collection pipe
@Pipe({
  name: 'completedTasks',
  standalone: true,
})
export class CompletedTasksPipe
  implements PipeTransform {

  transform(
    tasks:
      readonly Task[],
  ): Task[] {
    return tasks.filter(
      task =>
        task.completed,
    );
  }
}
trigger a pure change
// Preferred reference replacement:
this.tasks.update(tasks =>
  tasks.map(task =>
    task.id === id
      ? {
          ...task,
          completed: true,
        }
      : task,
  ),
);
mutation anti-pattern
// In-place mutation can leave a pure pipe cached:
this.tasks()[0].completed = true;

13.2 Impure pipe declaration

impure pipe
@Pipe({
  name: 'completedTasksImpure',
  standalone: true,
  pure: false,
})
export class CompletedTasksImpurePipe
  implements PipeTransform {

  transform(
    tasks:
      readonly Task[],
  ): Task[] {
    return tasks.filter(
      task =>
        task.completed,
    );
  }
}

An impure pipe is invoked during each relevant change-detection cycle even when its argument references are unchanged. Angular warns that impure pipes can create significant performance cost and recommends avoiding them unless necessary.[1][2]

13.3 Why built-ins can be impure

  • AsyncPipe’s result changes as its asynchronous source emits even though the source reference remains the same.[5]
  • JsonPipe is a debugging view of potentially mutated object state and is marked impure.[10]
  • SlicePipe is marked impure and returns fresh Array slices.[9]
  • KeyValuePipe tracks Object/Map entry changes and is marked impure.[12]

13.4 Better alternatives to an impure custom pipe

NeedAlternative
Filter or sort signal stateComputed signal.
Transform Observable valuesRxJS map and AsyncPipe.
React to mutable external objectNormalize it into immutable application state.
Format value outside templatePure function or built-in formatting function.
Run side effectsService command, effect, or event handler—not a pipe.

13.5 Instance and caching implications

Pure pipes are safe to cache because output is expected to depend only on explicit arguments. Impure pipes may depend on hidden state or mutated internals, so Angular cannot use the same reference-change optimization. That flexibility should be paid for only when the semantics require it.

14. Formatting outside templates

A pipe is primarily a template artifact. When non-template code needs the same behavior, use a shared pure function or Angular’s standalone formatting functions instead of injecting the pipe class.[1]

14.1 Locale-aware invoice formatter

standalone formatting functions
import {
  formatCurrency,
  formatDate,
  formatPercent,
} from '@angular/common';
import {
  LOCALE_ID,
  inject,
} from '@angular/core';

export class InvoiceTextFormatter {
  private readonly locale =
    inject(LOCALE_ID);

  currency(
    value: number,
    code = 'USD',
  ): string {
    const symbol =
      code === 'USD'
        ? '$'
        : code;

    return formatCurrency(
      value,
      this.locale,
      symbol,
      code,
      '1.2-2',
    );
  }

  date(
    value:
      string |
      number |
      Date,
  ): string {
    return formatDate(
      value,
      'mediumDate',
      this.locale,
      'UTC',
    );
  }

  percent(
    value: number,
  ): string {
    return formatPercent(
      value,
      this.locale,
      '1.1-1',
    );
  }
}

14.2 Keep domain values unformatted

domain representation
interface Invoice {
  readonly amountCents: number;
  readonly issuedAt:
    string;
  readonly taxRate:
    number;
}

Store money, timestamps, and ratios in machine-appropriate forms. Apply locale-specific strings only at presentation/export boundaries so sorting, calculations, validation, and API communication remain correct.

  private readonly api =
    inject(InvoiceApi);

  readonly debug = signal(false);

  readonly invoice$ =
    this.api.get('inv-1001');

  protected subtotalCents(
    invoice: Invoice,
  ): number {
    return invoice.lines.reduce(
      (sum, line) =>
        sum +
        line.quantity *
          line.unitPriceCents,
      0,
    );
  }

  protected taxCents(
    invoice: Invoice,
  ): number {
    return Math.round(
      this.subtotalCents(invoice) *
      invoice.taxRate,
    );
  }

  protected totalCents(
    invoice: Invoice,
  ): number {
    return (
      this.subtotalCents(invoice) +
      this.taxCents(invoice)
    );
  }

17. Performance and architecture

17.1 Prefer pure transformations

Pure pipes let Angular skip transform() when all argument values and references are unchanged. This reference-based contract is substantially cheaper than deep inspection.[1][2][25]

17.2 Make expensive inputs stable

derive before formatting
readonly chartRows =
  computed(() =>
    buildChartRows(
      this.records(),
      this.filters(),
    ),
  );

Do not pass a newly allocated object or array into a costly pure pipe on every check; the new reference invalidates the cache even if its contents are equivalent.

17.3 Do not hide network or storage work in a pipe

A pipe can run more often than expected, may be instantiated in multiple views, and has no suitable command/error/loading contract for I/O. Fetch and cache data in a service or store, then pipe the resulting display value.

17.4 Avoid methods whose only job is formatting templates

template formatting method
// Avoid repeated template method work:
formatPrice(value: number): string {
  return expensiveFormat(value);
}
cacheable pure pipe boundary
@Pipe({
  name: 'domainPrice',
  standalone: true,
})
export class DomainPricePipe
  implements PipeTransform {

  transform(
    value: number,
  ): string {
    return expensiveFormat(
      value,
    );
  }
}

A pure pipe can provide clearer template intent and reference-based caching. A computed signal is often better when the derivation belongs specifically to one component’s reactive state.

17.5 Keep impure work bounded

If an impure pipe is unavoidable, make transform() extremely small, avoid allocation where possible, limit the number of instances/usages, and profile the relevant interaction.

17.6 Pipes are not sanitizers

A formatting pipe does not make untrusted HTML, URLs, style values, or resource URLs safe. Bind untrusted content through Angular’s normal security contexts and never create a “safe HTML” pipe that broadly bypasses sanitization.

18. Common pitfalls

PitfallConsequenceBetter approach
Mutating an Array used by a pure pipeThe pipe may not run because the reference is unchangedReplace the collection reference.[1][25]
Using CurrencyPipe as an exchange-rate converterThe numeric amount is mislabeled, not convertedConvert in domain logic, then format.
Mutating a Date objectDatePipe keeps the cached resultCreate a new Date reference.[7]
Creating an Observable in a template methodAsyncPipe can resubscribe and restart cold workExpose a stable Observable property.[5]
Using JsonPipe on large or sensitive objectsPerformance cost and information exposureUse constrained development diagnostics.[10]
Making a pipe impure to fix state designTransform runs during every relevant checkImmutable state, computed signals, or RxJS mapping.[1][2]
Injecting custom pipes into servicesPresentation artifact leaks into application logicExtract a shared function.[1]
Depending on machine timezone in testsNondeterministic date assertionsProvide a timezone or configure defaults.[7][17]
Forgetting locale dataRequested locale formatting may be unavailableRegister/import locale data or use localized CLI builds.[15][32]
Ambiguous ternary with a pipeOnly one branch may be transformedParenthesize the conditional expression.[1]
Using SlicePipe for large-list paginationRepeated allocation and excessive client renderingComputed pagination, virtual scrolling, or server paging.[9]

19. Decision guide

RequirementRecommended tool
Format display-only template valuePure pipe.
Render Observable or PromiseAsyncPipe.
Format currencyCurrencyPipe in template; formatCurrency in TypeScript.
Format date/timeDatePipe; set explicit timezone where determinism matters.
Format a ratio as percentagePercentPipe.
Small String/Array excerptSlicePipe.
Temporary object inspectionJsonPipe in controlled development UI.
Reusable app-specific formattingCustom pure pipe wrapping a shared function.
Derived component stateComputed signal.
Temporal stream transformationRxJS operator.
Network/storage operationService or store, never a pipe.
Detect internal mutationPrefer immutable state; impure pipe only as a last resort.

21. Conclusion

Angular pipes provide concise, compiled, declarative transformations for templates. Built-in pipes cover asynchronous values, locale-sensitive dates and numbers, string transformations, slices, iteration adapters, pluralization, and diagnostics. Custom pipes package application-specific formatting behind typed transform() contracts.[1][2][3][4]

The central architectural distinction is purity. Pure pipes reward immutable values and stable references with skipped work; impure pipes observe changing state at a substantially higher execution cost. Keep domain data unformatted, use AsyncPipe for lifecycle-safe asynchronous rendering, use locale-aware built-ins at presentation boundaries, share plain functions outside templates, and reserve impure pipes for the rare case whose semantics truly require them.
