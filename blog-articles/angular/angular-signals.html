Angular Signals

Angular signals are synchronous reactive values with dependency tracking. A signal exposes its current value through a getter function; reactive consumers record signal reads; writes invalidate dependent computations and views. Use writable signals for owned state, computed signals for derivation, linked signals for writable dependent state, resources or RxJS for asynchronous work, and effects only to synchronize with non-reactive systems.

1. The signal mental model

Angular defines a signal as a wrapper around a value that notifies interested consumers when the value changes. Reading a signal means calling its getter function, which allows Angular to record the dependency. Signals can contain primitive values, objects, collections, and application-specific types, and they may be writable or read-only.[1][2]

Producer

A signal whose value can be read. Writable signals additionally expose mutation APIs.[2][3]

Consumer

A template, computed signal, linked signal, resource computation, effect, or render effect that reads signals in a reactive context.[1][4]

Dependency edge

A live relationship created when a consumer reads a producer. Angular recalculates dependencies dynamically on each execution.[1]

minimal signal graph
import { computed, signal } from '@angular/core';

const quantity = signal(2);
const unitPriceCents = signal(1_299);

const totalCents = computed(
  () => quantity() * unitPriceCents(),
);

console.log(totalCents()); // 2598

quantity.set(3);

console.log(totalCents()); // 3897

Computed signals are lazily evaluated and memoized. The relationship is declared once rather than maintained through assignments.[1][5]

Signals expose current state, not event historyReading a signal returns one value. Signals do not have completion, error, cancellation, buffering, or temporal operator semantics. RxJS remains the stronger abstraction for multi-event asynchronous workflows.[6]

2. Historical development

Angular before signals

Angular traditionally synchronized component views through change detection and commonly used RxJS Observables for asynchronous values and service state. Plain component fields did not form an explicit dependency graph.

Angular 16: developer preview

Angular introduced signal-based reactivity in version 16 as a developer preview and presented it as a foundation for explicit state dependencies and more targeted rendering decisions.[7]

Angular 17: core primitives stabilize

The public API records WritableSignal, isSignal, and related core primitives as stable from Angular 17.[3][8]

Angular 19: component contracts

InputSignal, model(), and output/RxJS interoperability helpers are stable from Angular 19.[9][10][11][12]

Angular 20: linked state and effects

linkedSignal and the current effect API are stable from Angular 20, providing a first-class alternative to copying dependent state through effects.[13][14]

Angular 22: stable resources

Angular 22, released on 3 June 2026, marks the Resource API stable for asynchronous dependencies represented through signal state.[15][16][17]

Signals and Observables remain complementary: synchronous current state versus asynchronous sequences, cancellation, concurrency, errors, completion, and time-based composition.[6]

3. Writable signals

signal(initialValue) returns a WritableSignal<T>, which is callable for reading and exposes set, update, and asReadonly.[2][3]

3.1 Set and update

direct and relative updates
import { signal } from '@angular/core';

const count = signal(0);

count.set(5);
count.update(current => current + 1);

console.log(count()); // 6

Use set for a known replacement and update when the next value depends on the current value.[3]

3.2 Immutable collection updates

immutable state transitions
interface Todo {
  readonly id: string;
  readonly title: string;
  readonly completed: boolean;
}

const todos = signal<readonly Todo[]>([]);

function addTodo(todo: Todo): void {
  todos.update(current => [...current, todo]);
}

function toggleTodo(id: string): void {
  todos.update(current =>
    current.map(todo =>
      todo.id === id
        ? { ...todo, completed: !todo.completed }
        : todo,
    ),
  );
}

Signals use Object.is by default. In-place mutation preserves the reference and can bypass the intended notification boundary. Prefer replacement updates for state objects and collections.[1]

3.3 Private writable, public read-only

encapsulated writable state
import { Signal, signal } from '@angular/core';

class CounterStore {
  private readonly _count = signal(0);

  readonly count: Signal<number> =
    this._count.asReadonly();

  increment(): void {
    this._count.update(value => value + 1);
  }
}

asReadonly() removes the public setter interface but does not deep-freeze object values.[3]

3.4 Custom equality

semantic equality
interface Coordinates {
  readonly x: number;
  readonly y: number;
}

const cursor = signal<Coordinates>(
  { x: 0, y: 0 },
  {
    equal: (a, b) =>
      a.x === b.x && a.y === b.y,
  },
);

cursor.set({ x: 0, y: 0 });
// No dependent invalidation.

Writable and computed signals may use a custom comparator. Deep comparison has a cost and can conceal mutation mistakes, so use it for a measured domain requirement rather than by default.[1][18]

3.5 Runtime type guards

isSignal and isWritableSignal
import {
  computed,
  isSignal,
  isWritableSignal,
  signal,
} from '@angular/core';

const count = signal(0);
const doubled = computed(() => count() * 2);

isSignal(count);              // true
isWritableSignal(count);      // true
isWritableSignal(doubled);    // false

The public type guards are most useful in adapters and reusable utilities.[8][19]

4. Computed signals

computed() creates a read-only Signal derived from other signals. Computations are lazy, memoized, and dynamically tracked.[1][5]

4.1 Derived selectors

computed view state
const products = signal<readonly Product[]>([]);
const query = signal('');

const visibleProducts = computed(() => {
  const normalized = query().trim().toLowerCase();

  if (!normalized) {
    return products();
  }

  return products().filter(product =>
    product.name.toLowerCase().includes(normalized),
  );
});

const resultCount = computed(
  () => visibleProducts().length,
);

The sources of truth are products and query; filtered results and count are consequences, not separately synchronized state.

4.2 Dynamic dependencies

conditional dependency tracking
const showDetails = signal(false);
const details = signal('Sensitive details');

const panelText = computed(() => {
  if (!showDetails()) {
    return 'Details hidden';
  }

  return details();
});

When the false branch executes, details is not read and is not a dependency. Angular recalculates the dependency set after each execution.[1]

4.3 Lazy memoization

lazy computed work
const searchIndex = computed(() => {
  console.log('building index');
  return buildSearchIndex(products());
});

// No work until first read.
const index = searchIndex();

// Cached until products changes.
const sameIndex = searchIndex();

The derivation runs on first read and the cached result remains valid until a dependency changes.[1]

4.4 Computed equality

computed equality
const selectedIds = computed(
  () => selection().map(item => item.id).sort(),
  {
    equal: (a, b) =>
      a.length === b.length &&
      a.every((id, index) => id === b[index]),
  },
);

4.5 Read-only by design

derived value
const subtotal = computed(() =>
  lines().reduce(
    (sum, line) =>
      sum + line.unitPriceCents * line.quantity,
    0,
  ),
);

// subtotal.set(5000); // No setter.

Use linkedSignal when a value is both dependent and legitimately writable, rather than copying a computed value into another signal.[20]

5. Dependency tracking and incidental reads

Angular tracks signal reads while evaluating computed and linked signals, resource computations, effects, render effects, component templates, and host bindings.[1]

5.1 Exclude incidental reads

untracked read
import { effect, signal, untracked } from '@angular/core';

const currentUser = signal('Ada');
const counter = signal(0);

effect(() => {
  const user = currentUser();
  const incidentalCount = untracked(() => counter());

  console.log(`${user}: ${incidentalCount}`);
});

The effect reruns for currentUser, but a counter-only change does not invalidate it. untracked executes its callback without adding dependencies to the surrounding reactive context.[21]

5.2 Isolate service implementation reads

prevent incidental service dependencies
effect(() => {
  const state = viewState();

  untracked(() => {
    analytics.recordViewState(
      state,
      analytics.sessionContext(),
    );
  });
});

5.3 Debug names

reactive debug names
const query = signal('', {
  debugName: 'catalog.query',
});

const normalizedQuery = computed(
  () => query().trim().toLowerCase(),
  {
    debugName: 'catalog.normalizedQuery',
  },
);

Debug names support tooling and diagnostics without changing semantics.[2][5]

6. Effects

An effect executes side-effecting code whenever its tracked dependencies change. It runs at least once, tracks dependencies dynamically, and normally requires an Angular injection context unless an injector is supplied explicitly.[4][14]

Effects are a boundary toolAngular recommends preferring computed for derived values and linkedSignal for writable dependent state. Copying data between signals in an effect usually indicates misplaced ownership.[4]

6.1 Appropriate use: browser storage

external synchronization
@Component({
  selector: 'app-theme-picker',
  standalone: true,
  template: `...`,
})
export class ThemePickerComponent {
  readonly theme =
    signal<'light' | 'dark'>('light');

  constructor() {
    effect(() => {
      localStorage.setItem('theme', this.theme());
    });
  }
}

Logging, analytics, storage, canvas, charting libraries, and other imperative systems are appropriate effect targets because they cannot consume Angular signals directly.[4]

6.2 Avoid propagation effects

computed instead of synchronization
const firstName = signal('Ada');
const lastName = signal('Lovelace');

// Avoid:
const copiedName = signal('');
effect(() => {
  copiedName.set(`${firstName()} ${lastName()}`);
});

// Prefer:
const fullName = computed(
  () => `${firstName()} ${lastName()}`,
);

6.3 Component and root effects

Component effects run as part of Angular component synchronization and can react to inputs or view state. Root effects run as microtasks outside the component tree. The creation context determines the default effect kind.[14]

root-service effect
@Injectable({ providedIn: 'root' })
export class AuditService {
  private readonly session = inject(SessionStore);

  constructor() {
    effect(() => {
      sendAuditHeartbeat(this.session.user());
    });
  }
}

6.4 Cleanup stale work

effect cleanup
effect(onCleanup => {
  const controller = new AbortController();
  const currentQuery = query();

  const timerId = setTimeout(() => {
    void fetch(
      `/api/suggest?q=${encodeURIComponent(currentQuery)}`,
      { signal: controller.signal },
    );
  }, 250);

  onCleanup(() => {
    clearTimeout(timerId);
    controller.abort();
  });
});

Cleanup runs before the next execution and when the effect is destroyed.[4][22]

6.5 Manual lifetime

EffectRef destruction
const ref = effect(
  () => console.log(currentState()),
  { manualCleanup: true },
);

// Later:
ref.destroy();

Effects normally follow their injection context. Manual cleanup requires explicit destruction.[14][22]

6.6 DOM work after rendering

afterRenderEffect
@Component({
  selector: 'app-progress-canvas',
  standalone: true,
  template: `<canvas #canvas></canvas>`,
})
export class ProgressCanvasComponent {
  readonly progress = input(0);

  readonly canvas =
    viewChild.required<ElementRef<HTMLCanvasElement>>(
      'canvas',
    );

  constructor() {
    afterRenderEffect({
      write: () => {
        drawProgress(
          this.canvas().nativeElement,
          this.progress(),
        );
      },
    });
  }
}

afterRenderEffect tracks signals but runs after Angular commits rendering. It supports ordered DOM phases, runs only in the browser, and is intended for DOM-dependent integrations rather than state derivation.[23][24]

7. Signal inputs

input() declares a compiler-recognized component or directive input exposed as an InputSignal. Angular updates it when parent bindings change; the receiver can read but not write it.[9][25][26]

7.1 Optional, defaulted, and required

signal input variants
@Component({
  selector: 'app-user-card',
  standalone: true,
  template: `
    <h2>{{ user().displayName }}</h2>
    <p>Compact: {{ compact() }}</p>
  `,
})
export class UserCardComponent {
  readonly user = input.required<UserSummary>();
  readonly compact = input(false);
  readonly subtitle = input<string>();
}

Required inputs exclude undefined; optional inputs without defaults include it; defaulted inputs infer their exposed type.[25][26]

8. Signal-era outputs and model signals

output() is not a SignalThe function belongs to Angular’s signal-era component model, but it returns an OutputEmitterRef, not a readable current-value signal. Outputs represent events; signals represent state.[28][29]

8.1 Typed output events

output event
export interface ProductSelected {
  readonly productId: string;
  readonly source: 'mouse' | 'keyboard';
}

@Component({
  selector: 'app-product-tile',
  standalone: true,
  template: `
    <button
      type="button"
      (click)="select('mouse')"
      (keydown.enter)="select('keyboard')">
      {{ name() }}
    </button>
  `,
})
export class ProductTileComponent {
  readonly productId = input.required<string>();
  readonly name = input.required<string>();
  readonly selected = output<ProductSelected>();

  select(source: ProductSelected['source']): void {
    this.selected.emit({
      productId: this.productId(),
      source,
    });
  }
}
listen for output
<app-product-tile
  [productId]="product.id"
  [name]="product.name"
  (selected)="openProduct($event)" />

Outputs are case-sensitive, do not bubble through the DOM, and support automatically cleaned-up programmatic subscriptions.[28][29]

8.2 Observable-backed output

outputFromObservable

9. Writable dependent state with linkedSignal

linkedSignal creates writable state initialized and reset by a reactive computation. It is appropriate when a user-editable value depends on another source and must remain valid as that source changes.[13][20]

basic linkedSignal
interface ShippingMethod {
  readonly id: string;
  readonly name: string;
}

const methods = signal<readonly ShippingMethod[]>([
  { id: 'ground', name: 'Ground' },
  { id: 'air', name: 'Air' },
]);

const selectedMethod = linkedSignal(
  () => methods()[0],
);

selectedMethod.set(methods()[1]);

methods.set([
  { id: 'pickup', name: 'Pickup' },
]);
// Selection resets to Pickup.

9.1 Preserve a valid previous value

previous-state-aware linkedSignal
const selectedMethod = linkedSignal({
  source: methods,

  computation: (currentMethods, previous) => {
    const previousId = previous?.value.id;

    return (
      currentMethods.find(
        method => method.id === previousId,
      ) ?? currentMethods[0]
    );
  },
});

The advanced form receives the new source and previous source/value pair, so it can preserve a choice when still valid.[20]

9.2 Prefer it to propagation effects

effect synchronization to avoid
// Avoid:
effect(() => {
  const available = methods();

  if (!available.includes(selectedMethod())) {
    selectedMethod.set(available[0]);
  }
});

linkedSignal expresses dependency and write behavior in one primitive and avoids effect timing and circularity concerns.[4][20]

10. Asynchronous state with resources

Core signals are synchronous. A Resource manages an asynchronous dependency and exposes value, status, error, isLoading, and snapshot as signals. Resource is stable in Angular 22.[15][16]

10.1 Reactive parameters and cancellation

resource loader
interface User {
  readonly id: string;
  readonly displayName: string;
}

const userId = signal<string | undefined>(undefined);

const userResource = resource({
  params: () => {
    const id = userId();
    return id ? { id } : undefined;
  },

  loader: async ({ params, abortSignal }): Promise<User> => {
    const response = await fetch(
      `/api/users/${encodeURIComponent(params.id)}`,
      { signal: abortSignal },
    );

    if (!response.ok) {
      throw new Error(`Request failed: ${response.status}`);
    }

    return response.json();
  },
});

The parameter computation is reactive. New parameters can abort obsolete work through the supplied AbortSignal. Returning undefined leaves the resource idle.[15]

10.2 Render resource state

resource status in a template
@switch (userResource.status()) {
  @case ('idle') {
    <p>Select a user.</p>
  }

  @case ('loading') {
    <p>Loading user…</p>
  }

  @case ('error') {
    <p role="alert">
      {{ userResource.error()?.message }}
    </p>
  }

  @case ('resolved')
  @case ('local') {
    @if (userResource.hasValue()) {
      <h2>{{ userResource.value().displayName }}</h2>
    }
  }
}

hasValue() narrows the type and prevents reading a throwing value in an error state.[15][16]

10.3 Local writes and reload

WritableResource operations
if (userResource.hasValue()) {
  userResource.update(user => ({
    ...user,
    displayName: 'Ada Byron',
  }));
}

userResource.reload();

Local writes move a writable resource into local state; reload requests another load.[31]

10.4 Read operations, not mutations

Angular documents resources as read-oriented. Automatic cancellation can be unsafe for writes that must complete, so mutations should use explicit command workflows.[15]

11. Signal-based state management

A service can own private writable signals, expose read-only signals and computed selectors, and provide commands that preserve invariants. Dependency-injection scope controls whether the state is application-wide, route-scoped, component-tree scoped, or instance-local.[32][33]

11.1 Minimal store

signal store service
import {
  Injectable,
  Signal,
  computed,
  signal,
} from '@angular/core';

interface CounterState {
  readonly count: number;
  readonly step: number;
}

@Injectable({ providedIn: 'root' })
export class CounterStore {
  private readonly _state = signal<CounterState>({
    count: 0,
    step: 1,
  });

  readonly state: Signal<CounterState> =
    this._state.asReadonly();

  readonly count = computed(() => this._state().count);
  readonly step = computed(() => this._state().step);
  readonly isZero = computed(() => this.count() === 0);

  increment(): void {
    this._state.update(state => ({
      ...state,
      count: state.count + state.step,
    }));
  }

  setStep(step: number): void {
    if (!Number.isInteger(step) || step <= 0) {
      throw new Error('Step must be a positive integer.');
    }

    this._state.update(state => ({ ...state, step }));
  }

  reset(): void {
    this._state.set({ count: 0, step: 1 });
  }
}

11.2 Store principles

  • Keep writable signals private.
  • Expose state through read-only signals.
  • Expose derived data through computed selectors.
  • Use named commands instead of arbitrary public setters.
  • Perform immutable transitions.
  • Represent loading and failure explicitly.
  • Scope the store according to state lifetime.

11.3 One state object or several?

Single state object

Best when fields change atomically, snapshots matter, or reset and serialization are common.

Focused signals

Best when values have independent ownership and update cadence.

focused source signals
class SearchStore {
  private readonly _query = signal('');
  private readonly _category = signal<string | null>(null);
  private readonly _products = signal<readonly Product[]>([]);

  readonly query = this._query.asReadonly();
  readonly category = this._category.asReadonly();

  readonly visibleProducts = computed(() =>
    filterProducts(
      this._products(),
      this._query(),
      this._category(),
    ),
  );
}

11.4 Feature-scoped store

component-tree store scope

11.5 Commands preserve invariants

domain command
setQuantity(productId: string, quantity: number): void {
  const normalized = Math.max(0, Math.floor(quantity));

  if (normalized === 0) {
    this.remove(productId);
    return;

12. RxJS interoperability

The @angular/core/rxjs-interop package converts between signals and Observables. Conversion should happen at architectural boundaries rather than repeatedly throughout a feature.[6]

12.1 Observable to Signal

toSignal
@Component({
  selector: 'app-clock',
  standalone: true,
  template: `<p>Tick: {{ tick() }}</p>`,
})
export class ClockComponent {
  readonly tick = toSignal(
    interval(1_000),
    { initialValue: 0 },
  );
}

toSignal subscribes immediately, retains the latest value, throws an Observable error when read, and normally unsubscribes with its injection context. Reuse the returned Signal instead of converting the same Observable repeatedly.[6][34]

12.2 Synchronous sources

requireSync
readonly state = toSignal(
  behaviorSubject,
  { requireSync: true },
);

requireSync enforces immediate emission, which is appropriate for BehaviorSubject-like sources and removes undefined from the result type.[6][34]

12.3 Signal to Observable

toObservable
readonly query = signal('');
readonly query$ = toObservable(this.query);

readonly results$ = this.query$.pipe(
  debounceTime(250),
  distinctUntilChanged(),
  switchMap(query => this.api.search(query)),
);

The adapter publishes stabilized signal values; several synchronous writes can coalesce into the final value.[6]

13. Templates, OnPush, and zoneless rendering

When a template reads a signal, Angular records the component as a consumer. Updating that signal marks the view for synchronization and is one of the core notifications used in zoneless applications.[1][27][35]

signal-driven OnPush component
@Component({
  selector: 'app-counter',
  standalone: true,
  changeDetection: ChangeDetectionStrategy.OnPush,
  template: `
    <p>Count: {{ count() }}</p>
    <p>Double: {{ double() }}</p>

    <button type="button" (click)="increment()">
      Increment
    </button>
  `,
})
export class CounterComponent {
  readonly count = signal(0);
  readonly double = computed(() => this.count() * 2);

  increment(): void {
    this.count.update(value => value + 1);
  }
}

14. Complete example: signal-based cart

The example combines feature-scoped state, private writable signals, computed selectors, signal inputs, output events, a model input, immutable commands, and a Resource-backed catalog.

cart.models.ts
export interface Product {

  readonly productId: string;
  readonly name: string;
  readonly unitPriceCents: number;
  readonly quantity: number;
}
cart.store.ts
@Injectable()
export class CartStore {
  private readonly _lines =
    signal<readonly CartLine[]>([]);

  readonly lines = this._lines.asReadonly();

  readonly itemCount = computed(() =>
    this._lines().reduce(
      (total, line) => total + line.quantity,
      0,
    ),
  );

  readonly subtotalCents = computed(() =>
    this._lines().reduce(
      (total, line) =>
        total + line.quantity * line.unitPriceCents,
      0,
    ),
  );

  readonly empty = computed(() => this._lines().length === 0);

  add(product: Product): void {
    this._lines.update(lines => {
      const existing = lines.find(
        line => line.productId === product.id,
      );

      if (!existing) {
        return [
          ...lines,
          {
            productId: product.id,
            name: product.name,
            unitPriceCents: product.priceCents,
            quantity: 1,
          },
        ];
      }

      return lines.map(line =>
        line.productId === product.id
          ? { ...line, quantity: line.quantity + 1 }
          : line,
      );
    });
  }

  setQuantity(productId: string, quantity: number): void {
    const normalized = Math.max(0, Math.floor(quantity));

    if (normalized === 0) {
      this.remove(productId);
      return;
    }

    this._lines.update(lines =>
      lines.map(line =>
        line.productId === productId
          ? { ...line, quantity: normalized }
          : line,
      ),
    );
  }

  remove(productId: string): void {
    this._lines.update(lines =>
      lines.filter(line => line.productId !== productId),
    );
  }

  clear(): void {
    this._lines.set([]);
  }
}

product-catalog.store.ts
@Injectable()
export class ProductCatalogStore {
  readonly category = signal<string | undefined>(undefined);

  readonly products = resource({
    params: () => ({
      category: this.category(),
    }),

    loader: async ({ params, abortSignal }) => {
      const url = new URL('/api/products', location.origin);

      if (params.category) {
        url.searchParams.set('category', params.category);
      }

      const response = await fetch(url, {
        signal: abortSignal,
      });

      if (!response.ok) {
        throw new Error('Product load failed.');
      }

      return response.json() as Promise<readonly Product[]>;
    },

    defaultValue: [],
  });
}

16. Migration from classic Angular and RxJS state

16.1 Plain field to signal

field migration
// Before:
count = 0;

increment(): void {
  this.count++;
}

// After:
readonly count = signal(0);

increment(): void {
  this.count.update(value => value + 1);
}

16.2 @Input to input()

signal input migration
// Before:
@Input({ required: true })
user!: User;

// After:
readonly user = input.required<User>();
readonly displayName = computed(
  () => this.user().displayName,
);

Angular provides input migration tooling, but setters, inheritance, transforms, and code that writes to inputs require review.[38]

16.3 @Output to output()

output migration
// Before:
@Output()
readonly saved = new EventEmitter<Item>();

// After:
readonly saved = output<Item>();

Angular provides a migration for common output declarations.[39]

16.4 BehaviorSubject to signal

current-state migration
// Before:
private readonly stateSubject =
  new BehaviorSubject<State>(initialState);

readonly state$ = this.stateSubject.asObservable();

// After:
private readonly _state = signal(initialState);
readonly state = this._state.asReadonly();

This conversion fits synchronous current-state semantics. Keep Observable state when completion, errors, scheduling, or stream operators are part of the contract.

16.5 Keep stream workflows in RxJS

naturally stream-oriented workflow
readonly results$ = query$.pipe(
  debounceTime(250),
  distinctUntilChanged(),
  switchMap(query => api.search(query)),
  retry({ count: 2 }),
);

Debouncing, cancellation, retry, sequencing, concurrency, and buffering are stream concerns. Convert at the UI boundary rather than reimplementing operators with effects.

17. Production architecture patterns

17.1 Give each writable signal one owner

A component, store, or service should own each mutable source. Other code receives a read-only Signal, input, computed selector, model contract, or event API.

17.2 Separate state from events

state and event contracts
readonly currentUser = signal<User | null>(null);
readonly signedOut = output<void>();

A current user is readable state; a sign-out occurrence is an event. Do not use a signal as an event queue or an output as a current-state container.

17.3 Narrow selectors

domain selector
readonly canCheckout = computed(() =>
  this.lines().length > 0 &&
  this.inventoryValid() &&
  this.paymentMethod() !== null,
);

17.4 Scope by lifetime

LifetimeOwner
One component instancePrivate component signals
Feature subtreeComponent-provided store
Lazy route visitRoute providers
Application sessionRoot/session store with explicit reset
Server read dependencyResource or RxJS-backed store

17.5 Preserve atomic updates

atomic transition
interface EditorState {
  readonly document: DocumentModel;
  readonly dirty: boolean;
  readonly lastSaved: Date | null;
}

private readonly _state = signal<EditorState>(initialState);

applyEdit(document: DocumentModel): void {
  this._state.update(state => ({
    ...state,
    document,
    dirty: true,
  }));
}

When fields form one invariant, one state object avoids exposing inconsistent intermediate combinations.

17.6 Use readonly and protected intentionally

Angular’s style guide recommends readonly for stable property references and protected for members used only by a component template.[33]

21. Conclusion

Angular signals create an explicit synchronous dependency graph. Writable signals own current state, computed signals declare derived values, linked signals model user-editable dependent state, effects synchronize with non-reactive APIs, resources expose asynchronous reads as signal state, and templates become reactive consumers through signal reads.[1][3][4][5][15][20]

The component contract APIs complete the model: signal inputs expose parent state as read-only signals; outputs remain event emitters rather than signals; model signals combine writable state with input/output semantics. Scalable state management follows from disciplined ownership—private writes, read-only publication, computed selectors, immutable transitions, appropriate injector scope, explicit asynchronous boundaries, and RxJS interoperability where sequence semantics matter.
