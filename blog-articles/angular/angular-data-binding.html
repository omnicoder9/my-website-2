Angular Data Binding

Data binding is the contract between an Angular component’s state and its rendered template. It moves values from a component into text, DOM properties, attributes, directives, and child-component inputs; it moves events from the DOM or child components back into application logic; and, when deliberately combined, it can keep a parent value and an editable child value synchronized.

1. The binding mental model

An Angular template is HTML plus compile-time binding syntax. Angular compiles templates into JavaScript instructions, evaluates binding expressions in their template context, and updates rendering targets when the application state that feeds those bindings changes.[1][2]

Component state
Template expression
Binding target
User or child event
Component statement

Source to view

Interpolation and property, attribute, class, style, directive, and component-input bindings move values from application state into a rendering target.[2]

View to source

Event bindings listen for native DOM events or Angular output events and run a template statement, usually a method call or assignment.[3][6]

Two-way sequence

The [()] syntax combines an input-like value binding and a corresponding change event so updates can travel in both directions.[4][5]

DirectionSyntaxExample
Source → view {{ expression }} {{ userName() }}
Source → target property [target]="expression" [disabled]="saving()"
Target event → component (event)="statement" (click)="save()"
Two-way [(target)]="state" [(value)]="volume"
Think in contracts The target appears on the left of the equals sign; the source expression or event statement appears on the right. For a custom component, only declared inputs can be property-binding targets and only declared outputs can be event-binding targets.

2. Historical development

AngularJS interpolation and the digest cycle

AngularJS used interpolation markup such as {{name}} in text and attribute values. During compilation, interpolation directives registered watches; the digest cycle reevaluated watched expressions and updated affected nodes. AngularJS expressions also supported one-time binding with the :: prefix.[17][19]

AngularJS ngModel

AngularJS ngModel connected native and custom form controls to scope properties, handled view-to-model and model-to-view synchronization, tracked validity and interaction state, and registered controls with parent forms.[18]

Angular 2: directional template syntax

The rewritten Angular framework formalized directional punctuation: interpolation and square brackets for source-to-view binding, parentheses for event binding, and [()] for two-way binding. It introduced component contracts with @Input, @Output, and EventEmitter.[20][21]

Signals become the modern reactive primitive

Modern Angular signals expose reactive values as getter functions. Templates are reactive consumers: Angular tracks signal reads made while rendering and schedules affected consumers when those signals change. The public Signal and WritableSignal types are stable from Angular 17.[7][29]

Signal inputs, outputs, and model inputs

Angular added initializer APIs for component contracts. input() returns a read-only InputSignal, output() returns an OutputEmitterRef, and model() creates a writable signal exposed as an input/output pair. Input signals and model inputs are stable from Angular 19; the improved output API is production-ready from Angular 19.[9][10][27][28][30]

Compatibility note The signal-based input(), output(), and model() APIs are recommended for new Angular code, while decorator-based @Input, @Output, and EventEmitter remain fully supported.[5][6]

3. One-way binding from state to the view

One-way source-to-view bindings evaluate a template expression and write its result into a target. The target may be a text node, native DOM property, HTML or SVG attribute, CSS class or style, directive input, or component input.[2]

3.1 Text interpolation

greeting.component.ts
import {
  Component,
  computed,
  signal,
} from '@angular/core';

@Component({
  selector: 'app-greeting',
  standalone: true,
  template: `
    <h1>Hello, {{ displayName() }}!</h1>
    <p>You have {{ unreadCount() }} unread messages.</p>
  `,
})
export class GreetingComponent {
  readonly firstName = signal('Ada');
  readonly lastName = signal('Lovelace');
  readonly unreadCount = signal(3);

  readonly displayName = computed(
    () => `${this.firstName()} ${this.lastName()}`,
  );
}

Interpolation converts the expression result to a string and inserts it into text content. Angular tracks signals read while rendering the template, so changing firstName, lastName, or unreadCount invalidates the dependent binding.[2][7]

3.2 Native DOM property binding

DOM property bindings
@Component({
  selector: 'app-save-button',
  standalone: true,
  template: `
    <button
      type="button"
      [disabled]="saving() || !valid()"
      [title]="buttonTitle()">
      {{ saving() ? 'Saving…' : 'Save' }}
    </button>
  `,
})
export class SaveButtonComponent {
  readonly saving = signal(false);
  readonly valid = signal(true);

  readonly buttonTitle = computed(() =>
    this.valid()
      ? 'Save the current document'
      : 'Correct validation errors before saving',
  );
}

Square brackets bind to a property of the target object. On a native element, Angular normally writes directly to the DOM object—for example, the boolean disabled property of an HTMLButtonElement—rather than merely setting a string attribute.[2][25]

3.3 Attributes are not the same as properties

HTML source contains content attributes, while the browser exposes DOM objects with IDL properties. Some properties reflect attributes, but the mapping, type, and runtime semantics differ. Angular property binding targets the DOM property; attr. explicitly writes an attribute.[2][25][34]

attribute bindings
<table>
  <tr>
    <th
      [attr.colspan]="headingSpan()"
      [attr.aria-sort]="sortDirection()">
      Product
    </th>
  </tr>
</table>

<svg viewBox="0 0 100 100" aria-hidden="true">
  <circle
    cx="50"
    cy="50"
    [attr.r]="radius()" />
</svg>

Use an attribute binding when no corresponding property exists or when attribute semantics are specifically required, including many ARIA, SVG, and table-span attributes. A null attribute-binding result removes the attribute.[2][32]

3.4 Class and style bindings

individual class and style bindings
<section
  class="card"
  [class.card--selected]="selected()"
  [class.card--disabled]="disabled()"
  [style.opacity]="disabled() ? 0.55 : 1"
  [style.max-width.px]="maximumWidth()">
  ...
</section>
class and style objects
readonly cardClasses = computed(() => ({
  'card--selected': this.selected(),
  'card--disabled': this.disabled(),
  'card--featured': this.featured(),
}));

readonly cardStyles = computed(() => ({
  borderWidth: this.featured() ? '2px' : '1px',
  transform: `scale(${this.selected() ? 1.02 : 1})`,
}));
aggregate class and style bindings
<article
  class="card"
  [class]="cardClasses()"
  [style]="cardStyles()">
  ...
</article>

When binding class or style objects, create a new object when values change. Angular compares the current and previous bound object references, so in-place mutation of the same object can leave the rendered classes or styles unchanged.[2]

3.5 Directive input binding

binding to directive and native properties
<img
  [ngSrc]="photoUrl()"
  [width]="320"
  [height]="240"
  alt="Profile photograph">

A single element can host native properties and directive inputs. Angular resolves a bracketed target against the element, component, and attached directives according to the template compiler’s binding metadata.[2][33]

3.6 Static attribute or bound expression?

literal versus expression
<!-- Static string literal -->
<app-avatar size="48" />

<!-- Number expression -->
<app-avatar [size]="48" />

<!-- Component expression -->
<app-avatar [size]="preferredAvatarSize()" />

Without brackets, the template supplies a literal string-like attribute value unless an input transform or directive gives it different semantics. With brackets, Angular evaluates the right-hand side as a template expression and assigns its typed result to the target.

4. One-way binding from events to application logic

Event binding places an event name in parentheses and a template statement on the right. Angular invokes the statement whenever the matching native event or Angular output event occurs.[3][6]

4.1 Native event binding

native click event binding
@Component({
  selector: 'app-counter',
  standalone: true,
  template: `
    <p>Count: {{ count() }}</p>

    <button type="button" (click)="increment()">
      Increment
    </button>

    <button type="button" (click)="count.set(0)">
      Reset
    </button>
  `,
})
export class CounterComponent {
  readonly count = signal(0);

  increment(): void {
    this.count.update(value => value + 1);
  }
}

4.2 The $event value

typed native event
@Component({
  selector: 'app-search-box',
  standalone: true,
  template: `
    <label for="search">Search</label>
    <input
      id="search"
      type="search"
      [value]="query()"
      (input)="onInput($event)">
  `,
})
export class SearchBoxComponent {
  readonly query = signal('');

  onInput(event: Event): void {
    const input = event.currentTarget as HTMLInputElement;
    this.query.set(input.value);
  }
}

For native events, $event is the DOM event object. Its type depends on the event and target. The DOM standard distinguishes target, where the event was dispatched, from currentTarget, whose listener is currently running; using currentTarget is often clearer when handling a listener attached to a known element.[3][24]

4.3 Keyboard modifiers

key event modifiers
<input
  type="text"
  (keydown.enter)="submit()"
  (keydown.escape)="cancel()"
  (keydown.control.s)="save($event)">
prevent a native default action
save(event: KeyboardEvent): void {
  event.preventDefault();
  // Save the document.
}

Angular supports key modifiers and can distinguish character-oriented key matching from physical-key code matching. For example, (keydown.code.alt.shiftleft) filters by physical key codes.[3]

4.4 Keep event statements small

simple event statements
<!-- Prefer -->
<button (click)="deleteProduct(product.id)">
  Delete
</button>

<!-- Avoid embedding a workflow in the template -->
<button
  (click)="selectedId = product.id;
           deleting = true;
           audit('delete-started');
           deleteProduct(product.id)">
  Delete
</button>

Angular event handlers are template statements rather than read-only expressions. Current Angular statements support assignment operators but not pipes. Keeping them to a method call or simple assignment improves testing, readability, and error handling.[14]

4.5 Global event targets in host bindings

global event listeners
@Component({
  selector: 'app-command-palette',
  standalone: true,
  host: {
    'document:keydown.control.k': 'open($event)',
    'document:keydown.escape': 'close()',
  },
  template: `...`,
})
export class CommandPaletteComponent {
  open(event: KeyboardEvent): void {
    event.preventDefault();
  }

  close(): void {}
}

Angular’s event system supports window, document, and body as global target prefixes in host event declarations.[3]

5. Two-way binding

Two-way binding is shorthand for a source-to-target binding plus a target-to-source change event. Angular combines square brackets and parentheses as [()], informally called “banana in a box.”[4]

5.1 First understand the expanded form

explicit property and event bindings
<input
  [value]="name()"
  (input)="name.set(
    ($event.currentTarget as HTMLInputElement).value
  )">

The input’s current value flows into the DOM value property. Each browser input event reads the new DOM value and writes it back to the signal. Two-way binding never means that Angular discovers arbitrary mutations automatically; it is a defined pair of value and event contracts.

5.2 Native form controls with ngModel

two-way binding with ngModel
import { Component } from '@angular/core';
import { FormsModule } from '@angular/forms';

@Component({
  selector: 'app-profile-name',
  standalone: true,
  imports: [FormsModule],
  template: `
    <label for="name">Name</label>
    <input
      id="name"
      type="text"
      [(ngModel)]="name">

    <p>Hello, {{ name }}.</p>
  `,
})
export class ProfileNameComponent {
  name = 'Ada';
}

Native form elements do not expose Angular’s conventional value/valueChange pair. The NgModel directive bridges a control value and component state; using it requires FormsModule.[4][18]

5.3 Decomposing [(ngModel)]

expanded ngModel binding
<input
  [ngModel]="name"
  (ngModelChange)="name = $event">

This form makes the two directions explicit: ngModel is the input target and ngModelChange is the output event.

5.4 Classic component two-way convention

classic value/valueChange component
import {
  Component,
  EventEmitter,
  Input,
  Output,
} from '@angular/core';

@Component({
  selector: 'app-quantity-stepper',
  standalone: true,
  template: `
    <button
      type="button"
      [disabled]="value <= minimum"
      (click)="setValue(value - 1)">
      −
    </button>

    <output>{{ value }}</output>

    <button
      type="button"
      [disabled]="value >= maximum"
      (click)="setValue(value + 1)">
      +
    </button>
  `,
})
export class QuantityStepperComponent {
  @Input() value = 1;
  @Input() minimum = 1;
  @Input() maximum = 99;

  @Output()
  readonly valueChange = new EventEmitter<number>();

  setValue(value: number): void {
    const next = Math.min(
      this.maximum,
      Math.max(this.minimum, value),
    );

    this.valueChange.emit(next);
  }
}
classic custom two-way binding
@Component({
  selector: 'app-order-line',
  standalone: true,
  imports: [QuantityStepperComponent],
  template: `
    <app-quantity-stepper
      [(value)]="quantity"
      [minimum]="1"
      [maximum]="20" />
  `,
})
export class OrderLineComponent {
  quantity = 1;
}

The custom two-way convention pairs an input named value with an output named valueChange. Angular’s [(value)] syntax binds the parent value into the input and assigns emitted change values back into the parent expression.[4][20]

5.5 Modern two-way binding with model()

model input component
import {
  Component,
  input,
  model,
} from '@angular/core';

@Component({
  selector: 'app-quantity-stepper',
  standalone: true,
  template: `
    <button
      type="button"
      [disabled]="value() <= minimum()"
      (click)="decrement()">
      −
    </button>

    <output>{{ value() }}</output>

    <button
      type="button"
      [disabled]="value() >= maximum()"
      (click)="increment()">
      +
    </button>
  `,
})
export class QuantityStepperComponent {
  readonly value = model(1);
  readonly minimum = input(1);
  readonly maximum = input(99);

  decrement(): void {
    this.value.update(value =>
      Math.max(this.minimum(), value - 1),
    );
  }

  increment(): void {
    this.value.update(value =>
      Math.min(this.maximum(), value + 1),
    );
  }
}
two-way binding to a parent signal
@Component({
  selector: 'app-order-line',
  standalone: true,
  imports: [QuantityStepperComponent],
  template: `
    <app-quantity-stepper
      [(value)]="quantity"
      [maximum]="20" />

    <p>Quantity: {{ quantity() }}</p>
  `,
})
export class OrderLineComponent {
  readonly quantity = signal(1);
}

A model input is a writable signal exposed as both an input and an output. Declaring value = model(1) automatically creates a corresponding valueChange output, emitted whenever the component calls set or update. When the parent binds a writable signal, it passes the signal instance rather than calling it.[5][10][11]

5.6 When two-way binding is appropriate

ScenarioRecommendation
Text, checkbox, or select field in a small template-driven form[(ngModel)] is concise.
Custom slider, stepper, date picker, or combobox whose purpose is editing one valueA model input is a natural primary contract.
Child emits a completed business action such as orderSubmittedUse a semantic output, not two-way binding.
Large object edited through many fieldsPrefer an explicit form or command model rather than two-way binding the entire mutable object.

6. Component input properties

An input defines data that a parent may supply to a component or directive. Angular records inputs statically at compile time; they cannot be added or removed dynamically at runtime. Input names are case-sensitive.[5]

6.1 Signal-based inputs

required and defaulted signal inputs
import {
  Component,
  computed,
  input,
} from '@angular/core';

export interface ProductSummary {
  readonly id: string;
  readonly name: string;
  readonly priceCents: number;
}

@Component({
  selector: 'app-product-card',
  standalone: true,
  template: `
    <article>
      <h2>{{ product().name }}</h2>
      <p>{{ formattedPrice() }}</p>
    </article>
  `,
})
export class ProductCardComponent {
  readonly product =
    input.required<ProductSummary>();

  readonly currency = input('USD');

  readonly formattedPrice = computed(() =>
    new Intl.NumberFormat('en-US', {
      style: 'currency',
      currency: this.currency(),
    }).format(this.product().priceCents / 100),
  );
}
bind parent data into child inputs
<app-product-card
  [product]="selectedProduct()"
  currency="EUR" />

input.required<T>() creates a required input without implicitly adding undefined. A defaulted input(initialValue) infers its read type from the default. Input signals are read-only from the component’s perspective; Angular writes them when the parent binding changes.[5][9]

6.2 Input transforms

input transforms
import {
  booleanAttribute,
  Component,
  input,
  numberAttribute,
} from '@angular/core';

@Component({
  selector: 'app-progress-ring',
  standalone: true,
  template: `...`,
})
export class ProgressRingComponent {
  readonly diameter = input(48, {
    transform: numberAttribute,
  });

  readonly disabled = input(false, {
    transform: booleanAttribute,
  });

  readonly label = input('', {
    transform: (
      value: string | null | undefined,
    ) => value?.trim() ?? '',
  });
}
template values accepted by transforms
<app-progress-ring
  diameter="64"
  disabled
  label="  Upload progress  " />

Input transforms allow a wider accepted template type while exposing a normalized input type to component code. Angular requires transforms to be statically analyzable and recommends pure functions; built-in boolean and number transforms cover common HTML-like coercions.[5]

6.3 Aliases

signal input alias
readonly value = input(0, {
  alias: 'sliderValue',
});
bind through an alias
<app-slider [sliderValue]="volume()" />

An alias changes the public template name without changing the TypeScript property name. Use aliases sparingly, primarily for compatibility during renaming or to avoid a collision with a native DOM property.[5]

6.4 Decorator-based inputs

@Input component
import {
  Component,
  Input,
} from '@angular/core';

@Component({
  selector: 'app-legacy-badge',
  standalone: true,
  template: `
    <span>{{ label }}</span>
  `,
})
export class LegacyBadgeComponent {
  @Input({ required: true })
  label = '';

  @Input()
  tone: 'neutral' | 'success' | 'danger' =
    'neutral';
}

The original @Input decorator remains supported. Signal inputs are recommended for new projects because they integrate directly with computed and other reactive contexts and provide a read-only child-side contract.[5]

6.5 Reacting to input changes

Signal input

derive rather than synchronize
readonly query = input('');
readonly normalizedQuery = computed(
  () => this.query().trim().toLowerCase(),
);

Decorator input

ngOnChanges
@Input() query = '';

ngOnChanges(
  changes: SimpleChanges,
): void {
  if (changes['query']) {
    this.rebuildIndex(this.query);
  }
}

ngOnChanges runs after one or more decorator-based inputs change and receives previous/current-value metadata. With signal inputs, prefer computed for derived state and use an effect only when synchronization with an imperative API is genuinely required.[8][22]

6.6 Object identity and ownership

immutable input update
readonly product = signal<Product>({
  id: 'p1',
  name: 'Keyboard',
  priceCents: 5000,
});

// Prefer a new reference:
product.update(current => ({
  ...current,
  priceCents: 4500,
}));

Passing an object input passes its reference; it does not create a deep copy. In-place mutation makes ownership ambiguous and can prevent identity-based change-detection boundaries from recognizing a new input. Prefer immutable updates and make the parent the source of truth unless the component contract explicitly models editing.[16]

7. Output events

An output defines a custom event that a parent can listen to with parentheses. Modern Angular uses output(), which returns an OutputEmitterRef. Output names are case-sensitive, inherited by subclasses, and do not bubble through the DOM.[6]

7.1 Declare and emit an output

typed output event
import {
  Component,
  input,
  output,
} from '@angular/core';

export interface ProductSelected {
  readonly productId: string;
  readonly source: 'mouse' | 'keyboard';
}

@Component({
  selector: 'app-product-tile',
  standalone: true,
  template: `
    <button
      type="button"
      (click)="select('mouse')"
      (keydown.enter)="select('keyboard')">
      {{ name() }}
    </button>
  `,
})
export class ProductTileComponent {
  readonly productId = input.required<string>();
  readonly name = input.required<string>();

  readonly selected =
    output<ProductSelected>();

  select(
    source: ProductSelected['source'],
  ): void {
    this.selected.emit({
      productId: this.productId(),
      source,
    });
  }
}
listen for a child output
<app-product-tile
  [productId]="product.id"
  [name]="product.name"
  (selected)="openProduct($event)" />
parent event handler
openProduct(event: ProductSelected): void {
  console.log(
    `Selected ${event.productId} with ${event.source}`,
  );
}

For a component output, $event is exactly the value passed to emit. Prefer event-specific payload interfaces over emitting a large mutable component object.

7.2 Name outputs as events

PreferAvoidReason
closedonCloseThe binding syntax already reads like an event listener.
productSelectedselectProductOutputs describe what happened, not a command to the parent.
valueChangechanged for a two-way value contractThe suffix participates in [(value)].

Angular recommends camel-case output names, discourages an on prefix, and advises avoiding collisions with native DOM event names.[6]

7.3 Output aliases

output alias
readonly changed = output<number>({
  alias: 'valueChanged',
});
listen through an output alias
<app-slider
  (valueChanged)="saveVolume($event)" />

An alias affects the template event name but not the TypeScript property. It is useful for a compatibility rename but usually should not be the default design.[6]

7.4 Programmatic output subscriptions

programmatic output subscription
const ref = viewContainerRef.createComponent(
  ProductTileComponent,
);

ref.setInput('productId', 'p42');
ref.setInput('name', 'Mechanical Keyboard');

const subscription =
  ref.instance.selected.subscribe(event => {
    openProduct(event);
  });

// Optional explicit cleanup:
subscription.unsubscribe();

OutputRef.subscribe() registers a callback, and Angular automatically cleans up subscriptions when it destroys dynamically created components involved in the subscription. The returned subscription can also be unsubscribed explicitly.[6][13]

7.5 Outputs are not DOM bubbling events

output listener scope
<!-- The parent can listen directly. -->
<app-dialog (closed)="onClosed()" />

<!-- A grandparent does not receive the output merely because
     the dialog is nested inside another component. -->

Angular custom outputs do not bubble through the DOM. A parent that wants to forward a child event must explicitly listen and emit its own output or lift the state and action contract higher in the component tree.[6][24]

8. EventEmitter

EventEmitter<T> is Angular’s established output emitter used with @Output. It extends RxJS subject behavior and exposes an emit method. The API remains stable, but Angular recommends output() for new component code.[6][12]

decorator-based output
import {
  Component,
  EventEmitter,
  Output,
} from '@angular/core';

@Component({
  selector: 'app-legacy-dialog',
  standalone: true,
  template: `
    <button type="button" (click)="close()">
      Close
    </button>
  `,
})
export class LegacyDialogComponent {
  @Output()
  readonly closed = new EventEmitter<void>();

  close(): void {
    this.closed.emit();
  }
}

8.1 Use it as a component output

The official API describes EventEmitter specifically in connection with @Output. For general application event streams, use a service-owned signal or an RxJS observable/subject whose lifecycle and ownership are explicit rather than repurposing component-output infrastructure as a global event bus.[12]

8.2 Modern equivalent

output() replacement
readonly closed = output<void>();

close(): void {
  this.closed.emit();
}

Angular provides an output migration that converts decorator outputs to output(), including common emit usage. The improved output API was introduced in Angular 17.3 and is considered production-ready from Angular 19.[27]

9. Signals and data binding in modern Angular

A signal wraps a value and notifies reactive consumers when that value changes. Signals are read by calling them as functions. Writable signals support set and update; computed signals derive read-only values and are lazily evaluated and memoized.[7][29]

9.1 Local state and computed bindings

signal-driven template
import {
  Component,
  computed,
  signal,
} from '@angular/core';

@Component({
  selector: 'app-cart-summary',
  standalone: true,
  template: `
    <p>Items: {{ itemCount() }}</p>
    <p>Subtotal: {{ subtotalCents() / 100 }}</p>

    <button type="button" (click)="addItem()">
      Add item
    </button>
  `,
})
export class CartSummaryComponent {
  readonly prices = signal<readonly number[]>([]);

  readonly itemCount = computed(
    () => this.prices().length,
  );

  readonly subtotalCents = computed(
    () => this.prices().reduce(
      (sum, price) => sum + price,
      0,
    ),
  );

  addItem(): void {
    this.prices.update(prices => [
      ...prices,
      1299,
    ]);
  }
}

The template is a reactive consumer of itemCount and subtotalCents. Updating prices invalidates both computed values; Angular updates the bindings that read them on the next rendering synchronization.[7]

9.2 Replace collections instead of mutating deeply

signal collection updates
readonly products = signal<readonly Product[]>([]);

// Preferred:
products.update(items => [
  ...items,
  newProduct,
]);

// Avoid relying on an in-place mutation:
products().push(newProduct);

Signals detect replacement according to their equality function; the default comparison is referential. A read-only signal also does not prevent deep mutation of an object or collection. Use immutable updates unless an explicit custom equality and mutation strategy is justified.[7]

9.3 Template tracking and change-detection boundaries

When a template reads a signal, Angular records the dependency. In an OnPush-style subtree, changing a read signal marks the component for a future update. Input bindings and handled events are also change-detection notifications for the affected component tree.[7][16][31]

9.4 Signal-based component contracts

APIDirectionChild capability
input()Parent → childRead only.
output()Child → parentEmit typed events.
model()Parent ↔ childRead, set, update, and emit the implicit NameChange output.
signal()Internal stateRead, set, and update locally.
computed()Derived stateRead only; automatically invalidated.

9.5 Effects are not a substitute for binding

computed rather than state propagation
readonly firstName = signal('Ada');
readonly lastName = signal('Lovelace');

// Prefer:
readonly fullName = computed(
  () => `${this.firstName()} ${this.lastName()}`,
);

// Avoid copying derived state:
readonly copiedFullName = signal('');

constructor() {
  effect(() => {
    this.copiedFullName.set(
      `${this.firstName()} ${this.lastName()}`,
    );
  });
}

Angular recommends computed for derived state and reserves effects for synchronization with imperative, non-signal APIs such as storage, logging, canvas, or third-party widgets. Propagating state through effects can create circular updates and unnecessary rendering work.[8]

9.6 Input signals in reactive derivations

computed value from an input signal
@Component({
  selector: 'app-temperature',
  standalone: true,
  template: `
    <p>{{ celsius() }} °C</p>
    <p>{{ fahrenheit() }} °F</p>
  `,
})
export class TemperatureComponent {
  readonly celsius = input.required<number>();

  readonly fahrenheit = computed(
    () => this.celsius() * 9 / 5 + 32,
  );
}

An InputSignal behaves like a read-only signal with additional transform typing. Angular updates it whenever the parent supplies a new bound value, invalidating computations and template bindings that read it.[5][9]

10. Complete example: product configurator

This example combines signal inputs, a model input, an output event, interpolation, property, attribute, class, style, and event bindings, plus a parent that owns the selected configuration.

product-configurator.models.ts
export interface ProductOption {
  readonly id: string;
  readonly label: string;
  readonly priceDeltaCents: number;
}

export interface ProductConfiguration {
  readonly quantity: number;
  readonly optionId: string;
}

export interface AddToCartEvent {
  readonly productId: string;
  readonly configuration: ProductConfiguration;
  readonly unitPriceCents: number;
}
product-configurator.component.ts
import {
  Component,
  computed,
  input,
  model,
  output,
} from '@angular/core';

@Component({
  selector: 'app-product-configurator',
  standalone: true,
  templateUrl: './product-configurator.component.html',
})
export class ProductConfiguratorComponent {
  readonly productId = input.required<string>();
  readonly productName = input.required<string>();
  readonly basePriceCents = input.required<number>();
  readonly options =
    input.required<readonly ProductOption[]>();

  readonly disabled = input(false);
  readonly configuration =
    model.required<ProductConfiguration>();

  readonly added = output<AddToCartEvent>();

  readonly selectedOption = computed(() =>
    this.options().find(
      option =>
        option.id === this.configuration().optionId,
    ) ?? this.options()[0],
  );

  readonly unitPriceCents = computed(() =>
    this.basePriceCents() +
    (this.selectedOption()?.priceDeltaCents ?? 0),
  );

  readonly totalPriceCents = computed(() =>
    this.unitPriceCents() *
    this.configuration().quantity,
  );

  updateQuantity(quantity: number): void {
    this.configuration.update(current => ({
      ...current,
      quantity: Math.max(1, Math.min(20, quantity)),
    }));
  }

  updateOption(optionId: string): void {
    this.configuration.update(current => ({
      ...current,
      optionId,
    }));
  }

  addToCart(): void {
    if (this.disabled()) {
      return;
    }

    this.added.emit({
      productId: this.productId(),
      configuration: this.configuration(),
      unitPriceCents: this.unitPriceCents(),
    });
  }
}

The parent owns the configuration signal. The child can update it only through the explicit model contract, and it emits a separate semantic event when the user completes the “add to cart” action. This keeps editable value synchronization distinct from business events.

11. Programmatic and dynamic bindings

Current Angular dynamic component APIs can receive binding helpers for input, output, and two-way contracts at creation time. These helpers preserve declarative binding semantics when a component cannot be written directly in a static template.[23]

dynamic component bindings
const quantity = signal(1);

const ref = viewContainerRef.createComponent(
  QuantityStepperComponent,
  {
    bindings: [
      inputBinding('minimum', () => 1),
      inputBinding('maximum', () => 20),

      twoWayBinding('value', quantity),

      outputBinding(
        'limitReached',
        (limit: number) => {
          console.log('Limit reached', limit);
        },
      ),
    ],
  },
);

Prefer static templates when the component structure is known. Programmatic bindings are appropriate for plugin hosts, overlays, schema-driven interfaces, and other genuinely dynamic composition systems.

12. Binding and change detection

Binding is declarative, but updates still occur through Angular’s rendering synchronization. Signals, input assignments, handled events, explicit change-detection notifications, and framework-integrated asynchronous work can make a component eligible to update. Current Angular supports zoneless operation and relies on explicit Angular notifications rather than assuming that every arbitrary field mutation will schedule rendering.[7][16][31]

12.1 Plain properties versus signals

plain property updated from an Angular event
@Component({
  selector: 'app-status',
  standalone: true,
  template: `
    <p>{{ status }}</p>
    <button type="button" (click)="status = 'ready'">
      Mark ready
    </button>
  `,
})
export class StatusComponent {
  status = 'idle';
}

A plain property can participate in binding when Angular checks the component; an Angular-handled event such as the button click provides a rendering notification. Signals additionally identify precisely which reactive consumers read the value and notify Angular when their setter API changes it.[3][7][31]

12.2 External callbacks should update through Angular-aware state

signal update from an external browser callback
readonly online = signal(navigator.onLine);

constructor() {
  window.addEventListener(
    'online',
    () => this.online.set(true),
  );

  window.addEventListener(
    'offline',
    () => this.online.set(false),
  );
}

Updating a signal read by the template is a supported notification for zoneless change detection. Manage listener cleanup in production code, for example with a service, DestroyRef, or an abort signal.[31]

12.3 Keep binding expressions inexpensive

memoize derived binding data
<!-- Avoid recomputing a large filter whenever the template is checked. -->
@for (
  product of products().filter(expensivePredicate);
  track product.id
) {
  ...
}

<!-- Prefer a memoized computed signal. -->
readonly visibleProducts = computed(() =>
  this.products().filter(expensivePredicate),
);

Template expressions may execute repeatedly as Angular synchronizes views. Move expensive derivations into computed signals or pure pipes so results can be cached until their inputs change.[7][35]

12.4 Immutable input boundaries

replace an input object reference
readonly settings = signal({
  theme: 'dark',
  density: 'comfortable',
});

// New reference notifies the child input boundary.
settings.update(current => ({
  ...current,
  density: 'compact',
}));

Identity-preserving mutation can leave an optimized child subtree with no new input notification. Treat component inputs as immutable values where practical and send a new reference when semantic input data changes.[16]

13. Binding security

Angular treats values inserted through template binding and interpolation as untrusted. Interpolated text is escaped, and property bindings are sanitized according to their security context where Angular can sanitize them. Angular templates themselves are executable code and must not be assembled from untrusted user strings.[15]

13.1 Text interpolation versus HTML binding

untrusted content
readonly userContent =
  '<img src=x onerror="alert(1)"><b>Hello</b>';
text and HTML contexts
<!-- Displays markup as text. -->
<p>{{ userContent }}</p>

<!-- Interprets safe HTML after Angular sanitization. -->
<div [innerHTML]="userContent"></div>

Interpolation writes text and escapes markup. Binding to innerHTML asks the browser to interpret HTML, so Angular sanitizes the value and removes unsafe content. Avoid bypassing sanitization unless the value has been reviewed for the exact target context.[15][36]

13.2 Do not synthesize event-handler attributes

unsafe design
<!-- Do not attempt to create executable bindings or event attributes
     from user-controlled strings. -->
<div [attr.onclick]="userSuppliedCode"></div>

Use Angular event binding to call trusted component code. Do not construct Angular templates or executable event attributes from external content. Content Security Policy and Trusted Types provide additional browser-enforced defense layers.[15]

13.3 Prefer templates to direct DOM mutation

Angular’s template bindings include security handling that direct calls through document, ElementRef.nativeElement, or third-party DOM APIs may bypass. Use templates for ordinary rendering and explicitly sanitize unavoidable direct DOM values.[15][36]

14. Accessible binding patterns

Dynamic state must remain available to assistive technologies. Angular supports attribute bindings for accessibility-related attributes, while native properties such as disabled should be used when the underlying HTML control supports them.[2][32]

bind visual and accessibility state together
<button
  type="button"
  [attr.aria-expanded]="expanded()"
  [attr.aria-controls]="panelId"
  (click)="expanded.update(value => !value)">
  {{ expanded() ? 'Hide details' : 'Show details' }}
</button>

<section
  [id]="panelId"
  [hidden]="!expanded()">
  ...
</section>

Do not bind only a visual class when the state has semantic meaning. Update the relevant native property or ARIA attribute from the same source of truth.

Binding tests should verify observable contracts: parent values reach child inputs, user events change state, child outputs deliver typed payloads, and two-way model changes update the parent. Avoid testing Angular’s punctuation itself; test the component behavior created by the binding.

15.4 High-value cases

  • Required inputs fail at compile time in application templates and receive valid values in tests.
  • Transforms normalize static and dynamic input forms correctly.
  • Output payloads contain stable identifiers and expected data.
  • Output aliases and input aliases preserve compatibility.
  • Two-way model changes update plain parent properties and writable signals.
  • Disabled, selected, expanded, and validation state are reflected in both visual and accessibility bindings.
  • Sanitized HTML and URL bindings do not render unsafe content.

16. Production architecture patterns

16.1 Presentational component contracts

small explicit contract
@Component({
  selector: 'app-user-card',
  standalone: true,
  template: `...`,
})
export class UserCardComponent {
  readonly user = input.required<UserSummary>();
  readonly selected = input(false);

  readonly opened = output<string>();

  open(): void {
    this.opened.emit(this.user().id);
  }
}

A presentational component should generally receive values through inputs and emit meaningful events through outputs. It should not reach into the parent or mutate input objects implicitly.

16.2 Lift shared state

When siblings need the same value, place the source of truth in their nearest common parent or a scoped state service. Bind values downward and events upward. Do not create a chain of local copies synchronized by effects.

16.3 Distinguish commands, values, and events

ConceptContractExample
Parent supplies configurationInput[pageSize]="50"
Child edits its primary valueModel input[(selection)]="selection"
Child reports that something occurredOutput(submitted)="save($event)"
Parent asks a child to perform an exceptional imperative actionOccasionally a queried component methodeditor.focus()

16.4 Keep the public binding surface small

Every public input and output is part of a reusable component’s API. Prefer a few cohesive values over dozens of tightly coupled flags. Use required inputs for essential identity, default values for optional presentation, and event payloads that remain useful if the component internals change.

16.5 Use strict template types

Strict template checking catches incompatible input values, invalid event payload assumptions, nullability errors, and misspelled targets during compilation. Required signal inputs and typed outputs make component contracts especially explicit.

17. Common pitfalls

PitfallConsequenceBetter approach
Confusing attributes with DOM properties Boolean and live-state behavior is incorrect. Use property binding by default and attr. when attribute semantics are required.[2][25]
Forgetting brackets around a numeric or object input The child receives a literal string or transformed attribute value. Use [input]="expression" for evaluated values.
Mutating an input object in the child Ownership becomes implicit and optimized boundaries may miss identity changes. Emit a requested change or use a model contract with immutable replacement.[16]
Using two-way binding for completed business events The contract hides intent and couples parent state to child internals. Use semantic outputs such as submitted or deleted.
Naming an output click Consumers cannot easily distinguish the component event from a native DOM event. Choose a domain event name.[6]
Expecting outputs to bubble Ancestors never receive the event. Listen directly, forward explicitly, or lift state.[6]
Using EventEmitter as a global event bus Component output semantics leak into application state architecture. Use scoped signals or RxJS streams owned by a service.
Copying derived signal state with an effect Duplicate sources of truth and circular updates. Use computed.[8]
Performing expensive work in a template method The work can repeat during rendering synchronization. Use a computed signal or pure pipe.[35]
Building templates from user input Untrusted values become executable template code. Use fixed compiled templates and bind data values.[15]

20. Conclusion

Angular data binding is a directional component contract. Interpolation and property-like bindings move values toward the rendered view; event bindings move notifications toward application logic; inputs and outputs expose parent-child boundaries; and two-way binding deliberately combines a value input with a change output.[2][3][4][5][6]

Modern Angular strengthens this model with signals. Local signal() state, memoized computed() derivations, read-only input() contracts, typed output() events, and writable model() inputs make reactive dependencies and ownership explicit. The most maintainable design keeps one source of truth, binds values downward, emits meaningful events upward, and reserves two-way binding for components whose primary purpose is editing a value.
