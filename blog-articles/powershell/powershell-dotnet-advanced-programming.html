1. Introduction: PowerShell is a .NET language

Every value in PowerShell is a .NET object. Strings are System.String, integers are System.Int32, and the items returned by Get-ChildItem are System.IO.FileInfo and System.IO.DirectoryInfo instances. The PowerShell language specification describes its type system in terms of the underlying .NET types, adding an adaptation layer (the extended type system) on top of them [1]. Two runtimes matter in practice: Windows PowerShell 5.1 runs on .NET Framework, while PowerShell 7.x runs on modern, cross-platform .NET, and some APIs available in one are missing in the other [2].

That close relationship has two consequences that frame the rest of this article. First, the entire .NET class library is directly usable from a script, with no wrappers. Second, PowerShell's own language features (classes, enumerations, custom objects, runspaces) compile down to ordinary .NET types, so the .NET rules about types, threads and memory apply to them too.

Conventions. Examples target PowerShell 7.4 or later unless marked otherwise. Lines beginning with # are comments; lines beginning with # → show representative output. Exact output (version numbers, timings, paths) varies by machine.
# Every value is a .NET object; GetType() returns its System.Type

'hello'.GetType().FullName           # → System.String
(Get-Item $PSHOME).GetType().FullName # → System.IO.DirectoryInfo

2. .NET integration

2.1 .NET assemblies

An assembly is the unit of deployment, versioning and security in .NET: a compiled file (usually a .dll) containing type definitions plus a manifest describing them [3]. Assemblies are represented at run time by System.Reflection.Assembly objects, which can be enumerated and inspected [4]. PowerShell automatically loads the assemblies it needs for its own engine and for imported modules; anything else must be loaded explicitly.

The supported cmdlet for loading assemblies and compiling code is Add-Type. It accepts an assembly name (-AssemblyName), a file path (-Path or -LiteralPath), C# source text (-TypeDefinition), or just a member signature (-MemberDefinition), from which it generates a wrapper type [5]. Since PowerShell 5.0, the using assembly statement can also load an assembly at parse time, which is required when classes in the same script refer to types from that assembly [6].

# List the assemblies currently loaded into the session
[System.AppDomain]::CurrentDomain.GetAssemblies() |
    Sort-Object { $_.GetName().Name } |
    Select-Object -First 5 @{ n = 'Name'; e = { $_.GetName().Name } },
                           @{ n = 'Version'; e = { $_.GetName().Version } }

# Load a framework assembly by name (Windows-only example)
Add-Type -AssemblyName System.Windows.Forms

# Load a private assembly from disk
Add-Type -Path "$PSScriptRoot\lib\Contoso.Utilities.dll"

# Compile C# source into an in-memory assembly
Add-Type -TypeDefinition @'
namespace Demo
{
    public static class Geometry
    {
        public static double Hypotenuse(double a, double b)
        {
            return System.Math.Sqrt(a * a + b * b);
        }
    }
}
'@
[Demo.Geometry]::Hypotenuse(3, 4)    # → 5

# Which assembly defines a type?
[string].Assembly.Location
Assemblies cannot be unloaded from a session. Once an assembly or an Add-Type definition is loaded, its types stay in the session; calling Add-Type again with a changed definition of the same type name fails. Start a new session (or a child pwsh process) when iterating on compiled code [5].

2.2 Namespaces

.NET organises types into hierarchical namespaces such as System, System.IO and System.Collections.Generic; the System namespace holds the fundamental types every program uses [7]. In PowerShell you refer to a type by its full name in square brackets, for example [System.IO.Path]. PowerShell also searches the System namespace implicitly, so [IO.Path] and [DateTime] both resolve [1].

The using namespace statement removes the need to repeat long prefixes. Like all using statements, it must appear before any other statements in a script or module [6].

using namespace System.Collections.Generic
using namespace System.Text

$names = [List[string]]::new()
$names.Add('Ada'); $names.Add('Grace')

$sb = [StringBuilder]::new()
foreach ($n in $names) { [void]$sb.AppendLine("Hello, $n") }
$sb.ToString()

2.3 Classes and objects

A .NET class is a template; an object is an instance of it. PowerShell offers three ways to create an instance: the static new() method (added in PowerShell 5.0), the New-Object cmdlet, and casting a hashtable to a type that has a parameterless constructor and settable properties [8,9]. The ::new() syntax is generally preferred because it is faster and makes overload selection explicit; calling [TypeName]::new without parentheses lists the available constructor overloads [8].

# 1. Static new() method
$uri  = [System.Uri]::new('https://learn.microsoft.com/powershell')
# 2. New-Object
$rand = New-Object -TypeName System.Random -ArgumentList 42
# 3. Hashtable cast (parameterless ctor + property setters)
$psi  = [System.Diagnostics.ProcessStartInfo]@{
    FileName        = 'pwsh'
    Arguments       = '-NoProfile -Command "$PID"'
    UseShellExecute = $false
}

# Discover constructor overloads
[System.DateTime]::new

Get-Member is the primary tool for discovering what an object can do. It lists properties, methods and PowerShell-added members of the objects piped to it, and with -Static it lists the static members of the type instead [10,11].

$uri | Get-Member -MemberType Property | Select-Object -First 5
[System.Math] | Get-Member -Static -MemberType Method | Select-Object -ExpandProperty Name

2.4 Static methods

Static members belong to the type itself rather than to an instance. PowerShell accesses them with the :: operator after a type literal: [Type]::Member [8,10]. Static methods are typical for utility classes (System.Math, System.IO.Path, System.IO.File) and factory methods ([Guid]::NewGuid(), [DateTime]::Parse()).

[System.Math]::Round(2.71828, 2)                 # → 2.72
[System.IO.Path]::Combine('C:\temp', 'logs', 'app.log')
[System.Guid]::NewGuid()
[System.Environment]::ProcessorCount
[System.TimeSpan]::FromMinutes(90).ToString()    # → 01:30:00

# Static properties use the same syntax
[System.DateTime]::UtcNow
[System.Int32]::MaxValue                         # → 2147483647

# Overload resolution: PowerShell converts arguments to match
[System.Math]::Max(3, 7.5)                       # double overload → 7.5

2.5 Instance methods

Instance methods operate on a particular object and are called with the dot operator. Because PowerShell's parser treats a method call as an expression, you must include parentheses even when there are no arguments; omitting them returns a description of the method's overloads instead of calling it [10].

$text = '  PowerShell on .NET  '
$text.Trim().ToUpperInvariant()      # → POWERSHELL ON .NET
$text.Split(' ', [System.StringSplitOptions]::RemoveEmptyEntries)
$text.Contains('.NET')               # → True

$text.Replace                        # no parentheses: lists overloads

$list = [System.Collections.Generic.List[int]]::new()
1..5 | ForEach-Object { $list.Add($_ * 10) }
$list.IndexOf(30)                    # → 2
$list.RemoveAll({ param($x) $x -gt 30 })   # script block converted to Predicate[int]
$list                                # → 10 20 30

The last example shows a useful feature: when a .NET method expects a delegate (here Predicate<int>), PowerShell converts a script block to it automatically. This works well for callbacks invoked synchronously on the same thread; section 5 explains why it is unsafe for callbacks raised on other threads.

2.6 Reflection

Reflection is the .NET facility for examining types, members and assemblies at run time, and for creating instances and invoking members dynamically [12]. In PowerShell, every type literal is a System.Type object, so the reflection API is always one step away: [datetime].GetMethods(), .GetProperties(), .GetConstructors(), .BaseType and .GetInterfaces(). Loaded assemblies expose their types through Assembly.GetTypes() or GetExportedTypes() [4].

$t = [System.Collections.Generic.Dictionary[string,int]]
$t.FullName
$t.BaseType.FullName                         # → System.Object
$t.GetInterfaces().Name | Sort-Object        # IDictionary`2, IEnumerable, ...
$t.GetConstructors().Count

# Walk an inheritance chain
function Get-TypeAncestry([type]$Type) {
    while ($Type) { $Type.FullName; $Type = $Type.BaseType }
}
Get-TypeAncestry ([System.IO.FileInfo])
# → System.IO.FileInfo, System.IO.FileSystemInfo, System.MarshalByRefObject, System.Object

# Find every public type in an assembly that implements IDisposable
[System.Net.Http.HttpClient].Assembly.GetExportedTypes() |
    Where-Object { [System.IDisposable].IsAssignableFrom($_) -and -not $_.IsAbstract } |
    Select-Object -ExpandProperty FullName

# Invoke a method chosen at run time
$method = [System.Math].GetMethod('Pow')
$method.Invoke($null, @(2.0, 10.0))          # → 1024 ($null target = static)

# Create an instance from a type name held in a string
$typeName = 'System.Text.StringBuilder'
$obj = [System.Activator]::CreateInstance([type]$typeName, @('seed'))
$obj.Append('!').ToString()                  # → seed!
Reflection can also reach non-public members through System.Reflection.BindingFlags. That is useful for diagnostics, but non-public members are implementation details that can change between .NET versions without notice, so production scripts should not depend on them [12].

2.7 Type accelerators

Type accelerators are short aliases for .NET types: [int] for System.Int32, [hashtable] for System.Collections.Hashtable, [pscustomobject] for System.Management.Automation.PSObject, [regex], [xml], [ipaddress] and many more [13]. They are resolved before namespace search, so [xml]$text parses a string as an XmlDocument. The full list can be read from the internal TypeAccelerators class [13]:

$accel = [psobject].Assembly.GetType('System.Management.Automation.TypeAccelerators')
$accel::Get.GetEnumerator() |
    Sort-Object Key |
    Select-Object -First 10 Key, @{ n = 'Type'; e = { $_.Value.FullName } }

[int].FullName              # → System.Int32
[xml]'<a><b>1</b></a>' | ForEach-Object { $_.a.b }   # → 1
The TypeAccelerators class is not a public API. It also has an Add() method that some community modules use to register their own aliases, but because it is internal it may change without notice. Prefer using namespace in your own code.

Write a function Get-TypeSummary that accepts a [type] and returns one object with the type's full name, base type, assembly name, the number of public constructors, and the names of its public static methods (unique, sorted). Test it with [System.IO.Path] and [System.Text.StringBuilder].

function Get-TypeSummary {
    [CmdletBinding()]
    param([Parameter(Mandatory, ValueFromPipeline)][type]$Type)
    process {
        $flags = [System.Reflection.BindingFlags]'Public, Static'
        [pscustomobject]@{
            FullName      = $Type.FullName
            BaseType      = $Type.BaseType.FullName
            Assembly      = $Type.Assembly.GetName().Name
            Constructors  = $Type.GetConstructors().Count

                            Where-Object { $_ -notlike 'get_*' -and $_ -notlike 'set_*' } |

[System.IO.Path], [System.Text.StringBuilder] | Get-TypeSummary

3. Object-oriented programming

3.1 Classes

Starting with PowerShell 5.0, the language has a formal syntax for defining classes and other user-defined types. A class can declare properties, methods and constructors, can inherit from another class, and can implement interfaces; the resulting type is a real .NET type, usable anywhere a type literal is accepted [14].

class Book {
    [string]   $Title
    [string]   $Author
    [int]      $Pages
    [datetime] $Published

    [string] ToString() { return "$($this.Title) by $($this.Author)" }
}

$b = [Book]@{ Title = 'Code'; Author = 'Petzold'; Pages = 400; Published = '1999-10-21' }
$b.ToString()                  # → Code by Petzold
$b.GetType().BaseType.Name     # → Object
$b -is [Book]                  # → True

Several rules from the documentation are worth stating up front [14]:

  • Class definitions are processed when the script is parsed, so any type a class refers to must already be resolvable at parse time. That is why using assembly or using module is required for types defined elsewhere [6,14].
  • Classes defined in a module are not exported by Import-Module; consumers use using module to make them visible [6,14].
  • Inside a class, $this refers to the current instance and must be used explicitly to reach members [14].
  • Members are public by default; the hidden and static keywords change visibility and scope [14,15].

3.2 Constructors

A constructor has the same name as the class and no return type. If you define no constructor, PowerShell provides a default parameterless one; as soon as you define any constructor, the implicit default is no longer generated, so define a parameterless constructor explicitly if you still need hashtable casts [16]. Constructors can be overloaded and can call a base-class constructor with : base(...). A static constructor runs once, the first time the type is used [16].

PowerShell does not support constructor chaining (calling one constructor from another of the same class with : this(...)). The documented workaround is a shared, usually hidden, initialisation method that each constructor calls [16].

class Account {
    [string]  $Owner
    [decimal] $Balance
    [string]  $Currency
    static [int] $Count

    static Account() { [Account]::Count = 0 }          # runs once

    Account()                     { $this.Init('unknown', 0, 'EUR') }
    Account([string]$owner)       { $this.Init($owner, 0, 'EUR') }
    Account([string]$owner, [decimal]$opening, [string]$currency) {
        $this.Init($owner, $opening, $currency)
    }

    hidden [void] Init([string]$owner, [decimal]$opening, [string]$currency) {
        if ($opening -lt 0) { throw [System.ArgumentOutOfRangeException]::new('opening') }
        $this.Owner    = $owner
        $this.Balance  = $opening
        $this.Currency = $currency
        [Account]::Count++
    }
}

[Account]::new('Ada', 100, 'GBP')
[Account]::new('Grace')
[Account]::Count              # → 2
[Account]::new                # lists the three overloads

3.3 Properties

Properties are declared as typed variables in the class body. They can have default values, can be static or hidden, and can carry validation attributes such as [ValidateNotNullOrEmpty()] or [ValidateRange()], which are checked whenever the property is assigned [17]. A typed property converts assigned values to its type, so assigning '42' to an [int] property stores the integer 42.

Class properties are fields with no custom getter or setter logic. When you need computed or validated-on-read properties, the documentation shows how to add script properties to the class with Update-TypeData from the static constructor [17,18].

class Thermostat {
    [ValidateNotNullOrEmpty()] [string] $Room = 'Lounge'
    [ValidateRange(5, 30)]     [double] $TargetC = 20
    hidden [string] $Serial = [guid]::NewGuid().ToString('N')

    static Thermostat() {
        # Computed property defined once for the type
        Update-TypeData -TypeName 'Thermostat' -MemberType ScriptProperty `
            -MemberName TargetF -Value { $this.TargetC * 9 / 5 + 32 } -Force
    }
}

$t = [Thermostat]::new()
$t.TargetC = 22
$t.TargetF                 # → 71.6
$t.TargetC = 45            # throws: 45 is greater than the maximum allowed range of 30

3.4 Methods

Methods declare a return type (or [void]) and typed parameters. Unlike functions, methods do not emit pipeline output implicitly: only the value of a return statement is returned, and any other uncaptured output is discarded [19]. Methods can be overloaded by parameter count and type, can be static, and errors thrown inside them become terminating exceptions for the caller [19].

class Temperature {
    static [double] ToFahrenheit([double]$c) { return $c * 9 / 5 + 32 }
    static [double] ToFahrenheit([string]$c) { return [Temperature]::ToFahrenheit([double]$c) }

    [double] $Celsius
    Temperature([double]$c) { $this.Celsius = $c }

    [string] Describe() {
        'this string is discarded'          # no return → not output
        return '{0:N1} °C = {1:N1} °F' -f $this.Celsius, [Temperature]::ToFahrenheit($this.Celsius)
    }
}

[Temperature]::new(37).Describe()      # → 37.0 °C = 98.6 °F
[Temperature]::ToFahrenheit('100')     # string overload → 212

3.5 Inheritance

A class inherits from one base class using the class Derived : Base syntax. The derived class receives the base class's members, can add new ones, and can override methods by declaring a method with the same signature. Base-class constructors are called with : base(...), and an overridden base method is reached by casting $this to the base type: ([Base]$this).Method() [20]. A PowerShell class can also inherit from a .NET class, provided the base class is not sealed [20].

class Shape {
    [string] $Name
    Shape([string]$name) { $this.Name = $name }
    [double] Area()      { throw [System.NotImplementedException]::new('Area') }
    [string] Describe()  { return '{0} with area {1:N2}' -f $this.Name, $this.Area() }
}

class Circle : Shape {
    [double] $Radius
    Circle([double]$r) : base('Circle') { $this.Radius = $r }
    [double] Area() { return [math]::PI * $this.Radius * $this.Radius }
}

class Square : Shape {
    [double] $Side
    Square([double]$s) : base('Square') { $this.Side = $s }
    [double] Area() { return $this.Side * $this.Side }
    [string] Describe() { return ([Shape]$this).Describe() + ' (all sides equal)' }
}

$shapes = [Shape[]]@([Circle]::new(1), [Square]::new(2))
$shapes.Describe()
# → Circle with area 3.14
# → Square with area 4.00 (all sides equal)

# Inheriting from a .NET type
class AppException : System.Exception {
    [int] $Code
    AppException([string]$msg, [int]$code) : base($msg) { $this.Code = $code }
}
try { throw [AppException]::new('Disk quota exceeded', 507) }
catch [AppException] { "Caught code $($_.Exception.Code): $($_.Exception.Message)" }

PowerShell has no abstract keyword. The pattern above (a base method that throws NotImplementedException) approximates an abstract member; another common approach is to throw from the base constructor when $this.GetType() -eq [Shape].

3.6 Interfaces

PowerShell classes can implement .NET interfaces by listing them after the base class (or alone) following the colon, and must then implement every member of the interface [20]. PowerShell cannot declare new interfaces in script; an interface you need must come from a .NET assembly, which can be compiled with Add-Type [5,20]. Implementing standard interfaces is how your types plug into .NET: IComparable enables sorting, IEquatable[T] customises equality, and IDisposable signals that an object owns resources to release.

class SemVer : System.IComparable, System.IEquatable[object] {
    [int] $Major
    [int] $Minor
    [int] $Patch

    SemVer([string]$text) {
        $p = $text.Split('.')
        $this.Major = $p[0]; $this.Minor = $p[1]; $this.Patch = $p[2]
    }

    [int] CompareTo([object]$other) {
        $o = [SemVer]$other
        foreach ($part in 'Major', 'Minor', 'Patch') {
            $c = $this.$part.CompareTo($o.$part)
            if ($c -ne 0) { return $c }
        }
        return 0
    }
    [bool] Equals([object]$other) { return $other -is [SemVer] -and $this.CompareTo($other) -eq 0 }
    [int]  GetHashCode()          { return [System.HashCode]::Combine($this.Major, $this.Minor, $this.Patch) }
    [string] ToString()           { return "$($this.Major).$($this.Minor).$($this.Patch)" }
}

$versions = [SemVer[]]@('1.10.0', '1.2.3', '1.2.10')
[Array]::Sort($versions)        # uses IComparable.CompareTo
$versions -join ', '            # → 1.2.3, 1.2.10, 1.10.0
[SemVer]'2.0.0' -eq [SemVer]'2.0.0'   # → True (Equals override)

Declaring an interface for script classes to implement requires a .NET definition:

Add-Type -TypeDefinition @'
namespace Plugins { public interface IGreeter { string Greet(string name); } }
'@

class FormalGreeter : Plugins.IGreeter {
    [string] Greet([string]$name) { return "Good afternoon, $name." }
}
[Plugins.IGreeter] $g = [FormalGreeter]::new()
$g.Greet('Dr Hopper')
Because classes are parsed before the script runs, the class above fails if Add-Type is in the same file: Plugins.IGreeter does not exist yet at parse time. Put the Add-Type call in a separate script that runs first, or compile the interface into an assembly and load it with using assembly [6,14].

3.7 Encapsulation

PowerShell classes have no private, protected or internal access modifiers: every member is public [14]. The hidden keyword hides a member from Get-Member (unless -Force is used) and from tab completion, but the member remains accessible to any caller that names it [15]. Encapsulation in PowerShell is therefore a matter of convention and design rather than enforcement:

  • Mark internal state hidden to keep it out of the public surface.
  • Use validation attributes on properties so invalid states cannot be assigned [17].
  • Expose behaviour through methods that maintain invariants, and route state changes through them.
  • Where real enforcement matters (for example, a library API), implement the type in C# with Add-Type, where the compiler enforces access modifiers.
class BankAccount {
    hidden [decimal] $_balance = 0
    hidden [System.Collections.Generic.List[string]] $_log = [System.Collections.Generic.List[string]]::new()

    [decimal] GetBalance() { return $this._balance }

    [void] Deposit([decimal]$amount) {
        if ($amount -le 0) { throw [System.ArgumentException]::new('Deposit must be positive') }
        $this._balance += $amount
        $this._log.Add("+$amount")
    }

    [void] Withdraw([decimal]$amount) {
        if ($amount -gt $this._balance) { throw [System.InvalidOperationException]::new('Insufficient funds') }
        $this._balance -= $amount
        $this._log.Add("-$amount")
    }

    [string[]] History() { return $this._log.ToArray() }
}

$acct = [BankAccount]::new()
$acct.Deposit(50); $acct.Withdraw(20)
$acct.GetBalance()                     # → 30
$acct | Get-Member -MemberType Property          # _balance not listed
$acct | Get-Member -MemberType Property -Force   # now listed
$acct._balance                         # still readable: hidden is not private

3.8 Enumerations

The enum keyword (PowerShell 5.0 and later) declares a set of named integral constants. Values are assigned automatically starting at zero unless given explicitly, and each enum is a real System.Enum-derived type [21]. Adding the [Flags()] attribute declares a bit-field enum whose values can be combined with -bor and tested with HasFlag() or -band. Since PowerShell 6.2 an enum can also declare its underlying integral type, for example enum Level : byte [21].

enum LogLevel {
    Trace           # 0
    Debug           # 1
    Information     # 2
    Warning = 10
    Error           # 11
}

[LogLevel]::Warning.value__            # → 10
[LogLevel]'Error'                      # string conversion → Error
[LogLevel]11                           # integer conversion → Error
[enum]::GetNames([LogLevel])
[LogLevel]::Debug -lt [LogLevel]::Error   # → True (compares underlying values)

[Flags()] enum FilePermission {
    None    = 0
    Read    = 1
    Write   = 2
    Execute = 4
    All     = 7
}
$p = [FilePermission]::Read -bor [FilePermission]::Write
$p                                    # → Read, Write
$p.HasFlag([FilePermission]::Write)   # → True
[FilePermission]'Read, Execute'       # parse a comma-separated list → Read, Execute

enum Priority : byte {   # PowerShell 6.2+
    Low    = 1
    Normal = 5
    High   = 9
}
[Priority].GetEnumUnderlyingType().Name  # → Byte

# Enums work naturally with switch and parameter validation
function Write-Log([LogLevel]$Level, [string]$Message) {
    switch ($Level) {
        { $_ -ge [LogLevel]::Warning } { Write-Warning $Message; break }
        default                         { Write-Verbose $Message -Verbose }
    }
}
Write-Log -Level Error -Message 'Out of disk space'

A parameter typed as an enum gives free tab completion and validation: passing -Level Critical to Write-Log above fails with a message that lists the valid names.

Exercise 3.1: An inventory model

Show solution 
enum Category {
    Hardware
    Software
    Service
}

class Item : System.IComparable {
    [ValidateNotNullOrEmpty()] [string] $Sku
    [ValidateRange(0, 1000000)] [decimal] $Price
    [Category] $Category

    Item() {}
    Item([string]$sku, [decimal]$price, [Category]$cat) {

    }

    [decimal] TotalCost() { return $this.Price }

4. Custom objects

4.1 PSCustomObject

[pscustomobject] is the lightweight way to create structured output without defining a class. Casting a hashtable literal to [pscustomobject] creates an object whose note properties appear in the order written, which is the idiomatic way to return records from functions [22]. Under the hood, [pscustomobject] is a type accelerator for PSObject, and the resulting object's base is System.Management.Automation.PSCustomObject [13,22].

$server = [pscustomobject]@{
    Name    = 'web01'
    IP      = [ipaddress]'10.0.0.15'
    Cores   = 8
    Online  = $true
}
$server.Name
$server.PSObject.Properties.Name     # → Name, IP, Cores, Online (order preserved)

# Add members after creation
$server | Add-Member -MemberType NoteProperty   -Name Role -Value 'Frontend'
$server | Add-Member -MemberType ScriptProperty -Name Label -Value { "$($this.Name) [$($this.Role)]" }
$server | Add-Member -MemberType ScriptMethod   -Name Ping  -Value { param($count = 1) "Pinging $($this.IP) x$count" }
$server.Label                        # → web01 [Frontend]
$server.Ping(3)

# Typical use: shaping output from a function
function Get-DiskReport {
    Get-PSDrive -PSProvider FileSystem | ForEach-Object {
        [pscustomobject]@{
            Drive  = $_.Name
            UsedGB = [math]::Round($_.Used / 1GB, 1)
            FreeGB = [math]::Round($_.Free / 1GB, 1)
        }
    }
}

Add-Member supports several member types, including NoteProperty (a static value), ScriptProperty (a computed getter, optionally with a setter), ScriptMethod, AliasProperty and CodeProperty; with -PassThru it returns the modified object [23]. Every object also carries intrinsic members such as PSObject (the adapter, which exposes Properties and Methods) and PSTypeNames [24].

4.2 Custom type definitions (type names)

PowerShell's formatting and type-extension systems key off an object's type names, which are stored in the PSTypeNames collection (the full .NET type name followed by each base type). For a PSCustomObject you can give the object a custom type name by inserting it at the front of this collection, or by including a PSTypeName key in the hashtable being cast [22,24]. Doing so costs nothing at run time and lets you attach default display properties, methods and formatting views to a logical type, without writing a class.

# → Contoso.ServerInfo
# → System.Management.Automation.PSCustomObject
# → System.Object

4.3 Type extensions

The extended type system (ETS) lets you add members to any type, .NET or custom, for the whole session. Update-TypeData does this dynamically: you name the type and the member, choose a member type (NoteProperty, AliasProperty, ScriptProperty, CodeProperty, ScriptMethod or CodeMethod), and supply the value [18]. It can also set a type's default display property set, which controls which properties appear when the object is formatted without an explicit view [18].

# Add an Age property to every FileInfo object in the session
Update-TypeData -TypeName System.IO.FileInfo -MemberType ScriptProperty `
    -MemberName Age -Value { (Get-Date) - $this.LastWriteTime } -Force
(Get-Item $PROFILE -ErrorAction Ignore).Age

# Add a method to System.String
Update-TypeData -TypeName System.String -MemberType ScriptMethod `
    -MemberName ToTitleCase -Value { (Get-Culture).TextInfo.ToTitleCase($this.ToLower()) } -Force
'the quick brown fox'.ToTitleCase()       # → The Quick Brown Fox

# Alias a property name
Update-TypeData -TypeName System.Diagnostics.Process -MemberType AliasProperty `
    -MemberName MemMB -Value WorkingSet64 -Force

$o | Format-List *

Get-TypeData -TypeName Contoso.ServerInfo

Extensions apply to every object of that type in the current session and disappear when it ends. To make them permanent and shareable, put them in a .ps1xml types file (section 4.5).

5. Advanced runtime concepts

5.1 Runspaces

A runspace is the operating environment in which PowerShell commands execute: it holds the session state (variables, functions, loaded modules, providers) and the pipeline engine. Each PowerShell console is one runspace, and a host application can create many. The System.Management.Automation.PowerShell class creates and runs pipelines against a runspace or runspace pool, synchronously (Invoke) or asynchronously (BeginInvoke/EndInvoke) [29]. RunspaceFactory creates runspaces and runspace pools, and a pool limits how many runspaces execute concurrently [30–32].

# A single extra runspace, run synchronously
$ps = [powershell]::Create()
try {
    $null = $ps.AddScript({ param($n) 1..$n | Measure-Object -Sum }).AddArgument(100)
    $result = $ps.Invoke()
    $result.Sum                       # → 5050
    if ($ps.HadErrors) { $ps.Streams.Error }
}
finally { $ps.Dispose() }

# A runspace pool running work concurrently (min 1, max 4 runspaces)
$pool = [runspacefactory]::CreateRunspacePool(1, 4)
$pool.Open()
try {
    $jobs = foreach ($url in 'https://learn.microsoft.com', 'https://github.com', 'https://dotnet.microsoft.com') {
        $ps = [powershell]::Create()
        $ps.RunspacePool = $pool
        $null = $ps.AddScript({
            param($u)
            $sw = [System.Diagnostics.Stopwatch]::StartNew()
            try   { $null = Invoke-WebRequest -Uri $u -Method Head -TimeoutSec 10; $ok = $true }
            catch { $ok = $false }
            [pscustomobject]@{ Url = $u; Ok = $ok; Ms = $sw.ElapsedMilliseconds; Thread = [Environment]::CurrentManagedThreadId }
        }).AddArgument($url)
        [pscustomobject]@{ Shell = $ps; Handle = $ps.BeginInvoke() }
    }
    foreach ($j in $jobs) {
        $j.Shell.EndInvoke($j.Handle)    # blocks until that pipeline finishes
        $j.Shell.Dispose()
    }
}
finally { $pool.Close(); $pool.Dispose() }

Runspaces in a pool start with a fresh session state: your functions and variables are not there unless you pass them in as arguments or configure an InitialSessionState (for example, with modules to import and variables to define) when creating the pool [30,32].

$iss = [System.Management.Automation.Runspaces.InitialSessionState]::CreateDefault()
$iss.Variables.Add([System.Management.Automation.Runspaces.SessionStateVariableEntry]::new(
    'Config', @{ Retries = 3 }, 'Shared configuration'))
$iss.Commands.Add([System.Management.Automation.Runspaces.SessionStateFunctionEntry]::new(
    'Get-Double', 'param($x) $x * 2'))

$pool = [runspacefactory]::CreateRunspacePool(1, 2, $iss, $Host)
$pool.Open()
$ps = [powershell]::Create(); $ps.RunspacePool = $pool
$ps.AddScript('"Retries=$($Config.Retries); Double=$(Get-Double 21)"').Invoke()   # → Retries=3; Double=42
$ps.Dispose(); $pool.Dispose()

5.2 Threading

The runspace API is powerful but verbose. PowerShell 7 adds two higher-level options built on the same mechanism [33]:

  • ForEach-Object -Parallel (PowerShell 7.0+) runs a script block for each input object in parallel runspaces on separate threads. -ThrottleLimit caps concurrency (default 5), -TimeoutSeconds bounds the total run, and -AsJob returns a job instead of blocking. Variables from the caller must be passed with the $using: scope modifier [34].
  • Start-ThreadJob creates background jobs that run in runspaces on threads within the current process, which are much cheaper than the process-based jobs created by Start-Job; the jobs are managed with the usual Receive-Job, Wait-Job and Remove-Job cmdlets [35,36].
# Parallel pipeline: hash files on up to 8 threads
$algorithm = 'SHA256'
Get-ChildItem $PSHOME -Filter *.dll |
    ForEach-Object -Parallel {
        Get-FileHash -Path $_.FullName -Algorithm $using:algorithm
    } -ThrottleLimit 8 |
    Select-Object -First 5 Hash, Path

# Thread jobs
$jobs = 1..3 | ForEach-Object {
    Start-ThreadJob -ScriptBlock { param($n) Start-Sleep -Milliseconds (200 * $n); "job $n on thread $([Environment]::CurrentManagedThreadId)" } -ArgumentList $_
}
$jobs | Wait-Job | Receive-Job
$jobs | Remove-Job

Parallelism is not free. Each parallel iteration needs a runspace, and the documentation warns that for small, fast script blocks the overhead can make -Parallel slower than a normal loop; it pays off when each item does substantial or I/O-bound work [33,34]. Measure before and after (section 5.6).

Thread safety

Values passed with $using: are references to the same objects, not copies. If several threads modify a shared object, it must be thread-safe [34]. Ordinary collections such as List[T], Hashtable and arrays are not safe for concurrent writes; use the types in System.Collections.Concurrent, or have each thread emit output and let the pipeline collect it [37].

# WRONG: concurrent writes to a non-thread-safe collection can lose items or throw
$unsafe = [System.Collections.Generic.List[int]]::new()
1..10000 | ForEach-Object -Parallel { ($using:unsafe).Add($_) } -ThrottleLimit 8
$unsafe.Count                                  # often less than 10000

# RIGHT (1): a concurrent collection
$bag = [System.Collections.Concurrent.ConcurrentBag[int]]::new()
1..10000 | ForEach-Object -Parallel { ($using:bag).Add($_) } -ThrottleLimit 8
$bag.Count                                     # → 10000

# RIGHT (2): a concurrent dictionary for keyed aggregation
$counts = [System.Collections.Concurrent.ConcurrentDictionary[string,int]]::new()
Get-ChildItem $PSHOME -File | ForEach-Object -Parallel {
    $d = $using:counts
    $null = $d.AddOrUpdate($_.Extension, 1, [Func[string,int,int]]{ param($k, $v) $v + 1 })
}
$counts.GetEnumerator() | Sort-Object Value -Descending | Select-Object -First 5

# RIGHT (3), usually simplest: return values and let the pipeline gather them
$squares = 1..10000 | ForEach-Object -Parallel { $_ * $_ } -ThrottleLimit 8
$squares.Count                                 # → 10000 (order not guaranteed)
The AddOrUpdate callback above is a script block converted to a delegate. It is safe here because it is invoked on the same thread that is running the parallel script block, which has a runspace. A script block delegate invoked by .NET on an arbitrary thread pool thread has no runspace to run in and fails or crashes the process. For callbacks raised by .NET on other threads, use PowerShell's event system (section 5.4) instead.

5.3 Asynchronous operations

Modern .NET APIs are asynchronous: they return a System.Threading.Tasks.Task or Task<TResult> representing work that completes later, following the task-based asynchronous pattern (TAP), in which methods are conventionally named with an Async suffix [38,39]. PowerShell has no await keyword, but tasks are ordinary objects. You can start several, do other work, and then block for the results with Task.WaitAll, Task.WhenAll, or GetAwaiter().GetResult(). The last of these rethrows the original exception rather than wrapping it in an AggregateException [39].

$client = [System.Net.Http.HttpClient]::new()
$client.Timeout = [TimeSpan]::FromSeconds(15)
try {
    $urls  = 'https://learn.microsoft.com', 'https://github.com', 'https://www.powershellgallery.com'
    # Start all requests at once; each call returns immediately with a Task[string]
    $tasks = foreach ($u in $urls) { $client.GetStringAsync($u) }

    # Do other work here while requests are in flight ...

    # Block until all complete (WhenAll returns a Task; waiting on it surfaces failures)
    [System.Threading.Tasks.Task]::WhenAll([System.Threading.Tasks.Task[]]$tasks).GetAwaiter().GetResult()

    for ($i = 0; $i -lt $urls.Count; $i++) {
        [pscustomobject]@{ Url = $urls[$i]; Status = $tasks[$i].Status; Chars = $tasks[$i].Result.Length }
    }
}
finally { $client.Dispose() }

Waiting in a tight loop keeps the console responsive and lets the user press Ctrl+C, which a single blocking wait does not:

function Wait-Task {
    param([Parameter(Mandatory)][System.Threading.Tasks.Task[]]$Task, [int]$PollMs = 200)
    # Short timed waits let PowerShell notice Ctrl+C between polls
    while (-not [System.Threading.Tasks.Task]::WaitAll($Task, $PollMs)) { }
}

$read  = [System.IO.File]::ReadAllTextAsync("$PSHOME/pwsh.deps.json")
$delay = [System.Threading.Tasks.Task]::Delay(500)
Wait-Task -Task $read, $delay
$read.Result.Length              # safe: the task has completed

5.4 Event handling

.NET objects raise events such as Timer.Elapsed, FileSystemWatcher.Created or Process.Exited. Register-ObjectEvent subscribes to such an event; when it fires, PowerShell queues it, and either runs an -Action script block (in a job, on the PowerShell side) or leaves the event in the queue to be read with Wait-Event or Get-Event [40]. Because events are marshalled into PowerShell's own event queue, this is the safe way to respond to callbacks from other threads. Inside an action, automatic variables describe the event: $Event, $EventArgs, $Sender, $EventSubscriber and $Event.MessageData [40,41].

# 1. Action-based: watch a folder for new files
$folder  = Join-Path ([IO.Path]::GetTempPath()) 'inbox'
$null    = New-Item -ItemType Directory -Path $folder -Force
$watcher = [System.IO.FileSystemWatcher]::new($folder, '*.txt')
$watcher.EnableRaisingEvents = $true

$sub = Register-ObjectEvent -InputObject $watcher -EventName Created -SourceIdentifier Inbox.Created `
    -MessageData @{ Log = Join-Path $folder 'events.log' } -Action {
        $line = '{0:u} {1} {2}' -f $Event.TimeGenerated, $EventArgs.ChangeType, $EventArgs.Name
        Add-Content -Path $Event.MessageData.Log -Value $line
    }

Set-Content -Path (Join-Path $folder 'hello.txt') -Value 'hi'
Start-Sleep -Seconds 1
Get-Content (Join-Path $folder 'events.log')

# Clean up: always unregister and dispose
Unregister-Event -SourceIdentifier Inbox.Created
Remove-Job -Name Inbox.Created -ErrorAction Ignore
$watcher.Dispose()
# 2. Queue-based: wait for a timer to tick three times, synchronously
$timer = [System.Timers.Timer]::new(500)
Register-ObjectEvent -InputObject $timer -EventName Elapsed -SourceIdentifier Tick
$timer.Start()
try {
    1..3 | ForEach-Object {
        $e = Wait-Event -SourceIdentifier Tick -Timeout 5
        "Tick $_ at $($e.SourceEventArgs.SignalTime.ToString('HH:mm:ss.fff'))"
        $e | Remove-Event                     # remove it from the queue
    }
}
finally {
    $timer.Stop(); Unregister-Event -SourceIdentifier Tick; $timer.Dispose()
}

PowerShell also raises engine events of its own. Register-EngineEvent subscribes to them, for example PowerShell.Exiting to run clean-up code when the session ends, and can subscribe to custom events raised with New-Event [42].

Register-EngineEvent -SourceIdentifier PowerShell.Exiting -Action {
    "Session ended $(Get-Date -Format u)" | Add-Content -Path "$HOME/session.log"
} | Out-Null

5.5 Memory management

PowerShell objects live on the .NET managed heap and are reclaimed by the garbage collector (GC). The GC is generational: new objects are allocated in generation 0, objects that survive a collection are promoted to generations 1 and 2, and objects of 85,000 bytes or more go on the large object heap, which is collected with generation 2 [43]. Memory is reclaimed only once nothing references an object, so in PowerShell the practical questions are what keeps references alive, and which objects hold resources that the GC does not manage.

Releasing unmanaged resources

Types that own unmanaged resources (file handles, sockets, database connections, timers, watchers) implement IDisposable, and their Dispose method should be called as soon as the resource is no longer needed rather than waiting for finalisation [44,45]. PowerShell has no using statement for disposal, so the equivalent is try/finally:

$reader = $null
try {

Keeping the working set small

  • Stream, don't collect. Pipelines process one object at a time; assigning a pipeline to a variable materialises the whole result. For very large files, [System.IO.File]::ReadLines() or a StreamReader reads line by line instead of loading everything into memory [46].
  • Release references. Large data in long-lived scopes (global variables, module scope, $Error, event queues, completed jobs) stays reachable. Use Remove-Variable or assign $null, remove finished jobs, unregister event subscribers, and clear $Error in long-running services.
  • Don't force collections in normal code. [GC]::Collect() exists, but the GC tunes itself, and forcing collection is usually only appropriate for diagnostics or benchmarking [43,47].

5.6 Performance profiling

Measure-Command runs a script block and returns a TimeSpan with the elapsed time; the script block's output is discarded [48]. For finer control, such as timing sections within a script or taking several samples, System.Diagnostics.Stopwatch provides a high-resolution timer [49]. Single measurements are noisy (just-in-time compilation, caching and GC all interfere), so repeat each measurement and compare medians.

function Measure-Average {
    param([Parameter(Mandatory)][scriptblock]$ScriptBlock, [int]$Iterations = 5)
    $null = & $ScriptBlock                       # warm-up run
    $samples = 1..$Iterations | ForEach-Object { (Measure-Command $ScriptBlock).TotalMilliseconds }
    $sorted = $samples | Sort-Object
    [pscustomobject]@{
        MedianMs = [math]::Round($sorted[[int][math]::Floor($Iterations / 2)], 2)
        MinMs    = [math]::Round($sorted[0], 2)
        MaxMs    = [math]::Round($sorted[-1], 2)
    }
}

$n = 20000
[pscustomobject]@{ Approach = 'array +=';      Result = Measure-Average { $a = @(); foreach ($i in 1..$n) { $a += $i } } }
[pscustomobject]@{ Approach = 'List[T].Add';   Result = Measure-Average { $l = [System.Collections.Generic.List[int]]::new(); foreach ($i in 1..$n) { $l.Add($i) } } }
[pscustomobject]@{ Approach = 'loop output';   Result = Measure-Average { $a = foreach ($i in 1..$n) { $i } } }

The PowerShell team's performance guidance documents the most common hot spots, and the example above reproduces the first of them [46]:

  • Array addition. Arrays have a fixed size, so += copies the whole array on every append, which is quadratic in total. Use a List[T], or assign the output of a loop directly to a variable [46].
  • String addition. Strings are immutable, so repeated += has the same problem. Use -join or a StringBuilder [46].
  • Suppressing output. Assigning to $null or casting to [void] is cheaper than piping to Out-Null [46].
  • Lookups. Searching a large collection repeatedly with Where-Object is slow; build a hashtable keyed on the lookup value once, then index into it [46].
  • Large files. Use streaming .NET readers rather than reading entire files when processing very large inputs [46].
  • Pipeline vs. loop. For tight inner loops over in-memory data, foreach statements avoid per-item pipeline overhead; keep pipelines where streaming matters [46].

Exercise 5.1: Parallel port check with a runspace pool

Without using ForEach-Object -Parallel, write Test-PortParallel that takes host names and a port, checks TCP connectivity using a runspace pool limited to 10 concurrent runspaces, and returns Host, Port, Open and Ms for each. Use System.Net.Sockets.TcpClient with a 2-second timeout, and make sure every PowerShell instance, client and the pool are disposed.

Show solution 
function Test-PortParallel {
    [CmdletBinding()]
    param([Parameter(Mandatory)][string[]]$ComputerName,
          [int]$Port = 443, [int]$TimeoutMs = 2000, [int]$MaxThreads = 10)

    $worker = {
        param($h, $p, $timeout)
        $sw = [System.Diagnostics.Stopwatch]::StartNew()
        $client = [System.Net.Sockets.TcpClient]::new()
        try {
            $open = $client.ConnectAsync($h, $p).Wait($timeout)   # Task.Wait(int) → bool
        } catch { $open = $false }
        finally { $client.Dispose() }
        [pscustomobject]@{ Host = $h; Port = $p; Open = $open; Ms = $sw.ElapsedMilliseconds }
    }

    $pool = [runspacefactory]::CreateRunspacePool(1, $MaxThreads)
    $pool.Open()
    $running = [System.Collections.Generic.List[object]]::new()
    try {
        foreach ($h in $ComputerName) {
            $ps = [powershell]::Create()
            $ps.RunspacePool = $pool
            $null = $ps.AddScript($worker).AddArgument($h).AddArgument($Port).AddArgument($TimeoutMs)
            $running.Add([pscustomobject]@{ Shell = $ps; Handle = $ps.BeginInvoke() })
        }
        foreach ($r in $running) { $r.Shell.EndInvoke($r.Handle) }
    }
    finally {
        foreach ($r in $running) { $r.Shell.Dispose() }
        $pool.Dispose()
    }
}

Test-PortParallel -ComputerName learn.microsoft.com, github.com, 'no-such-host.invalid' -Port 443

$worker is passed as a script block, but AddScript takes its text and the code is re-parsed in each pooled runspace, so it does not capture variables from the caller; everything it needs arrives as arguments [29,32]. Disposal happens in finally so that a Ctrl+C does not leak runspaces [44].

Exercise 5.2: Debounced file-change events

Editors often raise several Changed events for a single save. Using Register-ObjectEvent on a FileSystemWatcher, write a script that prints one line per file at most once every 2 seconds, keeping the last-seen times in a hashtable passed through -MessageData.

$path    = Join-Path ([IO.Path]::GetTempPath()) 'watched'
$null    = New-Item -ItemType Directory -Path $path -Force

$watcher.NotifyFilter = [System.IO.NotifyFilters]'LastWrite, FileName'
$watcher.EnableRaisingEvents = $true

$state = @{ LastSeen = @{}; Window = [TimeSpan]::FromSeconds(2) }

$null = Register-ObjectEvent -InputObject $watcher -EventName Changed -SourceIdentifier Debounce `
    -MessageData $state -Action {
        $s    = $Event.MessageData
        $name = $EventArgs.FullPath
        $now  = $Event.TimeGenerated
        $last = $s.LastSeen[$name]
        if (-not $last -or ($now - $last) -gt $s.Window) {
            $s.LastSeen[$name] = $now
            Write-Host ("{0:HH:mm:ss} changed: {1}" -f $now, $EventArgs.Name)
        }
    }

1..5 | ForEach-Object { Add-Content -Path (Join-Path $path 'a.txt') -Value $_ }
Start-Sleep -Seconds 1

Unregister-Event -SourceIdentifier Debounce

PowerShell's event manager runs queued actions one at a time on the session's own thread rather than on the thread that raised the event, so the shared hashtable is not written concurrently. That is a key advantage of the event queue over raw .NET callbacks [40]. $Event.TimeGenerated is used rather than Get-Date so the comparison reflects when the event was raised, not when the action happened to run [41].

Exercise 5.3: Find and fix the bottleneck

The function below builds a CSV-like report and is very slow for 50,000 input objects. Measure it, identify the two problems using the performance guidance, rewrite it, and measure again.

function New-SlowReport($Items) {
    $rows = @()
    $text = ''
    foreach ($i in $Items) {
        $rows += "$($i.Id),$($i.Name)"
        $text += "$($i.Id),$($i.Name)`n"
    }
    [pscustomobject]@{ Rows = $rows; Text = $text }
}
Show solution 
function New-FastReport($Items) {
    # Loop output assigned directly: no array copying
    $rows = foreach ($i in $Items) { "$($i.Id),$($i.Name)" }
    # One join instead of repeated string concatenation
    $text = ($rows -join "`n") + "`n"
    [pscustomobject]@{ Rows = $rows; Text = $text }
}

$data = 1..50000 | ForEach-Object { [pscustomobject]@{ Id = $_; Name = "n$_" } }
(Measure-Command { $null = New-SlowReport $data }).TotalSeconds
(Measure-Command { $null = New-FastReport $data }).TotalSeconds
# The fast version is typically orders of magnitude quicker; exact numbers vary.

Both $rows += ... and $text += ... reallocate and copy on every iteration because arrays are fixed-size and strings are immutable [46]. Collecting loop output and calling -join once does each job in a single pass. A StringBuilder would also work for the text [46].

Exercise 6.1: A typed, parallel, self-formatting health checker

Combine the article's techniques:

  1. An enum HealthState with Healthy, Degraded, Down.
  2. A class Endpoint with Url (validated non-empty), DegradedMs (default 800) and a method Classify([long]$ms, [bool]$ok) that returns a HealthState.
  3. A function Invoke-HealthCheck that probes endpoints in parallel with ForEach-Object -Parallel (throttle 6), using an HttpClient that is disposed in each runspace, and emits [pscustomobject] results with type name Lab.Health.
  4. A DefaultDisplayPropertySet for Lab.Health registered with Update-TypeData.
  5. Timing of the whole run with a Stopwatch.
Show solution 
enum HealthState { Healthy; Degraded; Down }

class Endpoint {
    [ValidateNotNullOrEmpty()] [string] $Url
    [int] $DegradedMs = 800

    Endpoint() {}
    Endpoint([string]$url) { $this.Url = $url }

    [HealthState] Classify([long]$ms, [bool]$ok) {
        if (-not $ok)                { return [HealthState]::Down }
        if ($ms -gt $this.DegradedMs) { return [HealthState]::Degraded }
        return [HealthState]::Healthy
    }
}

Update-TypeData -TypeName Lab.Health -DefaultDisplayPropertySet Url, State, Ms -Force

function Invoke-HealthCheck {
    param([Parameter(Mandatory)][Endpoint[]]$Endpoint, [int]$ThrottleLimit = 6)

    $sw = [System.Diagnostics.Stopwatch]::StartNew()

    # Classes are not available inside parallel runspaces, so pass plain data in
    # and classify afterwards in the caller's runspace.
    $raw = $Endpoint | ForEach-Object -Parallel {
        $client = [System.Net.Http.HttpClient]::new()
        $client.Timeout = [TimeSpan]::FromSeconds(5)
        $t = [System.Diagnostics.Stopwatch]::StartNew()
        try {
            $resp = $client.GetAsync($_.Url).GetAwaiter().GetResult()
            $ok = $resp.IsSuccessStatusCode; $code = [int]$resp.StatusCode
        }
        catch { $ok = $false; $code = $null }
        finally { $client.Dispose() }
        [pscustomobject]@{ Url = $_.Url; Ok = $ok; Code = $code; Ms = $t.ElapsedMilliseconds }
    } -ThrottleLimit $ThrottleLimit

    $byUrl = @{}; foreach ($e in $Endpoint) { $byUrl[$e.Url] = $e }
    foreach ($r in $raw) {
        [pscustomobject]@{
            PSTypeName = 'Lab.Health'
            Url   = $r.Url
            State = $byUrl[$r.Url].Classify($r.Ms, $r.Ok)
            Ms    = $r.Ms
            Code  = $r.Code
        }
    }
    Write-Verbose "Checked $($Endpoint.Count) endpoints in $($sw.ElapsedMilliseconds) ms" -Verbose
}

$targets = [Endpoint[]]@(
    'https://learn.microsoft.com', 'https://github.com',
    'https://www.powershellgallery.com', 'https://no-such-host.invalid'
)
$results = Invoke-HealthCheck -Endpoint $targets
$results                                   # Url, State, Ms (default display set)
$results | Group-Object State -NoElement

Design notes. [Endpoint[]] converts the strings using the one-argument constructor [16]. The parallel script block works only with properties of the piped object and with .NET types, because a PowerShell class defined in the caller's script is affinitised to the runspace that defined it, so calling its script-defined methods from a parallel runspace marshals back to (or blocks on) the original runspace. PowerShell 7.4 added the [NoRunspaceAffinity()] attribute to change this, but keeping class logic in the caller is simpler. The classification therefore happens back in the caller [14]. Each parallel runspace creates and disposes its own HttpClient, so no non-thread-safe state is shared [44].

7. Summary

  • PowerShell is a .NET language: type literals, ::, ::new(), Add-Type and reflection give direct access to the class library and to your own compiled code [1,5,12].
  • Classes, enums and interfaces produce real .NET types, with parse-time resolution, public-only members, no constructor chaining and no script-defined interfaces as the main limitations to design around [14,16,20,21].
  • [pscustomobject], type names, ETS extensions and .ps1xml files let you shape and present data without changing it [18,22,25,28].
  • Runspaces underpin all in-process concurrency. Use ForEach-Object -Parallel or thread jobs for most work, keep shared state thread-safe, use the event queue for cross-thread callbacks, dispose what you create, and measure before optimising [32,34,40,44,46].
