1. Introduction and conventions

PowerShell is both an interactive shell and a scripting language whose pipeline passes structured .NET objects rather than plain text. That property is what makes it well suited to cloud and DevOps work: the result of an Azure, Microsoft Graph or kubectl call can be filtered, reshaped and exported without string parsing. Two editions matter in practice. Windows PowerShell 5.1 ships with Windows, while PowerShell 7 is the cross-platform, open-source edition that runs on Windows, Linux and macOS and is released on Long-Term Servicing (LTS) and Standard-Term Servicing (STS) tracks[1,2]. Everything in this article targets PowerShell 7 unless a section says otherwise, because CI runners and containers are mostly Linux.

Conventions used in the examples. Names such as contoso, rg-demo and app-web are placeholders. Every example that changes something supports -WhatIf where the underlying commands do, and no example stores a secret in source. Commands that cost money in Azure (virtual machines, storage) are marked with a cost tag; delete the resource group when you finish.

Three habits recur through the article, so they are introduced once here.

  • Fail loudly. Set $ErrorActionPreference = 'Stop' in automation so non-terminating errors stop the script. In PowerShell 7.4 and later, $PSNativeCommandUseErrorActionPreference = $true also turns a non-zero exit code from a native tool such as git, docker or kubectl into a PowerShell error[3].
  • Support -WhatIf and -Confirm. Declaring [CmdletBinding(SupportsShouldProcess)] and wrapping each change in $PSCmdlet.ShouldProcess() gives your functions the same dry-run behaviour as built-in cmdlets[4].
  • Keep secrets out of scripts. Use managed identities, workload identity federation or a vault. The SecretManagement module provides a common interface over vault extensions such as SecretStore and Azure Key Vault[5].
PowerShell
# A reusable header for automation scripts in this article
#Requires -Version 7.4
[CmdletBinding(SupportsShouldProcess)]
param()
Set-StrictMode -Version Latest
$ErrorActionPreference = 'Stop'
$PSNativeCommandUseErrorActionPreference = $true   # native exit codes -> errors (7.4+)

2. Infrastructure automation

2.1 Server provisioning

Provisioning means taking a machine from nothing (or from a base image) to a usable, reachable state: networking, identity, roles and the baseline software it needs. In PowerShell the core building block for reaching many servers is remoting. PowerShell supports remoting over WS-Management (WinRM), which is the Windows default, and over SSH, which works across Windows, Linux and macOS[6]. New-PSSession takes -ComputerName for WinRM and -HostName for SSH, and a session object can then be reused by Invoke-Command and Copy-Item -ToSession[7].

PowerShell
# provision-baseline.ps1 - push a baseline to a list of new servers
[CmdletBinding(SupportsShouldProcess)]
param(
    [Parameter(Mandatory)] [string[]] $ComputerName,
    [string[]] $Features = @('Web-Server', 'Web-Mgmt-Console'),
    [pscredential] $Credential
)
$ErrorActionPreference = 'Stop'

$sessions = New-PSSession -ComputerName $ComputerName -Credential $Credential
try {
    # Run on all servers in parallel (Invoke-Command fans out over sessions)
    $result = Invoke-Command -Session $sessions -ScriptBlock {
        param($Features, $WhatIf)
        $missing = Get-WindowsFeature -Name $Features | Where-Object { -not $_.Installed }
        if ($missing -and -not $WhatIf) {
            Install-WindowsFeature -Name $missing.Name -IncludeManagementTools | Out-Null
        }
        [pscustomobject]@{
            Computer  = $env:COMPUTERNAME
            Installed = @($missing.Name)
            TimeZone  = (Get-TimeZone).Id
        }
    } -ArgumentList $Features, $WhatIfPreference.IsPresent

    $result | Select-Object Computer, Installed, TimeZone | Format-Table
}
finally {
    $sessions | Remove-PSSession
}

For Linux hosts reached over SSH, the same pattern works with -HostName and -UserName (or -SSHTransport with key-based authentication)[7]:

PowerShell
$s = New-PSSession -HostName web01.contoso.internal -UserName deploy -KeyFilePath ~/.ssh/id_ed25519
Invoke-Command -Session $s -ScriptBlock { uname -a; Get-PSDrive -PSProvider FileSystem }
Remove-PSSession $s

2.2 Configuration management

Configuration management keeps machines in a known state over time, rather than only at first boot. The essential discipline is idempotence: running the same configuration twice must leave the system unchanged the second time. A useful way to write idempotent PowerShell is the test-then-set pattern, where each setting has a test that reports drift and a set step that runs only when the test fails. That is exactly the model DSC formalises with its Get, Test and Set operations[8,9].

PowerShell
function Set-RegistryValueIdempotent {
    [CmdletBinding(SupportsShouldProcess)]
    param(
        [Parameter(Mandatory)] [string] $Path,
        [Parameter(Mandatory)] [string] $Name,
        [Parameter(Mandatory)] $Value,
        [Microsoft.Win32.RegistryValueKind] $Type = 'DWord'
    )
    $current = Get-ItemProperty -Path $Path -Name $Name -ErrorAction SilentlyContinue
    if ($null -ne $current -and $current.$Name -eq $Value) {
        Write-Verbose "$Path\$Name already $Value"
        return [pscustomobject]@{ Setting = "$Path\$Name"; Changed = $false }
    }
    if ($PSCmdlet.ShouldProcess("$Path\$Name", "Set to $Value")) {
        if (-not (Test-Path $Path)) { New-Item -Path $Path -Force | Out-Null }
        New-ItemProperty -Path $Path -Name $Name -Value $Value -PropertyType $Type -Force | Out-Null
    }
    [pscustomobject]@{ Setting = "$Path\$Name"; Changed = $true }
}

# Disable TLS 1.0 server-side (example hardening item)
Set-RegistryValueIdempotent -Path 'HKLM:\SYSTEM\CurrentControlSet\Control\SecurityProviders\SCHANNEL\Protocols\TLS 1.0\Server' `
    -Name Enabled -Value 0 -WhatIf

2.3 Infrastructure as Code

Infrastructure as Code (IaC) is the practice of describing infrastructure in versioned, declarative files so that every environment is produced by the same source, reviewed like application code and deployed through automation. Microsoft describes IaC as producing the same environment every time it is applied, which removes configuration drift between environments[10]. In the Microsoft ecosystem the declarative layer for Azure is usually an Azure Resource Manager (ARM) template or a Bicep file, and PowerShell acts as the orchestrator that validates, previews and deploys it[11,12].

A practical division of labour is: Bicep declares what should exist; PowerShell decides where and when (which subscription, which parameters, which gate to pass first). Section 3.5 shows the deployment commands in full.

Bicep
// main.bicep - a minimal, parameterised storage account
@description('Environment name, used in resource names and tags')
@allowed(['dev', 'test', 'prod'])
param env string

param location string = resourceGroup().location

var saName = toLower('st${uniqueString(resourceGroup().id)}${env}')

resource sa 'Microsoft.Storage/storageAccounts@2023-05-01' = {
  name: take(saName, 24)
  location: location
  sku: { name: env == 'prod' ? 'Standard_ZRS' : 'Standard_LRS' }
  kind: 'StorageV2'
  tags: { env: env }
  properties: {
    minimumTlsVersion: 'TLS1_2'
    allowBlobPublicAccess: false
    supportsHttpsTrafficOnly: true
  }
}

output storageAccountName string = sa.name

Classic PSDSC example (Windows PowerShell 5.1)

PowerShell
# WebServer.ps1 - compile with Windows PowerShell 5.1, push with Start-DscConfiguration
Configuration WebServer {
    param([string[]] $NodeName = 'localhost')
    Import-DscResource -ModuleName PSDesiredStateConfiguration

    Node $NodeName {
        WindowsFeature IIS {
            Name   = 'Web-Server'
            Ensure = 'Present'

            DestinationPath = 'C:\inetpub\wwwroot\index.html'
            Contents        = '<h1>Managed by DSC</h1>'
            Ensure          = 'Present'
            DependsOn       = '[WindowsFeature]IIS'
        }
    }
}

WebServer -NodeName 'web01','web02' -OutputPath .\WebServer   # produces web01.mof, web02.mof
Start-DscConfiguration -Path .\WebServer -Wait -Verbose
Test-DscConfiguration -ComputerName web01 -Detailed           # drift report

Microsoft DSC 3 example (cross-platform)

A DSC 3 configuration document lists resource instances by type and properties; the dsc config get, test and set commands read the current state, report drift and enforce the desired state respectively[13,15].

YAML
# baseline.dsc.config.yaml
$schema: https://aka.ms/dsc/schemas/v3/bundled/config/document.json
resources:
  - name: Disable telemetry opt-in prompt
    type: Microsoft.Windows/Registry
    properties:
      keyPath: HKCU\Software\Contoso\Baseline
      valueName: Managed
      valueData:
        String: "true"
PowerShell
dsc config test --file ./baseline.dsc.config.yaml   # is the machine compliant?
dsc config set  --file ./baseline.dsc.config.yaml   # make it compliant

# Because DSC 3 emits JSON, PowerShell can consume the result as objects
$report = dsc config test --file ./baseline.dsc.config.yaml | ConvertFrom-Json
$report.results | ForEach-Object {
    [pscustomobject]@{ Resource = $_.name; InDesiredState = $_.result.inDesiredState }
}

2.5 Deployment automation

Deployment automation turns a release into a repeatable function call. A good deployment script is parameterised (environment, version), idempotent (safe to re-run), observable (writes structured output) and reversible (keeps the previous version available). The skeleton below is the shape the CI/CD examples in Section 5 call.

PowerShell
# deploy.ps1 - generic, idempotent release entry point
[CmdletBinding(SupportsShouldProcess)]
param(
    [Parameter(Mandatory)] [ValidateSet('dev','test','prod')] [string] $Environment,
    [Parameter(Mandatory)] [ValidatePattern('^\d+\.\d+\.\d+$')] [string] $Version,
    [string] $ConfigPath = "$PSScriptRoot/config/$Environment.psd1"
)
$ErrorActionPreference = 'Stop'
$config  = Import-PowerShellDataFile -Path $ConfigPath
$started = Get-Date

function Write-Step([string] $Message) {
    Write-Host ("[{0:HH:mm:ss}] {1}" -f (Get-Date), $Message)
}

Write-Step "Deploying $Version to $Environment ($($config.ResourceGroup))"

if ($PSCmdlet.ShouldProcess($config.ResourceGroup, "Deploy infrastructure")) {
    $deployment = New-AzResourceGroupDeployment -ResourceGroupName $config.ResourceGroup `
        -TemplateFile "$PSScriptRoot/infra/main.bicep" -TemplateParameterObject @{ env = $Environment } `
        -Name "release-$Version-$(Get-Date -Format yyyyMMddHHmmss)"
}

# Emit a machine-readable summary for the pipeline
[pscustomobject]@{
    Environment = $Environment
    Version     = $Version
    Outputs     = $deployment.Outputs
    DurationSec = [int]((Get-Date) - $started).TotalSeconds
} | ConvertTo-Json -Depth 5

2.6 Environment management

Environment management keeps dev, test and prod structurally identical while letting values differ. In PowerShell the cleanest way is one PowerShell data file (.psd1) per environment, loaded with Import-PowerShellDataFile, which parses data only and does not execute script. Secrets are referenced by name and resolved at runtime from a vault through SecretManagement[5].

PowerShell
# config/prod.psd1
@{
    SubscriptionId = '00000000-0000-0000-0000-000000000000'
    ResourceGroup  = 'rg-app-prod'
    Location       = 'westeurope'
    Sku            = 'Standard_ZRS'
    SecretNames    = @{ SqlPassword = 'app-prod-sql-admin' }
    Tags           = @{ env = 'prod'; owner = 'platform-team'; costCenter = 'CC-1042' }
}
PowerShell
function Get-EnvironmentConfig {
    param([Parameter(Mandatory)][ValidateSet('dev','test','prod')] [string] $Name)
    $cfg = Import-PowerShellDataFile -Path "$PSScriptRoot/config/$Name.psd1"
    # Resolve secret references from a registered vault (e.g. Azure Key Vault extension)
    $cfg.Secrets = @{}
    foreach ($k in $cfg.SecretNames.Keys) {
        $cfg.Secrets[$k] = Get-Secret -Name $cfg.SecretNames[$k] -Vault AppVault
    }
    $cfg
}

3. Microsoft Azure

3.1 Azure PowerShell (Az)

Azure PowerShell is a set of modules, collectively named Az, for managing Azure resources directly from PowerShell; it is cross-platform and runs on PowerShell 7 on Windows, Linux and macOS[18]. Az replaced the older AzureRM module, and its cmdlets use the Verb-Az noun prefix[19]. Install it from the PowerShell Gallery[20]:

PowerShell
# Install or update for the current user
Install-PSResource -Name Az -Repository PSGallery -Scope CurrentUser -TrustRepository
# (PowerShellGet v2 equivalent: Install-Module -Name Az -Repository PSGallery -Scope CurrentUser -Force)

Connect-AzAccount                                    # interactive / device code
Set-AzContext -Subscription 'Contoso Dev'            # pick the subscription to work in
Get-AzContext | Select-Object Account, Subscription, Tenant

For unattended work, prefer identities that hold no long-lived secret: a managed identity when the code runs in Azure (Connect-AzAccount -Identity), or OpenID Connect federation from a CI system (Section 5.2)[21,22].

3.2 Virtual machines cost

New-AzVM has a simplified parameter set that creates the VM together with any missing virtual network, subnet, public IP and network security group when you pass their names[23,24]. That is ideal for labs; for production, create the network explicitly (Section 3.4) and attach the VM to it.

PowerShell
$rg  = 'rg-demo-vm'
$loc = 'westeurope'
New-AzResourceGroup -Name $rg -Location $loc -Tag @{ purpose = 'lab' } | Out-Null

$cred = Get-Credential -Message 'Local administrator for the VM'

$vmParams = @{
    ResourceGroupName   = $rg
    Name                = 'vm-web01'
    Location            = $loc
    Image               = 'MicrosoftWindowsServer:WindowsServer:2022-datacenter-azure-edition:latest'
    Size                = 'Standard_B2s'
    Credential          = $cred
    VirtualNetworkName  = 'vnet-demo'
    SubnetName          = 'snet-web'
    SecurityGroupName   = 'nsg-web'
    PublicIpAddressName = 'pip-web01'
    OpenPorts           = 80, 3389
}
New-AzVM @vmParams

# Day-2 operations
Get-AzVM -ResourceGroupName $rg -Status |
    Select-Object Name, @{n='Power';e={ $_.PowerState }}, Location
Stop-AzVM  -ResourceGroupName $rg -Name 'vm-web01' -Force   # deallocates; compute billing stops
Start-AzVM -ResourceGroupName $rg -Name 'vm-web01'

# Run a script inside the guest without opening RDP
Invoke-AzVMRunCommand -ResourceGroupName $rg -VMName 'vm-web01' -CommandId 'RunPowerShellScript' `
    -ScriptString 'Install-WindowsFeature Web-Server; hostname'

Opening RDP (3389) to the internet is acceptable only for a short-lived lab. In real environments use Azure Bastion or just-in-time access and restrict the NSG.

3.3 Storage accounts cost

New-AzStorageAccount creates the account; parameters such as -SkuName (redundancy), -Kind, -MinimumTlsVersion and -AllowBlobPublicAccess set the security posture at creation time[25]. Storage account names must be globally unique, 3–24 characters, lowercase letters and digits only[25].

PowerShell
$rg   = 'rg-demo-storage'
$name = 'stdemo{0}' -f (Get-Random -Minimum 10000 -Maximum 99999)
New-AzResourceGroup -Name $rg -Location westeurope | Out-Null

$sa = New-AzStorageAccount -ResourceGroupName $rg -Name $name -Location westeurope `
        -SkuName Standard_LRS -Kind StorageV2 `
        -MinimumTlsVersion TLS1_2 -AllowBlobPublicAccess $false -EnableHttpsTrafficOnly $true

# Use Entra ID (not account keys) for data-plane access
$ctx = New-AzStorageContext -StorageAccountName $name -UseConnectedAccount
New-AzStorageContainer -Name 'artifacts' -Context $ctx | Out-Null
Set-AzStorageBlobContent -File ./build/app.zip -Container 'artifacts' -Blob 'app/1.4.2/app.zip' -Context $ctx

Get-AzStorageBlob -Container 'artifacts' -Context $ctx |
    Select-Object Name, Length, LastModified

-UseConnectedAccount requires a data-plane role such as Storage Blob Data Contributor on the account; being Owner of the resource group is not enough by itself.

3.4 Virtual networks

A virtual network is built from subnet configurations created in memory with New-AzVirtualNetworkSubnetConfig and passed to New-AzVirtualNetwork; later changes are made to the in-memory object and committed with Set-AzVirtualNetwork[26,27].

PowerShell
$rg  = 'rg-demo-net'
$loc = 'westeurope'
New-AzResourceGroup -Name $rg -Location $loc | Out-Null

# NSG that allows HTTPS from the internet and nothing else inbound (beyond defaults)
$https = New-AzNetworkSecurityRuleConfig -Name 'allow-https' -Protocol Tcp -Direction Inbound `
          -Priority 100 -SourceAddressPrefix Internet -SourcePortRange * `
          -DestinationAddressPrefix * -DestinationPortRange 443 -Access Allow
$nsg = New-AzNetworkSecurityGroup -ResourceGroupName $rg -Location $loc -Name 'nsg-web' -SecurityRules $https

$web  = New-AzVirtualNetworkSubnetConfig -Name 'snet-web'  -AddressPrefix '10.20.1.0/24' -NetworkSecurityGroup $nsg
$data = New-AzVirtualNetworkSubnetConfig -Name 'snet-data' -AddressPrefix '10.20.2.0/24'

$vnet = New-AzVirtualNetwork -ResourceGroupName $rg -Location $loc -Name 'vnet-app' `
          -AddressPrefix '10.20.0.0/16' -Subnet $web, $data

# Add a subnet later
Add-AzVirtualNetworkSubnetConfig -VirtualNetwork $vnet -Name 'snet-mgmt' -AddressPrefix '10.20.3.0/24' |
    Set-AzVirtualNetwork | Out-Null

(Get-AzVirtualNetwork -ResourceGroupName $rg -Name 'vnet-app').Subnets |
    Select-Object Name, AddressPrefix, @{n='NSG';e={ ($_.NetworkSecurityGroup.Id -split '/')[-1] }}

3.5 Azure Resource Manager

Azure Resource Manager is the deployment and management service for Azure: every request from the portal, CLI, PowerShell or SDKs passes through it, and it provides consistent authentication, authorisation, tagging, locks and templates across resource types[11]. Bicep is a domain-specific language that compiles to ARM JSON templates[12]. Azure PowerShell deploys a Bicep file directly with New-AzResourceGroupDeployment -TemplateFile main.bicep, but it does not install the Bicep CLI for you; you install it separately[28].

Before deploying, run the what-if operation. It shows which resources would be created, modified or deleted without changing anything[29].

PowerShell
$rg = 'rg-app-dev'
New-AzResourceGroup -Name $rg -Location westeurope -Force | Out-Null

$common = @{
    ResourceGroupName       = $rg
    TemplateFile            = './infra/main.bicep'
    TemplateParameterObject = @{ env = 'dev' }
}

# 1. Validate (syntax + many preflight checks)
Test-AzResourceGroupDeployment @common

# 2. Preview the change set
$whatIf = Get-AzResourceGroupDeploymentWhatIfResult @common
$whatIf.Changes | Group-Object ChangeType | Select-Object Name, Count

# 3. Deploy, failing the script if anything would be deleted
if ($whatIf.Changes.ChangeType -contains 'Delete') {
    throw "What-if reports deletions; refusing to deploy without review."
}
$d = New-AzResourceGroupDeployment @common -Name "dev-$(Get-Date -Format yyyyMMddHHmm)"
$d.Outputs.storageAccountName.Value

Add -WhatIf to New-AzResourceGroupDeployment for a quick interactive preview, or -Confirm to preview and then be asked whether to continue[29].

3.6 Azure Resource Graph

Azure Resource Graph lets you query resources across subscriptions with the Kusto Query Language (KQL), far faster than enumerating resources one API call at a time. In PowerShell the Az.ResourceGraph module provides Search-AzGraph[30]. Results are paged: -First controls page size and a returned SkipToken retrieves the next page[31].

PowerShell
Install-PSResource Az.ResourceGraph -Scope CurrentUser -TrustRepository   # if not already present

# VMs by size and power state across every subscription you can read
$kql = @'
Resources
| where type =~ 'microsoft.compute/virtualmachines'
| extend size = tostring(properties.hardwareProfile.vmSize),
         power = tostring(properties.extended.instanceView.powerState.code)
| summarize count() by size, power
| order by count_ desc
'@
Search-AzGraph -Query $kql | Format-Table

# Untagged resource groups (governance check), with full pagination
function Invoke-AzGraphAll([string] $Query) {
    $skip = $null
    do {
        $page = if ($skip) { Search-AzGraph -Query $Query -First 1000 -SkipToken $skip }
                else       { Search-AzGraph -Query $Query -First 1000 }
        $page
        $skip = $page.SkipToken
    } while ($skip)
}

Invoke-AzGraphAll @'
ResourceContainers
| where type =~ 'microsoft.resources/subscriptions/resourcegroups'
| where isnull(tags) or tags !has 'owner'
| project subscriptionId, name, location
'@ | Export-Csv ./untagged-rgs.csv -NoTypeInformation

Microsoft publishes a library of starter queries that are good templates for inventory and compliance reports[32].

3.7 Azure Automation

Azure Automation runs PowerShell runbooks in the cloud on a schedule, from a webhook or from an alert. It supports PowerShell, PowerShell Workflow, Python and graphical runbook types, and newer PowerShell versions are selected through runtime environments[33,34]. Run As accounts have been retired in favour of managed identities, so a runbook authenticates with Connect-AzAccount -Identity[21]. Runbooks that must reach on-premises systems can run on a Hybrid Runbook Worker[35].

PowerShell
# Runbook: Stop-TaggedVMs.ps1  (PowerShell 7.x runtime)
# Deallocates VMs tagged autoShutdown=true. Schedule it for 19:00 on weekdays.
param(
    [string] $TagName  = 'autoShutdown',
    [string] $TagValue = 'true'
)
$ErrorActionPreference = 'Stop'

# Use the Automation account's system-assigned managed identity
Connect-AzAccount -Identity | Out-Null

$vms = Get-AzVM -Status | Where-Object {
    $_.Tags[$TagName] -eq $TagValue -and $_.PowerState -eq 'VM running'
}

foreach ($vm in $vms) {
    # -NoWait returns immediately, so the VMs deallocate concurrently
    Stop-AzVM -ResourceGroupName $vm.ResourceGroupName -Name $vm.Name -Force -NoWait | Out-Null
    "Stopping $($vm.Name)"
}

Write-Output "Requested deallocation of $($vms.Count) VM(s)."
PowerShell
# Publishing the runbook and schedule from your workstation
$aa = @{ ResourceGroupName = 'rg-ops'; AutomationAccountName = 'aa-ops' }
Import-AzAutomationRunbook @aa -Path ./Stop-TaggedVMs.ps1 -Name 'Stop-TaggedVMs' -Type PowerShell -Published -Force
New-AzAutomationSchedule @aa -Name 'weekday-19h' -StartTime (Get-Date '19:00').AddDays(1) `
    -WeekInterval 1 -DaysOfWeek Monday,Tuesday,Wednesday,Thursday,Friday -TimeZone 'Europe/Amsterdam'
Register-AzAutomationScheduledRunbook @aa -RunbookName 'Stop-TaggedVMs' -ScheduleName 'weekday-19h'

The managed identity needs a role (for example Virtual Machine Contributor) on the subscriptions or resource groups it manages.

4. Microsoft 365

4.1 Microsoft Graph PowerShell SDK

The Microsoft Graph PowerShell SDK wraps the Microsoft Graph REST API in cmdlets such as Get-MgUser and New-MgGroup, and is the recommended general-purpose module for Entra ID and much of Microsoft 365[36]. Authentication is handled by Connect-MgGraph: delegated sign-in requests the permission scopes you name, while app-only sign-in uses an app registration with a certificate or a managed identity[37,38]. Find-MgGraphCommand maps an API URI to its cmdlet and lists the permissions it needs, which makes least-privilege scoping practical[39].

PowerShell
Install-PSResource Microsoft.Graph -Scope CurrentUser -TrustRepository

# Delegated: ask only for what this session needs
Connect-MgGraph -Scopes 'User.Read.All','Group.ReadWrite.All' -NoWelcome
Get-MgContext | Select-Object Account, Scopes, AuthType

# Which cmdlet and permissions does an endpoint need?
Find-MgGraphCommand -Uri '/users/{id}/memberOf' | Select-Object Command, Method, Permissions

# App-only with a certificate (for unattended jobs)
Connect-MgGraph -ClientId $env:APP_ID -TenantId $env:TENANT_ID -CertificateThumbprint $env:CERT_THUMB -NoWelcome

Graph returns paged results. -All follows the paging links for you, -Property limits returned attributes, and advanced filters such as endsWith require -ConsistencyLevel eventual together with a count[40,41].

PowerShell
# Licensed, enabled users in a department, with only the columns we need
Get-MgUser -All -Filter "accountEnabled eq true and department eq 'Finance'" `
    -Property displayName,userPrincipalName,assignedLicenses,signInActivity |
  Where-Object { $_.AssignedLicenses.Count -gt 0 } |
  Select-Object DisplayName, UserPrincipalName,
      @{n='LastSignIn';e={ $_.SignInActivity.LastSignInDateTime }}

# Advanced query: guest accounts from a given domain
Get-MgUser -Filter "endsWith(mail,'@fabrikam.com')" -ConsistencyLevel eventual -CountVariable n -All
"Found $n guest(s)"

# Anything without a dedicated cmdlet: call the REST API through the same session
Invoke-MgGraphRequest -Method GET -Uri 'https://graph.microsoft.com/v1.0/organization' |
    Select-Object -ExpandProperty value | Select-Object displayName, id

Reading signInActivity requires additional permissions (AuditLog.Read.All) and an Entra ID P1 or P2 licence; check the cmdlet's permissions with Find-MgGraphCommand first.

4.2 Exchange Online

Exchange Online is managed with the ExchangeOnlineManagement module and Connect-ExchangeOnline. The module's Get-EXO* cmdlets (for example Get-EXOMailbox) are optimised for large result sets[42]. For automation, Exchange Online supports app-only authentication with a certificate or managed identity, using the -AppId, -CertificateThumbprint and -Organization parameters[43].

PowerShell
Install-PSResource ExchangeOnlineManagement -Scope CurrentUser -TrustRepository
Connect-ExchangeOnline -UserPrincipalName admin@contoso.onmicrosoft.com -ShowBanner:$false

# Mailboxes over 90 % of quota
Get-EXOMailbox -ResultSize Unlimited -RecipientTypeDetails UserMailbox |
  Get-EXOMailboxStatistics -Properties TotalItemSize |
  ForEach-Object {
      $bytes = [int64]($_.TotalItemSize.Value.ToString() -replace '.*\(([\d,]+) bytes\).*','$1' -replace ',','')

5.1 Git

Git is a native executable, so PowerShell interacts with it through its exit code and output. Git's --porcelain output formats for git status are explicitly designed to be stable for scripts, unlike the human-readable default[50]. Settings such as line-ending handling or the signing key are managed with git config[51,52].

PowerShell
function Get-GitChange {
    <# Returns uncommitted changes as objects using git's stable porcelain format #>
    git status --porcelain=v1 | ForEach-Object {
        [pscustomobject]@{
            Index    = $_.Substring(0,1).Trim()
            WorkTree = $_.Substring(1,1).Trim()
            Path     = $_.Substring(3)
        }
    }
}

# Guard: refuse to release from a dirty tree or the wrong branch
$branch = git rev-parse --abbrev-ref HEAD
if ($branch -ne 'main')       { throw "Release must run from main (current: $branch)" }
if (Get-GitChange)            { throw 'Working tree has uncommitted changes.' }

# Derive a version from the latest tag and tag the release
$last = (git describe --tags --abbrev=0 2>$null) ?? 'v0.0.0'
$v    = [version]($last.TrimStart('v'))
$next = 'v{0}.{1}.{2}' -f $v.Major, $v.Minor, ($v.Build + 1)
git tag -a $next -m "Release $next"
git push origin $next

Before PowerShell 7.4, or without $PSNativeCommandUseErrorActionPreference, check $LASTEXITCODE after each native call, because a failed git push does not otherwise stop a script[3].

5.2 GitHub Actions

In a GitHub Actions workflow, a run step uses PowerShell 7 when you set shell: pwsh; pwsh is also the default shell on Windows runners[53]. GitHub's guide to building PowerShell projects shows running Pester tests and linting in this way[54]. Steps pass values to later steps by appending to the files named by environment variables such as GITHUB_OUTPUT[55]. For Azure, OpenID Connect lets the workflow obtain a short-lived token without storing a client secret: the job needs the id-token: write permission, and the azure/login action exchanges the token, optionally creating an Azure PowerShell session with enable-AzPSSession[22,56].

YAML
# .github/workflows/deploy.yml
name: build-and-deploy
on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  id-token: write      # required for OIDC
  contents: read

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Lint and test
        shell: pwsh
        run: |
          Install-PSResource PSScriptAnalyzer, Pester -TrustRepository -Quiet
          $issues = Invoke-ScriptAnalyzer -Path . -Recurse -Severity Error
          if ($issues) { $issues | Format-Table; throw 'PSScriptAnalyzer errors found' }
          Invoke-Pester -Path ./tests -CI
      - name: Compute version
        id: ver
        shell: pwsh
        run: |
          $v = "1.4.$env:GITHUB_RUN_NUMBER"
          "version=$v" >> $env:GITHUB_OUTPUT
    outputs:
      version: ${{ steps.ver.outputs.version }}

  deploy-dev:
    needs: test
    runs-on: ubuntu-latest
    environment: dev
    steps:
      - uses: actions/checkout@v4
      - uses: azure/login@v2
        with:
          client-id: ${{ secrets.AZURE_CLIENT_ID }}
          tenant-id: ${{ secrets.AZURE_TENANT_ID }}
          subscription-id: ${{ secrets.AZURE_SUBSCRIPTION_ID }}
          enable-AzPSSession: true
      - uses: azure/powershell@v2
        with:
          azPSVersion: latest
          inlineScript: |
            ./deploy.ps1 -Environment dev -Version '${{ needs.test.outputs.version }}'

function Deploy-K8sImage {
    [CmdletBinding(SupportsShouldProcess)]
    param(
        [Parameter(Mandatory)] [string] $Namespace,
        [Parameter(Mandatory)] [string] $Deployment,
        [Parameter(Mandatory)] [string] $Container,
        [Parameter(Mandatory)] [string] $Image,
        [string] $Timeout = '180s'
    )

        kubectl rollout undo "deployment/$Deployment" -n $Namespace
        throw "Deployment of $Image failed and was rolled back."
    }
}

)

    try   { & $stages[$name]; $ok = $true }
    catch { $ok = $false; Write-Error "Stage '$name' failed: $_" -ErrorAction Continue }

    if (-not $ok) { break }
}

Exercise 1 · Idempotent provisioning Beginner

Write a function Set-DirectoryPresent (an approved verb, so PSScriptAnalyzer stays quiet) that creates a directory only if it does not exist, accepts paths from the pipeline, supports -WhatIf, and returns an object with Path and Changed. Running it twice must report Changed = $false the second time.

PowerShell
function Set-DirectoryPresent {
    [CmdletBinding(SupportsShouldProcess)]
    param([Parameter(Mandatory, ValueFromPipeline)] [string] $Path)
    process {
        if (Test-Path -LiteralPath $Path -PathType Container) {
            return [pscustomobject]@{ Path = $Path; Changed = $false }
        }
        if ($PSCmdlet.ShouldProcess($Path, 'Create directory')) {
            New-Item -ItemType Directory -Path $Path -Force | Out-Null
        }
        [pscustomobject]@{ Path = $Path; Changed = $true }
    }
}

'./data','./logs' | Set-DirectoryPresent      # Changed = True
'./data','./logs' | Set-DirectoryPresent      # Changed = False

The key points are the test-before-set check, which gives idempotence, and ShouldProcess, which gives -WhatIf for free[4].

Exercise 3 · Safe Bicep deployment gate Intermediate

function Invoke-SafeDeployment {
    [CmdletBinding(SupportsShouldProcess)]
    param(
        [Parameter(Mandatory)] [string] $ResourceGroupName,
        [Parameter(Mandatory)] [string] $TemplateFile,
        [hashtable] $Parameters = @{},
        [switch] $AllowDelete
    )
    $p = @{ ResourceGroupName = $ResourceGroupName; TemplateFile = $TemplateFile; TemplateParameterObject = $Parameters }

    $result = Get-AzResourceGroupDeploymentWhatIfResult @p
    $result.Changes | Group-Object ChangeType | Select-Object @{n='Change';e={$_.Name}}, Count | Format-Table | Out-Host

    $deletes = $result.Changes | Where-Object ChangeType -eq 'Delete'
    if ($deletes -and -not $AllowDelete) {
        $deletes.ResourceId | ForEach-Object { Write-Warning "Would delete: $_" }
        throw 'Deployment blocked: deletions detected. Re-run with -AllowDelete after review.'
    }
    if ($PSCmdlet.ShouldProcess($ResourceGroupName, "Deploy $TemplateFile")) {
        New-AzResourceGroupDeployment @p -Name ("safe-{0:yyyyMMddHHmmss}" -f (Get-Date))
    }
}

Exercise 8 · Kubernetes rollout with automatic rollback Advanced

Extend Deploy-K8sImage so that, after a successful rollout, it also calls an HTTP health endpoint up to five times with a 10-second pause, and rolls back if it never returns HTTP 200.

Show solution
PowerShell
function Test-HttpHealthy {
    param([string] $Url, [int] $Attempts = 5, [int] $DelaySec = 10)
    for ($i = 1; $i -le $Attempts; $i++) {
        try {
            $r = Invoke-WebRequest -Uri $Url -TimeoutSec 5 -SkipHttpErrorCheck
            if ($r.StatusCode -eq 200) { return $true }
            Write-Verbose "Attempt $i : HTTP $($r.StatusCode)"
        } catch { Write-Verbose "Attempt $i : $($_.Exception.Message)" }
        Start-Sleep -Seconds $DelaySec
    }
    $false
}

function Deploy-K8sImageVerified {
    [CmdletBinding(SupportsShouldProcess)]
    param($Namespace, $Deployment, $Container, $Image, [string] $HealthUrl)
    Deploy-K8sImage -Namespace $Namespace -Deployment $Deployment -Container $Container -Image $Image
    if (-not (Test-HttpHealthy -Url $HealthUrl)) {
        kubectl rollout undo "deployment/$Deployment" -n $Namespace
        kubectl rollout status "deployment/$Deployment" -n $Namespace --timeout=180s
        throw "Health check failed for $Image; rolled back."
    }
    "Deployed and verified $Image"
}

kubectl rollout status confirms Kubernetes considers the rollout complete, while the HTTP check confirms the application actually works; kubectl rollout undo returns to the previous ReplicaSet revision[76,77].
