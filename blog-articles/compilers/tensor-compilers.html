1. What a tensor compiler is

A tensor compiler takes a high-level description of a computation over multidimensional arrays, such as a matrix multiplication, a convolution, a stencil or a sparse tensor contraction, and generates low-level code (C, LLVM IR, CUDA/PTX or accelerator instructions) that computes it efficiently on a chosen machine. Deep-learning compilers are the best-known family, but the same ideas power image-processing languages and scientific sparse-algebra compilers.1,2,3

The central difficulty is that a single mathematical expression has an enormous number of correct implementations. Matrix multiplication is three nested loops in its textbook form, yet a high-performance version reorders, blocks, packs, vectorizes and parallelizes those loops to fit the cache and register hierarchy of the target.4 The best choice changes with the processor, the tensor shapes and the sparsity of the data. Tensor compilers therefore share three design ideas:

  • A compact, analyzable input. Programs are written as index expressions or structured operators whose loops, iteration bounds and memory accesses the compiler can see exactly.3,5
  • Separation of concerns. What is computed (the algorithm) is kept apart from how it is computed (the schedule: loop order, tiling, parallelism, memory placement).6,7
  • A space of legal transformations that a human, a heuristic, a mathematical optimizer or a learned search can explore.8,9

2. Tensors and index notation

In this field a tensor is simply a multidimensional array: a vector is an order-1 tensor, a matrix is order-2, and an order-N tensor is indexed by N indices.10 Tensor compilers describe computations with index notation, which goes back to Einstein's summation convention: an index that appears on the right-hand side but not on the left is summed over.11,12

Index notation is useful to a compiler because it makes the iteration space explicit. Each distinct index becomes one loop, the bounds come from tensor shapes, and each tensor access is a simple (affine) function of the loop indices. TACO compiles directly from this notation,3 Tensor Comprehensions used a closely related syntax,13 and TVM's tensor expression language and MLIR's linalg.generic encode the same information as a compute rule plus indexing maps.5,7 The textbook lowering of matrix multiplication is the loop nest below.

// C(i,j) = A(i,k) * B(k,j), lowered in index order i, j, k
for (i = 0; i < M; i++)
  for (j = 0; j < N; j++)
    for (k = 0; k < K; k++)          // k is a reduction index
      C[i][j] += A[i][k] * B[k][j];

Matrix multiplication performs 2MNK floating-point operations on only MK + KN + MN inputs and outputs, so each element can be reused many times. Whether that reuse actually happens in cache or registers depends entirely on loop order and blocking, which is why a naive nest can run far below a machine's peak.4,14,15

3. Algorithms and schedules

Halide, introduced for image-processing pipelines in 2012, made the separation explicit: a program is a pure functional algorithm plus a schedule that says when and where each stage is computed and stored.6 Its PLDI 2013 paper framed scheduling as a three-way trade-off between parallelism, locality and redundant recomputation; for example, computing a producer inside each consumer tile improves locality at the cost of recomputing overlapping borders.2 The CACM retrospective reports that Halide went on to be used in production, including at Google and Adobe.16

The classic example is a separable 3×3 box blur. The two lines of algorithm never change; the schedule below tiles the output, vectorizes it, parallelizes over rows of tiles, and computes the intermediate blur_x per tile so that it stays in cache.16,17

Func blur_3x3(Func input) {
  Func blur_x, blur_y;
  Var x, y, xi, yi;

  // The algorithm: no storage, no order
  blur_x(x, y) = (input(x-1, y) + input(x, y) + input(x+1, y)) / 3;
  blur_y(x, y) = (blur_x(x, y-1) + blur_x(x, y) + blur_x(x, y+1)) / 3;

  // The schedule: order, locality, parallelism
  blur_y.tile(x, y, xi, yi, 256, 32)
        .vectorize(xi, 8).parallel(y);
  blur_x.compute_at(blur_y, x).vectorize(x, 8);
  return blur_y;
}

Listing 1. Halide (C++ embedded DSL). Adapted from the Halide CACM article and project page.16,17

TVM adopted the same separation for deep-learning operators and added primitives for accelerators, such as tensorize, which replaces a loop sub-nest with a hardware tensor instruction.7 Its current TensorIR layer organizes programs into blocks that state their iteration variables, whether each is spatial or a reduction, and which buffer regions they read and write, so that schedule primitives can be checked for correctness.18 The table below lists the primitives that recur across systems.

Exo pushes the idea further toward hardware: it lets performance engineers define accelerator instructions and memories in user code and then rewrite programs toward them with checked scheduling operations, an approach its authors call exocompilation.19

4. Loop transformations and legality

A schedule is only useful if it preserves meaning. The classic tool for checking this is data dependence analysis: two iterations depend on each other if they touch the same memory location and at least one writes it. For loop nests with array accesses, a dependence is summarized by a distance vector giving how many iterations apart, along each loop, the source and sink are.20,21

A sequential loop nest executes iterations in lexicographic order, so every real dependence has a lexicographically positive distance vector (its first non-zero entry is positive). A transformation is legal if every dependence remains lexicographically positive afterward.20,21 Three consequences recur constantly:

  • Interchange permutes the entries of every distance vector. Swapping the loops of a nest with distance (1, −1) yields (−1, 1), which is illegal.20
  • Tiling a band of loops is legal when the band is fully permutable, which holds when all distance components in the band are non-negative.21
  • Skewing (replacing j with i + j) adds a multiple of one distance component to another. It can turn negative components non-negative, enabling tiling, and can expose wavefront parallelism.21,22

Consider the 2D recurrence below. Iteration (i, j) reads the values written at (i−1, j) and (i, j−1), so the distance vectors are (1, 0) and (0, 1). Neither loop can run in parallel on its own, because each carries a dependence. All components are non-negative, however, so the nest can be tiled, and after skewing, every iteration on an anti-diagonal i + j = t is independent.

// Original: dependences (1,0) and (0,1)
for (i = 1; i < N; i++)
  for (j = 1; j < N; j++)
    A[i][j] = A[i-1][j] + A[i][j-1];

// Skewed into wavefronts: t = i + j; the inner loop is parallel
for (t = 2; t <= 2*(N-1); t++) {
  #pragma omp parallel for
  for (i = max(1, t-(N-1)); i <= min(N-1, t-1); i++)
    A[i][t-i] = A[i-1][t-i] + A[i][t-i-1];
}

Listing 2. Wavefront parallelization by skewing, the idea behind Lamport's hyperplane method.21,22

For locality, the most important transformation is tiling (blocking). Lam, Rothberg and Wolf showed that blocked matrix multiplication can cut cache misses dramatically but that performance is sensitive to tile size because of cache conflicts.14 Goto and van de Geijn's analysis of BLAS kernels shows how production libraries layer several levels of blocking and data packing to match registers, L1, L2 and the TLB.4 Tensor compilers try to derive such structures automatically.

6. The polyhedral model

Distance vectors summarize dependences, but they cannot express every transformation or every nest. The polyhedral model instead represents each statement's iteration domain as the integer points inside a polyhedron (a set described by affine inequalities), each array access as an affine map, and each schedule as an affine function from iterations to time.23,24 For the recurrence above:

Domain:     S = { S[i,j] : 1 <= i < N and 1 <= j < N }
Write:          S[i,j] -> A[i, j]
Reads:          S[i,j] -> A[i-1, j];   S[i,j] -> A[i, j-1]
Dependences:    S[i-1,j] -> S[i,j];    S[i,j-1] -> S[i,j]
Original schedule:   S[i,j] -> (i, j)
Wavefront schedule:  S[i,j] -> (i + j, i)

Listing 3. Polyhedral description in isl-style set and map notation.24

Because everything is affine, legality becomes a set of linear constraints: a schedule θ is valid if θ(sink) − θ(source) is lexicographically positive for every dependence. Feautrier gave exact array dataflow analysis for such programs and formulated the search for valid affine schedules as linear programming.23,25 Code generation, which turns a domain and a new schedule back into loops with correct bounds, was made practical by algorithms such as Bastoul's CLooG.26

Several tools build on this foundation:

  • Pluto finds affine transformations that minimize communication distance between dependent iterations, which yields tileable bands and coarse-grained parallelism automatically.8
  • isl, the integer set library, provides the set and map operations, dependence analysis and scheduling used by many polyhedral tools.24
  • Polly applies polyhedral optimization inside LLVM, working on LLVM IR rather than source code.27
  • PPCG generates CUDA from C loop nests, mapping tiles to GPU blocks and staging data in shared memory.28
  • Tensor Comprehensions combined an index-notation language for ML operators with a polyhedral, isl-based GPU code generator and autotuning.13
  • Tiramisu exposes polyhedral transformations through an explicit scheduling language, aimed at dense and sparse deep learning and image processing.29

Limits. The model requires affine loop bounds and subscripts. Indirect accesses such as x[crd[p]], which are everywhere in sparse code, fall outside it. That gap is one reason sparse tensor algebra developed its own compilation theory (Section 8).3,23

7. Tensor IRs compared

Each production system chooses a different level of abstraction for its main intermediate representation. Seeing the same kind of computation in each makes the differences concrete.

7.1 XLA HLO: whole-array operations

XLA's High Level Optimizer IR (HLO) is a graph of operations on entire arrays with static shapes, such as dot, broadcast, reduce and convolution. Contracting dimensions and broadcasts are explicit attributes, so the compiler can reason about layouts and fuse elementwise consumers into their producers.30,31

HloModule matmul_bias
ENTRY main {
  a    = f32[128,256] parameter(0)
  b    = f32[256,64]  parameter(1)
  bias = f32[64]      parameter(2)
  d    = f32[128,64]  dot(a, b), lhs_contracting_dims={1}, rhs_contracting_dims={0}
  bb   = f32[128,64]  broadcast(bias), dimensions={1}
  ROOT r = f32[128,64] add(d, bb)
}

Listing 4. HLO text. Loops are implicit; dimension numbers carry the index structure.31

7.2 TVM TensorIR: loops and blocks

TensorIR sits at the loop level. A T.block wraps the computation body and declares its block iterators: "SSR" marks vi, vj as spatial and vk as a reduction. Schedules transform the loops around blocks while the block signature lets TVM verify legality.18,32

from tvm.script import tir as T

@T.prim_func
def matmul(A: T.Buffer((128, 128), "float32"),
           B: T.Buffer((128, 128), "float32"),
           C: T.Buffer((128, 128), "float32")):
    for i, j, k in T.grid(128, 128, 128):
        with T.block("C"):
            vi, vj, vk = T.axis.remap("SSR", [i, j, k])
            with T.init():
                C[vi, vj] = T.float32(0)
            C[vi, vj] = C[vi, vj] + A[vi, vk] * B[vk, vj]

Listing 5. TVMScript for TensorIR.18,32

7.3 MLIR linalg: structured operations

MLIR is a framework for building many IRs (dialects) that coexist and lower progressively into one another.33 Its linalg dialect represents tensor computations as structured operations: a payload region plus one affine indexing map per operand and an iterator type per loop. Because the loop structure is recoverable from these attributes, tiling, fusion and vectorization can be applied without first materializing loops, and they work on both value-semantics tensors and in-memory buffers.5,34

// C(i,j) += A(i,k) * B(k,j) as a linalg.generic
#mapA = affine_map<(i, j, k) -> (i, k)>
#mapB = affine_map<(i, j, k) -> (k, j)>
#mapC = affine_map<(i, j, k) -> (i, j)>

func.func @matmul(%A: tensor<128x256xf32>, %B: tensor<256x64xf32>,
                  %C: tensor<128x64xf32>) -> tensor<128x64xf32> {
  %0 = linalg.generic {
         indexing_maps  = [#mapA, #mapB, #mapC],
         iterator_types = ["parallel", "parallel", "reduction"]}
       ins(%A, %B : tensor<128x256xf32>, tensor<256x64xf32>)
       outs(%C : tensor<128x64xf32>) {
  ^bb0(%a: f32, %b: f32, %c: f32):
    %p = arith.mulf %a, %b : f32
    %s = arith.addf %c, %p : f32
    linalg.yield %s : f32
  } -> tensor<128x64xf32>
  return %0 : tensor<128x64xf32>
}

Listing 6. MLIR linalg.generic. The named op linalg.matmul is equivalent.5

Schedules in MLIR can be written as IR too. The transform dialect holds scripts that match payload operations and apply transformations such as tiling, which gives MLIR a Halide-like schedule language that lives beside the program.34,35 The exact op names have changed between LLVM releases, so check the documentation for your version; a recent form looks like this:

module attributes {transform.with_named_sequence} {
  transform.named_sequence @__transform_main(%root: !transform.any_op {transform.readonly}) {
    %mm = transform.structured.match ops{["linalg.generic"]} in %root
          : (!transform.any_op) -> !transform.any_op
    // Tile i, j, k by 32, 32, 8: produces scf.for loops around a smaller linalg op
    %tiled, %loops:3 = transform.structured.tile_using_for %mm tile_sizes [32, 32, 8]
          : (!transform.any_op) -> (!transform.any_op, !transform.any_op, !transform.any_op, !transform.any_op)
    transform.yield
  }
}

7.4 Triton: blocks as the unit of programming

Triton moves the abstraction up from scalar threads to blocks (tiles) of data. A Triton kernel is written in Python, each program instance operates on whole tiles with operations such as tl.load, tl.dot and tl.store, and the compiler decides how tiles map to threads, shared memory and tensor-core instructions.36,37 In tensor-compiler terms, the programmer chooses the outer tiling and the compiler schedules the intra-tile computation.

8. Sparse tensor compilation

When most entries are zero, storing and computing them is wasteful. Sparse formats keep only the non-zeros plus index metadata. The most common for matrices is compressed sparse row (CSR): an array of non-zero values, an array of their column coordinates, and a row-pointer array marking where each row starts.40

Hand-writing a kernel for every combination of operation and format does not scale. TACO showed that a compiler can instead generate code for any compound tensor algebra expression over any mix of dense and sparse operands, from index notation plus a per-dimension format description.3 Later work generalized formats into a small set of level formats (for example dense, compressed, singleton and hashed), each defined by capabilities such as iteration and lookup, so that CSR, DCSR, COO, CSF and others become compositions of levels.41

8.1 Co-iteration and merge lattices

The heart of sparse compilation is co-iteration: walking several sparse operands together. Multiplication needs only coordinates present in both operands (an intersection), while addition needs coordinates present in either (a union). TACO derives the control flow from a merge lattice, whose points list which operands are still being iterated and which cases a loop must handle as operands run out.3

/* a(i) = b(i) + c(i), b and c sparse: union co-iteration.
   Lattice points: {b,c} -> {b} and {c}. Tested with b={0:1,3:2,5:3}, c={1:10,3:20,7:30}
   giving a={0:1, 1:10, 3:22, 5:3, 7:30}. */
while (pb < nb && pc < nc) {                /* both operands still active */
  int ib = b_crd[pb], ic = c_crd[pc], i = ib < ic ? ib : ic;
  if (ib == i && ic == i) a_val[pa] = b_val[pb] + c_val[pc];
  else if (ib == i)       a_val[pa] = b_val[pb];
  else                    a_val[pa] = c_val[pc];
  a_crd[pa++] = i;
  pb += (ib == i);  pc += (ic == i);
}
while (pb < nb) { a_crd[pa] = b_crd[pb]; a_val[pa++] = b_val[pb++]; }   /* {b} */
while (pc < nc) { a_crd[pa] = c_crd[pc]; a_val[pa++] = c_val[pc++]; }   /* {c} */

8.2 TACO in practice

#include "taco.h"
using namespace taco;

int main() {
  Format csr({Dense, Sparse});                 // rows dense, columns compressed
  Tensor<double> A({512, 512}, csr);
  Tensor<double> x({512}, Format({Dense}));
  Tensor<double> y({512}, Format({Dense}));
  A.insert({0, 3}, 1.0);  A.insert({2, 4}, 7.0);  A.pack();
  for (int j = 0; j < 512; j++) x.insert({j}, 1.0);
  x.pack();

  IndexVar i, j;
  y(i) = A(i, j) * x(j);                       // index notation
  y.compile();  y.assemble();  y.compute();    // generate, allocate, run
}

The same group added workspaces, dense temporaries that turn costly sparse merges into cheap scatters (the trick behind fast sparse matrix–matrix multiplication),44 and a scheduling language for sparse iteration spaces, so that split, reorder and parallelize work on loops over non-zeros, not just dense ranges.39

8.3 Sparsity in MLIR and beyond

MLIR's sparse_tensor dialect brings the same ideas into a general compiler: sparsity is an encoding attribute on an ordinary tensor type, and the sparsifier rewrites linalg operations over annotated tensors into co-iterating loops.42,45 Writing the matmul of Listing 6 with %A : tensor<128x256xf32, #CSR> is enough to get sparse code.

#CSR = #sparse_tensor.encoding<{ map = (i, j) -> (i : dense, j : compressed) }>

Taichi tackles a related problem for simulation and graphics, letting programmers describe hierarchical spatially sparse data structures separately from the computation over them.46

9. Searching the schedule space

Writing schedules by hand demands expertise, so most tensor compilers can also search for them. Only an outline is given here; the companion inference article discusses auto-tuning in more depth.

  • Analytical and heuristic. Polyhedral schedulers such as Pluto solve for transformations directly from dependences.8 Halide's first automatic scheduler used a heuristic over groupings and tile sizes.47
  • Learned cost models with search. AutoTVM searched human-written templates guided by a learned cost model;48 Ansor generated the search space automatically from sketches;9 MetaSchedule expresses the space as probabilistic programs built from schedule primitives;38 and Halide's later autoscheduler used tree search with a cost model trained on random programs.49
  • User-guided. Exo and Halide keep a human in the loop: the engineer writes the schedule, and the compiler guarantees it is correct.2,19

10. Build a toy tensor compiler

The Python program below is a complete, if tiny, tensor compiler. It holds a matrix multiplication as an algorithm (a statement plus an iteration space), applies split, reorder and parallel as schedule primitives in the style of Table 2, and emits C. It was run for this article: the generated 512×512 kernel was compiled with GCC and matched a naive reference exactly.

# minitc.py: a toy tensor compiler with an algorithm/schedule split.
import re
from dataclasses import dataclass

@dataclass
class Loop:
    var: str                 # loop variable name
    extent: int              # trip count
    kind: str = "serial"     # serial | parallel | unroll

class Schedule:
    def __init__(self, dims):              # dims: {"i": 64, "j": 64, "k": 64}
        self.loops = [Loop(v, n) for v, n in dims.items()]
        self.expr = {v: v for v in dims}  # original index -> expression

    def _find(self, var):
        return next(l for l in self.loops if l.var == var)

    def split(self, var, factor):
        l = self._find(var)
        assert l.extent % factor == 0, "toy compiler: perfect splits only"
        outer, inner = Loop(var + "o", l.extent // factor), Loop(var + "i", factor)
        pos = self.loops.index(l)
        self.loops[pos:pos + 1] = [outer, inner]
        for k, e in self.expr.items():        # substitute var := vo*f + vi
            self.expr[k] = re.sub(rf"\b{var}\b", f"({outer.var}*{factor}+{inner.var})", e)
        return outer.var, inner.var

    def reorder(self, *order):
        moved = [self._find(v) for v in order]
        slots = sorted(self.loops.index(l) for l in moved)
        for s, l in zip(slots, moved):
            self.loops[s] = l

    def parallel(self, var): self._find(var).kind = "parallel"
    def unroll(self, var):   self._find(var).kind = "unroll"

def codegen(s, M, N, K):
    i, j, k = s.expr["i"], s.expr["j"], s.expr["k"]
    body = f"C[{i}*{N} + {j}] += A[{i}*{K} + {k}] * B[{k}*{N} + {j}];"
    lines, ind = ["void matmul(const float *A, const float *B, float *C) {"], "  "
    for l in s.loops:
        if l.kind == "parallel": lines.append(ind + "#pragma omp parallel for")
        if l.kind == "unroll":   lines.append(ind + "#pragma GCC unroll 8")
        lines.append(f"{ind}for (int {l.var} = 0; {l.var} < {l.extent}; ++{l.var})")
        ind += "  "
    lines += [ind + body, "}"]
    return "\n".join(lines)

if __name__ == "__main__":
    M = N = K = 512
    s = Schedule({"i": M, "j": N, "k": K})    # algorithm: C[i,j] += A[i,k]*B[k,j]
    io, ii = s.split("i", 32)                  # schedule: 32x32 output tiles,
    jo, ji = s.split("j", 32)                  # k between tile and point loops,
    s.reorder(io, jo, "k", ii, ji)             # contiguous j innermost
    s.parallel(io)
    print(codegen(s, M, N, K))

Running it prints:

void matmul(const float *A, const float *B, float *C) {
  #pragma omp parallel for
  for (int io = 0; io < 16; ++io)
    for (int jo = 0; jo < 16; ++jo)
      for (int k = 0; k < 512; ++k)
        for (int ii = 0; ii < 32; ++ii)
          for (int ji = 0; ji < 32; ++ji)
            C[(io*32+ii)*512 + (jo*32+ji)] += A[(io*32+ii)*512 + k] * B[k*512 + (jo*32+ji)];
}

What it lacks is instructive. It performs no dependence check (reordering is always legal for matmul, but not in general, see Section 4), handles only perfect splits, and never simplifies index arithmetic. Real compilers add exactly these pieces: legality analysis, boundary handling for imperfect tiles, and algebraic simplification before code generation.2,18

12. Exercises with solutions

Exercise 1: index notation

Write a 2D convolution without padding, O of size (H−R+1)×(W−S+1), from input I (H×W) and filter F (R×S) in index notation. Which indices are free and which are reductions? Why can't a plain einsum express it?

Show solution

O(y,x) = I(y+r, x+s) · F(r,s). Free indices: y, x. Reductions: r, s. einsum allows only a single index per subscript position, not an expression like y+r, so convolution needs a richer form such as TVM's compute rules or a linalg.generic with the indexing map (y,x,r,s) -> (y+r, x+s).5,7,12

Exercise 2: dependence distances

For for i in 1..N: for j in 0..N-2: A[i][j] = A[i-1][j+1] * 2; give the distance vector. Is interchanging the loops legal? Is tiling the (i, j) band legal without other changes?

Show solution

Iteration (i, j) reads what (i−1, j+1) wrote, so the distance is (1, −1). Interchange gives (−1, 1), which is lexicographically negative, so it is illegal. The band is not fully permutable because of the −1, so rectangular tiling is illegal too. Skewing j by i (j′ = i + j) turns the distance into (1, 0), after which both interchange and tiling are legal.20,21

Exercise 3: reuse from tiling

In the toy compiler's output (Section 10), one (io, jo) tile keeps a 32×32 block of C. For each value of k, how many elements of A and B are read, and how many multiply–adds are done? What does that ratio become for a T×T tile?

Show solution

For each k, the tile reads 32 elements of A (a column segment) and 32 of B (a row segment), 64 in total, and does 32×32 = 1024 multiply–adds: 16 per element loaded. For a T×T tile it is T² / 2T = T/2 multiply–adds per element loaded, so arithmetic intensity grows linearly with T until the tile no longer fits in fast memory. This is the reasoning behind blocking and the roofline model.4,14,15

Exercise 4: CSR by hand

Encode this matrix in CSR: row 0 = [0 9 0 0], row 1 = [1 0 0 8], row 2 = [0 0 6 0].

Show solution

pos = [0, 1, 3, 4], crd = [1, 0, 3, 2], vals = [9, 1, 8, 6]. Row r occupies positions pos[r] to pos[r+1]−1; pos has one more entry than there are rows.40,41

Exercise 5: merge lattices

For a(i) = b(i) · c(i) + d(i) with b, c, d sparse vectors, which combinations of operands must the generated loops handle, and which while-loops would a TACO-style compiler emit?

Show solution

b·c is non-zero only where both are present (intersection), and + d takes a union with d. The lattice points are {b, c, d} (compute b·c + d or one of its sub-cases at each coordinate), then {b, c} once d is exhausted (only b·c), and {d} once b or c is exhausted (copy d). Once b or c runs out, no further product terms can appear, so the {b, c} loop needs both and the {d} loop finishes the rest.3

Exercise 6: linalg indexing maps

Give the indexing maps and iterator types for a linalg.generic that computes the matrix–vector product y(i) = A(i,j) · x(j).

Show solution

Loops (i, j). Maps: A ↦ (i, j) -> (i, j), x ↦ (i, j) -> (j), y ↦ (i, j) -> (i). Iterator types: ["parallel", "reduction"]. The payload multiplies and accumulates, exactly as in Listing 6.5

Exercise 7: extend the toy compiler

Add a vectorize(var) primitive to minitc.py that emits #pragma omp simd, and schedule ji with it. Why does it make sense for ji but not for k?

Show solution

Add def vectorize(self, var): self._find(var).kind = "vector" and in codegen emit #pragma omp simd when l.kind == "vector". The ji loop accesses C and B at consecutive addresses and has no loop-carried dependence, so its iterations map to SIMD lanes. The k loop carries the reduction into the same C element, so vectorizing it needs a reduction clause and reassociation of floating-point additions.2,20

13. Trivia with answers

1. What do the letters in MLIR stand for?

Multi-Level Intermediate Representation. The "ML" is not machine learning.33

2. What does XLA stand for?

Accelerated Linear Algebra.30

3. What application domain was Halide first designed for?

Image-processing pipelines; its first paper appeared in ACM Transactions on Graphics (SIGGRAPH 2012).6

4. Who described the "hyperplane method" for running DO-loop iterations in parallel, and when?

Leslie Lamport, in Communications of the ACM in 1974, a precursor of wavefront parallelization and polyhedral scheduling.22

5. In which paper did the "Einstein summation convention" first appear?

Einstein's 1916 paper on the foundations of general relativity, which introduced dropping the summation sign over repeated indices.11

6. What is the name of the polyhedral optimizer built into LLVM?

Polly.27

7. What does TACO stand for?

The Tensor Algebra COmpiler.3,43

8. Which institution did Triton's original MAPL 2019 paper come from?

Harvard University (Tillet, Kung and Cox).36

9. Which three-way trade-off did the Halide PLDI 2013 paper put at the centre of scheduling?

Parallelism, locality and redundant recomputation.2

10. What is the "isl" in many polyhedral tools?

The integer set library, by Sven Verdoolaege.24

11. In MLIR's sparse_tensor encoding, what level type marks the columns of a CSR matrix?

compressed, with the rows marked dense.42

12. What does the "SSR" in TVMScript's T.axis.remap("SSR", ...) mean?

Spatial, spatial, reduction: the kinds of the three block iterators.18,32

14. Glossary

Affine
Linear in loop indices and parameters plus a constant, for example 2i + j − 1.
Co-iteration
Iterating over several sparse operands at once, by intersection or union of their coordinates.
Distance vector
The iteration difference between the source and sink of a dependence, one entry per loop.
Fully permutable band
A group of loops that can be put in any order, and therefore tiled, without breaking dependences.
Iteration domain
The set of integer points at which a statement executes.
Level format
A per-dimension storage scheme (dense, compressed, singleton…) composed to build tensor formats.
Merge lattice
A structure describing the cases a co-iteration loop must handle as operands are exhausted.
Schedule
The specification of loop order, tiling, parallelism and storage for an algorithm, or an affine map from iterations to time in the polyhedral model.
Structured operation
An MLIR op whose loop structure is described by indexing maps and iterator types, such as linalg.generic.
Tensorize
Replace a loop sub-nest with a hardware tensor instruction.
Tiling (blocking)
Splitting loops so that a block of the iteration space runs together to reuse data in fast memory.
