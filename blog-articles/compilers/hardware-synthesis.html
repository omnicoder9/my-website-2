Hardware Synthesis: Compiling Descriptions into Circuits

Hardware synthesis is the compiler problem in silicon. A synthesis tool reads a hardware description, optimises it, and emits a netlist of real gates, flip-flops or FPGA lookup tables. This article walks through the whole flow, from HDL source to a mapped netlist, with worked examples, runnable source code, the main open-source and commercial tools, exercises and trivia. 1. Core concepts: synthesis as compilation

De Micheli defines circuit synthesis as the process of producing a detailed structural representation of a circuit from a more abstract model, while optimising figures of merit such as area, delay and power 14. That is the same contract a software compiler keeps: translate a program into a lower-level form, preserve its meaning, and make the result better along some cost model 15. The differences lie in the target. A software compiler emits instructions that execute one after another. A synthesis tool emits a graph of hardware that all operates at the same time, so "meaning" includes cycle-by-cycle behaviour at the registers.

Synthesis is usually divided into levels of abstraction 14:

  • Architectural or high-level synthesis turns an algorithm into a register-transfer design by deciding which operations happen in which clock cycle (scheduling) and on which hardware unit (allocation and binding) 1.
  • RTL (logic-level) synthesis turns a register-transfer description, where registers and the combinational logic between them are explicit, into a network of logic gates and storage elements 14,16.
  • Logic optimisation rewrites the Boolean network to reduce cost 17.
  • Technology mapping covers the optimised network with the cells actually available: a standard-cell library for an ASIC, or lookup tables (LUTs) and flip-flops for an FPGA 13,18.

2. Hardware description languages and RTL

The two dominant HDLs are Verilog and VHDL. Verilog was designed at Gateway Design Automation in the mid-1980s and was first standardised as IEEE 1364-1995 20,27. VHDL came out of the United States Department of Defense VHSIC programme and was first standardised as IEEE 1076-1987 22. SystemVerilog (IEEE 1800) added verification and design features, and since the 2009 revision it includes Verilog as a subset 21.

Both languages describe far more than hardware can build: delays such as #5, file I/O and most of the testbench constructs simulate but cannot be synthesised. IEEE 1364.1 defines the synthesisable subset of Verilog and how each construct should map to hardware 16. Designers therefore write at the register-transfer level (RTL): explicit registers, updated on clock edges, with combinational logic between them 14.

Listing 1. A 4-bit counter in Verilog

// counter4.v : 4-bit up counter with synchronous reset and enable
module counter4 (
    input  wire       clk,
    input  wire       rst,     // synchronous, active high
    input  wire       en,
    output reg  [3:0] q
);
    always @(posedge clk) begin
        if (rst)
            q <= 4'd0;
        else if (en)
            q <= q + 4'd1;
    end
endmodule

Listing 2. The same counter in VHDL

-- counter4.vhd
library ieee;
use ieee.std_logic_1164.all;
use ieee.numeric_std.all;

entity counter4 is
  port (clk, rst, en : in  std_logic;
        q            : out unsigned(3 downto 0));
end entity;

architecture rtl of counter4 is
  signal cnt : unsigned(3 downto 0) := (others => '0');
begin
  process (clk) begin
    if rising_edge(clk) then
      if rst = '1' then
        cnt <= (others => '0');
      elsif en = '1' then
        cnt <= cnt + 1;
      end if;
    end if;
  end process;
  q <= cnt;
end architecture;

Both listings describe the same hardware: four D flip-flops, a 4-bit incrementer, and multiplexing for reset and enable. The edge-triggered process is what tells the tool to infer flip-flops 16,22.

Blocking and non-blocking assignment

Verilog has two assignment operators inside always blocks. A blocking assignment (=) updates its target immediately; a non-blocking assignment (<=) schedules the update for the end of the time step 20. Cummings' widely cited guideline is to use non-blocking assignments for sequential logic and blocking assignments for combinational logic, because mixing them up makes simulation disagree with the synthesised hardware 28.

// Intended: a 3-stage shift register
always @(posedge clk) begin   // correct: non-blocking
    s1 <= d;  s2 <= s1;  s3 <= s2;
end

always @(posedge clk) begin   // wrong: blocking
    s1 = d;   s2 = s1;   s3 = s2;   // all three get d in one cycle
end

With blocking assignments each statement sees the value just written by the previous one, so the "shift register" collapses into one stage. Synthesis then builds a single register driving three outputs 28.

3. Elaboration and inference

After parsing, the tool elaborates the design: it binds parameters, unrolls generate loops, and builds the module hierarchy 21. It then infers hardware from behavioural code. The IEEE 1364.1 standard gives the rules: an assignment inside an edge-sensitive process becomes a flip-flop; a variable that a level-sensitive process does not assign on every path becomes a latch; an if or case becomes a multiplexer 16.

Yosys makes these steps visible as separate passes. hierarchy resolves the module tree, proc converts processes into multiplexers and flip-flop cells, fsm extracts and re-encodes state machines, memory infers RAMs, and opt removes redundant cells 19. Its internal representation, RTLIL, keeps word-level cells such as $add and $mux until later passes lower them to single-bit gates 4,29.

Listing 3. An accidental latch, and the fix

// BAD: y is not assigned when sel == 2'b11, so a latch is inferred
always @(*) begin
    case (sel)
        2'b00: y = a;
        2'b01: y = b;
        2'b10: y = c;
    endcase
end

// GOOD: a default assignment makes the block purely combinational
always @(*) begin
    y = 1'b0;
    case (sel)
        2'b00: y = a;
        2'b01: y = b;
        2'b10: y = c;
    endcase
end

In the first block y must "remember" its old value when sel is 3, which is exactly what a latch does 16. Most tools warn about inferred latches; Vivado's synthesis guide lists them among coding issues to check 5.

Finite-state machines

Finite-state machines (FSMs) are the sequential-logic equivalent of a control-flow graph. Huffman's 1954 paper laid out a systematic method for synthesising sequential switching circuits, including state reduction 30. Modern tools detect FSMs in RTL and may re-encode them: binary encoding uses ⌈log2 n⌉ flip-flops for n states, while one-hot uses n flip-flops but simpler next-state logic 14. Vivado exposes the choice through the fsm_encoding attribute, with values such as one_hot, sequential, gray and johnson 5, and Yosys provides fsm_recode 19.

Listing 4. The "101" detector in Verilog

module seq101 (
    input  wire clk, rst, din,
    output wire hit
);
    localparam S0 = 2'd0, S1 = 2'd1, S2 = 2'd2, S3 = 2'd3;
    reg [1:0] state, next;

    always @(posedge clk)            // state register
        state <= rst ? S0 : next;

    always @(*) begin                 // next-state logic
        next = state;                 // default avoids a latch
        case (state)
            S0: next = din ? S1 : S0;
            S1: next = din ? S1 : S2;
            S2: next = din ? S3 : S0;
            S3: next = din ? S1 : S2;
        endcase
    end

    assign hit = (state == S3);       // Moore output
endmodule

The two-process style (one clocked block, one combinational block) is the pattern FSM extractors look for 5,19.

4. Boolean optimisation

Once the design is a network of gates, synthesis becomes a problem in Boolean algebra. Shannon's 1938 paper showed that relay switching circuits could be analysed and simplified with Boolean algebra, which is the foundation for everything in this section 31.

Two-level minimisation

A two-level circuit is a sum of products (SOP): an OR of AND terms. Minimising one means finding the fewest, smallest product terms that cover all the function's ones. Karnaugh's 1953 map method arranges the truth table in Gray-code order so that adjacent cells differ in one variable, letting people spot groupings by eye 32. Quine and McCluskey turned the same idea into an algorithm: generate every prime implicant by repeatedly merging terms that differ in one bit, then choose a minimum set that covers all minterms 33,34. The covering step is NP-hard in general, so industrial tools use heuristics; Espresso, developed at IBM and Berkeley, became the standard heuristic two-level minimiser 10,35.

Listing 5. Quine–McCluskey prime implicants in Python

This short program implements the first, prime-generating half of the Quine–McCluskey method 33,34. Running it on the function in Figure 3 prints the two prime implicants -0-0 b'd' and -1-1 bd.

from itertools import combinations

def combine(a, b):
    """Merge two implicants (strings over 0/1/-) that differ in one bit."""
    diff = [i for i in range(len(a)) if a[i] != b[i]]
    if len(diff) == 1 and '-' not in (a[diff[0]], b[diff[0]]):
        i = diff[0]
        return a[:i] + '-' + a[i+1:]
    return None

def prime_implicants(minterms, n):
    terms = {format(m, f'0{n}b') for m in minterms}
    primes = set()
    while terms:
        used, nxt = set(), set()
        for a, b in combinations(sorted(terms), 2):
            c = combine(a, b)
            if c:
                nxt.add(c); used.update((a, b))
        primes |= terms - used
        terms = nxt
    return primes

def covers(imp, m, n):
    bits = format(m, f'0{n}b')
    return all(p in ('-', q) for p, q in zip(imp, bits))

def to_expr(imp, names):
    lits = [v if b == '1' else v + "'" for v, b in zip(names, imp) if b != '-']
    return ''.join(lits) or '1'

if __name__ == '__main__':
    names, ms = 'abcd', [0, 2, 5, 7, 8, 10, 13, 15]
    for p in sorted(prime_implicants(ms, 4)):
        print(p, to_expr(p, names), [m for m in ms if covers(p, m, 4)])

Implicants are strings over 0, 1 and - (don't care). Two implicants merge when they differ in exactly one fixed bit; an implicant that never merges is prime. Tested with Python 3.

Multi-level logic and and-inverter graphs

Real circuits are rarely two-level. Multi-level synthesis factors common subexpressions so that logic is shared, trading depth for area. Berkeley's MIS and SIS systems made this style of optimisation standard in the late 1980s and early 1990s 9,17. Their successor in wide use today is ABC, which represents logic as an and-inverter graph (AIG): every node is a two-input AND, and edges may carry an inversion 8. Because AND and NOT form a complete basis, any Boolean function can be expressed this way, and the uniform structure makes rewriting fast 8,23.

Three ABC passes do most of the work. rewrite replaces small subgraphs, typically 4-input cuts, with precomputed smaller equivalents; refactor collapses a larger cone and re-factors it; and balance reduces depth by rebalancing chains of ANDs 11,24. Mishchenko, Chatterjee and Brayton's DAG-aware rewriting accounts for logic sharing, so a rewrite is accepted only if the whole graph shrinks 24.

Binary decision diagrams

Bryant's reduced ordered binary decision diagrams (BDDs) give a canonical form for a Boolean function once the variable order is fixed: two functions are equal exactly when their BDDs are the same graph 36. That makes BDDs powerful for equivalence checking and some optimisations, but their size depends heavily on the variable order and some functions, such as multiplication, have no small BDD under any order 36. Modern equivalence checkers therefore combine AIGs with SAT solving and use BDDs only where they stay small 23.

5. Technology mapping

Technology mapping is synthesis's instruction selection. The optimised network is expressed in a technology-independent form, and the mapper chooses which available cells cover it at lowest cost 14. Keutzer's DAGON split the subject graph into trees and applied tree-pattern matching borrowed from compiler code generators, which gives an optimal cover for each tree 13.

The two main targets need different mappers:

  • ASIC standard cells. The library is a fixed set of gates (NAND2, NOR3, AOI21, flip-flops, and so on), each with area, delay and power characterised in a Liberty (.lib) file 37,38. The mapper matches library patterns against the subject graph and picks the cheapest cover.
  • FPGA lookup tables. A K-input LUT is a small memory that can implement any function of K inputs, so matching is replaced by finding cuts: sets of at most K signals that separate a node from the primary inputs 12,18. Cong and Ding's FlowMap computes a depth-optimal K-LUT mapping in polynomial time 18, and ABC's priority-cut mapper adds area recovery 12.

The LUT size is a property of the device. AMD (Xilinx) 7-series FPGAs have six-input LUTs, four per slice, and each can also act as two five-input LUTs that share inputs 39. Lattice iCE40 devices use four-input LUTs, each paired with a flip-flop and carry logic in a logic cell 40. Arithmetic is usually not mapped into LUTs alone: synthesis tools infer the dedicated carry chains and DSP blocks the fabric provides 5,39.

6. Sequential and timing-driven synthesis

Area is not the only cost. Most designs must meet a clock frequency, so synthesis is guided by static timing analysis (STA). STA computes, for every path from a launching register to a capturing register, the arrival time of the data and compares it with the required time set by the clock period and the capturing flip-flop's setup time. The difference is the slack; a negative slack is a timing violation 38. Constraints are written in SDC (Synopsys Design Constraints), a Tcl-based format that commercial and open-source tools accept; Vivado's XDC is based on it 5,38.

Retiming

Leiserson and Saxe showed that registers can be moved across combinational logic without changing a circuit's input-output behaviour, and gave graph algorithms that find the register placement minimising clock period 25. Retiming is the hardware counterpart of software pipelining: it rebalances the work between pipeline stages. Vivado can apply it during synthesis with synth_design -retiming 5,41, and ABC provides sequential commands such as retime 11.

Formal equivalence checking

A compiler bug in software produces a wrong program; a synthesis bug produces a wrong chip, which is far more expensive. Teams therefore check that the netlist is functionally equivalent to the RTL. Combinational equivalence checking builds a miter, which XORs the outputs of the two designs, and proves that the miter output can never be 1, using AIGs, SAT and BDDs together 23. ABC's cec command does this for combinational logic 8, Yosys offers an equiv_* family of passes 19, and SymbiYosys drives formal property checking on top of Yosys 42.

Yosys open-source RTL synthesis

Yosys (Yosys Open SYnthesis Suite) was created by Claire Wolf and first presented in 2013 29. It parses Verilog-2005 with a useful subset of SystemVerilog, converts it to its RTLIL intermediate representation, and runs a script of passes 4. The generic synth command chains the coarse-grained passes (proc, opt, fsm, memory, alumacc, share) with fine-grained lowering (techmap) and calls ABC for logic optimisation and mapping 19. Target-specific scripts such as synth_ice40, synth_ecp5 and synth_xilinx map to particular FPGA families 19.

Listing 6. A Yosys script for a generic ASIC library

# asic.ys : run with  yosys -s asic.ys
read_verilog counter4.v
hierarchy -check -top counter4
synth -top counter4          # generic coarse + fine synthesis
dfflibmap -liberty cells.lib # map flip-flops to library cells
abc -liberty cells.lib       # optimise and map combinational logic
opt_clean
stat -liberty cells.lib      # area report from library data
write_verilog -noattr counter4_netlist.v

dfflibmap and abc -liberty are the documented way to target a standard-cell library in Yosys 19. cells.lib stands for any Liberty file, for example one from the SKY130 open PDK 52.

Listing 7. Verilog to bitstream on a Lattice iCE40

# 1. synthesise to iCE40 primitives (SB_LUT4, SB_CARRY, SB_DFF*)
yosys -p "synth_ice40 -top counter4 -json counter4.json" counter4.v

# 2. place and route; pins come from a .pcf constraints file
nextpnr-ice40 --hx8k --package ct256 --json counter4.json \
              --pcf counter4.pcf --asc counter4.asc

# 3. pack the ASCII configuration into a binary bitstream
icepack counter4.asc counter4.bin

This fully open flow was described by Shah et al. and builds on the reverse-engineered bitstream documentation of Project IceStorm 43,53.

ABC logic synthesis and verification

ABC, from the Berkeley Logic Synthesis and Verification Group, combines AIG-based combinational and sequential optimisation, technology mapping for standard cells and LUTs, and equivalence and model checking in one program 8,11. Yosys, VTR and OpenROAD-based flows all call it for the bit-level part of synthesis 19,44,49.

Listing 8. An ABC session that optimises and maps to 4-LUTs

read_blif design.blif
strash                    # build a structurally hashed AIG
print_stats
# the "resyn2" recipe written out in full:
balance; rewrite; refactor; balance; rewrite; rewrite -z
balance; refactor -z; rewrite -z; balance
print_stats
if -K 4                   # cut-based mapping to 4-input LUTs
print_stats
write_blif design_mapped.blif

strash, rewrite, refactor, balance and if are documented ABC commands; the -z flag also accepts zero-gain rewrites, which can open up later improvements 11,12,24.

AMD Vivado FPGA synthesis and implementation

Vivado synthesises Verilog, SystemVerilog and VHDL for AMD (formerly Xilinx) FPGAs and controls inference with HDL attributes such as fsm_encoding, ram_style and use_dsp 5. Its Tcl interface supports a "non-project" mode in which a script drives each step explicitly 41.

Listing 9. Vivado non-project Tcl flow

# build.tcl : vivado -mode batch -source build.tcl

synth_design -top counter4 -part xc7a35tcpg236-1

report_timing_summary -file timing.rpt
write_bitstream -force counter4.bit

Every command in Listing 9 is documented in the Vivado Tcl reference 41. The part number is an Artix-7 device used on common teaching boards.

Synopsys Design Compiler ASIC RTL synthesis

Design Compiler is Synopsys's long-standing ASIC synthesis tool; the product family now sits within Synopsys's RTL synthesis portfolio 6. It reads RTL, maps it to the standard cells in the target library, and optimises against SDC timing constraints 6,38. Cadence Genus fills the same role in the Cadence flow 7.

Listing 10. A Design Compiler script with SDC constraints

# dc.tcl : dc_shell -f dc.tcl
set_app_var target_library "stdcells_tt.db"
set_app_var link_library   "* stdcells_tt.db"

analyze -format sverilog counter4.v
elaborate counter4
link

# --- SDC timing constraints ---
create_clock -name clk -period 2.0 [get_ports clk]
set_input_delay  0.3 -clock clk [remove_from_collection [all_inputs] [get_ports clk]]
set_output_delay 0.3 -clock clk [all_outputs]

compile_ultra
report_qor
report_timing -max_paths 5
write -format verilog -hierarchy -output counter4_netlist.v
write_sdc counter4_out.sdc

create_clock, set_input_delay and set_output_delay are standard SDC commands, which Bhasker and Chadha describe in detail 38. The library name is a placeholder for a vendor's compiled Liberty file.

Other tools place and route, simulation, research

  • nextpnr is a portable, timing-driven FPGA place-and-route tool that supports Lattice iCE40 and ECP5 among other architectures 43,48.
  • VTR (Verilog to Routing) is an academic flow that combines a Verilog front end, ABC and the VPR placer and router, and lets researchers describe hypothetical FPGA architectures 49.
  • OpenROAD is an open-source RTL-to-GDSII flow that uses Yosys for synthesis and aims at layout without human intervention 44. Combined with the SkyWater SKY130 open process design kit it can produce manufacturable layouts 52.
  • Verilator compiles synthesisable Verilog into a fast cycle-based C++ model, and Icarus Verilog is an event-driven simulator; both are used to check designs before and after synthesis 50,51.

9. A short note on high-level synthesis

High-level synthesis is covered in depth in a separate article in this series. This section only places it in the overall flow.

High-level synthesis (HLS) sits one level above RTL synthesis. It takes an untimed algorithm, usually C or C++, and produces RTL by performing three core tasks: scheduling (assigning operations to clock cycles), allocation (choosing how many functional units of each kind to build) and binding (assigning each operation to a unit and each value to a register) 1. The RTL it produces then goes through the logic synthesis flow described above. Examples include AMD Vitis HLS, which accepts C and C++ with pragmas for pipelining and interfaces 2, and the open-source Bambu framework 3. Nane et al. compared academic and commercial HLS tools and found that results vary widely with the tool and the optimisations applied 54.

10. Beyond HDLs: hardware construction languages and MLIR

Hardware construction languages embed hardware description inside a general-purpose language so that generators, not hand-written modules, produce the RTL. Chisel is embedded in Scala 55, and its compiler lowers designs through the FIRRTL intermediate representation, which applies compiler-style transformation passes to circuits 56. Amaranth embeds hardware description in Python 57. CIRCT, an LLVM project, applies the MLIR compiler infrastructure to hardware, providing dialects for FIRRTL, RTL structure and SystemVerilog emission 58. These projects make the link between hardware synthesis and compiler construction explicit: they reuse IR design, pass managers and rewriting frameworks from software compilers.

Listing 11. The 4-bit counter in Chisel

import chisel3._

class Counter4 extends Module {
  val io = IO(new Bundle {
    val en = Input(Bool())
    val q  = Output(UInt(4.W))
  })
  val cnt = RegInit(0.U(4.W))      // implicit clock and synchronous reset
  when (io.en) { cnt := cnt + 1.U }
  io.q := cnt
}

Chisel modules have an implicit clock and reset, and RegInit creates a register with a reset value 55. The generated Verilog is equivalent to Listing 1.

11. Exercises with solutions

Try each exercise before opening its solution.

Exercise 1 · Spot the latch

Which of these combinational blocks infers a latch, and why?

// (A)
always @(*) if (en) y = d;
// (B)
always @(*) begin y = 1'b0; if (en) y = d; end
// (C)
always @(*) y = en ? d : 1'b0;

Only (A). When en is 0, y is not assigned, so it must hold its previous value, which is the behaviour of a level-sensitive latch 16. (B) assigns a default first, and (C) assigns on both branches of the conditional, so both are purely combinational AND gates.

Exercise 2 · Quine–McCluskey by hand

Find all prime implicants of f(a,b,c) = Σm(0, 1, 2, 5, 6, 7), then give a minimum sum of products.

The prime implicants are a′b′ (m0, m1), a′c′ (m0, m2), b′c (m1, m5), bc′ (m2, m6), ac (m5, m7) and ab (m6, m7). Every minterm is covered by exactly two primes, so there are no essential primes; this is a cyclic covering problem 34. Two minimum covers each use three terms: f = a′b′ + bc′ + ac, or f = a′c′ + b′c + ab. Running Listing 5 with prime_implicants([0,1,2,5,6,7], 3) prints the same six primes.

Exercise 3 · Count the AIG nodes

How many two-input AND nodes does a direct AIG translation of the unfactored sum of products ab + ac + bc need, and how many does the factored form in Figure 4 need?

Unfactored: three ANDs for the product terms, then a three-input OR, which in an AIG is two ANDs with complemented inputs and output (De Morgan). That totals 5 nodes. Factored ab + c(a + b): one AND for ab, one for a + b (as ¬(¬a ∧ ¬b)), one for c ∧ (a + b), and one for the final OR, totalling 4 23. Rewriting passes such as ABC's rewrite find this kind of saving automatically 24.

Exercise 4 · LUT counting

An 8-input AND gate must be mapped to (a) 4-input LUTs and (b) 6-input LUTs. What is the minimum number of LUTs and the logic depth in each case?

(a) A 4-LUT can absorb at most four inputs, so the first level needs two LUTs (inputs 1 to 4 and 5 to 8), and a third LUT ANDs their outputs: 3 LUTs, depth 2. (b) One 6-LUT takes six inputs; a second LUT combines its output with the remaining two inputs (three inputs in total): 2 LUTs, depth 2. One LUT is impossible in both cases because the function depends on eight inputs, more than K. This illustrates why depth-optimal mapping such as FlowMap reasons about K-feasible cuts 18.

Exercise 5 · Slack and maximum frequency

Using Figure 6 (tcq = 0.3 ns, tlogic = 3.9 ns, tsetup = 0.2 ns), what is the highest clock frequency this path supports? If the clock is tightened to 4 ns, what is the slack?

The minimum period is tcq + tlogic + tsetup = 4.4 ns, so fmax = 1 / 4.4 ns ≈ 227 MHz. At a 4 ns period, required time is 4.0 − 0.2 = 3.8 ns and arrival is 4.2 ns, so slack is −0.4 ns, a violation 38. Synthesis would respond by restructuring or upsizing logic on this path, or retiming could move a register into the logic 25.

Exercise 6 · FSM encoding

A controller has 10 states. How many flip-flops does it need with binary, Gray and one-hot encoding? Why might an FPGA tool still prefer one-hot?

Binary and Gray both need ⌈log2 10⌉ = 4 flip-flops; one-hot needs 10. FPGAs have a flip-flop next to every LUT, so the extra registers are almost free, while one-hot next-state and output logic depends on few signals and maps into small, shallow LUT networks 14,39. Vivado lets you choose with the fsm_encoding attribute 5.

Exercise 7 · Write the LUT INIT value

Write the 8-bit INIT value for a LUT3 that computes the full-adder sum s = a ⊕ b ⊕ c, with address bit 0 = a, bit 1 = b, bit 2 = c.

Sum is 1 when an odd number of inputs are 1, that is at addresses 1, 2, 4 and 7. Setting those bits gives binary 1001 0110, which is 8'h96. (For comparison, the carry in Figure 5 is 8'hE8, with ones at addresses 3, 5, 6 and 7.) A full adder therefore needs two LUT3s, or one fractured LUT6 on a 7-series device 39.

Exercise 8 · Blocking versus non-blocking

A designer writes a two-stage synchroniser as always @(posedge clk) begin q1 = d; q2 = q1; end. How many flip-flops will synthesis build, and how do you fix it?

Because q1 = d takes effect immediately, q2 receives d in the same cycle, so the circuit has one stage of delay instead of two; the tool may build a single flip-flop feeding both names. Using non-blocking assignments, q1 <= d; q2 <= q1;, gives the intended two flip-flops in series 20,28.

12. Trivia with answers

1. Whose 1938 paper first applied Boolean algebra to switching circuits?

Claude Shannon, in "A symbolic analysis of relay and switching circuits", based on his MIT master's thesis 31.

2. Where was Maurice Karnaugh working when he published the map method?

At Bell Telephone Laboratories; the 1953 paper refined Veitch's earlier chart into the Karnaugh map 32.

3. What does the name "Yosys" stand for?

It is a recursive acronym: Yosys Open SYnthesis Suite 4,29.

4. How many distinct Boolean functions can a single 4-input LUT implement?

A 4-LUT stores 24 = 16 configuration bits, so it can implement 216 = 65,536 functions, which is every possible 4-input function 18.

5. Which software-compiler technique did DAGON borrow for technology mapping?

Tree-pattern matching from code generators, the approach used for instruction selection 13,15.

6. What is special about a reduced ordered BDD?

For a fixed variable order it is canonical: equal functions have identical graphs, so equivalence is a pointer comparison 36.

7. Roughly how much larger was soft FPGA logic than a standard-cell ASIC in Kuon and Rose's 90 nm study?

About 35 times the area for logic-only designs 45.

8. Which organisation's programme gave rise to VHDL?

The United States Department of Defense, through its Very High Speed Integrated Circuits (VHSIC) programme; the "V" in VHDL stands for VHSIC 22.

9. What is a "miter" in equivalence checking?

A circuit that feeds the same inputs to two designs and XORs (then ORs) their outputs. The designs are equivalent if and only if the miter output is constant 0 23.

10. Which IEEE standard defines the synthesisable subset of Verilog?

IEEE 1364.1, the standard for Verilog register-transfer-level synthesis 16.

Further reading. De Micheli's textbook remains the standard reference for synthesis algorithms 14, Hachtel and Somenzi cover logic synthesis and verification in depth 17, and Mano and Ciletti give an accessible introduction to digital design with HDLs 59. Mead and Conway's text is the classic account of the structured VLSI design style that made automated synthesis practical 60.
