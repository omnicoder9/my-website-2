1. Core concepts: the shape of a compiler

A compiler translates a program from a source language into a target language while preserving its meaning. Textbook treatments divide this work into phases: lexical analysis, syntax analysis, semantic analysis, intermediate code generation, machine-independent optimisation, and target code generation 1. In practice the phases are grouped into three parts.

  • Front end. Reads source text, turns it into tokens (scanning), builds a syntax tree (parsing), and checks types and names. Flex, Bison, ANTLR and Clang live here.
  • Middle end (optimiser). Works on a language- and machine-neutral intermediate representation (IR) and applies transformations such as constant propagation, inlining and dead-code elimination. LLVM IR, GCC's GIMPLE and MLIR live here.
  • Back end. Selects machine instructions, allocates registers and emits assembly or object code. LLVM's code generator, GCC's RTL passes, Cranelift, QBE and Jasmin live here.

Key ideas you will meet repeatedly

Regular expressions and finite automata
Token patterns are regular languages. Scanner generators compile a list of regular expressions into a single deterministic finite automaton (DFA) that finds the longest match 1,15.
Context-free grammars and parsing strategies
Program structure is described by a context-free grammar. Bottom-up LR-family parsers (Yacc, Bison) shift tokens onto a stack and reduce them by grammar rules; top-down LL-family parsers (ANTLR) predict which rule to expand 1,12.
Static single assignment (SSA)
An IR form in which every variable is assigned exactly once, and φ (phi) functions merge values where control flow joins. SSA makes many optimisations simpler and faster 30. LLVM IR, MLIR, Cranelift IR and QBE IL all use SSA 5,20,22,25.
Basic blocks and control-flow graphs
A basic block is a straight-line instruction sequence with one entry and one exit, ending in a terminator such as a branch or return. Functions are graphs of blocks 1,5.
Lowering
Translating from a higher-level representation to a lower-level one, for example from an AST to IR, or from IR to machine instructions.

2. Front-end generators: Flex, Bison, ANTLR

Flex lexical analyser generator

Flex ("fast lexical analyser generator") reads a specification of regular expressions paired with C actions and writes a C source file, lex.yy.c, that defines a scanning function yylex() 15. It is a free reimplementation of the original Unix lex, which Mike Lesk and Eric Schmidt described at Bell Labs in 1975 16. The Flex manual credits Vern Paxson as its principal author 15.

A Flex file has three sections separated by %%: definitions, rules, and user code. When several patterns could match, Flex picks the longest match; on a tie, the rule listed first wins 15.

/* calc.l : scanner for a tiny calculator */
%{
#include <stdlib.h>
#include "calc.tab.h"      /* token codes generated by Bison */
%}
%option noyywrap

%%
[0-9]+        { yylval = atoi(yytext); return NUM; }
[-+*/()\n]    { return yytext[0]; }   /* single-char tokens */
[ \t]+        { /* skip whitespace */ }
.             { fprintf(stderr, "bad char: %s\n", yytext); }
%%

Listing 1. A Flex specification. yytext holds the matched text and yylval passes the token's value to the parser.

Bison parser generator

GNU Bison converts an annotated context-free grammar into a C (or C++, Java, D) parser 18. It is upward compatible with Yacc ("Yet Another Compiler-Compiler"), which Stephen C. Johnson wrote at Bell Labs 17,18. By default Bison builds LALR(1) tables; it can also generate IELR(1) or canonical LR(1) tables, and Generalised LR (GLR) parsers for grammars that are ambiguous or need more lookahead 18.

/* calc.y : grammar for the calculator */
%{
#include <stdio.h>
int  yylex(void);
void yyerror(const char *s) { fprintf(stderr, "%s\n", s); }
%}

%token NUM
%left '+' '-'          /* lowest precedence  */
%left '*' '/'
%precedence NEG        /* unary minus, highest */

%%
input : %empty
      | input line
      ;
line  : '\n'
      | expr '\n'              { printf("= %d\n", $1); }
      ;
expr  : NUM
      | expr '+' expr          { $$ = $1 + $3; }
      | expr '-' expr          { $$ = $1 - $3; }
      | expr '*' expr          { $$ = $1 * $3; }
      | expr '/' expr          { $$ = $1 / $3; }
      | '-' expr %prec NEG     { $$ = -$2; }
      | '(' expr ')'           { $$ = $2; }
      ;
%%
int main(void) { return yyparse(); }

Listing 2. A Bison grammar. $$ is the value of the rule's left side; $1, $2… are the values of the symbols on the right. %left and %precedence resolve the shift/reduce conflicts of this ambiguous expression grammar 18.

$ bison -d calc.y        # writes calc.tab.c and calc.tab.h
$ flex calc.l            # writes lex.yy.c
$ cc -o calc calc.tab.c lex.yy.c
$ echo "2 + 3 * (4 - 1)" | ./calc
= 11

ANTLR ALL(*) parser generator

ANTLR ("ANother Tool for Language Recognition") is a parser generator by Terence Parr that reads one grammar and generates both a lexer and a parser, plus tree listeners and visitors for walking the parse tree 13,14. ANTLR 4 uses the Adaptive LL(*), or ALL(*), algorithm, which does grammar analysis at parse time rather than ahead of time. This lets it accept any non-left-recursive context-free grammar, and ANTLR 4 additionally rewrites direct left recursion such as e : e '*' e automatically 12. The tool is written in Java, but it can generate parsers for many targets, including Java, C#, Python 3, JavaScript, TypeScript, Go, C++, Swift, PHP and Dart 14.

// Expr.g4 : the same calculator in ANTLR 4
grammar Expr;

prog : stat+ EOF ;
stat : expr NEWLINE                 # printExpr
     | NEWLINE                      # blank
     ;
expr : '-' expr                     # neg
     | expr op=('*'|'/') expr       # mulDiv
     | expr op=('+'|'-') expr       # addSub
     | INT                          # int
     | '(' expr ')'                 # parens
     ;

INT     : [0-9]+ ;
NEWLINE : '\r'? '\n' ;
WS      : [ \t]+ -> skip ;

Listing 3. Alternatives listed earlier bind tighter, so * beats +. The # labels give each alternative its own visitor method.

$ antlr4 -Dlanguage=Python3 -visitor Expr.g4
$ antlr4-parse Expr.g4 prog -tree     # quick test with the ANTLR tools package
Flex/Bison or ANTLR? Flex and Bison produce small, fast C code and give you exact control over LR conflicts. ANTLR gives one grammar file for lexer and parser, readable recursive-descent output, automatic parse trees, and many target languages. Hand-written recursive descent remains common in production compilers: both Clang and GCC's C and C++ front ends use hand-written parsers 11,9.

3. Industrial compilers: GCC, LLVM, Clang

GCC GNU Compiler Collection

Richard Stallman started GCC as the GNU C Compiler; its first beta release was on 22 March 1987 7. It has since become the GNU Compiler Collection, with front ends for C, C++, Objective-C, Fortran, Ada, Go, D and Modula-2 6, and a COBOL front end added in GCC 15 8. GCC is the system compiler on most GNU/Linux distributions and supports a very wide range of processor architectures.

Internally, GCC passes code through three main representations 9:

  1. GENERIC, a language-independent tree form produced by each front end;
  2. GIMPLE, a simplified three-address form (at most three operands per statement) used by the tree-SSA optimisers;
  3. RTL (Register Transfer Language), a low-level, Lisp-like form used for instruction selection, scheduling and register allocation.
$ gcc -O2 -fdump-tree-gimple -fdump-tree-optimized -fdump-rtl-expand -c square.c
$ ls square.c.*
square.c.006t.gimple   square.c.2xxt.optimized   square.c.2xxr.expand

Listing 4. GCC's -fdump-* options write each pass's IR to a file so you can watch the lowering happen 6. Exact pass numbers differ between GCC versions.

LLVM compiler infrastructure

LLVM began in 2000 as a research project at the University of Illinois led by Chris Lattner and Vikram Adve 2,3. Its central idea is a well-specified, typed, SSA-based intermediate representation, LLVM IR, which is used throughout the life of a program and can be stored as text (.ll) or compact bitcode (.bc) 3,5. The name was once short for "Low Level Virtual Machine", but the project now says it is not an acronym but the full name of the project 2. In 2012 LLVM received the ACM Software System Award 2.

LLVM is built as a set of reusable libraries. The main command-line tools are opt (run IR passes), llc (IR to assembly or object code), lli (interpret or JIT IR), and lld (linker). Front ends for Swift, Rust, Julia, Zig and many other languages produce LLVM IR so they can reuse its optimiser and back ends.

; square.ll : LLVM IR for  int square(int x) { return x * x; }
define i32 @square(i32 %x) {
entry:
  %r = mul nsw i32 %x, %x     ; nsw = "no signed wrap"
  ret i32 %r
}

; a loop with a phi node: sum of 0..n-1
define i32 @sum(i32 %n) {
entry:
  br label %loop
loop:
  %i   = phi i32 [ 0, %entry ], [ %i.next, %loop ]
  %acc = phi i32 [ 0, %entry ], [ %acc.next, %loop ]
  %acc.next = add i32 %acc, %i
  %i.next   = add i32 %i, 1
  %done     = icmp sge i32 %i.next, %n
  br i1 %done, label %exit, label %loop
exit:
  ret i32 %acc.next
}

Listing 5. Every value (%r, %i) is assigned once. The phi instruction picks a value based on which block control came from 5.

$ clang -S -emit-llvm -O0 square.c -o square.ll   # C to IR
$ opt -passes='default<O2>' square.ll -S -o square.opt.ll
$ llc -O2 square.opt.ll -o square.s                # IR to native assembly

Clang C-family front end

Clang is the LLVM project's front end for C, C++, Objective-C and Objective-C++, with additional support for OpenCL, CUDA and other C-family dialects 10. Apple started it, and it was released as open source in 2007 2,10. Its stated goals include fast compilation, low memory use, expressive diagnostics, GCC compatibility, and a library-based design so that IDEs and tools can reuse the parser 10. Tools such as clang-format, clang-tidy and clangd are built on these libraries.

Clang lexes, parses with a hand-written recursive-descent parser, and builds an AST with semantic analysis (Sema) before generating LLVM IR (CodeGen) 11. You can inspect the AST directly:

$ clang -Xclang -ast-dump -fsyntax-only square.c
`-FunctionDecl 0x... <square.c:1:1, col:35> col:5 square 'int (int)'
  |-ParmVarDecl 0x... col:16 used x 'int'
  `-CompoundStmt 0x...
    `-ReturnStmt 0x...
      `-BinaryOperator 0x... 'int' '*'
        |-ImplicitCastExpr ... <LValueToRValue>
        | `-DeclRefExpr ... 'x' 'int'
        `-ImplicitCastExpr ... <LValueToRValue>
          `-DeclRefExpr ... 'x' 'int'

Listing 6. Abridged Clang AST dump. Note the implicit "lvalue to rvalue" conversions that semantic analysis inserts.

4. MLIR: many IRs in one framework

MLIR (Multi-Level Intermediate Representation) is a framework for building IRs, rather than one fixed IR. It was created at Google and contributed to the LLVM project in 2019 19,20. Its designers argued that each domain, such as machine learning graphs, affine loop nests or hardware description, had been building its own IR and its own infrastructure, and that a shared, extensible framework would cut that cost 19.

The main concepts are 20:

  • Operations, the single unit of semantics. Instructions, functions and modules are all operations.
  • Dialects, namespaces that group operations, types and attributes, such as arith, scf (structured control flow), affine, linalg, gpu and llvm.
  • Regions and blocks: an operation can hold regions, which hold SSA blocks, so IR nests naturally.
  • Progressive lowering: passes convert from high-level dialects to lower ones in small steps, ending at the llvm dialect, which translates to LLVM IR.
// square.mlir
func.func @square(%x: i32) -> i32 {
  %r = arith.muli %x, %x : i32
  return %r : i32
}

// a loop in the structured-control-flow dialect
func.func @sum(%n: index) -> i32 {
  %c0   = arith.constant 0 : index
  %c1   = arith.constant 1 : index
  %zero = arith.constant 0 : i32
  %res = scf.for %i = %c0 to %n step %c1
           iter_args(%acc = %zero) -> (i32) {
    %iv  = arith.index_cast %i : index to i32
    %nxt = arith.addi %acc, %iv : i32
    scf.yield %nxt : i32
  }
  return %res : i32
}

Listing 7. MLIR keeps the loop as a structured scf.for with loop-carried values, instead of the blocks and phi nodes of Listing 5. Lowering to cf and then llvm produces the flat form.

$ mlir-opt sum.mlir --convert-scf-to-cf --convert-to-llvm -o sum.llvm.mlir
$ mlir-translate --mlir-to-llvmir sum.llvm.mlir -o sum.ll

Pass names change between MLIR releases; check mlir-opt --help for your version 20.

5. Lightweight backends: Cranelift and QBE

LLVM and GCC produce excellent code but are large, and their optimisers take time. Two newer back ends trade some peak performance for speed of compilation or simplicity.

Cranelift fast code generator in Rust

Cranelift is a code generator developed by the Bytecode Alliance and written in Rust 21. It was originally named Cretonne. Its main users are the Wasmtime WebAssembly runtime, which uses it to compile WebAssembly to native code 23, and rustc_codegen_cranelift, an alternative Rust compiler back end aimed at faster debug builds 26. It supports x86-64, AArch64, s390x and RISC-V 64 21.

Cranelift's IR (CLIF) is SSA-based, but instead of phi nodes it uses block parameters: a branch passes values as arguments to the target block 22. Instruction selection rules are written in ISLE (Instruction Selection Lowering Expressions), a term-rewriting DSL compiled to Rust 21.

; square.clif
function %square(i32) -> i32 {
block0(v0: i32):
    v1 = imul v0, v0
    return v1
}

; sum of 0..n-1 using block parameters instead of phi
function %sum(i32) -> i32 {
block0(v0: i32):
    v1 = iconst.i32 0
    jump block1(v1, v1)          ; i = 0, acc = 0
block1(v2: i32, v3: i32):        ; v2 = i, v3 = acc
    v4 = iadd v3, v2
    v5 = iadd_imm v2, 1
    v6 = icmp sge v5, v0
    brif v6, block2(v4), block1(v5, v4)
block2(v7: i32):
    return v7
}

Listing 8. CLIF text format. Compare block1(v2, v3) with the two phi nodes in Listing 5 22.

$ cargo install cranelift-tools   # provides clif-util
$ clif-util compile --target x86_64 -D square.clif

QBE compact backend in C

QBE is a compiler back end by Quentin Carbonneaux. Its stated aim is to provide "70% of the performance of industrial optimizing compilers in 10% of the code" 24. It reads a small, textual SSA intermediate language and writes assembly for amd64, arm64 and riscv64 24. Users include the cproc C11 compiler and the Hare programming language 24.

QBE IL has only four base types: w (32-bit word), l (64-bit long), s (single float) and d (double). Global symbols start with $, temporaries with %, and block labels with @ 25. Front ends may emit non-SSA code that assigns a temporary more than once; QBE converts it to SSA itself 25.

# hello.ssa
data $str = { b "hello world", b 0 }

export function w $square(w %x) {
@start
    %r =w mul %x, %x
    ret %r
}

export function w $main() {
@start
    %r =w call $puts(l $str)
    ret 0
}

Listing 9. QBE IL. The instruction %r =w mul declares that the result %r has type w 25.

$ qbe -o hello.s hello.ssa && cc hello.s -o hello && ./hello
hello world

6. Targeting a virtual machine: Jasmin

Not every compiler emits native code. Compilers for Java, Kotlin, Scala, Clojure and others target the Java Virtual Machine, whose binary format is the .class file 29. Jasmin is an assembler that turns a human-readable description of a class, with JVM instructions written as mnemonics, into a .class file 27. Jon Meyer and Troy Downing wrote it as a companion to their 1997 O'Reilly book Java Virtual Machine 27,28. Because it removes the work of encoding the constant pool and class file layout, it is a popular back end for teaching compilers.

The JVM is a stack machine: instructions push operands on an operand stack and pop them off. Each method declares its maximum stack depth (.limit stack) and number of local variable slots (.limit locals) 27,29.

; Hello.j
.class public Hello
.super java/lang/Object

.method public <init>()V
    aload_0
    invokespecial java/lang/Object/<init>()V
    return
.end method

.method public static square(I)I
    .limit stack 2
    .limit locals 1
    iload_0          ; push x
    iload_0          ; push x
    imul             ; pop two, push x*x
    ireturn
.end method

.method public static main([Ljava/lang/String;)V
    .limit stack 2
    getstatic java/lang/System/out Ljava/io/PrintStream;
    bipush 7
    invokestatic Hello/square(I)I
    invokevirtual java/io/PrintStream/println(I)V
    return
.end method

Listing 10. Jasmin source. Type descriptors such as (I)I (int to int) and Ljava/lang/String; follow the JVM specification 29.

$ java -jar jasmin.jar Hello.j     # writes Hello.class
$ java Hello
49
$ javap -c Hello                   # disassemble to check

8. Exercises with solutions

Try each exercise before opening its solution.

Exercise 1 · Flex: longest match

A Flex file has these rules in this order: "if" { return IF; } and [a-z]+ { return ID; }. What token is returned for the input if? For iffy? What changes if you swap the two rules?

if returns IF: both rules match two characters, and on a tie the earlier rule wins. iffy returns ID, because [a-z]+ matches four characters and the longest match always wins. If you swap the rules, if becomes ID (the tie now goes to [a-z]+), and Flex warns that the "if" rule can never be matched 15.

Exercise 2 · Bison: add exponentiation

Extend Listing 2 with a right-associative ^ operator that binds more tightly than * but less tightly than unary minus. Write the declarations and the rule.

%left '+' '-'
%left '*' '/'
%right '^'             /* right-assoc: 2^3^2 = 2^(3^2) */
%precedence NEG
...
expr : expr '^' expr   { $$ = ipow($1, $3); }

Precedence rises with each later declaration line; %right makes Bison prefer shifting on ^ when a ^ is already on the stack, which groups to the right 18. You also need to add '^' to the Flex single-character class and write ipow.

Exercise 3 · ANTLR: why does order matter?

In Listing 3, what would happen to 1+2*3 if the addSub alternative were listed before mulDiv?

ANTLR 4 gives earlier alternatives of a left-recursive rule higher precedence. With addSub first, + would bind tighter than *, so the tree would be (1+2)*3 and evaluate to 9 instead of 7 13.

Exercise 4 · SSA by hand

Convert this to SSA form with phi nodes:

x = 1;
if (c) x = 2; else x = 3;
y = x + 1;
x1 = 1
br c, Then, Else
Then: x2 = 2 ; br Join
Else: x3 = 3 ; br Join
Join: x4 = phi(x2 from Then, x3 from Else)
      y1 = x4 + 1

Each assignment gets a fresh name. The phi at the join chooses based on the incoming edge. x1 is dead and would be removed by dead-code elimination 30.

Exercise 5 · LLVM IR: write a function

Write LLVM IR for int max(int a, int b) { return a > b ? a : b; } without branches.

define i32 @max(i32 %a, i32 %b) {
entry:
  %gt = icmp sgt i32 %a, %b
  %m  = select i1 %gt, i32 %a, i32 %b
  ret i32 %m
}

icmp sgt is a signed greater-than comparison and select picks one of two values based on an i1 condition 5. Running clang -O1 -S -emit-llvm on the C code may instead produce a call to the llvm.smax.i32 intrinsic, which means the same thing.

Exercise 6 · Cranelift: block parameters

Rewrite the max function from Exercise 5 in CLIF using a conditional branch and a block parameter instead of select.

function %max(i32, i32) -> i32 {
block0(v0: i32, v1: i32):
    v2 = icmp sgt v0, v1
    brif v2, block1(v0), block1(v1)
block1(v3: i32):
    return v3
}

Both branch edges go to block1 but pass different arguments; v3 plays the role of a phi node 22.

Exercise 7 · QBE: add a loop

Write a QBE function $sum(w %n) that returns 0 + 1 + … + (n − 1).

export function w $sum(w %n) {
@start
    %i =w copy 0
    %acc =w copy 0
@loop
    %c =w csltw %i, %n
    jnz %c, @body, @end
@body
    %acc =w add %acc, %i
    %i =w add %i, 1
    jmp @loop
@end
    ret %acc
}

This assigns %i and %acc more than once, which QBE accepts and converts to SSA. csltw is "compare signed less than, on words", and jnz jumps to the first label if its argument is non-zero 25.

Exercise 8 · Jasmin: stack depth

What is the smallest correct .limit stack for a method computing (a + b) * (c + d) from four int locals, evaluated left to right?

Sequence: iload a, iload b, iadd, iload c, iload d, iadd, imul. Depths after each step are 1, 2, 1, 2, 3, 2, 1. The peak is 3, so .limit stack 3. The JVM verifier rejects the class if the declared limit is too small 29.

Exercise 9 · Compare the toolchains

Compile square.c with gcc -O2 -S and clang -O2 -S on x86-64. Then write the same function in QBE and Cranelift and compare the assembly. What do you expect to see?

All four typically produce two instructions on x86-64: a move into the return register and an imul (in some order), then ret. For a function this small there is nothing to optimise, so differences show only in register choice and instruction order. To see the optimisers differ, try a loop such as sum: GCC and Clang at -O2 may replace it with a closed-form formula or vectorise it, while QBE and Cranelift emit a straightforward loop.

9. Trivia with answers

1. What did "GCC" originally stand for?

GNU C Compiler. It became the GNU Compiler Collection as more languages were added 6,7.

2. Is "LLVM" an acronym?

Not any more. It once stood for Low Level Virtual Machine, but the project now treats LLVM as the full name 2.

3. Which award did LLVM receive in 2012?

The ACM Software System Award 2.

4. What does "Yacc" stand for?

Yet Another Compiler-Compiler, written by Stephen C. Johnson at Bell Labs 17. Bison's name is a pun on it (a yak and a bison are both large bovines).

5. Which parsing algorithm does ANTLR 4 use?

Adaptive LL(*), or ALL(*), described by Parr, Harwell and Fisher at OOPSLA 2014 12.

6. What was Cranelift's original name?

Cretonne 21.

7. QBE aims for what share of industrial compiler performance, in what share of the code?

70% of the performance in 10% of the code 24.

8. What is the "M" in MLIR?

Multi-Level, as in Multi-Level Intermediate Representation 19.

9. Which three IRs does GCC use internally, from highest to lowest?

GENERIC, GIMPLE, RTL 9.

10. Which language did GCC gain a front end for in GCC 15?

COBOL 8.

11. Where were lex and Yacc created?

Bell Laboratories, in the mid-1970s, as part of Unix 16,17.

12. What file does Jasmin produce, and what tool ships with the JDK to disassemble it?

A JVM .class file 27; the JDK's javap -c prints its bytecode.
