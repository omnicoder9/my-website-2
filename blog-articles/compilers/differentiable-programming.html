1What is differentiable programming?

Differentiable programming is the practice of writing programs, with loops, branches, function calls, recursion and data structures, whose numerical outputs can be differentiated with respect to their inputs or parameters automatically. The enabling technology is automatic differentiation (AD), also called algorithmic differentiation: a family of techniques that compute exact derivatives (up to floating-point rounding) of functions specified by computer programs, by systematically applying the chain rule to the elementary operations those programs execute1,2.

From a compiler writer's point of view, AD is a program transformation. Given a program P that computes y = f(x), an AD system produces a new program P′ that computes f(x) together with a derivative quantity such as a Jacobian-vector product, a vector-Jacobian product, or a full gradient2. That makes AD a sibling of other classic transformations such as inlining, partial evaluation and continuation-passing-style conversion, and it is subject to the same engineering questions: which intermediate representation (IR) to work on, how to handle control flow and memory, and how it interacts with optimisation11,16.

The phrase "differentiable programming" was popularised in machine learning around 2018, when Yann LeCun argued that the essential idea behind deep learning was assembling networks of parameterised functional blocks and training them with gradient-based optimisation, which is to say writing differentiable programs41. The underlying mathematics and much of the compiler technology are decades older3,4,5,40.

Key idea. Every program, however complicated, executes a finite sequence of elementary operations (+, ×, sin, exp, …) whose derivatives are known. Composing those local derivatives with the chain rule gives the derivative of the whole program, with a cost that is a small constant multiple of the original program's cost2.

2Three ways to get derivatives

There are three common ways to compute derivatives on a computer, and AD is often confused with the other two1.

MethodHow it worksAccuracyMain problem
Numerical (finite differences)Approximate f′(x) ≈ (f(x+h) − f(x))/hTruncation error vs. round-off error trade-off in hInexact; needs O(n) evaluations for a gradient in n inputs
SymbolicManipulate expressions with rules (as a computer algebra system does)Exact"Expression swell"; awkward with control flow and imperative code
Automatic (algorithmic)Apply the chain rule to the operations a program actually executes, propagating numerical valuesExact to working precisionEngineering: memory for reverse mode, IR design, aliasing, parallelism

Baydin et al. describe AD as neither numerical nor symbolic differentiation: like symbolic differentiation it uses exact derivative rules, but it works on numerical values and intermediate variables rather than building closed-form expressions, which avoids expression swell and handles arbitrary control flow naturally1.

3Programs as computational graphs

Consider the running example used throughout this article:

f(x₁, x₂) = x₁·x₂ + sin(x₁)

A compiler can linearise any straight-line evaluation of f into a sequence of single-assignment statements, often called a Wengert list or evaluation trace after R. E. Wengert's 1964 paper describing exactly this decomposition for derivative evaluation3,2. Note how closely this resembles static single assignment (SSA) form, which is why SSA-based IRs are natural targets for AD16.

// Wengert list for f(x1, x2) at (2, 3)
v1 = x1            // 2
v2 = x2            // 3
v3 = v1 * v2       // 6
v4 = sin(v1)       // 0.909297…
v5 = v3 + v4       // 6.909297…
y  = v5

4Forward mode and dual numbers

In forward (tangent-linear) mode, each intermediate value vᵢ is paired with a tangent v̇ᵢ = ∂vᵢ/∂x · ẋ, for a chosen input direction ẋ. Tangents are propagated in the same order as the original computation, so one forward pass computes a Jacobian-vector product (JVP) J·ẋ1,2.

Seeding ẋ = (1, 0) for our example gives ∂f/∂x₁:

Dual numbers

Forward mode has an elegant algebraic formulation. A dual number is a + bε with ε² = 0, an algebra introduced by W. K. Clifford in 187325. Evaluating any polynomial (and, by extension, any analytic function) on x + 1·ε gives f(x) + f′(x)ε, because the Taylor series truncates after the linear term1. Operator overloading on a dual-number type is therefore a complete forward-mode AD implementation, and it is exactly how libraries such as Julia's ForwardDiff.jl work (ForwardDiff generalises to multiple simultaneous tangent components, or "chunks")35.

Python · forward mode with dual numbers (complete, runnable)
import math

class Dual:
    """a + b·ε with ε² = 0. `val` is the primal, `tan` the tangent."""
    def __init__(self, val, tan=0.0):
        self.val, self.tan = val, tan
    def _lift(o): return o if isinstance(o, Dual) else Dual(o)
    def __add__(a, b): b = Dual._lift(b); return Dual(a.val + b.val, a.tan + b.tan)
    def __mul__(a, b): b = Dual._lift(b); return Dual(a.val * b.val, a.tan * b.val + a.val * b.tan)
    __radd__, __rmul__ = __add__, __mul__
    def __repr__(self): return f"Dual({self.val:.6f}, {self.tan:.6f})"

def sin(x):
    if isinstance(x, Dual):
        return Dual(math.sin(x.val), math.cos(x.val) * x.tan)   # chain rule
    return math.sin(x)

def f(x1, x2):
    return x1 * x2 + sin(x1)

print(f(Dual(2.0, 1.0), Dual(3.0, 0.0)))   # Dual(6.909297, 2.583853)  -> df/dx1
print(f(Dual(2.0, 0.0), Dual(3.0, 1.0)))   # Dual(6.909297, 2.000000)  -> df/dx2

5Reverse mode and the tape

In reverse (adjoint) mode, the program first runs forward, recording the values it needs; then a backward sweep propagates adjoints v̄ᵢ = ∂y/∂vᵢ from the output back to the inputs. One reverse sweep computes a vector-Jacobian product (VJP) ȳᵀ·J; for a scalar output with ȳ = 1 this is the whole gradient1,2. Backpropagation in neural networks, as popularised by Rumelhart, Hinton and Williams6, is a special case of reverse-mode AD1.

Adjoint (reverse order)RuleValue
v̄₅seed ȳ = 11
v̄₄v̄₅ · ∂v₅/∂v₄ = v̄₅1
v̄₃v̄₅ · ∂v₅/∂v₃ = v̄₅1
v̄₂v̄₃ · v₁2
v̄₁v̄₃ · v₂ + v̄₄ · cos v₁ (two uses ⇒ adjoints add)2.583853

Two compiler-relevant facts stand out. First, a variable used in several places (here v₁) accumulates adjoint contributions: fan-out in the primal becomes a sum in the adjoint. Second, the backward sweep needs primal values (v₁, v₂) that the forward sweep computed, so they must be stored or recomputed. This storage is the tape, and managing it is the central engineering problem of reverse mode2,8.

Python · a minimal tape-based reverse mode (complete, runnable)
import math

class Var:
    def __init__(self, val, parents=()):
        self.val, self.parents, self.grad = val, parents, 0.0   # parents: [(Var, local_partial)]
    def __add__(a, b): return Var(a.val + b.val, [(a, 1.0), (b, 1.0)])
    def __mul__(a, b): return Var(a.val * b.val, [(a, b.val), (b, a.val)])

def sin(a): return Var(math.sin(a.val), [(a, math.cos(a.val))])

def backward(y):
    # 1. topological order of the recorded graph (this list *is* the tape)
    order, seen = [], set()
    def visit(v):
        if id(v) in seen: return
        seen.add(id(v))
        for p, _ in v.parents: visit(p)
        order.append(v)
    visit(y)
    # 2. reverse sweep: v̄_parent += v̄ · ∂v/∂parent
    y.grad = 1.0
    for v in reversed(order):
        for p, d in v.parents:
            p.grad += v.grad * d

x1, x2 = Var(2.0), Var(3.0)
y = x1 * x2 + sin(x1)
backward(y)
print(y.val, x1.grad, x2.grad)   # 6.909297… 2.583853… 2.0

This is, in miniature, the design of define-by-run systems such as HIPS Autograd and PyTorch's autograd: the graph is recorded dynamically while the program executes, then walked backwards18,38.

6Cost model: when to use which mode

For f : ℝⁿ → ℝᵐ with Jacobian J ∈ ℝᵐˣⁿ1,2:

  • One forward-mode pass gives one column-combination J·ẋ; the full Jacobian needs n passes.
  • One reverse-mode pass gives one row-combination ȳᵀ·J; the full Jacobian needs m passes.
  • For a scalar loss (m = 1), the whole gradient costs one reverse pass. Griewank and Walther show the operation count of a gradient is bounded by a small constant multiple of the cost of evaluating f (no more than about 4 under their complexity model), independent of n: the so-called cheap gradient principle2.
  • The price of reverse mode is memory: naively, storage proportional to the number of operations executed. Checkpointing trades recomputation for memory; Griewank's binomial checkpointing achieves logarithmic growth in both time and space overhead8,9, and a simple √n-segment scheme was popularised for deep networks by Chen et al.30

Modes compose. Applying forward mode to a reverse-mode gradient ("forward-over-reverse") yields Hessian-vector products at a small constant multiple of the gradient's cost, a technique the JAX documentation recommends for second-order work31,2.

7Implementation strategies

AD tools are traditionally classified by how they obtain the derivative program1,2.

7.1 Operator overloading (tracing at run time)

A special numeric type overloads every operation to record it (on a tape) or to propagate tangents. Implementations need no compiler support and handle any host-language control flow, because only the operations actually executed are recorded. Costs include per-operation run-time overhead and the fact that the derivative is rebuilt on every execution, which limits whole-program optimisation. Examples: ADOL-C and CppAD for C++, PyTorch autograd, HIPS Autograd, ForwardDiff.jl18,35,38,42.

7.2 Source transformation

A compiler pass reads the program (as source or IR) and emits a new program that computes derivatives. Control flow is transformed statically: in reverse mode, loops must be reversed and branch decisions recorded so the adjoint can replay them in reverse order. The output can be optimised like any other code. Classic examples are Tapenade for Fortran and C10; modern compiler-integrated examples include Zygote (Julia SSA IR)16, Swift's differentiation transform (SIL)20, Clad (Clang AST)27 and Enzyme (LLVM IR)11.

7.3 Staged tracing: the hybrid

JAX popularised a middle path. Python functions are executed once with abstract tracer values, which records the primitive operations into a small typed functional IR called a jaxpr. Transformations (grad, jvp, vmap, jit) are then interpreters or rewrites over that IR, and jit hands the result to the XLA compiler13,14,32. Python control flow is "unrolled away" during tracing, so data-dependent control flow must use structured primitives such as lax.cond, lax.while_loop and lax.scan32.

8Where in the compiler? AD and intermediate representations

8.1 SSA, phi nodes and loops

In SSA form, each value is defined once and control-flow merges use φ (phi) nodes. Innes's Zygote paper shows how to differentiate SSA-form programs directly, including loops and branches, without unrolling them: the forward pass records which predecessor block was taken (a small amount of control-flow "path" information plus the stacks of pullbacks), and the generated adjoint code walks the control-flow graph in reverse, with a φ node in the primal becoming a branch in the adjoint16. The paper's title, Don't Unroll Adjoint, is a pun on the earlier Lambda: the ultimate backpropagator line of work7,16.

8.2 Closures and pullbacks

A clean functional view of reverse mode associates each primitive f with a function that returns both the result and a pullback closure ȳ ↦ x̄. Pearlmutter and Siskind showed that reverse-mode AD can be expressed as a first-class, nestable program transformation in a functional language with closures7. Elliott later derived AD compositionally from category theory, showing that forward and reverse mode arise from interpreting the same program in different categories23, and Wang et al. showed that reverse mode can be implemented with delimited continuations (shift/reset) without an explicit tape24.

8.3 Linearise, then transpose

JAX implements reverse mode not as a separate transformation but as forward mode followed by partial evaluation and transposition of the resulting linear program. Radul et al. formalise this decomposition, "you only linearize once," and show it recovers the efficiency of reverse mode15. A practical consequence is that authors of new primitives need only supply a JVP rule (plus a transpose rule for any new linear primitive) to get both modes15,31.

8.4 Differentiate before or after optimisation?

Enzyme's central claim is that running AD after standard compiler optimisations produces faster gradients than differentiating unoptimised code. Its paper motivates this with a loop that recomputes a vector norm on every iteration: loop-invariant code motion hoists the norm out of the loop in the primal, and differentiating the optimised code inherits that asymptotic improvement, whereas differentiating first leaves an adjoint that is quadratic in the vector length. On a machine-learning benchmark suite that includes Microsoft's ADBench, the authors report that AD on optimised IR achieves a geometric-mean speedup of 4.5× over AD on IR before optimisation11. Working on LLVM IR also means one tool covers every language with an LLVM front end11,22. Later work extended Enzyme to GPU kernels12 and to parallel programs37.

8.5 Activity analysis and other static analyses

Source-transformation tools use dataflow analyses to avoid needless work. Activity analysis determines which variables both depend on an independent input and influence a dependent output; only "active" variables need derivative storage or code. To-be-recorded (TBR) analysis determines which overwritten values must actually be saved for the reverse sweep. Both are described for Tapenade10, and Enzyme performs activity analysis and type analysis on LLVM IR, where it must also infer which bytes of untyped memory hold floating-point data11.

9Systems tour

All examples compute the gradient of the running example f(x₁,x₂) = x₁x₂ + sin x₁ at (2, 3) where practical, so the expected answer is (2.583853…, 2).

9.1 JAX and XLA

JAX grew out of the Autograd project and the SysML 2018 paper by Frostig, Johnson and Leary, which described compiling numerical Python programs by tracing them at a high level and handing the traced program to XLA13,14. JAX's transformations are composable: jit(grad(vmap(f))) is meaningful14,31. Under jit, JAX lowers jaxprs to StableHLO, which XLA (now developed under the OpenXLA project) compiles for CPU, GPU and TPU32,34.

Python · JAX
import jax, jax.numpy as jnp

def f(x1, x2):
    return x1 * x2 + jnp.sin(x1)

print(jax.grad(f, argnums=(0, 1))(2.0, 3.0))       # (2.5838532, 2.0)  reverse mode
y, t = jax.jvp(f, (2.0, 3.0), (1.0, 0.0))            # forward mode: t = df/dx1
y, pullback = jax.vjp(f, 2.0, 3.0); print(pullback(1.0))  # (2.5838532, 2.0)

print(jax.make_jaxpr(f)(2.0, 3.0))                        # inspect the traced IR
# { lambda ; a:f32[] b:f32[]. let c:f32[] = mul a b; d:f32[] = sin a; e:f32[] = add c d in (e,) }
# (exact printing varies between JAX versions)

fast_grad = jax.jit(jax.grad(f))                            # differentiate, then compile with XLA

# Hessian-vector product: forward-over-reverse
def hvp(g, x, v):
    return jax.jvp(jax.grad(g), (x,), (v,))[1]
Python · a custom JVP rule (numerically stable log1p(exp(x)))
@jax.custom_jvp
def softplus(x):
    return jnp.logaddexp(x, 0.0)

@softplus.defjvp
def softplus_jvp(primals, tangents):
    (x,), (xd,) = primals, tangents
    return softplus(x), jax.nn.sigmoid(x) * xd   # reverse mode is derived by transposition

9.2 PyTorch autograd

PyTorch's autograd is a define-by-run, tape-based reverse-mode system: as tensor operations execute, PyTorch records a directed acyclic graph of Function nodes (visible as grad_fn), and backward() traverses it from the output to the leaves18,33. Because the graph is rebuilt on every iteration, arbitrary Python control flow is supported19,33. PyTorch 2 added torch.compile, which captures graphs with TorchDynamo by analysing Python bytecode, and uses AOTAutograd to trace the backward pass ahead of time so the joint forward-backward graph can be compiled (by default with TorchInductor)26. The torch.func module provides JAX-style composable grad, jvp, vjp and vmap33.

Python · PyTorch
import torch

x1 = torch.tensor(2.0, requires_grad=True)
x2 = torch.tensor(3.0, requires_grad=True)
y = x1 * x2 + torch.sin(x1)
print(y.grad_fn)          # <AddBackward0 object at …>  the recorded graph
y.backward()
print(x1.grad, x2.grad)   # tensor(2.5839) tensor(2.)

# A custom differentiable operation
class Cube(torch.autograd.Function):
    @staticmethod
    def forward(ctx, x):
        ctx.save_for_backward(x)          # explicit tape entry
        return x ** 3
    @staticmethod
    def backward(ctx, grad_out):
        (x,) = ctx.saved_tensors
        return grad_out * 3 * x ** 2

# Composable function transforms
from torch.func import grad
print(grad(lambda t: (t * t).sum())(torch.tensor([1., 2.])))   # tensor([2., 4.])

9.3 Zygote.jl (Julia)

Zygote is a source-to-source reverse-mode AD for Julia that operates on Julia's SSA-form IR, generating adjoint code through Julia's generated-function mechanism, so differentiated code is compiled and optimised by the normal Julia compiler16,17. Derivative rules are supplied through the ChainRules ecosystem, and Zygote supports closures, data structures and user-defined types17.

Julia · Zygote
using Zygote

f(x1, x2) = x1 * x2 + sin(x1)
gradient(f, 2.0, 3.0)                 # (2.5838531634528574, 2.0)

# Control flow and loops are differentiated directly from the IR
function pow(x, n)
    r = one(x)
    for i in 1:n
        r *= x
    end
    r
end
gradient(x -> pow(x, 3), 2.0)           # (12.0,)

# Peek at the pullback
y, back = pullback(f, 2.0, 3.0)
back(1.0)                               # (2.5838531634528574, 2.0)

9.4 Enzyme (LLVM and MLIR)

Enzyme is an LLVM plugin that differentiates LLVM IR. User code calls a placeholder such as __enzyme_autodiff, and the pass replaces the call with a synthesised derivative function11,36. Arguments are annotated with activity: enzyme_dup passes a value with a "shadow" buffer that receives its derivative, enzyme_const marks an inactive argument, and active scalar arguments return their derivative36. Because it works at the LLVM level, Enzyme is used from C, C++, Fortran, Rust, Julia (Enzyme.jl) and Swift, and the project has an MLIR-based variant for higher-level dialects11,36.

C · Enzyme (compile with clang and the Enzyme plugin)
#include <stdio.h>

double __enzyme_autodiff(void*, ...);
void   __enzyme_autodiff_v(void*, ...) __asm__("__enzyme_autodiff");
int enzyme_dup, enzyme_const;

double square(double x) { return x * x; }

void sumsq(const double *x, double *out, int n) {
    double s = 0;
    for (int i = 0; i < n; i++) s += x[i] * x[i];
    *out = s;
}

int main(void) {
    printf("d/dx x^2 at 3 = %f\n", __enzyme_autodiff((void*)square, 3.0));   // 6.0

    double x[3] = {1, 2, 3}, dx[3] = {0}, out = 0, dout = 1;   // seed dout = 1
    __enzyme_autodiff_v((void*)sumsq,
                        enzyme_dup, x, dx,        // x is active: gradient accumulates into dx
                        enzyme_dup, &out, &dout,
                        enzyme_const, 3);         // n is inactive
    printf("%f %f %f\n", dx[0], dx[1], dx[2]);              // 2 4 6
}

// clang sumsq.c -O2 -fplugin=/path/to/ClangEnzyme-<LLVM version>.so -o sumsq

9.5 Swift: differentiable programming in the language

Swift for TensorFlow (S4TF), led at Google, aimed to make differentiation a first-class language feature, with type-checked @differentiable function types and a compiler transform on the Swift Intermediate Language (SIL)20,21. The S4TF project was archived in February 2021 (its GitHub repository was later made read-only), but the differentiation work had been upstreamed into the Swift compiler, where it remains available as an experimental feature through the _Differentiation module20,21. The design is laid out in the Swift Differentiable Programming Manifesto, which introduces the Differentiable protocol with an associated TangentVector type, @derivative(of:) registration and differentiable function types20.

Swift · experimental differentiation
import _Differentiation

@differentiable(reverse)
func g(_ x1: Double, _ x2: Double) -> Double { x1 * x2 + x1 * x1 }

let (d1, d2) = gradient(at: 2.0, 3.0, of: g)   // (7.0, 2.0)

// Registering a custom derivative (a VJP returning value + pullback)
func cube(_ x: Double) -> Double { x * x * x }

@derivative(of: cube)
func cubeVJP(_ x: Double) -> (value: Double, pullback: (Double) -> Double) {
    (cube(x), { v in v * 3 * x * x })
}

Note. Swift differentiation is experimental; syntax and availability depend on the toolchain. The example uses only arithmetic to avoid platform-specific math-library derivative registrations20.

10Hard problems

Memory and checkpointing

Reverse mode must make every needed intermediate available in reverse order. Storing everything costs memory proportional to run time; recomputing everything costs time quadratic in run length. Checkpointing stores selected states and recomputes segments between them. Griewank's binomial scheme, implemented as revolve, is optimal for a fixed number of checkpoints over a sequence of steps8,9. Deep-learning frameworks expose this as gradient (or activation) checkpointing, for example jax.checkpoint (also called jax.remat) and torch.utils.checkpoint30,31,33.

Mutation, aliasing and memory

In imperative code, an overwritten value may be needed later by the adjoint, and two pointers may refer to the same memory. Adjoints of reads become accumulating writes into shadow memory, so aliasing must be respected. Enzyme handles this by shadowing memory allocations and by caching overwritten values identified through alias analysis11; Tapenade uses TBR analysis to decide what to push onto its stack10. Functional systems such as JAX sidestep much of the problem by requiring pure functions with immutable arrays32.

Parallelism

The adjoint of a parallel read (many threads read x) is a parallel accumulation (many threads add to x̄), which introduces races unless atomics or reductions are used. Moses et al. describe how Enzyme differentiates GPU kernels, including handling shared memory and synchronisation, and report gradient performance competitive with the original kernels12.

Non-differentiable points and control flow

AD differentiates the program path actually taken. For piecewise functions such as relu or abs, systems pick a convention at the kink. Programs can also be differentiable in exact arithmetic yet produce poor derivatives because of how they are written; the classic remedy is a custom derivative rule, as in the softplus example above1,31.

Perturbation confusion in nested AD

Nesting forward mode (derivatives of derivatives) requires tagging each perturbation, or tangents from different levels can be mixed up. Siskind and Pearlmutter call this perturbation confusion28,1. ForwardDiff.jl prevents it with type-level tags35.

Exercise 1 · Hand-differentiate a Wengert list Warm-up

For f(x, y) = x²y + y at (3, 2), write the Wengert list, then compute ∇f once with two forward passes and once with a single reverse pass.

Show solution 
v1 = x = 3;  v2 = y = 2;  v3 = v1*v1 = 9;  v4 = v3*v2 = 18;  v5 = v4 + v2 = 20

Forward, seed (1,0): v̇3 = 2·v1·1 = 6; v̇4 = v̇3·v2 + v3·0 = 12; v̇5 = 12      → ∂f/∂x = 12
Forward, seed (0,1): v̇3 = 0;          v̇4 = 0 + v3·1 = 9;       v̇5 = 9 + 1 = 10 → ∂f/∂y = 10

Reverse: v̄5 = 1; v̄4 = 1; v̄2 = v̄5·1 + v̄4·v3 = 1 + 9 = 10;
         v̄3 = v̄4·v2 = 2; v̄1 = v̄3·2·v1 = 12

Both give ∇f = (2xy, x² + 1) = (12, 10). Note that y is used twice, so its adjoint is a sum.

Exercise 2 · Extend the dual-number class Coding

Add subtraction, division and exp to the Dual class from section 4, and check that the derivative of eˣ/x at x = 1 is 0.

Show solution 
def __sub__(a, b): b = Dual._lift(b); return Dual(a.val - b.val, a.tan - b.tan)
def __rsub__(a, b): return Dual._lift(b) - a
def __truediv__(a, b):
    b = Dual._lift(b)
    return Dual(a.val / b.val, (a.tan * b.val - a.val * b.tan) / (b.val ** 2))   # quotient rule
def __rtruediv__(a, b): return Dual._lift(b) / a
Dual.__sub__, Dual.__rsub__, Dual.__truediv__, Dual.__rtruediv__ = __sub__, __rsub__, __truediv__, __rtruediv__

def exp(x):
    e = math.exp(x.val)
    return Dual(e, e * x.tan)

x = Dual(1.0, 1.0)
print(exp(x) / x)   # Dual(2.718282, 0.000000)  since d/dx eˣ/x = eˣ(x−1)/x² = 0 at x = 1

Exercise 3 · Choose the mode Analysis

You need the full Jacobian of (a) f : ℝ¹⁰⁰⁰ → ℝ¹⁰ and (b) g : ℝ¹⁰ → ℝ¹⁰⁰⁰. How many passes does each mode need, and which would you choose?

Show solution

(a) Forward mode needs 1000 JVPs (one per input), reverse needs 10 VJPs (one per output): use reverse. (b) Forward needs 10 JVPs, reverse needs 1000 VJPs: use forward. JAX packages exactly this choice as jax.jacrev and jax.jacfwd31. Reverse mode also pays memory for the tape, which tilts close calls towards forward mode2.

Exercise 4 · Hessian-vector products JAX

Write a function that computes H(x)·v for a scalar function without forming H, and verify it for f(x) = Σ xᵢ³.

Show solution 
import jax, jax.numpy as jnp
f = lambda x: jnp.sum(x ** 3)
hvp = lambda f, x, v: jax.jvp(jax.grad(f), (x,), (v,))[1]   # forward-over-reverse
x, v = jnp.array([1., 2., 3.]), jnp.array([1., 0., 1.])
print(hvp(f, x, v))   # [ 6.  0. 18.]  since H = diag(6x)

The cost is a small multiple of one gradient evaluation, and memory stays O(n) rather than O(n²)31.

Exercise 5 · Tracing and control flow Compilers

Why does the following fail under jax.jit, and how would you fix it?

@jax.jit
def h(x):
    if x > 0:
        return x ** 2
    return -x
Show solution

Under jit, x is an abstract tracer with a shape and dtype but no concrete value, so Python cannot decide x > 0 at trace time and JAX raises a concretisation error. The trace records a single path and Python's if is invisible to the IR32. Fixes: express the branch inside the IR with jnp.where(x > 0, x**2, -x) (computes both sides) or jax.lax.cond(x > 0, lambda x: x**2, lambda x: -x, x) (a structured conditional that is differentiable). The deeper lesson: tracing systems see only the operations that were traced, while source-transformation systems such as Zygote or Enzyme see the branch itself in the IR16,11.

Exercise 6 · Checkpoint arithmetic Analysis

A time-stepping simulation runs n = 10 000 steps and each state is 1 MB. Estimate the reverse-mode memory with no checkpointing and with a checkpoint every 100 steps.

Show solution

No checkpointing: store all 10 000 states, about 10 GB. Every 100 steps: 100 stored checkpoints plus one 100-step segment re-materialised at a time, about 100 + 100 = 200 states, so roughly 200 MB, for about one extra forward simulation of compute. This is the √n scheme30; revolve reduces memory further for a given recomputation budget9.

Exercise 7 · Transposition Theory

For f(x) = A x with A ∈ ℝᵐˣⁿ, give the JVP and show that transposing it yields the VJP.

Show solution

The JVP is the linear map ẋ ↦ Aẋ. Its transpose is ȳ ↦ Aᵀȳ, which is the VJP ȳᵀA written as a column. In a linear program, every mul by a constant transposes to a mul by the same constant with inputs and outputs swapped, every fan-out transposes to an add, and the statement order reverses. That is precisely JAX's linearise-then-transpose route to reverse mode15.

Exercise 8 · Optimise before differentiating Compilers

Explain why differentiating this C function before optimisation gives a slow gradient, while Enzyme's approach does not.

double mag(const double *x, int n);            // O(n), pure
void normalize(double *out, const double *x, int n) {
    for (int i = 0; i < n; i++) out[i] = x[i] / mag(x, n);
}
Show solution

As written, the primal is O(n²) because mag is called on each iteration. An optimiser that knows mag is pure and x is not modified (no aliasing with out, which restrict or alias analysis can establish) hoists it out of the loop, making the primal O(n). If AD runs first, the adjoint contains n calls to the adjoint of mag, and the resulting adjoint code is harder to optimise, so the gradient stays O(n²). Running AD on the optimised IR differentiates a single mag call, so the gradient is O(n). This is the motivating example of the Enzyme paper11.

14Trivia questions

1. Which 1964 paper gave its name to the "Wengert list"?

R. E. Wengert, "A simple automatic derivative evaluation program," Communications of the ACM 7(8), 19643.

2. In what context was reverse-mode accumulation first described, by Seppo Linnainmaa in 1970?

In his master's thesis at the University of Helsinki, on representing the cumulative rounding error of an algorithm as a Taylor expansion of local rounding errors4,40.

3. What algebraic object satisfies ε² = 0 and gives forward-mode AD for free?

The dual numbers, introduced by W. K. Clifford in 187325,1.

4. The title "Lambda the ultimate backpropagator" echoes which famous series of papers?

The "Lambda: the ultimate …" MIT AI Lab memos by Guy Steele and Gerald Sussman on Scheme43. Pearlmutter and Siskind's 2008 TOPLAS paper adopted the pattern7, and Wang et al. answered with "the penultimate backpropagator"24.

5. What does Enzyme differentiate, and what speedup did its authors report from differentiating after optimisation?

LLVM IR. They reported a 4.5× geometric-mean speedup over differentiating before optimisation on an ML-focused benchmark suite including ADBench11.

6. What is a "jaxpr"?

JAX's intermediate representation: a typed, first-order functional program produced by tracing a Python function with abstract values, on which transformations such as grad and vmap operate32.

7. In which month and year was Swift for TensorFlow archived, and what survived?

February 2021, according to the project's README. The differentiation feature had been upstreamed into the Swift compiler and remains available experimentally via import _Differentiation21,20.

8. Which Zygote paper title puns on Pearlmutter and Siskind, and what IR does Zygote differentiate?

"Don't Unroll Adjoint: Differentiating SSA-Form Programs" (2018). Zygote differentiates Julia's SSA-form IR16.

9. What does JAX do instead of implementing reverse mode directly?

It linearises (forward mode plus partial evaluation) and then transposes the linear program, a design formalised in "You Only Linearize Once" (POPL 2023)15.

10. What is Speelpenning's function, and why is it a favourite AD test case?

f(x) = ∏ᵢ xᵢ, named after Bert Speelpenning, whose 1980 thesis compiled fast partial derivatives5. Every partial derivative is a product of all the other inputs, so a naive approach costs O(n²) while reverse mode costs O(n), which demonstrates the cheap gradient principle2.

11. What is "perturbation confusion"?

A bug in naive nested forward mode where tangents belonging to different differentiation levels are mixed, giving wrong higher-order derivatives. It is avoided by tagging perturbations28,35.

12. Which PyTorch 2 component traces the backward pass ahead of time?

AOTAutograd, which works with TorchDynamo (graph capture from Python bytecode) and TorchInductor (code generation)26.

15Glossary

Adjoint (v̄)
Sensitivity of the output to an intermediate, ∂y/∂v, propagated in reverse mode2.
Tangent (v̇)
Directional derivative of an intermediate, propagated in forward mode2.
JVP / VJP
Jacobian-vector product (forward mode) and vector-Jacobian product (reverse mode)31.
Pullback
A closure mapping an output adjoint to input adjoints, the functional form of a VJP7,16.
Tape
Record of operations and saved values needed by the reverse sweep2.
Activity analysis
Static analysis that finds variables that need derivatives10,11.
Shadow
A derivative buffer that mirrors a primal memory allocation, as in Enzyme's enzyme_dup11.
Checkpointing / rematerialisation
Storing selected states and recomputing the rest during the reverse sweep8,30.
