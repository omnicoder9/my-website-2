The React Ecosystem: Concepts, Tools and Reference Stacks

Technical review · November 2026 · Code targets React 19, TypeScript 5 and current major versions of each library
Abstract

React is a JavaScript library for building user interfaces out of components.[1,2] Because the library deliberately limits itself to rendering, real applications are assembled from an ecosystem of complementary tools for routing, state, data fetching, styling, forms, testing, building, deployment and observability. This article organises that ecosystem into 23 categories, explains the problem each category solves, demonstrates representative technologies with working source code, and then composes them into five reference stacks ranging from a minimal single-page application to an enterprise Java-backed system and a cross-platform mobile app. Exercises with worked solutions close the article. Factual claims are referenced to primary documentation and standards in the Vancouver (numbered) style.[3]

1Introduction

React describes a user interface as a tree of components: functions that take inputs (props) and return a description of what should appear on screen.[2] When a component's state changes, React re-runs the component and updates only the parts of the host environment (the browser DOM, or native views on mobile) that actually changed.[4] The same component model runs on the web through react-dom and on Android and iOS through React Native.[1,5]

What React does not include is just as important. It ships no router, no data-fetching cache, no form library, no styling system and no build pipeline. The React team's own guidance is to start new apps with a framework (for example Next.js, React Router in framework mode, or Expo) or, if building from scratch, to pick a build tool such as Vite, Parcel or Rsbuild and add routing and data fetching yourself.[6,7] That guidance replaced the older Create React App tool, which the React team deprecated in February 2025.[8] The result is a large, modular ecosystem. Learning it well means understanding which problem each tool solves, so that choices between tools become trade-offs rather than fashions.

How to read this article

Sections 3–20 work through the categories in roughly the order you encounter them when building an app. Each section states the problem, explains the core idea, and shows short, runnable code. Section 21 combines the pieces into the five reference stacks. Exercises are collected in Section 23, cross-referenced from each topic. Version-sensitive APIs are flagged; always check the cited documentation for the version you install.

3React core concepts

3.1 Components and JSX

A React component is a JavaScript function whose name starts with a capital letter and which returns markup.[2] That markup is written in JSX, a syntax extension that looks like HTML but is stricter: a component must return a single root element (or a fragment <>...</>), all tags must be closed, and most attributes use camelCase, for example className instead of class.[9] Curly braces embed any JavaScript expression.

Props flow from parent to child and are read-only. React expects components to be pure with respect to their inputs: given the same props, state and context, a component should return the same JSX and must not mutate pre-existing objects during render.[10] Side effects belong in event handlers or Effects.

3.2 Rendering lists and keys

Lists are produced with ordinary array methods such as map. Each item needs a key that is unique among its siblings and stable across renders, so React can match items between renders; using array indices as keys can cause subtle bugs when items are reordered, inserted or deleted.[11]

3.3 State with useState

useState returns the current value and a setter. Calling the setter schedules a re-render; the variable in the current render does not change. When the next state depends on the previous one, pass an updater function so that queued updates compose correctly.[4]

State must be treated as immutable: to update an object or array, create a new one (setUser({ ...user, name })) rather than mutating it, because React compares the old and new values with Object.is to decide whether to re-render.[4]

3.4 Hooks and their rules

Hooks are functions whose names start with use. They may be called only at the top level of a component or a custom Hook, never inside conditions, loops or nested functions, because React identifies each Hook by its call order.[12] Custom Hooks are the main unit of logic reuse in React:

3.5 Effects, and when not to use them

useEffect synchronises a component with an external system: a network connection, a browser API, a third-party widget. It runs after render; its dependency array lists every reactive value the effect reads; and the function it returns is a cleanup that React runs before re-running the effect and on unmount.[13] In development, Strict Mode runs effects an extra time to surface missing cleanups.[13]

The React documentation is emphatic that many effects are unnecessary. Values derivable from props or state should be calculated during render; logic caused by a user action belongs in the event handler; and resetting state when a prop changes is better done with a key.[14,15] Data fetching inside effects is possible but must handle race conditions, and the docs recommend using a framework's data mechanism or a client-side cache library instead.[14] That recommendation is the reason the server-state category exists.

3.6 Context and reducers

Context lets a parent make a value available to any descendant without passing props through every level. Combined with useReducer, which centralises update logic in a pure function, it scales to moderately complex state without external libraries.[16]

Note the <CartContext value=...> syntax: since React 19 a context object can be rendered directly as a provider, and <Context.Provider> is slated for deprecation.[17] Context re-renders every consumer when its value changes, which is one reason dedicated state libraries remain popular for frequently-changing global state (Section 7).

3.7 React 19: Actions, useActionState and use

React 19, released on 5 December 2024, introduced Actions: async functions passed to transitions or to a form's action prop, with React tracking pending state, errors and optimistic updates for you.[17] useActionState wraps an action and returns the last result, a wrapped action to pass to the form, and an isPending flag.[18] React 19 also added useOptimistic, the use API for reading promises and context during render, and support for ref as a regular prop on function components.[17]

3.8 Server Components

React Server Components render ahead of time, either at build time or per request on a server, in an environment separate from the client bundle. They can be async, can read databases or files directly, and ship no JavaScript of their own to the browser. Interactive pieces are marked as Client Components with the "use client" directive.[19] Server Components require a framework or bundler integration; in practice that means Next.js's App Router or React Router's RSC support.[19–21] The full-stack Stack C (Section 21.3) uses them.

3.9 The React Compiler

Historically, developers avoided unnecessary re-renders by hand with useMemo, useCallback and React.memo. The React Compiler is a build-time tool that applies this memoization automatically to code that follows the Rules of React.[22] Version 1.0 was announced as stable on 7 October 2025.[23] It runs as a Babel plugin, and integrations exist for Vite, Next.js and Expo.[22,23] With the compiler enabled, manual memoization becomes the exception rather than the rule.

4Language: JavaScript and TypeScript

React components are JavaScript. The language is standardised by Ecma International as ECMAScript (ECMA-262), and the features React code leans on most, such as modules, arrow functions, destructuring, spread syntax and async/await, are all part of that standard.[24,25] JSX is not part of ECMAScript; it is compiled away by tools such as Babel, SWC, esbuild or the TypeScript compiler (Section 5).[9,26]

TypeScript is a typed superset of JavaScript developed by Microsoft that type-checks code ahead of time and then emits plain JavaScript.[27] It supports JSX in files with the .tsx extension.[28] The React documentation recommends TypeScript and documents how to type props, Hooks and events.[29]

Types vanish at runtime

TypeScript types are erased during compilation, so they cannot validate data arriving from a network or a form.[27] That gap is why runtime validators like Zod, which can also derive TypeScript types, appear in Stacks B, C and D (Section 12).[30]

5Build tools and compilers

Browsers cannot execute JSX or TypeScript directly, and shipping hundreds of unbundled modules is slow. A build pipeline therefore has two jobs: transformation (one file in, one file out: JSX to React.createElement-style calls, TypeScript to JavaScript, modern syntax to older syntax) and bundling (a module graph in, optimised chunks out). The compiler/transformation category covers the first; build tools orchestrate both and provide the development server.

5.1 Vite

Vite provides a development server that serves source files over native ES modules, so that only the modules a page actually imports are transformed on demand, with fast Hot Module Replacement, and a build command that produces optimised static assets for production.[31,32] It is one of the build tools the React documentation suggests when starting from scratch.[7] React support comes from an official plugin; @vitejs/plugin-react uses Babel and @vitejs/plugin-react-swc uses SWC.[31]

The server.proxy option forwards matching requests to another server during development.[33] Vite exposes environment variables to client code only when they are prefixed with VITE_, through import.meta.env; anything exposed this way ends up in the public bundle and must not be a secret.[34]

5.2 Webpack

Webpack is a static module bundler built around four concepts: an entry point, an output location, loaders that transform non-JavaScript or untranspiled files as they are imported, and plugins that act on the whole compilation; a mode selects development or production optimisations.[35] It remains common in established codebases and offers fine-grained control.

5.3 Parcel

Parcel positions itself as a zero-configuration build tool: you point it at an HTML entry file and it discovers and transforms dependencies, including JSX and TypeScript, automatically.[36]

5.4 Babel and SWC

Babel is a JavaScript compiler that converts modern syntax and syntax extensions such as JSX into code that runs in target environments, via configurable plugins and presets.[37] @babel/preset-react handles JSX; its runtime: "automatic" option imports the JSX runtime automatically so that files no longer need import React.[26]

SWC is an extensible Rust-based platform for compiling and bundling, positioned as a much faster drop-in for Babel-style transformation.[38] Next.js uses SWC as its compiler.[39] The React Compiler, by contrast, is distributed as a Babel plugin, so pipelines that use it still run Babel for that pass.[22]

6Routing and full-stack frameworks

A router maps the browser's URL to a tree of components and keeps the two in sync on navigation, without full page reloads. A full-stack framework goes further: it also decides where code runs (server or client), how data is loaded before a route renders, how mutations are submitted, and how the app is built and deployed.

6.1 React Router

React Router (version 7 at the time of writing) can be used in three modes that trade simplicity for features: declarative mode (basic URL matching and navigation with <BrowserRouter>), data mode (route objects with loaders, actions and pending states via createBrowserRouter), and framework mode (a Vite plugin adding type-safe file routes, code splitting and server rendering or static/SPA output).[40] Framework mode can also be configured to emit a purely client-side SPA.[41] In version 7 the main package is react-router.[21]

6.2 TanStack Router

TanStack Router is a router built around end-to-end type safety: route paths, path parameters and search parameters are inferred by TypeScript, search parameters can be validated with schema libraries, and loaders integrate with caching libraries such as TanStack Query.[42] It supports both code-based and file-based route definitions.[42]

6.3 Next.js

Next.js is a React framework from Vercel. Its App Router uses the file system for routing (folders under app/ become URL segments, and a page.tsx file makes a segment publicly routable) and renders pages and layouts as Server Components by default.[20,43] A file starting with the "use client" directive marks the boundary below which components are bundled for, and hydrated in, the browser.[44] Mutations are written as Server Functions (also called Server Actions) marked with "use server", which can be passed to a form's action.[45]

Only LikeButton contributes JavaScript to the browser bundle; the list itself arrives as rendered output.[20]

Router or framework?

Choose a client-side router (React Router in declarative or data mode, TanStack Router) when another team owns the backend and the frontend can be deployed as static files: Stacks A, B and D. Choose a framework (Next.js, React Router framework mode) when the same codebase should render on the server, talk to the database, or handle mutations: Stack C.

7Client state management

It helps to separate two kinds of state. Client state is owned by the browser session: UI toggles, wizard steps, a draft shopping cart, the current theme. Server state is a cached copy of data that lives elsewhere and can go stale: users, orders, prices. Mixing the two in one store was a common source of complexity; modern stacks typically use a small client-state tool alongside a dedicated server-state cache (Section 8).[46]

7.1 Redux and Redux Toolkit

Redux keeps global state in a single store that changes only when an action is dispatched to a pure reducer, making updates predictable and traceable.[47] Redux Toolkit (RTK) is the official, recommended way to write Redux logic; configureStore sets up the store with good defaults, and createSlice generates action creators and reducers, letting you write "mutating" update code that Immer turns into immutable updates.[48]

Pre-typed useAppDispatch/useAppSelector Hooks are the pattern the React-Redux TypeScript guide recommends.[49] The app is wrapped once in <Provider store={store}>.

7.2 Zustand

Zustand is a small state library whose store is itself a Hook: create returns a Hook, components select the slice they need, and no context provider is required.[50] Middleware such as persist can save the store to storage.[51]

7.3 MobX

MobX takes a reactive approach: state is made observable, derivations are computed automatically, and components wrapped in observer re-render when the observables they read change, without selectors.[52,53]

8Server-state management

Remote data needs caching, request deduplication, background refetching, retries, pagination and invalidation after mutations, which is a lot to implement correctly by hand with useEffect.[14,46] Server-state libraries provide all of this behind a Hook.

8.1 TanStack Query

TanStack Query identifies cached data by a query key and fetches it with a query function that returns a promise. By default, cached data is considered stale immediately, is refetched in the background when a component mounts, the window regains focus or the network reconnects, failed queries are retried three times, and unused data is garbage-collected after five minutes.[54] After a mutation, related queries are refreshed by invalidating their keys.[55]

8.2 SWR

SWR, from Vercel, is named after the HTTP stale-while-revalidate cache directive: it returns cached (stale) data first, revalidates in the background, and then returns fresh data.[56,57] Its core API is a single Hook taking a key and a fetcher.[56]

8.3 RTK Query

RTK Query is the data-fetching and caching layer built into Redux Toolkit. You define an API "slice" with createApi and endpoints; it generates React Hooks such as useGetPostsQuery, caches results in the Redux store, and uses tags to invalidate cached data after mutations.[58] It is the natural server-state choice when an app already uses Redux, as in Stack B.

9API communication

Server-state libraries decide when to fetch; a transport decides how. The three representatives cover the built-in browser API, a feature-rich HTTP client, and a GraphQL client.

9.1 Fetch

The Fetch API is built into browsers (and modern server runtimes). Two behaviours catch newcomers: the promise returned by fetch() does not reject on HTTP error statuses such as 404 or 500, only on network failure, so code must check response.ok; and request bodies are not serialised automatically.[59] Requests can be cancelled with an AbortController.[60]

9.2 Axios

Axios is a promise-based HTTP client for the browser and Node.js.[61] Unlike fetch, it rejects on non-2xx statuses by default, serialises JSON request bodies and parses JSON responses automatically, and supports interceptors that run on every request or response, which are commonly used to attach tokens or handle 401 responses centrally.[61,62]

9.3 Apollo Client and GraphQL

GraphQL is a query language in which the client specifies exactly which fields it needs from a typed schema, typically over a single endpoint.[63] Apollo Client is a GraphQL client with a normalised in-memory cache and React Hooks.[64] In Apollo Client 4 the React-specific exports, including ApolloProvider and useQuery, are imported from @apollo/client/react, and an explicit link such as HttpLink is required.[65]

9.4 REST and CORS

REST, the architectural style used between frontend and backend in Stacks A, B and D, was defined by Roy Fielding as a set of constraints, including client–server separation, statelessness, cacheability and a uniform interface built on resources.[66] In practice it maps resources to URLs and operations to HTTP methods whose semantics (safe, idempotent) are defined by the HTTP standard.[67] When the frontend and API are served from different origins, the browser enforces the Cross-Origin Resource Sharing protocol: the server must answer with appropriate Access-Control-Allow-* headers, and non-simple requests trigger a preflight OPTIONS request.[68]

10Styling

Every styling approach in React ultimately produces CSS, the language browsers use to describe presentation, with its cascade, specificity and inheritance rules.[69] The approaches differ in how they avoid name collisions and how much they abstract.

10.1 Plain CSS and CSS Modules

Global stylesheets are imported directly in Vite. Files named *.module.css are treated as CSS Modules: class names are scoped locally and the import returns an object mapping your names to generated ones.[70]

10.2 Sass

Sass is a stylesheet language that compiles to CSS and adds variables, nesting, mixins, functions and a module system (@use); its SCSS syntax is a superset of CSS.[71] Vite compiles .scss files once the sass-embedded (or sass) package is installed, and they work with CSS Modules too.[70]

10.3 Tailwind CSS

Tailwind is a utility-first framework: you compose small single-purpose classes directly in markup, and the build step generates only the CSS you use.[72] Version 4 introduced CSS-first configuration and a dedicated Vite plugin; setup is installing tailwindcss and @tailwindcss/vite, adding the plugin, and writing @import "tailwindcss"; in your CSS.[72,73]

11UI component libraries

Component libraries supply accessible, tested widgets such as dialogs, menus, date pickers and data tables, so teams do not rebuild them. The three representatives illustrate three distribution models: an installed library that implements a published design language (MUI), an installed enterprise-oriented library (Ant Design), and source code you copy into your repository (shadcn/ui).

11.1 MUI (Material UI)

Material UI is an open-source React component library implementing Google's Material Design.[74] Global look and feel is customised with createTheme and ThemeProvider.[75]

11.2 Ant Design

Ant Design is an enterprise-class UI design language with a React implementation, offering a large set of components oriented to data-heavy back-office applications, with theming through design tokens on ConfigProvider.[76]

11.3 shadcn/ui

shadcn/ui describes itself not as a component library but as a way to build your own: a CLI copies component source code into your project, where you own and edit it.[77] The components are styled with Tailwind and built on headless, accessible primitives; in July 2026 the project made Base UI the default primitive layer, with Radix UI still supported.[77,78]

12Forms and validation

Forms combine three concerns: tracking field values and their touched/dirty state, validating them, and submitting. Form libraries handle the first and third; schema libraries handle the second and can be plugged into the form library.

12.1 Zod and Yup

Zod is a TypeScript-first schema validation library: you declare a schema once, validate unknown data at runtime with parse or safeParse, and derive the static TypeScript type with z.infer.[30] Yup is a schema builder for runtime value parsing and validation with a similar chainable API and type inference via InferType; it is commonly paired with Formik.[79,80]

12.2 React Hook Form

React Hook Form registers inputs as uncontrolled by default, reading values from the DOM through refs, which keeps re-renders to a minimum; register wires up an input, handleSubmit validates before calling your handler, and formState.errors exposes messages.[81] Schema validation is added through @hookform/resolvers, which provides zodResolver, yupResolver and others.[82]

12.3 Formik

Formik manages form values, errors, touched fields and submission through a <Formik> component or the useFormik Hook, and accepts a Yup schema directly via its validationSchema prop.[80]

Validate twice

Client-side validation is a usability feature, not a security control: anything sent to the server must be validated again there. Sharing one Zod schema between a Next.js Server Function and its form (Stack C) makes this cheap.[30,45]

13Charts

Chart libraries expose visualisations as React components, so data flows in as props and charts re-render like any other component.

13.1 Recharts

Recharts composes charts declaratively from components such as LineChart, XAxis, Tooltip and Line, and is built on React and D3 submodules.[83]

13.2 Nivo

Nivo provides a rich set of data-visualisation components built on D3 and React, published as per-chart packages (for example @nivo/bar), with responsive variants that fill their parent container, which must therefore have a defined height.[84]

14Animation

14.1 Motion

Motion (formerly Framer Motion) animates elements declaratively: you render motion.div and friends, describe target values with animate, and wrap conditionally rendered children in AnimatePresence to animate them out with exit. For React the package is imported from motion/react.[85]

14.2 React Spring

React Spring is a spring-physics animation library: Hooks such as useSpring produce animated values that are applied to animated elements, outside React's render cycle.[86]

Whatever the library, honour users' operating-system request for reduced motion, exposed to CSS as the prefers-reduced-motion media feature.[87]

15Testing

A balanced test suite has many fast unit and component tests and fewer, slower end-to-end tests that exercise real user journeys in a real browser.

15.1 Vitest and Jest

Vitest is a test runner powered by Vite: it reuses the app's Vite configuration and transforms, and offers a Jest-compatible API (describe, it, expect, mocks).[88] Jest is a long-established JavaScript testing framework with the same core API, typically configured with a jsdom environment for React and Babel or SWC for transformation.[89] Both pair with React Testing Library, which renders components and queries them the way users find elements, by role, label or text, rather than by implementation details.[90,91]

The same test runs under Jest by replacing vi.fn with jest.fn and importing from @jest/globals (or relying on Jest's globals).[89]

15.2 Playwright

Playwright is an end-to-end testing framework from Microsoft that drives Chromium, Firefox and WebKit through a single API and ships its own test runner.[92] Its actions auto-wait for elements to be visible, stable and enabled before interacting, and its web-first assertions retry until they pass or time out, which removes most hand-written sleeps.[93]

15.3 Cypress

Cypress runs tests inside the browser alongside the application, providing end-to-end and component testing with an interactive runner that shows each command's effect on the app.[94]

16Mobile: React Native and Expo

16.1 React Native

React Native uses React's component model to build native Android and iOS apps: components such as View, Text and Image are backed by real platform views rather than HTML elements, and styling uses JavaScript objects with a Flexbox-based layout.[5] The "New Architecture" (the Fabric renderer, TurboModules and direct JavaScript-to-native interfaces) became the default in React Native 0.76 in October 2024 and enables React's concurrent features on native.[95,96] The React Native documentation recommends starting new apps with a framework, naming Expo.[97]

FlatList virtualises long lists, rendering only rows near the viewport, which is why it is preferred over mapping an array inside a ScrollView.[5]

16.2 Expo and Expo Router

Expo is an open-source framework and platform around React Native that provides an SDK of native modules (camera, notifications, file system and so on), development tools, and cloud services for building, submitting and updating apps (EAS).[98] Expo Router is a file-based router for React Native and web apps: each file in the app directory becomes a route, layouts are defined in _layout.tsx, and square-bracket file names define dynamic segments.[99,100]

17Desktop: Electron and Tauri

Both tools package a web frontend, such as a Vite-built React app, as an installable desktop application, but they differ fundamentally in what they bundle.

Electron embeds Chromium and Node.js: a main process with Node.js access creates BrowserWindows that run your web content in renderer processes.[101] Electron's security guidance is to keep context isolation on and Node.js integration off in renderers, exposing only narrow APIs through a preload script and contextBridge.[102]

Tauri builds apps from a web frontend and a Rust core. Instead of bundling a browser it uses the operating system's native webview, which yields much smaller binaries, and frontend code calls Rust commands through an IPC bridge.[103,104] Tauri 2 also targets iOS and Android.[103]

18Authentication

Browser-based apps are public clients: they cannot keep a client secret. The standard approach is OAuth 2.0's authorization code flow with Proof Key for Code Exchange (PKCE), with OpenID Connect layered on top to provide an ID token describing the signed-in user.[105–107] Identity providers implement these protocols so that the app redirects to a hosted login page and receives tokens back; the API then validates access tokens on every request (Stack D shows the server side).

18.1 Auth0

Auth0 is a hosted identity platform. Its React SDK wraps the app in Auth0Provider and exposes useAuth0 for login state, redirects and obtaining access tokens for APIs.[108]

18.2 Clerk

Clerk provides hosted authentication and user management with prebuilt React components such as <SignInButton> and <UserButton>, configured with a publishable key on <ClerkProvider>.[109]

Version note

The code follows Clerk Core 3 (March 2026), which renamed @clerk/clerk-react to @clerk/react and replaced <SignedIn>, <SignedOut> and <Protect> with a single <Show when=...> component. Older tutorials use the previous names.[110]

18.3 Keycloak

Keycloak is an open-source identity and access management server that can be self-hosted, supporting OpenID Connect, OAuth 2.0 and SAML, with realms, clients, roles and federation to directories such as LDAP.[111] Browser apps integrate with it through the keycloak-js adapter.[112] It is a common choice when an organisation must keep identity on its own infrastructure, as in Stack D.

Where tokens live

Anything JavaScript can read, an injected script can read too. Prefer SDKs that keep tokens in memory, use short-lived access tokens, and protect the app against cross-site scripting; for server-rendered stacks, session cookies set by the server (as Auth.js does in Stack C) avoid exposing tokens to client code entirely.[107,113]

19Hosting

A client-only React build is a folder of static files that any static host or CDN can serve. Server-rendered frameworks additionally need a runtime for server functions. In both cases, a client-side router needs a fallback so that deep links such as /users/42 return index.html rather than a 404.

  • Vercel is a cloud platform for frontend frameworks, from the company that develops Next.js; it builds on every Git push, creates preview deployments, and runs server-side code as functions.[43,114] SPA fallbacks are configured as rewrites in vercel.json.[115]
  • Netlify offers Git-based builds, a global CDN, serverless and edge functions, and deploy previews.[116] Redirect and rewrite rules live in a _redirects file or netlify.toml.[117]

Static vs. server

20Monitoring

Production apps need to know when users hit errors and how fast pages feel on real devices. React's error boundaries catch rendering errors in a subtree and show a fallback UI instead of unmounting the whole app.[120] React 19 additionally lets you pass onCaughtError, onUncaughtError and onRecoverableError callbacks to createRoot, which monitoring SDKs hook into.[17]

20.1 Sentry

Sentry's React SDK captures errors with stack traces (de-minified with uploaded source maps), performance traces and optional session replays, and provides a Sentry.ErrorBoundary component and a reactErrorHandler for React 19's root callbacks.[121,122]

20.2 Datadog

Datadog Real User Monitoring (RUM) records page views, user actions, resource timings, errors and Core Web Vitals from real browsers, and can correlate frontend sessions with backend traces in Datadog APM.[123] A React integration adds component-level error and router-aware view tracking.[124]

The five stacks below are representative combinations, not prescriptions. For each, the article lists the technologies, explains why they fit together, sketches the architecture, and shows the code that wires the pieces up. Everything not shown follows the individual sections above.

21.1Stack A: Basic React SPA

  • React
  • JavaScript
  • Vite
  • React Router
  • CSS
  • Fetch API

Use it for: a client-side application that talks to an existing backend; learning projects; internal tools. It is the smallest stack that still has routing and data fetching, and it maps exactly to the React documentation's "build from scratch" path.[7]

Architecture: Vite serves and builds a static bundle.[31] React Router in declarative mode maps URLs to pages.[40] Data is fetched with fetch inside a small custom Hook that handles loading, errors and cancellation.[59,60] Styles are plain CSS plus CSS Modules.[70]

Deploying: npm run build produces dist/; host it on any static host with an SPA fallback (Section 19). Growing out of it: when several components need the same remote data, replace useFetch with TanStack Query (Section 8); when the app needs SEO-critical server rendering, move to a framework (Stack C).

21.2Stack B: Modern enterprise frontend

  • React
  • TypeScript
  • Vite
  • Redux Toolkit
  • RTK Query
  • React Router
  • MUI
  • React Hook Form
  • Zod
  • Vitest
  • Playwright

Use it for: enterprise portals, banking applications, dashboards and complex line-of-business apps with many screens, many developers and long lifetimes.

Why these together: TypeScript catches contract errors across a large codebase.[27] Redux Toolkit gives one predictable, DevTools-inspectable store with strong conventions, and RTK Query keeps server data in that same store with tag-based invalidation, so there is one mental model for all state.[48,58] MUI supplies a consistent, themeable, accessible component set.[74] React Hook Form with Zod gives performant forms whose validation rules are also TypeScript types.[30,81] Vitest reuses the Vite pipeline for fast unit tests, and Playwright verifies critical journeys across browsers.[88,92]

21.3Stack C: Full-stack React

  • Next.js
  • React
  • TypeScript
  • Tailwind CSS
  • Prisma
  • PostgreSQL
  • Auth.js
  • Zod

Use it for: products where one team owns the whole application: SaaS apps, content sites with logged-in areas, internal tools with a database.

Why these together: Next.js Server Components read the database directly and Server Functions handle mutations, so there is no separate API layer to build for the app's own UI.[20,45] Prisma ORM provides a typed database client generated from a schema file, and PostgreSQL is the relational database underneath.[125,126] Auth.js provides session-based authentication with OAuth providers and database adapters, including a Prisma adapter.[113,127] Zod validates form input on the server inside each Server Function, and Tailwind styles everything without leaving the component file.[30,72]

21.4Stack D: React + Java enterprise backend

  • TypeScript
  • Vite
  • Redux Toolkit
  • TanStack Query
  • MUI
  • Spring Boot
  • Spring Security
  • REST
  • PostgreSQL
  • Docker
  • Kubernetes

Use it for: organisations with established Java expertise, separate frontend and backend teams, and independently deployed services.

Why these together: The frontend and backend are separate deployables that share only a REST contract.[66,67] On the frontend, TanStack Query owns server state and Redux Toolkit owns client-only state (filters, selections, wizard progress), a division that keeps each tool doing what it is best at.[46,48] Spring Boot builds stand-alone, production-ready Spring applications with embedded servers and auto-configuration.[130] Spring Security protects the API; configured as an OAuth 2.0 resource server, it validates JWT access tokens issued by an identity provider such as Keycloak.[111,131,132] Both halves are packaged as Docker images and run on Kubernetes, which manages deployment, scaling and self-healing of containerised workloads.[133,134]

Backend: Spring Boot REST API

Setting issuer-uri is enough for Spring Security to discover the provider's signing keys and validate token signatures, expiry and issuer.[132] Disabling CSRF protection is appropriate only because this API authenticates with bearer tokens in the Authorization header rather than cookies; a cookie-session API must keep it on.[131] CORS is configured through Spring's standard CORS support.[136]

Frontend: TanStack Query for server data, Redux Toolkit for UI state

Containers and Kubernetes

Multi-stage builds keep compilers and source code out of the final image, which then contains only the runtime and the build output.[137]

  • Expo
  • TypeScript
  • Expo Router
  • TanStack Query
  • Zustand
  • NativeWind

Use it for: one React codebase shipping to Android and iOS (and optionally the web).

Why these together: React Native renders native views and Expo supplies the SDK, tooling and build services.[5,98] Expo Router brings file-based routing with deep linking.[99] TanStack Query works unchanged on React Native and handles caching and refetching for remote data.[46] Zustand holds lightweight client state such as preferences, and its persist middleware accepts a custom storage engine such as AsyncStorage.[50,51] NativeWind lets you style React Native components with Tailwind class names, which it compiles to native styles.[139]

The same components run on both platforms. Production binaries are built and submitted to the app stores with EAS, and the app can be previewed during development on a device or simulator from npx expo start.[98]

22Choosing a stack

The five stacks differ mainly along three axes: where code runs (browser only, or browser plus your own server), who owns the backend (another team, or the same codebase), and which platforms you ship to.

QuestionIf yes…
Is it a mobile app for Android and iOS?Stack E (React Native + Expo).[97,98]
Does one team own UI and data, and do you want server rendering, SEO or direct database access?Stack C (Next.js), or React Router framework mode.[40,43]
Is there an existing or separate Java/Spring backend, with independent deployments?Stack D.
Is it a large, long-lived, form- and table-heavy business frontend over existing APIs?Stack B.
Is it small, a prototype, or a learning project?Stack A, then add pieces as needs appear.
Must it be a desktop app?Any web stack (A, B, D) inside Electron or Tauri.[101,103]

A few cross-cutting rules of thumb follow from the earlier sections:

  • Do not fetch remote data in bare useEffect calls in a large app; use a framework loader or a server-state library.[14,46]
  • Keep server state and client state in separate tools, or at least separate slices, so caching rules do not leak into UI logic.[46,58]
  • Use TypeScript for types at compile time and a schema library (Zod/Yup) at every trust boundary at runtime.[27,30]
  • Never put secrets in client bundles: Vite's VITE_ variables are public by design.[34]
  • Prefer standard protocols (OIDC with PKCE) and maintained SDKs over hand-rolled login code.[106,107]
  • Instrument from day one: error boundaries plus an error/RUM service.[120,121,123]

23Exercises and solutions

Each exercise names the section it practises. Try it before opening the solution.

Exercise 1: The counter that only adds one Section 3.3 · basic

The button below is meant to add 3 per click, but adds 1. Explain why and fix it.

Show solution

During one render, count is a constant snapshot. All three calls compute 0 + 1 and queue "set to 1". Passing an updater function makes React apply each update to the result of the previous one.[4]

Exercise 2: Remove an unnecessary Effect Section 3.5 · basic

Refactor this component so it does not use an Effect, and explain what was wrong.

Show solution

total is derived entirely from props. Storing it in state and syncing with an Effect causes an extra render, with a stale value shown first, and duplicates the source of truth. Calculate it during render instead; wrap it in useMemo only if it is measurably expensive, which the React Compiler can also do for you.[14,22]

Exercise 3: Reset a form when the selection changes Section 3.5 · intermediate

A <ContactEditor contact={selected} /> keeps a local draft in useState(contact.name). When the user selects a different contact, the old draft stays visible. Fix it without an Effect.

Show solution

React preserves state while a component stays at the same position in the tree. Giving the editor a key tied to the contact's identity tells React it is a different component, so its state is reset.[15]

Exercise 4: Configure Vite for an API Section 5.1 · basic

(a) Make fetch("/api/orders") reach http://localhost:8080/api/orders during development. (b) A teammate adds VITE_STRIPE_SECRET_KEY to .env so the frontend can call Stripe. What is wrong?

Show solution

(a) server.proxy forwards matching requests from the dev server, so the browser sees a single origin and no CORS headers are needed.[33,68] (b) Every VITE_-prefixed variable is embedded into the client bundle and visible to anyone who loads the page.[34] Secret keys must stay on a server (a backend endpoint, a Next.js Server Function, or a serverless function) that the frontend calls.

Exercise 5: Extend a Redux slice, test-first Section 7.1 · intermediate

Add a quantityChanged({ id, qty }) reducer to the cart slice from Section 7.1. A quantity of 0 or less removes the item. Write Vitest tests for the reducer.

Show solution

Reducers are pure functions, so they can be tested by calling them directly with a state and an action; Immer guarantees the earlier state object is untouched.[47,48]

Exercise 6: Optimistic update with rollback Section 8.1 · advanced

Using TanStack Query, write a useToggleTodo Hook that flips a todo's completed flag in the cache immediately, rolls back if the request fails, and refetches afterwards either way.

Show solution

Cancelling in-flight queries first prevents a slower background refetch from overwriting the optimistic value; invalidating on settle re-synchronises with the server whatever the outcome.[46,55]

Exercise 7: A registration schema Section 12 · intermediate

Write a Zod schema for a registration form with email, password (at least 12 characters, with at least one digit) and confirm, which must equal password, reporting the error on confirm. Derive the TypeScript type and wire it into React Hook Form.

Show solution

refine with path attaches the cross-field error to confirm, which is where React Hook Form displays it.[30,81] (z.email() is the Zod 4 top-level form; in Zod 3 write z.string().email().[30])

Exercise 8: Test like a user Section 15 · intermediate

(a) Write a React Testing Library test for the Counter from Section 3.3 that proves one click adds 3. (b) Explain why getByRole("button", { name: /clicked/i }) is preferable to container.querySelector(".counter-btn").

Show solution

(b) Role-and-name queries find elements the way users and assistive technologies do, so the test keeps passing through refactors that change class names or markup structure, and it fails if the element stops being an accessible button. This is Testing Library's guiding principle: the more tests resemble the way software is used, the more confidence they give.[91]

Exercise 9: A protected route in data mode Section 6.1 · intermediate

Using React Router's data mode, protect /settings so that signed-out users are redirected to /login?next=/settings before the page renders. Assume an async getSession() that resolves to a user or null.

Show solution

Loaders run before the route renders, and throwing (or returning) a redirect response from one navigates elsewhere, so protected UI never flashes.[40] Remember that this only protects the UI; the API must still reject unauthenticated requests (as Spring Security does in Stack D).

Exercise 10: Delete a note safely in Stack C Section 21.3 · advanced

Add a deleteNote(id) Server Function and a delete button. Make sure a signed-in user cannot delete someone else's note by posting a different id.

Show solution

Server Functions are reachable by direct POST requests, so each one must authenticate and authorise on its own; hidden form fields are user-controlled input.[45] Filtering by both id and authorId enforces ownership in the database query itself.[125]

Exercise 11: Scope-based authorisation in Stack D Section 21.4 · advanced

Only tokens carrying the OAuth scope accounts:write may rename accounts. Implement this in Spring Security, and explain why checking a role in the React UI is not enough.

Show solution

By default, Spring Security's resource server maps each scope in the JWT's scope (or scp) claim to an authority prefixed SCOPE_.[132] Hiding a button in React improves the experience, but the client is fully under the user's control: anyone can send the PATCH request directly. Authorisation must be enforced where the data is.[105]

Exercise 12: A product detail screen in Stack E Section 21.5 · intermediate

Implement app/product/[id].tsx: read the id from the route, fetch https://dummyjson.com/products/{id} with TanStack Query, set the header title to the product name, and add an "Add to cart" button using the Zustand store.

Show solution

Square brackets in the file name create a dynamic segment read with useLocalSearchParams.[100] Including the id in the query key gives each product its own cache entry, so navigating back and forth is instant.[46]

Exercise 13: Pick the stack Sections 21–22 · conceptual

For each scenario, choose a stack (A–E, possibly modified) and justify it in two or three sentences.

  1. A credit union's member portal. The core banking API is an existing Spring service. Fifteen frontend developers, strict accessibility requirements, many forms.
  2. A two-person startup building a subscription recipe site that needs good search-engine visibility and a Postgres database.
  3. A field-inspection app used offline on Android tablets and iPhones, with photo capture.
  4. A university course project to display weather from a public API.
Show solution
  1. Stack B for the frontend, deployed as in Stack D. The backend already exists, so a client-side SPA consuming REST fits; Redux Toolkit/RTK Query and MUI provide conventions and accessible components for a large team, React Hook Form with Zod handles the forms, and Playwright guards critical journeys across browsers.[48,74,81,92] Authentication would use OIDC with PKCE against the bank's identity provider.[106]
  2. Stack C. Server rendering helps search visibility, Server Components and Server Functions remove the need for a separate API, and Prisma with PostgreSQL covers persistence with one TypeScript codebase.[20,125] Vercel or a similar platform keeps operations minimal.[114]
  3. Stack E. React Native with Expo targets both platforms from one codebase, and Expo's SDK covers camera access.[5,98] TanStack Query's cache plus Zustand with persisted storage provide a basis for offline use, though a production offline-sync design would need a local database and conflict handling as well.[46,51]
  4. Stack A. A Vite SPA with fetch is the least machinery that does the job; adding TanStack Query later would be a small, local change.[31,59]
