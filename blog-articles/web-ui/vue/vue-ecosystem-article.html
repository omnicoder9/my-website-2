1. Overview and purpose table

Vue describes itself as a progressive framework: the core library handles declarative rendering and reactivity, and you add routing, state management, build tooling and so on only when an application needs them1. That design is why an "ecosystem" exists at all. Some of these packages are maintained by the Vue core team (Vue Router, Pinia, Vue DevTools, Vue Test Utils), some come from the same people who created Vue and now work on the wider JavaScript toolchain (Vite, Vitest), and the rest are independent projects built for Vue2.

2. Vue core concepts the ecosystem builds on

Every library in this article plugs into a small number of Vue core ideas. Knowing them makes each library easier to learn.

2.1 Single-File Components and <script setup>

A Single-File Component (SFC, a .vue file) keeps a component's template, logic and styles together. Build tools such as Vite compile SFCs into JavaScript1,2. The <script setup> form is compile-time syntax for the Composition API, in which top-level bindings are exposed to the template automatically.

2.2 Reactivity

ref() wraps a value in a reactive container read and written through .value; reactive() makes an object deeply reactive through a Proxy; computed() derives cached values; and watch()/watchEffect() run side effects when dependencies change4. Templates unwrap top-level refs, so count.value in script is just count in the template.

2.3 The Composition API and composables

The Composition API groups code by logical concern instead of by option type, and it gives better TypeScript inference than the Options API5. A composable is a function that uses Composition API features to encapsulate and reuse stateful logic6. Pinia setup stores, the router's useRoute(), Vue I18n's useI18n() and every VueUse function are composables.

2.4 Plugins and provide/inject

Ecosystem libraries are installed with app.use(plugin). A plugin usually registers global components and provides an object (a router, a Pinia instance, an i18n instance) that composables later inject. This is why useRouter() or useStore() works only inside a component's setup or after the plugin is installed.

src/main.ts — the shape most apps in this article share
ts
import { createApp } from 'vue'
import { createPinia } from 'pinia'
import App from './App.vue'
import { router } from './router'
import { i18n } from './i18n'

createApp(App)
  .use(createPinia())  // state management (§6)
  .use(router)         // routing (§5)
  .use(i18n)           // internationalization (§8)
  .mount('#app')
src/components/CounterButton.vue — a typed component using core reactivity
vue
<script setup lang="ts">
import { computed, ref, watch } from 'vue'

const props = withDefaults(defineProps<{ step?: number; max?: number }>(), {
  step: 1,
  max: 10,
})
const emit = defineEmits<{ limit: [value: number] }>()

const count = ref(0)
const atMax = computed(() => count.value >= props.max)

function increment() {
  count.value = Math.min(count.value + props.step, props.max)
}

watch(atMax, (reached) => {
  if (reached) emit('limit', count.value)
})
</script>

<template>
  <button :disabled="atMax" @click="increment">
    Count: {{ count }}
  </button>
</template>

This component is reused in the testing and Storybook sections.

3. Vite: build tooling

Purpose: development server and production bundler.

3.1 Concepts

Vite has two parts: a dev server that serves source files over native ES modules with very fast Hot Module Replacement (HMR), and a build command that bundles the app for production7. It is the build tool the Vue documentation recommends, and npm create vue@latest scaffolds a Vite project2.

Vite 8, released on 12 March 2026, replaced the earlier pair of esbuild (development) and Rollup (production) with a single Rust-based bundler, Rolldown. The announcement reports 10–30× faster builds, requires Node.js 20.19+ or 22.12+, and includes a compatibility layer that converts existing esbuild and rollupOptions configuration8. Vite 8 also added a resolve.tsconfigPaths option (off by default) for TypeScript path aliases8.

Environment variables are exposed on import.meta.env. Only variables prefixed with VITE_ reach client code, which prevents server secrets from leaking into the bundle9.

3.2 Example

bash
npm create vue@latest my-app   # choose TypeScript, Router, Pinia, Vitest
cd my-app && npm install
npm run dev                     # dev server with HMR
npm run build                   # type-check + production build

  plugins: [vue(), vueDevTools()],
  resolve: {
    alias: { '@': fileURLToPath(new URL('./src', import.meta.url)) },

Exercise 3.1

Your app reads import.meta.env.API_SECRET and gets undefined, while import.meta.env.VITE_API_URL works. Explain why, and say whether you should rename the secret to VITE_API_SECRET.

Show solution

Vite only exposes variables with the VITE_ prefix to client code9. Renaming the secret would make it work, but it would also embed the secret in the JavaScript bundle that every visitor downloads. Secrets belong on a server (for example a Nuxt server route, §15). The client should call that server instead of holding the secret.

4. TypeScript: static typing

Purpose: catch type errors before runtime and power editor tooling.

4.1 Concepts

TypeScript is a typed superset of JavaScript that compiles to plain JavaScript10. Vue 3 is written in TypeScript and provides first-class type support. Vite transpiles .ts and <script lang="ts"> but does not type-check; for SFCs you run vue-tsc, a wrapper around the TypeScript compiler that understands .vue files, usually in the build script11. In the editor, the Vue (Official) extension provides the same checking.

Key typed APIs in <script setup> are type-based defineProps and defineEmits, defineModel for v-model, typed template refs with useTemplateRef, and generic components through the generic attribute12.

4.2 TypeScript 7 and Vue projects

TypeScript 7.0 is a port of the compiler to Go. Microsoft's release-candidate announcement (18 June 2026) reports builds that are often about ten times faster than TypeScript 6.0. The package is still typescript and the command is still tsc. TypeScript 7 also changes defaults: strict is now true and module defaults to esnext. Options such as baseUrl and moduleResolution: "node" are now hard errors13. Version 7.0 shipped in July 2026, and 7.0.2 is the current npm release3,14.

The same announcement says a stable programmatic API is not expected until 7.1, and that a compatibility package, @typescript/typescript6, can be installed side by side13. Tools like vue-tsc drive TypeScript through that API. vue-tsc 3.3.14 declares a peer dependency of typescript >=5.0.03, but that range alone does not prove it works with 7.0. Microsoft's 7.0 announcement expects Vue and similar workflows to stay on TypeScript 6.0 for type-checking until the stable API arrives in 7.114. In practice, keep vue-tsc on TypeScript 6 (for example with the compatibility package) until the Vue language tools announce TypeScript 7 support.

4.3 Example

src/components/DataList.vue — a generic, typed component

    <li
      v-for="item in items"
      :key="item.id"
      :class="{ active: selected?.id === item.id }"
      @click="selected = item"
    >{{ label(item) }}</li>
  </ul>
</template>

Exercise 4.1

Type the emits of a SearchBox component so that search carries a string and clear carries nothing. Then add a typed v-model named query.

5. Vue Router: routing

Purpose: map URLs to components in a single-page application.

5.1 Concepts

Vue Router is the official router. You create a router with a history mode (createWebHistory for clean URLs, createWebHashHistory for hash URLs, createMemoryHistory for SSR and tests) and a list of route records. <RouterView> renders the matched component and <RouterLink> renders navigation links. In components, useRoute() gives the current location and useRouter() gives the router instance15.

  • Dynamic segments such as /users/:id expose parameters on route.params.
  • Nested routes use children and a nested <RouterView>.
  • Navigation guards (router.beforeEach, per-route beforeEnter, in-component onBeforeRouteLeave/onBeforeRouteUpdate) can cancel or redirect navigation by returning false or a route location16.
  • Lazy loading: component: () => import('./X.vue') splits each route into its own chunk17.

Vue Router 5 merged the former unplugin-vue-router project into core, which adds optional file-based routing and typed routes. The migration guide states there are no breaking changes for Vue Router 4 users who did not use that plugin. The only exception is that the IIFE build no longer bundles @vue/devtools-api18,19. The guide also says Vue Router 6 will be ESM-only and will remove deprecated APIs18.

5.2 Example: classic route records

src/router/index.ts
ts
import { createRouter, createWebHistory, type RouteRecordRaw } from 'vue-router'
import { useAuthStore } from '@/stores/auth'
import HomeView from '@/views/HomeView.vue'

const routes: RouteRecordRaw[] = [
  { path: '/', name: 'home', component: HomeView },
  {
    path: '/users/:id(\\d+)',               // only numeric ids match
    name: 'user',
    component: () => import('@/views/UserView.vue'),  // lazy-loaded chunk
    props: (route) => ({ id: Number(route.params.id) }),
  },
  {
    path: '/admin',
    component: () => import('@/views/AdminLayout.vue'),
    meta: { requiresAuth: true },
    children: [
      { path: '', name: 'admin', component: () => import('@/views/AdminHome.vue') },
    ],
  },
  { path: '/:pathMatch(.*)*', name: 'not-found', component: () => import('@/views/NotFound.vue') },
]

export const router = createRouter({
  history: createWebHistory(import.meta.env.BASE_URL),
  routes,
})

router.beforeEach((to) => {
  const auth = useAuthStore()   // works: Pinia is installed before navigation runs
  if (to.meta.requiresAuth && !auth.isLoggedIn) {
    return { name: 'home', query: { redirect: to.fullPath } }
  }
})

declare module 'vue-router' {
  interface RouteMeta { requiresAuth?: boolean }
}
src/views/UserView.vue
vue
<script setup lang="ts">
import { onBeforeRouteLeave, useRouter } from 'vue-router'
import { ref } from 'vue'

const props = defineProps<{ id: number }>()   // provided by the route's props function
const router = useRouter()
const dirty = ref(false)

onBeforeRouteLeave(() => {
  if (dirty.value && !window.confirm('Discard unsaved changes?')) return false
})
</script>

<template>
  <h1>User {{ props.id }}</h1>
  <button @click="router.push({ name: 'home' })">Back</button>
</template>

Exercise 5.1

Add a global guard that sets document.title from a meta.title field after every successful navigation, falling back to "My App".

Show solution
ts
declare module 'vue-router' {
  interface RouteMeta { title?: string }
}

router.afterEach((to, _from, failure) => {
  if (!failure) document.title = to.meta.title ?? 'My App'
})

afterEach cannot change navigation, but its third argument reports a navigation failure, so the title only changes when navigation succeeds16.

Exercise 5.2

A user on /users/1 clicks a link to /users/2. The URL changes, but data loaded in onMounted still shows user 1. Why, and how do you fix it?

Show solution

The same route record matches both URLs, so Vue Router reuses the component instance and onMounted does not run again. You can watch the parameter, or use the in-component guard onBeforeRouteUpdate16:

ts
const props = defineProps<{ id: number }>()
const user = ref<User | null>(null)

watch(() => props.id, async (id) => {
  user.value = await fetchUser(id)
}, { immediate: true })

6. Pinia: state management

Purpose: share state across components with a type-safe, devtools-aware store.

6.1 Concepts

Pinia is the official state management library for Vue21. A store is defined with defineStore(id, ...) and has three parts: state, getters (computed values) and actions (methods, which may be async). There is no mutations layer as in Vuex21,22. Stores come in two forms22:

  • Option stores: an object with state, getters and actions.
  • Setup stores: a function where refs become state, computeds become getters, and functions become actions. All state must be returned for devtools, SSR and plugins to work.

Destructuring a store loses reactivity. Use storeToRefs(store) for state and getters, and destructure actions directly22.

Pinia 4 is ESM-only and moves to @vue/devtools-api v8, which must now be installed alongside Pinia23.

6.2 Example

bash
npm install pinia @vue/devtools-api
src/stores/cart.ts — a setup store
ts
import { defineStore, acceptHMRUpdate } from 'pinia'
import { computed, ref } from 'vue'

export interface CartItem { id: number; name: string; price: number; qty: number }

export const useCartStore = defineStore('cart', () => {
  const items = ref<CartItem[]>([])

  const count = computed(() => items.value.reduce((n, i) => n + i.qty, 0))
  const total = computed(() => items.value.reduce((s, i) => s + i.price * i.qty, 0))

  function add(product: Omit<CartItem, 'qty'>) {
    const existing = items.value.find((i) => i.id === product.id)
    if (existing) existing.qty++
    else items.value.push({ ...product, qty: 1 })
  }

  function remove(id: number) {
    items.value = items.value.filter((i) => i.id !== id)
  }

  async function checkout() {
    await fetch('/api/checkout', { method: 'POST', body: JSON.stringify(items.value) })
    items.value = []
  }

  return { items, count, total, add, remove, checkout }
})

if (import.meta.hot) import.meta.hot.accept(acceptHMRUpdate(useCartStore, import.meta.hot))
src/components/CartSummary.vue
vue
<script setup lang="ts">
import { storeToRefs } from 'pinia'
import { useCartStore } from '@/stores/cart'

const cart = useCartStore()
const { count, total } = storeToRefs(cart)   // stays reactive
const { checkout } = cart                    // actions can be destructured directly
</script>

<template>
  <p>{{ count }} items, total {{ total.toFixed(2) }}</p>
  <button :disabled="count === 0" @click="checkout">Checkout</button>
</template>

Exercise 6.1

A colleague writes const { total } = useCartStore() and the displayed total never updates. Explain and fix it.

Show solution

A store is a reactive object. Plain destructuring copies the current value and breaks the reactive link. Use const { total } = storeToRefs(useCartStore()), or keep the store object and read cart.total22.

Exercise 6.2

Write a unit test for CartSummary.vue that starts with two items in the cart and asserts that clicking the button calls checkout, without performing a real fetch.

Show solution

createTestingPinia from @pinia/testing stubs every action by default and lets you set the initial state24:

ts
import { mount } from '@vue/test-utils'
import { createTestingPinia } from '@pinia/testing'
import { expect, it, vi } from 'vitest'
import CartSummary from '@/components/CartSummary.vue'
import { useCartStore } from '@/stores/cart'

it('calls checkout', async () => {
  const wrapper = mount(CartSummary, {
    global: {
      plugins: [createTestingPinia({
        createSpy: vi.fn,
        initialState: { cart: { items: [
          { id: 1, name: 'Pen', price: 2, qty: 1 },
          { id: 2, name: 'Pad', price: 3, qty: 2 },
        ] } },
      })],
    },
  })
  expect(wrapper.text()).toContain('3 items, total 8.00')
  await wrapper.get('button').trigger('click')
  expect(useCartStore().checkout).toHaveBeenCalledOnce()
})

Getters still compute from the initial state, which is why the total is 8.00.

7. VueUse: a collection of composables

Purpose: ready-made composables for browser APIs, sensors, state, timing and more.

7.1 Concepts

VueUse is a large collection of utility composables built on the Composition API25. Most functions return refs, and many accept refs, getters or plain values as arguments, so they compose naturally with your own reactive state. Functions that touch browser APIs are SSR-friendly and clean up their listeners when the calling component unmounts25. Version 15.0.0 requires Vue ^3.5 and Node.js 22 or later3.

Typical examples include useLocalStorage (a ref synchronised with localStorage)26, useFetch (reactive fetch with abort and refetch)27, useMouse, useDark, useDebounceFn, refDebounced, useIntervalFn and useBreakpoints.

7.2 Example

src/components/ProductSearch.vue
vue
<script setup lang="ts">
import { computed, ref } from 'vue'
import { refDebounced, useFetch, useLocalStorage } from '@vueuse/core'

interface Product { id: number; title: string }

const term = ref('')
const debounced = refDebounced(term, 300)               // waits for typing to pause
const recent = useLocalStorage<string[]>('recent-searches', [])

const url = computed(() => `/api/products?q=${encodeURIComponent(debounced.value)}`)
const { data, isFetching, error } = useFetch(url, { refetch: true }).get().json<Product[]>()

function remember() {
  if (term.value && !recent.value.includes(term.value)) {
    recent.value = [term.value, ...recent.value].slice(0, 5)
  }
}
</script>

<template>
  <input v-model="term" placeholder="Search" @keyup.enter="remember" />
  <p v-if="isFetching">Loading…</p>
  <p v-else-if="error">Something went wrong.</p>
  <ul v-else><li v-for="p in data ?? []" :key="p.id">{{ p.title }}</li></ul>
  <small>Recent: {{ recent.join(', ') }}</small>
</template>

With refetch: true, useFetch runs again whenever the URL ref changes27.

Exercise 7.1

Write your own composable useCounterStorage(key) that returns a counter persisted in localStorage, plus inc and reset functions. Then rewrite it with VueUse.

Show solution
ts
// Hand-written (no SSR guard, single tab only)
import { ref, watch } from 'vue'
export function useCounterStorage(key: string) {
  const count = ref(Number(localStorage.getItem(key) ?? 0))
  watch(count, (v) => localStorage.setItem(key, String(v)))
  return { count, inc: () => count.value++, reset: () => (count.value = 0) }
}

// With VueUse: serialisation, SSR safety and cross-tab sync are handled for you
import { useLocalStorage } from '@vueuse/core'
export function useCounterStorageVU(key: string) {
  const count = useLocalStorage(key, 0)
  return { count, inc: () => count.value++, reset: () => (count.value = 0) }
}

Both follow the composable convention: a use prefix, called inside setup, returning refs6,26.

8. Vue I18n: internationalization

Purpose: translate messages and format numbers and dates per locale.

8.1 Concepts

Vue I18n is the internationalization plugin for Vue, maintained by the Intlify project28. You create an instance with createI18n, supplying a locale, a fallbackLocale and messages. In components, useI18n() returns t (translate), n (number format), d (date format) and a writable locale ref28. Messages support named interpolation ({name}), pluralization with |-separated forms, and linked messages. Number and date formats use the browser's Intl API.

The library has a Legacy API (Options-API style $t) and a Composition API mode. New Vue 3 projects should use the Composition API, which legacy: false selects28. The Legacy API is deprecated in v11 and will be removed in v1229.

8.2 Example

src/i18n.ts
ts
import { createI18n } from 'vue-i18n'
import en from './locales/en.json'
import fr from './locales/fr.json'

export type MessageSchema = typeof en

export const i18n = createI18n<[MessageSchema], 'en' | 'fr'>({
  legacy: false,
  locale: 'en',
  fallbackLocale: 'en',
  messages: { en, fr },
  numberFormats: {
    en: { currency: { style: 'currency', currency: 'USD' } },
    fr: { currency: { style: 'currency', currency: 'EUR' } },
  },
})
src/locales/en.json
json
{
  "greeting": "Hello, {name}!",
  "cart": "no items | one item | {count} items"
}
src/components/LocaleDemo.vue
vue
<script setup lang="ts">
import { useI18n } from 'vue-i18n'
const { t, n, locale } = useI18n()
</script>

<template>
  <select v-model="locale">
    <option value="en">English</option>
    <option value="fr">Français</option>
  </select>
  <p>{{ t('greeting', { name: 'Ada' }) }}</p>
  <p>{{ t('cart', 3) }}</p>          <!-- "3 items" -->
  <p>{{ n(1234.5, 'currency') }}</p> <!-- $1,234.50 or 1 234,50 € -->
</template>

9. Vue DevTools: debugging

Purpose: inspect components, state, routes and performance in a running app.

9.1 Concepts

Vue DevTools is available as a browser extension, as a standalone app, and as a Vite plugin (vite-plugin-vue-devtools) that embeds the tools in the page during development30,31. Its main features are:

  • a component tree with live props, state and computed values, which you can edit;
  • a timeline of events and performance;
  • inspectors that libraries register through @vue/devtools-api, such as Pinia stores (state, getters, action log and time travel) and Vue Router routes;
  • "open in editor", which jumps from a component to its source file (Vite plugin)31.

Both Pinia 4 and Vue Router 5 now depend on @vue/devtools-api v818,23. Note that Vite 8 also added its own devtools option for inspecting the build8. That tool is separate from Vue DevTools, which inspects your Vue application.

9.2 Example

The Vite plugin is enabled by the vueDevTools() line in the §3 config. A library can also add its own inspector. The sketch below adds a custom panel listing the app's feature flags:

src/plugins/flags-devtools.ts
ts

10. Vitest: unit testing

Purpose: fast unit and integration tests that reuse your Vite configuration.

10.1 Concepts

Vitest is a test framework powered by Vite. It reuses the app's Vite config, plugins and aliases, so .vue files and TypeScript work in tests without separate setup, and it offers a Jest-compatible API (describe, it, expect, snapshots)32. 11. Vue Test Utils: component testing

Purpose: mount Vue components in tests and interact with them.

11.1 Concepts

Vue Test Utils (VTU) is the official low-level library for testing Vue components. Version 2 targets Vue 336. It is not a test runner, so you pair it with Vitest. The core API is37:

  • mount(Component, { props, slots, global }) renders a component and returns a wrapper. shallowMount stubs child components.
  • global.plugins, global.stubs and global.provide inject a router, Pinia, i18n or stubs.
  • find/get/findComponent query the rendered output. trigger fires DOM events and setValue fills inputs.
  • emitted() records emitted events. flushPromises() resolves pending promises.

DOM updates in Vue are asynchronous, so await the result of trigger and setValue before asserting36. Test what the user sees and what the component emits, not internal state34.

12. Storybook: component development and documentation

Purpose: build, view and document components in isolation.

12.1 Concepts

Storybook is a workshop for building UI components outside the app. Each story captures one rendered state of a component, written in Component Story Format (CSF): a default export (meta) describes the component, and each named export is a story38. 15. Nuxt: Vue-based application framework

Purpose: full-stack Vue with server-side rendering, static generation, file-based routing and server routes.

15.1 Concepts

Nuxt is a free, open source framework that builds on Vue, Vite and its Nitro server engine53. Its main features are:

  • Rendering modes: universal rendering (SSR plus hydration) by default, with client-only, static and hybrid per-route rules53.
  • Conventions: file-based routing from pages/, layouts, middleware, and automatic imports of components, composables and Vue APIs. Nuxt 4 makes app/ the default source directory (for example app/pages), while server/, public/ and nuxt.config.ts stay at the project root54.
  • Data fetching: useFetch and useAsyncData fetch on the server, send the result to the client in the payload, and avoid fetching twice during hydration55.
  • Server routes: files in server/api become API endpoints written with defineEventHandler56.

Nuxt 4.6.4 declares Node.js ^22.22.3 || ^24.15.0 || >=26.0.0 in its engines field3. Pinia, Vue I18n, VueUse, Vuetify, PrimeVue and Element Plus all integrate through Nuxt modules.

Exercise 15.1

Explain why calling plain fetch() inside onMounted in a Nuxt page gives a worse result than useFetch, in terms of what the user and search engines see.

Show solution

onMounted runs only in the browser. With plain fetch() there, the server-rendered HTML contains no product data, so users see a loading state first and crawlers may index an empty page. useFetch runs during server rendering, puts the data in the HTML and the payload, and reuses it on the client during hydration without a second request55.

ts
import { defineStore } from 'pinia'
import { computed } from 'vue'
import { useLocalStorage } from '@vueuse/core'

export interface Book { id: number; title: string; author: string; read: boolean }

export const useBooksStore = defineStore('books', () => {
  const books = useLocalStorage<Book[]>('bookshelf', [])
  const unreadCount = computed(() => books.value.filter((b) => !b.read).length)

  function add(title: string, author: string) {
    const id = Math.max(0, ...books.value.map((b) => b.id)) + 1
    books.value.push({ id, title, author, read: false })
    return id
  }
  function toggleRead(id: number) {
    const book = books.value.find((b) => b.id === id)
    if (book) book.read = !book.read
  }
  const byId = (id: number) => books.value.find((b) => b.id === id)

  return { books, unreadCount, add, toggleRead, byId }
})

import type { Meta, StoryObj } from '@storybook/vue3-vite'
import { expect, fn } from 'storybook/test'
import BookCard from './BookCard.vue'

const meta = {
  component: BookCard,
  args: { book: { id: 1, title: 'Dune', author: 'Frank Herbert', read: false }, onToggle: fn() },
} satisfies Meta<typeof BookCard>
export default meta

export const Toggles: StoryObj<typeof meta> = {
  play: async ({ canvas, userEvent, args }) => {
    await userEvent.click(canvas.getByRole('button'))
    await expect(args.onToggle).toHaveBeenCalledWith(1)
  },
}
