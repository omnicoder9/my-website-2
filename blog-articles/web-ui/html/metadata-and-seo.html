HTML Metadata and SEO

What a page says about itself, and who reads it: the <meta> declarations that browsers act on (character encoding, viewport, theme colour, language), the signals search engines use to crawl, index and present a page (titles, descriptions, headings, canonical URLs, robots rules, internal links), the social metadata behind link previews (Open Graph and X cards), and the three syntaxes for structured data (JSON-LD, Microdata and RDFa) that turn a page into machine-readable facts. Grounded in the WHATWG HTML Standard, the W3C and IETF specifications, schema.org, and the search engines' own documentation.

Updated 15 November 2026118 references (Vancouver style)Includes exercises, trivia, a robots.txt tester, a metadata inspector and a playground

The first article in this series introduced the head element as the place for "information about the document". Since then the series has dealt almost entirely with the body: text, links, media, semantic structure, tables, forms and, most recently, the APIs that script it. This article returns to the head. The HTML Standard calls its contents metadata content: "content that sets up the presentation or behavior of the rest of the content, or that sets up the relationship of the document with other documents, or that conveys other 'out of band' information".1 Very little of it is ever shown to a reader, yet it decides how the page is decoded, how it is laid out on a phone, what appears in a browser tab, whether it shows up in a search engine, and what a link to it looks like in a chat message.2,3

Search engine optimisation (SEO) is the practice of helping search engines understand a page and helping people find it. Google's own starter guide frames it that way, and warns that there are no secrets that automatically rank a page first.3 Much of what works is ordinary, standards-conforming HTML: a descriptive title, real links, real headings, a declared language, and a canonical URL. The article therefore treats metadata and SEO together. Section 2 covers the meta declarations themselves, section 3 the HTML that search engines and social platforms read, and section 4 structured data. Sections 5 to 10 hold a complete worked example, exercises, trivia, an inspector that reads the metadata of any HTML you paste, a playground and a quick-reference table.

1Introduction

1.1 What metadata is

Metadata is data about data. In an HTML document it lives mostly in the head, whose content model is "one or more elements of metadata content, of which exactly one is a title element and no more than one is a base element".2 Metadata content is a short list: base, link, meta, noscript, script, style, template and title.1 Of these, three carry nearly all of the metadata discussed here:

  • title gives the document's title or name, the text a browser shows in its tab, history and bookmarks.4
  • meta "represents various kinds of metadata that cannot be expressed using the title, base, link, style, and script elements". It works in one of four modes, chosen by which attribute it carries: name (document-level metadata), http-equiv (a pragma directive), charset (the character encoding declaration) or itemprop (Microdata).5
  • link "allows authors to link their document to other resources": style sheets and icons, but also the canonical URL, alternate language versions and feeds.6

Structured data, covered in section 4, is a second kind of metadata. It describes not the document but the things the document is about (a product, a recipe, a person, an event) and can be placed anywhere in the page, in a script type="application/ld+json" block or in attributes on ordinary body elements.7–9

1.2 How search engines use a page

Google describes Search as working in three stages, and notes that not every page makes it through each one.14 In crawling, an automated program (Googlebot) discovers URLs, mostly by following links from pages it already knows and from submitted sitemaps, and downloads them. In indexing, Google analyses the text, images, video and key tags such as the title element and alt attributes, decides whether the page is a duplicate of another page and, if not, stores it in the index. In serving, it returns the most relevant indexed pages for a query.14 Pages that rely on JavaScript go through an extra rendering step: Googlebot queues them, renders them in a recent ("evergreen") version of Chromium and then processes the rendered HTML.15

Each stage has its own HTML-level controls, and confusing them is the most common mistake in technical SEO. robots.txt controls crawling; a robots meta tag controls indexing and presentation; rel="canonical" influences which duplicate is indexed; the title, meta description and structured data influence presentation in the results.16–19 Figure 2 maps each one onto the pipeline.

1.3 A short history

The meta element is as old as standardised HTML: it is already in HTML 2.0, published as RFC 1866 in November 1995, where it carries name, http-equiv and content attributes.21 The rest of the toolkit arrived piecemeal, usually from search engines or social networks rather than from HTML's editors, which is why it is spread across so many documents today.

2.1 <meta charset>

A web server sends bytes, not characters. The browser has to choose a character encoding to turn those bytes into text, and if it chooses wrongly every non-ASCII character comes out garbled. The charset attribute declares the encoding. In HTML its value "must be an ASCII case-insensitive match for the string utf-8": UTF-8 is the only encoding a conforming document may declare, because the Encoding Standard requires UTF-8 for new content.5,32 A document may contain only one meta element with charset.5

The character encoding declarationHTML
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="utf-8">        <!-- first thing in the head -->
  <title>Café menu</title>
  …

Position matters. The declaration must be serialised completely within the first 1024 bytes of the document, because the parser's encoding sniffing algorithm looks only that far ahead before it starts decoding.44,46 The W3C Internationalization Activity therefore recommends putting it immediately after the opening head tag, before the title or anything else that might contain non-ASCII text.47 A byte order mark at the start of the file, or a charset parameter in the HTTP Content-Type header, takes precedence over the meta declaration; the meta element is the fallback that travels with the file when it is saved to disk or served by a misconfigured server.46,47

The older pragma form, <meta http-equiv="content-type" content="text/html; charset=utf-8">, is still conforming and means the same thing, but a document must not contain both forms.48 The short form is easier to get right.




2.2 Viewport metadata


When the iPhone shipped, almost no websites were designed for a small screen. Safari for iOS therefore rendered pages into a virtual "layout viewport" 980 CSS pixels wide and scaled the result down to fit the screen, and Apple introduced <meta name="viewport"> so that pages designed for phones could opt out.49 Other mobile browsers copied both the behaviour and the tag, and it is now specified in the W3C's CSS Viewport Module Level 1, a Working Draft whose properties are width, height, initial-scale, minimum-scale, maximum-scale, user-scalable and interactive-widget.33



The standard responsive viewportHTML
<meta name="viewport" content="width=device-width, initial-scale=1">



width=device-width sets the layout viewport to the device's width in CSS pixels, so a 390-pixel-wide phone lays the page out at 390 pixels and media queries see that width; initial-scale=1 starts the page at 100% zoom.33,50 Without the tag, a responsive layout's narrow breakpoints never apply on a phone, because the page believes it is 980 pixels wide. Google lists viewport among the meta tags it understands, and because Google predominantly indexes the mobile version of a page, a page that is unusable on a phone is a search problem as well as a usability one.10,51





Do not disable zoomuser-scalable=no and maximum-scale=1 stop people with low vision from zooming in. WCAG 2.2 success criterion 1.4.4 (Level AA) requires that text can be resized up to 200% without loss of content, and the W3C's ACT rule "Meta viewport allows for zoom" flags exactly these values.52,53 If a form field zooms the page on focus in iOS Safari, fix the cause (a font size below 16px) rather than disabling zoom.50



The newer interactive-widget property says what an on-screen keyboard does to the viewport: resizes-visual (the default: only the visual viewport shrinks), resizes-content (the layout viewport shrinks too, so position: fixed footers move up) or overlays-content (nothing resizes).33




2.3 Description metadata


The HTML Standard defines description as "a free-form string that describes the page", whose value "must be appropriate for use in a directory of pages, e.g. in a search engine". There must be no more than one per document.41


A descriptionHTML
<meta name="description" content="Opening hours, menu and prices for Lantern Café, a vegetarian café near Riverside Station. Breakfast from 7 am, weekend brunch until 3 pm.">


The browser does nothing visible with it. Its main consumers are search engines, which may use it as the snippet under the title, and social platforms, which fall back to it when no og:description is given.11,54 How to write one is a search question, so it is covered with the other presentation signals in section 3.2.




2.4 Author metadata and other standard names


author is "a free-form string giving the name of one of the page's authors". Unlike description it may be repeated, one element per author.41 It is a plain string, so it cannot say who the person is, link to a profile or distinguish two people with the same name. Two richer alternatives exist. A rel="author" link points to information about the author, such as a profile page or a mailto: address.55 And schema.org's author property, in structured data, can describe a Person or Organization with a name and URL; this is what Google's article documentation recommends for author information, while its list of supported meta tags does not include author at all.10,56



Three ways to say who wrote a pageHTML
<meta name="author" content="Priya Raman">
<link rel="author" href="/people/priya-raman">
<script type="application/ld+json">
{ "@context": "https://schema.org", "@type": "Article",
  "headline": "Choosing a sourdough flour",
  "author": { "@type": "Person", "name": "Priya Raman",
              "url": "https://example.com/people/priya-raman" } }
</script>

2.6 Theme color and color scheme


theme-color suggests a colour that the browser may use to tint its own interface around the page, such as the address bar or the title bar of an installed app. Its value "must be a string that matches the CSS <color> production", and it is the one standard metadata name with which the media attribute has an effect, so different colours can be given for light and dark modes. In an HTML document each theme-color element's media value must be unique.5,41 Support varies by browser and platform, so treat it as a progressive enhancement.58



Theme colour for light and dark modes, and colour-scheme supportHTML
<meta name="theme-color" content="#f4efe6" media="(prefers-color-scheme: light)">
<meta name="theme-color" content="#1c1f24" media="(prefers-color-scheme: dark)">
<meta name="color-scheme" content="light dark">



color-scheme is the related declaration for the page itself. It tells the browser which colour schemes the page supports, before any CSS has loaded, so that default backgrounds, form controls and scroll bars can be drawn in dark mode from the first frame instead of flashing white. Its values follow the CSS color-scheme property: for example normal, light, dark, light dark or only light.41,59,60 This article itself uses both the CSS property and a theme toggle; try switching it with the button at the top.

2.7 Language declarations


The lang attribute declares the primary language of an element's contents, and on the html element it sets the language of the whole document. Its value is a BCP 47 language tag such as en, en-GB, pt-BR, zh-Hant or sr-Latn, or the empty string, which means the language is unknown.34,45 Elements without the attribute inherit the language of their parent.45 The subtags come from the IANA Language Subtag Registry, so en-UK is wrong (the region code for the United Kingdom is GB).34,61



Document language, a change of language, and alternatesHTML
<html lang="en-GB">
<head>
  <link rel="alternate" hreflang="en-GB" href="https://lantern.example/en-gb/menu">
  <link rel="alternate" hreflang="fr-FR" href="https://lantern.example/fr-fr/menu">
  <link rel="alternate" hreflang="x-default" href="https://lantern.example/menu">
</head>
<body>
  <p>Our pastry chef trained in Lyon, where a croissant is
     <span lang="fr">une viennoiserie</span>.</p>
  <p translate="no">Lantern Café</p>   <!-- brand name: do not translate -->
</body>



The declaration has practical effects. Screen readers switch pronunciation rules and voices; browsers choose fonts and hyphenation dictionaries and decide whether to offer translation; and CSS :lang() selectors and quotation marks depend on it.62,63 WCAG 2.2 requires the page language to be programmatically determinable (success criterion 3.1.1, Level A) and changes of language within the page to be marked (3.1.2, Level AA).13,64 The translate="no" attribute marks content, such as a brand name, that translation tools should leave alone.65


Two things do not work as language declarations. The W3C advises that "you should never use a meta element with the http-equiv attribute set to Content-Language" to declare the language of a page; it is not among the HTML Standard's conforming pragma states.48,62 And search engines generally ignore markup: Google says it detects a page's language from its visible text and "doesn't use code-level language information such as lang attributes".10,66 To tell Google about translated or regional versions of a page, use hreflang alternates, which must be reciprocal (each version lists all the others and itself), must use fully qualified URLs, and can name an x-default page for unmatched languages.66



Other pragma directives


The http-equiv attribute exists so that a document can carry what would otherwise be an HTTP header. The HTML Standard defines a closed list of states for it, content-type (the encoding declaration above), default-style, refresh, x-ua-compatible and content-security-policy. Other values, such as the old content-language and set-cookie, are not conforming.48,62 For SEO only refresh matters, and Google recommends a server-side 301 redirect instead of a meta refresh redirect.10,67




3SEO in HTML


Google's SEO Starter Guide gives a modest definition: SEO is about helping search engines understand your content, and helping people find your site and decide whether to visit it.3 Google's Search Essentials set the ground rules, separating technical requirements (Googlebot must be able to fetch the page, it must return HTTP 200, and it must contain indexable content), spam policies, and key best practices.31 Bing's guidelines are similar in substance.39 This section takes the HTML side of those rules in order: what a result looks like, what the page says about its structure, which URL is the real one, whether it can be crawled and indexed, how pages connect, and how they appear when shared.






3.1 Page titles


The title element "represents the document's title or name", and the HTML Standard asks authors to use titles "that identify their documents even when they are used out of context, for example in a user's history or bookmarks, or in search results".4 There must be no more than one per document, and its content must be text that is not inter-element whitespace, so an empty or blank title is invalid.2,4 WCAG 2.2 success criterion 2.4.2, Page Titled (Level A), requires that web pages "have titles that describe topic or purpose", because the title is the first thing a screen reader announces and the label of every browser tab.12


For search, the title is the main source of the title link, the clickable headline in a result. Google says it builds title links from several sources: the title element, the main visual title on the page, heading elements such as h1, og:title, other prominent text, anchor text of links pointing to the page, and WebSite structured data. It rewrites a title when it judges the title element a poor description, for example when it is empty, identical across many pages, stuffed with keywords or out of date.19 There is no fixed length limit, but long titles are truncated to fit the device width.19

3.2 Meta descriptions


The snippet under a title link is mostly generated from the page's own content, chosen to match the query. Google says it will "sometimes" use the meta description instead, when it gives a more accurate summary of the page than any extract from the text.54 A good description therefore earns its place by being better than an automatic extract. Google's guidance is to write a unique description for each page, to summarise the page rather than list keywords, and to include concrete facts a reader would want, such as the author, date, price or opening hours. Like titles, descriptions have no length limit but are truncated to fit the device.54




A summary with facts


GoodHTML
<meta name="description" content="Written by Priya Raman, 12 March 2026. Compares six sourdough flours by protein content, water absorption and price per kilo, with a recommendation for beginners.">


Keywords, or the same text everywhere


AvoidHTML
<meta name="description" content="sourdough, flour, bread, baking, best flour, cheap flour">
<meta name="description" content="Welcome to Lantern Café's website.">




Three controls limit snippets: the nosnippet and max-snippet robots rules, and the data-nosnippet attribute (see section 2.5).17,54 Social platforms use the description as a fallback when og:description is missing, so it often appears in link previews too.11




3.3 Heading hierarchy


The six heading elements, h1 to h6, "represent headings for their sections", and their numbers give their rank: h1 is the highest and h6 the lowest.72 A heading's level is given by the number in its name, adjusted only by the new headingoffset attribute; it is not changed by nesting inside section or article, so an h1 inside a section is still a level-one heading and the level has to be chosen to match the structure.72,73 The standard makes skipping a conformance error: each heading "must have a heading level that is less than, equal to, or 1 greater than" the level of the heading before it, so h2 straight to h4 is invalid. Subtitles and taglines belong in hgroup with a p, not in an extra heading.73,74





Headings matter to search for the same reason they matter to people. Screen reader users commonly move through a page by its headings, and WCAG requires that structure conveyed visually is also available in markup (1.3.1, Info and Relationships) and that headings describe their topic (2.4.6, Headings and Labels).75–77 Google lists the main visual title and heading elements among the sources for title links and advises making the page's main title the most prominent heading, so a clear h1 that agrees with the title helps.19 Neither the HTML Standard nor Google requires exactly one h1; the advice is to make the hierarchy reflect the content.19,73 Style is a separate matter: if a heading looks too big, change the CSS, not the level.



A hierarchy that matches the contentHTML
<body>
  <header><a href="/">Lantern Café</a> <nav>…</nav></header>
  <main>
    <hgroup>
      <h1>Breakfast menu</h1>
      <p>Served 7 am to 11:30 am, every day</p>   <!-- subtitle, not a heading -->
    </hgroup>
    <section>
      <h2>Hot dishes</h2>
      <h3>Shakshuka</h3> …
      <h3>Porridge</h3> …
    </section>
    <section>
      <h2>Bakery</h2>
      <h3>Croissants</h3> …                     <!-- h3, not h4 -->
    </section>
  </main>
</body>




3.4 Semantic HTML


Part 5 of this series covered semantic HTML in depth; here the question is only what it does for search. Search engines read HTML, so the more accurately the markup describes the content, the less they have to guess. The relevant habits are few:


    

  • Put the content in the HTML. Google indexes the rendered page and can run JavaScript, but rendering is an extra, deferred step, and content or links that appear only after user interaction may never be seen.15
    • 

  • Use the elements for what they mean. main marks the dominant content, nav major navigation blocks, article self-contained compositions, header and footer introductory and closing content.78,79 These landmarks also let assistive technology skip boilerplate.80
    • 

  • Make links real links (<a href>), covered in section 3.6.81
    • 

  • Describe images. Google uses alt text, along with captions, file names and surrounding text, to understand images; an image that is a link uses its alt text as anchor text.81,82
    • 

  • Give machine-readable values where HTML has them: time datetime for dates, data value for numbers, address for contact information.83–85
    •

3.5 Canonical URLs


The same content is often reachable at many URLs: with and without www, over http and https, with and without a trailing slash, with tracking parameters, with sort orders, or through a printer-friendly version. A search engine that finds several such URLs groups them as duplicates and picks one, the canonical, to show in results.18 The canonical link relation, standardised in RFC 6596 and listed as a link type in the HTML Standard, lets the author say which one they prefer: it "indicates that URL given by the href attribute is the preferred URL for the current document".26,86



A canonical link, and the HTTP header form for non-HTML filesHTML
<!-- on https://lantern.example/menu?utm_source=newsletter&sort=price -->
<link rel="canonical" href="https://lantern.example/menu">

<!-- for a PDF, as an HTTP response header:
     Link: <https://lantern.example/menu.pdf>; rel="canonical" -->





Google treats the methods as signals of different strength that reinforce each other: redirects are a strong signal, rel="canonical" annotations are strong, and listing a URL in a sitemap is weak.18 A canonical is a hint, not a directive; if it points at a page that is very different, or contradicts other signals, the engine can choose another URL. Google's documentation gives the practical rules: use absolute URLs, put one canonical in the head, do not use robots.txt or noindex to pick a canonical, and send it as an HTTP Link header for files that are not HTML.18 Many sites also add a self-referencing canonical to every page, which protects against parameter variants they did not foresee.18 Note that the HTML Standard deliberately leaves canonical out of the tokens browsers "support": it is information for consumers like search engines, not something browsers act on.6


For permanent moves the redirect status matters. Google treats 301 and 308 as strong signals that the target should be canonical, and 302 and 307 as weak signals.67




3.6 Crawlability


A page is crawlable when a crawler can discover its URL and is permitted and able to fetch it. Discovery happens mainly through links and sitemaps; permission comes from robots.txt; and the fetch must succeed with a sensible status code.14,16,67



robots.txt


The Robots Exclusion Protocol, first written by Martijn Koster in 1994 and standardised in September 2022 as RFC 9309, lets a site ask crawlers not to fetch certain paths.16 The rules "MUST be accessible in a file named /robots.txt (all lowercase) in the top-level path of the service", and apply only to the host, protocol and port they are served from.16 A file consists of groups. Each group starts with one or more user-agent lines and contains allow and disallow rules matched against the URL path. The crawler uses the group that matches its own name most specifically, falling back to *.16



robots.txtTEXT
# https://lantern.example/robots.txt
User-agent: *
Disallow: /admin/
Disallow: /search          # internal search result pages
Allow: /search/help
Disallow: /*.pdf$          # * matches any characters, $ anchors the end

User-agent: ExampleBot
Disallow: /

Sitemap: https://lantern.example/sitemap.xml



When several rules match a path, "the most specific match is the match that has the most octets", and if an allow and a disallow rule are equally specific, the allow rule should be used.16 The order of the lines does not matter. Crawlers must parse at least 500 KiB of the file and should not use a cached copy for more than 24 hours. If the file returns a 4xx status the crawler may access anything; if it is unreachable (a 5xx status) the crawler must assume everything is disallowed.16 Other records, such as Sitemap, are allowed and ignored by crawlers that do not understand them.16 Test your own rules here:

Sitemaps


An XML sitemap lists the URLs a site wants crawled, with optional last-modification dates. Links, JavaScript and status codes


Google "can only discover your links if they are <a> HTML elements with an href attribute". A span with a click handler, an a with only an onclick, or a javascript: URL is not reliably followed.15,81 Pages built by JavaScript are crawled, then queued for rendering in evergreen Chromium, then indexed; server-side or static rendering removes the wait and works for every crawler, including those that do not run scripts.15 Finally, the response must be right: a 200 for real content, a 404 or 410 for content that is gone (Google does not index URLs that return 4xx codes), and a 5xx or 429 only for genuine trouble, since those make Google slow its crawling. A "not found" page that returns 200 is reported as a soft 404.67

3.8 Internal linking


Internal links, links from one page of a site to another, do three jobs at once: they let crawlers discover pages, they tell search engines which pages the site itself considers important and how they relate, and their text describes the target.3,14,81 A page with no internal links pointing to it (an orphan) can be found only through a sitemap or external links.





Google's link guidance comes down to a few rules. Use <a href>; make anchor text descriptive, reasonably concise and relevant to the target, rather than "click here"; avoid empty anchors; and for image links, give the image meaningful alt text, which is used as the anchor text.81 Navigation menus, breadcrumbs (ideally with BreadcrumbList structured data) and related-content links all help, as long as they are real links in the HTML.3,70

3.9 Structured data


Everything so far describes the document. Structured data describes the things in it, in a vocabulary a machine can read: this page is a Recipe whose cookTime is 30 minutes, this is a Product with an offers.price of 6.50 GBP. 3.10 Open Graph metadata


When a link is pasted into a social network or messaging app, the app fetches the page and builds a preview card from its metadata. Four properties are required for every page: og:title, og:type (such as website, article, profile or video.movie), og:image and og:url, the canonical URL that is used as the object's permanent ID.11 Optional properties include og:description, og:site_name, og:locale, og:locale:alternate, og:audio, og:video and og:determiner.11 An image can be described in more detail with structured properties placed after it: og:image:secure_url, og:image:type, og:image:width, og:image:height and og:image:alt; the protocol says a page that specifies og:image "should specify og:image:alt".11 Repeating a tag creates an array, and when tags conflict the first one wins.11

4Structured data


Structured data is a description of things as a graph: items that have a type and properties, whose values are text, numbers, URLs or other items. A café is an item of type CafeOrCoffeeShop; its name is "Lantern Café"; its address is another item, of type PostalAddress. To write that graph down you need two things: a vocabulary that names the types and properties, almost always schema.org on today's web, and a syntax for embedding it in HTML, of which there are three.37,68






4.1 Schema.org


Schema.org is a shared vocabulary for structured data on the web. It was founded by Google, Microsoft, Yahoo and Yandex, initiated by R. V. Guha of Google, and announced in June 2011; since April 2015 its main forum has been the W3C Schema.org Community Group.25,37 The vocabulary is versioned, and the current release at the time of writing is 30.1, published on 16 September 2026.29


Types form a hierarchy rooted at Thing. A type inherits every property of its parents, so CafeOrCoffeeShop, a subtype of FoodEstablishment, LocalBusiness and Organization, can use servesCuisine from FoodEstablishment, openingHours from LocalBusiness, address from Organization and name from Thing.94,97 Each property lists the types its values are expected to have: address expects a PostalAddress or text, aggregateRating an AggregateRating.94 By convention type names are written in UpperCamelCase and property names in lowerCamelCase, and terms are case-sensitive.8,98






4.2 JSON-LD


JSON-LD ("JSON for Linking Data") is a W3C Recommendation, version 1.1 of which was published on 16 July 2020, for expressing linked data as JSON.8 In HTML it is embedded in a script element whose type is application/ld+json. Because that is not a JavaScript MIME type, the HTML Standard treats the element as a data block: the browser does not execute it, and its contents are available to any program that reads the page.8,100 Google recommends JSON-LD because it keeps the data separate from the visible markup, which makes it easy to add, maintain and generate.68

4.6 Rich search results


A rich result is a search result with extra features drawn from structured data: star ratings, prices and stock, recipe cook times and images, event dates, breadcrumbs, or carousels. Google's search gallery lists the types it currently supports, among them Article, Breadcrumb, Carousel, Course list, Dataset, Discussion forum, Education Q&A, Employer aggregate rating, Event, Image metadata, Job posting, Local business, Math solver, Movie, Organization, Product, Profile page, Q&A, Recipe, Review snippet, Software app, Subscription and paywalled content, Vacation rental and Video.108 Each feature has its own documentation with required and recommended properties, which are usually narrower than schema.org's own definitions.107,108





Google's general structured data guidelines set the conditions for eligibility. The markup must be in a supported format and follow the feature's documentation; it must describe the main content of the page and be visible to readers ("don't mark up content that is not visible to readers of the page"); it must be up to date and not misleading; and spammy or manipulative markup can earn a manual action that removes rich results from the whole site.107 Two tools check the work. The Schema Markup Validator, run by schema.org, checks any schema.org markup in any of the three syntaxes; Google's Rich Results Test checks whether a page is eligible for Google's specific features and shows the rendered HTML Googlebot saw.68,109,110



The list of features changes. In August 2023 Google limited FAQ rich results to well-known, authoritative government and health websites and reduced HowTo rich results, later removing them.27 In June 2025 it announced it was phasing out seven more (Book Actions, Course Info, Claim Review, Estimated Salary, Learning Video, Special Announcement and Vehicle Listing) to simplify the results page, and in November 2025 it announced a further round.28,111 The markup for retired features does no harm, and other consumers may still read it, but it no longer produces a Google rich result.28 Check the search gallery before investing in a new type.108

Exercise 1: Find the problems


This head has at least eight problems. Find them.


Exercise 1HTML
<html lang="en-UK">
<head>

Show solution

    2.

    3.

    4.

    5.

    6. 

  6. The description is generic and says nothing about the page.54
    7. 

  7. keywords is ignored by Google; the list is keyword stuffing anyway.10
    8. 

  8. The canonical URL is relative; Google asks for absolute URLs.18
    9. 

  9. og:image is relative, and the other three required Open Graph properties (og:title, og:type, og:url) and og:image:alt are missing.11

Exercise 2: Allowed or disallowed?


Using the RFC 9309 rules, decide whether Googlebot may crawl each path.


robots.txtTEXT
User-agent: *
Disallow: /shop/
Allow: /shop/gift-cards
Disallow: /*?sessionid=

User-agent: Googlebot
Disallow: /drafts/


  1. /shop/mugs
  2. /drafts/new-menu
  3. /menu?sessionid=42
  4. /shop/gift-cards/50


Show solution


The crawler obeys only the most specific group that matches its name. Googlebot has its own group, so the * group does not apply to it at all.16 (a) Allowed. (b) Disallowed. (c) Allowed. (d) Allowed. For any crawler without its own group, the answers would be: (a) disallowed; (b) allowed; (c) disallowed, because * matches any characters; (d) allowed, because /shop/gift-cards (16 octets) is a longer match than /shop/ (6 octets).16 Paste the file into the tester in section 3.6 to check.









Exercise 3: Why is it still in the results?


A site added <meta name="robots" content="noindex"> to its old staff directory and added Disallow: /staff/ to robots.txt. Weeks later, the directory URL still appears in search results with the note that no information is available. Explain why, and fix it.


Show solution


Because crawling is disallowed, Googlebot never fetches the page, so it never sees the noindex. The URL is still known from links elsewhere, so it can be listed without a snippet.17,20 Remove the Disallow rule so the page can be crawled and the noindex read; once it has dropped out, you can block crawling again if you wish. If the content must not be public at all, protect it with authentication or remove it and return 404 or 410.16,67









Exercise 4: One page, five URLs


The menu page answers at http://lantern.example/menu, https://www.lantern.example/menu, https://lantern.example/menu, https://lantern.example/menu?ref=flyer and https://lantern.example/menu?lang=en (identical to the default). Which should be canonical, and what would you do with each of the others?


Show solution


Canonical: https://lantern.example/menu (HTTPS, the site's preferred host, no parameters). Redirect the http: and www variants with a 301 or 308, which Google treats as a strong canonical signal. The two parameter variants must keep working, so leave them reachable and give every version a <link rel="canonical" href="https://lantern.example/menu">, which is also a strong signal. List only the canonical in the sitemap, and link to it internally.18,67
