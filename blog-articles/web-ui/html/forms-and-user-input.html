Earlier articles in this series covered how a document is built, the text inside it, links, media, semantic structure and tables. All of those carry information from the server to the reader. Forms carry it the other way. A form is the only part of HTML that lets a page collect data and send it to a server without any JavaScript,1 and it is where front-end markup meets back-end code: the names you give your fields become the keys your server reads, and the method and enctype you choose decide the shape of the HTTP request it receives.2,3

Section 2 covers the elements that build a form, section 3 every value of type on input, and section 4 the attributes that configure forms and controls. Section 5 follows the data out of the browser and onto the server, including the security work every form handler needs. Sections 6 to 11 hold a complete worked example, exercises, trivia, a submission inspector, a playground and a quick-reference table.

1Introduction

1.2 How a form works

The standard's introduction describes a form as "a component of a web page that has form controls, such as text, buttons, checkboxes, range, or color picker controls," with which "a user can interact … providing data which can then be sent to the server for further processing."1 Figure 1 shows the round trip. The browser does the first half (gathering, checking and encoding the data); the server does the second (decoding, checking again, acting, and answering).2,13

1.3 A short history

Forms were not in the first versions of HTML. The earliest way for a page to ask the user for anything was the ISINDEX element, which displayed a single search box and sent its words to the server in the query string.15 HTML 2.0, published as RFC 1866 in November 1995, was the first standard to define FORM, INPUT, SELECT, OPTION and TEXTAREA, with the input types text, password, checkbox, radio, submit, reset, image and hidden, and with application/x-www-form-urlencoded as the only encoding.16 File upload arrived the same month in RFC 1867, which added type="file" and the multipart/form-data encoding.17 HTML 4.0 (1997, revised as HTML 4.01 in 1999) added button, label, fieldset, legend and optgroup.18

The next big step came from browser vendors. In April 2005 Opera Software and the Mozilla Foundation submitted Web Forms 2.0, edited by Ian Hickson, to the W3C, proposing new input types such as email, url, date and number together with the required, pattern, min and max attributes for validation without script.19 That work was folded into HTML5 and lives on in today's Living Standard, which added datalist, output and the constraint validation API.4,20 The W3C's own next-generation design, XForms, became a separate XML-based Recommendation in 2003; it took a different path and is not part of HTML.21

1.4 Forms and accessibility

Forms are where accessibility failures cost users the most, because a form that cannot be completed blocks the task entirely. WebAIM's annual survey of the top million home pages has repeatedly found missing form labels among the most common detectable WCAG failures, alongside low contrast and missing alternative text.23 WCAG 2.2 has several success criteria aimed directly at forms, summarised in Table 2; the W3C's forms tutorial explains how to meet them with plain HTML.24

2.1 The form element

<form>

Flow contentRole: form (when named)No nested forms

A form "represents a hyperlink that can be manipulated through a collection of form-associated elements, some of which can represent editable values that can be submitted to a server for processing."38 Its content model is flow content with one restriction: it must not contain another form.38 The HTML parser enforces this by ignoring a <form> start tag while another form is open, so nested forms silently disappear.44 Its attributes are accept-charset, action, autocomplete, enctype, method, name, novalidate, rel and target; section 4 covers each one.38

A form with no attributes at all is valid. It submits with GET to the current page's URL, which is often exactly what a search or filter form wants.45 A form element only gets the ARIA role form, and so only becomes a landmark, when it has an accessible name, for example from aria-label or aria-labelledby.36,46

A minimal search form (GET to the current URL)HTML
<form role="search" aria-label="Site">
  <label for="d-q">Search the docs</label>
  <input type="search" id="d-q" name="q" value="fieldset">
  <button>Search</button>
</form>
Rendered in your browser

A control does not have to be inside its form. The form attribute on any listed element names the id of the form it belongs to, which lets a button in a page footer submit a form in the page body, or lets one table row hold controls for several forms.47

2.2 The label element

<label>

Phrasing contentInteractiveOne labelled control

A label "represents a caption in a user interface."39 It is associated with a control in one of two ways: explicitly, by putting the control's id in its for attribute, or implicitly, by wrapping the control. Either way, activating the label (clicking or tapping it) activates or focuses the control, which gives small checkboxes and radio buttons a much bigger target.39,48 The label's text also becomes the control's accessible name, which is what a screen reader announces when the control gains focus.35

Explicit and implicit labelsHTML
<p><label for="d-name">Full name</label><br>
<input id="d-name" name="name" autocomplete="name"></p>

<p><label><input type="checkbox" name="terms"> I accept the terms</label></p>
Rendered in your browser


Do

Give every control a visible label. Prefer for/id for text fields; wrapping is convenient for checkboxes. Both are sufficient techniques for WCAG.29,49

Don't

Rely on placeholder or a nearby <span> as the label. A placeholder disappears as soon as the user types, and adjacent text is not programmatically tied to the field.48,50

A label may contain only phrasing content, may not contain another label, and may contain no labelable element other than the one it labels.39 A control can have several labels (they are all available as input.labels), but each label points to exactly one control.39

2.3 The input element

<input>

Void element22 typesListed · submittable · resettable · labelable

The input element "represents a typed data field, usually with a form control to allow the user to edit the data."51 It is a void element, so it has no end tag and no content.51 Its type attribute selects one of twenty-two states, each with its own user interface, value format, validation rules and set of attributes that apply. If type is missing or has an unknown value, the input is a plain text field.51 Section 3 describes every type.

input is a void elementHTML
<input type="text" name="city">          <!-- correct -->
<input type="text" name="city" />        <!-- also fine: the slash is ignored -->
<input type="text" name="city"></input>  <!-- invalid: the end tag is a parse error -->

2.4 The textarea element

<textarea>

Escapable raw textMulti-line

A textarea "represents a multiline plain text edit control for the element's raw value."52 Its content is text only, and that text is the control's initial value, so there is no value attribute.52 The parser drops a single newline straight after the start tag, so the source can put the text on its own line.44 rows and cols suggest a size (defaults 2 and 20); wrap="hard" makes the browser insert line breaks into the submitted value at the visual wrap points, and requires cols.52 Line breaks in the submitted value are normalised to CRLF (%0D%0A).52,53

A textarea with a character limitHTML
<label for="d-bio">Short bio (up to 160 characters)</label><br>
<textarea id="d-bio" name="bio" rows="3" cols="40" maxlength="160">
I write about the web.</textarea>
Rendered in your browser

2.5 The select, option and optgroup elements

<select> · <option> · <optgroup>

Role: combobox or listbox

A select "represents a control for selecting amongst a set of options."54 Without multiple and with no size greater than 1 it renders as a drop-down box and has the role combobox; otherwise it is a list box (role listbox) with a default height of four rows when multiple is present.36,54 Each option represents a choice. Its value attribute is what gets submitted; if value is absent, the option's text is submitted instead. A label attribute can give a shorter display label, disabled makes it unselectable, and selected marks the default choice.55

An optgroup groups options under a heading given by its required-in-practice label attribute. Groups cannot be nested, and a disabled group disables all its options.56

Options grouped with optgroup, and a placeholder optionHTML
<label for="d-tz">Time zone</label><br>
<select id="d-tz" name="tz" required>
  <option value="">Choose a time zone…</option>
  <optgroup label="Europe">
    <option value="Europe/London">London</option>
    <option value="Europe/Paris" selected>Paris</option>
  </optgroup>
  <optgroup label="Americas">
    <option value="America/New_York">New York</option>
    <option value="America/Los_Angeles" label="Los Angeles">Los Angeles (Pacific)</option>
  </optgroup>
</select>
<button>Save</button>
Rendered in your browser

The first option above is a placeholder label option: when a required single-choice select has a first option with an empty value, choosing it counts as no choice, so the form will not submit.54 A multi-choice select submits one name–value pair per selected option, all with the same name.57

Newer: customizable selectBrowsers have begun shipping an opt-in mode, enabled in CSS with appearance: base-select, that lets authors style the drop-down picker and put rich content inside options while keeping the native element's keyboard and accessibility behaviour. Check support before relying on it.58

2.6 The datalist element

<datalist>

Not renderedSuggestions only

A datalist "represents a set of option elements that represent predefined options for other controls."59 It is linked to an input through the input's list attribute and renders nothing itself. Unlike a select, it only suggests: the user may still type any value, so it does not constrain what is submitted.59,60 It works with text-like, numeric, date and colour inputs; on range some browsers draw the options as tick marks.60,61

2.7 The button element

<button>

Phrasing contentRole: buttonDefault: Auto (submit in a form)

A button "represents a button labeled by its contents."62 Its type attribute has three keywords: submit (submits the form), reset (resets it) and button (does nothing by default, for use with script). When type is missing or invalid the button is in the Auto state, which behaves as a submit button unless the button has command/commandfor attributes or sits directly inside a select,62 which is the most common forms bug of all: a "Show password" or "Add another" button inside a form that, without type="button", submits the form when clicked.

A button's content can be any phrasing content except interactive content, so it can hold an icon and text, which input type="submit" cannot.62 If it has a name, its value is submitted only when it is the button that was used to submit, which lets one form offer several actions.57 Submit buttons can also override the form's settings with formaction, formmethod, formenctype, formnovalidate and formtarget.45

One form, two actionsHTML
<form action="/drafts" method="post">
  <label for="d-post">Post</label><br>
  <textarea id="d-post" name="body" rows="2" cols="40" required>Hello, world</textarea><br>
  <button name="intent" value="publish">Publish</button>
  <button name="intent" value="draft" formnovalidate>Save draft</button>
  <button type="reset">Clear</button>
  <button type="button" onclick="this.form.body.value += ' 👋'">Add wave</button>
</form>
Rendered in your browser


2.8 The fieldset and legend elements

<fieldset> · <legend>

Role: grouplegend must be first child

A fieldset "represents a set of form controls (or other content) grouped together, optionally with a caption," and the caption is given by a legend, which must be the fieldset's first child.40,41 The fieldset has the role group, and its legend becomes the group's accessible name, so a screen reader announces "Delivery speed, group" before reading the first radio button's own label.35,63 Grouping is required whenever the individual labels do not make sense alone, such as a set of radio buttons or a date split into three fields.63,64

A disabled fieldset disables every control inside it, except those inside its first legend. That exception lets a checkbox in the legend switch the whole group on and off.40,65

Radio buttons grouped by fieldset, with a legend switchHTML
<form action="/checkout" method="post">
  <fieldset>
    <legend>Delivery speed</legend>
    <label><input type="radio" name="speed" value="standard" checked> Standard (3–5 days)</label><br>
    <label><input type="radio" name="speed" value="express"> Express (next day)</label>
  </fieldset>
  <fieldset id="d-gift" disabled>
    <legend><label><input type="checkbox" onchange="this.closest('fieldset').disabled = !this.checked"> This is a gift</label></legend>
    <label for="d-msg">Gift message</label><br>
    <input id="d-msg" name="gift_message" size="36">
  </fieldset>
  <button>Continue</button>
</form>
Rendered in your browser
Delivery speed

Notice in the output that the gift message is not sent while the box is unchecked: disabled controls are never submitted.57 The checkbox itself has no name, so it is never sent either.

2.9 The output element

<output>

Role: statusNot submitted

An output "represents the result of a calculation performed by the application, or the result of a user action."66 Its for attribute lists the ids of the controls that contributed to the result. It has the implicit role status, which is a polite live region, so screen readers announce changes without moving focus.36,67 Although it can have a name and is reset with the form, an output is not submittable: its value is never sent to the server.43

3.1 Text entry: text, search, password, email, tel, url

text is a single-line plain-text field, and the state every unknown or missing type falls back to. Line breaks are stripped from its value.71 search behaves identically; the difference is presentational and semantic, so a browser may draw it with rounded corners or a clear button.71

password obscures what is typed so that onlookers cannot read it.72 It does not encrypt anything: the value is sent in clear text unless the page uses HTTPS. Use autocomplete="current-password" on login forms and autocomplete="new-password" on sign-up and change-password forms so password managers can fill and generate passwords correctly.73,74 NIST's digital identity guidelines (SP 800-63B-4) say verifiers should accept passwords of at least 64 characters, must not impose composition rules such as "one digit and one symbol", and must allow password managers and autofill; WCAG 3.3.8 makes support for paste and password managers an accessibility requirement as well.33,75

email checks that the value is a syntactically valid email address, or with multiple a comma-separated list of them.76 The standard's definition is deliberately stricter and simpler than the address grammar in RFC 5322; the spec calls it "a willful violation of RFC 5322", because the full grammar allows forms such as comments and quoted strings that no one types into a web form.76,77 Passing the check proves only that the text looks like an address. Only sending a message proves it works.13

url requires a valid absolute URL, so example.com fails but https://example.com passes.78 tel is the odd one out: because telephone number formats vary so much around the world, it applies no syntax check at all. Its value is still useful, because phones show a dial pad and autofill can offer the user's number.69,79

3.2 Numbers: number and range

number accepts a floating-point number and exposes it to script through valueAsNumber. Its default step is 1, so 2.5 is a step mismatch unless you add step="0.1" or step="any".80,81 The browser shows a localised number but always submits it with a full stop as the decimal separator.82

number is for quantities, not for every string of digits. Card numbers, postcodes, account numbers and one-time codes are identifiers: they can have leading zeros, they are never incremented, and a spinner or a scroll wheel can change them by accident. The GOV.UK Design System advises not to use type="number" unless research shows a need, and to use type="text" with inputmode="numeric" for whole numbers instead.83 The standard makes the same point: it says number is not appropriate for input that merely consists of digits, such as credit card numbers or US postal codes, and suggests asking whether a spin box with up and down arrows would make sense for the field.80

range is for values where the exact number matters less than the position, such as volume. It always has a value: the default range is 0 to 100 and the default value is halfway between the minimum and maximum, so an untouched slider submits 50.84

5Form processing

This section follows the data from the moment the user presses Submit to the moment the server answers. The browser half is specified precisely in HTML §4.10.22 Form submission;2 the server half is a matter of HTTP semantics and security practice.3,13

5.1 Form submission

A form is submitted when the user activates a submit button, when the user presses Enter in a field (implicit submission), or when a script calls form.requestSubmit().2,38 Implicit submission uses the form's default button, the first submit button in tree order; a form without a submit button can still be submitted with Enter if it has only one field.130 The browser then:

  1. runs interactive constraint validation, unless the form has novalidate or the submitter has formnovalidate. If any control is invalid, it reports the problem (usually focusing the first invalid field and showing a message) and stops;114
  2. fires a cancelable submit event at the form, a SubmitEvent whose submitter property is the button used. If a script calls preventDefault(), nothing is sent;131
  3. constructs the entry list, a list of name–value pairs, then fires a formdata event that lets scripts add or change entries;57,132
  4. encodes the list according to the method and encoding type, and navigates to the action URL with the resulting request, opening the response in the target.2

By contrast, the older form.submit() method skips steps 1 and 2: it neither validates nor fires submit. Use requestSubmit() when you want script-triggered submission to behave like a real click.38

5.3 URL-encoded form data

application/x-www-form-urlencoded is the default encoding and the one GET always uses. It is defined in the URL Standard, and its serializer works as follows:5,53

  1. Each name and value is encoded as UTF-8 (the only encoding the standard now allows for forms).5,38
  2. ASCII letters, digits and the four characters * - . _ are kept as they are.
  3. Each space becomes +.
  4. Every other byte becomes % followed by two upper-case hex digits, so & becomes %26, + becomes %2B, and é (two bytes in UTF-8) becomes %C3%A9.
  5. Each name is joined to its value with =, and the pairs are joined with &.

Line breaks in values are first normalised to CRLF, so a newline in a textarea arrives as %0D%0A.57

5.4 Multipart form data

multipart/form-data, defined in RFC 7578, sends each entry as a separate part of the body.6 The parts are separated by a boundary, a string chosen by the browser that does not occur in the data, and announced in the Content-Type header.6,141 Each part has a Content-Disposition: form-data header carrying the field's name; a file part also carries the filename and a Content-Type header for the file's media type, and then the file's raw bytes.6,142 Because the bytes are not percent-encoded, multipart is much more efficient than URL encoding for binary data, which is why it is the only encoding that can upload files.6

The third encoding, text/plain, writes each pair as name=value on its own line with no escaping at all. Because a value containing = or a line break cannot be told apart from the separators, the standard warns that it is "not reliably interpretable by computer" and is meant only for humans; avoid it.143

The three encodings are no accident. They are exactly the three Content-Type values a page may send cross-origin without a CORS preflight, because they are what a plain HTML form could always send.144 That fact matters for CSRF (section 5.10).

5.5 File uploads

A working upload form needs three things on the client: method="post", enctype="multipart/form-data", and an input type="file" with a name.2,97 Everything else happens on the server, and almost all of it is security. OWASP's File Upload Cheat Sheet lists the controls every upload handler needs:98

  • Allow-list extensions for the business need, and check them after decoding the filename.
  • Do not trust Content-Type or the filename sent by the client; verify the file's real type, for example by its signature bytes or by re-encoding images.
  • Rename files with a server-generated name, and never use the client's filename in a file system path (path traversal such as ../../etc/passwd).
  • Limit size, both per file and per request, and limit the number of files.
  • Store outside the web root, or on a separate domain or object store, and serve with Content-Disposition: attachment and X-Content-Type-Options: nosniff where appropriate.
  • Require authentication and CSRF protection, and scan for malware where the risk warrants it.

On the client, the File API lets you show a preview or check the size before upload, which improves the experience but proves nothing to the server.98,101 HTTP has a dedicated status code for oversized uploads, 413 Content Too Large.145

5.6 Client-side validation

The attributes in section 4 are constraints. Every submittable control that is not barred from validation (disabled, read-only, hidden, or a button) has a validity property, a ValidityState object with one boolean flag per kind of failure.114,122

The constraint validation API exposes this to scripts: checkValidity() returns a boolean and fires invalid events; reportValidity() does the same and shows the browser's messages; setCustomValidity(message) marks a field invalid with your message (pass an empty string to clear it); and validationMessage gives the current message.146 In CSS, :invalid matches from the moment the page loads, which makes a fresh form look full of errors; :user-invalid matches only after the user has interacted with the field or tried to submit, and is almost always the better choice.10,147

Built-in error bubbles are quick but limited: you cannot style them, they disappear after a few seconds, and not all assistive technologies announce them reliably.     5.7 Server-side validation

    Everything that arrives from a browser is untrusted input, including hidden fields, select values, cookies and headers. OWASP's Input Validation Cheat Sheet recommends validating it as early as possible, on a trusted system, using an allow-list (define exactly what is acceptable and reject everything else) rather than a deny-list of known-bad patterns.13 It distinguishes two levels:13

    • Syntactic validation: the value has the right form. Is it present? Is it a number, a date, an email, a known enum value, within the length limit?
    • Semantic validation: the value makes sense in context. Is the start date before the end date? Does this user own the record ID in the hidden field? Is the price the one in the database, not the one the form sent?

    When validation fails, respond with the form re-displayed: keep what the user typed (except passwords), show the messages, and use a 4xx status code. RFC 9110 defines 422 Unprocessable Content for a request whose syntax is fine but whose content cannot be processed, which fits failed form validation well; 400 Bad Request is for malformed requests.152,153 When it succeeds, perform the action and respond with 303 See Other, so that the browser fetches the result page with GET and a reload does not resubmit the form. This is the Post/Redirect/Get pattern.14

    5.8 Form submission with JavaScript

    Many applications intercept the submit event and send the data with fetch() so the page does not reload.     5.9 HTML integration with REST APIs

    REST APIs use the HTTP methods for their meaning: GET to read, POST to create, PUT or PATCH to replace or modify, and DELETE to remove.157,158 HTML forms can send only GET and POST, so there are three common ways to connect a form to such an API:

    1. Method override. The form sends POST with a hidden field such as <input type="hidden" name="_method" value="DELETE">, and server middleware rewrites the method. Ruby on Rails and Laravel both use this convention.159,160
    2. A server-rendered layer. The HTML-serving server accepts the form POST and calls the API itself, then redirects with 303. The browser never talks to the API directly.
    3. JavaScript. The page cancels the submission and calls the API with fetch(), using any method and any body format, often JSON.144

    5.10 CSRF considerations

    Cross-site request forgery (CSRF) tricks a user's browser into sending a state-changing request to a site where the user is logged in. It works because browsers attach a site's cookies to requests to that site, even when another site started the request, and because any page can contain a form that auto-submits to any URL.11 Figure 10 shows the attack and the three defences.

    OWASP's first recommendation is to use the CSRF protection built into your framework, rather than writing your own.11 The underlying techniques are:

    • Synchronizer token pattern. The server generates an unpredictable token per session (or per form), puts it in a hidden field, and rejects any state-changing request whose token does not match. The same-origin policy stops the attacker's page from reading the token.11
    • Signed double-submit cookie, for stateless servers: the token is placed in both a cookie and the form, and is bound to the session with an HMAC so it cannot be planted. OWASP recommends the signed variant and discourages the naive one.11
    • Fetch Metadata. Browsers send Sec-Fetch-Site (same-origin, same-site, cross-site or none) on every request, so a server can reject cross-site POSTs outright; checking the Origin header is a similar, older technique.11,164
    • SameSite cookies. A session cookie with SameSite=Lax is not sent on cross-site subresource or POST requests, and SameSite=Strict is not sent on any cross-site request, which blocks the classic attack in Figure 10.163 OWASP treats it as defence in depth rather than a replacement for tokens.11

    5.11 Input sanitization and output encoding

    Three related terms are often blurred together:

    • Validation decides whether input is acceptable and rejects it if not (section 5.7).
    • Sanitization changes input to make it safe, for example by removing disallowed tags from user-supplied HTML.
    • Output encoding (escaping) converts data at the moment it is placed into an HTML page, a URL, a script or a query, so that it is treated as data and not as code.

    OWASP is clear about the roles. Input validation reduces the attack surface but "should not be used as the primary method of preventing XSS, SQL injection and other attacks."13 The primary defence against cross-site scripting (XSS) is output encoding appropriate to the context the data is written into, and the primary defence against SQL injection is parameterised queries.12,154 The reason is that the same string can be harmless in one context and dangerous in another: O'Brien is a valid name, but breaks out of a single-quoted SQL string or HTML attribute if it is not encoded for that context.

      RFC 1866, Hypertext Markup Language – 2.0, published in November 1995.16

    2. Which RFC introduced <input type="file"> and multipart/form-data?
      Answer

      RFC 1867, Form-based File Upload in HTML, by Ernesto Nebel and Larry Masinter of Xerox, November 1995.17

    3. Which RFC did RFC 7578 obsolete as the definition of multipart/form-data?
      Answer

      RFC 2388, from 1998. RFC 7578 was published in July 2015, also authored by Larry Masinter.6

    4. What does a script get when it reads the value of a file input after the user picks cv.pdf?
      Answer

      C:\fakepath\cv.pdf, on every operating system, so the real path is never exposed.100

    5. What does a checked checkbox with no value attribute submit?
      Answer

      The string on.92

    6. How does the HTML standard describe its own definition of a valid email address, relative to RFC 5322?
      Answer

      As "a willful violation of RFC 5322".76

    7. Which method keyword sends no HTTP request at all?
      Answer

      dialog. It closes the enclosing dialog and sets its returnValue.45

    8. Which name may a form control not have, as a relic of an element older than forms?
      Answer

      isindex.42

    9. What does an untouched <input type="range"> submit?
      Answer

      50: the default range is 0 to 100 and the default value is the midpoint.84

    10. Which input type has a periodic domain, so min may be greater than max?
      Answer

      time, because times wrap around midnight.90

    11. What minimum URI length does RFC 9110 recommend that all senders and recipients support?
      Answer

      8000 octets.136

    12. What two fields does <input type="image" name="map"> submit?
      Answer

      map.x and map.y, the coordinates of the click.107

    13. How many characters does maxlength count the emoji 🙂 as?
      Answer

      Two, because length is measured in UTF-16 code units.123

    14. Which form method skips both constraint validation and the submit event?
      Answer

      form.submit(). form.requestSubmit() does both.38

    15. Which HTTP status code does the Post/Redirect/Get pattern use?
      Answer

      303 See Other, which tells the client to fetch the new location with GET.14

    16. What value is filled into <input type="hidden" name="_charset_">?
      Answer

      The name of the character encoding used to submit the form, in practice UTF-8.42

    17. Which two organisations submitted Web Forms 2.0 to the W3C in 2005?
      Answer

      Opera Software and the Mozilla Foundation.19

    18. Which three Content-Type values can a page send cross-origin without a CORS preflight?
      Answer

      application/x-www-form-urlencoded, multipart/form-data and text/plain, the same three values as enctype.144

    Accessibility

    Visible label for every control; fieldset/legend for groups; hints and errors via aria-describedby; an error summary; autocomplete tokens.24–26,28

    Validation

    Client side for the user's convenience, server side for correctness and security. Allow-list, check types and ranges, and re-check every hidden or "fixed" value.13

    CSRF

    Framework protection first; synchronizer token or signed double-submit cookie; SameSite cookies and Sec-Fetch-Site checks; never change state on GET.11,163,164

    Output

    Encode for the context at output time; textContent not innerHTML; parameterised SQL; sanitize rich HTML with a library; add a CSP.12,154,165

    Uploads

    POST + multipart; allow-list extensions; verify real type; rename; limit size; store outside the web root.98
