HTML Tables

The ten table elements, from table and caption to colgroup and col; how colspan and rowspan place cells on the grid; how th, scope and headers tie every data cell to its headers; and how to build data tables that work with screen readers and on small screens. Grounded in the HTML Living Standard, CSS 2.1, WCAG 2.2 and the W3C's tables tutorial.

Updated 14 November 202677 references (Vancouver style)Includes exercises, trivia, a table inspector and a live playground

The earlier articles in this series covered how an HTML document is built, the text inside it, links and navigation, images, audio and video and semantic structure. This one is about the one HTML feature that is two-dimensional. The standard says that a table element "represents data with more than one dimension, in the form of a table",1 and the browser has to work out, for every cell, which row and column it sits in and which header cells describe it.2,3 Get the markup right and a screen reader can say "Q2, Pears, 95" as a user moves through the grid; get it wrong and the same table becomes a stream of unconnected numbers.4,5

The article follows the outline in the table of contents. Section 2 covers each table element, section 3 the attributes and the table model behind them, and section 4 accessibility, responsive design, styling and the DOM. Sections 6 to 10 hold exercises, trivia questions, a table inspector that shows the header cells your browser would assign, a playground and a quick-reference table.

1Introduction

1.1 Where tables are defined

The elements and attributes live in section 4.9 of the HTML Living Standard, "Tabular data". The same section also holds the processing model: the algorithm that turns markup into a grid of cells and the algorithm that decides which header cells apply to each data cell.2,3,6 How tables look is CSS's job. The CSS 2.1 table model defines the display values, column styling, the two layout algorithms and the two border models.7 How tables reach assistive technology is set by the accessibility mappings and WAI-ARIA,8,9 and what makes them accessible is set by WCAG.10

1.3 A short history

Tables were not part of the first versions of HTML. Dave Raggett's RFC 1942, HTML Tables, published as an experimental RFC in May 1996, proposed the model that is still recognisable today, with captions, header and data cells, and spanning.16 HTML 3.2, a W3C Recommendation of 14 January 1997, standardised tables as "a widely deployed subset" of that RFC.17 HTML 4.01 (1999) added the structural parts: thead, tbody, tfoot, colgroup and col, along with the accessibility attributes scope, headers, abbr, axis and summary.18 CSS 2.1 then gave tables a full presentation model, so borders, spacing and alignment could move out of HTML attributes and into style sheets.7

1.4 Data tables, not layout

Before CSS layout was reliable, many sites used invisible tables to place a logo, a sidebar and content side by side. The Living Standard now says plainly: "Tables must not be used as layout aids." It points to CSS grid, flexbox, multi-column layout, positioning and the CSS table model instead.1 The W3C tutorial agrees that "tables aren't meant to be used for layout purposes",4 and MDN's guide calls table-based layout "a bad idea".13

The reason is not just neatness. A screen reader announces a table as a table, reads its dimensions, and offers table navigation commands, which is noise on a layout grid.20 A layout table is also read in source order, cell by cell, which can scramble the content: WCAG lists that as failure F49 of SC 1.3.2 Meaningful Sequence.21,22 If you inherit a legacy layout table, the WAI advice is to leave out th and caption (using them is failure F46) and add role="presentation" so assistive technology ignores the table structure.23,24

Avoid

A layout tableHTML
<table>
  <tr>
    <td><nav>…</nav></td>
    <td><main>…</main></td>
  </tr>
</table>

A table used only to put two blocks side by side. It is non-conforming, and assistive technology may announce a one-row, two-column table.1,20

Prefer

<div style="display:grid; grid-template-columns:14rem 1fr">
  <nav>…</nav>
  <main>…</main>

The same layout with CSS grid, one of the alternatives the standard lists. The source order stays meaningful.1

The test for whether something is a data table is simple: does the content have meaningful rows and columns, so that each cell is understood by looking along its row and up its column? A price list, a timetable or a set of test results is tabular. A list of links laid out in three columns is not; it is a list styled with CSS.1,4

2.1 The table element

FlowPalpableBoth tags requiredRole: table

The table element "represents data with more than one dimension, in the form of a table". Neither its start tag nor its end tag may be omitted, and it has no attributes of its own beyond the global ones.1 Its content model is strict and ordered: optionally a caption; then zero or more colgroup elements; then optionally a thead; then either zero or more tbody elements or one or more tr elements; then optionally a tfoot. Script-supporting elements (script and template) may be mixed in.1

Everything that used to be a table attribute for presentation is now obsolete: align, bgcolor, border, cellpadding, cellspacing, frame, rules, width and height among them, together with summary.19,25 The standard's own guidance is that authors "are encouraged to use CSS to achieve these effects".1 Table 3 gives the usual CSS replacement for each.

2.2 The caption element

First child of tableFlow content, no nested tablesRole: caption

A caption "represents the title of the table that is its parent". It must be the first element child of the table, and it may contain flow content but no descendant tables.28,29 Because it is part of the table, assistive technology announces it as the table's accessible name, which is why WCAG technique H39 recommends it as the way to identify a data table.30,31 The W3C tutorial describes the caption as acting "like a heading for a table".31

The caption is rendered above the table by default; the CSS caption-side property moves it below without changing the source order.7,32 The old align attribute on caption is obsolete.19 When a table is the only content of a figure apart from its figcaption, the standard says the caption should be omitted in favour of the figcaption.28,33

2.3 The thead element

At most one per tableContains trRole: rowgroup

The thead element "represents the block of rows that consist of the column labels (headers)" for its parent table. It comes after any caption and colgroup elements and before any tbody, tfoot and tr, and a table may have only one.34 It contains zero or more tr elements (and script-supporting elements). Its end tag may be omitted if it is immediately followed by a tbody or tfoot.34

A thead does not by itself make its cells headers: you still need th elements inside it.34,35 What it does give you is a row group that CSS can target, that some browsers repeat at the top of every printed page when a long table breaks, and that screen readers expose as a rowgroup.7,9,36

2.4 The tbody element

Any numberTags optionalRole: rowgroup

A tbody "represents a block of rows that consist of a body of data for the parent table". It comes after any caption, colgroup and thead, and a table can have several, so long as the table has no tr children of its own.37,38 Several bodies are a way to group rows under a shared heading, such as the months of each quarter, which section 3.7 uses with scope="rowgroup".35,37

Both tags are optional: the start tag can be omitted if the first thing inside it is a tr, and the end tag if it is followed by another tbody, a tfoot or nothing.37,39 In practice you almost never need to write it for a simple table, because the parser inserts it. In the standard's words, "If a tr element is put inside a table in the markup, it will in fact imply a tbody start tag before it."40 MDN puts it more bluntly: tbody "is always implicitly included in every table".20 Section 2.11 shows why that matters for CSS selectors and scripts.

2.5 The tfoot element

At most one, lastContains trRole: rowgroup

The tfoot element "represents the block of rows that consist of the column summaries (footers)" of the table: totals, averages, notes. It comes after the caption, colgroup, thead, tbody and tr elements, and a table may have only one.41,42 HTML 4.01 actually required tfoot to come before the bodies, so that a browser could draw the footer before a long body had downloaded.18 In current HTML it must come last, which also matches the order in which it is read aloud.41

2.6 The tr element

Contains th and tdEnd tag optionalRole: row

A tr "represents a row of cells in a table". It is used inside a thead, tbody or tfoot, or directly inside a table that has no tbody elements (in which case the parser supplies one). It contains zero or more td and th elements, and its end tag may be omitted before another tr or at the end of its parent.39,43,44

Rows are the only real structure in an HTML table. There is no element for a column; columns emerge from the way cells line up row after row, and the colgroup and col elements merely describe them.2,15

2.7 The th element

Child of trFlow content (no headings, header, footer, sectioning)Role: columnheader / rowheader

A th "represents a header cell in a table". It may contain flow content, but no header, footer, sectioning content or heading content; a table header is not a document heading.45 Its attributes are colspan, rowspan and headers, shared with td, plus two of its own: scope, which says which cells it applies to, and abbr, which supplies "an alternative label for the header cell, to be used when referencing the cell in other contexts", typically a shorter form.11,45

Browsers render th bold and centred by default, but that is presentation; the meaning is in the element, so do not use th just to get bold text, and do not fake a header with a bold td.46,47 Section 3.4 explains how the browser decides whether a th is a column header or a row header.

2.8 The td element

Child of trFlow contentRole: cell

A td "represents a data cell in a table". It may contain any flow content, including lists, paragraphs, images, forms or, if you really must, another table.48 Its attributes are colspan, rowspan and headers.11 The standard adds that, when a user agent lists the header cells that apply to a data cell, it may use their abbr values.48 The old abbr, axis and scope attributes on td are obsolete; for axis, the standard says to "use the scope attribute on the relevant th" instead.19,27

Empty data cells are allowed. If a cell has no value, it is often clearer to say so in words ("n/a", "none", "0") than to leave it blank, so that a screen-reader user can tell an empty cell from a missed one.

2.9 The colgroup element

A colgroup "represents a group of one or more columns in the table that is its parent". It goes after any caption and before the row groups and rows.14 It can describe its columns in one of two ways: with a span attribute and no content, or with col children and no span. The span value must be an integer from 1 to 1000; without one, an empty colgroup covers one column.14,49

2.10 The col element

VoidChild of colgroupNo role

A col represents one or more columns in its column group. It is a void element (no content, no end tag) used inside a colgroup that has no span, and its own span, from 1 to 1000, says how many adjacent columns it covers.15,50

Because columns do not contain cells, CSS can apply only a few properties through them. CSS 2.1 §17.3 lists exactly four: border (only with collapsed borders), background (visible only where the cell and row are transparent), width (a minimum width) and visibility (where collapse hides the column).7 Text colour, alignment and padding cannot be set on a column; for those, select the cells, for example with td:nth-child(3).7,51

2.11 Order, optional tags and the parser

Figure 3 shows the order the content model requires. Because the parser fixes many mistakes silently, a page with a misplaced element still renders, but its DOM may not be what the source suggests.1,12

Two consequences follow. First, a selector such as table > tr matches nothing in an HTML document, because every row ends up inside a row group; write table tr or tbody > tr.20,40 Second, content that is not allowed where it appears is moved. Text or a p placed directly inside a table, between rows, is "foster-parented": the parser takes it out and inserts it before the table. You can see both effects in the playground's "Parser repairs" preset.12

Optional tagsThe standard allows the end tags of tr, td and th, and both tags of tbody, to be left out in the right circumstances, so <table><tr><td>A<td>B</table> is a valid table.39 Valid is not the same as readable: most style guides, and every example in this article, write the end tags out.

3Attributes and concepts

3.1 The table model: slots, cells and groups

To understand spanning and headers you need the model the browser builds. The standard says "a table consists of cells aligned on a two-dimensional grid of slots with coordinates (x, y)", counted from zero at the top left. Each cell covers a rectangle of slots and is anchored at its top-left slot. A row is the set of slots with the same y, a column the set with the same x; a row group is the set of rows from one thead, tbody or tfoot, and a column group the set of columns from one colgroup.2

The "forming a table" algorithm walks the rows in order. For each cell it moves right past any slots already filled by a cell spanning down from an earlier row, then claims a block of slots colspan wide and rowspan tall.2 Two conditions are table model errors: two cells covering the same slot, and a row or column with no cell anchored in it.2 Browsers still render such tables, but the result is unpredictable and a validator will report the error.2,52

The table inspector in section 8 runs a version of this algorithm in your browser and draws the grid for any table you paste in.

3.2 colspan

The colspan attribute on a td or th gives the number of columns the cell spans. Its value "must be a valid non-negative integer greater than zero and less than or equal to 1000"; the default is 1.11 Values above 1000 are clamped to 1000 by browsers.27

The rowspan attribute gives the number of rows a cell spans. 3.4 Table headers: how cells get their headers

Every data cell in a well-formed table has a set of header cells that explain it. In the opening-hours example, "16:00" is explained by "Closes" and "Saturday". The standard's §4.9.12.2 defines the algorithm that computes this set; assistive technology uses the result to announce headers as the user moves from cell to cell.3,4 The algorithm works in two ways:

  1. If the cell has a headers attribute, its header cells are exactly the cells whose ids it lists.3
  2. Otherwise, the browser looks left along the row for row headers and up the column for column headers, then adds any row-group and column-group headers whose group contains the cell.3

When scanning, the algorithm has to know whether each th is a column header or a row header. That is what scope declares. Without it, the browser guesses from context: a th is treated as a column header if there are no data cells in its row, and as a row header if it is not a column header and there are no data cells in its column.3,45 So in a table whose first row is all th and whose first column is all th, the guess is right; in an irregular table it may not be, and an explicit scope removes the doubt.55,56

3.7 Row and column grouping

Groups let a single header apply to a block of rows or columns. A row group is a thead, tbody or tfoot; a column group is a colgroup.2 A th scope="rowgroup" applies to all the remaining cells in its row group, and a th scope="colgroup" to all the remaining cells in its column group.45 The W3C's "irregular headers" pattern uses both, together with col and colgroup spans and the row-group elements, and recommends using thead, tbody and tfoot in such tables.35

4.1 Accessible data tables

Sighted users understand a cell by glancing along its row and up its column. A screen-reader user cannot glance, so the structure has to be in the markup. WCAG SC 1.3.1 Info and Relationships (Level A) requires that structure and relationships conveyed through presentation can be programmatically determined; for tables, that means header cells marked up as headers and associated with their data cells.5 WCAG's sufficient techniques for this are H51 (use table markup for tabular information), H63 (scope), H43 (id and headers) and H39 (caption); its documented failures include F91 (headers not marked up as headers) and F90 (wrong headers/id associations).30,47,55,57–59

4.3 CSS and table semantics

The HTML elements carry the meaning; CSS gives them their default display values (table, table-caption, table-column-group, table-column, table-header-group, table-row-group, table-footer-group, table-row and table-cell).7,46 Two traps follow from that split:

  • Changing display should not change meaning, but has in practice. CSS Display Level 3 states that "the display property has no effect on an element's semantics".64 For years, though, browsers dropped table roles from the accessibility tree when table elements were restyled with display: block, flex or grid, a common trick for small screens. Adrian Roselli's long-running tests record that Chromium, Gecko and WebKit had fixed this by October 2023, but older browsers still in use may not have.65 If you change a table's display, test with a screen reader; ARIA table roles (role="table", "row", "columnheader", "rowheader", "cell") can restore lost semantics, but only add them if you can test the result.9,60,65
  • Using CSS table display on non-table markup does not make a table. A div with display: table-cell looks like a cell but has no table semantics. That is fine for layout, which is exactly why the standard lists the CSS table model as a replacement for layout tables.1,7

A table with many columns does not fit a 320-pixel-wide phone. 4.5 Styling tables

A handful of CSS properties do most of the work:7,70,71

  • border-collapse: collapse makes adjacent cells share a single border; the default, separate, draws each cell's border separately with border-spacing between them.7,70 The standard's suggested default style sheet gives tables border-spacing: 2px and cells padding: 1px.46
  • table-layout: fixed sizes columns from the table's width and the widths of the columns or first-row cells, not from the content of every cell, so a large table can be laid out before all of it has loaded.7,71
  • caption-side puts the caption above or below.32
  • :nth-child(even) on tbody tr gives "zebra" stripes; font-variant-numeric: tabular-nums gives digits equal widths so columns of numbers line up; right-aligning numeric columns helps comparison.51,72
  • visibility: collapse on a row or column hides it and removes its space without recalculating the other columns.7,73

4.6 Tables in the DOM

Tables have their own DOM interface, older than most of the DOM. HTMLTableElement offers caption, tHead, tFoot, the live collections rows and tBodies, and methods such as createCaption(), createTHead(), createTBody(), insertRow() and deleteRow().74 If a table has no rows and no tbody, insertRow() creates a tbody for the new row, mirroring the parser.74 Each cell is an HTMLTableCellElement, with colSpan, rowSpan, headers, scope, abbr and a read-only cellIndex.75 The reflected colSpan is clamped to 1–1000 and rowSpan to 0–65534.11

Building a table with the table APIJavaScript
const table = document.createElement("table");
table.createCaption().textContent = "Scores";
const head = table.createTHead().insertRow();
for (const label of ["Name", "Score"]) {
  const th = document.createElement("th");
  th.scope = "col";
  th.textContent = label;
  head.append(th);
}
const body = table.createTBody();
for (const [name, score] of [["Ada", 92], ["Grace", 88]]) {
  const row = body.insertRow();
  row.insertCell().textContent = name;
  row.insertCell().textContent = score;
}
document.body.append(table);
console.log(table.rows.length); // 3: the head row and two body rows

    Answer

    border, background, width and visibility.7

  8. What should you use instead of the obsolete axis attribute?
    Answer

    The scope attribute on the relevant th.19

  9. What does the CSS selector table > tr match in an HTML (not XHTML) document?
    Answer

    Nothing: the parser always puts rows inside a row group, implying a tbody when needed.40

  10. What is the parser's name for moving misplaced content out of a table to just before it?
    Answer

    Foster parenting.12

  11. Where did HTML 4.01 require tfoot to go?
    Answer

    Before the tbody elements. Current HTML requires it at the end.18,41

  12. What border-spacing does the HTML standard's suggested style sheet give tables?
    Answer

    2px, with 1px of padding in cells.46

  13. Which WCAG technique is "Using caption elements to associate data table captions with data tables"?
    Answer

    H39.30

  14. What implicit ARIA role does a td get inside an element with role="grid"?
    Answer

    gridcell; otherwise it is cell.27

  15. What width does WCAG's Reflow criterion use for vertically scrolling content, and what zoom level does it correspond to?
    Answer

    320 CSS pixels, the width of a 1280-pixel viewport at 400% zoom.66

  16. What happens to a summary attribute on a table today?
    Answer

    It is non-conforming, and WCAG's technique H73 for it is marked obsolete. Use a caption, prose or a figure instead.1,19,62
