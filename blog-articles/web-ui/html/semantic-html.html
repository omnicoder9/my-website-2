Semantic HTML

How HTML says what content is rather than how it looks: the structural elements from header to dialog, how they differ from div and span, heading hierarchy and the document outline, grouping content, and what meaningful markup does for accessibility, search engines and the people who maintain the code. Grounded in the HTML Living Standard, ARIA in HTML, the accessibility API mappings and WCAG.

Updated 14 November 202676 references (Vancouver style)Includes exercises, trivia, a structure inspector and a live playground

The first article in this series covered how an HTML document is built, the second the text inside it, the third the links that join documents together, and the fourth the media embedded in them. This one steps back to the idea that runs through all of them. The HTML standard says that elements, attributes and attribute values "are defined (by this specification) to have certain meanings (semantics)", and that authors must not use them for anything other than their intended purpose.1 Semantic HTML is simply taking that rule seriously: choosing each element for what the content means, and leaving its appearance to CSS.1,2

Section 1 explains what semantics are and who reads them. Section 2 walks through the twelve structural elements in the table below. Section 3 compares semantic elements with div and span and covers headings, grouping, search engines, accessibility and maintainability. Sections 4 to 9 hold a worked refactoring, exercises, trivia questions, a structure inspector, a playground and a quick-reference table.

1Introduction

1.1 Meaning, not appearance

The standard's own example of semantics is that "the ol element represents an ordered list, and the lang attribute represents the language of the content".1 Nothing in that sentence mentions numbers in the margin or a font. The numbers are a default presentation that a style sheet can remove; the fact that the items are in order is part of the content and survives any style sheet, a screen reader, a text-only browser or a search engine's crawler.1,5

The standard is explicit that this is a rule, not a style preference: "Authors must not use elements, attributes, or attribute values for purposes other than their appropriate intended semantic purpose, as doing so prevents software from correctly processing the page."1 Its own first example is a company home page that marks up the name "ACME Corporation" as an h1 and the slogan underneath as an h2. That is non-conforming, because the slogan is a subtitle, not the heading of a subsection; the fix is an hgroup wrapping the h1 and a p.1,6 The payoff is portability. In the standard's words, "Because HTML conveys meaning, rather than presentation, the same page can also be used by a small browser on a mobile phone" without changes, and the same goes for speech browsers and other software that never displays the page at all.1

1.2 Where semantics are defined

The meaning of each element is defined by the HTML Living Standard.9 How that meaning reaches assistive technology is defined by a family of W3C specifications that map HTML onto the accessibility APIs of each operating system, and WCAG sets the requirements a page must meet.3,4,10,11

1.3 Who reads the semantics

A page has more readers than the people looking at it. Browsers use semantics for default styles, reader modes and built-in behaviour such as the toggle on details or the focus trap of a modal dialog.5,16,17 They also build an accessibility tree from the DOM, a parallel structure of roles, names and states that screen readers, voice control and other assistive technology consume.4,18 Search engines parse the same markup to work out what the page is about and which text is its title.19,20 And developers read the source, where <nav> says more than <div class="nav-wrapper-2">.

1.4 A short history

Early HTML mixed meaning and appearance. HTML 3.2 (1997) added presentational elements such as font and center, alongside a div element used mostly for alignment, and pages laid themselves out with tables.21 HTML 4 (published in 1997 and revised as HTML 4.01 in 1999) deprecated much of that in favour of style sheets, added span, and described div and span together as "a generic mechanism for adding structure to documents" that carried no meaning of their own.22 The result, through the 2000s, was the "div soup" familiar from that era: pages built almost entirely from div elements distinguished only by class and id values such as header, nav and footer.

HTML5 gave the most common of those containers names of their own. W3C's guide to what changed lists section, article, main, aside, header, footer, nav and figure (with figcaption) as new elements, and HTML5 became a W3C Recommendation on 28 October 2014.23,24 main was first specified separately, as a 2012–13 extension edited by Steve Faulkner, before being folded into HTML.25 details and summary came through the WHATWG's living standard;16 dialog has been available across browsers since March 2022;26 and search is the newest landmark element, added to ARIA in HTML in March 2023.3,27 Even so, div is still the web's most common element by a wide margin: the 2024 Web Almanac counted it as 28.7% of all elements on mobile pages, more than a and span combined.28

2Structural elements

The elements in this section divide a page into parts that software can recognise. Several of them are landmarks: regions that screen-reader users can list and jump between with a single keystroke, the way sighted users scan a layout.30,31 Figure 3 shows a typical page and the landmark role each element produces.

2.1 header: introductory content

FlowPalpableRole: banner / generic

The header element "represents a group of introductory or navigational aids".32 It usually holds a heading, but it may also hold a logo, a search form, a table of contents or navigation. It may not contain another header or a footer.32 It is not a sectioning element, so it does not start a new section; the heading inside it belongs to the surrounding one.12,32

A page can have many header elements: one for the site and one for each article, for example. Only a header that is not inside article, aside, main, nav or section gets the banner landmark role; the others are exposed as generic.3,4

2.2 nav: navigation

FlowSectioningPalpableRole: navigation

The nav element "represents a section of a page that links to other pages or to parts within the page".33 The standard says it is meant for major navigation blocks; not every group of links needs one. A short list of links in a footer, for instance, is fine without it.33 Every nav has the navigation landmark role, so when a page has more than one, each should get a distinct label with aria-label or aria-labelledby.3,30 The previous article covers menus, breadcrumbs and in-page navigation in detail.

2.3 main: the primary content

FlowPalpableRole: main

The main element represents the dominant contents of the document.34 A document must not have more than one main element without the hidden attribute, so a single-page app may keep several views in the markup as long as only one is shown.34 It must also be a hierarchically correct main: its ancestors may only be html, body, div, form without an accessible name, and autonomous custom elements, so it cannot sit inside an article, aside, header, footer or nav.34

The main landmark is what a "skip to main content" link and a screen reader's "jump to main" command both aim for, which makes it the simplest way to satisfy WCAG's Bypass Blocks criterion.30,35,36 The 2026 WebAIM Million survey found a main landmark on only 46.1% of the top million home pages.37

One main per page; other views hiddenHTML
<body>
  <header>…</header>
  <main id="inbox">…</main>
  <main id="settings" hidden>…</main>
  <footer>…</footer>
</body>

2.4 section: a thematic grouping

FlowSectioningPalpableRole: region (if named) / generic

The section element "represents a generic section of a document or application", which the standard defines as "a thematic grouping of content, typically with a heading".38 Chapters, the tabs of a tabbed panel, and the numbered sections of a thesis are its examples. The standard is emphatic about the limit: "The section element is not a generic container element. When an element is needed only for styling purposes or as a convenience for scripting, authors are encouraged to use the div element instead."38 A rule of thumb from the same passage: a section is appropriate if its contents would be listed explicitly in the document's outline.38

A section becomes a region landmark only if it has an accessible name, usually from aria-labelledby pointing at its heading. Without one it is exposed as generic, the same as a div.3,10 Name only the few sections a user would want to jump to: every named section adds an entry to the landmark list a screen-reader user has to step through.

    <p style="margin:0">Water at 70–80 °C, two minutes.</p>
  </section>
  <section>

2.5 article: independent content

FlowSectioningPalpableRole: article

The article element "represents a complete, or self-contained, composition in a document, page, application, or site and that is, in principle, independently distributable or reusable, e.g. in syndication".39 The test is whether the content would still make sense on its own, in a feed reader or on another site. Blog posts, news stories, forum posts, product cards and user comments all pass; the standard's examples include a forum post, a magazine or newspaper article, a blog entry and a user-submitted comment.39

Articles nest. A comment on a blog post is an article inside the post's article, and the standard says that nested articles represent content related to the outer one.39 Each article should normally have a heading, and an author's contact details belong in an address element inside it.39,40

2.6 aside: related, supplementary content

FlowSectioningPalpableRole: complementary

The aside element "represents a section of a page that consists of content that is tangentially related to the content around the aside element, and which could be considered separate from that content".41 The standard mentions sidebars in printed typography, pull quotes, advertising and groups of nav elements as typical uses. It also notes that an aside should not be used for a mere parenthetical remark that is part of the main flow of the text.41

Its context matters. An aside directly inside body relates to the whole site, such as a list of popular posts; one inside an article relates to that article, such as a glossary box.41 All of them have the complementary role, and a top-level one should be labelled if there is more than one.3,30

2.7 footer: footer information

FlowPalpableRole: contentinfo / generic

The footer element "represents a footer for its nearest ancestor sectioning content element, or for the body element if there is no such ancestor".42 It typically holds who wrote the section, links to related documents, copyright data and the like. Despite the name it does not have to be at the bottom: a "next and previous" bar at the top of an article can be a footer.42 Like header, it may not contain a header or another footer.42

The page-level footer, one not inside article, aside, main, nav or section, is the contentinfo landmark; footers inside those elements are generic.3 Contact details go in an address element, which represents "the contact information for its nearest article or body element ancestor"; it is not for postal addresses in general.40

2.8 figure and figcaption: self-contained content

FlowPalpableRole: figure

The figure element "represents some flow content, optionally with a caption, that is self-contained (like a complete sentence) and is typically referenced as a single unit from the main flow of the document".43 It is not only for images: code listings, diagrams, tables, poems and quotations all qualify. The key property is that the figure could be moved to an appendix or the side of the page without breaking the text that refers to it.43

The figcaption element represents a caption or legend for the rest of the figure's contents, and must be the first or last child of its figure.44 Browsers use it as the figure's accessible name.4 A caption is not a replacement for an image's alt text: the caption says what the figure is about, while alt stands in for the image itself.43,45 Every diagram in this article is a figure with a figcaption.

2.9 details and summary: expandable content

FlowInteractivePalpableRole: group

The details element "represents a disclosure widget from which the user can obtain additional information or controls".16 Its first child, if it is a summary, provides the label that is always visible; the rest is hidden until the user opens it.16,46 The browser provides everything a hand-built disclosure needs: the toggle is focusable, works with the keyboard, shows a disclosure triangle, and exposes its expanded or collapsed state to assistive technology.4,46,47 The open attribute reflects whether it is open, and the element fires a toggle event when that changes.16

Several details elements that share a name attribute form a group in which "at most one of the details elements can be open at once": an exclusive accordion, with no script.16,47 The standard warns against using details for footnotes and against using it as a tab widget.16 The FAQ below is a working example; open one question and the others close.

2.10 dialog: dialogs and modals

FlowSectioning rootRole: dialog

The dialog element "represents a transitory part of an application, in the form of a small window", for example a dialog box, an inspector or a window.17 It can be shown in two ways:

  • show() displays it non-modally: the rest of the page stays usable.17
  • showModal() "displays the dialog element and makes it the top-most modal dialog". The dialog is placed in the top layer, above everything else regardless of z-index; the rest of the document is blocked and becomes inert, so it can be neither clicked nor focused; a ::backdrop pseudo-element covers the page; and the Esc key closes it.17,26,48

A form with method="dialog" inside a dialog closes it on submission and sets the dialog's returnValue to the value of the button that submitted it, so simple confirm dialogs need almost no script.17,26 The ARIA Authoring Practices list what a modal must do, including moving focus into the dialog, keeping it there, and returning it to the control that opened it; showModal() provides the first two automatically and browsers restore focus on close.17,49 Try it:

3Semantic vs. non-semantic elements

3.1 Semantic elements vs. div and span

div: Flow, Palpablespan: Phrasing, PalpableRole: generic

Two elements exist precisely to mean nothing. The standard says "the div element has no special meaning at all. It represents its children."52 MDN describes span the same way, as "a generic inline container for phrasing content, which does not inherently represent anything".53,54 Both map to the ARIA role generic, which assistive technology does not announce.3,10 They are the right choice when you need a hook for CSS or script, such as a grid wrapper or a highlighted word, and no element with a meaning fits.

The standard is just as clear about the order of preference: "Authors are strongly encouraged to view the div element as an element of last resort, for when no other element is suitable." It gives examples: a blog post should be an article, a chapter a section, navigation aids a nav, and a group of form controls a fieldset.52 Using div is not wrong; using it instead of an element that says what the content is loses information that nothing else can restore.1,52

3.2 Document outline and heading hierarchy

The six heading elements, h1 to h6, "represent headings for their sections". The standard explains the numbering plainly: "The h1 element is for a top-level section, h2 for a subsection, h3 for a sub-subsection, and so on."7 Together the headings form the page's outline, the table of contents a reader could build from them.56

The rule for a conforming outline is short. "Each heading following another heading lead in the outline must have a heading level that is less than, equal to, or 1 greater than lead's heading level", and if a document has headings, "at least a single heading within the outline should have a heading level of 1".56 In practice that means you may go down only one level at a time (h2 to h3, never h2 to h4) but may jump back up by any amount.56 The 2026 WebAIM Million found skipped heading levels on 41.8% of the top million home pages and no headings at all on 7.5%.37

Heading levels carry the structure; heading size is CSS. If a design calls for a small h2, style it small rather than choosing h4 for its default look. The reverse also holds: large text that is not a heading should not be marked up as one.1,8 A subtitle or tagline that belongs to a heading goes in a p inside an hgroup, which "represents a heading and related content".6

The outline algorithm that never was

For more than a decade the standard described a different system. Under the old outline algorithm, every sectioning element (article, section, nav, aside) started a new level, so an author could use h1 everywhere and let the nesting decide the levels.24,29 Browsers and screen readers never implemented it: they report the level written in the tag, so a page of nested h1 elements was presented as a flat list of top-level headings. The WHATWG replaced the algorithm with the heading-level rules above in 2022, after a pull request by Steve Faulkner titled "replace current outline algorithm with one based on heading levels".29,56 Advice to "use h1 in every section" dates from that era and should be ignored.

One h1 or several?The standard does not forbid more than one h1, but the heading-level rule means a second h1 starts a new top-level part of the outline.56 Most pages read best with a single h1 naming the page. The WebAIM Million found more than one h1 on 18.1% of home pages.37

3.3 Content grouping

Choosing between article, section, aside, nav and div is the most common semantic decision. The standard has a non-normative subsection, "Article or section?", for exactly this question, and its answer turns on whether the content stands on its own.57 Figure 6 turns the definitions from section 2 into questions.

Two mistakes cover most real-world problems. The first is using section as a styling wrapper, which the standard explicitly discourages.38 The second is wrapping everything in landmarks. A page with a dozen section regions, each labelled, gives a screen-reader user a long landmark list to wade through. The APG's aim is that landmarks identify the main areas of a page, with all perceivable content inside one of them, not that every block becomes a landmark.30 Grouping elements also have finer-grained relatives: p for paragraphs, ul, ol and dl for lists, blockquote for quotations, and hr for "a paragraph-level thematic break", all covered in part 2.14

3.4 Search engine optimisation

Search engines read the markup, not the pixels, so semantics shape what a crawler can understand. Google's SEO Starter Guide advises authors to "break up long content into paragraphs and sections, and provide headings to help users navigate your pages".19 When Google generates the title link shown in its results, the sources it lists include the title element and "heading elements, such as <h1> elements", and it suggests putting the page's main title in the first visible h1.20 And as the previous article showed, Google follows links only when they are a elements with an href, not script-driven div or span elements.58

Two cautions keep this in proportion. Google's documentation describes headings as a way to help users and to make the main title clear, not as a ranking trick, so keyword-stuffed headings or extra h1 elements do not help.19,20 And for richer results such as article dates or breadcrumbs, Google relies on structured data (Schema.org vocabulary in JSON-LD, microdata or RDFa) rather than on HTML element names alone.59,60

3.5 Accessibility benefits

For assistive technology, semantics are not a nice-to-have; they are the interface. WCAG success criterion 1.3.1 Info and Relationships, at level A, requires that "information, structure, and relationships conveyed through presentation can be programmatically determined or are available in text".61 A heading that is only big and bold fails that test; an h2 passes it. The W3C's techniques for 1.3.1 include using h1–h6 to identify headings and using semantic HTML elements or ARIA landmarks to identify regions of a page.62–64

Users rely on this structure heavily. In WebAIM's tenth screen reader user survey (1,539 responses, December 2023 to January 2024), 71.6% of respondents said their first move when looking for information on a long page is to navigate through its headings, and 88.8% found heading levels very or somewhat useful.68 Landmarks are used less as a first step (3.7%), but 31.8% of respondents used them whenever available or often.68

Native first, ARIA second

ARIA can give a div a role, but it cannot give it behaviour. A div role="button" is announced as a button but is still not focusable and does not respond to Enter or Space until the author adds tabindex and key handlers, all of which a button element provides already.3,55 The W3C's notes on using ARIA put this as its "first rule": if you can use a native HTML element or attribute with the semantics and behaviour you require already built in, do that instead of repurposing an element and adding ARIA. (The document is now a discontinued draft, kept for historical purposes, but the advice is restated throughout ARIA in HTML.)3,69 ARIA in HTML also tells authors not to add roles an element already has; <nav role="navigation"> is allowed but "NOT RECOMMENDED".3

Rebuilt with ARIA

A div pretending to be a buttonHTML
<div role="button" tabindex="0" class="btn"
     onclick="save()"
     onkeydown="if (event.key === 'Enter' || event.key === ' ') save()">
  Save
</div>

Three attributes and a key handler to approximate what one element does, and it still does not submit forms or respect disabled.

Native

A buttonHTML
<button type="button" onclick="save()">Save</button>

Focusable, keyboard-operable and announced as "Save, button" with no extra work.4,55

The data point in the other direction is sobering. The 2026 WebAIM Million found that home pages using ARIA averaged 59.1 detected errors, against 42 on pages without it. WebAIM is careful to say that this is a correlation, not proof that ARIA causes errors, since pages that use ARIA tend to be more complex.37 It is still a reminder that ARIA is a repair tool for when no native element fits, not a substitute for one.

3.6 Maintainability

Semantic markup is easier to work on. MDN's summary of the benefits includes that finding blocks of meaningful code is significantly easier than searching through endless div elements, and that the element name itself suggests what kind of content will fill it.2 Some concrete consequences:

  • Self-documenting structure. A closing </article> tells you what it closes; a closing </div> needs a comment.
  • Shorter selectors and fewer classes. CSS can target nav a, article > header or dialog::backdrop without a parallel naming scheme.17,70
  • Free behaviour. details, dialog and button replace hand-written toggles, focus traps and key handlers, which are code someone would otherwise have to test and maintain.16,17,49
  • Testable intent. Testing libraries and validators can query by role (find "the navigation", "the heading level 2 named Prices"), so tests survive changes to class names and layout.4,71
  • Future-proofing. Content marked up by meaning keeps working in contexts that did not exist when it was written, from reader modes to voice assistants, as the standard intends.1

6Trivia questions

  1. What does the standard call the div element?
    Answer

    "An element of last resort, for when no other element is suitable." It has "no special meaning at all".52

  2. What is the most common element on the web?
    Answer

    div. The 2024 Web Almanac found it made up 28.7% of elements on mobile pages, ahead of a (12.6%) and span (11.2%).28

  3. In the standard's own example of misused semantics, which company's slogan is wrongly marked up as an h2?
    Answer

    ACME Corporation, "The leaders in arbitrary fast delivery since 1920". The fix is hgroup.1

  4. How many visible main elements may a document have?
    Answer

    One. Others are allowed only if they have the hidden attribute.34

  5. What landmark role does a section have if it has no accessible name?
    Answer

    None. It is generic, like a div; it becomes a region only when named.3

  6. What percentage of screen reader users first navigate by headings when looking for information on a long page?
    Answer

    71.6%, in WebAIM's Screen Reader User Survey #10 (2024).68

  7. On what share of the top million home pages did WebAIM find skipped heading levels in 2026?
    Answer

    41.8%.37

  8. What did the WHATWG replace the HTML5 "outline algorithm" with?
    Answer

    An outline based on heading levels, via a pull request titled "replace current outline algorithm with one based on heading levels".29

  9. When was HTML5 published as a W3C Recommendation?
    Answer

    28 October 2014.24

  10. Which element was specified separately, as an extension edited by Steve Faulkner, before being merged into HTML?
    Answer

    main. Its extension specification was published as a W3C Working Group Note on 28 May 2013.25

  11. Which two browser releases in March 2022 made dialog available everywhere?
    Answer

    Firefox 98 and Safari 15.4 (which also added ::backdrop).50,51

  12. What attribute turns a set of details elements into an exclusive accordion?
    Answer

    name. Elements that share a name form a group in which at most one can be open.16

  13. What is the newest landmark element in HTML?
    Answer

    search, with the implicit role search. MDN lists it as available across browsers since October 2023.27,74

  14. What does the address element not mean?
    Answer

    Any postal address. It is for the contact information of its nearest article or body ancestor.40

  15. Which is older, div or span?
    Answer

    div. It was already in HTML 3.2 (1997), mainly as a way to align blocks; span arrived with HTML 4, whose 4.01 edition describes the pair as "a generic mechanism for adding structure to documents".21,22

  16. Is <nav role="navigation"> invalid?
    Answer

    No, but ARIA in HTML marks it "NOT RECOMMENDED" because the role is already implied.3

The one-line rule

Choose elements for what the content is; let CSS decide how it looks.1

Headings

One h1 naming the page; no skipped levels on the way down; size with CSS, not with the level.8,56

Native first

button, a href, details and dialog come with behaviour. ARIA adds meaning, not behaviour.3,55,69

Search engines

Clear headings, a visible h1 for the title, crawlable a href links; structured data for rich results.19,20,59
