01Why organize data

A list of raw measurements says little at a glance. Forty commute times written in the order they were collected do not show where most values fall, how spread out they are, or whether a few commuters travel far longer than everyone else. Descriptive statistics answers these questions by organizing observations (sorting, counting, grouping, cross-classifying) and then summarizing them with tables, graphs and a few well-chosen numbers.1,2 Tukey called this stage exploratory data analysis: looking at data to see what it seems to say before formal modelling.3

The methods in this article form a pipeline. Each step trades detail for clarity, and the analyst decides how much detail can be given up without hiding something important.

Before any counting, the data should be in a consistent rectangular layout. Wickham's tidy data principles state that each variable forms a column, each observation forms a row, and each type of observational unit forms a table.4 Every tool shown below (pandas value_counts, crosstab, groupby) assumes this layout. The examples use pandas, a Python library built around the labelled DataFrame structure,5 and NumPy for array computation.6

Running datasets

Three small, reproducible datasets are used throughout. They are illustrative values constructed for teaching, not data from a published study.

02Frequency distributions

Frequency distribution. A description of how often each value, or each range of values, of a variable occurs in a dataset. It may be shown as a table (a frequency table) or a graph (a bar chart for categorical or discrete data, a histogram for continuous data).1

The frequency distribution is the most basic summary of one variable. It answers three questions at once: which values occur (the support), which are most common (the mode and the centre), and how spread out and how symmetric the values are (the shape).1,2

The distinction between nominal and ordinal categories matters for summarization: ordinal categories have a natural order, so cumulative counts and medians make sense, while nominal categories do not.7

Shape vocabulary

Distributions are described as symmetric, right-skewed (a long tail toward large values, common for incomes and waiting times), or left-skewed; and as unimodal, bimodal or multimodal by the number of peaks.1 Tukey's stem-and-leaf display is a quick way to see shape while keeping every original value:3

03Frequency tables

A frequency table lists each distinct value (or category) with its count f. For dataset D1 the variable is discrete with only six values, so each value gets its own row.

s  = pd.Series(kids, name="children")
ft = s.value_counts().sort_index().to_frame("f")
print(ft)
print("n =", ft["f"].sum())

The table is lossless: the original 25 values can be rebuilt from it, only their order is lost. Summary statistics follow directly. The mean is the weighted sum divided by n:

Mean from an ungrouped frequency tablex̄ = Σ fixi / Σ fi = 43 / 25 = 1.72 children

The mode is 2 (the largest frequency), and the median is the 13th ordered value, which also falls in the row x = 2.

Good practice for frequency tables

  • Categories must be mutually exclusive and exhaustive: each observation is counted exactly once, so frequencies sum to n.1
  • Show the total, and report missing values explicitly (pandas: value_counts(dropna=False)) rather than silently dropping them.
  • Order nominal categories by frequency or by a meaningful convention; keep ordinal categories in their natural order.

04Relative and cumulative frequencies

Raw counts depend on sample size, so comparing a sample of 25 with a sample of 2,500 requires proportions. Three derived columns are standard:1,2

Relative, cumulative and cumulative relative frequency rfi = fi / n     Fi = f1 + f2 + … + fi     crfi = Fi / n
ft["rel"]     = ft["f"] / ft["f"].sum()
ft["cum_f"]   = ft["f"].cumsum()
ft["cum_rel"] = ft["rel"].cumsum()
print(ft)

# Shortcut for relative frequencies
s.value_counts(normalize=True).sort_index()

5         1  0.04     25     1.00

Reading the table: 36% of households have exactly two children; 80% have two or fewer; and 1 − 0.80 = 20% have three or more. Relative frequencies always sum to 1 (or 100%), and the last cumulative relative frequency is always 1.

Cumulative frequencies need an order. "Cumulative" means "this value or below", which only makes sense for ordinal or numeric variables. A cumulative column for blood types (O, A, B, AB) would depend on the arbitrary order of the rows and has no interpretation.7

A graph of cumulative relative frequency against the upper boundary of each class is called an ogive. Its value at any point x is the proportion of observations at or below x, which is the empirical cumulative distribution function. Percentiles can be read off it by going across from the vertical axis and down to the horizontal axis (see Figure 2).

05Grouped data

When a variable takes many distinct values, as commute time does, a row per value would produce a table nearly as long as the data. Values are instead grouped into class intervals. Each class is described by its lower and upper limits, its width h, and its midpoint (class mark) m.

c    = pd.Series(commute)
bins = [10, 20, 30, 40, 50, 60]
grp  = pd.cut(c, bins=bins, right=False)       # [10,20), [20,30), ...
gt   = grp.value_counts().sort_index().to_frame("f")
gt["mid"]     = [b + 5 for b in bins[:-1]]
gt["rel"]     = gt["f"] / len(c)
gt["cum_f"]   = gt["f"].cumsum()
gt["cum_rel"] = gt["rel"].cumsum()
print(gt)

Histogram rules

In a histogram the area of each bar represents the share of observations in the class. When all classes have the same width, bar heights can simply be frequencies. When widths differ, heights must be plotted on a density scale (relative frequency divided by class width); otherwise wide classes look misleadingly large.2

Density height for a class of width hiheighti = (fi / n) / hi     so that Σ heighti · hi = 1

Summary statistics from grouped data

Grouping is lossy: we know only how many values fall in each class, not where. The standard working assumption is that values in a class are concentrated at (or spread evenly around) its midpoint. This gives approximate formulas:

Grouped mean and variance x̄ ≈ Σ fimi / n = 1180 / 40 = 29.5     s² ≈ Σ fi(mi − x̄)² / (n − 1) → s ≈ 10.61
Grouped median (linear interpolation inside the median class) Median ≈ L + ((n/2 − F) / f) · h = 20 + ((20 − 7) / 16) · 10 = 28.125

Here L is the lower limit of the class containing the (n/2)th value, F the cumulative frequency before that class, f its frequency and h its width. The interpolation assumes values are spread evenly within the class, which is exactly what the straight segments of the ogive in Figure 2 represent.

The exact statistics from the raw data are mean 29.3, median 27.5 and standard deviation 10.55, so the grouped approximations are close. The error grows with wider classes and with skewed data inside a class.

n  = len(c)
gm = (gt["f"] * gt["mid"]).sum() / n
gs = np.sqrt((gt["f"] * (gt["mid"] - gm)**2).sum() / (n - 1))
print(round(gm, 3), round(gs, 3))             # 29.5 10.61
print(c.mean(), c.median(), round(c.std(), 3))  # 29.3 27.5 10.554

06Data grouping and binning

Binning (also called discretization or bucketing) converts a numeric variable into a categorical one by assigning each value to an interval. It is used for frequency tables and histograms, for reporting (age bands, income brackets), and for smoothing noisy measurements. The main design choices are the number of bins, their edges, and the rule for values that fall exactly on an edge.

How many bins?

Too few bins hide structure; too many produce a ragged histogram dominated by sampling noise. Several published rules give a starting point:

Table 4. Common bin-number and bin-width rules, applied to D2 (n = 40, s = 10.55, IQR = 13.25)
RuleFormulaResult for D2
Sturges (1926)8k = 1 + log2 nk = 6.32 → 7 bins
Scott (1979)9h = 3.49 · s · n−1/3h ≈ 10.8 min
Freedman–Diaconis (1981)10h = 2 · IQR · n−1/3h ≈ 7.7 min
Doane (1976)11Sturges plus a term for sample skewnessmore bins for skewed data

Sturges' rule was derived for roughly normal data and tends to give too few bins for large samples.9 Scott's rule minimizes the asymptotic mean integrated squared error for normal data,9 while the Freedman–Diaconis rule replaces the standard deviation with the interquartile range, which makes it less sensitive to outliers.10 In practice, analysts round the computed width to a "nice" number (here, 10 minutes) so that the class limits are easy to read. NumPy implements these rules directly in np.histogram_bin_edges:6

for rule in ["sturges", "scott", "fd", "doane"]:
    edges = np.histogram_bin_edges(commute, bins=rule)
    print(f"{rule:8s} {len(edges)-1} bins, width {edges[1]-edges[0]:.2f}")

               labels=["under 20", "20-29", "30-44", "45+"])
print(bands.value_counts(sort=False))

Quantile boundaries depend on how sample quantiles are computed, and statistical packages differ. Hyndman and Fan catalogued nine definitions in common use.12 The quartiles quoted in this article (22, 27.5 and 35.25 minutes) use linear interpolation between order statistics, the pandas and NumPy default, which corresponds to their definition 7.

Edge conventions and pitfalls

  • Closed side. Decide whether intervals are [a, b) (left-closed, right=False) or (a, b] (the pandas default). A value of exactly 30 minutes must land in one class only.
  • Coverage. The first edge must be at or below the minimum and the last above the maximum; values outside the edges become missing (NaN) in pd.cut.
  • Information loss. Binning a continuous predictor before modelling discards information and can create artificial thresholds; bin for presentation, and keep the raw values for analysis wherever possible.

07Contingency tables

Contingency table. A table that cross-classifies observations by two or more categorical variables. Each cell holds the count of observations with that combination of categories; the row and column totals (the margins) give the one-way frequency distributions of each variable.7

An r × c table has r rows and c columns. For dataset D3, region (2 levels) by travel mode (3 levels) gives a 2 × 3 table.

Joint, marginal and conditional distributions

Dividing a contingency table by different totals answers different questions:7

  • Joint (divide by the grand total): 30/200 = 15% of all respondents are urban car users.
  • Marginal (row or column totals over n): 100/200 = 50% of respondents use a car.
  • Conditional (divide by a row or column total): among urban respondents, 30/100 = 30% use a car; among car users, 30/100 = 30% are urban.

When one variable is plausibly explanatory (region) and the other a response (mode), compare the conditional distributions of the response within each level of the explanatory variable. Here 70% of suburban respondents drive, compared with 30% of urban respondents.

Expected counts and independence

If the two variables were independent, the expected count in cell (i, j) would be the product of its row and column totals divided by the grand total. Pearson's chi-square statistic measures how far the observed counts are from these expected counts:13,7

Expected count and Pearson chi-square, df = (r − 1)(c − 1) Eij = (rowi total × columnj total) / n     X² = Σ (Oij − Eij)² / Eij

For Table 6 every row total is 100, so the expected counts are 50, 32.5 and 17.5 in each row. Then X² = 32.04 on 2 degrees of freedom, far beyond the 5% critical value of 5.99, so the data are strongly inconsistent with independence. Cramér's V rescales X² to lie between 0 and 1 so that association strength can be compared across tables of different size:14,7

Cramér's VV = √( X² / (n · (min(r, c) − 1)) ) = √(32.04 / (200 · 1)) = 0.40

The chi-square approximation is unreliable when expected counts are small. Cochran's widely cited guideline is that no expected count should be below 1 and no more than 20% of expected counts should be below 5; otherwise categories should be combined or an exact test used.15,7

08Cross-tabulation

Cross-tabulation is the operation of building a contingency table from record-level data. In pandas, pd.crosstab counts combinations; its normalize argument returns joint, row or column proportions, and margins=True adds totals.5

ct = pd.crosstab(survey["region"], survey["mode"], margins=True, margins_name="Total")
print(ct)

# Row percentages: distribution of mode within each region
print(pd.crosstab(survey["region"], survey["mode"], normalize="index").round(3))

# Column percentages: distribution of region within each mode
print(pd.crosstab(survey["region"], survey["mode"], normalize="columns").round(3))

# Expected counts, chi-square and Cramer's V with NumPy only
obs = pd.crosstab(survey["region"], survey["mode"]).to_numpy()
exp = obs.sum(axis=1, keepdims=True) * obs.sum(axis=0, keepdims=True) / obs.sum()
chi2 = ((obs - exp)**2 / exp).sum()
v    = np.sqrt(chi2 / (obs.sum() * (min(obs.shape) - 1)))
print(round(chi2, 2), round(v, 3))   # 32.04 0.4

Three-way tables and Simpson's paradox

Cross-tabulating by a third variable (a layer or stratum) can reverse an association seen in the collapsed two-way table. This reversal is known as Simpson's paradox.16 The best-known case is graduate admissions at the University of California, Berkeley, in fall 1973: across the whole graduate division, 44% of 8,442 male applicants and 35% of 4,321 female applicants were admitted, yet when Bickel and colleagues examined individual departments they found little evidence of bias against women. Women had applied disproportionately to departments with low admission rates.17

# Three-way cross-tab: rows = department, columns = (sex, outcome)
pd.crosstab(df["dept"], [df["sex"], df["admitted"]], margins=True)

# Admission rate per sex within each department
df.groupby(["dept", "sex"])["admitted"].mean().unstack()
Lesson. Aggregating over a variable that is related to both the grouping variable and the outcome can produce a misleading summary. Always ask which variables were summed over, and check the stratified tables. Exercise 8 works through a numerical example.

09Data aggregation

Aggregation collapses many records into one summary record per group, using functions such as count, sum, mean, median, minimum and maximum. Wickham described the general pattern as split-apply-combine: split the data into groups, apply a function to each group independently, and combine the results into a new table.18 The same idea underlies SQL's GROUP BY, and Gray and colleagues showed that group-by, cross-tabulation and subtotals are all special cases of a single CUBE operator.19

sales = pd.DataFrame({
    "region":  ["North","North","North","South","South","South","North","South","East","East"],
    "month":   ["Jan","Jan","Feb","Jan","Feb","Feb","Feb","Jan","Jan","Feb"],
    "product": ["A","B","A","A","B","A","B","B","A","A"],
    "units":   [120, 80, 135, 90, 60, 110, 95, 70, 50, 65],
    "price":   [2.5, 4.0, 2.5, 2.5, 4.0, 2.5, 4.0, 4.0, 2.5, 2.5],
})
sales["revenue"] = sales["units"] * sales["price"]

# Named aggregation: several summaries per group in one call
by_region = sales.groupby("region").agg(
    orders=("units", "size"),
    units=("units", "sum"),
    revenue=("revenue", "sum"),
    mean_units=("units", "mean"),
)
print(by_region)

# Two grouping keys reshaped into a cross-tab of sums, with subtotals
print(sales.pivot_table(index="region", columns="month", values="revenue",
                        aggfunc="sum", margins=True, margins_name="Total"))

Aggregate, transform or filter

pandas distinguishes three group operations:20

  • Aggregation returns one row per group (.agg, .sum, .mean).
  • Transformation returns a result the same length as the input, aligned to the original rows. For example, sales.groupby("region")["revenue"].transform("sum") attaches each region's total to every record, which makes "share of region revenue" a one-line calculation.
  • Filtration keeps or drops whole groups based on a group-level condition, for example .filter(lambda g: len(g) >= 3).

Choosing the right aggregate

  • Additive measures (units, revenue, counts) can be summed across groups and re-aggregated.
  • Ratios and averages cannot. The average price per unit sold in North is total revenue over total units, 1337.5 / 430 = 3.11, not the unweighted mean of the four row prices (3.25). Aggregate the numerator and denominator separately, then divide.
  • Medians and percentiles of groups cannot be combined into an overall median; recompute from the records.
  • Granularity. State the unit of the aggregated table (one row per region per month) and keep the record-level data so that other cuts remain possible.

Long and wide layouts

An aggregated table often needs reshaping. The long layout has one row per combination of keys and suits further grouping and plotting; the wide layout spreads one key across columns and suits reading. Tidy-data principles favour long data for analysis.4

long = sales.groupby(["region", "month"], as_index=False)["revenue"].sum()
wide = long.pivot(index="region", columns="month", values="revenue")
back = wide.reset_index().melt(id_vars="region", value_name="revenue")  # wide to long again

10Data transformations

A transformation replaces each value x with g(x) for some function g. Transformations are used to reduce skewness, to stabilize variance across groups, to make relationships closer to linear, and to put variables on comparable scales.21,22 It helps to separate two families:

  • Linear (affine) transformations g(x) = a + bx: unit changes (minutes to hours), centring, standardization. They change the location and scale of the distribution but never its shape.
  • Non-linear transformations (log, square root, reciprocal, power): they change the shape of the distribution, compressing some regions and stretching others.

The ladder of powers

For positive, right-skewed data, moving "down" Tukey's ladder of powers (from x, to √x, to log x, to −1/x) pulls in the long right tail progressively harder.3 Common choices:

Example: log-transforming a skewed variable

Fourteen annual household incomes (in thousands): 21, 24, 28, 30, 33, 35, 39, 44, 52, 61, 75, 98, 140, 260. The mean (67.1) is pulled far above the median (41.5) by the two largest values, and the moment skewness is 2.13. On the log scale skewness falls to 0.91. The back-transformed mean of the logs is the geometric mean, 50.6, which sits much closer to the centre of the bulk of the data.

inc = pd.Series([21,24,28,30,33,35,39,44,52,61,75,98,140,260], dtype=float)

def skewness(x):
    x = np.asarray(x, float); d = x - x.mean()
    return (d**3).mean() / (d**2).mean()**1.5

print(round(skewness(inc), 2), round(skewness(np.log(inc)), 2), round(skewness(np.sqrt(inc)), 2))
# 2.13 0.91 1.54
print(round(np.exp(np.log(inc).mean()), 1))   # geometric mean 50.6

Box and Cox proposed choosing λ by maximum likelihood, so that the transformed data are as close as possible to normal with constant variance.22 Scikit-learn's PowerTransformer implements both the Box–Cox and Yeo–Johnson families.24

Interpreting transformed results. Summaries computed on a transformed scale must be interpreted on that scale. The back-transformed mean of log data is the geometric mean, not the arithmetic mean. A difference of 0.1 in natural logs corresponds to a ratio of e0.1 ≈ 1.105, about a 10.5% difference.

11Standardization and normalization

Variables measured in different units, or with very different spreads, cannot be compared or combined directly. Rescaling puts them on a common footing. Terminology varies between fields; in this article standardization means z-scores and normalization means rescaling to a fixed range, which matches scikit-learn's usage.24

Practical points

  • Population or sample SD. pandas' std() divides by n − 1; NumPy's np.std and scikit-learn's StandardScaler divide by n. The z-scores differ by a factor of √(n/(n − 1)), so state which one is used.
  • Fit on training data only. In predictive modelling, compute means, SDs, minima and maxima on the training set and apply the same constants to new data; computing them on all data leaks information from the test set.24
  • Shape is unchanged. A z-score transformation does not make data normal. A z-score of 2 corresponds to the 97.7th percentile only if the data are normally distributed.
  • Comparing across distributions. z-scores answer "how unusual is this value within its own group?", which is how a score of 85 on one test can be compared with 80 on another (Exercise 6).

E2Statistics from a grouped table

Fifty delivery distances (km) are grouped as: [0,10): 5, [10,20): 12, [20,30): 18, [30,40): 10, [40,50): 5. Estimate (a) the mean, (b) the median, (c) the percentage of deliveries under 30 km.

Show solution

(a) Midpoints 5, 15, 25, 35, 45. Σfm = 25 + 180 + 450 + 350 + 225 = 1230, so x̄ ≈ 1230 / 50 = 24.6 km.

(b) n/2 = 25. Cumulative frequencies are 5, 17, 35, …, so the median class is [20,30) with F = 17, f = 18. Median ≈ 20 + (25 − 17)/18 × 10 = 24.44 km.

(c) Cumulative frequency at 30 is 35, and 35/50 = 70%.

A sample has n = 200 and interquartile range 16. Find the number of bins suggested by Sturges' rule and the bin width suggested by the Freedman–Diaconis rule.

E4A 2 × 2 contingency table

In a trial, 100 patients received a drug (60 improved, 40 did not) and 100 received a placebo (45 improved, 55 did not). (a) Give the row percentages. (b) Compute the expected counts under independence. (c) Compute Pearson's X² (without continuity correction) and Cramér's V.

Show solution

(a) Improved: 60% with the drug, 45% with placebo.

(b) Column totals are 105 improved and 95 not. Expected: 100 × 105 / 200 = 52.5 improved and 47.5 not, in each row.

(c) Each |O − E| = 7.5, so X² = 7.5² × (2/52.5 + 2/47.5) = 4.51 on 1 df (above the 5% critical value 3.84). V = √(4.51 / 200) = 0.15, a weak association.

E5Aggregating ratios correctly

Using the sales table from section 9, compute the average price per unit sold in each region. Why is sales.groupby("region")["price"].mean() the wrong answer?

Show solution 
agg = sales.groupby("region")[["revenue", "units"]].sum()
agg["avg_price"] = agg["revenue"] / agg["units"]

East 287.5 / 115 = 2.50; North 1337.5 / 430 = 3.11; South 1020 / 330 = 3.09.

The mean of the price column gives each order equal weight regardless of its size (North: (2.5 + 4 + 2.5 + 4)/4 = 3.25). The price per unit sold must weight each price by the units sold, which is what dividing the summed revenue by the summed units does.

E6Comparing scores with z-scores

Ana scored 85 on a test with mean 70 and SD 10. Ben scored 80 on a different test with mean 65 and SD 6. Who did relatively better? Then min–max normalize the values 3, 7, 10, 15.

Show solution

Ana: z = (85 − 70)/10 = 1.5. Ben: z = (80 − 65)/6 = 2.5. Ben is further above his group's mean in SD units, so he did relatively better.

Min–max with min 3, range 12: 0, 4/12 = 0.333, 7/12 = 0.583, 1.

E7Log transformation and the geometric mean

Bacterial counts on three plates are 10, 100 and 1000. Find the arithmetic mean, the mean of the base-10 logs, and the geometric mean. Which summary better describes a "typical" plate?

Show solution

Arithmetic mean = 1110 / 3 = 370. log10 values are 1, 2, 3, with mean 2. Geometric mean = 102 = 100.

The counts grow by multiplication, so the geometric mean (100, the middle plate) is the better typical value; the arithmetic mean is dominated by the largest plate.

E8Simpson's paradox

A university has two departments. Department X admitted 80 of 100 male and 18 of 20 female applicants. Department Y admitted 4 of 20 male and 30 of 100 female applicants. Compute admission rates by sex within each department and overall. Explain the result.

Show solution
MenWomen
Dept X80/100 = 80%18/20 = 90%
Dept Y4/20 = 20%30/100 = 30%
Overall84/120 = 70%48/120 = 40%

Women have the higher rate in both departments but a much lower rate overall. Most women applied to department Y, which admits few applicants; most men applied to X, which admits most. Department is related to both sex and admission, so collapsing over it reverses the association. This is the same structure Bickel and colleagues found at Berkeley.17

E9Putting it together in pandas

Write a function freq_table(series, bins=None) that returns a DataFrame with columns f, rel, cum_f and cum_rel, binning numeric data when bins is given. Test it on kids and on commute with 10-minute bins.

Show solution 
def freq_table(series, bins=None, right=False):
    s = pd.Series(series)
    if bins is not None:
        s = pd.cut(s, bins=bins, right=right)
    t = s.value_counts(sort=False).sort_index().to_frame("f")
    t["rel"] = t["f"] / t["f"].sum()
    t["cum_f"] = t["f"].cumsum()
    t["cum_rel"] = t["rel"].cumsum()
    return t

print(freq_table(kids))
print(freq_table(commute, bins=range(10, 70, 10)))

The outputs reproduce Tables 2 and 3. For nominal data, drop the two cumulative columns.
