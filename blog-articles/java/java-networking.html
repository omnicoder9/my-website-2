1. Networking as a layered state machine

A network program coordinates addressing, transport state, application framing, concurrency, timeouts, resource ownership, protocol semantics, and peer trust. A successful socket connection proves only that bytes can flow to an endpoint—not that the endpoint is authorized, the protocol is correctly framed, or the operation is safe to retry.

Name and address

Hostname resolution produces one or more IPv4/IPv6 addresses; a socket endpoint combines an address and port.

Transport

TCP supplies a reliable ordered byte stream; UDP supplies independent datagrams with minimal transport semantics.

Application protocol

Defines message boundaries, encoding, request/response rules, errors, flow control, and compatibility.

Security and operations

TLS identity, authentication, authorization, deadlines, limits, backpressure, telemetry, and recovery.

Java SE divides the core networking API between low-level addressing and socket abstractions in java.net, channel-based I/O in java.nio.channels, high-level HTTP and WebSocket clients in java.net.http, and TLS/DTLS facilities in javax.net.ssl.[1][2]

Design the wire protocol before writing loops. Specify maximum sizes, byte order, encoding, message boundaries, timeouts, authentication, version negotiation, and failure behavior. “Read until the stream pauses” is not framing.

Modern TCP is specified by RFC 9293 and presents a connection-oriented reliable byte-stream service; it does not preserve application write boundaries.[11] UDP is defined by RFC 768 as a minimal datagram service over IP; it does not add delivery, ordering, duplicate suppression, congestion control, or session establishment.[12]

HTTP is a stateless application-level request/response protocol whose semantics are shared across protocol versions. Java's standard client supports HTTP/1.1 and HTTP/2; it does not expose HTTP/3 in Java 25.[27][21]

3. IP addresses, socket addresses, and DNS

InetAddress represents an IP address and has IPv4 and IPv6 subclasses. InetSocketAddress combines an IP address or hostname with a port and can remain unresolved for uses such as proxy routing.[3][4]

Resolve all addresses

InetAddress[] addresses =
    InetAddress.getAllByName(
        "api.example.com");

for (InetAddress address : addresses) {
    System.out.printf(
        "%s family=%s loopback=%s linkLocal=%s%n",
        address.getHostAddress(),
        address instanceof Inet6Address
            ? "IPv6"
            : "IPv4",
        address.isLoopbackAddress(),
        address.isLinkLocalAddress());
}

Unresolved endpoint

InetSocketAddress proxyTarget =
    InetSocketAddress.createUnresolved(
        "api.example.com",
        443);

assert proxyTarget.isUnresolved();

Do not assume one hostname equals one address

  • DNS can return several addresses and answers can change during the process lifetime.
  • IPv6 addresses can require a scope/interface identifier, especially for link-local addresses.
  • Reverse lookup is not an authentication mechanism.
  • Use the original DNS name for TLS endpoint identification; an IP connection alone does not establish service identity.

Java 18 introduced an Internet-address resolution service-provider interface, allowing alternative resolvers while retaining InetAddress as the application abstraction.[44] Happy Eyeballs Version 2 defines a general strategy for reducing connection delay when IPv6 and IPv4 paths differ in availability or performance.[53]

4. Network interfaces

NetworkInterface represents a physical or virtual network interface and exposes names, indexes, addresses, hardware address, MTU, multicast support, and status. Interface configuration can change while the JVM is running; returned objects may reflect a snapshot.[5]

NetworkInterface.networkInterfaces()
    .forEach(network -> {
        try {
            System.out.printf(
                "%s display=%s up=%s loopback=%s mtu=%d%n",
                network.getName(),
                network.getDisplayName(),
                network.isUp(),
                network.isLoopback(),
                network.getMTU());

            network.inetAddresses()
                .forEach(address ->
                    System.out.println(
                        "  "
                            + address.getHostAddress()));
        } catch (SocketException failure) {
            throw new UncheckedIOException(
                new IOException(failure));
        }
    });

Binding choices

  • Binding to the wildcard address accepts traffic on eligible local interfaces.
  • Binding to loopback restricts access to the local host.
  • Binding to one interface/address can prevent unintended exposure but must account for failover and address changes.
  • Containers and orchestrators may present virtual interfaces and translated addresses that differ from externally visible endpoints.

6. TCP semantics

TCP TCP creates a full-duplex, reliable, in-order byte stream between endpoints. It detects loss, retransmits, orders bytes, performs flow control, and participates in congestion control. Applications still need message framing, deadlines, overload policy, and handling for connection failure and uncertain peer processing.[11]

What TCP guarantees

  • Bytes delivered to the receiving application are in order and without duplication.
  • A connection has independent input and output directions.
  • EOF indicates an orderly shutdown of the peer's output direction.

What TCP does not guarantee

  • One write() equals one read().
  • A write reaching the local kernel means the remote application processed it.
  • A connection remains alive without application activity or failure detection.
  • Message boundaries, content encoding, authentication, or confidentiality.
  • Immediate detection of a silently failed peer or network partition.
Never retry a non-idempotent operation merely because the TCP connection failed. The server may have processed the request before the response was lost. Use operation IDs, status lookup, deduplication, or transactional messaging.

7. A bounded TCP client

public final class FramedTcpClient
        implements AutoCloseable {

    private static final int MAX_MESSAGE_BYTES =
        1 * 1024 * 1024;

    private final Socket socket;
    private final DataInputStream input;
    private final DataOutputStream output;

    public FramedTcpClient(
            InetSocketAddress remote,
            Duration connectTimeout,
            Duration readTimeout)
            throws IOException {

        socket = new Socket();

        boolean initialized = false;

        try {
            socket.connect(
                remote,
                Math.toIntExact(
                    connectTimeout.toMillis()));

            socket.setSoTimeout(
                Math.toIntExact(
                    readTimeout.toMillis()));

            socket.setTcpNoDelay(true);

            input =
                new DataInputStream(
                    new BufferedInputStream(
                        socket.getInputStream()));

            output =
                new DataOutputStream(
                    new BufferedOutputStream(
                        socket.getOutputStream()));

            initialized = true;
        } finally {
            if (!initialized) {
                socket.close();
            }
        }
    }

    public synchronized void send(
            byte[] message)
            throws IOException {

        if (message.length
                > MAX_MESSAGE_BYTES) {
            throw new ProtocolException(
                "Message too large");
        }

        output.writeInt(
            message.length);

        output.write(
            message);

        output.flush();
    }

    public synchronized byte[] receive()
            throws IOException {

        int length =
            input.readInt();

        if (length < 0
                || length
                    > MAX_MESSAGE_BYTES) {
            throw new ProtocolException(
                "Invalid frame length: "
                    + length);
        }

        return input.readNBytes(length);
    }

    @Override
    public void close()
            throws IOException {
        socket.close();
    }
}

Validate complete reads

byte[] payload =
    input.readNBytes(length);

if (payload.length != length) {
    throw new EOFException(
        "Peer closed during frame: expected "
            + length
            + ", received "

}

Socket.connect(endpoint, timeout) controls connection establishment, while setSoTimeout limits blocking reads. The socket supports standard options including buffers, keepalive, reuse address, linger, and TCP_NODELAY.[6]

8. TCP server with virtual threads

public final class FramedTcpServer
        implements AutoCloseable {

    private final ServerSocket listener;
    private final ExecutorService connections;
    private final AtomicBoolean running =
        new AtomicBoolean(true);

    public FramedTcpServer(
            InetSocketAddress bindAddress,
            int backlog)
            throws IOException {

        listener = new ServerSocket();
        listener.setReuseAddress(true);
        listener.bind(
            bindAddress,
            backlog);

        connections =
            Executors
                .newVirtualThreadPerTaskExecutor();
    }

    public void serve()
            throws IOException {

        while (running.get()) {
            try {
                Socket socket =
                    listener.accept();

                connections.submit(
                    () ->
                        handle(socket));
            } catch (SocketException closed) {
                if (running.get()) {
                    throw closed;
                }
            }
        }
    }

    private void handle(
            Socket socket) {

        try (socket;
             DataInputStream input =
                 new DataInputStream(
                     new BufferedInputStream(
                         socket.getInputStream()));
             DataOutputStream output =
                 new DataOutputStream(
                     new BufferedOutputStream(
                         socket.getOutputStream()))) {

            socket.setSoTimeout(30_000);

            for (;;) {
                int length;

                try {
                    length = input.readInt();
                } catch (EOFException end) {
                    return;
                }

                if (length < 0
                        || length > 1_048_576) {
                    throw new ProtocolException(
                        "Invalid frame length");
                }

                byte[] request =
                    input.readNBytes(length);

                if (request.length != length) {
                    throw new EOFException(
                        "Truncated frame");
                }

                byte[] response =
                    application.process(
                        request);

                output.writeInt(
                    response.length);

                output.write(
                    response);

                output.flush();
            }
        } catch (IOException failure) {
            connectionFailures.record(
                failure);
        }
    }

    @Override
    public void close()
            throws IOException {

        running.set(false);
        listener.close();
        connections.close();
    }
}

ServerSocket.accept() blocks until a connection arrives. When blocking socket operations run in a virtual thread, interruption closes the socket and wakes the operation. Virtual threads improve concurrency for waiting tasks; they do not increase CPU capacity or remove the need to bound accepted connections, request size, database sessions, and downstream work.[7][20]

Admission control

A virtual-thread-per-connection design still needs a semaphore, rate limiter, queue limit, or downstream concurrency control. Otherwise a peer can create more active work, memory, and backend pressure than the service can sustain.

static FrameHeader readHeader(
        DataInput input)
        throws IOException {

    short magic =
        input.readShort();

    if (magic != (short) 0x4A4E) {
        throw new ProtocolException(
            "Invalid magic");
    }

    byte version =
        input.readByte();

    byte type =
        input.readByte();

    int requestId =
        input.readInt();

    int payloadLength =
        input.readInt();

    if (version != 1
            || payloadLength < 0
            || payloadLength > MAX_PAYLOAD) {
        throw new ProtocolException(
            "Unsupported frame");
    }

    return new FrameHeader(
        magic,
        version,
        type,
        requestId,
        payloadLength);
}

Framing rules

  • Specify network byte order and character encoding.
  • Validate length before allocation.
  • Cap nested structures, strings, collections, and decompressed size.
  • Include a protocol version and stable message type.
  • Define unknown-field and unknown-message behavior.
  • Never deserialize untrusted Java native serialization as a network protocol.

10. Connect, read, write, idle, and operation deadlines

A robust client distinguishes several clocks. One timeout cannot represent the entire operation.

Instant deadline =
    clock.instant()
        .plusSeconds(5);

Duration remaining(
        Instant deadline,
        Clock clock) {

    Duration value =
        Duration.between(
            clock.instant(),
            deadline);

    if (value.isNegative()
            || value.isZero()) {
        throw new OperationTimedOut();
    }

    return value;
}

Socket read timeout is inactivity, not total response time

SO_TIMEOUT applies to blocking reads and can expire after a period without data. A peer that sends bytes slowly can keep a request alive indefinitely unless the application also enforces an absolute deadline and throughput/size limits.[6]

Writing with classic sockets

Classic Socket exposes no direct write-timeout setter. Bound writes through an overall deadline, non-blocking channels/selectors, asynchronous channels, or an architecture that closes the socket when the operation expires.

11. EOF, half-close, and connection shutdown

TCP is full duplex. One endpoint can finish sending while continuing to receive. Java exposes this with shutdownOutput() and shutdownInput(); closing the socket closes both directions.[6]

Request followed by EOF

try (Socket socket = new Socket()) {
    socket.connect(
        remote,
        2_000);

    socket.getOutputStream()
        .write(requestBytes);

    socket.shutdownOutput();

    byte[] response =
        socket.getInputStream()
            .readAllBytes();
}

EOF behavior

  • InputStream.read() returning -1 means the peer ended its output direction.
  • EOF in the middle of a fixed or length-prefixed message is a protocol failure.
  • A successful local close does not prove the peer processed all preceding bytes.
  • Abrupt reset and orderly FIN communicate different transport conditions but can still leave application outcome uncertain.

13. UDP semantics

UDP UDP preserves datagram boundaries. A send operation creates one datagram and a receive operation returns at most one datagram. Delivery, order, duplicate suppression, path-MTU handling, retries, and congestion behavior are application concerns.[12]

Datagram properties

  • A datagram can be lost, duplicated, reordered, or delayed.
  • A receive buffer smaller than the datagram truncates it; the remainder is discarded.
  • IP fragmentation increases loss sensitivity and can be blocked by middleboxes.
  • A “connected” UDP socket records a default peer and filters incoming datagrams; it does not perform a TCP-like handshake.
  • ICMP errors can be delayed, absent, or surfaced as PortUnreachableException only in some connected-socket cases.

DatagramSocket represents an endpoint for sending and receiving datagram packets, while DatagramPacket carries one payload plus source or destination address information.[8][9]

Client

public static byte[] request(
        InetSocketAddress server,

        int maximumResponseBytes,
        Duration timeout)
        throws IOException {

    try (DatagramSocket socket =

            new byte[maximumResponseBytes];

        DatagramPacket response =
            new DatagramPacket(

                buffer.length);

        socket.receive(response);

            response.getData(),
            response.getLength());
    }

Server

public void serve(
        InetSocketAddress bindAddress)
        throws IOException {

    try (DatagramSocket socket =
            new DatagramSocket(null)) {

        socket.setReuseAddress(true);
        socket.bind(bindAddress);

        byte[] buffer =
            new byte[1_200];

        while (!Thread.currentThread()
                .isInterrupted()) {

            DatagramPacket request =
                new DatagramPacket(
                    buffer,
                    buffer.length);

            socket.receive(request);

            byte[] response =
                application.process(
                    request.getData(),
                    request.getOffset(),
                    request.getLength());

            if (response.length > 1_200) {
                continue;
            }

            DatagramPacket reply =
                new DatagramPacket(
                    response,
                    response.length,
                    request.getSocketAddress());

            socket.send(reply);
        }
    }
}

Amplification control

Before the sender is authenticated or has proved address reachability, keep responses no larger than requests, use unpredictable challenges/cookies, and rate-limit by source/network. Source IP addresses can be spoofed in many UDP environments.

15. Designing reliability above UDP

A reliable UDP-based protocol must define mechanisms normally supplied by TCP or QUIC:

  • Connection or association identifiers.
  • Packet and message sequence numbers.
  • Acknowledgments and retransmission timers.
  • Duplicate detection and replay window.
  • Fragmentation/reassembly with strict memory and time limits.
  • Congestion control and pacing.
  • Path MTU and migration behavior.
  • Authentication before state allocation or amplification.

Minimal request envelope

record UdpRequest(
    byte version,
    long requestId,
    int attempt,
    Instant expiresAt,
    byte[] payload,
    byte[] authenticationTag) {
}

Do not implement a bespoke reliable transport simply to avoid TCP head-of-line behavior. Use a mature standardized protocol and implementation when reliability, congestion control, encryption, and migration are required.

16. UDP multicast

MulticastSocket and DatagramChannel can join IP multicast groups on a selected network interface. Multicast delivery is best effort and constrained by network routing, switch configuration, TTL/hop limits, and host membership.[2][17]

InetAddress group =
    InetAddress.getByName(
        "239.255.10.20");

NetworkInterface network =
    NetworkInterface.getByName(
        "eth0");

try (MulticastSocket socket =
        new MulticastSocket(5000)) {

    socket.joinGroup(
        new InetSocketAddress(
            group,
            5000),
        network);

    try {
        byte[] buffer =
            new byte[1_024];

        DatagramPacket packet =
            new DatagramPacket(
                buffer,
                buffer.length);

        socket.receive(packet);
    } finally {
        socket.leaveGroup(
            new InetSocketAddress(
                group,
                5000),
            network);
    }
}

Multicast safety

  • Authenticate application messages; group membership is not sender identity.
  • Bound message size and processing rate.
  • Choose administratively scoped groups and hop limits.
  • Expect duplicate, reordered, and missing datagrams.
  • Test on the actual network; loopback behavior is not representative.

17. NIO channels and buffers

java.nio.channels provides blocking and non-blocking channels, scatter/gather operations, selectors, asynchronous channels, and network-channel socket options. A ByteBuffer explicitly tracks position, limit, capacity, and byte order.[13]

Blocking SocketChannel

try (SocketChannel channel =
        SocketChannel.open()) {

    channel.configureBlocking(true);

    channel.setOption(
        StandardSocketOptions.TCP_NODELAY,
        true);

    channel.connect(
        new InetSocketAddress(
            "example.com",
            9000));

    ByteBuffer request =
        StandardCharsets.UTF_8
            .encode("hello");

    while (request.hasRemaining()) {
        channel.write(request);
    }

    ByteBuffer response =
        ByteBuffer.allocate(4_096);

    int count =
        channel.read(response);

    if (count == -1) {
        throw new EOFException();
    }

    response.flip();

    String text =
        StandardCharsets.UTF_8
            .decode(response)
            .toString();
}

Partial operations are normal

  • A channel write may consume only part of a buffer.
  • A read may return zero in non-blocking mode.
  • A read may contain a partial frame, several frames, or the end of one and start of another.
  • flip() switches a buffer from writing into it to reading from it; compact() preserves unread bytes and makes room for more input.

SocketChannel implements scattering and gathering channels, allowing several buffers to participate in one read or write operation. It can operate in blocking or non-blocking mode and register with a selector.[14]

18. A selector-based framed server

A selector multiplexes registered non-blocking channels and reports readiness for accept, connect, read, and write operations. Readiness is a hint, not a guarantee that a subsequent operation will transfer data without blocking.[15][16]

final class ConnectionState {
    static final int MAX_PAYLOAD =
        1_048_576;

    final ByteBuffer inbound =
        ByteBuffer.allocate(
            MAX_PAYLOAD + Integer.BYTES);

    final Deque<ByteBuffer> outbound =
        new ArrayDeque<>();

    int expectedPayload = -1;
}
public void runSelectorServer(
        InetSocketAddress address)
        throws IOException {

    try (Selector selector =
            Selector.open();
         ServerSocketChannel listener =
            ServerSocketChannel.open()) {

        listener.configureBlocking(false);
        listener.bind(address);
        listener.register(
            selector,
            SelectionKey.OP_ACCEPT);

        while (!Thread.currentThread()
                .isInterrupted()) {

            selector.select();

            Iterator<SelectionKey> keys =
                selector.selectedKeys()
                    .iterator();

            while (keys.hasNext()) {
                SelectionKey key =
                    keys.next();

                keys.remove();

                try {
                    if (!key.isValid()) {
                        continue;
                    }

                    if (key.isAcceptable()) {
                        accept(
                            selector,
                            (ServerSocketChannel)
                                key.channel());
                    }

                    if (key.isReadable()) {
                        read(key);
                    }

                    if (key.isWritable()) {
                        write(key);
                    }
                } catch (IOException
                         | RuntimeException failure) {

                    closeKey(key);
                }
            }
        }
    }
}

private void accept(
        Selector selector,
        ServerSocketChannel listener)
        throws IOException {

    for (SocketChannel channel;
            (channel = listener.accept())
                != null;) {

        channel.configureBlocking(false);

        channel.setOption(
            StandardSocketOptions.TCP_NODELAY,
            true);

        channel.register(
            selector,
            SelectionKey.OP_READ,
            new ConnectionState());
    }
}
private void read(
        SelectionKey key)
        throws IOException {

    SocketChannel channel =
        (SocketChannel) key.channel();

    ConnectionState state =
        (ConnectionState)
            key.attachment();

    int count =
        channel.read(
            state.inbound);

    if (count == -1) {
        closeKey(key);
        return;
    }

    if (count == 0) {
        return;
    }

    state.inbound.flip();

    while (true) {
        if (state.expectedPayload == -1) {
            if (state.inbound.remaining()
                    < Integer.BYTES) {
                break;
            }

            state.expectedPayload =
                state.inbound.getInt();

            if (state.expectedPayload < 0
                    || state.expectedPayload
                        > ConnectionState.MAX_PAYLOAD) {
                throw new ProtocolException(
                    "Invalid payload length");
            }
        }

        if (state.inbound.remaining()
                < state.expectedPayload) {
            break;
        }

        byte[] payload =
            new byte[
                state.expectedPayload];

        state.inbound.get(payload);
        state.expectedPayload = -1;

        byte[] result =
            application.process(payload);

        ByteBuffer frame =
            ByteBuffer.allocate(
                Integer.BYTES
                    + result.length);

        frame.putInt(
            result.length);

        frame.put(result);
        frame.flip();

        state.outbound.add(frame);
    }

    state.inbound.compact();

    if (!state.outbound.isEmpty()) {
        key.interestOps(
            key.interestOps()
                | SelectionKey.OP_WRITE);
    }
}

private void write(
        SelectionKey key)
        throws IOException {

    SocketChannel channel =
        (SocketChannel) key.channel();

    ConnectionState state =
        (ConnectionState)
            key.attachment();

    while (!state.outbound.isEmpty()) {
        ByteBuffer head =
            state.outbound.peek();

        channel.write(head);

        if (head.hasRemaining()) {
            return;
        }

        state.outbound.remove();
    }

    key.interestOps(
        key.interestOps()
            & ~SelectionKey.OP_WRITE);
}

private static void closeKey(
        SelectionKey key) {

    key.cancel();

    try {
        key.channel().close();
    } catch (IOException ignored) {
    }
}

Selector design rules

  • Never perform long business work on the selector thread; dispatch bounded tasks and preserve per-connection ordering.
  • Enable OP_WRITE only when output is queued, or the selector can spin because sockets are usually writable.
  • Bound each connection's inbound and outbound buffers.
  • Apply high- and low-water marks to stop reading from slow consumers.
  • Call selector.wakeup() when another thread changes registrations or interest operations.

static byte[] readBounded(
        InputStream input,
        int maximum)
        throws IOException {

    ByteArrayOutputStream output =
        new ByteArrayOutputStream(
            Math.min(
                maximum,
                8_192));

    byte[] buffer =
        new byte[8_192];

    int total = 0;

    for (int count;
            (count = input.read(buffer))
                != -1;) {

        total =
            Math.addExact(
                total,
                count);

        if (total > maximum) {
            throw new ProtocolException(
                "Response body exceeds limit");
        }

        output.write(
            buffer,
            0,
            count);
    }

    return output.toByteArray();
}

Retry policy

boolean mayRetry(
        HttpRequest request,
        int status,
        Throwable failure,
        int attempt) {

    if (attempt >= 3) {
        return false;
    }

    boolean repeatableMethod =
        Set.of(
            "GET",
            "HEAD",
            "PUT",
            "DELETE",
            "OPTIONS")
            .contains(
                request.method());

    boolean transientStatus =
        status == 408
        || status == 429
        || status == 502
        || status == 503
        || status == 504;

    boolean transientFailure =
        failure instanceof ConnectException
        || failure
            instanceof HttpConnectTimeoutException;

    return repeatableMethod
        && (transientStatus
            || transientFailure);
}

Retry conditions

  • Use a total deadline, maximum attempts, exponential backoff, and jitter.
  • Honor a valid Retry-After within the caller's deadline and policy.
  • Ensure the body publisher can generate the same bytes again.
  • Do not retry after receiving a partial application response unless the protocol defines recovery.
  • Use request IDs and server-side deduplication for operations whose outcome can be uncertain.

28. TLS security model

TLS TLS 1.3 establishes a secure channel over a reliable ordered byte stream. It negotiates parameters and shared keys, authenticates the server and optionally the client, and protects application data confidentiality and integrity.[35]

TLS does not decide service identity alone

  • The application supplies a reference identity such as a DNS name.
  • PKIX validation establishes a chain to a trusted anchor and validates certificate constraints.
  • Endpoint identification matches the reference identity to certificate subject alternative names.
  • Authorization decides whether the authenticated peer may perform the application operation.

RFC 9525 defines current service-identity verification guidance for TLS/PKIX applications and requires reference identifiers to be constructed independently of names presented by the server.[36]

TLS 1.3 current specification

RFC 9846, published in July 2026, is the current TLS 1.3 specification and obsoletes RFC 8446. Java 25's SSLContext requires support for TLS 1.2 and TLS 1.3.[35][30]

                    .createSocket(

            tls.getSSLParameters();

A raw SSLSocket can validate a certificate chain without checking that the certificate identifies the intended host. Set the protocol-appropriate endpoint identification algorithm and preserve the original service name as the reference identity.

Handshake timeout

35. Listener flow control and fragmented messages

Java WebSocket reception is demand-driven. A newly built socket has zero receive demand; the listener must call request(n). The counter counts listener invocations, not complete application messages.[37]

public final class BoundedTextListener
        implements WebSocket.Listener {

    private static final int MAX_CHARS =
        256 * 1024;

    private final StringBuilder current =
        new StringBuilder();

    private final Consumer<String> messages;

    public BoundedTextListener(
            Consumer<String> messages) {
        this.messages = messages;
    }

    @Override
    public void onOpen(
            WebSocket socket) {

        socket.request(1);
    }

    @Override
    public CompletionStage<?> onText(
            WebSocket socket,
            CharSequence data,
            boolean last) {

        if (current.length()
                + data.length()
                > MAX_CHARS) {

            return socket.sendClose(
                1009,
                "message too large");
        }

        current.append(data);

        if (last) {
            String complete =
                current.toString();

            current.setLength(0);

            messages.accept(
                complete);
        }

        socket.request(1);

        return CompletableFuture
            .completedFuture(null);
    }

    @Override
    public CompletionStage<?> onClose(
            WebSocket socket,
            int statusCode,
            String reason) {

        closed(
            statusCode,
            reason);

        return CompletableFuture
            .completedFuture(null);
    }

    @Override
    public void onError(
            WebSocket socket,
            Throwable error) {

        failed(error);
    }
}

Listener callbacks are serialized so a later callback does not start before the previous one finishes. The returned completion stage represents completion of listener processing; heavy work should be dispatched deliberately while preserving ordering and demand.[38]

Binary fragments

Do not retain or mutate a delivered ByteBuffer after asynchronous processing begins unless its bytes have been copied into owned storage. Enforce a limit across all fragments, not per callback.

37. Network security and untrusted destinations

Security Network input is untrusted even when it arrives over TLS: TLS authenticates and protects a connection according to its configured trust policy; it does not make payloads valid, authorized, small, or safe to parse.

SSRF-resistant fixed-origin client

public final class OrdersEndpoint {
    private static final String HOST =
        "orders-api.example.com";

    private static final URI ORIGIN =
        URI.create(
            "https://orders-api.example.com/");

    private OrdersEndpoint() {
    }

    public static URI resolve(
            String relativePath) {

        URI candidate =
            ORIGIN.resolve(
                relativePath);

        if (!"https".equals(
                candidate.getScheme())
                || !HOST.equals(
                    candidate.getHost())
                || candidate.getPort() != -1
                || candidate.getUserInfo() != null
                || candidate.getFragment() != null) {

            throw new IllegalArgumentException(
                "Destination outside allowed origin");
        }

        return candidate;
    }
}

The safest SSRF design is to avoid arbitrary destinations: allowlist complete origins, centralize URL construction, disable automatic redirects, and enforce egress policy at a proxy, firewall, or network namespace. URI parsing follows the generic syntax standardized by RFC 3986, but syntactic validity alone does not establish destination safety.[40] Application-only deny lists are difficult to make complete because of DNS changes, alternate address forms, redirects, and non-HTTP schemes.[48]

Untrusted URL rules

  • Accept only required schemes, normally https.
  • Reject user information, fragments, unexpected ports, and ambiguous encodings.
  • Use a canonical allowlist of hosts/origins rather than suffix substring checks.
  • Validate every redirect and do not forward credentials cross-origin.
  • Block access to loopback, link-local, private/internal, multicast, metadata, and Unix-socket destinations through network policy.
  • Resolve and connect through controlled infrastructure so DNS rebinding cannot bypass authorization.

Protocol input limits

  • Bound header, frame, message, decompressed, and aggregate sizes.
  • Set connect, read, handshake, idle, and overall deadlines.
  • Limit concurrent connections and in-flight requests per identity/source.
  • Reject malformed lengths before allocation.
  • Authenticate before allocating expensive state or sending amplified UDP responses.
  • Use parsers that reject duplicate/ambiguous fields according to protocol policy.

Credential handling

  • Never log authorization headers, cookies, WebSocket tokens, private keys, or full query strings containing secrets.
  • Do not place long-lived secrets in URIs; they leak through logs, referrers, histories, and telemetry.
  • Use separate HTTP clients for separate tenant cookie jars and client identities.
  • Rotate TLS keys/certificates and recreate long-lived pools/connections.

WebSocket server checks

Browser WebSocket handshakes include an Origin header, but non-browser clients can set arbitrary headers. Validate origin for browser cross-site protections, authenticate the session independently, authorize each subscription/action, and enforce message limits. RFC 6455 defines the opening handshake and origin-based browser security model.[39]

Fault tests

  • Connection refusal, DNS failure, delayed resolution, and connect timeout.
  • Partial frame, invalid length, oversized message, and peer close mid-message.
  • Slow sender/receiver, stalled TLS handshake, and idle timeout.
  • Packet loss, duplication, reorder, and truncation for UDP.

40. Performance, concurrency, and capacity

Choose the simplest correct I/O model

ModelStrengthCost
Blocking + virtual threadSequential code, straightforward stacks and cancellationOne task object/stack per connection; still needs admission control
SelectorExplicit buffer/backpressure control for many mostly idle socketsComplex state machines, partial I/O, selector-thread discipline
Asynchronous channelsCompletion-oriented APIsCallback/future composition and lifecycle complexity
High-level HTTP/WebSocketProtocol implementation, pooling, TLS, HTTP/2Less transport-level control; must understand body and demand semantics

Virtual threads target high-throughput workloads with many concurrent tasks that wait on blocking operations; additional threads do not improve CPU-bound throughput. JDK socket blocking operations integrate with virtual-thread suspension.[20]

Reuse and pooling

  • Reuse HttpClient instances to reuse connections and HTTP/2 sessions.
  • Do not create an unbounded socket pool; each live connection consumes kernel, memory, remote, and NAT state.
  • Bound idle connection age and account for certificate/DNS/backend changes.
  • Avoid reconnect storms with exponential backoff and jitter.

Buffers and copies

  • Buffer at the protocol layer, not reflexively at every stream.
  • Use fixed maximums and reuse bounded buffers where ownership is clear.
  • Direct buffers can reduce native I/O copying in some channel workloads but have allocation/cleanup cost; benchmark them.
  • Scatter/gather can avoid concatenation when writing headers plus payload.
  • Streaming prevents large payload retention but extends connection/resource lifetime.

HTTP/2

HTTP/2 multiplexes concurrent streams on one connection and compresses header fields, reducing the need for many parallel TCP connections. A single transport connection can still experience transport-level loss and shared flow-control or server limits; measure actual latency under concurrency.[29]

Backpressure

  • Bound TCP outbound queues and stop reading when consumers are slow.
  • Bound HTTP fan-out and response bodies.
  • Advance WebSocket demand only when ready for more listener invocations.
  • For UDP, rate-limit sends and implement congestion-aware behavior.
  • Reject overload early rather than allowing latency and memory to grow without bound.

41. Production networking checklist

Addresses and exposure

  • Bind address is explicit; loopback versus wildcard exposure is intentional.
  • IPv4 and IPv6 behavior is tested.
  • DNS changes, multiple addresses, and resolution failure are handled.
  • Unix-domain sockets live in protected directories.

TCP and sockets

  • The application protocol has explicit framing, byte order, version, and size limits.
  • Partial reads/writes and EOF are handled correctly.
  • Connect, read, idle, and overall deadlines are distinct.
  • Connection admission and per-peer work are bounded.
  • Retries account for uncertain remote processing.
  • Socket options are changed only with measured justification.

UDP

  • Loss, duplication, reorder, and truncation are expected.
  • Datagrams avoid fragmentation-prone sizes.
  • Responses cannot amplify spoofed requests.
  • Authentication, replay, congestion, and reassembly policy are explicit.
  • Multicast messages are authenticated and bounded.

NIO and concurrency

  • Selector threads never perform blocking business work.
  • OP_WRITE is enabled only while output remains.
  • Per-connection buffers and queues have limits.
  • Virtual threads are per task, not pooled.
  • Downstream capacity—not thread count—sets concurrency permits.

HTTP

  • HttpClient is reused and closed at shutdown.
  • Every request has an operation timeout and bounded body handling.
  • Redirects are disabled or validated at each hop.
  • Retries are limited to safe/idempotent or deduplicated operations.
  • Authentication headers and cookies do not cross origins unintentionally.
  • Response status, media type, encoding, and size are validated.

TLS

  • Trust anchors are minimal and environment-specific.
  • Endpoint identification is enabled for the independent service name.
  • No trust-all manager or disabled hostname verifier exists.
  • TLS/client certificates are mapped to application identity and authorization.
  • Key/certificate rotation recreates affected connections.
  • JDK algorithm restrictions are not weakened to preserve obsolete peers.

WebSocket

  • The listener calls request(n) deliberately.
  • Fragmented text/binary messages are accumulated with aggregate limits.
  • Outbound operations and queue size are controlled.
  • Heartbeat, idle, close, reconnect, resume, and deduplication behavior is defined.
  • Subscriptions and messages are authorized independently of connection establishment.

Security and operations

  • Untrusted destinations are protected by origin allowlists and network egress controls.
  • Credentials and bodies are redacted from logs.
  • Metrics distinguish DNS, connect, TLS, server, and body phases.
  • JFR and server/network telemetry can be correlated.
  • Fault tests cover slow, partial, malformed, lost, reordered, and untrusted traffic.
Final principle: networking code is protocol code. Java supplies reliable socket, channel, HTTP, TLS, and WebSocket primitives; the application must add framing, bounded concurrency, deadlines, peer identity, authorization, retry semantics, and observability.
