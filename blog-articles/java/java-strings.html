1. Text has several distinct representations

Correct string code distinguishes Java source text, immutable runtime values, UTF-16 code units, Unicode code points, user-perceived grapheme clusters, encoded bytes, locale-sensitive linguistic text, and regular-expression syntax. Treating all of them as “characters” causes truncation, comparison, indexing, and security defects.

Java char

A 16-bit UTF-16 code unit; it may be a complete BMP character or half of a surrogate pair.

Unicode code point

An integer identifying an abstract character, from U+0000 through U+10FFFF.

Grapheme cluster

A user-perceived character that can contain several code points, such as a base letter plus marks or an emoji sequence.

Encoded bytes

A representation such as UTF-8 produced only after choosing a charset and error policy.

String represents immutable character strings and exposes both UTF-16 code-unit methods and Unicode code-point methods. Its indices are measured in char units, not code points or grapheme clusters.[1]

Choose the unit before measuring or slicing. Protocol lengths may be bytes, Java APIs often use UTF-16 indices, Unicode algorithms use code points, and user interfaces usually need grapheme boundaries.

2. The String class

Immutable String is a final, immutable class implementing Serializable, CharSequence, Comparable<String>, Constable, and ConstantDesc. String literals are instances of this class.[1]

String name =
    "Grace Hopper";

String copy =
    new String(name);

assert name.equals(copy);
assert name != copy;

Prefer value operations

String normalized =
    input.strip()
        .toLowerCase(
            Locale.ROOT);

boolean present =
    normalized.contains(
        "java");

Null is not an empty string

static String requireNonBlank(
        String value) {

    Objects.requireNonNull(
        value,
        "value");

    if (value.isBlank()) {
        throw new IllegalArgumentException(
            "Blank value");
    }

    return value;
}

3. String literals, escapes, and text blocks

A string literal is a compile-time String value enclosed in double quotes. Literal and constant-expression strings are interned. Text blocks are also string literals, but permit multiline source representation and incidental-indentation processing.[2]

String escaped =
    "first line\nsecond line\t\u03BB";

String json = """
    {
      "language": "Java",
      "version": 25
    }
    """;

Unicode escapes are processed early

// The source processor handles Unicode
// escapes before normal lexical analysis.
String slash =
    "\u005c\u005c";

Because Unicode escapes are translated before tokens are recognized, use ordinary escape sequences such as \n, \r, \t, \", and \\ for syntactic characters and controls in literals.

Translate runtime escape text explicitly

String sourceText =
    "line one\\nline two";

String translated =
    sourceText.translateEscapes();

4. Immutability, sharing, and thread safety

A String value cannot change after construction. Operations that appear to modify a string return another string. This permits safe sharing of the string's value among threads, although references holding strings can still be reassigned and surrounding mutable objects still require synchronization.[1]

String original =
    "  Java  ";

String stripped =
    original.strip();

assert original.equals(
    "  Java  ");

assert stripped.equals(
    "Java");

Hash-based keys

Map<String, Configuration> byName =
    new HashMap<>();

byName.put(
    "production",
    configuration);

Immutability makes strings reliable map keys as long as the application's equality and normalization rules match the domain.

Secrets

Immutability is undesirable for some secrets because their storage cannot be overwritten through the public API. Prefer purpose-built credential APIs or mutable arrays where the surrounding system can meaningfully limit and erase copies.

5. Construction, characters, and byte decoding

String fromChars =
    new String(
        new char[] {
            'J', 'a', 'v', 'a'
        });

String fromCodePoints =
    new String(
        new int[] {
            0x0041,
            0x1F680
        },
        0,
        2);

String fromBytes =
    new String(
        bytes,
        StandardCharsets.UTF_8);

Byte-to-string construction is decoding and requires a charset. Constructors that use the platform default charset make behavior environment-dependent. Some convenience constructors replace malformed or unmappable input; use a configured CharsetDecoder when rejection is required.[1]

Avoid redundant copies

String value =
    existingString;

// Usually unnecessary:
String copy =
    new String(
        existingString);

6. Three different notions of length

String rocket =
    "A🚀";

int utf16Units =
    rocket.length();
// 3

int codePoints =
    rocket.codePointCount(
        0,
        rocket.length());
// 2

length() returns UTF-16 code units. Supplementary code points use two indices. Neither length() nor codePointCount() necessarily counts user-perceived characters, because combining marks and emoji sequences can comprise several code points.[3]

Protocol byte length

int utf8Bytes =
    value.getBytes(
        StandardCharsets.UTF_8)
        .length;

Byte length depends on the chosen encoding and cannot be derived from Java string length by a universal multiplier.

7. Iterating by Unicode code point

String text =
    "A🚀β";

text.codePoints()
    .forEach(codePoint ->
        System.out.printf(
            "U+%04X %s%n",
            codePoint,
            Character.getName(
                codePoint)));

Manual index loop

for (int index = 0;
        index < text.length();) {

    int codePoint =
        text.codePointAt(index);

    process(codePoint);

    index +=
        Character.charCount(
            codePoint);
}

Java SE 25's character-property data is based on Unicode 16.0. Methods accepting int code points support supplementary characters; methods accepting only char cannot represent them as single values.[3]

8. Substrings and safe slicing

String value =
    "order-2026-00042";

String year =
    value.substring(
        6,
        10);

String suffix =
    value.substring(11);

Substring indices use UTF-16 code-unit offsets. A boundary in the middle of a surrogate pair produces an ill-formed sequence of isolated surrogate code units.

Slice by code points

static String firstCodePoints(
        String value,
        int count) {

    if (count < 0) {
        throw new IllegalArgumentException();
    }

    int end =
        value.offsetByCodePoints(
            0,
            Math.min(
                count,
                value.codePointCount(
                    0,
                    value.length())));

    return value.substring(
        0,
        end);
}

Even code-point-safe slicing can split a grapheme cluster. User-facing truncation needs a boundary algorithm.

9. Equality, identity, and hashing

String first =
    new String("java");

String second =
    new String("java");

assert first.equals(second);
assert first.hashCode()
    == second.hashCode();

assert first != second;

equals compares the string's sequence of UTF-16 code units. == compares object references and is inappropriate for content equality, even though pooling can make it appear to work for some literals.[1]

Null-safe equality

boolean equal =
    Objects.equals(
        left,
        right);

Constant first

if ("READY".equals(status)) {
    start();
}

10. Lexicographic comparison and case conversion

compareTo orders strings lexicographically by UTF-16 char values, not by dictionary order for a human language. Most string comparison methods are not locale-sensitive.[1]

Comparator<String> binaryOrder =
    Comparator.naturalOrder();

List<String> sorted =
    names.stream()
        .sorted(binaryOrder)
        .toList();

Case-normalized identifiers

String key =
    input.toLowerCase(
        Locale.ROOT);

Use Locale.ROOT for language-neutral protocol keys and identifiers when the protocol explicitly defines case normalization. Use a user locale for linguistic display transformations.[4]

Case-insensitive equality is limited

equalsIgnoreCase is not a locale-sensitive collation algorithm and does not define a general Unicode identifier-security policy.

11. Locale-sensitive collation

Collator performs locale-sensitive string comparison and supports strengths controlling which linguistic differences are significant. Collation rules and strength meanings are locale-dependent.[5]

Collator collator =
    Collator.getInstance(
        Locale.forLanguageTag(
            "sv-SE"));

collator.setStrength(
    Collator.TERTIARY);

List<String> sorted =
    new ArrayList<>(names);

sorted.sort(
    collator::compare);

Repeated sorting

List<CollationKey> keys =
    names.stream()
        .map(
            collator::getCollationKey)
        .sorted()
        .toList();

Collation keys can improve repeated comparisons, but keys from different collators cannot be compared. The reference implementation can have contention under concurrent use, so separate collator instances per thread may be appropriate.[5]

13. Common string transformations

String stripped =
    input.strip();

boolean blank =
    input.isBlank();

String repeated =
    "-".repeat(80);

String indented =
    block.indent(4);

List<String> lines =
    block.lines()
        .toList();

strip uses Unicode-aware whitespace testing through Character.isWhitespace, while trim removes characters no greater than U+0020. lines() recognizes Java's defined line terminators and returns a lazy stream.[1]

Replacement choices

String literal =
    value.replace(
        "cat",
        "dog");

String regex =
    value.replaceAll(
        "\\bcat\\b",
        "dog");

replace(CharSequence, CharSequence) performs literal replacement despite replacing all occurrences; replaceAll interprets its first argument as a regex.

14. String concatenation

String message =
    "Order "
        + order.id()
        + " contains "
        + order.items().size()
        + " items";

If either operand of + is a string, Java performs string conversion and concatenation. A non-constant concatenation produces a new string value, but the compiler/runtime may combine conversions and concatenations to avoid unnecessary intermediate objects.[6]

Modern implementation flexibility

Since JDK 9, javac can emit invokedynamic-based concatenation sites whose implementation is supplied by JDK library machinery, allowing optimization strategies to evolve without changing source code.[7]

Loop concatenation

StringBuilder result =
    new StringBuilder();

for (String value : values) {
    result.append(value);
}

String joined =
    result.toString();

Use a builder or joining abstraction when concatenation spans a loop or dynamic number of pieces. Simple one-expression concatenation is clear and compiler-optimizable.

15. Formatting strings

String message =
    "Customer %s owes %,.2f %s"
        .formatted(
            customer.name(),
            amount,
            currency);
String localized =
    String.format(
        Locale.FRANCE,
        "%,.2f",
        amount);

String.formatted delegates to formatter-style conversions using the default formatting locale. String.format(Locale, ...) makes locale choice explicit. Format syntax, argument indexes, flags, widths, precision, and conversions are defined by Formatter.[8]

Do not build SQL with formatting

// Unsafe and incorrect:
String sql =
    "select * from user where name = '%s'"
        .formatted(userInput);

// Use PreparedStatement parameters instead.

String csv =
    String.join(

    users.stream()
        .map(User::name)
        .collect(

StringJoiner incrementally constructs delimiter-separated text with optional prefix and suffix. It is useful for imperative assembly where stream collection is unnecessary.[9]

17. The string pool

Interning String maintains a private pool of unique string values. All string literals and string-valued constant expressions are interned. intern() returns the pool's equal string, adding the receiver when no equal pooled value exists.[1]

String literal =
    "java";

String computed =
    new String(
        new char[] {
            'j', 'a', 'v', 'a'
        });

assert literal != computed;

assert literal
    == computed.intern();

Constant expressions

String first =
    "java";

String second =
    "ja" + "va";

assert first == second;

Identity behavior of interned values is specified, but normal application equality should still use equals.

18. Interning policy and memory

Interning can reduce duplicate storage for a small, bounded vocabulary repeatedly retained for a long time. It is not a general-purpose cache, and interning high-cardinality or attacker-controlled input can retain large numbers of values.

Appropriate bounded domain

enum ProtocolToken {
    START,
    STOP,
    STATUS
}

Enums or canonical domain objects are generally clearer than manually interning a fixed vocabulary.

Explicit application canonicalization

ConcurrentMap<String, String> canonical =
    new ConcurrentHashMap<>();

String value =
    canonical.computeIfAbsent(
        input,
        Function.identity());

An application-owned canonicalization map can expose size limits, eviction, metrics, and lifecycle, whereas the string pool does not provide those application policies.

19. Compact Strings in HotSpot

JEP 254 changed the JDK 9 implementation of String, StringBuilder, and StringBuffer to use a byte array plus an encoding indicator, storing Latin-1-compatible content with one byte per element and other content in a UTF-16 representation. This is an implementation optimization and does not change the public UTF-16-oriented API contract.[10]

Do not infer storage from length(). Java API indices remain UTF-16 code-unit indices even when HotSpot internally stores a particular string compactly.

Portability

Applications must not use reflection or unsupported VM assumptions to depend on the internal representation. Other conforming JVM implementations can choose different layouts.

20. StringBuilder

Mutable sequence StringBuilder is a mutable character sequence designed primarily for single-threaded construction. It provides append, insert, delete, replace, reverse, search, code-point, capacity, and substring operations and is generally preferred over StringBuffer when synchronization is unnecessary.[11]

StringBuilder builder =
    new StringBuilder();

builder.append("Order ");
builder.append(orderId);
builder.append(": ");
builder.append(itemCount);
builder.append(" items");

String result =
    builder.toString();

Not value equality

StringBuilder first =
    new StringBuilder("java");

StringBuilder second =
    new StringBuilder("java");

assert !first.equals(second);
assert first.compareTo(second) == 0;

StringBuilder implements Comparable but does not override equals; avoid using builders as map keys or sorted-set values.

21. Builder length and capacity

StringBuilder builder =
    new StringBuilder(
        1_024);

int length =
    builder.length();

int capacity =
    builder.capacity();

Length is the number of UTF-16 code units currently present. Capacity is the amount available before expansion. The no-argument constructor begins with capacity 16; constructors from text allocate based on the initial content.[11]

Pre-size when accurately known

int expected =
    prefix.length()
    + payload.length()
    + suffix.length();

StringBuilder builder =
    new StringBuilder(expected);

Do not guess huge capacities

Over-allocation increases retained memory. Pre-sizing is useful when the estimate is cheap and reliable, especially in hot loops.

22. Builder operations and indexing

StringBuilder builder =
    new StringBuilder(
        "customer:unknown");

builder.replace(
    9,
    builder.length(),
    customerId);

builder.insert(
    0,
    "[INFO] ");

builder.deleteCharAt(
    builder.length() - 1);

builder.reverse();

Builder indices and lengths use UTF-16 code units. Operations can split surrogate pairs if boundaries are calculated incorrectly. reverse() performs special surrogate handling, but it is not a grapheme-cluster reversal algorithm.[11]

Search

int separator =
    builder.indexOf(":");

String key =
    builder.substring(
        0,
        separator);

23. Efficient builder patterns

Conditional delimiter

StringBuilder builder =
    new StringBuilder();

for (String value : values) {
    if (!builder.isEmpty()) {
        builder.append(", ");
    }

    builder.append(value);
}

String result =
    builder.toString();

Reusable local builder

static String render(
        Order order) {

    StringBuilder result =
        new StringBuilder(128);

    result.append(order.id())
        .append(' ')
        .append(order.status())
        .append(' ')
        .append(order.total());

    return result.toString();
}

Keep builders method-local when possible. Reusing a shared builder creates synchronization and lifecycle hazards; retaining a very large builder for later small jobs can also retain excessive capacity.

Reset local reusable state

builder.setLength(0);

Resetting length does not erase the underlying content. Do not use builder reuse as a secure erasure mechanism.

24. StringBuffer

StringBuffer is a thread-safe mutable character sequence whose operations are synchronized. It predates StringBuilder; since JDK 5, StringBuilder is generally preferred for single-thread use.[12]

StringBuffer buffer =
    new StringBuffer();

buffer.append("shared");
buffer.append(':');
buffer.append(value);

Method synchronization is not transaction synchronization

if (buffer.length() > 0) {
    buffer.deleteCharAt(
        buffer.length() - 1);
}

Another thread can modify the buffer between synchronized method calls. Compound invariants still require one external synchronization boundary.

synchronized (buffer) {
    if (buffer.length() > 0) {
        buffer.deleteCharAt(
            buffer.length() - 1);
    }
}

Prefer thread confinement or immutable results rather than sharing a mutable text buffer across threads.

25. CharSequence and Appendable

CharSequence abstracts readable sequences of char values through length, indexing, subsequences, and code-unit/code-point streams. Appendable abstracts destinations that accept characters and character sequences.[13][14]

static int countAsciiDigits(
        CharSequence value) {

    int count = 0;

    for (int index = 0;
            index < value.length();
            index++) {

        char character =
            value.charAt(index);

        if (character >= '0'
                && character <= '9') {
            count++;
        }
    }

    return count;
}
static void writeLabel(
        Appendable output,
        String key,
        Object value)
        throws IOException {

    output.append(key)
        .append('=')
        .append(
            String.valueOf(value));
}

An arbitrary CharSequence can be mutable, so its contents may change during use. Convert to String when a stable snapshot is required.

26. Unicode: code units, code points, and scalar values

Unicode Unicode assigns code points to abstract characters and defines properties and algorithms independently of particular encodings. Unicode 17.0 is the latest published version as of 31 July 2026, while Java SE 25's Character data is based on Unicode 16.0.[15][3]

ConceptExampleJava representation
Code pointU+1F680 ROCKETint
UTF-16 code unitHigh or low surrogatechar
Code-point sequenceText abstractionString plus code-point APIs
Grapheme clusterFamily emoji or accented letterBoundary algorithm, not one primitive type

Validate code points

static String fromCodePoint(
        int codePoint) {

    if (!Character.isValidCodePoint(
            codePoint)) {
        throw new IllegalArgumentException(
            "Invalid code point");
    }

    return new String(
        Character.toChars(
            codePoint));
}

Unpaired surrogates

A Java string can contain isolated surrogate code units even though they do not form valid Unicode scalar values. Encoders and external protocols need an explicit malformed-input policy.

27. Unicode normalization

Unicode can represent canonically equivalent text with different code-point sequences, such as a precomposed accented letter or a base letter followed by a combining mark. Normalizer supports NFC, NFD, NFKC, and NFKD forms.[16][17]

String composed =
    "\u00E9";

String decomposed =
    "e\u0301";

assert !composed.equals(
    decomposed);

String first =
    Normalizer.normalize(
        composed,
        Normalizer.Form.NFC);

String second =
    Normalizer.normalize(
        decomposed,
        Normalizer.Form.NFC);

assert first.equals(second);

Canonical versus compatibility normalization

  • NFC and NFD preserve canonical equivalence.
  • NFKC and NFKD additionally apply compatibility mappings that can erase presentation distinctions.
  • Normalization is not case folding, collation, transliteration, or confusable detection.

Normalize at a defined boundary

Choose a normalization policy for identifiers, search indexes, signatures, or storage and apply it consistently. Do not normalize blindly when exact code-point preservation is a requirement.

28. User-perceived characters and text boundaries

A grapheme cluster can contain several code points: combining sequences, emoji modifiers, flags, and zero-width-joiner sequences are common examples. Unicode Standard Annex #29 defines default grapheme, word, and sentence boundary algorithms.[18][19]

Boundary iteration

static List<String> graphemes(
        String text,
        Locale locale) {

    BreakIterator iterator =
        BreakIterator
            .getCharacterInstance(
                locale);

    iterator.setText(text);

    List<String> result =
        new ArrayList<>();

    int start =
        iterator.first();

    for (int end =
            iterator.next();
            end != BreakIterator.DONE;
            start = end,
            end = iterator.next()) {

        result.add(
            text.substring(
                start,
                end));
    }

    return result;
}

Provider and version behavior

BreakIterator is locale/provider-sensitive and should be tested against the application's required emoji and language cases. For strict conformance to a particular Unicode grapheme algorithm/version, use a library whose contract states that version.

29. Encoding strings to bytes

byte[] utf8 =
    text.getBytes(
        StandardCharsets.UTF_8);

String restored =
    new String(
        utf8,
        StandardCharsets.UTF_8);

A charset maps between Unicode character sequences and byte sequences. Java guarantees the availability of standard charsets including US-ASCII, ISO-8859-1, UTF-8, UTF-16, UTF-16BE, and UTF-16LE.[20]

Strict encoding

CharsetEncoder encoder =
    StandardCharsets.UTF_8
        .newEncoder()
        .onMalformedInput(
            CodingErrorAction.REPORT)
        .onUnmappableCharacter(
            CodingErrorAction.REPORT);

ByteBuffer bytes =
    encoder.encode(
        CharBuffer.wrap(text));

Never rely on the default charset in protocols

// Environment-dependent:
byte[] ambiguous =
    text.getBytes();

// Explicit:
byte[] stable =
    text.getBytes(
        StandardCharsets.UTF_8);

30. Unicode and identifier security

Visually confusable characters, mixed scripts, bidirectional controls, invisible formatting characters, normalization differences, and case behavior can create identifiers that look alike but compare differently. Unicode Technical Standard #39 defines mechanisms for security profiles, restriction levels, and confusable detection.[21]

Security profile, not one cleanup call

record IdentifierPolicy(
    Normalizer.Form normalization,
    Set<Character.UnicodeScript>
        allowedScripts,
    int maximumCodePoints) {
}
  • Define allowed scripts and character properties for security-sensitive identifiers.
  • Normalize under a documented form.
  • Reject prohibited controls and malformed sequences.
  • Apply locale-neutral case rules only when the protocol calls for them.
  • Store and display the original value separately when auditability requires it.
Do not treat normalization as spoofing protection. Canonically equal text and visually confusable text are different problems.

31. Java regular-expression architecture

Regex Pattern is the compiled representation of a regular expression. A Matcher applies a pattern to a CharSequence and retains mutable match state. Patterns are safe for concurrent use; matchers are not intended for sharing across threads.[22][23]

Pattern assignment =
    Pattern.compile(
        "(?<key>[A-Za-z][A-Za-z0-9_]*)"
            + "\\s*=\\s*"
            + "(?<value>.*)");

Matcher matcher =
    assignment.matcher(
        "timeout = 30");

Compile once when reused

private static final Pattern
    IDENTIFIER =
        Pattern.compile(
            "[A-Za-z_][A-Za-z0-9_]*");

String.matches(regex) compiles and attempts a full-input match for each call. Reuse a compiled pattern in repeated or hot operations.

32. Compiling patterns and diagnosing syntax

Pattern pattern =
    Pattern.compile(
        "(?<year>\\d{4})-"
            + "(?<month>\\d{2})-"
            + "(?<day>\\d{2})");

Java string escaping versus regex escaping

// Regex token \d is written "\\d".
Pattern digits =
    Pattern.compile(
        "\\d+");

// Literal backslash:
Pattern slash =
    Pattern.compile(
        "\\\\");

Syntax diagnostics

try {
    return Pattern.compile(
        userPattern);
} catch (PatternSyntaxException failure) {
    throw new InvalidPattern(
        failure.getDescription(),
        failure.getIndex(),
        failure);
}

PatternSyntaxException reports the description, erroneous pattern, and approximate error index for an invalid regex.[24]

34. Character classes and Unicode properties

Pattern asciiIdentifier =
    Pattern.compile(
        "[A-Za-z_][A-Za-z0-9_]*");

Pattern unicodeLetters =
    Pattern.compile(
        "\\p{L}+");

Pattern greek =
    Pattern.compile(
        "\\p{IsGreek}+");

Pattern notWhitespace =
    Pattern.compile(
        "\\S+");

Java regex supports predefined classes, POSIX classes, Unicode general categories, scripts, blocks, binary properties, intersections, and subtraction. The meaning of shorthand classes such as \w and \d depends on flags.[22]

Character class intersection

Pattern consonants =
    Pattern.compile(
        "[a-z&&[^aeiou]]+");

Define identifiers explicitly

Choose ASCII-only or Unicode-aware identifier rules intentionally. A broad “letter or digit” rule can admit scripts and confusable characters the application never planned to support.

35. matches, lookingAt, and find

Matcher matcher =
    pattern.matcher(input);

boolean whole =
    matcher.matches();

matcher.reset();

boolean prefix =
    matcher.lookingAt();

matcher.reset();

while (matcher.find()) {
    process(
        matcher.start(),
        matcher.end(),
        matcher.group());
}

matches() attempts to match the entire region; lookingAt() matches from the region start without requiring the end; find() scans for the next matching subsequence.[23]

Regions

A snapshot can be passed without exposing the mutable matcher's later state.[25]

36. Capturing, noncapturing, and named groups

Pattern date =
    Pattern.compile(
        "(?<year>\\d{4})-"
            + "(?<month>\\d{2})-"
            + "(?<day>\\d{2})");

Matcher matcher =
    date.matcher(
        "2026-07-31");

if (matcher.matches()) {
    int year =
        Integer.parseInt(
            matcher.group("year"));

    int month =
        Integer.parseInt(
            matcher.group("month"));

    int day =
        Integer.parseInt(
            matcher.group("day"));
}

Noncapturing group

Pattern protocol =
    Pattern.compile(
        "(?:https?|wss)://"
            + "(?<host>[^/]+)");

Optional group can be null

Pattern signAndDigits =
    Pattern.compile(
        "([+-])?(\\d+)");

String sign =
    matcher.group(1);
// null when group did not participate.

Use noncapturing groups when grouping is needed only for precedence or quantification. Named groups improve maintainability when a pattern is a parser rather than a simple predicate.

37. Quantifiers, greediness, and backtracking

FamilyExamplesBehavior
Greedy*, +, {m,n}Prefer more input, backtrack if necessary
Reluctant*?, +?, {m,n}?Prefer less input, expand if necessary
Possessive*+, ++, {m,n}+Consume without giving characters back
Pattern greedy =
    Pattern.compile(
        "<.*>");

Pattern reluctant =
    Pattern.compile(
        "<.*?>");

Pattern possessive =
    Pattern.compile(
        "\\w++:");

Atomic grouping

Pattern atomic =
    Pattern.compile(
        "(?>[A-Za-z]+):");

Possessive quantifiers and atomic groups can prevent backtracking into a completed subexpression when that matches the grammar, improving predictability. They can also change which inputs match, so apply them from a language model rather than as a blind optimization.

40. Quoting literal pattern text

Quote one inserted literal

Pattern exactToken =
    Pattern.compile(
        "^"
            + Pattern.quote(
                userToken)
            + "$");

Compile the whole pattern literally

Pattern literal =
    Pattern.compile(
        userText,
        Pattern.LITERAL);

Pattern.quote produces a literal pattern fragment. Pattern.LITERAL treats the complete supplied pattern as literal text. Quoting the pattern and quoting the replacement are separate operations.[22]

Never interpolate untrusted text into regex syntax without deciding whether it is syntax or literal data.

42. Streaming match results

Pattern number =
    Pattern.compile(
        "\\d+");

    number.matcher(input)
        .results()
        .map(
            MatchResult::group)
        .map(
            Integer::parseInt)
        .toList();

Matcher.results() returns a sequential stream of immutable match-result snapshots. The matcher must not be modified while the stream pipeline executes.[23]

Predicate factories

    number.asPredicate();

Predicate<String> allNumber =
    number.asMatchPredicate();

asPredicate tests whether a match can be found; asMatchPredicate tests whether the entire input matches.

43. Regular-expression denial of service

Backtracking regex engines can consume excessive CPU on carefully chosen nonmatching inputs when patterns contain ambiguous nested repetition or overlapping alternatives. CWE-1333 classifies inefficient regular-expression complexity as a denial-of-service weakness.[26]

High-risk shape

Pattern risky =
    Pattern.compile(
        "(a+)+$");

Engineering controls

  • Prefer structurally unambiguous patterns.
  • Use bounded quantifiers where the protocol has limits.
  • Use possessive quantifiers or atomic groups when semantically valid.
  • Bound input length before matching.
  • Avoid executing attacker-supplied patterns.
  • Test long near-miss inputs, not only successful examples.
  • Use a parser or linear-time regex implementation when complexity must be guaranteed.

Interrupting or timing out a thread is not a substitute for safe pattern design, because cancellation behavior and resource isolation can be difficult to guarantee.

44. Pattern reuse and matcher lifecycle

private static final Pattern
    LOG_LINE =
        Pattern.compile(
            "(?<level>TRACE|DEBUG|INFO|WARN|ERROR)"
                + "\\s+"
                + "(?<message>.*)");

Pattern objects are immutable and safe to reuse concurrently. Create a new matcher per input or per thread. A matcher can be reset for sequential reuse, but retaining matchers can retain their input character sequences.[22][23]

Matcher matcher =
    LOG_LINE.matcher(
        firstInput);

parse(matcher);

matcher.reset(
    secondInput);

parse(matcher);

Cache policy

Cache a bounded set of application-defined patterns. An unbounded cache of user-supplied regexes creates memory pressure and preserves potentially dangerous patterns.

45. Complete example: bounded assignment-file parser

Grammar

assignment := key whitespace? '=' whitespace? value
key        := ASCII letter or '_' followed by
              ASCII letters, digits, '_' or '-'
comment    := blank line or line beginning with '#'

Implementation

public final class AssignmentParser {
    private static final Pattern ASSIGNMENT =
        Pattern.compile(
            "(?<key>[A-Za-z_][A-Za-z0-9_-]*)"
                + "\\s*=\\s*"
                + "(?<value>.*)");

    private static final int MAX_LINE_UNITS =
        4_096;

    private static final int MAX_ENTRIES =
        1_000;

    private AssignmentParser() {
    }

    public static Map<String, String> parse(
            List<String> lines) {

        Map<String, String> result =
            new LinkedHashMap<>();

        int lineNumber = 0;

        for (String raw : lines) {
            lineNumber++;

            if (raw.length()
                    > MAX_LINE_UNITS) {
                throw new ParseFailure(
                    lineNumber,
                    "Line is too long");
            }

            String line =
                raw.strip();

            if (line.isEmpty()
                    || line.startsWith("#")) {
                continue;
            }

            Matcher matcher =
                ASSIGNMENT.matcher(line);

            if (!matcher.matches()) {
                throw new ParseFailure(
                    lineNumber,
                    "Invalid assignment");
            }

            String key =
                matcher.group("key")
                    .toLowerCase(
                        Locale.ROOT);

            String value =
                Normalizer.normalize(
                    matcher.group("value")
                        .strip(),
                    Normalizer.Form.NFC);

            String previous =
                result.putIfAbsent(
                    key,
                    value);

            if (previous != null) {
                throw new ParseFailure(
                    lineNumber,
                    "Duplicate key: " + key);
            }

            if (result.size()
                    > MAX_ENTRIES) {
                throw new ParseFailure(
                    lineNumber,
                    "Too many entries");
            }
        }

        return Map.copyOf(result);
    }
}

Design properties

  • The regex is fixed, compiled once, and anchored by matches().
  • Input and entry counts are bounded.
  • Keys deliberately use an ASCII protocol grammar.
  • Key case normalization uses Locale.ROOT.
  • Values use a documented NFC policy.
  • Duplicate semantics are explicit.
  • Parsing does not interpret escapes, variables, or comments inside values accidentally.

47. String and regex performance

Measure allocation and retained memory

  • Large temporary strings and encoded byte arrays.
  • Builder growth and oversized retained capacity.
  • Repeated case conversion and normalization.
  • Regex compilation and backtracking.
  • Substring copies and materialized match groups.
  • Unbounded intern/canonicalization tables.

Guidelines

  • Use simple + for one readable concatenation expression.
  • Use StringBuilder for dynamic loops and incremental construction.
  • Use literal methods instead of regex for literal operations.
  • Compile reused patterns.
  • Use code-point or boundary algorithms only where required; they cost more because they solve a harder problem.
  • Avoid repeated normalization when storage already guarantees one form.
  • Keep builders, matchers, and large text local to shorten retention.

49. Production checklist

String values

  • Content equality uses equals, not identity.
  • Null, empty, and blank have explicit domain meanings.
  • Concatenation style matches the dynamic structure.
  • Builders are local, appropriately sized, and not value keys.
  • StringBuffer is used only when its synchronization model is genuinely needed.

Unicode and internationalization

  • Every length/index operation names its unit: bytes, UTF-16 units, code points, or graphemes.
  • Code-point iteration handles supplementary characters.
  • User-visible slicing uses boundary-aware logic.
  • Normalization form and boundary are documented.
  • Case conversion and collation use explicit locales.
  • Security-sensitive identifiers use a script/confusable/control policy.
  • Encoding uses an explicit charset and error action.

String pool and memory

  • Application correctness never depends on intern identity.
  • Unbounded or attacker-controlled values are not interned.
  • Canonicalization caches have explicit size and lifecycle.
  • Internal compact-string representation is not assumed.
  • Large builders and matchers do not retain oversized inputs indefinitely.

Regular expressions

  • Literal operations avoid regex.
  • Reusable regexes are compiled once.
  • A matcher is not shared concurrently.
  • Full, prefix, and scanning semantics use the correct matcher method.
  • Capturing groups are limited to values actually needed.
  • Inserted pattern and replacement text is quoted correctly.
  • Input length and quantifiers are bounded.
  • Long near-miss inputs are performance-tested.
  • Grammar-aware parsers replace regex when syntax becomes complex.
Final principle: a Java string is an immutable sequence exposed through UTF-16 indices, not a byte array and not automatically a sequence of visible characters. Reliable text systems make encoding, Unicode unit, normalization, locale, grammar, memory policy, and trust boundary explicit.
