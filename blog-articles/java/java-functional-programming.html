1. Functional programming as value transformation

Functional programming emphasizes expressions, immutable values, explicit inputs and outputs, composition, and controlled effects. Java supports these techniques inside a statically typed, object-oriented language rather than replacing objects, classes, mutation, or exceptions.

Pure core

Functions compute results from inputs without hidden reads, writes, clocks, randomness, or external I/O.

Immutable data

State transitions produce new values or controlled updates instead of exposing arbitrary shared mutation.

Higher-order design

Methods accept or return behavior through functional-interface values.

Effect boundary

Database, network, logging, files, time, and mutation remain explicit at application boundaries.

Java's general-purpose functional interfaces live in java.util.function. They provide target types for lambda expressions and method references, including the core shapes Predicate, Function, Consumer, Supplier, and their arity and primitive specializations.[1]

Functional Java is architectural, not syntactic. Replacing an anonymous class with a lambda shortens code; making dependencies, transformations, and effects explicit improves design.

2. Java is multiparadigm, not a purely functional language

Java remains a class-based, object-oriented, imperative language with mutable objects, statements, loops, exceptions, threads, identity, and side effects. Lambdas add a concise way to express instances of functional interfaces and support functional-style APIs such as streams, optionals, asynchronous stages, comparators, and callbacks.[2]

Imperative version

List<String> names =
    new ArrayList<>();

for (User user : users) {
    if (user.active()) {
        names.add(
            user.name()
                .strip()
                .toLowerCase(
                    Locale.ROOT));
    }
}

names.sort(
    Comparator.naturalOrder());

Functional-style version

List<String> names =
    users.stream()
        .filter(User::active)
        .map(User::name)
        .map(String::strip)
        .map(name ->
            name.toLowerCase(
                Locale.ROOT))
        .sorted()
        .toList();

The second version describes a pipeline of values. It is not automatically superior: a loop may be clearer for complex state machines, multiple exits, or tightly optimized index-based code.

3. Behavior as an ordinary typed value

Functional interface Java does not have one universal function type. A lambda or method reference is a poly expression whose type comes from its target functional interface in an assignment, invocation, or cast context.[3]

Predicate<String> nonBlank =
    value ->
        !value.isBlank();

Function<String, Integer> length =
    String::length;

Consumer<String> printer =
    System.out::println;

Supplier<UUID> identifiers =
    UUID::randomUUID;

Pass behavior to a method

static <T> List<T> select(
        List<T> source,
        Predicate<? super T> predicate) {

    return source.stream()
        .filter(predicate)
        .toList();
}

Return behavior from a method

static Predicate<Order> minimumTotal(
        BigDecimal minimum) {

    return order ->
        order.total()
            .compareTo(minimum) >= 0;
}

4. Lambda-expression syntax

Lambda A lambda has parameters, an arrow token, and an expression body or block body. Parameter types can often be inferred from the target type. A block body follows method-body rules and must explicitly return a value when the functional method requires one.[3]

// No parameters:
Supplier<Instant> now =
    () -> Instant.now();

// One inferred parameter:
Predicate<String> empty =
    text -> text.isEmpty();

// Two inferred parameters:
Comparator<User> byName =
    (left, right) ->
        left.name()
            .compareTo(
                right.name());

// Explicit types:
BinaryOperator<BigDecimal> add =
    (BigDecimal left,
     BigDecimal right) ->
        left.add(right);

// Block body:
Function<String, Integer> parse =
    text -> {
        String normalized =
            text.strip();

        return Integer.parseInt(
            normalized);
    };

Parentheses rules

A single implicitly typed parameter can omit parentheses. Zero, multiple, explicitly typed, or annotated parameters require parentheses.

Function<String, String> trim =
    value -> value.strip();

Function<String, String> annotated =
    (@Deprecated String value) ->
        value.strip();

5. Target typing and overload resolution

The same lambda syntax can target different functional interfaces when their function types are compatible. The target controls parameter types, return adaptation, checked-exception compatibility, and overload selection.[3]

Predicate<String> first =
    value -> value.isEmpty();

Function<String, Boolean> second =
    value -> value.isEmpty();

Explicit target through a cast

var result =
    transform(
        (Function<String, Integer>)
            String::length);

Prefer descriptive variable types

Predicate<Invoice> overdue =
    invoice ->
        invoice.dueDate()
            .isBefore(today);

List<Invoice> result =
    invoices.stream()
        .filter(overdue)
        .toList();

Named functional values can make type inference, debugging, reuse, and domain meaning clearer than dense inline lambdas.

6. Capturing local variables

A lambda can capture local variables only when they are final or effectively final. It can also access fields and static variables, which remain mutable under normal Java rules.[3]

BigDecimal taxRate =
    new BigDecimal("0.0725");

Function<BigDecimal, BigDecimal>
    addTax =
        subtotal ->
            subtotal.multiply(
                BigDecimal.ONE.add(
                    taxRate));

Illegal reassignment

int minimum = 10;

// Reassignment means minimum is
// no longer effectively final.
minimum = 20;

Predicate<Integer> accepted =
    value -> value >= minimum;
// Compilation error.

Captured reference does not imply immutable object

List<String> output =
    new ArrayList<>();

Consumer<String> append =
    output::add;

The reference variable is not reassigned, but the referenced list is mutable. Captured mutation can create hidden coupling and data races when the function is reused concurrently.

7. Lexical scope and this

Lambda expressions do not introduce a new this or super scope. Inside a lambda, this refers to the enclosing instance. Lambda parameter and local names also follow lexical shadowing restrictions.[3]

public final class Validator {
    private final int minimumLength;

    public Validator(int minimumLength) {
        this.minimumLength =
            minimumLength;
    }

    public Predicate<String> rule() {
        return value ->
            value.length()
                >= this.minimumLength;
    }
}

Difference from anonymous classes

Runnable lambda =
    () ->
        System.out.println(
            this.getClass());

Runnable anonymous =
    new Runnable() {
        @Override
        public void run() {
            System.out.println(
                this.getClass());
        }
    };

The anonymous class has its own this; the lambda uses the enclosing object's this.

8. Functional interfaces and SAM conversion

A functional interface has one abstract method after accounting for inherited methods and methods corresponding to public methods of Object. Its function type defines the lambda's parameters, return type, and throws clause.[4]

@FunctionalInterface
public interface Formatter<T> {
    String format(T value);
}
Formatter<Money> formatter =
    money ->
        "%s %.2f".formatted(
            money.currency(),
            money.amount());

Default and static methods are allowed

@FunctionalInterface
public interface Rule<T> {
    boolean test(T value);

    default Rule<T> negate() {
        return value ->
            !test(value);
    }

    static <T> Rule<T> always() {
        return value -> true;
    }
}

Default, static, and private interface methods do not add abstract function methods and therefore do not prevent functional-interface status.

9. @FunctionalInterface

@FunctionalInterface documents design intent and asks the compiler to reject an interface declaration that is not functional. The annotation is not required for lambda compatibility; structural rules determine whether an interface is functional.[5]

@FunctionalInterface
public interface Decoder<T> {
    T decode(String input)
        throws DecodeException;
}

Accidental breakage is detected

@FunctionalInterface
interface Broken {
    void first();
    void second();
}
// Compilation error.

Annotate public functional interfaces unless there is a specific reason not to. It protects the single-abstract-method contract during later maintenance.

10. Designing a custom functional interface

Use a standard java.util.function interface when its semantics and exception contract fit. Define a domain interface when the concept deserves a name, requires checked exceptions, needs domain-specific composition, or carries important documentation.

Domain-specific policy

@FunctionalInterface
public interface PricingPolicy {
    Money price(
        Product product,
        Customer customer,
        Instant quotedAt);
}

Why not a generic tri-function?

A hypothetical TriFunction<Product,Customer,Instant,Money> captures shape but not meaning. PricingPolicy communicates intent, supports domain documentation, and can grow default combinators without exposing unrelated generic vocabulary.

Variance-friendly API

static <T, R> List<R> transform(
        List<T> source,
        Function<? super T,
                 ? extends R> mapper) {

    return source.stream()
        .map(mapper)
        .toList();
}

Use ? super T for consumed inputs and ? extends R for produced outputs where flexibility is useful.

11. Checked exceptions in functional code

A lambda body may throw checked exceptions only when the target functional method's throws clause permits them. The standard java.util.function interfaces generally do not declare checked exceptions.[6]

Domain throwing interface

@FunctionalInterface
public interface ThrowingFunction<T, R, X
        extends Exception> {

    R apply(T value)
        throws X;
}

Boundary adapter

static <T, R> Function<T, R>
unchecked(
        ThrowingFunction<T, R, IOException>
            function) {

    return value -> {
        try {
            return function.apply(value);
        } catch (IOException failure) {
            throw new UncheckedIOException(
                failure);
        }
    };
}
List<String> contents =
    paths.stream()
        .map(
            unchecked(
                Files::readString))
        .toList();

Do not erase error policy accidentally

Wrapping checked exceptions is appropriate only at a boundary whose contract uses unchecked failure. When partial failure is expected, return a typed success/failure value instead of aborting the whole pipeline.

12. Predicate<T>

Predicate A predicate accepts one value and returns a boolean through test(T). It represents selection, validation, matching, policy checks, and conditional behavior.[7]

Predicate<Order> paid =
    Order::paid;

Predicate<Order> domestic =
    order ->
        order.destination()
            .countryCode()
            .equals("US");

List<Order> result =
    orders.stream()
        .filter(
            paid.and(domestic))
        .toList();

Collection APIs

users.removeIf(
    user ->
        user.lastLogin()
            .isBefore(cutoff));

Validation rule

Predicate<String> validUsername =
    value ->
        value != null
        && value.length() >= 3
        && value.length() <= 32
        && value.chars()
            .allMatch(character ->
                Character.isLetterOrDigit(
                    character)
                || character == '_');

Predicates should normally be deterministic and free of side effects so they can be reused in streams, collection methods, tests, and concurrent execution.

13. Predicate composition

and and or compose predicates with short-circuiting evaluation; negate returns logical negation. Static helpers include isEqual and not.[7]

Predicate<Customer> active =
    Customer::active;

Predicate<Customer> verified =
    Customer::verified;

Predicate<Customer> eligible =
    active.and(verified);

Predicate<Customer> ineligible =
    eligible.negate();

Readable rule factory

static Predicate<Order>
createdWithin(
        Instant startInclusive,
        Instant endExclusive) {

    return order ->
        !order.createdAt()
            .isBefore(startInclusive)
        && order.createdAt()
            .isBefore(endExclusive);
}

Negating a method reference

List<String> nonBlank =
    values.stream()
        .filter(
            Predicate.not(
                String::isBlank))
        .toList();
Composition preserves side effects. Short-circuiting means the right predicate may not run. Never depend on both predicates executing for logging, counters, mutation, or cleanup.

14. Function<T,R>

Function A function accepts one value and produces one result through apply(T). The input and result types may differ.[8]

Function<User, String> displayName =
    user ->
        user.firstName()
            + " "
            + user.lastName();

Function<String, URI> parseUri =
    URI::create;

Function<Order, BigDecimal> total =
    Order::total;

Map transformation

List<OrderView> views =
    orders.stream()
        .map(
            order ->
                new OrderView(
                    order.id(),
                    order.total(),
                    order.status()))
        .toList();

Identity

Function<Customer, Customer> identity =
    Function.identity();

Map<CustomerId, Customer> byId =
    customers.stream()
        .collect(
            Collectors.toMap(
                Customer::id,
                Function.identity()));

15. Function composition: compose and andThen

compose(before) applies the supplied function first and then the current function. andThen(after) applies the current function first and the supplied function second.[8]

Function<String, String> strip =
    String::strip;

Function<String, String> lower =
    value ->
        value.toLowerCase(
            Locale.ROOT);

Function<String, String> normalize =
    strip.andThen(lower);

String result =
    normalize.apply(
        "  EXAMPLE  ");

Different intermediate types

Function<String, URI> parse =
    URI::create;

Function<URI, String> host =
    URI::getHost;

Function<String, String> hostFromText =
    parse.andThen(host);

Order matters

Function<BigDecimal, BigDecimal> discount =
    amount ->
        amount.multiply(
            new BigDecimal("0.90"));

Function<BigDecimal, BigDecimal> tax =
    amount ->
        amount.multiply(
            new BigDecimal("1.07"));

BigDecimal discountThenTax =
    discount.andThen(tax)
        .apply(price);

BigDecimal taxThenDiscount =
    discount.compose(tax)
        .apply(price);

Composition is not necessarily commutative. Name pipelines according to their real execution order.

16. Consumer<T>

Effect A consumer accepts one input and returns no result through accept(T). Unlike most functional interfaces, its purpose is normally side effects.[9]

Consumer<AuditEvent> writeAudit =
    auditRepository::save;

Consumer<String> print =
    System.out::println;

names.forEach(print);

Sequence consumers

Consumer<Order> recordMetric =
    order ->
        metrics.record(
            order.status());

Consumer<Order> writeLog =
    order ->
        LOGGER.log(
            System.Logger.Level.INFO,
            order.toString());

Consumer<Order> observe =
    recordMetric.andThen(writeLog);

andThen runs the first consumer and then the second. If the first throws, the second is not invoked.[9]

Effect boundaries

Consumers are appropriate at explicit boundaries: event delivery, persistence commands, logging, UI callbacks, and resource setup. Core transformations are generally easier to reason about when they return values instead.

17. Supplier<T>

Supplier A supplier takes no arguments and returns a value through get(). It can represent deferred construction, factories, defaults, clocks, randomness, resource acquisition, and lazy fallback. It is not required to return a new or distinct result on every invocation.[10]

Supplier<UUID> identifiers =
    UUID::randomUUID;

Supplier<List<String>> lists =
    ArrayList::new;

Supplier<Instant> now =
    clock::instant;

Lazy default

Configuration configuration =
    cache.find(key)
        .orElseGet(
            () ->
                repository.load(key));

Dependency injection

public final class TokenIssuer {
    private final Supplier<UUID> ids;
    private final Supplier<Instant> now;

    public TokenIssuer(
            Supplier<UUID> ids,
            Supplier<Instant> now) {

        this.ids =
            Objects.requireNonNull(ids);

        this.now =
            Objects.requireNonNull(now);
    }

    public Token issue() {
        return new Token(
            ids.get(),
            now.get());
    }
}

Suppliers make nondeterministic dependencies replaceable in tests without requiring static mocking.

18. UnaryOperator<T>

UnaryOperator<T> specializes Function<T,T> for transformations whose input and result have the same type. It inherits composition methods and provides identity().[11]

UnaryOperator<String> normalize =
    value ->
        value.strip()
            .toLowerCase(
                Locale.ROOT);

UnaryOperator<BigDecimal> roundMoney =
    value ->
        value.setScale(
            2,
            RoundingMode.HALF_EVEN);

State transition

record Counter(
    int value) {
}

UnaryOperator<Counter> increment =
    counter ->
        new Counter(
            counter.value() + 1);

List replacement

names.replaceAll(
    String::strip);

Operators are especially useful for immutable state transitions, normalization, retry transformations, and update functions.

19. BinaryOperator<T>

BinaryOperator<T> specializes BiFunction<T,T,T> for combining two values of the same type into one value of that type. Static helpers select a minimum or maximum using a comparator.[12]

BinaryOperator<BigDecimal> add =
    BigDecimal::add;

BigDecimal total =
    amounts.stream()
        .reduce(
            BigDecimal.ZERO,
            add);

Maximum by comparator

BinaryOperator<Order> newer =
    BinaryOperator.maxBy(
        Comparator.comparing(
            Order::updatedAt));

Associativity

// Associative:
BinaryOperator<Integer> sum =
    Integer::sum;

// Not associative:
BinaryOperator<Integer> subtract =
    (left, right) ->
        left - right;

Binary operators used in parallel reductions must be associative and compatible with the identity value. Otherwise grouping changes can alter the result.

20. Two-argument functional interfaces

The Bi prefix denotes two input arguments: BiFunction, BiPredicate, and BiConsumer. BinaryOperator is the same-type specialization of BiFunction.[1]

BiFunction<BigDecimal,
           BigDecimal,
           BigDecimal> percentage =
    (amount, rate) ->
        amount.multiply(rate);

BiPredicate<User, Permission> allowed =
    authorization::isAllowed;

BiConsumer<String, Long> metric =
    metrics::record;

Map merge

totals.merge(
    customerId,
    order.total(),
    BigDecimal::add);

Map replacement

balances.replaceAll(
    (account, balance) ->
        balance.max(
            BigDecimal.ZERO));

21. Primitive specializations

The function package provides primitive-specialized shapes to avoid boxing, including IntPredicate, LongConsumer, DoubleSupplier, IntUnaryOperator, ToLongFunction<T>, ObjIntConsumer<T>, and many others.[1]

IntPredicate positive =
    value -> value > 0;

IntUnaryOperator square =
    value -> value * value;

ToLongFunction<FileMetadata> size =
    FileMetadata::size;

ObjIntConsumer<StringBuilder> appendCodePoint =
    StringBuilder::appendCodePoint;

Numeric stream

long totalBytes =
    files.stream()
        .mapToLong(
            FileMetadata::size)
        .sum();

Primitive specializations reduce wrapper allocation and unboxing overhead in numeric hot paths. Choose them when the domain is genuinely primitive rather than obscuring domain types for micro-optimization.

22. Method references

Method reference A method reference denotes a method or constructor without invoking it immediately. Evaluation produces an instance of the target functional interface; the referenced method runs later when the functional method is invoked.[13]

Function<String, Integer> length =
    String::length;

Consumer<String> printer =
    System.out::println;

Supplier<ArrayList<String>> factory =
    ArrayList::new;

Lambda equivalence

Function<String, Integer> first =
    value -> value.length();

Function<String, Integer> second =
    String::length;

Use a method reference when it makes the operation clearer. A lambda is preferable when it names parameters, reorders arguments, adds validation, or makes transformations explicit.

24. Overloads, type inference, and ambiguity

Ambiguous lambda

void process(
    Predicate<String> predicate) {
}

void process(
    Function<String, Boolean> function) {
}

// Potentially ambiguous:
process(value -> value.isEmpty());

Disambiguate with a target variable

Predicate<String> empty =
    String::isEmpty;

process(empty);

Disambiguate with a cast

process(
    (Predicate<String>)
        String::isEmpty);

API design guidance

Avoid overload sets whose only distinction is unrelated functional interfaces with the same apparent lambda shape. Descriptive method names often produce better diagnostics and more stable source compatibility.

25. Higher-order methods

A higher-order method accepts behavior, returns behavior, or both. Java represents that behavior with interface instances.

Decorator

static <T, R> Function<T, R>
timed(
        Function<T, R> function,
        BiConsumer<Duration, T> observer,
        Clock clock) {

    return input -> {
        Instant start =
            clock.instant();

        try {
            return function.apply(input);
        } finally {
            Duration elapsed =
                Duration.between(
                    start,
                    clock.instant());

            observer.accept(
                elapsed,
                input);
        }
    };
}

Validation wrapper

static <T, R> Function<T, R>
require(
        Predicate<? super T> rule,
        Supplier<? extends RuntimeException>
            failure,
        Function<? super T,
                 ? extends R> function) {

    return input -> {
        if (!rule.test(input)) {
            throw failure.get();
        }

        return function.apply(input);
    };
}

Higher-order helpers should preserve exception, thread-safety, and side-effect semantics in their contracts.

26. Partial application and currying patterns

Java does not provide special currying syntax, but methods can bind some arguments and return a function for the remaining inputs.

Bind tax rate

static UnaryOperator<BigDecimal>
taxAt(
        BigDecimal rate) {

    BigDecimal multiplier =
        BigDecimal.ONE.add(rate);

    return amount ->
        amount.multiply(
            multiplier);
}
UnaryOperator<BigDecimal> northCarolinaTax =
    taxAt(
        new BigDecimal("0.0475"));

Curried function

Function<BigDecimal,
    Function<BigDecimal,
        BigDecimal>> percentage =
            rate ->
                amount ->
                    amount.multiply(rate);

Function<BigDecimal, BigDecimal>
    tenPercent =
        percentage.apply(
            new BigDecimal("0.10"));

Excessively nested function types can hurt readability. Use domain-named interfaces or ordinary methods when the behavior represents a business concept.

27. Building composable transformation pipelines

record Registration(
    String username,
    String email) {
}

UnaryOperator<Registration> strip =
    registration ->
        new Registration(
            registration.username()
                .strip(),
            registration.email()
                .strip());

UnaryOperator<Registration> normalizeEmail =
    registration ->
        new Registration(
            registration.username(),
            registration.email()
                .toLowerCase(
                    Locale.ROOT));

UnaryOperator<Registration> normalize =
    strip.andThen(
        normalizeEmail);

Dynamic pipeline

static <T> UnaryOperator<T>
pipeline(
        List<UnaryOperator<T>> stages) {

    return stages.stream()
        .reduce(
            UnaryOperator.identity(),
            UnaryOperator::andThen);
}

Each stage should have a precise contract. Composition is most reliable when stages are deterministic, side-effect-free, and preserve domain invariants.

28. Pure functions and referential transparency

A pure function's result depends only on explicit inputs, and evaluating it does not produce externally observable effects. Java does not enforce purity, so it is a design discipline.

Pure calculation

static BigDecimal subtotal(
        List<LineItem> items) {

    return items.stream()
        .map(LineItem::total)
        .reduce(
            BigDecimal.ZERO,
            BigDecimal::add);
}

Impure calculation

static BigDecimal subtotal(
        List<LineItem> items) {

    LOGGER.log(
        System.Logger.Level.INFO,
        "calculating");

    BigDecimal rate =
        globalConfiguration
            .currentTaxRate();

    return calculate(
        items,
        rate);
}

Functional core, imperative shell

TaxConfiguration configuration =
    configurationRepository.load();

Order order =
    orderRepository.load(orderId);

Invoice invoice =
    InvoiceCalculator.calculate(
        order,
        configuration);

invoiceRepository.save(invoice);
eventPublisher.publish(
    InvoiceCreated.from(invoice));

The shell performs I/O; the core calculation receives explicit values and returns a value. This separation improves testability and replayability.

29. Immutability and value-oriented modeling

Immutable values can be freely shared when their reachable state is also immutable. Java records provide concise nominal data carriers, but record components can still reference mutable objects.

public record Cart(
        List<LineItem> items) {

    public Cart {
        items =
            List.copyOf(items);
    }

    public Cart add(
            LineItem item) {

        List<LineItem> next =
            new ArrayList<>(items);

        next.add(item);

        return new Cart(next);
    }
}

Immutable update function

UnaryOperator<Cart> addBook =
    cart ->
        cart.add(bookItem);

Copy at boundaries

List.copyOf, Set.copyOf, and Map.copyOf create unmodifiable snapshots, but they do not deep-copy mutable elements. Document ownership of nested objects.

30. Optional<T> as an explicit return model

Optional Optional<T> is a value-based container that either contains one non-null value or is empty. Its primary API purpose is a method return type where absence is expected and returning null would be error-prone.[14]

Optional<Customer> findCustomer(
        CustomerId id) {

    return Optional.ofNullable(
        database.findNullable(id));
}

Absence is not failure

SituationModel
Search found no matching valueOptional.empty()
Query failed because database is unavailableException or typed failure result
Many results, possibly noneEmpty collection/stream
Field is required by domainNon-null field validated at construction
Several alternative error reasonsDomain result/sealed hierarchy

Value-based semantics

Equal optional instances should be treated as interchangeable. Do not synchronize on an Optional or test empty instances with identity comparison.[14]

31. Creating optional values

Optional<String> empty =
    Optional.empty();

Optional<String> present =
    Optional.of(
        "value");

Optional<String> nullable =
    Optional.ofNullable(
        legacyValue);

of rejects null

Optional<String> value =
    Optional.of(null);
// NullPointerException.

Never return null instead of Optional

Optional<User> find(
        UserId id) {

    // Wrong:
    return null;
}

A variable whose declared type is Optional should itself never be null. Return Optional.empty() for legitimate absence.[14]

Convert nullable boundary once

Optional<String> normalized =
    Optional.ofNullable(
            request.header("X-Trace-ID"))
        .map(String::strip)
        .filter(
            Predicate.not(
                String::isEmpty));

32. map, flatMap, and filter

Map a present value

Optional<String> email =
    customer.map(
        Customer::email);

If map's mapper returns null, the result becomes empty because mapping is defined as though through ofNullable.[14]

Flatten an optional-returning method

Optional<Address> address =
    customer.flatMap(
        Customer::primaryAddress);
// Avoid nested Optional:
Optional<Optional<Address>> nested =
    customer.map(
        Customer::primaryAddress);

Retain only valid values

Optional<DiscountCode> activeCode =
    discountCode.filter(
        code ->
            code.expiresAt()
                .isAfter(now));

Composed lookup

Optional<URI> avatar =
    repository.findUser(userId)
        .filter(User::active)
        .flatMap(User::profile)
        .map(Profile::avatarUri);

33. Fallbacks, lazy defaults, and exceptions

orElse evaluates eagerly

Customer customer =
    cached.orElse(
        repository.loadDefault());

The argument to orElse is evaluated before the method call, even when the optional is present.

orElseGet is lazy

Customer customer =
    cached.orElseGet(
        repository::loadDefault);

Alternative optional source

Optional<Configuration> configuration =
    memoryCache.find(key)
        .or(() ->
            diskCache.find(key))
        .or(() ->
            remoteStore.find(key));

Throw for required result

User user =
    repository.findUser(id)
        .orElseThrow(
            () ->
                new UserNotFoundException(
                    id));

Consume either branch

user.ifPresentOrElse(
    this::render,
    this::renderNotFound);

Fallback suppliers and exception suppliers are invoked only for an empty optional.[14]

34. Optional.stream() and stream integration

Optional.stream() returns a sequential stream containing the value when present and an empty stream otherwise. It is useful for flattening a stream of optionals.[14]

List<User> users =
    ids.stream()
        .map(
            repository::findUser)
        .flatMap(
            Optional::stream)
        .toList();

Optional from stream search

Optional<Product> product =
    products.stream()
        .filter(
            candidate ->
                candidate.sku()
                    .equals(sku))
        .findFirst();

Stream search operations return Optional because an empty stream or no match has no element. Stream functions should remain non-interfering and usually stateless.[15]

Single optional versus stream

Use Optional<T> for zero-or-one values and Stream<T> for potentially many values or deferred traversal. Do not return a stream merely to represent one optional value unless it participates directly in a pipeline.

35. Optional anti-patterns

Calling get() after a manual check

if (customer.isPresent()) {
    return customer.get()
        .email();
}

return defaultEmail;

Transform instead

return customer
    .map(Customer::email)
    .orElse(defaultEmail);

Optional field

record Customer(
    CustomerId id,
    Optional<String> nickname) {
}

Although legal, optional fields complicate construction, serialization frameworks, ORM mapping, and invariants. A nullable private field with a non-null-returning accessor, a dedicated domain type, or alternative record shapes can be clearer. Evaluate the domain rather than applying an absolute prohibition.

Optional collection

// Avoid:
Optional<List<Order>> orders();

// Usually:
List<Order> orders();

An empty collection already represents no elements. Reserve an optional collection for a distinct semantic such as “not loaded” versus “loaded and empty,” and name that state explicitly when possible.

Optional parameter

void send(
    Message message,
    Optional<Address> override) {
}

Callers are often clearer with overloads, a request object, or nullable boundary conversion. Optional is primarily intended as a return type.[14]

36. Complete validation-composition example

Validation result

public sealed interface Validation<T> {
    record Valid<T>(
        T value)
        implements Validation<T> {
    }

    record Invalid<T>(
        List<String> errors)
        implements Validation<T> {

        public Invalid {
            errors =
                List.copyOf(errors);
        }
    }
}

Named rule

public record Rule<T>(
        Predicate<? super T> predicate,
        Function<? super T, String>
            message) {

    public Rule {
        Objects.requireNonNull(
            predicate);

        Objects.requireNonNull(
            message);
    }

    Optional<String> evaluate(
            T value) {

        return predicate.test(value)
            ? Optional.empty()
            : Optional.of(
                message.apply(value));
    }
}

Validator factory

static <T> Function<T, Validation<T>>
validator(
        List<Rule<T>> rules) {

    List<Rule<T>> immutable =
        List.copyOf(rules);

    return value -> {
        List<String> errors =
            immutable.stream()
                .map(rule ->
                    rule.evaluate(value))
                .flatMap(
                    Optional::stream)
                .toList();

        return errors.isEmpty()
            ? new Validation.Valid<>(
                value)
            : new Validation.Invalid<>(
                errors);
    };
}

Usage

record Registration(
    String username,
    String email,
    int age) {
}

Function<Registration,
    Validation<Registration>> validate =
        validator(
            List.of(
                new Rule<>(
                    value ->
                        !value.username()
                            .isBlank(),
                    value ->
                        "Username is required"),
                new Rule<>(
                    value ->
                        value.email()
                            .contains("@"),
                    value ->
                        "Email is invalid"),
                new Rule<>(
                    value ->
                        value.age() >= 18,
                    value ->
                        "User must be an adult")));

This design treats rules as values, accumulates all errors, preserves immutable results, and separates validation from I/O.

37. Functional strategy and policy injection

Object-oriented strategy

interface ShippingPolicy {
    Money cost(
        Shipment shipment);
}

Functional strategy

Function<Shipment, Money> shipping =
    shipment ->
        shipment.weight()
            .multiply(
                ratePerUnit);

Named policy factory

static Function<Shipment, Money>
weightBasedShipping(
        Money ratePerUnit,
        Money minimum) {

    return shipment ->
        ratePerUnit
            .multiply(
                shipment.weight())
            .max(minimum);
}

Policy registry

Map<ShippingMethod,
    Function<Shipment, Money>> policies =
        Map.of(
            ShippingMethod.STANDARD,
            weightBasedShipping(
                standardRate,
                standardMinimum),
            ShippingMethod.EXPRESS,
            weightBasedShipping(
                expressRate,
                expressMinimum));

Money cost =
    Optional.ofNullable(
            policies.get(method))
        .orElseThrow(

Use a lambda for small behavior with a clear standard shape. Use a domain interface when policy identity, documentation, multiple operations, lifecycle, or checked exceptions justify it.

38. Complete example: composable pricing engine

Domain values

public record Money(
        BigDecimal amount,
        Currency currency) {

    public Money {
        Objects.requireNonNull(amount);
        Objects.requireNonNull(currency);

        amount =
            amount.setScale(
                currency
                    .getDefaultFractionDigits(),
                RoundingMode.HALF_EVEN);
    }

    Money add(Money other) {
        requireSameCurrency(other);

        return new Money(
            amount.add(
                other.amount),
            currency);
    }

    Money multiply(
            BigDecimal multiplier) {

        return new Money(
            amount.multiply(multiplier),
            currency);
    }

    Money max(Money other) {
        requireSameCurrency(other);

        return amount.compareTo(
                    other.amount) >= 0
            ? this
            : other;
    }

    private void requireSameCurrency(
            Money other) {

        if (!currency.equals(
                other.currency)) {
            throw new IllegalArgumentException(
                "Currency mismatch");
        }
    }
}

Price context and adjustment

record PriceContext(
    Product product,
    Customer customer,
    Instant quotedAt) {
}

@FunctionalInterface
interface PriceAdjustment
        extends UnaryOperator<Money> {

    default PriceAdjustment
    followedBy(
            PriceAdjustment next) {

        Objects.requireNonNull(next);

        return price ->
            next.apply(
                apply(price));
    }

    static PriceAdjustment identity() {
        return price -> price;
    }
}

Factories

static PriceAdjustment percentageOff(
        BigDecimal rate) {

    BigDecimal multiplier =
        BigDecimal.ONE.subtract(rate);

    return price ->
        price.multiply(multiplier);
}

static PriceAdjustment tax(
        BigDecimal rate) {

    BigDecimal multiplier =
        BigDecimal.ONE.add(rate);

    return price ->
        price.multiply(multiplier);
}

static PriceAdjustment minimumPrice(
        Money minimum) {

    return price ->
        price.max(minimum);
}

Optional policy selection

static Optional<PriceAdjustment>
loyaltyAdjustment(
        Customer customer) {

    return customer.loyaltyTier()
        .filter(tier ->
            tier != LoyaltyTier.NONE)
        .map(tier ->
            switch (tier) {
                case SILVER ->
                    percentageOff(
                        new BigDecimal("0.05"));
                case GOLD ->
                    percentageOff(
                        new BigDecimal("0.10"));
                case PLATINUM ->
                    percentageOff(
                        new BigDecimal("0.15"));
                case NONE ->
                    PriceAdjustment.identity();
            });
}

Engine

static Money quote(
        PriceContext context,
        Function<Product, Money> basePrice,
        Function<PriceContext,
                 List<PriceAdjustment>>
            rules) {

    Money base =
        basePrice.apply(
            context.product());

    List<PriceAdjustment> adjustments =
        new ArrayList<>(
            rules.apply(context));

    loyaltyAdjustment(
        context.customer())
        .ifPresent(
            adjustments::add);

    PriceAdjustment pipeline =
        adjustments.stream()
            .reduce(
                PriceAdjustment.identity(),
                PriceAdjustment::followedBy);

    return pipeline.apply(base);
}

Configuration

Function<Product, Money> basePrice =
    Product::listPrice;

Function<PriceContext,
    List<PriceAdjustment>> rules =
        context ->
            List.of(
                minimumPrice(
                    context.product()
                        .minimumPrice()),
                tax(
                    taxTable.rateFor(
                        context.customer()
                            .address(),
                        context.quotedAt())));

Money quoted =
    quote(
        new PriceContext(
            product,
            customer,
            clock.instant()),
        basePrice,
        rules);

Why this is functional

  • Pricing stages are values with explicit input/output types.
  • Composition order is explicit.
  • The engine receives time and tax data rather than reading globals.
  • Optional loyalty behavior is modeled as zero or one adjustment.
  • Money is immutable and validates currency arithmetic.
  • I/O remains outside the pricing calculation.

39. Testing functional code

Example-based test

@Test
void percentageDiscountIsApplied() {
    PriceAdjustment discount =
        percentageOff(
            new BigDecimal("0.10"));

    Money result =
        discount.apply(
            usd("100.00"));

    assertEquals(
        usd("90.00"),
        result);
}

Composition-law test

@Test
void followedByMatchesManualApplication() {
    PriceAdjustment first =
        percentageOff(
            new BigDecimal("0.10"));

    PriceAdjustment second =
        tax(
            new BigDecimal("0.05"));

    Money price =
        usd("100.00");

    assertEquals(
        second.apply(
            first.apply(price)),
        first.followedBy(second)
            .apply(price));
}

Predicate truth table

@ParameterizedTest
@CsvSource({
    "true,true,true",
    "true,false,false",
    "false,true,false",
    "false,false,false"
})
void andComposition(
        boolean left,
        boolean right,
        boolean expected) {

    Predicate<Boolean> first =
        ignored -> left;

    Predicate<Boolean> second =
        ignored -> right;

    assertEquals(
        expected,
        first.and(second)
            .test(true));
}

Optional branches

  • Present and empty paths.
  • Mapper returns a value and mapper returns null.
  • Lazy fallback is not invoked when present.
  • Fallback and exception supplier run when empty.
  • Filtering retains and removes values.

Property-oriented checks

  • Identity operator leaves every generated value unchanged.
  • Normalization is idempotent: applying it twice equals once.
  • Predicate negation reverses every result.
  • Associative binary operators produce equal grouping results.
  • Immutable operations do not mutate their inputs.

40. Runtime and performance considerations

Lambdas and method references are language-level expressions whose runtime representation is deliberately not specified as a source-visible anonymous-class identity. Code must not depend on lambda object class names, identity, serialization, or allocation behavior.[3]

Avoid identity assumptions

Supplier<String> first =
    () -> "value";

Supplier<String> second =
    () -> "value";

// No semantic guarantee:
boolean same =
    first == second;

Captured versus non-captured lambdas

Supplier<String> constant =
    () -> "value";

String prefix =
    configuration.prefix();

Function<String, String> captured =
    value ->
        prefix + value;

Exact allocation, caching, and invocation optimization are implementation details. Keep functional objects out of extremely hot allocation paths only after profiling.

Primitive interfaces

Use primitive specializations to avoid boxing in high-volume numeric code. For domain-rich values, clearer types usually matter more than eliminating a wrapper.

Composition depth

Very deep chains can complicate stack traces and debugging. Name significant stages, collapse trivial layers, and retain ordinary methods for complex logic.

Benchmark correctly

JVM warmup, inlining, escape analysis, dead-code elimination, and constant folding make ad hoc timing unreliable. Use JMH for microbenchmarks and representative end-to-end tests for application decisions.[16]

41. Production functional-programming checklist

Lambdas and interfaces

  • The target functional-interface type is clear.
  • Public custom interfaces use @FunctionalInterface.
  • Standard interfaces are used when their semantics and exception contract fit.
  • Domain interfaces are used when behavior deserves a name.
  • Overloads do not create ambiguous lambda targets.

Composition

  • Predicate short-circuiting does not hide required effects.
  • Function composition order is documented.
  • Binary reductions are associative and use a valid identity.
  • Higher-order decorators preserve exceptions and thread-safety contracts.
  • Deep function types are replaced by domain names when readability suffers.

State and effects

  • Captured mutable state is avoided.
  • Core transformations receive explicit dependencies.
  • I/O, logging, time, randomness, and persistence are effect boundaries.
  • Immutable values defensively copy mutable inputs.
  • Consumers are used deliberately for effects rather than as hidden mutation channels.

Optional

  • Optional represents legitimate zero-or-one results, not failures.
  • Optional-returning methods never return null.
  • map and flatMap are selected correctly.
  • orElseGet is used for expensive lazy fallback.
  • get() is not used without a proven presence invariant.
  • Empty collections represent zero elements unless another state is genuinely needed.
  • Optional fields and parameters are justified by domain semantics.

Testing and performance

  • Functions are tested directly with deterministic inputs.
  • Composition and algebraic properties are tested.
  • Present, absent, exception, and fallback branches are covered.
  • Primitive specialization is used where profiling shows boxing cost.
  • Performance claims use JMH or representative load tests.
  • Loops and ordinary methods remain available when clearer.
Final principle: functional Java makes behavior explicit and composable while keeping effects controlled. Lambdas are the notation, functional interfaces are the type system, immutable values are the data model, and disciplined boundaries are what produce reliable software.
