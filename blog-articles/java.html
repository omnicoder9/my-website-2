Java, and the long argument for not breaking things

Designed for set-top boxes nobody bought, saved by a browser that no longer exists, and now the substrate of most of the software that moves money and freight. A technical account of where Java came from, how it changes, what it costs, and what it still wins.

Published 26 July 2026 Current release: Java 26 · current LTS: Java 25 75 references, Vancouver style 11 figures

Java is the most successful boring language ever written, and it got that way by accident. It was designed for cable set-top boxes that nobody bought, rescued by a browser that no longer exists, and then spent three decades becoming the substrate of banking, telecommunications, retail logistics, and most of the software that quietly moves money and freight around the planet. In July 2026 it sits fourth on the TIOBE index and seventh among languages developers actually used last year, which are both true and neither of which explains why a bytecode format frozen in 1996 still executes correctly on hardware that did not exist when it was written.41,43

This article covers where Java came from, how it changes, what its designers believed, what it is genuinely good at, where it genuinely hurts, who uses it now, and what it plugs into. The interesting question is not whether Java is fashionable. It is what a language buys when it spends thirty years refusing to break its users.

01Origins: the wrong market, the right machine

The Green project started at Sun Microsystems in December 1990. Patrick Naughton, Mike Sheridan, and James Gosling were given money and time to work out what the next wave of computing would be, and they concluded it would be the convergence of digitally controlled consumer devices and computers. They were, characteristically, right about the destination and about fifteen years early.1

The team was explicit that it was not a research group. Everyone came from product organisations, and the goal was a shippable thing.1 What they shipped first, in 1992, was *7 — a handheld remote control with an animated touchscreen interface, driven by a new language Gosling had written. He called it Oak, after a tree outside his window. The consumer electronics industry declined to be revolutionised. The team spent 1993 and much of 1994 pitching interactive television and losing bids.3,4

What saved the language was the property it had been given for an entirely different reason. Set-top boxes came from a dozen manufacturers with a dozen chips, so Oak compiled not to machine code but to a compact intermediate bytecode executed by a small virtual machine. That made the code portable across chips nobody had standardised. In 1994 it made the code portable across something else: the internet. The team built a browser to prove the point, the language was renamed Java after Oak turned out to be taken, and Sun announced it in 1995 with Netscape's endorsement.3,4,5

The lucky accident

Java's defining technical decision — compile once to a portable intermediate form, execute everywhere on a virtual machine — was made to solve a hardware fragmentation problem in consumer electronics. It happened to be exactly the property a network of heterogeneous, untrusted machines required. Almost every subsequent advantage the platform has, including the just-in-time compiler, the garbage collectors, the observability stack, and the fact that Kotlin and Scala exist at all, descends from that one choice.

The applet era that followed was brief, loud, and ultimately a dead end; the browser plugin was a security liability and was eventually removed entirely. But it did the job of distribution. By the time applets died, Java had colonised the place it would actually live: the server. Sun open-sourced the implementation as OpenJDK in 2006 and 2007, Oracle acquired Sun in 2010, and the platform's centre of gravity shifted from a single vendor's product to a jointly maintained codebase with many distributors.5,44

02How Java changes

For twenty years Java changed the way tectonic plates do: rarely, and with consequences. Java 5 (2004) added generics, annotations, enums, and the enhanced for loop. Java 8 (2014) added lambdas, the streams API, and default methods, which was the largest single language change in the platform's history and remains, more than a decade later, the version a substantial installed base is still running. Java 9 (2017) delivered the module system, a genuinely ambitious re-architecture of the platform that split rt.jar into named modules with explicit dependencies.6

Java 9 also delivered the more consequential change: the release model itself. Since September 2017 a feature release ships every six months, on schedule, with whatever is finished. Features that are not finished simply miss the train and catch the next one. Every second year a release is designated long-term support and receives years of updates.24,44 Java 26, released on 17 March 2026, was the seventeenth consecutive on-time feature release.31

This is the single most underrated thing about modern Java. A time-boxed train schedule converts a political question — is this feature important enough to delay the release? — into an engineering one, and it lets the language ship preview features that are real, compiled, and shipped in the JDK but disabled by default, so they can be revised or withdrawn based on use. Pattern matching for switch went through several previews before finalisation in Java 21.11 Structured concurrency reached its sixth preview in Java 26 and has still not been finalised, which is not a failure of the process but the process working exactly as intended.22,64

The LTS releases that matter

Java 8 (2014, LTS). Lambdas, streams, the new date and time API, Optional. The version that made functional idioms mainstream in enterprise Java, and the version an astonishing amount of production code never left.

Java 11 (2018, LTS). The first LTS after the cadence change. HTTP client, var in lambda parameters, single-file source execution.7 Also the release whose licensing terms triggered a mass migration away from Oracle's own binaries.44

Java 17 (2021, LTS). Sealed classes, records finalised the release before, switch expressions, a restored open licence for Oracle's build. This became the practical baseline for the modern ecosystem: Spring Boot 3 and Jakarta EE 10 both require it.8,9

Java 21 (2023, LTS). Virtual threads, record patterns, pattern matching for switch, generational ZGC. The most significant runtime change since Java 8, and adopted materially faster than its predecessors: in the six months after release, 1.4% of monitored applications were on Java 21, against 0.37% for Java 17 at the same point.12,10,11,15,46

Java 25 (2025, LTS). Scoped values, compact source files and instance main methods, flexible constructor bodies, compact object headers, generational Shenandoah, ahead-of-time method profiling. Eighteen JEPs, and a deliberate effort to lower the on-ramp: hello world is now three lines with no class declaration.18,19,20,21,35,37,38,39 Oracle has stated it intends to support Java 25 for at least eight years.40

Java 26 (2026, non-LTS). Ten JEPs: a garbage-collector-agnostic ahead-of-time cache, HTTP/3 support, warnings for mutation of final fields, hybrid public key encryption, post-quantum-ready JAR signing, and further previews of structured concurrency and primitive patterns.24,31,33,34,36 Java 27 arrives in September 2026; the targeted work includes post-quantum hybrid key exchange for TLS 1.3, and Project Valhalla's value classes are a live candidate.34

The projects behind the releases

Amber

Small, productivity-oriented language features: records, sealed types, pattern matching, text blocks, compact source files. The most visible source of change in day-to-day code.29

Loom

Virtual threads, structured concurrency, scoped values. Rewrote the economics of blocking I/O without changing the programming model.30,12,21

Valhalla

Value classes and objects: immutable, identity-free types that let the JVM flatten data into memory instead of chasing pointers. The longest-running and most technically ambitious of the four.25,23

Panama, Leyden, Babylon

Panama replaced JNI with a safe foreign function and memory API.13,27 Leyden attacks startup and warmup through ahead-of-time caching.26 Babylon extends reflection over code itself, aimed at GPU and machine-learning back ends.28

03The philosophy, and the taste

The 1995 white paper is unusually candid about what the designers were optimising for. Simplicity is named as an overriding goal, achieved specifically by removing features of dubious worth from Java's C and C++ ancestry rather than by inventing new abstractions. A second goal was familiarity: the language should look like C++ so that a working programmer could learn it in roughly a couple of weeks.2 The canonical summary of the design goals — simple, object-oriented and familiar; robust and secure; architecture-neutral and portable; high-performance; interpreted, threaded and dynamic — reads today less like a manifesto than a risk register.2

Three commitments follow from that, and they explain most of what people either love or resent about the language.

Compatibility as a covenant

Java's governing constraint is that old code keeps working. A class file compiled in 1998 will, in the overwhelming majority of cases, still load and run on a 2026 JVM. This is not a technical curiosity; it is the entire commercial proposition. It is why banks wrote core systems in Java and why those systems are still there. It is also the reason the language accumulates weight: every mistake is permanent, so features arrive slowly and hedged, and removals — the applet API, the security manager, the 32-bit x86 port — take decades and generate release notes of their own.33,37

The runtime is the product

Java the language is genuinely conservative. Java the runtime is not. Most of the platform's real innovation over thirty years has happened below the source code: adaptive just-in-time compilation, four production garbage collectors with different pause characteristics, a flight recorder that profiles production systems at negligible cost, and now a threading model that makes a million concurrent blocking operations unremarkable.12,14,15,16,17 Developers get large performance changes without editing anything, which is a very deliberate distribution of effort.

Explicit over clever

Java prefers the reader to the writer. Types are written down. Control flow is visible. There is no operator overloading, no implicit conversion machinery, no macro system, and until recently no type inference beyond the trivial. The result is code that is verbose to write and unusually easy to read cold, six years later, when the author has left the company. This is a real engineering position, and it is the reason Java survives in organisations where code outlives teams.

On the aesthetics

It is worth saying plainly that Java has a look, and that many programmers dislike it. The deep package hierarchies, the AbstractSingletonProxyFactoryBean naming tradition, the ceremonial getters and setters, the four-line try-with-resources where a scripting language would use one — this is a genuine aesthetic, not merely an absence of one. It descends from a specific belief: that a program is read far more often than it is written, and mostly by strangers. Whether that trade is beautiful or merely tedious depends almost entirely on whether you have ever inherited a two-hundred-thousand-line codebase from people you cannot ask questions of. Modern Java has softened the edges — records collapse a forty-line data class to one line, var removes redundant type ceremony, pattern matching removes cast-and-check boilerplate — without abandoning the underlying position.7,8,11

What thirty years of accumulation looks like

The following is idiomatic modern Java. Every construct in it postdates Java 14, and the same logic in Java 8 would run to roughly four times the length.

sealed interface Shape permits Circle, Rect, Tri {}

record Circle(double r)            implements Shape {}
record Rect(double w, double h)    implements Shape {}
record Tri(double b, double h)     implements Shape {}

static String describe(Shape s) {
    return switch (s) {
        case Circle c when c.r() > 100 -> "huge circle";
        case Circle c                   -> "circle of radius " + c.r();
        case Rect(double w, double h)
                    when w == h         -> "square, side " + w;
        case Rect r                     -> "rectangle " + r.w() + "x" + r.h();
        case Tri t                      -> "triangle, base " + t.b();
    };
}

Three things are happening. sealed tells the compiler the complete set of subtypes, so the switch needs no default arm and will fail to compile if a fourth shape is added.9 record generates the constructor, accessors, equals, hashCode and toString.8 Record patterns destructure the components directly in the case label.10,11 The result is closer to an ML dialect than to Java 6, and it is fully compatible with Java 6 bytecode semantics.

04The machine underneath

Understanding Java's performance profile requires understanding that Java is compiled twice. javac performs a mostly syntactic translation to bytecode, doing almost no optimisation. The interesting compilation happens at runtime, in the JVM, after the code has been observed executing.

Because the optimising compiler runs with live profile data, it can do things a static compiler cannot: inline through virtual calls that turn out to have exactly one implementation in practice, eliminate branches that never execute, escape-analyse objects into registers, and de-optimise back to the interpreter when an assumption is invalidated by a class loaded later. On long-running server workloads this routinely produces machine code competitive with C++, which is why the JVM ended up under Hadoop, Kafka, Elasticsearch, and Cassandra rather than a nominally faster language.72,73

The cost is warmup. A freshly started JVM interprets, then compiles, then recompiles; the first thousand requests are slow. For a process that runs for weeks this is invisible. For a serverless function invoked for eighty milliseconds, it is the whole story — which is precisely the pressure that produced Project Leyden's ahead-of-time caching and the GraalVM native image path.26,67

Memory management

Java ships several production garbage collectors with genuinely different trade-offs, selectable by flag. G1 has been the default since Java 9 and targets a balance of throughput and predictable pauses on large heaps.14 ZGC and Shenandoah are concurrent collectors designed to keep pause times flat as heaps grow into the hundreds of gigabytes; both became generational (ZGC in Java 21, Shenandoah in Java 25) which substantially improved their throughput.15,16,17,35 Serial and Parallel remain the right answer for small containers and batch jobs respectively.

05What Java is good at

Throughput under sustained load

The profile-guided JIT, mature collectors, and thirty years of tuning make the JVM one of the best available platforms for long-running, high-throughput, memory-heavy services. This is not a marketing claim so much as an observation about what the infrastructure layer of the internet is actually written in: Hadoop's storage and scheduling layers, Kafka, Elasticsearch, Cassandra, Solr, Flink, and Spark's JVM core all run here.72,73

Concurrency that stopped being expensive

Until Java 21, a Java thread was an operating system thread, reserving on the order of a megabyte of stack whether or not it used it. Thread pools existed to ration that scarcity, and the industry's answer to high-concurrency I/O was reactive programming: callback chains and operator pipelines that scale well and are miserable to debug because the stack trace no longer corresponds to the logical operation.

Virtual threads dissolved the trade. A virtual thread is a java.lang.Thread whose stack lives on the heap and grows on demand; when it blocks, it unmounts from its carrier and releases it to other work. Millions can exist where thousands of platform threads could.12,63 Crucially it is the same API, so existing debuggers, profilers, and libraries keep working — a deliberate design choice that distinguishes it from coroutine systems requiring a parallel ecosystem.65

// Ten thousand concurrent blocking calls. No pool, no tuning.
try (var scope = Executors.newVirtualThreadPerTaskExecutor()) {
    for (var url : urls) {
        scope.submit(() -> httpClient.send(request(url), ofString()));
    }
}   // close() waits for every task to finish

The companion feature, structured concurrency, treats a group of related subtasks as one unit with a defined lifetime, so a failure cancels siblings and the parent cannot outlive its children. It has been in preview since Java 19 and reached its sixth iteration in Java 26; the JDK 25 revision introduced a compositional Joiner that separates completion policy from result production.22,64

Tooling and observability

This is Java's quietest advantage and often its decisive one. JDK Flight Recorder profiles production JVMs continuously at low overhead and is built into the runtime rather than bolted on. Heap dumps, thread dumps, JMX metrics, and a mature bytecode-instrumentation story mean commercial APM vendors can attach to an unmodified application. IntelliJ IDEA — used by 27% of all respondents to the 2025 Stack Overflow survey and 28% of professionals — offers refactoring and static analysis that is only possible because the type system makes the program's shape statically knowable.43 JDK 25 added JFR cooperative sampling and method timing and tracing; JDK 26 continued that work.35,38

A library ecosystem that has already solved your problem

Maven Central is the largest repository of open-source Java components, with strict publication requirements — domain-verified group identifiers, mandatory cryptographic signatures, and metadata validation — that have kept it noticeably freer of the typosquatting and malicious-package incidents that have plagued other registries.70,71 Its consumption is enormous: Maven Central downloads grew 19.4% year over year in 2025, part of 9.8 trillion downloads across the four major public registries.69

Backward compatibility as an economic asset

The reason a bank runs Java is not that Java is elegant. It is that a system written in 2009 can be moved to a 2026 runtime, gain a decade of garbage collector and JIT improvements, and pass its regression suite. Very few platforms offer that, and the ones that do tend to be much older and much worse to write.

06Where it hurts

An honest account has to be specific. Java's weaknesses are not the ones the internet usually names.

Startup and footprint

A JVM has to load and verify classes, initialise a heap, and warm up the JIT before it is fast. For microservices scaled to zero, CLI tools, and serverless functions, this is a real disqualifier — which is why the native-image and AOT-cache work exists at all.26,67,68

The null reference

Java has no null safety in the type system. The NullPointerException remains the archetypal Java failure. Helpful NPE messages (Java 14) tell you which reference was null; they do not stop it being null. Kotlin's chief selling point on Android is precisely this gap, and Google reports Kotlin-containing apps crash 20% less often.56

Erased generics and boxed primitives

Generic type arguments are erased at runtime, so List<String> and List<Integer> are the same class. Worse for performance, a collection of numbers is a collection of pointers to heap objects. Project Valhalla's value classes are the fifteen-year attempt to fix this without breaking anything.23,25

Verbosity, still

Records, var, text blocks, and compact source files have removed a great deal of ceremony, but Java remains wordier than its peers and its standard library carries three decades of API strata with inconsistent conventions.18,19

Licensing complexity

OpenJDK is GPL-licensed and free. Oracle's build of it is not always. In January 2023 Oracle replaced per-user and per-processor Java SE subscriptions with a Universal Subscription priced per employee — counting every employee and contractor, whether or not they use Java.52,54,55 Reported cost increases ranged from three-fold to thirty-fold, and the practical consequence was accelerated migration to Eclipse Temurin, Amazon Corretto, Azul, and Microsoft builds.53,44

Dependency-chain blast radius

Ubiquity is a security property. Log4Shell (CVE-2021-44228), disclosed in December 2021, scored the maximum 10.0 on CVSS and allowed unauthenticated remote code execution through a logging call in a library embedded almost everywhere.59,61,62 CISA, the FBI, NSA and five partner agencies issued joint guidance, and a US emergency directive followed.59,60 Nothing about the flaw was intrinsic to Java, but the scale of the response was a direct function of how much of the world's software the JVM runs.

The deeper structural problem

Java's compatibility guarantee is also its ceiling. Null cannot simply be removed. Erasure cannot simply be undone. The primitive/object divide cannot be closed by fiat. Every fix must be expressible as a strict addition that leaves twenty-five years of bytecode valid, which is why Valhalla has been in development since 2014 and why value classes are still, in mid-2026, a preview candidate.23,25,34 Languages without installed bases fix these problems in a release. Java trades speed of correction for the guarantee that your correction never breaks anyone. Reasonable engineers disagree about whether that trade is worth it, and the disagreement is usually a proxy for how much legacy code they are responsible for.

07Popularity, measured carefully

Every popularity index measures something different, and Java's ranking moves depending on which. Taken together the picture is clear: Java is no longer the default choice for new work in most segments, and it is nevertheless enormous.

That gap between use and affection is the most informative number in the set. Java is used far more than it is loved, which is the characteristic signature of a language people encounter through employment rather than choice. It is also worth noting what the same survey says about Java's neighbours: Spring Boot was used by 14.7% of all respondents and 15.6% of professionals, making it the largest server-side framework outside the JavaScript ecosystem; Maven and Gradle were each used by 16.4% and 14.4% respectively.43

Version adoption tells a different story than language ranking. Java 17 overtook Java 11 as the most-used LTS release in 2024, reaching about 35% of monitored applications after growing nearly 300% year over year, and Java 21 was adopted 287% faster in its first six months than Java 17 was in its.44,46,47 More recent industry compilations put Java 17 at 61% and Java 21 at 45% of surveyed developers.74 The tail is long — Java 8 was still at 33% of monitored applications in 2023 — but the distribution is moving faster than it used to.45

08Notable products and open-source projects

Infrastructure written in Java

The most consequential Java code in the world is not application code; it is the data plane other people's applications run on.

  • Apache Hadoop — the origin of the modern big-data stack, written almost entirely in Java; HDFS and YARN are Java components.72
  • Apache Kafka — the de facto event-streaming backbone for large organisations, running on the JVM.72
  • Elasticsearch, OpenSearch, Apache Solr, Apache Lucene — the search layer of an enormous fraction of the web, all Java, all descending from Doug Cutting's Lucene.
  • Apache Cassandra — the wide-column store built for linear scalability and fault tolerance on commodity hardware.73
  • Apache Spark and Apache Flink — distributed processing engines whose cores run on the JVM even when the user-facing API is Python or SQL.
  • Apache Tomcat, Jetty, Netty — the servers and the asynchronous network layer beneath most JVM web traffic.
  • Jenkins, SonarQube, Keycloak, Neo4j, H2 — CI, code quality, identity, and graph and embedded databases.
  • Eclipse, IntelliJ IDEA platform, Android Studio — the IDEs themselves, including the ones used to write other languages.43

Products end users touch

Android. The largest deployment of Java-language code by headcount. Android does not use Oracle's Java SE implementation, and the reimplementation of the Java API in Android was the subject of a decade of litigation that ended in April 2021 when the US Supreme Court held 6–2 that Google's copying of the Java SE API's declaring code was fair use as a matter of law.48,50,75 The Court declined to decide whether the declaring code was copyrightable at all, resting the holding entirely on fair use, and the practical effect was to give legal cover to the common practice of reimplementing software interfaces.48,49,51

Minecraft: Java Edition. Probably the most widely installed desktop Java application ever written, and an unusually large modding ecosystem built directly on the JVM's class-loading flexibility.

Enterprise systems. Core banking, payments, insurance claims, airline reservation, telecommunications billing, warehouse management, and point-of-sale software across most large organisations. This category is invisible, unglamorous, and by volume it is what Java is.

10Notable frameworks

Spring and Spring Boot

Spring began as a reaction against the weight of early Enterprise JavaBeans and became, by a wide margin, the dominant way server-side Java is written. Spring Boot's contribution was opinionated auto-configuration and an embedded server, collapsing a day of XML into a single runnable jar. It was used by 14.7% of all 2025 Stack Overflow respondents and 15.6% of professionals — the most-used non-JavaScript web framework in the survey.43 Spring Framework 6 added ahead-of-time processing and GraalVM native image support.66

Quarkus

Red Hat's framework, built for Kubernetes and native compilation from the start. Its central idea is moving work from runtime to build time — dependency graphs resolved, configuration processed, and reflection metadata computed during compilation — which is why its native images start in roughly fifty milliseconds and use a fraction of Spring Boot Native's resident memory.66,67 Oracle announced in March 2026 that it intends to align Helidon's release cadence with Java's and propose it as an OpenJDK project.31,32

Micronaut

From the team behind Grails, and built on compile-time dependency injection. By resolving injection and aspect weaving during compilation rather than with runtime reflection, it produces small binaries that are unusually well suited to native image, with startup comparable to Quarkus.66

Jakarta EE

The standards track, transferred from Oracle to the Eclipse Foundation and renamed from Java EE — the origin of the javax.* to jakarta.* package migration that forced a generation of libraries to re-release. It remains the specification layer beneath servlets, persistence, validation, REST, and CDI, and vendors including Red Hat, IBM, Payara and Eclipse ship certified implementations.

The rest of the field

  • Helidon — Oracle's microservices framework, now with commercial support in the Java Verified Portfolio.31,32
  • Vert.x — a polyglot reactive toolkit on Netty, for teams that want event-loop control.
  • Dropwizard — a deliberately small assembly of Jetty, Jersey and Jackson.
  • Apache Camel — enterprise integration patterns as a routing DSL; unglamorous and everywhere in integration estates.
  • Android Jetpack and Compose — Android's modern application framework, now Kotlin-first, though the Java-language APIs remain fully supported.56,58
  • JavaFX — the desktop UI toolkit, developed as OpenJFX; Oracle extended support for JavaFX on JDK 8 to March 2028 and added commercial support in 2026.31

11Integrations and adjacent technology

Other languages on the same machine

The JVM is a general-purpose runtime, and several serious languages target it: Kotlin (statically typed, null-safe, fully interoperable both ways), Scala (functional and type-theoretic), Clojure (a Lisp with immutable data structures), and Groovy (dynamic, and the language of Gradle build scripts). Kotlin's rise on Android is the clearest case of the JVM outliving Java as the primary language on a platform: Google made Android development Kotlin-first at I/O 2019, and JetBrains reports that over half of professional Android developers now use Kotlin as their main language against about 30% for Java.56,57,58 Java-language support on Android remains complete.56

Native code and hardware

The foreign function and memory API, finalised in Java 22, replaced JNI with a safe, statically typed way to call C libraries and manage off-heap memory without writing native glue code.13,27 This matters for cryptography, GPU access, and the numerical libraries that machine learning depends on. Project Babylon extends this direction by making Java code itself reflectable in a form suitable for translation to GPU kernels and autodiff.28

Containers, orchestration and the cloud

The JVM is container-aware: it reads cgroup limits and sizes the heap against the container's memory allocation rather than the host's. Every major cloud vendor ships and supports its own OpenJDK build — Amazon Corretto, Microsoft Build of OpenJDK, Oracle's own, plus Eclipse Temurin and Azul — which is precisely the diversification visible in the vendor-share data.44,45 For serverless and scale-to-zero workloads, GraalVM native image compiles a closed-world Java application to a standalone executable that starts in milliseconds and uses a fraction of the memory, at the cost of build time (ten to fifteen minutes for large applications) and constraints on reflection and dynamic class loading that require explicit metadata.67,68

Data and messaging

JDBC remains the universal database interface; JPA and Hibernate sit above it, and lighter mappers such as jOOQ and MyBatis sit alongside. On the messaging side, Kafka clients, JMS implementations, and the Camel routing layer connect JVM services to everything else. Because so much of the data infrastructure is itself Java, integration is frequently in-process rather than over a wire.72,73

Build, supply chain, and security posture

Maven and Gradle dominate builds, both resolving from Maven Central by default.43,70 The supply-chain tooling around them — dependency scanning, SBOM generation, reproducible builds, and signature verification — has become a first-class concern since Log4Shell, and Maven Central's mandatory signing and namespace verification are a structural advantage here.59,70,71 On the cryptographic side, the platform is moving early on post-quantum readiness: a module-lattice key encapsulation mechanism landed in Java 24, post-quantum-ready JAR signing and hybrid public key encryption in Java 26, and hybrid key exchange for TLS 1.3 is targeted for Java 27.32,34

12Choosing Java in 2026

Java is a good default when the workload is long-running and throughput- sensitive, when the team is large enough that readability beats concision, when the system will outlive the people who wrote it, when the data infrastructure is already on the JVM, or when operational visibility into production is a hard requirement. It is a poor default for short-lived processes, for tight-memory edge deployments, for numerical and machine learning work where the ecosystem lives in Python, and for new Android applications, where Kotlin is now the recommended language.56

The more interesting observation is what has changed about the argument. Ten years ago the case against Java was that it was slow to start, verbose, and stagnant. Two of those three have been substantially addressed: the language now has records, sealed types, pattern matching and a threading model that removes the main reason to write reactive code, and the ahead-of-time work has cut startup from seconds to tens of milliseconds where it matters.8,9,11,12,26,66 What has not changed is the compatibility constraint, and that is not a bug being fixed — it is the product.

The languages that outlive their fashions are usually the ones that made an unglamorous promise and kept it. Java promised that your code would still run. Thirty-one years later, it does.
