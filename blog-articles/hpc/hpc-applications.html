A supercomputer is usually described by a single number, and almost no application is limited by the quantity that number measures. This article reads thirteen application areas of high-performance computing not as thirteen sciences but as instances of a much smaller set: the six resources an application can exhaust first. Which resource it exhausts predicts how it scales, what arithmetic precision it needs, which hardware investment helps it, and what a larger machine will and will not buy. Every quantitative claim below is produced by a deterministic laboratory of eight experiments, written in the Python standard library and executed at build time, whose complete output is reproduced verbatim.

I

The question

The list is familiar to anyone who has read a national laboratory's mission statement. Weather and climate. Fluid dynamics. Nuclear simulation. Astrophysics. Molecular dynamics. Drug discovery. Genomics. Seismic analysis. Finance. Cryptography. Engineering. Artificial intelligence. Large-scale scientific research. It is presented as a catalogue of subjects, and read that way it is nearly useless: it tells you that supercomputers are used by many disciplines, which was never in doubt, and nothing about why any of them needs one.

Read as engineering, the same list is far more informative, because the disciplines are not thirteen independent things. A machine offers a small number of distinguishable resources. It can perform arithmetic at some rate. It can move bytes between memory and the arithmetic units at some other rate. It can send a message to another node with some latency and some bandwidth. It can retain some quantity of state and write some quantity to storage. It can run for some interval before a component fails. Every application consumes all of these and is limited by exactly one, and the identity of that one is the most compressive fact about it.

The organising question of this article is therefore: which resource runs out first?

The claim being tested is that the answer is stable, predictable from the mathematical structure of the problem rather than from its subject matter, and strongly predictive of everything else. If it holds, then two disciplines with nothing else in common should behave identically when they share a bottleneck, and two branches of the same discipline should diverge when they do not. Both happen below, repeatedly. Seismic forward modelling and atmospheric dynamics are the same computation wearing different vocabulary. Monte Carlo neutron transport and Monte Carlo option pricing share an arithmetic profile and almost nothing else, because one streams and the other pointer-chases.

The claim is falsifiable in an ordinary way. If a domain's limiting resource changed whenever its hardware changed, the taxonomy would be a description of current machines rather than of applications, and would carry no predictive weight. If domains sharing a bottleneck adopted unrelated optimisation strategies, the classification would not be doing any work. And if the distribution of applications across the six classes were uniform, the taxonomy would be a partition rather than a finding. Section VI returns to each of these.

Six classes are used throughout, and they are the article's colour system as well as its argument. Nothing here is coloured decoratively.

II

The common substrate

Three models account for nearly all of the behaviour that follows, and each is old enough to be uncontroversial.

The first is the roofline1. Define the arithmetic intensity of a kernel as the number of floating-point operations it performs per byte it moves to and from main memory, and define the balance of a node as its peak arithmetic rate divided by its peak memory bandwidth2. A kernel whose intensity is below the balance cannot possibly reach peak, no matter how well it is written, because the memory system cannot supply operands fast enough. The attainable fraction of peak is simply the ratio of the two, capped at one. Figure 1 plots the consequence for ten kernels drawn from the domains below. At a balance of 16 flop per byte, an ideally cached seven-point stencil reaches 3.12% of peak and a compressed sparse-row matrix-vector product reaches 1.04%, while a dense matrix multiplication reaches all of it. The factor of 96 between the last two is not a measure of programmer skill. It is a property of the operations.

The balance itself has been drifting in the unhelpful direction for decades. Arithmetic capability has grown faster than memory bandwidth and very much faster than memory latency, so the ridge point has moved steadily to the right and kernels that were once compute-bound are no longer3. The end of conventional device scaling has removed the mechanism that used to improve every resource at once, leaving performance to come from specialisation, from algorithms, and from software4,5 — which is to say, from choices that are specific to the application rather than general to the machine. That is also why the field's own forecasts have become notably more cautious about what the next generation of hardware will deliver to any particular science6. A dense matrix multiplication at 85.3 flop per byte is comfortably clear of the ridge and will remain so; a stencil at 0.500 was never close and is receding.

This is the entire explanation for the persistent and much-discussed gap between dense-factorisation rankings and sparse-solver rankings of the same machines, and it is why a benchmark of the second kind was introduced alongside the first7. It is also why any argument that begins “the machine delivers X petaflop/s, therefore this simulation will run Y times faster” should be treated with suspicion until the intensity of the relevant kernel is known.

The second model concerns parallelism. Amdahl observed that a fixed problem's speed-up is bounded by its serial fraction8; Gustafson observed that if the problem grows with the machine, the serial fraction need not dominate9. Both are correct and they describe different scientific practices. Increasing the resolution of a climate model is Gustafson's regime. Delivering tomorrow's forecast sooner is Amdahl's. The distinction between weak and strong scaling is not a technicality; it determines whether a discipline can usefully spend a larger machine at all.

The third is the latency-bandwidth decomposition of a message: the cost of sending n bytes is a fixed startup plus a term proportional to n10,11. Combined with the surface-to-volume ratio of a subdivided domain, this produces the strong-scaling wall directly. Figure 2 traces it for a 10243 stencil: communication overtakes computation at 4,096 ranks, parallel efficiency falls below one half at 4,096, and the speed-up saturates near 4,919 times serial no matter how many further ranks are added. The subdomain surface shrinks more slowly than its volume, so beyond some division the ranks spend their time talking about a calculation they have already finished.

The six classes

From these three models, six mutually exclusive answers to “which resource runs out first?” exhaust the practical cases. The scheme is a descendant of the computational-pattern taxonomies that preceded it12, but it classifies by limit rather than by pattern, which is what makes it predictive.

Two clarifications matter before the plates. First, class assignment is by the binding constraint at production scale, not at any scale. Almost every application in this article is compute-bound on a laptop and something else on ten thousand nodes; the taxonomy describes the regime in which the machine was actually purchased to operate. Second, a high arithmetic intensity does not imply class F. Intensity is a ratio of operations to bytes; it says nothing about whether those bytes can be fetched without waiting. Plate 03 is the instructive failure case.

III

The bench

Nothing in the plates below is asserted on authority where it can be computed. Eight experiments, written in the Python standard library with fixed seeds and no external dependencies, run at build time; their output is embedded verbatim in the appendix and every figure in this article is drawn from it. They are small. That is deliberate: each is intended to isolate one mechanism at a scale where the mechanism is unambiguous, not to imitate a production code. Where a result is pre-asymptotic or where the model breaks down, this is stated rather than smoothed over.

Two of these deserve a word of caution about what they do and do not show. The strong-scaling and communication experiments (L2 and L7) are analytic models evaluated numerically, not measurements of any machine; their parameters are stated in the output and are chosen to be plausible rather than to describe a specific system. Their value lies in the shape of the resulting curves and in the crossover points, both of which are robust to the exact constants. The Barnes-Hut experiment (L5) is a genuine measurement, but at particle counts small enough that the method is not yet in its asymptotic regime, and the output says so.

IV

Thirteen plates

Each plate carries the same six fields, so that domains can be compared across them, together with a gauge showing where the domain's dominant kernel falls on the intensity axis of Figure 1. The shaded band on each gauge is the ridge region of current nodes: a kernel to its left cannot saturate the arithmetic units, and a kernel to its right can. The colour of the gauge marker is the domain's limiting resource, in the scheme established above. Plate order follows the conventional listing rather than any ranking.

Weather is the discipline that made the case for supercomputing and it remains the cleanest illustration of why raw peak performance is the wrong figure of merit. The dynamical core is a stencil: each grid cell reads its neighbours, performs a handful of multiplications and additions, and writes one value back. In the lab's accounting that kernel carries an arithmetic intensity of 0.500 flop per byte, and on a node balanced at 16 flop per byte it can reach 3.12% of the machine's advertised floating-point rate. The other ninety-seven per cent of the arithmetic units are idle by construction, waiting on memory. This is not a deficiency of the code. It is a property of the equations once they are discretised on a grid, and it is why the community pushed for a ranking metric that reflects sparse, bandwidth-bound work7 rather than dense factorisation alone.

What distinguishes weather from every other stencil science in this article is the deadline. A forecast delivered late is not a slower forecast; it is not a forecast. That converts an otherwise comfortable weak-scaling problem into a strong-scaling one, and strong scaling has a wall. Figure 2 traces it under an explicit latency-bandwidth model: parallel efficiency for a 10243 domain falls below half at 4,096 ranks, and past that point additional hardware buys progressively less wall-clock time until the curve flattens against a latency floor at roughly 4,919 times the serial rate. Resolution increases are affordable because they hold the subdomain fixed; turnaround improvements are not. The community's own exascale roadmap was written in exactly these terms13, and the 1 km near-global demonstrations that followed were reported as sustained throughput at fixed resolution rather than as peak numbers14. The 2025 climate prize at SC25 went to a full Earth system computed at 1 km15.

Beneath the engineering sits a harder limit that no machine addresses. Lorenz's 1963 system16 is the canonical demonstration, and the lab measures its consequence directly: a Benettin renormalisation17 returns a largest Lyapunov exponent of 0.9109, so errors double every 0.761 time units. Halving the initial uncertainty therefore extends the useful forecast by one doubling time and no more. Forecast range grows with the logarithm of observational accuracy, which is why the operational answer has been ensembles rather than precision18,19.

The lab makes the point sharper than the textbook version. Summing the same 4,096 double-precision numbers in three different orders produced results spanning 8.64 × 10-12, a relative spread of 4.09 × 10-15 and entirely within the guarantees of IEEE 75420,21. Injected as the sole difference between two Lorenz integrations, that spread grew to order unity by t = 38.15. Changing the number of MPI ranks reorders global reductions and thus produces exactly this perturbation. A forecast system is therefore not bitwise reproducible across decompositions, and cannot be made so cheaply; the discipline's response has been to treat that irreproducibility as signal to be sampled rather than noise to be suppressed.

The recent arrival of learned emulators reframes the resource question without dissolving it. Graph-network and diffusion models now match or exceed physics-based forecasts on many headline scores22,23, and ECMWF has run a machine-learned system operationally since February 2025, at a grid spacing of about 28 km and with a claimed thousand-fold reduction in the energy needed to produce a forecast24,25. The training cost is a dense-algebra problem that sits far to the right of the roofline ridge; the inference cost is trivial by comparison. What has changed is which resource is scarce, and when. What has not changed is the Lyapunov exponent.

Fluid dynamics is where the cost of resolution is most brutally explicit. Chapman's 1979 estimate of the grid points required to resolve a turbulent boundary layer26 was revisited by Choi and Moin27, who found the requirement for wall-resolved large-eddy simulation grows roughly as the Reynolds number to the thirteen-sevenths, and direct numerical simulation worse again. No conceivable machine brings a full-aircraft direct simulation into reach; the exponent, not the constant, is the obstacle. What supercomputers have delivered instead is canonical flows at Reynolds numbers high enough to settle disputes about the underlying physics. Lee and Moser's channel simulation reached a friction Reynolds number of about 5,186 and measured a von Karman constant of 0.384 with a quoted uncertainty of 0.00428, a measurement whose value lies precisely in its resolution of a long-running empirical disagreement29.

Production engineering CFD looks nothing like that. It is unstructured, implicit, and dominated by sparse matrix-vector products whose intensity the lab puts at 0.167 flop per byte, which is 1.04% of peak on a reference node. Worse, an implicit solve is not merely bandwidth-bound; every Krylov iteration contains a global inner product, and a global inner product is a synchronising collective whose cost is governed by latency and by the slowest rank. This is why communication-avoiding reformulations of Krylov methods have been pursued so persistently30: the arithmetic was never the problem.

The spectral codes used for canonical turbulence show the network limit in its purest form. A distributed three-dimensional FFT31 requires global transposes, and the lab quantifies what that costs. For a 20483 complex grid, each transpose message shrinks as the square of the rank count, so message size falls below the point at which latency overtakes bandwidth at about 1,914 ranks. Beyond that, adding ranks adds messages faster than it removes bytes, and the transform stops improving (Figure 7). A stencil never encounters this: it exchanges six messages regardless of how many ranks exist.

NASA's own assessment of the field is worth taking at face value: its 2030 vision study identified the binding constraints as automated meshing, robust scalable solvers, and the handling of separated flow, not as floating-point throughput32. It remains the most candid statement any computational discipline has made about the difference between the resource it is given and the resource it actually lacks.

Monte Carlo neutron transport is the best available counterexample to naive roofline reasoning, and it earns its place here for that reason. Score the kernel arithmetically and it looks gloriously compute-bound: the lab's model path performs 625 flop per byte written, which on any current node places it far to the right of the ridge. In practice the code stalls. Each collision requires a continuous-energy cross-section lookup, a binary search into per-nuclide tables that together run to gigabytes, indexed by a value that depends on the outcome of the previous collision. The access is random, the dependency chain is serial, and no amount of arithmetic capability helps. The XSBench proxy application exists specifically to expose this behaviour33, and open implementations of the full method make the same structure inspectable34.

This is why the plate is filed under irregularity rather than throughput. Two workloads can share an arithmetic intensity of several hundred flop per byte and have nothing else in common: financial path simulation, which streams predictably and vectorises, and neutron transport, which pointer-chases through a table and does not. The roofline places both in the same region of the diagram and is, on this point, misleading. It is a model of bandwidth and arithmetic, not of latency, and latency is what binds here.

The deterministic alternative trades that problem for a different one. Discrete-ordinates methods sweep the mesh along each discrete direction, and a sweep carries a genuine data dependency from cell to upstream cell. Parallel sweeps must therefore be pipelined, with a fill and drain cost that grows with the process grid, and the acceleration schemes that make the outer iteration converge quickly introduce their own coupled solves35.

The application context deserves stating plainly. Absent full-scale testing, weapons physics is a simulation-led discipline, and the machines built for it are procured on that basis; El Capitan held second place on the June 2026 list at 1,809 petaflop/s36. In the civil and inertial-confinement branch the record is more openly assessable: the achievement of target gain above unity at the National Ignition Facility37 was the outcome of a design campaign in which simulation set the target geometry and the drive. The measure of success in this domain is not benchmark performance but whether an experiment that costs a great deal to perform behaves as predicted.

Gravity is unscreened, so every particle interacts with every other, and the naive cost is quadratic. The discipline's founding computational insight was that distant groups can be replaced by their multipole expansion: the Barnes-Hut tree reduced the cost to O(N log N)38, and the fast multipole method reduced it further to linear in the particle count39. The lab reproduces the mechanism at small scale (Figure 4) and, more usefully, reproduces its limitations honestly. At 1,500 bodies the tree is only 3.3 times cheaper than direct summation at an opening angle of 0.5, for a mean relative force error of 3.6 × 10-3; at the tightest angle tested the advantage nearly vanishes. Across a sweep from 1,000 to 8,000 bodies the measured interaction count grows as N to the power 1.452 — well above the asymptotic exponent of one, because at these sizes the tree is not yet in its asymptotic regime. What the sweep does establish is the direction and the rate: the advantage over direct summation grew from 2.70 to 8.40 across an eightfold increase in N. Production runs sit nine or more decades further along that curve.

The consequence for procurement is worth stating bluntly. An algorithmic factor that grows with problem size cannot be bought. A machine ten times faster runs the quadratic method on a problem 3.2 times larger; the tree runs it on a problem nearly ten times larger, and the fast multipole method on one ten times larger still. The codes that made trillion-particle cosmology feasible40,41 and the simulations that first reproduced realistic galaxy populations42 are algorithmic achievements executed on large machines, in that order.

What binds at scale is not arithmetic but balance. Gravitational systems cluster by construction: after a few dynamical times, a small fraction of the volume contains a large fraction of the particles and an even larger fraction of the interactions. A static domain decomposition therefore leaves most ranks idle at every synchronisation point, and the practical engineering of a cosmology code is dominated by space-filling-curve decompositions, work estimators and continuous rebalancing. The tree walk itself is irregular: which remote nodes a rank needs depends on where its particles happen to be, so the communication pattern is neither fixed nor knowable in advance.

The observational side of the field has meanwhile become a data problem of the kind described in Plate 13. The Legacy Survey of Space and Time began on 30 June 2026; the observatory collects roughly ten terabytes each night and issues up to seven million alerts, each of which is a claim that something in the sky has changed43,44. Simulation and survey now constrain each other, and the comparison itself is a computation.

Molecular dynamics is the domain in which the serial dimension is inescapable. A protein folds on the microsecond to millisecond scale; the integration step is bounded near two femtoseconds by the fastest bond vibrations; the ratio is nine to twelve orders of magnitude. Those steps are sequential by definition. Parallelism therefore cannot reduce the number of steps, only the time to take one, and the time to take one is bounded below by the latency of the communication it contains.

The pair loop itself is comfortable. At an assumed ninety per cent cache hit rate on neighbour coordinates the lab scores it at 4.69 flop per byte, which reaches 29.30% of peak at the reference balance — respectable, and far better than any stencil. The difficulty is elsewhere. Electrostatics are long-ranged and cannot be truncated without artefacts, so the standard treatment splits them, computing the smooth part on a mesh by FFT45. That mesh solve carries the same global transposes analysed in Figure 7, and it must be completed before the step can end. Every femtosecond of simulated time contains a synchronising collective. Mature codes have spent two decades attacking exactly this seam, through multiple time-stepping, through separate rank sets dedicated to the mesh, and through overlapping the short-range loop with the transpose46,47.

The most direct evidence that latency is the binding resource is that a special-purpose machine was built to defeat it. Anton was designed around communication rather than arithmetic, and its third generation reports tens of microseconds of simulated time per day on systems of modest size48 — a regime no general-purpose cluster reaches, not because it lacks floating-point capability but because it cannot complete a round trip fast enough. The scientific payoff of crossing that threshold has been substantial: reversible folding trajectories for a dozen small proteins49 became observable only once the accessible timescale exceeded the folding time.

Machine-learned interatomic potentials are now shifting the balance again. They replace a cheap analytic force evaluation with an expensive neural one, which moves the kernel decisively to the right of the ridge and makes the network relatively less important — at the cost of far more arithmetic per step50. That is a rational trade on hardware whose reduced-precision matrix units are abundant and whose interconnect latency has improved comparatively little. It is also a clean example of the general pattern in this article: applications do not become faster so much as they migrate to whichever resource is currently cheap.

Virtual screening is the most nearly perfect parallel workload in this article. Candidate ligands are independent, so a library of a billion compounds is a billion independent jobs, and a machine's contribution is simply its integral of cores over time. Platforms built on this observation have screened libraries of that order51, and the pandemic produced a well-documented instance at supercomputer scale in which the pipeline, not the kernel, was the object of engineering52. Nothing about the interconnect matters. Nothing about strong scaling matters. The relevant metric is compounds evaluated per megawatt-hour.

The difficulty is that the cheap method is not the accurate one. Docking scores rank candidates crudely; rigorous relative binding free energies require alchemical molecular dynamics, which inherits every constraint of Plate 05 and costs several orders of magnitude more per compound53. The discipline therefore operates a funnel, and the interesting resource question is where to place the boundaries: how many compounds to score cheaply, how many to promote to expensive simulation, and how many to synthesise. That is an allocation problem, not a performance problem.

Learned structure prediction has changed the shape of the funnel rather than its logic. Accurate prediction of protein structure from sequence54, and subsequently of complexes including ligands and nucleic acids55, removed a step that had previously required experiment. The compute profile of that step is dense inference: high intensity, trivially parallel, entirely unlike the physics-based methods it partially displaces.

It is worth being precise about what the machine is and is not the limit on. A screening campaign that evaluates a billion compounds produces a ranked list, and the value of that list is bounded by the accuracy of the scoring function and by the throughput of the wet laboratory that must test its top entries. Compute is abundant here in a way it is not in Plates 01 through 05. The constraint has moved downstream.

Genomics enters this taxonomy as the discipline with no floating point worth speaking of. Its foundational kernels are combinatorial: optimal local alignment by dynamic programming56, the heuristic that made database search tractable57, and index-based read mapping over a Burrows-Wheeler transform58. The lab scores a banded alignment cell at 1.5 integer operations per byte of band state, which places it firmly on the bandwidth-bound side of any ridge, and understates the difficulty: index search is a chain of dependent random accesses into a structure much larger than cache, so the effective limit is memory latency rather than throughput.

The resource that actually binds is storage. A decade-old analysis compared sequencing's growth in acquisition, storage, distribution and analysis against astronomy's and against the major consumer data domains, and concluded that genomics was on track to be comparable or larger on every axis59. That projection has aged well, and it identified the right bottleneck: the expensive part of a genome is not aligning it once but keeping it, moving it, and re-analysing it when the reference or the caller improves.

Two developments have made the access pattern worse. The completion of a genuinely gapless human genome60 resolved the segmental duplications and satellite arrays that short-read pipelines had simply skipped, and the draft pangenome that followed61 replaced a single linear reference with a graph representing many. A graph reference is scientifically superior and computationally hostile: linear-reference alignment is a mostly sequential scan with good locality, while graph alignment is pointer-chasing. The field has improved its answer and, in doing so, moved further from the hardware's preferences.

This plate also marks the boundary of what a supercomputer contributes. Population-scale genomics is executed on large clusters and increasingly in cloud object stores, because the workload is embarrassingly parallel and storage-dominated, and because the governance of human data imposes constraints that have nothing to do with performance. The machine that serves this domain best is not the one at the top of the list.

Forward seismic modelling is an ordinary stencil problem, structurally identical to Plate 01, and it scales well for the same reasons. Spectral-element formulations handle complex geometry and free surfaces with high-order accuracy and a diagonal mass matrix62, and large dynamic-rupture simulations have been demonstrated on heterogeneous machines at petascale63. If seismology only ever ran forward, it would sit beside weather in this taxonomy.

It does not, because the scientific object is the inverse problem. Full waveform inversion seeks the subsurface model whose synthetic seismograms match the recorded ones, and the gradient of that misfit is formed by correlating the forward wavefield with an adjoint field propagated backwards in time64. The two fields are needed simultaneously at each time step, and they run in opposite temporal directions. Storing the entire forward wavefield is prohibitive; a three-dimensional field at production resolution is measured in petabytes per iteration. The alternatives are to checkpoint sparsely and recompute the intervening segments, or to reconstruct the forward field by running it backwards from a stored final state, which is unstable in attenuating media. Every practical scheme is a negotiation between memory capacity, I/O bandwidth and redundant arithmetic — the same economics that Figure 8 applies to resilience, here operating inside a single job.

The payoff justifies the cost. Adjoint tomography has produced global models of the mantle at resolutions that were unreachable by ray-based methods65, and the technique transfers directly between planetary interiors and hydrocarbon reservoirs because the mathematics does not care about the scale.

The domain also supplies the clearest current example of an inverse problem placed under a wall-clock deadline. The 2025 Gordon Bell Prize went to a real-time Bayesian inversion for tsunami early warning on the Cascadia subduction zone, run on El Capitan15. Early warning is a discipline in which the answer must arrive before the wave does, which converts a throughput-limited inference problem into a strong-scaling one and imports every constraint discussed under Plate 01.

Derivative valuation and risk measurement are Monte Carlo problems66, and Monte Carlo has a convergence rate that is both famous and merciless. The lab measures it on a four-dimensional test integral: the fitted error decay is -0.529 against a theoretical one-half, so obtaining one further decimal digit costs a factor of about 77 in samples (Figure 5). No property of the machine alters that exponent. Doubling the cluster reduces the standard error by about thirty per cent.

Two responses exist, and both are algorithmic. Low-discrepancy sequences replace pseudorandom points with points chosen to fill the unit cube evenly67,68; the lab's Halton construction achieved a fitted decay of -1.002, approaching the linear rate that the theory permits for sufficiently regular integrands69, and at sixty-five thousand samples its error was more than forty times smaller than the pseudorandom estimate. The second and more powerful response is multilevel Monte Carlo, which combines coarse and fine time discretisations so that most samples are cheap and only a few need be accurate, reducing the complexity of a typical path-dependent problem by a full order in the tolerance70. American and Bermudan exercise features are handled by regressing the continuation value across paths71, which introduces the one point in the workflow where paths must be considered together.

Everything else is independent, which makes this the domain in which precision reduction is nearly free. If the statistical error of an estimate is of order 10-3, carrying twelve additional decimal digits through the path generation is waste; single precision, and in places less, is entirely defensible. Very few scientific domains can say the same, and it is a consequence of the workload's structure rather than of any tolerance for sloppiness.

What makes finance distinctive in this collection is the character of the deadline. Weather's deadline is set by the weather, and seismology's by the wave. Finance's is set by regulation and by the opening bell: capital computations under the revised market-risk framework must be produced on a prescribed cycle72. A deadline imposed by rule is the only kind that can, in principle, be renegotiated — and the only kind that reliably is not.

Cryptanalysis is the one domain in this article where the community's goal is to establish that a computation is infeasible, and where the resource question is therefore adversarial. The number field sieve remains the best known classical method for factoring general integers, and the current public record stands where it was set in February 2020: RSA-250, a 250-digit, 829-bit semiprime, at a cost the authors put near 2,700 core-years73,74. More than six years of hardware progress have not displaced it, which is itself informative.

The method has two phases with opposite computational characters. Sieving is embarrassingly parallel and can be spread across arbitrarily many loosely connected machines, but it is memory-bound and irregular: the working set is large and the access pattern scattered. The linear algebra phase that follows, finding dependencies in a sparse matrix over GF(2), is not decomposable in the same way. It is a tightly coupled iterative computation with global communication in every step, and it is the reason a factoring record requires a real machine rather than merely a large volunteer pool. The same asymmetry appears in hash cryptanalysis: the identical-prefix collision on SHA-175 and the chosen-prefix attack that followed76 were search problems whose cost was quoted, tellingly, in dollars of rented compute. This is the only discipline here that measures its limits in currency.

The security margin is what distinguishes the domain from every other plate. In weather, fluid dynamics or astrophysics, a machine ten times larger buys proportionately more science. In factoring it buys almost nothing: the sieve's complexity is sub-exponential in the bit length, so the gap between an 829-bit record and a 2048-bit deployed modulus is not a gap that hardware crosses. Shor's algorithm changes the exponent rather than the constant77, which is why the migration to post-quantum primitives is being conducted on a standards timetable rather than in response to any demonstrated break78. NIST's transition report, still an initial public draft at the time of writing, proposes deprecating 112-bit-security public-key algorithms after 2030 and disallowing quantum-vulnerable ones after 203579; resource estimates for the quantum attack itself continue to fall while remaining far above any existing device80.

The lesson this plate contributes to the taxonomy is that a resource limit can be a design goal. Everywhere else in this article, exhausting a resource is a problem to be engineered around. Here it is the product.

Industrial simulation is where the taxonomy meets a constraint the sciences mostly escape: the answer must arrive inside a design cycle. A crash analysis that runs overnight is used; one that runs for a week is not, regardless of its fidelity. That makes engineering a strong-scaling discipline with all the attendant limits, and it explains why the field's performance literature is preoccupied with turnaround rather than throughput.

The kernels are familiar from earlier plates. Implicit analysis reduces to repeated sparse solves at the 0.167 flop-per-byte intensity already established, with global reductions in every Krylov iteration81. What is unfamiliar is contact. In an explicit crash simulation, the expensive and unpredictable operation is determining which surfaces have come into contact this step, a search whose cost concentrates wherever the structure is currently deforming. That region moves. A decomposition balanced at the start of the analysis is unbalanced by the time the first buckle forms, and the resulting idle time is not recoverable by faster arithmetic. This is why the plate is classified by imbalance rather than by the solver.

The most striking demonstration that resolution changes engineering conclusions rather than merely their presentation is topology optimisation at extreme scale. Optimising an aircraft wing over roughly 1.1 billion voxels on 8,000 cores produced an internal structure that reproduced features of natural load-bearing morphology and was reported to outperform the conventional design82,83. At coarse resolution the optimiser cannot represent those features, so it does not find them. The computation is not verifying a design; it is generating one.

The direction of travel is towards persistent, continuously updated models of specific physical assets rather than one-off analyses. A recent consensus study sets out both the promise and the unsolved problems, chiefly the statistical machinery required to keep a model calibrated against streaming sensor data and to quantify how much its predictions should be trusted84. That is a different computational shape again: many small inferences under a real-time constraint, rather than one large solve.

Machine learning is the workload that inverted the relationship between applications and machines. Every other plate in this article describes a science adapting to hardware designed for something else. Here the hardware was redesigned for the application, because the application's kernel is the one thing a processor can execute at close to its advertised rate. The lab scores a reduced-precision attention-scale matrix multiplication at 2,731 flop per byte, thousands of times to the right of any current node's ridge point. Dense matrix multiplication is the only kernel in the collection that is genuinely, comfortably compute-bound, and the systematic case for specialised matrix hardware was made on precisely that observation85.

The scaling behaviour is empirical rather than derived. Loss falls as a power law in model size, dataset size and compute86, and the allocation between parameters and tokens that minimises loss at fixed compute was found to favour far more data than earlier practice assumed87. Neither result is a theorem, and both are statements about a regime rather than about the limit. What they establish for this taxonomy is that the domain is weak-scaling by nature: more machine is spent on a bigger problem, not on the same problem faster.

At the largest scales the familiar constraints reassert themselves. A model that does not fit on one device must be partitioned, and each partitioning strategy purchases memory relief with communication: data parallelism requires a gradient all-reduce every step, pipeline parallelism introduces bubbles, tensor parallelism places collectives inside the layer itself, and combinations of the three are chosen by measuring which collective the interconnect tolerates88,89. The discipline also independently rediscovered communication avoidance. FlashAttention is presented explicitly as an IO-aware algorithm: it computes exactly the same function while reorganising the computation to avoid materialising an intermediate in slow memory90, which is the same insight, arrived at separately, that underlies communication-optimal linear algebra30.

Two qualifications belong on this plate. First, the growth in training compute has been extraordinarily rapid by the standards of any other scientific workload91, and that growth is what has driven memory-interface standards such as HBM492 on a schedule the traditional HPC applications could not have justified alone. Second, inference is a different workload entirely: autoregressive generation reads the whole model, and a large cache of prior state, to produce one token, which returns the binding constraint to memory bandwidth. The domain sits at opposite ends of this article's spectrum depending on which phase you observe.

The final plate is not a simulation domain at all, and it is included because it accounts for a large share of what actually runs on scientific computing infrastructure. Particle physics, radio astronomy, optical survey astronomy, light sources and fusion experiments all share a structure: an instrument produces data at a fixed rate, and a distributed computing system must reduce, calibrate, reconstruct and archive that data continuously, without falling behind. The Worldwide LHC Computing Grid was the first system built on this premise at scale93, and the community's own assessment of the high-luminosity era is candid that projected resource needs exceed what technology trends will supply, so the shortfall must be closed by software94.

Radio interferometry pushes the ingest problem furthest: correlating signals from many antennas produces raw rates that cannot be stored at all, so the reduction must happen in the instrument's own real-time path, and only the reduced product survives95. Optical survey astronomy supplies the current worked example. The Legacy Survey of Space and Time formally began on 30 June 2026; a new image is captured about every forty seconds, roughly ten terabytes accumulate each night, and difference imaging against a reference generates up to seven million alerts nightly, distributed publicly to brokers that must filter them for the handful worth following up43,44. The scientific value of an alert decays within hours, so this is a latency-constrained pipeline attached to a capacity-constrained archive.

The resource that binds is not the one a benchmark measures. Nothing in this plate is compute-limited in the sense of Plates 01 to 05. What limits it is sustained write bandwidth, archive capacity across decades, the ability to reprocess an entire dataset when calibration improves, and the metadata discipline that makes a decade-old observation usable by someone who was not present when it was taken96. That last item is not a hardware property at all, which is precisely the point: for the largest scientific undertakings, the computer is a subordinate component of an apparatus whose clock is set elsewhere97.

V

What cuts across

Four techniques recur across the plates, and each of them is an instance of the same manoeuvre: spend an abundant resource to relieve a scarce one. Their ubiquity is the strongest evidence that the taxonomy is describing something real, because a domain adopts them exactly when its bottleneck makes them profitable, and ignores them otherwise.

Trading precision for bandwidth and arithmetic

Reduced-precision arithmetic is faster and, more importantly, halves or quarters the bytes moved, which lifts a bandwidth-bound kernel directly up the roofline. The obstacle is accuracy, and the classical resolution is iterative refinement: factor cheaply in low precision, then correct using residuals computed in high precision98,99. The lab performs this exactly (Figure 6). A binary32 factorisation of an 200-element system leaves a relative forward error of 4.06 × 10-7; after 2 refinement sweeps the error reaches 10.0 × 10-17, at the level of binary64 unit roundoff, having recovered roughly 9.9 orders of magnitude. The sweeps cost 6.00% of the factorisation at this size, and because refinement is quadratic in n while factorisation is cubic, that overhead falls to 0.0120% at a hundred thousand unknowns. The technique is essentially free at scale, which is why mixed-precision solvers moved from a research topic to standard practice within a few years of tensor units becoming widely available100,101.

The domains that adopted this fastest are precisely those the taxonomy predicts: engineering and fluid dynamics, whose implicit solves are bandwidth-bound, and machine learning, whose training loop tolerates far cruder arithmetic than either. The domains that did not are those where precision is not the binding constraint, and reducing it buys nothing: cryptanalysis, which requires exact integers, and genomics, which barely uses floating point.

Trading arithmetic for communication

Once communication rather than arithmetic is the scarce resource, the correct response is to recompute rather than to fetch. This is the organising idea of communication-avoiding numerical linear algebra30, and it is rediscovered independently whenever a field arrives at the same constraint: the IO-aware reformulation of attention90 performs additional arithmetic in order to avoid materialising an intermediate in slow memory, which is structurally the same move.

Figure 7 shows why the pressure is uneven across domains. A nearest-neighbour halo always sends six messages, whatever the rank count, and the bytes in each shrink as the subdomain does. A global transpose sends messages proportional to the rank count, each shrinking as its square. For the lab's 20483 grid, transpose messages fall below the size at which bandwidth dominates latency at about 1,914 ranks, and beyond that the transform gets slower rather than faster as ranks are added. Stencil disciplines never meet this wall; spectral ones meet it at a rank count fixed by their grid size and by nothing else. That single asymmetry separates Plates 01 and 08 from Plates 02 and 05 more sharply than any difference in their physics.

Trading capacity for survivability

A machine large enough to be interesting fails often enough to be a problem. If nodes fail independently, the system's mean time between failures falls inversely with node count, and the optimal checkpoint interval scales as the square root of the product of checkpoint cost and system MTBF102,103. Figure 8 evaluates this for a 50,000-hour per-node MTBF and a 300-second checkpoint. The useful fraction of machine time falls below ninety per cent at about 3,700 nodes and below half at about 300,000; at a million nodes the optimal interval is under six minutes and the machine spends most of itself staying alive. Halving the checkpoint cost doubles both thresholds exactly, which is why the storage hierarchy of a leadership machine is not a peripheral concern but a determinant of how large it can usefully be. The same arithmetic reappears inside a single job whenever an adjoint calculation must choose between storing a wavefield and recomputing it, as in Plate 08.

Trading determinism for tractability

The most uncomfortable trade is the one made against reproducibility. Floating-point addition is not associative21,20, so a global reduction returns a different result when the rank count changes. The lab measures the size of that effect and its consequence: summing the same 4,096 values three ways produced a spread of 8.64 × 10-12, a relative difference of 4.09 × 10-15, and injecting that spread as the sole difference between two Lorenz trajectories produced order-one divergence by t = 38.15 (Figure 3). For a chaotic system, bitwise reproducibility across decompositions is therefore not merely expensive; it is a property that must be deliberately engineered and paid for, and the operational disciplines have largely declined to pay. They sample the uncertainty instead18. Reproducible reduction orders are still worth having for verification and debugging, and are a different thing from physical accuracy.

What the taxonomy predicts, and what would refute it

Three tests were proposed in Section I. On the first — whether the classification tracks applications or merely current hardware — the evidence is reasonably strong. The reasons a stencil is bandwidth-bound and a matrix multiplication is not follow from the operation counts, which are properties of the discretisation. A machine with a very different balance would move the ridge and change the numbers, but it would not reorder the kernels along the intensity axis, because that ordering is arithmetic. The exception is instructive: machine learning has been influential enough to move the hardware toward itself, which is a genuine case of the causal arrow reversing.

On the second — whether domains sharing a bottleneck converge on strategies — the plates supply repeated confirmation. Bandwidth-bound domains adopted mixed precision and cache blocking. Latency-bound domains adopted communication avoidance, overlapping, and in one case a custom machine. Imbalance-bound domains built dynamic decomposition machinery and largely ignored precision. Storage-bound domains invested in compression, streaming reduction and metadata, and have almost nothing to say about floating point. Throughput-bound domains improved their estimators rather than their kernels, which is why multilevel Monte Carlo mattered more to finance than any processor generation.

On the third — whether the classes are populated unevenly enough to be informative — the answer is yes, and the imbalance is itself the most interesting result. Only one of thirteen domains is limited by arithmetic throughput. The single quantity by which supercomputers are ranked, advertised and compared is the binding constraint for one application area in this list.

Two honest weaknesses remain. Several domains are genuinely bimodal, and the plate assigns the class of the frontier workload rather than of the median one: nuclear simulation contains both an irregular-access Monte Carlo and a latency-bound deterministic sweep, and machine learning is compute-bound in training and bandwidth-bound in inference. And the taxonomy has nothing to say about the constraints that several plates identify as their real limits — mesh generation, experimental validation throughput, data governance, human design cycles. Those are not resources a machine supplies. That they keep appearing in the plates as the actual bottleneck is a finding the framework can report but not explain.

What the framework does explain is why the headline number so rarely predicts anything. A machine is a bundle of resources, an application exhausts one of them, and the two are matched only by accident. The thirteen sciences in this article are not thirteen demands on a supercomputer. They are six.

# Deterministic pseudo-random source: Lehmer / MINSTD. Fixed seed, no imports.

class LCG:
    """Park-Miller minimal standard generator. Reproducible everywhere."""

    M = 2147483647          # 2**31 - 1
    A = 48271

    def __init__(self, seed=20260822):
        self.s = seed % self.M or 1

    def u(self):
        self.s = (self.A * self.s) % self.M
        return self.s / self.M

    def normal(self):
        """Box-Muller, single deviate per call (deterministic, no cache)."""
        u1 = max(self.u(), 1e-12)
        u2 = self.u()
        return math.sqrt(-2.0 * math.log(u1)) * math.cos(2.0 * math.pi * u2)


def f32(x):
    """Round a Python float (IEEE binary64) to binary32 and back."""
    return struct.unpack("f", struct.pack("f", x))[0]

def l2_strong_scaling():
    head("L2", "Halo exchange, surface-to-volume, and the strong-scaling wall")

    N = 1024            # global grid is N^3
    flop_pt = 8.0       # 7-point stencil update
    F = 2.0e11          # sustained flop/s available to one rank
    alpha = 1.5e-6      # message latency, s
    beta = 2.5e10       # link bandwidth, B/s
    depth = 1           # ghost depth
    word = 8            # fp64

    w("Global grid %d^3 = %.3g points, 7-point stencil, fp64." % (N, float(N) ** 3))
    w("Per rank: T_comp = %g flop / %.3g flop/s" % (flop_pt, F))
    w("          T_comm = 6 (alpha + bytes/beta), alpha = %.1f us, beta = %.0f GB/s"
      % (alpha * 1e6, beta / 1e9))
    w()

    def model(P):
        side = round(P ** (1.0 / 3.0))
        n = N / side                       # subdomain edge
        comp = flop_pt * n ** 3 / F
        halo = 6.0 * depth * n * n * word
        comm = 6.0 * alpha + halo / beta
        return n, comp, comm, comp + comm

    ranks = [1, 8, 64, 512, 4096, 32768, 262144, 2097152]
    t1 = model(1)[3]
    w("%9s %9s %11s %11s %10s %9s %9s" %
      ("ranks", "n edge", "T_comp(s)", "T_comm(s)", "comm frac", "speedup", "eff"))
    rule()
    curve = []
    for P in ranks:
        n, comp, comm, tot = model(P)
        sp = t1 / tot
        curve.append((P, n, comp, comm, sp, sp / P))
        w("%9d %9.1f %11.4g %11.4g %9.1f%% %9.0f %8.1f%%" %
          (P, n, comp, comm, 100 * comm / tot, sp, 100 * sp / P))
    rule()
    w()

    # locate the peak of the strong-scaling curve on a dense sweep
    best = (0, 0.0)
    dense = []
    for k in range(0, 26):
        side = 2 ** k
        P = side ** 3
        if P > 4194304:
            break
        n, comp, comm, tot = model(P)
        sp = t1 / tot
        dense.append((P, sp, sp / P))
        if sp > best[1]:
            best = (P, sp)
    p_peak, s_peak = best
    w("Peak speedup on the sweep: %.0f x at %d ranks (%d^3 points per rank)."
      % (s_peak, p_peak, round(N / round(p_peak ** (1 / 3.)))))

    # rank count at which communication first exceeds computation

    for k in range(0, 26):

def l3_chaos():
    head("L3", "Chaos, reduction order, and the case for ensembles")

    sigma, rho, beta_l = 10.0, 28.0, 8.0 / 3.0
    dt = 0.001

    def deriv(s):
        x, y, z = s
        return (sigma * (y - x), x * (rho - z) - y, x * y - beta_l * z)

    def rk4(s, h):
        k1 = deriv(s)
        s2 = tuple(s[i] + 0.5 * h * k1[i] for i in range(3))
        k2 = deriv(s2)
        s3 = tuple(s[i] + 0.5 * h * k2[i] for i in range(3))
        k3 = deriv(s3)
        s4 = tuple(s[i] + h * k3[i] for i in range(3))
        k4 = deriv(s4)
        return tuple(s[i] + h / 6.0 * (k1[i] + 2 * k2[i] + 2 * k3[i] + k4[i])
                     for i in range(3))

    def sep(a, b):
        return math.sqrt(sum((a[i] - b[i]) ** 2 for i in range(3)))

    base = (1.0, 1.0, 1.0)
    w("Lorenz-63, sigma=%.0f rho=%.0f beta=8/3, RK4 with dt=%.3f." % (sigma, rho, dt))
    w("Reference trajectory from x0 = (1, 1, 1).")
    w()

    perts = [1e-6, 1e-9, 1e-12]
    tmax = 40.0
    steps = int(tmax / dt)
    tracks = {}
    w("%14s %14s %14s %14s" %
      ("perturbation", "t(sep>1e-3)", "t(sep>1)", "sep at t=40"))
    rule()
    summary = []
    for p in perts:
        a = base
        b = (base[0] + p, base[1], base[2])
        t_small = t_big = None
        tr = []
        for i in range(steps):
            a = rk4(a, dt)
            b = rk4(b, dt)
            d = sep(a, b)
            if i % 100 == 0:
                tr.append(((i + 1) * dt, max(d, 1e-18)))
            if t_small is None and d > 1e-3:
                t_small = (i + 1) * dt
            if t_big is None and d > 1.0:
                t_big = (i + 1) * dt
        tracks["%.0e" % p] = tr
        summary.append((p, t_small, t_big, sep(a, b)))
        w("%14.0e %14.2f %14.2f %14.4f" % (p, t_small, t_big, sep(a, b)))
    rule()
    w()

    # Growth rate between the 1e-12 and 1e-6 launches: 6 decades of head start
    d_dec = math.log10(perts[0] / perts[2])
    dt_gain = summary[2][2] - summary[0][2]
    lam_thr = math.log(10.0) * d_dec / dt_gain
    w("Six decades of extra initial accuracy buy %.2f time units of forecast," % dt_gain)
    w("implying a growth rate of %.3f per unit time from the threshold crossings."
      % lam_thr)
    w()

    # Benettin renormalisation: the standard estimator for the largest exponent
    d0 = 1e-8
    T = 0.1
    nT = int(T / dt)
    a = base
    bb = (base[0] + d0, base[1], base[2])
    # discard a transient so the pair sits on the attractor
    for _ in range(20000):
        a = rk4(a, dt)
        bb = rk4(bb, dt)
    d = sep(a, bb)
    bb = tuple(a[i] + (bb[i] - a[i]) * d0 / d for i in range(3))
    acc = 0.0
    nseg = 1000
    for _ in range(nseg):
        for _ in range(nT):
            a = rk4(a, dt)
            bb = rk4(bb, dt)
        d = sep(a, bb)
        acc += math.log(d / d0)
        bb = tuple(a[i] + (bb[i] - a[i]) * d0 / d for i in range(3))
    lam = acc / (nseg * T)
    w("Benettin renormalisation over %.0f time units, d0 = %.0e, renormalising"
      % (nseg * T, d0))
    w("every %.1f time units:" % T)
    w("   largest Lyapunov exponent  lambda = %.4f" % lam)
    w("   error doubling time        %.4f time units" % (math.log(2.0) / lam))
    w("   published value for these parameters is close to 0.906")
    w()
    w("Halving the initial error therefore extends the useful forecast by")
    w("%.3f time units, and no more. Forecast range grows with the logarithm"
      % (math.log(2.0) / lam))
    w("of initial accuracy, so buying range by observation alone is ruinous.")
    w()

    # ---- reduction-order experiment -------------------------------------
    w("Reduction order. The same 4096 fp64 addends summed three ways:")
    g = LCG(7)
    vals = [g.normal() * 10 ** (g.u() * 6 - 3) for _ in range(4096)]
    fwd = 0.0
    for v in vals:
        fwd += v
    rev = 0.0
    for v in reversed(vals):
        rev += v

    def tree(a):
        cur = a[:]
        while len(cur) > 1:
            nxt = [cur[i] + cur[i + 1] for i in range(0, len(cur) - 1, 2)]
            if len(cur) % 2:
                nxt.append(cur[-1])
            cur = nxt
        return cur[0]

    tre = tree(vals)
    w("   sequential forward   %.20g" % fwd)
    w("   sequential reverse   %.20g" % rev)
    w("   pairwise tree        %.20g" % tre)
    spread = max(fwd, rev, tre) - min(fwd, rev, tre)
    w("   spread               %.3e   (%.2e relative)"
      % (spread, spread / abs(tre)))
    w()
    w("Injecting that spread as the only difference between two forecasts:")
    a = base
    b = (base[0] + spread, base[1], base[2])
    t_reassoc = None
    reassoc_track = []
    for i in range(steps):
        a = rk4(a, dt)
        b = rk4(b, dt)
        d = sep(a, b)
        if i % 100 == 0:
            reassoc_track.append(((i + 1) * dt, max(d, 1e-18)))
        if t_reassoc is None and d > 1.0:
            t_reassoc = (i + 1) * dt
    w("   initial separation   %.3e" % spread)
    if t_reassoc is None:
        w("   O(1) divergence      not reached within t = %.0f" % tmax)
        t_reassoc = float("nan")
    else:
        w("   O(1) divergence at   t = %.2f" % t_reassoc)
    w()
    w("A change of MPI rank count that reorders one global reduction is therefore")
    w("sufficient to produce a visibly different forecast in finite time. The")
    w("response is not more precision but an ensemble: sample the uncertainty")
    w("instead of pretending it is absent.")

    RESULTS["l3"] = {
        "summary": summary, "tracks": tracks, "lam": lam, "lam_thr": lam_thr,
        "doubling": math.log(2.0) / lam, "dt_gain": dt_gain,
        "fwd": fwd, "rev": rev, "tre": tre, "spread": spread,
        "rel": spread / abs(tre),
        "t_reassoc": t_reassoc, "reassoc_track": reassoc_track,
    }

def radical_inverse(n, base):
    f, r = 1.0 / base, 0.0
    while n > 0:
        r += f * (n % base)
        n //= base
        f /= base
    return r


def l4_monte_carlo():
    head("L4", "Monte Carlo against quasi-Monte Carlo convergence")

    d = 4
    bases = [2, 3, 5, 7]

    def integrand(x):
        # product_i (|4 x_i - 2| + i) / (1 + i)  -- Sobol' g-function, exact = 1
        p = 1.0
        for i, xi in enumerate(x):
            a = float(i)
            p *= (abs(4.0 * xi - 2.0) + a) / (1.0 + a)
        return p

    exact = 1.0
    w("Sobol' g-function in d=%d, a_i = i, exact integral = %.1f." % (d, exact))
    w("Pseudorandom sampling from a Park-Miller LCG; quasi-random from a")
    w("Halton sequence on bases %s." % bases)
    w()

    reps = 40
    Ns = [2 ** k for k in range(8, 17)]
    w("%9s %14s %14s %10s" % ("N", "MC rms err", "QMC err", "MC/QMC"))
    rule()
    mc_curve, qmc_curve = [], []
    for N in Ns:
        acc = 0.0
        for r in range(reps):
            g = LCG(1000 + 17 * r)
            s = 0.0
            for _ in range(N):
                s += integrand([g.u() for _ in range(d)])
            acc += (s / N - exact) ** 2
        mc = math.sqrt(acc / reps)
        s = 0.0
        for i in range(1, N + 1):
            s += integrand([radical_inverse(i, b) for b in bases])
        qmc = abs(s / N - exact)
        mc_curve.append((N, mc))
        qmc_curve.append((N, qmc))
        w("%9d %14.3e %14.3e %10.1f" % (N, mc, qmc, mc / qmc))
    rule()
    w()

    def slope(curve):
        xs = [math.log(n) for n, e in curve]
        ys = [math.log(e) for n, e in curve]
        mx, my = sum(xs) / len(xs), sum(ys) / len(ys)
        num = sum((xs[i] - mx) * (ys[i] - my) for i in range(len(xs)))
        den = sum((xs[i] - mx) ** 2 for i in range(len(xs)))
        return num / den

    s_mc, s_qmc = slope(mc_curve), slope(qmc_curve)
    w("Fitted convergence rates (log error against log N):")
    w("   Monte Carlo        %+.3f   (theory -0.500)" % s_mc)
    w("   quasi-Monte Carlo  %+.3f   (theory approaches -1)" % s_qmc)
    w()
    w("Consequences for the machine. At rate %.3f, one more decimal digit costs"
      % s_mc)
    w("a factor of %.0f in samples." % (10 ** (1.0 / abs(s_mc))))
    w("Samples are independent, so that factor is spent on cores, not on")
    w("interconnect: the work is throughput-bound and network-indifferent.")

    RESULTS["l4"] = {
        "mc": mc_curve, "qmc": qmc_curve,
        "s_mc": s_mc, "s_qmc": s_qmc,
        "digit_cost": 10 ** (1.0 / abs(s_mc)),
        "reps": reps, "d": d, "bases": bases,
    }

class Cell:
    __slots__ = ("cx", "cy", "cz", "h", "m", "mx", "my", "mz", "kids", "body", "n")

    def __init__(self, cx, cy, cz, h):
        self.cx, self.cy, self.cz, self.h = cx, cy, cz, h
        self.m = 0.0
        self.mx = self.my = self.mz = 0.0
        self.kids = None
        self.body = None
        self.n = 0


def _octant(c, p):
    return ((1 if p[0] > c.cx else 0) |
            (2 if p[1] > c.cy else 0) |
            (4 if p[2] > c.cz else 0))


def _subdivide(c):
    q = c.h * 0.5
    c.kids = []
    for k in range(8):
        dx = q if (k & 1) else -q
        dy = q if (k & 2) else -q
        dz = q if (k & 4) else -q
        c.kids.append(Cell(c.cx + dx, c.cy + dy, c.cz + dz, q))


def insert(c, p, depth=0):
    c.n += 1
    if c.n == 1 and c.kids is None:
        c.body = p
        return
    if c.kids is None:
        if depth > 40:
            c.n -= 1
            return
        old = c.body
        c.body = None
        _subdivide(c)
        insert(c.kids[_octant(c, old)], old, depth + 1)
    insert(c.kids[_octant(c, p)], p, depth + 1)


def moments(c):
    if c.kids is None:
        if c.body is not None:
            c.m = c.body[3]
            c.mx, c.my, c.mz = c.body[0], c.body[1], c.body[2]
        return
    m = mx = my = mz = 0.0
    for k in c.kids:
        if k.n:
            moments(k)
            m += k.m
            mx += k.m * k.mx
            my += k.m * k.my
            mz += k.m * k.mz
    c.m = m
    if m > 0:
        c.mx, c.my, c.mz = mx / m, my / m, mz / m


def bh_force(c, p, theta, eps2, counter):
    if c.n == 0:
        return (0.0, 0.0, 0.0)
    dx = c.mx - p[0]
    dy = c.my - p[1]
    dz = c.mz - p[2]
    r2 = dx * dx + dy * dy + dz * dz + eps2
    if c.kids is None:
        if c.body is None or c.body is p:
            return (0.0, 0.0, 0.0)
        counter[0] += 1
        inv = c.m / (r2 * math.sqrt(r2))
        return (dx * inv, dy * inv, dz * inv)
    if (2.0 * c.h) * (2.0 * c.h) < theta * theta * r2:
        counter[0] += 1
        inv = c.m / (r2 * math.sqrt(r2))
        return (dx * inv, dy * inv, dz * inv)
    fx = fy = fz = 0.0
    for k in c.kids:
        if k.n:
            a, b, cc = bh_force(k, p, theta, eps2, counter)
            fx += a
            fy += b
            fz += cc
    return (fx, fy, fz)


def l5_barnes_hut():
    head("L5", "Barnes-Hut against direct summation")

    N = 1500
    eps2 = 1e-4
    g = LCG(31337)
    bodies = []
    for _ in range(N):
        # Plummer-like radial profile, isotropic angles
        u = g.u()
        r = 1.0 / math.sqrt(max(u ** (-2.0 / 3.0) - 1.0, 1e-9))
        r = min(r, 12.0)
        ct = 2.0 * g.u() - 1.0
        st = math.sqrt(max(0.0, 1.0 - ct * ct))
        ph = 2.0 * math.pi * g.u()
        bodies.append((r * st * math.cos(ph), r * st * math.sin(ph),
                       r * ct, 1.0 / N))

    w("N = %d bodies drawn from a Plummer profile, softening eps^2 = %g." % (N, eps2))
    w("Reference: direct summation, %d force evaluations (N(N-1))."
      % (N * (N - 1)))
    w()

    exact = []
    for i, p in enumerate(bodies):
        fx = fy = fz = 0.0
        px, py, pz = p[0], p[1], p[2]
        for j, q in enumerate(bodies):
            if i == j:
                continue
            dx = q[0] - px
            dy = q[1] - py
            dz = q[2] - pz
            r2 = dx * dx + dy * dy + dz * dz + eps2
            inv = q[3] / (r2 * math.sqrt(r2))
            fx += dx * inv
            fy += dy * inv
            fz += dz * inv
        exact.append((fx, fy, fz))

    root = Cell(0.0, 0.0, 0.0, 16.0)
    for p in bodies:
        insert(root, p)
    moments(root)

    thetas = [0.2, 0.3, 0.5, 0.7, 1.0]
    w("%8s %14s %12s %14s %14s" %
      ("theta", "interactions", "per body", "mean rel err", "max rel err"))
    rule()
    rows = []
    direct_pairs = N * (N - 1)
    for th in thetas:
        cnt = [0]
        errs = []
        for i, p in enumerate(bodies):
            f = bh_force(root, p, th, eps2, cnt)
            ex = exact[i]
            mag = math.sqrt(ex[0] ** 2 + ex[1] ** 2 + ex[2] ** 2)
            de = math.sqrt(sum((f[k] - ex[k]) ** 2 for k in range(3)))
            if mag > 0:
                errs.append(de / mag)
        mean_e = sum(errs) / len(errs)
        max_e = max(errs)
        rows.append((th, cnt[0], cnt[0] / N, mean_e, max_e, direct_pairs / cnt[0]))
        w("%8.2f %14d %12.1f %14.3e %14.3e" %
          (th, cnt[0], cnt[0] / N, mean_e, max_e))
    rule()
    w()
    w("%8s %14s" % ("theta", "speed-up vs direct"))
    rule()
    for th, cnt, per, me, xe, sp in rows:
        w("%8.2f %14.1f x" % (th, sp))
    rule()
    w()

    th_ref = 0.5
    ref = [r for r in rows if abs(r[0] - th_ref) < 1e-9][0]
    w("At theta = %.1f the tree gives %.1f x fewer interactions than direct"
      % (th_ref, ref[5]))
    w("summation for a mean force error of %.2e. At theta = 0.2 the advantage"
      % ref[3])
    w("has almost vanished (%.1f x): at N = %d the tree's constant is not yet"
      % (rows[0][5], N))
    w("amortised, which is the honest small-N behaviour of every fast method.")
    w()

    # ---- how does the interaction count actually grow with N? -------------
    w("Interaction count against N at theta = %.1f, same Plummer profile:" % th_ref)
    w()
    w("%9s %16s %14s" % ("N", "interactions", "per body"))
    rule()
    sweep = []
    for Nx in (1000, 2000, 4000, 8000):
        gx = LCG(31337)
        bs = []
        for _ in range(Nx):
            u = gx.u()
            r = 1.0 / math.sqrt(max(u ** (-2.0 / 3.0) - 1.0, 1e-9))
            r = min(r, 12.0)
            ct = 2.0 * gx.u() - 1.0
            st = math.sqrt(max(0.0, 1.0 - ct * ct))
            ph = 2.0 * math.pi * gx.u()
            bs.append((r * st * math.cos(ph), r * st * math.sin(ph),
                       r * ct, 1.0 / Nx))
        rt = Cell(0.0, 0.0, 0.0, 16.0)
        for p in bs:
            insert(rt, p)
        moments(rt)
        cnt = [0]
        for p in bs:
            bh_force(rt, p, th_ref, eps2, cnt)
        sweep.append((Nx, cnt[0], cnt[0] / Nx))
        w("%9d %16d %14.1f" % (Nx, cnt[0], cnt[0] / Nx))
    rule()
    w()

    # measured advantage over direct summation at each N in the sweep
    adv = [(nx, nx * (nx - 1), c, nx * (nx - 1) / c) for nx, c, pb in sweep]
    w("%9s %16s %16s %14s" % ("N", "direct N(N-1)", "tree", "advantage"))
    rule()
    for nx, dd, c, a in adv:
        w("%9d %16d %16d %13.2f x" % (nx, dd, c, a))
    rule()
    w()

    # power-law fits over the sweep
    lx = [math.log(nx) for nx, c, pb in sweep]
    ly = [math.log(c) for nx, c, pb in sweep]
    mlx, mly = sum(lx) / len(lx), sum(ly) / len(ly)
    pexp = (sum((lx[i] - mlx) * (ly[i] - mly) for i in range(len(lx))) /
            sum((lx[i] - mlx) ** 2 for i in range(len(lx))))
    la = [math.log(a) for nx, dd, c, a in adv]
    mla = sum(la) / len(la)
    aexp = (sum((lx[i] - mlx) * (la[i] - mla) for i in range(len(lx))) /
            sum((lx[i] - mlx) ** 2 for i in range(len(lx))))
    w("Fits over %d <= N <= %d:" % (sweep[0][0], sweep[-1][0]))
    w("   tree interactions   ~ N^%.3f" % pexp)
    w("   advantage           ~ N^%.3f" % aexp)
    w()
    w("The measured exponent %.3f is well above the asymptotic 1: at these N the"
      % pexp)
    w("tree is still pre-asymptotic, and this lab is too small to measure the")
    w("O(N log N) regime directly. What it does measure is the direction and")
    w("the rate: the advantage grows as roughly N^%.2f over this range, so it" % aexp)
    w("is a factor of %.1f across the sweep's %d-fold increase in N."
      % (adv[-1][3] / adv[0][3], sweep[-1][0] // sweep[0][0]))
    w("Production runs sit nine or more decades further along the same curve,")
    w("where the theoretical N/log N separation is the operative one.")
    w()
    w("No plausible increase in machine performance closes a factor that grows")
    w("with N. Astrophysics at scale is an algorithm result in hardware costume.")

    RESULTS["l5"] = {"N": N, "rows": rows, "th_ref": th_ref, "ref": ref,
                     "sweep": sweep, "adv": adv,
                     "pexp": pexp, "aexp": aexp}

def l6_mixed_precision():
    head("L6", "Mixed-precision LU with iterative refinement")

    n = 200
    g = LCG(4242)
    A = [[0.0] * n for _ in range(n)]
    for i in range(n):
        for j in range(n):
            A[i][j] = g.normal()
        A[i][i] += n * 0.5           # diagonally dominant, moderately conditioned
    xtrue = [1.0 + 0.001 * i for i in range(n)]
    b = [sum(A[i][j] * xtrue[j] for j in range(n)) for i in range(n)]

    w("Dense system n = %d, diagonally dominant, exact solution known." % n)
    w("Working precision: IEEE binary64. Factorisation precision: binary32,")
    w("emulated by rounding every stored and intermediate value through")
    w("struct.pack('f', ...). Residuals are always formed in binary64.")
    w()

    # ---- low-precision LU with partial pivoting --------------------------
    LU = [[f32(A[i][j]) for j in range(n)] for i in range(n)]
    piv = list(range(n))
    for k in range(n):
        p = max(range(k, n), key=lambda r: abs(LU[r][k]))
        if p != k:
            LU[k], LU[p] = LU[p], LU[k]
            piv[k], piv[p] = piv[p], piv[k]
        akk = LU[k][k]
        for i in range(k + 1, n):
            m = f32(LU[i][k] / akk)
            LU[i][k] = m
            if m != 0.0:
                row_i, row_k = LU[i], LU[k]
                for j in range(k + 1, n):
                    row_i[j] = f32(row_i[j] - f32(m * row_k[j]))

    def lusolve(rhs):
        y = [0.0] * n
        for i in range(n):
            s = f32(rhs[piv[i]])
            for j in range(i):
                s = f32(s - f32(LU[i][j] * y[j]))
            y[i] = s
        x = [0.0] * n
        for i in range(n - 1, -1, -1):
            s = y[i]
            for j in range(i + 1, n):
                s = f32(s - f32(LU[i][j] * x[j]))
            x[i] = f32(s / LU[i][i])
        return x

    def resid(x):
        return [b[i] - sum(A[i][j] * x[j] for j in range(n)) for i in range(n)]

    def nrm(v):
        return math.sqrt(sum(t * t for t in v))

    nb = nrm(b)
    nx = nrm(xtrue)
    x = lusolve(b)
    hist = []
    r = resid(x)
    hist.append((0, nrm(r) / nb, nrm([x[i] - xtrue[i] for i in range(n)]) / nx))
    for step in range(1, 6):
        dx = lusolve(r)
        x = [x[i] + dx[i] for i in range(n)]
        r = resid(x)
        hist.append((step, nrm(r) / nb,
                     nrm([x[i] - xtrue[i] for i in range(n)]) / nx))

    w("%10s %20s %20s" % ("refinement", "rel residual", "rel forward error"))
    rule()
    for s, rr, fe in hist:
        w("%10d %20.6e %20.6e" % (s, rr, fe))
    rule()
    w()
    gain = hist[0][2] / hist[-1][2]
    conv = next((s for s, rr, fe in hist if fe < 1e-15), len(hist) - 1)
    w("Refinement recovers %.3g orders of magnitude of forward error, reaching"
      % math.log10(gain))
    w("binary64 accuracy after %d sweeps." % conv)
    w("Cost accounting:")
    fact = 2.0 / 3.0 * n ** 3
    per_it = 4.0 * n ** 2
    its = conv
    w("   low-precision factorisation   %.4g flop  (2/3 n^3)" % fact)
    w("   one refinement sweep          %.4g flop  (4 n^2, residual + solve)" % per_it)
    w("   %d sweeps to convergence      %.4g flop  = %.2f%% of the factorisation"
      % (its, its * per_it, 100 * its * per_it / fact))
    w("   at n = 10^5 the same ratio is %.4f%%"
      % (100 * its * 4.0 * (1e5 ** 2) / (2.0 / 3.0 * 1e5 ** 3)))
    w()
    w("The refinement is free at scale, so a machine whose reduced-precision")
    w("units are k times faster than its fp64 units delivers close to k-fold")
    w("speed at full fp64 accuracy for this class of problem.")

    RESULTS["l6"] = {
        "n": n, "hist": hist, "fact": fact, "per_it": per_it,
        "its": its, "conv": conv, "overhead": 100 * its * per_it / fact,
        "gain_orders": math.log10(gain),
    }

def l7_communication():
    head("L7", "Nearest-neighbour halo against global transpose")

    N = 2048
    word = 16.0          # complex fp64
    alpha = 1.5e-6
    beta = 2.5e10

    w("Grid %d^3 complex fp64 = %.4g bytes of global state." % (N, N ** 3 * word))
    w("A 7-point stencil halo is compared with the all-to-all transposes of a")
    w("distributed 3D FFT (three transposes per transform).")
    w("alpha = %.1f us, beta = %.0f GB/s per link." % (alpha * 1e6, beta / 1e9))
    w("The bandwidth-latency crossover message size is alpha*beta = %.0f bytes."
      % (alpha * beta))
    w()

    rows = []
    w("%9s %13s %11s %13s %13s %13s" %
      ("ranks", "halo B/rank", "halo msgs", "a2a B/rank", "a2a msgs", "a2a msg B"))
    rule()
    for k in range(1, 7):
        side = 2 ** k
        P = side ** 3
        n = N / side
        halo_bytes = 6.0 * n * n * 8.0
        halo_msgs = 6
        a2a_bytes = 3.0 * (N ** 3 / P) * word * (P - 1) / P
        a2a_msgs = 3.0 * (P - 1)
        msg = a2a_bytes / a2a_msgs
        t_halo = halo_msgs * alpha + halo_bytes / beta
        t_a2a = a2a_msgs * alpha + a2a_bytes / beta
        rows.append((P, halo_bytes, halo_msgs, a2a_bytes, a2a_msgs, msg,
                     t_halo, t_a2a))
        w("%9d %13.4g %11d %13.4g %13.4g %13.4g" %
          (P, halo_bytes, halo_msgs, a2a_bytes, a2a_msgs, msg))
    rule()
    w()
    w("%9s %15s %15s %12s %14s" %
      ("ranks", "T_halo (s)", "T_a2a (s)", "ratio", "a2a latency %"))
    rule()
    for P, hb, hm, ab, am, ms, th, ta in rows:
        w("%9d %15.4g %15.4g %11.0f x %13.1f%%" %
          (P, th, ta, ta / th, 100 * am * alpha / ta))
    rule()
    w()

    # Analytic crossover: transpose message size N^3 * word / P^2 falls below
    # alpha * beta, after which the all-to-all is a latency problem.
    p_lat = math.sqrt(N ** 3 * word / (alpha * beta))
    w("Transpose message size falls as N^3 * word / P^2. Setting that equal to")
    w("alpha*beta gives the rank count beyond which the all-to-all is latency-")
    w("bound rather than bandwidth-bound:")
    w("   P_lat = sqrt(N^3 * word / (alpha*beta)) = %.0f ranks" % p_lat)
    w()
    for Nx in (1024, 2048, 4096, 8192):
        w("   N = %5d   P_lat = %10.0f ranks"
          % (Nx, math.sqrt(Nx ** 3 * word / (alpha * beta))))
    w()
    big = rows[-1]
    w("At %d ranks the transpose moves %.1f x the bytes of the halo, issues"
      % (big[0], big[3] / big[1]))
    w("%.4g x as many messages, and spends %.1f%% of its time on latency alone."
      % (big[4] / big[2], 100 * big[4] * alpha / big[7]))
    w()
    w("Halo cost per rank falls as the domain is divided; all-to-all cost per")
    w("rank falls only as 1/P while the message count rises as P, so the")
    w("transpose crosses into the latency regime at a rank count fixed by the")
    w("grid. This single asymmetry separates the stencil sciences from the")
    w("spectral ones more sharply than any difference in their physics.")

    RESULTS["l7"] = {"N": N, "rows": rows, "p_lat": p_lat, "alpha": alpha,
                     "beta": beta,
                     "plat_curve": [(Nx, math.sqrt(Nx ** 3 * word / (alpha * beta)))
                                    for Nx in (1024, 2048, 4096, 8192)]}

def l8_resilience():
    head("L8", "Checkpoint interval and resilience efficiency at scale")

    node_mtbf_h = 50000.0     # hours, per node
    delta = 300.0             # checkpoint write, seconds
    w("Per-node MTBF %.0f h. Checkpoint write delta = %.0f s." % (node_mtbf_h, delta))
    w("System MTBF M = node MTBF / nodes. Daly's first-order optimum is")
    w("tau = sqrt(2 delta M); efficiency ~ (tau) / (tau + delta + tau^2/(2M)).")
    w()

    rows = []
    w("%10s %14s %14s %14s %12s" %
      ("nodes", "system MTBF", "tau_opt (s)", "checkpoints/h", "efficiency"))
    rule()
    for nodes in (1000, 10000, 50000, 100000, 500000, 1000000, 5000000):
        M = node_mtbf_h * 3600.0 / nodes
        tau = math.sqrt(2.0 * delta * M)
        useful = tau
        overhead = delta + (tau * tau) / (2.0 * M)
        eff = useful / (useful + overhead)
        rows.append((nodes, M, tau, 3600.0 / (tau + delta), eff))
        w("%10d %12.4g s %14.1f %14.2f %11.1f%%"
          % (nodes, M, tau, 3600.0 / (tau + delta), 100 * eff))
    rule()
    w()

    # efficiency curve for the figure
    curve = []
    nn = 1000
    while nn <= 8000000:
        M = node_mtbf_h * 3600.0 / nn
        tau = math.sqrt(2.0 * delta * M)
        eff = tau / (tau + delta + tau * tau / (2.0 * M))
        curve.append((nn, eff))
        nn = int(nn * 1.35)

    # node count at which efficiency drops below 90 % and 50 %
    thr = {}
    for target in (0.9, 0.5):
        lo, hi = 1000.0, 5.0e7
        for _ in range(80):
            mid = math.sqrt(lo * hi)
            M = node_mtbf_h * 3600.0 / mid
            tau = math.sqrt(2.0 * delta * M)
            e = tau / (tau + delta + tau * tau / (2.0 * M))
            if e > target:
                lo = mid
            else:
                hi = mid
        thr[target] = mid
    w("Efficiency falls below 90%% at %.3g nodes and below 50%% at %.3g nodes."
      % (thr[0.9], thr[0.5]))
    w()
    w("Halving delta -- by writing less state, or writing it to node-local")
    w("storage -- moves both thresholds up by a factor of:")
    for target in (0.9, 0.5):
        lo, hi = 1000.0, 5.0e7
        d2 = delta / 2.0
        for _ in range(80):
            mid = math.sqrt(lo * hi)
            M = node_mtbf_h * 3600.0 / mid
            tau = math.sqrt(2.0 * d2 * M)
            e = tau / (tau + d2 + tau * tau / (2.0 * M))
            if e > target:
                lo = mid
            else:
                hi = mid
        w("   %.0f%% threshold: %.3g -> %.3g nodes (%.2f x)"
          % (100 * target, thr[target], mid, mid / thr[target]))
    w()
    w("Resilience is therefore an I/O problem before it is a hardware problem,")
    w("which is why the fastest machines are also, necessarily, the ones with")
    w("the most aggressive storage hierarchies.")

    RESULTS["l8"] = {
        "node_mtbf_h": node_mtbf_h, "delta": delta,
        "rows": rows, "curve": curve, "thr": thr,
    }
