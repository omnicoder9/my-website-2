Objects, types and values

Every piece of data in a Python program is an object, and every object has an identity, a type and a value.[1] The type decides which operations the object supports and which values it can hold. You can ask any object for its type with type(), and test membership of a type (including its subclasses) with isinstance().[2]

Names in Python are not declared with a type. A name is bound to an object, and the object carries the type. The same name can be rebound to an object of a different type later on.

Two properties come up again and again in this article. A mutable object can change its state after it is created; an immutable object has a fixed value, so a new object has to be created to store a different value.[3] An object is hashable if its hash value never changes during its lifetime, which is what makes it usable as a dictionary key or set member.[3] The table below summarises the built-in types covered here.

1 Numeric types

Python has three distinct built-in numeric types: integers, floating-point numbers and complex numbers. Booleans are a subtype of integers.[4] When a binary arithmetic operator gets operands of different numeric types, the “narrower” operand is widened to the other’s type, where integer is narrower than floating point and floating point is narrower than complex.[4]

int

type intmutable norange unlimitedsince int/long unified in Python 2.2 (PEP 237)

Integers have unlimited precision.[4] The data model describes them as numbers “in an unlimited range, subject to available (virtual) memory only.”[1] This is the result of PEP 237, which unified the old fixed-size int and arbitrary-size long types into one.[5]

Integer literals can be written in decimal, binary (0b), octal (0o) or hexadecimal (0x), and since Python 3.6 underscores may be used to group digits; they are ignored when the value is computed.[6,7]

The floor-division operator // rounds towards minus infinity, not towards zero, so (-1) // 2 is -1.[4] The remainder % follows the same rule and takes the sign of the divisor, so that (a // b) * b + a % b == a always holds.

Since Python 3.11, converting between int and str in a non-power-of-two base such as base 10 raises ValueError when the number has more than 4300 digits. The limit mitigates a denial-of-service risk (CVE-2020-10735) and can be changed with sys.set_int_max_str_digits().[8,9] Arithmetic on large integers is not limited; only the text conversion is.

float

type floatmutable nostorage IEEE 754 binary64 on almost all platformsprecision 53 bits

Floating-point numbers are usually implemented with C double; details for the running machine are in sys.float_info.[4,9] Almost all platforms map Python floats to IEEE 754 binary64 values, which carry 53 bits of precision.[10] Many decimal fractions, including 0.1, cannot be represented exactly in binary, so what is stored is the nearest binary fraction.[10]

Because exact equality is fragile, compare floats with a tolerance using math.isclose(). When you need exact decimal arithmetic, for example with money, use the decimal module, which represents decimal numbers exactly.[11]

The built-in round() rounds halves to the even neighbour, so round(0.5) and round(-0.5) are both 0 and round(1.5) is 2. round(2.675, 2) gives 2.67, because 2.675 is stored as a value slightly below 2.675.[2]

complex

type complexmutable nostorage two doublesliteral suffix j or J

A complex number is stored as a pair of machine-level double-precision floats.[1] An imaginary literal such as 4.2j denotes a complex number with a zero real part; add a real number to it to get a general complex value.[6] The parts are available as z.real and z.imag, and each is a float.[4] The cmath module provides mathematical functions that accept complex arguments, and the built-in abs() gives the modulus.[12]

2 Boolean

bool

type boolvalues True, Falsebase class intsince Python 2.3 (PEP 285)

The bool type was added by PEP 285.[13] It is a subclass of int with exactly two instances, True and False, which behave like 1 and 0 in almost every context except conversion to a string.[1,4] The documentation discourages relying on that numeric behaviour and recommends an explicit int() instead.[4] Assigning to True or False is a SyntaxError.[14]

Any object can be tested for truth. The built-in values considered false are None and False, zero of any numeric type, and empty sequences and collections; nearly everything else is true.[4] bool(x) applies the same rule.

The operators and and or do not always return a bool. x and y returns x if it is false and y otherwise; x or y returns x if it is true and y otherwise. Evaluation stops as soon as the result is known.[4,15] not always returns a bool. Comparisons can be chained, so a < b <= c means a < b and b <= c with b evaluated once.[15]

Using bitwise inversion ~ on a bool has been deprecated since Python 3.12, because ~True is -2, not False. Use not for logical negation.[4]

3 Strings

type strmutable noholds Unicode code pointsitem type str of length 1

Text is handled with str objects. Strings are immutable sequences of Unicode code points.[4] Python has no separate character type: each code point is itself a string of length 1.[1]

Creation

String literals can use single quotes, double quotes, or triple quotes for text spanning several lines. Backslash escapes such as \n and \u00e9 are interpreted unless the literal has an r (raw) prefix. Adjacent literals separated only by whitespace are joined into one.[6] The str() constructor turns any object into its informal string form.[4]

Indexing

Indexing starts at 0. Negative indices count from the right, so s[-1] is the last character. An index that is out of range raises IndexError.[16] Because strings are immutable, assigning to an index raises TypeError.[16]

Slicing

A slice s[start:stop:step] takes characters from start up to but not including stop. Omitted bounds default to the ends of the string, and a negative step walks backwards.[4] Unlike indexing, out-of-range slice bounds are handled gracefully.[16]

Slice positions sit between characters: word[2:5] takes the characters between positions 2 and 5.

String methods

Because strings are immutable, every method that seems to modify a string returns a new one.[4] The most common groups are shown below. casefold() is a stronger form of lower() meant for caseless matching (it maps “ß” to “ss”).[4] removeprefix() and removesuffix() were added in Python 3.9.[17]

Formatting

Python offers three ways to build strings from values. f-strings and str.format() share the same format specification mini-language after the colon, which controls fill, alignment, sign, width, grouping, precision and type.[18] The older % operator follows C’s printf conventions.[4]

f-strings

A formatted string literal is a literal prefixed with f or F whose replacement fields in braces contain expressions evaluated at run time.[6] They were introduced in Python 3.6 by PEP 498.[19] Python 3.8 added the = specifier, which prints the expression text together with its value, handy for debugging.[6] Since Python 3.12, PEP 701 lets an f-string reuse its own quote character inside the braces and nest f-strings freely.[20]

str.format() and format()

PEP 3101 introduced str.format(), which fills numbered or named fields from its arguments, and the built-in format(value, spec), which applies one format specification to one value.[18,21] str.format() is useful when the template is stored separately from the values, for example in a configuration file.

% formatting

printf-style formatting handles a narrower range of types and is slightly harder to use correctly than the newer methods, though it is often faster for the cases it handles.[4] A common trap is that a single tuple argument must be wrapped in another tuple. You will still meet % in older code and in the logging module.

Python 3.14 adds a fourth form, template strings (t"...", PEP 750). A t-string looks like an f-string but evaluates to a Template object rather than a str, so code can process the values before they become text, for example to escape them.[22] The examples in this article run on Python 3.13.17, so t-strings are not shown.

4 Collections

Python’s four general-purpose built-in containers are the list, tuple, set and dictionary. Lists and tuples are sequences indexed by position; sets hold unique members with no order; dictionaries map keys to values.[4,23]

Lists

type listmutable yeshashable noliteral [a, b]

Lists are mutable sequences, typically used to store collections of similar items.[4] Unlike strings, their contents can be changed in place.[16] They support indexing and slicing like strings, plus methods that modify the list. List comprehensions build a new list by applying an expression to each item of an iterable, optionally filtered by a condition.[23]

A list stores references to objects, not copies. Repeating a list with * repeats the references, so [[0] * 3] * 3 creates three references to the same inner list.[4] Assignment also copies only the reference. list.copy() and copy.copy() make a shallow copy that still shares nested objects; copy.deepcopy() copies them recursively.[24]

Tuples

type tuplemutable nohashable if all items areliteral (a, b) or a, b

Tuples are immutable sequences that usually hold a fixed group of different kinds of item, accessed by unpacking or indexing.[23] It is the comma that makes a tuple, not the parentheses, so a one-item tuple needs a trailing comma: (a,). The parentheses are optional except for the empty tuple or where they avoid ambiguity.[4] An immutable container such as a tuple is hashable only if all its elements are hashable.[3]

Sets

type set, frozensetmutable set yes, frozenset nomembers unique, hashableliteral {a, b}

A set is an unordered collection with no duplicate elements, used for membership testing and removing duplicates, and supporting union, intersection, difference and symmetric difference.[23] Set members follow the same rules as dictionary keys: they must be hashable. Numbers that compare equal, such as 1, 1.0 and True, count as the same member.[1] An empty pair of braces creates a dictionary, so an empty set must be written set().[23] frozenset is the immutable, hashable counterpart.[4]

Dictionaries

type dictmutable yeskeys hashableorder insertion order (guaranteed since 3.7)

A dictionary maps keys to values. Keys can be any immutable (more precisely, hashable) type; strings and numbers can always be keys.[3,23] Dictionaries preserve insertion order: replacing a value keeps the key’s position, while deleting and re-inserting a key moves it to the end.[1] This ordering became an official part of the language in Python 3.7.[25] Python 3.9 added the | and |= operators for merging dictionaries.[26]

5 Binary types

Python 3 separates text (str) from raw binary data. PEP 3137 settled the design: an immutable bytes type and a mutable bytearray type.[27] The third binary type, memoryview, gives access to another object’s memory without copying it.[4]

bytes

type bytesmutable noitems integers 0–255literal b"..."

A bytes object is an immutable sequence of integers in the range 0 ≤ x < 256.[1,2] Bytes literals use a b prefix and may contain only ASCII characters; other byte values are written with escapes such as \xff.[6] Indexing returns an int, while slicing returns bytes. Text is turned into bytes with str.encode() and back with bytes.decode(); the default encoding is UTF-8.[4]

The last line uses % formatting on bytes, which PEP 461 added in Python 3.5 for binary protocols.[28]

bytearray

type bytearraymutable yesitems integers 0–255literal none

bytearray is the mutable counterpart of bytes: a mutable sequence of integers in the range 0 ≤ x < 256 that has most of the usual methods of mutable sequences as well as most of the methods of bytes.[2,4] It has no literal syntax and is always created with the constructor.

memoryview

type memoryviewcopies data noworks with any buffer-protocol objectprotocol PEP 3118

The built-in memoryview() returns a “memory view” of an object that supports the buffer protocol.[2] The buffer protocol was redesigned for Python 3 by PEP 3118 so that objects can share memory directly.[29] Objects that export a C-contiguous buffer, such as bytes, bytearray and array.array, are called bytes-like objects. A view of a bytearray is writable; a view of bytes is read-only.[3] Slicing a memoryview creates a new view rather than copying, which matters when you work with large buffers.

The cast example assumes a little-endian machine, which covers x86 and most ARM systems. The last lines show why views should be released (or used in a with block) when you are done: an object cannot change size while a view of its memory exists.

6 NoneType

None

type NoneTypeinstances exactly onetruth value falsetest with is None

None represents the absence of a value. It is the sole instance of NoneType, and assigning to the name None is a SyntaxError.[1,14] A function that ends without a return statement, or with a bare return, returns None.[30] None is false in a Boolean context.[4]

Because there is only one None object, test for it by identity. PEP 8 states that comparisons to singletons such as None should always use is or is not, never the equality operators,[31] and is is true only when both operands are the same object.[15] A class can override == to claim equality with anything, but it cannot fake identity.

The most important idiom involving None is the default argument. Default values are evaluated only once, when the function is defined, so a mutable default such as a list is shared between calls. The tutorial’s fix is to default to None and create a fresh object inside the function.[30]

Summary

  • Numbers. int is exact with unlimited size; float is binary64 and approximates most decimals; complex is a pair of floats. Use math.isclose, decimal or fractions when exactness matters.
  • Booleans. bool is a two-value subclass of int. Every object has a truth value, and and/or return one of their operands.
  • Strings. Immutable sequences of code points with zero-based indexing, forgiving slices and many methods that return new strings. Prefer f-strings for formatting; know str.format() and % for templates and older code.
  • Collections. Lists are mutable sequences; tuples are immutable records; sets hold unique hashable members; dictionaries map hashable keys to values in insertion order. Watch for shared references.
  • Binary data. bytes is immutable, bytearray is mutable, and memoryview exposes either without copying.
  • None. A single object meaning “no value”. Test it with is, and use it as the default for optional mutable arguments.
