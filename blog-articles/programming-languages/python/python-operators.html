1What an operator is

An operator is a symbol or keyword that combines one or more values, called operands, into an expression that produces a new value. In 3 + 4 the operator is + and the operands are 3 and 4. Most Python operators are binary (two operands); a few are unary, such as -x, ~x and not x[1].

Operators are not limited to built-in numbers. Each operator is backed by a "special method" (for example + calls __add__), so any class can define what an operator means for its own objects[2]. The standard library's operator module also exposes every operator as an ordinary function, so operator.add(x, y) is equivalent to x + y[3].

Two kinds of division

Dividing two integers with / always produces a float, while // applied to integers produces an integer equal to the mathematical quotient with the floor function applied[1]. The floor means the result is rounded towards minus infinity, not towards zero: (-1)//2 is -1[4]. This split dates from PEP 238, which separated "true division" (/) from "floor division" (//) and made true division the standard behaviour in Python 3.0[5].

>>> 7 / 2
3.5
>>> 8 / 2
4.0
>>> 7 // 2
3
>>> -7 // 2
-4
>>> 7.5 // 2
3.0

The remainder takes the sign of the divisor

The result of % always has the same sign as its second operand (or is zero), and its absolute value is smaller than that of the second operand. Floor division and modulo are tied together by the identity x == (x//y)*y + (x%y)[1]. The built-in divmod(x, y) returns both parts as the pair (x // y, x % y)[4].

>>> 17 % 5
2
>>> -17 % 5
3
>>> 17 % -5
-3
>>> divmod(-17, 5)
(-4, 3)
>>> x, y = -17, 5
>>> (x // y) * y + (x % y) == x
True

The Python FAQ explains why this rule is useful in practice: if a clock reads 10 now, the hour 200 hours ago is -190 % 12 == 2, a meaningful answer, whereas a result of -10 would be "a bug waiting to bite"[6].

Exponentiation

The power operator ** binds more tightly than a unary operator on its left but less tightly than a unary operator on its right. As a result -1**2 is -1, and 2**-1 is 0.5[1]. Unlike the other arithmetic operators, ** groups from right to left, so 2**3**2 means 2**(3**2)[1]. Python defines 0 ** 0 as 1[4].

>>> -1 ** 2
-1
>>> (-1) ** 2
1
>>> 2 ** -1
0.5
>>> 2 ** 3 ** 2
512
>>> (2 ** 3) ** 2
64
>>> 0 ** 0
1

Floating-point results are approximations

Binary floating point cannot represent most decimal fractions exactly, so summing three values of 0.1 does not give exactly 0.3. The tutorial recommends math.isclose() for comparing inexact values[7].

>>> 0.1 + 0.1 + 0.1 == 0.3
False
>>> import math
>>> math.isclose(0.1 + 0.1 + 0.1, 0.3)
True

Arithmetic operators on other types

For sequences, + means concatenation and * means repetition: s * n is equivalent to adding s to itself n times, and a negative n is treated as 0. The items are referenced, not copied, which is why [[]] * 3 creates three references to the same inner list[4]. The bool type is a subclass of int, so True + 1 equals 2[8].

>>> [1, 2] + [3]
[1, 2, 3]
>>> "ab" * 3
'ababab'
>>> "ab" * -1
''
>>> grid = [[]] * 3
>>> grid[0].append("x")
>>> grid
[['x'], ['x'], ['x']]
>>> True + 1
2

The @ operator was added by PEP 465 for matrix multiplication. Its precedence is the same as *, and no built-in or standard-library type implements it; it exists for libraries such as NumPy[9].

Defining arithmetic for your own class

A class supports an operator by defining the matching special method. If the left operand does not support the operation, Python tries the reflected method of the right operand (for example __rmul__), and a method signals "not supported" by returning NotImplemented[2]. The following two-dimensional vector supports +, -, scalar * on either side, unary -, and uses @ for the dot product.

3Comparison operators

Python has six value-comparison operators, <, <=, >, >=, == and !=; the standard types documentation lists them together with the identity operators is and is not as the eight comparison operations[4].

OperatorMeaningSpecial method
==Equal__eq__
!=Not equal__ne__
<Less than__lt__
<=Less than or equal__le__
>Greater than__gt__
>=Greater than or equal__ge__

The ability to overload each of these six operators separately comes from PEP 207, "Rich Comparisons"[3,10].

Comparisons chain

Comparisons can be chained: x < y <= z is equivalent to x < y and y <= z, except that y is evaluated only once, and z is not evaluated at all when x < y is false[1].

>>> age = 34
>>> 18 <= age < 65
True
>>> 1 < 3 > 2
True
>>> 1 == 1.0 == True
True

Equality across types, ordering and NaN

Unless a type says otherwise, objects of different types never compare equal. The ordering operators are only defined where they make sense, and raise TypeError otherwise, for example when one argument is a complex number[4]. If a class does not define equality, == falls back to comparing object identity[1]. Strings compare by Unicode code point, so two strings that look identical can compare unequal[1]. Not-a-number is not equal to itself: for x = float('NaN'), x == x is false and x != x is true[1].

>>> 1 == 1.0
True
>>> "1" == 1
False
>>> "apple" < "banana"
True
>>> "Zebra" < "apple"
True
>>> [1, 2, 3] < [1, 3]
True
>>> 1j < 2j
Traceback (most recent call last):
  ...
TypeError: '<' not supported between instances of 'complex' and 'complex'
>>> nan = float("nan")
>>> nan == nan, nan != nan
(False, True)
>>> "Ç" == "Ç"
False

Tip. "Zebra" < "apple" is true because every uppercase ASCII letter has a lower code point than every lowercase one. For case-insensitive ordering compare s.casefold() values instead.

4Logical (Boolean) operators

The logical operators are the keywords and, or and not. They work on any object, using Python's truth-value rules. The false values are None and False, zero of any numeric type (0, 0.0, 0j, and so on), and empty sequences and collections such as '', (), [], {}, set() and range(0); other objects are true by default[4]. A class can control its truth value with __bool__, or with __len__ if it does not define __bool__[2].

ExpressionResultEvaluates the right operand?
x or yif x is true, then x, else yOnly if x is false
x and yif x is false, then x, else yOnly if x is true
not xif x is false, then True, else False(unary)

Table adapted from the Boolean operations table in the standard types documentation[4].

They return an operand, not necessarily a bool

and and or return one of their operands unchanged. Because not has to create a new value, it always returns a bool: not 'foo' is False, not ''[1].

>>> 0 or "default"
'default'
>>> "given" or "default"
'given'
>>> [] and 99
[]
>>> 3 and 99
99
>>> not "foo"
False
>>> not []
True

Short-circuit evaluation

and and or are short-circuit operators: the second operand is only evaluated when the first one does not already decide the result[4]. This makes guards such as d and d[0] safe.

Common pitfalls

not has lower priority than the non-Boolean operators, so not a == b means not (a == b), and a == not b is a syntax error[4]. PEP 8 also advises against comparing Boolean values to True or False with ==; write if greeting: instead[11].

The x or default idiom treats every false value as "missing". If 0 or an empty string is a legitimate value, test for None explicitly, as shown in Exercise 3.

5Assignment operators

Plain assignment

An assignment statement evaluates the right-hand side and assigns the single resulting object to each target, from left to right. With several comma-separated targets the object is unpacked, and one target may be "starred" to collect the remaining items into a list[12]. When Python evaluates an assignment, the right-hand side is evaluated before the left-hand side[1].

>>> x = y = 0
>>> x, y
(0, 0)
>>> a, b = 1, 2
>>> a, b = b, a
>>> a, b
(2, 1)
>>> first, *rest = [10, 20, 30, 40]
>>> first, rest
(10, [20, 30, 40])

Augmented assignment

Augmented assignment combines a binary operation and an assignment in one statement. The augmented operators are +=, -=, *=, @=, /=, //=, %=, **=, >>=, <<=, &=, ^= and |=[12]. There is no ++ or --.

x += 1 is similar to x = x + 1, but not exactly the same: the target is evaluated only once, and when possible the operation is performed in place, modifying the existing object instead of creating a new one[12]. In the operator module's terms, x += y is equivalent to x = operator.iadd(x, y)[3]. The difference is visible when two names refer to the same list:

>>> a = [1, 2]
>>> alias = a
>>> a += [3]
>>> alias
[1, 2, 3]
>>> a = a + [4]
>>> alias
[1, 2, 3]
>>> a
[1, 2, 3, 4]
>>> n = 10
>>> n //= 3
>>> n **= 2
>>> n
9

Python 3.9 added | and |= for dictionaries. When a key appears in both operands, the value from the right-hand operand wins[13].

>>> defaults = {"colour": "blue", "size": 10}
>>> defaults | {"size": 12}
{'colour': 'blue', 'size': 12}
>>> settings = dict(defaults)
>>> settings |= {"debug": True}
>>> settings
{'colour': 'blue', 'size': 10, 'debug': True}

Puzzle. Because the in-place step and the assignment step are separate, t[0] += [1] on a tuple t whose first item is a list both extends the list and raises TypeError. The Python FAQ explains that the __iadd__ call succeeds and then the assignment back into the immutable tuple fails[6].

>>> t = ([0],)
>>> t[0] += [1]
Traceback (most recent call last):
  ...
TypeError: 'tuple' object does not support item assignment
>>> t
([0, 1],)

The assignment expression :=

The assignment expression, also called the named expression or "walrus" operator, assigns a value to a name and also returns that value, so it can be used inside a larger expression[1]. It was introduced in Python 3.8 by PEP 572[14]. An unparenthesized assignment expression is not allowed at the top level of an expression statement: y := f(x) is invalid, while (y := f(x)) is valid[14]. It has the lowest precedence of all operators[1], which is why it usually needs parentheses.

6Bitwise operators

Bitwise operators work on the binary representation of integers. Python computes them as if the integer were stored in two's complement with an infinite number of sign bits, so negative numbers behave consistently however large they are[4].

OperatorMeaningExample (binary)Result
&AND0b1100 & 0b10100b1000 (8)
|OR0b1100 | 0b10100b1110 (14)
^XOR (exclusive or)0b1100 ^ 0b10100b0110 (6)

<<Left shift0b0011 << 20b1100 (12)
>>Right shift0b1100 >> 20b0011 (3)

The inversion ~x is defined as -(x+1)[1]. A left shift by n bits is equivalent to multiplying by pow(2, n) and a right shift is equivalent to floor division by pow(2, n); a negative shift count raises ValueError[4].

>>> bin(0b1100 & 0b1010), bin(0b1100 | 0b1010), bin(0b1100 ^ 0b1010)
('0b1000', '0b1110', '0b110')
>>> ~12
-13
>>> ~-1
0
>>> 5 << 3, 5 * 2**3
(40, 40)
>>> -9 >> 1, -9 // 2
(-5, -5)
>>> 1 << -1
Traceback (most recent call last):
  ...
ValueError: negative shift count

Bit flags

Bitwise operators are commonly used to pack several yes/no flags into one integer: | sets a flag, & ~flag clears it, ^ toggles it, and & tests it.

The same symbols on bool, set and dict

Applied to two bool values, &, | and ^ return a bool, but the documentation recommends and, or and != for logic. Using ~ on a bool has been deprecated since Python 3.12 and is scheduled to raise an error in Python 3.16, because ~True is -2, not False[4]. For sets the operators mean intersection, union and symmetric difference[3], and for dicts | means merge[13].

>>> True & False, True | False, True ^ True
(False, True, False)
>>> a, b = {1, 2, 3}, {2, 3, 4}
>>> a & b, a | b, a ^ b
({2, 3}, {1, 2, 3, 4}, {1, 4})

7Membership operators

x in s is True if x is a member of s, and x not in s gives the opposite result[1]. For built-in containers such as lists, tuples, sets and dicts, membership means that some element is identical or equal to x; because iterating over a dict yields its keys, in tests a dict's keys[1,4]. For str and bytes, in tests for a substring, and the empty string is a substring of every string, so "" in "abc" is True[1].

>>> 3 in [1, 2, 3]
True
>>> "x" not in ("a", "b")
True
>>> "gg" in "eggs"
True
>>> "" in "abc"
True
>>> ages = {"ana": 31, "ben": 27}
>>> "ana" in ages
True
>>> 31 in ages
False
>>> 31 in ages.values()
True

How a class supports in

Python looks for three methods in turn. If the class defines __contains__, x in y is true when y.__contains__(x) returns a true value. Otherwise, if it defines __iter__, Python iterates and looks for an item that is or == x. Failing that, it tries __getitem__ with indexes 0, 1, 2, … until it finds a match or gets IndexError[1].

8Identity operators

is and is not test object identity: x is y is true only when both names refer to the very same object, and x is not y gives the inverse result[1]. The test a is b is equivalent to id(a) == id(b)[6]. Unlike ==, the behaviour of is cannot be customized by a class, and is can be applied to any two objects without raising an exception[4].

>>> a = [1, 2, 3]
>>> b = a
>>> c = [1, 2, 3]
>>> a == c, a is c
(True, False)
>>> a is b
True
>>> id(a) == id(b)
True

When identity is guaranteed

The FAQ lists three cases where identity is guaranteed: after new = old, new is old; after storing an object in a container, as in s[0] = x, s[0] is x; and when the object is a singleton such as None[6]. In other cases, including integers and strings, identity is not guaranteed and == is the right test[6]. CPython reuses objects for some small integers, but this is a documented implementation detail of CPython and not a language rule[15].

PEP 8 states that comparisons to singletons like None should always use is or is not, never the equality operators, and recommends x is not None over not x is None[11]. The example below shows why: a class can make == return anything, but it cannot change is.

9Operator precedence

When an expression contains several operators, precedence decides which ones are applied first. The table below runs from the highest precedence (binds most tightly) to the lowest. Operators in the same row have the same precedence and group from left to right, except exponentiation and conditional expressions, which group from right to left[1].

Precedence in practice

Three rules from the table cause most surprises. First, the bitwise operators bind more tightly than comparisons, so x & 1 == 0 means (x & 1) == 0. Second, comparisons, membership tests and identity tests all share one precedence level and chain together[1], so 1 in [1] == True means (1 in [1]) and ([1] == True). Third, not sits below the comparisons, so not a == b means not (a == b)[4].

>>> 2 + 3 * 4
14
>>> (2 + 3) * 4
20
>>> 10 - 4 - 3
3
>>> 2 ** 3 ** 2
512
>>> -2 ** 2
-4
>>> 6 & 1 == 0
True
>>> 1 in [1] == True
False
>>> (1 in [1]) == True
True
>>> not 1 == 2
True
>>> True or False and False
True
>>> "yes" if 0 else "no" or "maybe"
'no'

Precedence is not evaluation order

Precedence only decides how operands are grouped. Python still evaluates expressions from left to right[1], so in f() + g() * h() the call f() runs first even though the multiplication is grouped first.

Style. When precedence is not obvious, add parentheses. PEP 8 also suggests using whitespace to show grouping, for example x = x*2 - 1 and hypot2 = x*x + y*y[11].

10Operators as functions: the operator module

The operator module provides an efficient function for each intrinsic operator, for example add, mul, truediv, floordiv, mod, pow, and_, or_, xor, invert, lshift, is_, is_not, contains, and lt through gt. Note that contains(a, b) computes b in a, with the operands reversed[3]. These functions are handy wherever a function is expected, such as functools.reduce, map or a sort key; itemgetter and attrgetter build key functions that fetch an item or attribute[3].

>>> import operator
>>> from functools import reduce
>>> reduce(operator.mul, [1, 2, 3, 4, 5])
120
>>> list(map(operator.pow, [2, 3, 4], [2, 2, 2]))
[4, 9, 16]
>>> operator.contains([1, 2, 3], 2)
True
>>> inventory = [("apple", 3), ("banana", 2), ("pear", 5)]
>>> sorted(inventory, key=operator.itemgetter(1))
[('banana', 2), ('apple', 3), ('pear', 5)]

11Exercises

Try each exercise before opening its solution. The solutions were run on CPython 3.13 and show their real output.

Exercise 1 · Predict the arithmetic

Without running them, predict the value of each expression: 7 // -2, -7 % 3, 2 ** 3 ** 2, -3 ** 2, 10 / 5.

Show solution 
>>> 7 // -2
-4
>>> -7 % 3
2
>>> 2 ** 3 ** 2
512
>>> -3 ** 2
-9
>>> 10 / 5
2.0

// rounds towards minus infinity, so −3.5 becomes −4. The remainder takes the sign of the divisor, so -7 % 3 is 2 (and -3 * 3 + 2 == -7). ** groups right to left and binds more tightly than the unary minus on its left. / always gives a float[1,4].

Exercise 2 · Leap years

Write is_leap(year) as a single expression using only %, ==, !=, and and or. A year is a leap year if it is divisible by 4, except century years, which must also be divisible by 400.

Show solution

The parentheses matter: and binds more tightly than or[1], so without them the expression would mean (year % 4 == 0 and year % 100 != 0) or year % 400 == 0, which happens to be correct too. Writing the parentheses makes the intent clear either way.

Exercise 3 · Fix the default value

This function is meant to use 10 retries when the caller passes nothing, but retries(0) returns 10. Explain why and fix it.

def retries(n=None):
    return n or 10
Show solution

or returns its right operand whenever the left operand is false, and 0 is false[4]. Test for the "missing" marker with is, as PEP 8 recommends for None[11].

Exercise 4 · Count the set bits

Write popcount(n) that returns how many 1 bits a non-negative integer has, using only &, >> and += (no bin() or string methods).

Show solution

n & 1 isolates the lowest bit, and n >>= 1 is floor division by 2[4]. A faster trick is n &= n - 1, which clears the lowest set bit in one step.

Exercise 5 · Use the walrus

Rewrite this code so that parse(s) is called only once per string and the result is kept when it is not None.

results = [parse(s) for s in data if parse(s) is not None]
Show solution

The assignment expression binds n and yields its value in one step[1,14]. It must be parenthesized here because := has lower precedence than is not[1].

Exercise 6 · A container that supports in

Write a class Multiples(k) so that x in Multiples(3) is true for every integer divisible by 3, including negative ones. It cannot store the multiples, since there are infinitely many.

Show solution

Defining __contains__ lets in answer without iterating, and not in returns the inverse automatically[1].

Exercise 7 · Precedence puzzles

Predict each result, then add parentheses to show how Python groups it: 3 & 1 == 1, not 0 == 1, 2 * 3 ** 2, False == False in [False], 1 + 2 << 3.

Show solution 
>>> 3 & 1 == 1
True
>>> not 0 == 1
True
>>> 2 * 3 ** 2
18
>>> False == False in [False]
True
>>> 1 + 2 << 3
24
  • (3 & 1) == 1: & binds more tightly than ==.
  • not (0 == 1): not is below the comparisons.
  • 2 * (3 ** 2): ** is above *.
  • (False == False) and (False in [False]): == and in share a level and chain.
  • (1 + 2) << 3: + is above the shifts.

All five follow from the precedence table[1].

Exercise 8 · Identity versus equality

Predict the output, then explain each line.

x = [1, 2]
y = [1, 2]
z = x
print(x == y, x is y, x is z)
z += [3]
print(x, x is z)
z = z + [4]
print(x, x is z)
Show solution

x and y are equal but separate lists. z = x binds a second name to the same object, which guarantees z is x[6]. z += [3] extends that list in place, so x sees the change[12]. z = z + [4] builds a new list and rebinds only z.
