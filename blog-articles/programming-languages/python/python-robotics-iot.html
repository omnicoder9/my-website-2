1Overview

Robotics and the Internet of Things (IoT) both join software to the physical world. A device reads sensors, decides what to do, drives actuators such as motors and LEDs, and usually talks to other machines over a network. Python is used at almost every layer of that stack, though it runs in different forms at each layer.

  • On a Linux single-board computer such as the Raspberry Pi, ordinary CPython controls the 40-pin general-purpose input/output (GPIO) header directly[1]. Libraries such as GPIO Zero, which Raspberry Pi OS includes[1], wrap the pins in objects like LED and Button.
  • On a microcontroller, MicroPython provides “a lean and efficient implementation of the Python 3 programming language” with a small subset of the standard library, able to run in as little as 256 KB of code space and 16 KB of RAM[2].
  • Between devices, the MQTT publish/subscribe protocol is designed to be light and simple to implement, which suits machine-to-machine and IoT use[3].
  • On the robot itself, ROS 2 connects many small programs (nodes) through typed messages, and rclpy is its Python client library[4]. OpenCV supplies the computer-vision algorithms; it is an open-source computer vision and machine learning library with more than 2500 optimised algorithms and C++, Python, Java and MATLAB interfaces[5].

This article works from the wire upwards. Sections 2 to 4 cover electrical basics and the buses that connect chips; section 5 moves to microcontrollers; section 6 connects devices over a network; sections 7 and 8 add vision; section 9 brings everything into ROS 2; and section 10 closes the loop with feedback control.

How the code was tested

Code that can run without hardware was run, and its real output is printed underneath. That includes GPIO Zero programs on simulated pins, a serial link over a software loopback, MicroPython programs on the MicroPython Unix port, MQTT against a local Mosquitto broker, and OpenCV on synthetic images. Code that needs a real board, camera or ROS 2 installation carries an Untested badge: it was checked for valid syntax but not run. A recurring pattern is to put the decision logic in a plain function, test that function anywhere, and keep the hardware-specific wrapper thin.

2Hardware interface basics

Before writing code that touches a pin it is worth knowing what the pin can do electrically, because mistakes here damage hardware rather than raise exceptions.

Digital input and output

A GPIO pin is either an input, which reads a voltage as high or low, or an output, which drives a voltage. Raspberry Pi GPIO pins operate at 3.3 V and are not 5 V tolerant[1]. An individual pin can supply up to 16 mA, and all GPIO pins together a maximum of 50 mA[1]. That is enough for an LED with a resistor, but never enough to drive a motor directly: motors need a driver board between the pin and the load.

An input that is connected to nothing “floats” and reads random values, so inputs are tied to a known level with a pull-up or pull-down resistor. GPIO Zero's Button enables the internal pull-up by default, so the button is wired between the pin and ground[6]. Pins GP2 and GP3, the I²C pins, have fixed 1.8 kΩ pull-up resistors on the board[1].

PWM and analogue values

Pulse-width modulation (PWM) switches a pin on and off rapidly; the fraction of time it is on (the duty cycle) controls the average power delivered to devices such as motors and LEDs[1]. Hobby servos use the pulse width itself as a position command: GPIO Zero's Servo defaults to pulses between 1 ms and 2 ms in a 20 ms frame[7].

The Raspberry Pi has no analogue inputs on its header, so analogue sensors are read through an external analogue-to-digital converter (ADC) on a bus. Microcontrollers usually have ADCs built in: on the RP2 port of MicroPython, ADC.read_u16() returns 0–65535 across 0–3.3 V[8].

Reading a datasheet: bytes to values

Sensor drivers mostly turn raw register bytes into physical units, and that is ordinary Python. The Texas Instruments TMP102 temperature sensor is a typical example. Its temperature register holds a 12-bit value in which one least-significant bit equals 0.0625 °C, and negative temperatures are stored in two's complement[10]. The datasheet's table gives 25 °C as 0x190 and −25 °C as 0xE70[10]. The 12 bits arrive left-justified in two bytes, so they need shifting right by four.

The output matches the datasheet: 0x190 is 25 °C, 0x004 is 0.25 °C, 0xFFC is −0.25 °C and 0xE70 is −25 °C[10]. Because the function takes plain integers it can be tested on any computer, which is exactly the habit to build. Exercise 1 rewrites it with int.from_bytes().

3Raspberry Pi and GPIO Zero

GPIO Zero is “a simple interface to GPIO devices with Raspberry Pi”, maintained by Ben Nuttall and Dave Jones[11]. Instead of configuring pins and polling registers, you create objects that represent devices. It uses Broadcom (BCM) numbering, so LED(17) means GPIO17, which is physical pin 11; the string "BOARD11" names the same pin by its physical position[11].

Pin factories and simulated pins

GPIO Zero does not talk to the hardware itself. A pin factory does, and the library tries the lgpio, RPi.GPIO, pigpio and native factories in that order unless the GPIOZERO_PIN_FACTORY environment variable picks one[12]. One more factory, MockFactory, simulates pins entirely in software; it is never loaded by default and must be selected explicitly[12]. A mock pin can be driven high or low from code to imitate a button press[12]. That makes it possible to test GPIO programs on a laptop or in continuous integration, which is how the next listing was run.

Callbacks such as when_pressed take a function. The recipes page warns that writing say_hello() with parentheses calls the function at once and assigns its return value, None, instead[11]. GPIO Zero also has a declarative style in which one device's values feed another, for example led.source = button[11].

PWM, motors and robots

PWMLED sets brightness from 0.0 (off) to 1.0 (fully on) with a default PWM frequency of 100 Hz, and Motor takes a speed from 0 to 1 in forward() and backward()[7]. A Robot combines two motors, built as Robot(left=Motor(4, 14), right=Motor(17, 18)) in the recipes[11]. On mock pins, PWM needs the MockPWMPin class[12].

The signed motor.value, from −1 for full speed backward to 1 for full speed forward, matches the documentation[7]. On a real robot the two pins would go to a motor driver, never straight to the motor.

A real sensor: ultrasonic distance

The HC-SR04 ultrasonic sensor is a common first robot sensor. GPIO Zero's DistanceSensor reads it and reports distance in metres, with max_distance defaulting to 1 m[6]. The sensor's ECHO pin outputs 5 V, so the documentation calls for a voltage divider to protect the Pi[6]; this ties back to the 3.3 V limit in section 2.

Installing Python packages on Raspberry Pi OS

From Raspberry Pi OS Bookworm onwards, pip installs only into a virtual environment; the documentation explains that this change comes from the Python community's PEP 668, not from Raspberry Pi[13]. PEP 668 lets a distribution mark its Python as “externally managed”, so that pip refuses to modify it globally and directs users to a virtual environment[14]. Use python3 -m venv for your project, or the distribution's own apt packages, which are built specifically for Raspberry Pi OS[13].

4I²C, UART and SPI from Python

I²C with smbus2

On Linux, user programs reach I²C through device files named /dev/i2c-N, one per adapter, provided by the i2c-dev kernel module; an ioctl call selects the target device's address, normally a 7-bit address[15]. The smbus2 package is a pure-Python replacement for the python-smbus bindings and wraps that ioctl interface directly[16]. Its main calls are read_byte_data(), write_byte_data() and read_i2c_block_data(), whose maximum length is 32 bytes because of the Linux SMBus implementation; i2c_rdwr() handles longer combined transactions[17]. The documentation recommends opening the bus in a with block so it is closed even after an exception[17].

A good driver does not create the bus itself. It receives a bus object, so the same class runs against the real SMBus on a Pi and against a fake in a test. The TMP102 has a pointer register in which 0 selects the temperature register and 1 the configuration register, and its address is 0b1001000 (0x48) when the ADD0 pin is tied to ground[10].

On the Pi itself the only change is the bus object. The listing below assumes I²C is enabled and the sensor is wired to GP2/GP3, which appear as bus 1.

UART with pySerial

pySerial opens serial ports by name (/dev/ttyUSB0, COM3) or by URL[18]. The Serial constructor defaults to 9600 baud, eight data bits, no parity and one stop bit[19]. The timeout argument decides how reads behave: None waits until the requested bytes arrive, 0 returns immediately, and a number of seconds returns whatever arrived when it expires[19]. write() takes bytes, so strings must be encoded first[19].

The loop:// URL simulates a loopback connection in which everything sent is received back, which the documentation recommends for testing[18]. The next program uses it to test a parser for a line-based sensor protocol.

Replacing "loop://" with the real device name is the only change on hardware. Always set a timeout on a real port, otherwise a disconnected device leaves read() waiting forever[19].

SPI

SPI uses separate data lines in each direction plus a clock and one chip-enable line per device[1]. Devices are selected by their chip-enable line rather than by an address. On a Pi the third-party spidev package is the usual way to reach the SPI device files from Python, and on a microcontroller machine.SPI plays the same role[20]. The driver pattern is the same as for I²C: decode bytes in a pure function and inject the bus.

5MicroPython

A microcontroller has no operating system, a few hundred kilobytes of RAM and direct control of its pins. MicroPython is optimised for exactly that kind of constrained environment[2]. The Raspberry Pi Pico's RP2040 chip, for example, has a dual-core M0+ processor clocked at up to 133 MHz and 264 kB of SRAM; the Pico 2's RP2350 raises that to 150 MHz and 520 kB[21].

To install MicroPython on a Pico you hold the BOOTSEL button while plugging it in, then copy the board's UF2 firmware file onto the USB drive that appears[22]. The mpremote tool (installed with pip) then gives you a REPL, copies files with mpremote fs cp main.py :main.py, runs a local script from RAM with mpremote run, and installs packages with mpremote mip install[23].

The machine module

Hardware access goes through machine, which offers classes such as Pin, PWM, ADC, UART, SPI, I2C, Timer and WDT[20]. The documentation warns that these functions give “direct and unrestricted access” to hardware and that misuse can crash the board or, in extreme cases, damage it[20]. A Pin is created with a mode such as Pin.IN or Pin.OUT and an optional pull such as Pin.PULL_UP, and its value(), on() and off() methods read or set the level[24].

Raspberry Pi's own blink example toggles the Pico's on-board LED from a periodic timer rather than a sleep loop[25]:

On the original Pico the LED is on GP25, but on the Pico W it is wired to the wireless chip, which is why the example uses the name "LED" rather than a number[21]. Timer callbacks on the RP2 port run as soft interrupts by default, so they can allocate memory but may be delayed by garbage collection[8]. Hard interrupt handlers are stricter: keep them short, avoid allocating memory (no list appends, no floating point), and pass longer work to micropython.schedule()[26].

Reading a sensor on a microcontroller

machine.I2C provides scan(), which returns the addresses between 0x08 and 0x77 that respond, and readfrom_mem(), which reads bytes starting at a register[27]. On the Pico the default pins for bus 0 are SCL on GP5 and SDA on GP4[8]. The TMP102 decoding from section 2 is unchanged, because MicroPython supports int.from_bytes(); only the bus call differs.

The sign is extended by hand because int.from_bytes() in MicroPython is not a full copy of CPython's. On the MicroPython 1.22 Unix port used for this article, passing signed=True raised TypeError: function doesn't take keyword arguments, and passing True positionally was silently ignored, returning 59136 instead of −6400 for the bytes E7 00. Test such details on the firmware you deploy.

6Connecting devices with MQTT

MQTT is a client–server publish/subscribe messaging transport[3]. Clients never talk to each other directly. A sensor publishes a message on a topic such as lab/bench1/temperature to a broker, and the broker forwards it to every client subscribed to a matching topic. Topics need no configuration: publishing on one is enough, and slashes form a hierarchy like a file path[31].

  • Wildcards. + matches exactly one level and # matches all remaining levels and must come last; so a/+/c/d and a/# both match a/b/c/d, but a/b/c does not[31].
  • Quality of service. QoS 0 is “at most once” and messages may be lost; QoS 1 is “at least once” and duplicates may occur; QoS 2 is “exactly once”[3].
  • Retained messages. When a client publishes with the RETAIN flag set, the server stores the message and sends it to any client that subscribes later, marked as retained[32]. That gives a new dashboard the last known value at once[31].

The Eclipse Paho client is the usual Python library. Version 2 asks you to choose the callback API explicitly when creating a Client; connect() defaults to port 1883 with a 60-second keep-alive, and loop_start() runs the network loop in a background thread[33]. The program below publishes a retained reading, connects a second client that receives it, then publishes a live reading. It ran against a local Mosquitto broker.

The first message carries retain=True because it was delivered from the broker's store when the subscription was made; the second, delivered on an existing subscription, carries retain=False[32]. A zero-byte retained message is not stored, which is how the last line removes the retained value[32]. On a MicroPython board, client libraries are installed with mpremote mip install, which fetches packages from micropython-lib, GitHub or GitLab[23].

7OpenCV fundamentals

OpenCV's Python package, imported as cv2, comes from PyPI in four variants. The headless ones leave out GUI functions such as cv2.imshow(), which suits servers and robots without a display, and only one variant should be installed in an environment[34]. The examples here used opencv-python-headless.

Images are NumPy arrays

OpenCV represents an image as a NumPy array: img.shape gives rows, columns and channels (grayscale images have no channel dimension), img.dtype is usually uint8, and colour pixels are stored in BGR order, not RGB[35]. A region of interest is just a NumPy slice[35]. All examples in this section build synthetic images, so they run anywhere and their output is reproducible.

The blue rectangle and red circle become different gray levels because the conversion weights the channels differently. Note the two coordinate conventions: drawing functions take (x, y) points, while NumPy indexing is [row, column], that is [y, x].

Thresholding, contours and moments

cv2.threshold() returns two values, the threshold used and the thresholded image[36]. With the THRESH_OTSU flag OpenCV picks the threshold itself from the histogram, which works best when the image has two clear peaks[36]. Contours found in the binary image can then be measured: cv2.moments() gives the centroid as cx = M10/M00 and cy = M01/M00, cv2.contourArea() gives the area, and cv2.boundingRect() an upright bounding box[37].

The centroids land within a pixel of the centres used to draw the shapes, despite the added noise. Blurring before thresholding removes the speckle that would otherwise become hundreds of one-pixel contours.

8Computer vision for robots

Robots rarely need to understand a whole scene. Usually they need one number: how far the line is from the centre, where the ball is, which marker is in view. This section shows three classic techniques that produce such numbers, and then how frames get from a camera into them.

Colour tracking in HSV

Colour is easier to segment in HSV (hue, saturation, value) than in BGR, because hue stays fairly constant as lighting changes brightness. OpenCV converts with cv2.cvtColor(frame, cv2.COLOR_BGR2HSV) and builds a mask with cv2.inRange(); its tutorial tracks a coloured object by converting each frame to HSV, thresholding a hue range and extracting the object[38]. OpenCV's hue runs from 0 to 179, not 0 to 360, while saturation and value run 0 to 255[38]. Red sits at both ends of the hue circle, so it needs two ranges.

The morphological opening removes isolated pixels before the contour search. The steering error is the kind of single number that a control loop (section 10) or a ROS 2 node (section 9) consumes.

Edges with Canny

The Canny detector, developed by John F. Canny, runs in stages: a 5×5 Gaussian filter to reduce noise, Sobel gradients, non-maximum suppression to thin edges, and hysteresis thresholding in which pixels above maxVal are edges and pixels between minVal and maxVal are kept only if connected to strong edges[39].

The step of 130 gray levels gives a horizontal Sobel response of 4 × 130 = 520, comfortably above the first two pairs of thresholds, so both find the same outline; the third pair sits above the gradient and finds nothing. Tuning these thresholds for the lighting is a routine part of deploying vision on a robot.

Fiducial markers: ArUco

When a robot needs to know exactly where something is, it is often easier to put a marker on it than to recognise it. An ArUco marker is a square with a wide black border and an inner binary matrix that encodes its id; generateImageMarker() draws one and ArucoDetector.detectMarkers() returns each marker's four corners, clockwise from the top left, together with its id[40]. The tutorial advises choosing the smallest dictionary that fits the application[40].

The angle of the top edge recovers the 15° rotation (negative, because image y points down and OpenCV's positive rotation angle is counter-clockwise). Turning corners into a 3-D position and orientation needs the camera matrix and distortion coefficients from a calibration, which cv2.solvePnP() then uses[40].

Getting frames from a camera

For USB webcams, cv2.VideoCapture(0) opens the first camera; the loop checks the returned flag on every read() and releases the camera at the end[41]. The Raspberry Pi Camera Module is driven by the libcamera stack[42], and its Python library is Picamera2, the libcamera-based replacement for the old Picamera, which Raspberry Pi recommends installing with apt rather than pip[43]. The original Picamera library has been deprecated for many years and is unsupported[42].

The Picamera2 loop follows the structure of the library's own OpenCV example, which captures with captured_request() and hands the arrays to OpenCV[44]. Check the channel order of the format you configure before feeding it to colour code written for BGR.

9ROS 2 with rclpy

ROS 2, the second generation of the Robot Operating System, was redesigned from ROS 1 to support teams of multiple robots, small embedded computers, real-time control, networks that lose or delay packets, and the move from lab prototype to product[45]. Its communication is built on DDS, an Object Management Group publish/subscribe standard whose distributed discovery lets programs find each other without a central master[46]. ROS 1 needed a master process for this[47].

Core concepts

  • Nodes are the processes (or parts of processes) that make up the system. Unlike ROS 1, ROS 2 can run several nodes in one process[47].
  • Topics carry a stream of typed messages from publishers to subscribers; communication is one-way[51].
  • Services are request–response calls[52].
  • Actions are for goals that take a long time: the client sends a goal, the server sends feedback while working and a result at the end, and the client may cancel[51].
  • Parameters are hosted by individual nodes, typed as booleans, 64-bit integers, doubles, strings or homogeneous arrays of these[53].
  • Quality of service (QoS) profiles set history depth, reliability and durability. For sensor data, timely delivery matters more than delivering every sample, so the sensor-data profile uses best-effort reliability and a small queue[54].
  • Launch files describe which nodes to start and with what configuration, and ROS 2 launch files can be written in Python[47,55]. Packages are built with colcon, the universal build tool chosen for ROS[56].

ROS also fixes conventions that make packages interoperable: SI units (metres, seconds, radians) and right-handed body frames with x forward, y left and z up[57]. A mobile base is typically commanded with a geometry_msgs/Twist, which “expresses velocity in free space broken into its linear and angular parts”[58].

10Control loops and timing

PID control

Most actuators are driven by feedback: measure, compare with the target, correct. The proportional-integral-derivative (PID) controller is the most common form; Åström and Murray devote a chapter to it, including the practical problem of integrator windup, where the integral term grows while the actuator is saturated[63]. The speed settles on 60 rad/s and then follows the step down to 30. Gains like these are found by tuning on the real system; the simulation only checks that the code behaves sensibly before hardware is involved.

Running a loop at a fixed rate

A control loop needs a steady period. time.monotonic() is the right clock for this, because it cannot go backwards and is not affected by system clock updates[64]. time.sleep() may sleep longer than requested “by an arbitrary amount” because of other activity on the system[64], so the loop below schedules each wake-up from a fixed start time rather than sleeping a fixed amount after each iteration, which would let errors accumulate.

The numbers vary from run to run; on a busy machine the maximum can be several milliseconds late. That is acceptable for soft real-time work, where a missed deadline lowers quality, but not for hard real-time work, where missing a deadline counts as a system failure[65]. Dynamic memory allocation is a common source of timing jitter[65], and CPython allocates objects as it runs. The usual architecture is therefore to keep hard real-time loops (motor current control, for example) on a microcontroller or dedicated driver, and let Python on the main computer handle planning, vision and coordination at tens of hertz.

11Safety and common pitfalls

  • Voltage. Raspberry Pi GPIO is 3.3 V and not 5 V tolerant; only the 5 V power pins are designed to carry 5 V[1]. Use level shifters or voltage dividers for 5 V signals such as the HC-SR04 echo[6].
  • Current. Stay within 16 mA per pin and 50 mA in total[1]. Motors, solenoids and relays need a driver and their own supply, with grounds connected.
  • Pin numbering. GPIO numbers are not physical pin numbers[1]. GPIO Zero uses BCM numbers unless you write "BOARD11"-style names[11].
  • Floating inputs. Use pull-up or pull-down resistors, and software debounce (bounce_time on a GPIO Zero Button) for mechanical switches[6].
  • Blocking reads. A serial read with no timeout blocks until data arrives[19]. Always set a timeout and handle a short read.
  • Tick arithmetic. On MicroPython, compare tick values with ticks_diff(), never by subtraction[28].
  • Interrupt handlers. Keep them short and free of allocation; defer work with micropython.schedule()[26].
  • Colour order. OpenCV images are BGR[35]; libraries that return RGB need a conversion first.
  • Coordinate frames. In ROS, x is forward, y left, z up, and angles are radians[57]. A wrong sign on angular.z makes a robot turn away from its target.
  • Fail safe. Decide what the robot does when input stops: the follower above stops and searches when it loses the target. Hardware watchdogs (machine.WDT) reset a microcontroller whose program hangs[20].

Create a synthetic 200×400 image of a conveyor with five bright parts of different sizes and some salt noise. Count the parts, ignoring blobs under 50 px², and print them sorted by area, largest first, with their centroids[36,37].

Show solution

Every noise pixel becomes a tiny contour, so the area filter does the real work. A median blur (cv2.medianBlur(img, 3)) before thresholding would remove salt noise even more cleanly.

Exercise 7: Line-following errorComputer vision

A downward-facing camera sees a dark line on a light floor. Write line_error(gray) that looks only at the bottom quarter of the frame, finds the line's centroid, and returns the steering error in [−1, 1], or None if no line is visible. Test it with a line that slants across a 160×120 image and with an empty floor.

Show solution

Looking only at the bottom of the image reports where the line is under the robot now, not where it will be. Line followers often combine a near and a far region to anticipate curves. The pixel-count check matters: Otsu always picks some threshold, even on an empty floor, so without it the function would report noise as a line.

Exercise 8: Anti-windup mattersControl

Remove the anti-windup condition from the PID class in section 10 so it always integrates, and run both versions on the motor model with the command limited to ±0.3 (so the motor cannot reach 60 rad/s quickly). Compare the peak speed and the overshoot[63].

Show solution

While the output is pinned at its limit, the unclamped integrator keeps accumulating error. When the speed finally reaches the target, that stored integral pushes it well past, and it takes time to unwind. The clamped version barely overshoots.

Exercise 9: Emergency stop from a range scanROS 2

A ROS laser scanner publishes a list of ranges in metres, where readings can be inf (nothing in range) or nan (invalid). Write a pure function should_stop(ranges, angle_min, angle_increment, stop_distance=0.4, half_width_deg=30) that returns True if any valid reading within ±30° of straight ahead is closer than stop_distance. Angles are in radians and 0 is straight ahead, following REP 103[57]. Then sketch the node that would use it.

Show solution

math.isfinite() rejects both inf and nan in one test; note that nan < 0.4 is simply False, so forgetting the check would not crash, but treating inf differently from nan is a common source of bugs. In a real system the stop should also be enforced below ROS, for example by a motor controller that stops when commands stop arriving.
