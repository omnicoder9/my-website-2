1Overview

A conditional statement runs a block of code only when some condition holds. Python has two compound statements for this. The if statement, with optional elif and else clauses, tests a series of expressions and runs the block belonging to the first one that is true[1]. The match statement, added in Python 3.10, compares one value against a series of patterns and runs the block of the first pattern that fits[1,2].

Python has no switch statement. The tutorial describes an if … elif … elif chain as the substitute for the switch or case statements found in other languages[3]. The match statement looks similar to a C or Java switch, but the tutorial notes that it is closer to the pattern matching found in languages such as Rust or Haskell[3].

This article assumes you can already run a Python script and know the basic data types. It covers each clause in turn, then the pattern kinds that match supports, and ends with eight exercises with worked solutions.

2Conditions and truth values

The condition in an if or elif clause does not need to be a bool. Any object can be tested for truth value[4]. By default an object is true unless its class defines a __bool__() method that returns False or a __len__() method that returns zero[4]. The built-in objects that are false are:

  • the constants None and False;
  • zero of any numeric type: 0, 0.0, 0j, Decimal(0), Fraction(0, 1);
  • empty sequences and collections: '', (), [], {}, set(), range(0)[4].

Everything else is true, including the string "0" and a list that contains a zero.

Your own classes take part in the same rules. Defining __len__() is enough to make an empty container behave as false in a condition[4].

3The if statement

The language reference gives the full grammar of the statement in one rule[1]:

A suite is the indented block of statements that belongs to a clause. Python uses the leading whitespace of each line to work out its indentation level, and the indentation level decides how statements are grouped[5]. There are no braces. The block ends at the first line that returns to the outer indentation level. PEP 8, the standard style guide, recommends 4 spaces per indentation level[6]. Mixing tabs and spaces in a way that makes the meaning depend on the width of a tab raises a TabError[5].

If temperature were 25, the two indented lines would be skipped and only the last line would print.

4The else clause

An else clause gives the statement a block to run when every condition before it is false[1]. It takes no condition of its own and must come last. Exactly one of the two blocks below runs on each call.

5The elif clause

The keyword elif is short for “else if”. An if statement may have zero or more elif clauses, and using them avoids the deep indentation that nested if … else blocks would cause[3].

Only the first true branch runs

The reference states the evaluation rule precisely. Python evaluates the conditions one by one until it finds one that is true, runs that suite, and does not execute or evaluate any other part of the statement. If all the conditions are false, the else suite runs, if there is one[1]. Two consequences follow.

6Writing good conditions

Comparison chains and Boolean operators

Comparisons can be chained. x < y <= z means x < y and y <= z, except that y is evaluated only once[7]. The operators and and or short-circuit: x and y evaluates y only if x is true, and x or y evaluates y only if x is false[4]. They also return the last operand they evaluated rather than a strict True or False[7]. The operator not has lower priority than non-Boolean operators, so not a == b means not (a == b)[4].

Testing for None and for emptiness

PEP 8 recommends comparing to singletons such as None with is or is not, never with ==. It also advises against comparing Boolean values to True or False with ==, and recommends relying on the fact that empty sequences are false[6]. When None and an empty value mean different things, test for None explicitly first.

Conditional expressions

For choosing between two values, Python has a conditional expression, written x if C else y, which was introduced by PEP 308 in Python 2.5[8]. Python evaluates the condition C first. If it is true, Python evaluates and returns x. Otherwise it evaluates and returns y[7]. The branch that is not chosen is never evaluated.

Assignment expressions in a condition

The grammar above uses assignment_expression for each condition, so a condition may contain the “walrus” operator :=[1]. PEP 572, which added the operator in Python 3.8, names the header of an if statement as one of its main uses[9]. It lets you compute a value, test it and keep it in one step.

Flattening nested conditions

Deeply nested if blocks are hard to read. Inside a function, you can often replace them with guard clauses: test each failure case first and return early, so the main logic stays at one indentation level. Both functions below give the same results.

7The match statement

Structural pattern matching arrived in Python 3.10, which was released on 4 October 2021[2]. It is specified in three PEPs: PEP 634 (the specification)[10], PEP 635 (the motivation and rationale)[11] and PEP 636 (a tutorial)[12]. Code that uses match will not run on Python 3.9 or earlier.

The grammar is reproduced from the language reference[1]. The statement works in three steps:

  1. Python evaluates the subject expression after match. If it contains a comma, Python builds a tuple from it[1].
  2. Python tries each case pattern against the subject, from top to bottom. A pattern may bind names to parts of the subject as it matches[1].
  3. The block of the first matching case runs, and no other block does. If no case matches, no block runs[3].

Unlike a C switch, there is no fall-through and no break. The | symbol combines alternatives in one case[3]. The final case _: is a wildcard that never fails to match[3], so it plays the role of default in other languages, and of else in an if statement.

Without a wildcard case, a subject that matches nothing simply skips the whole statement. No exception is raised:

match and case are soft keywords

The names match, case and _ act as keywords only inside a match statement[5]. PEP 635 explains why. The word match is so common in existing code that making it a reserved keyword would have broken almost every existing program, so it stays a soft keyword and the change remains backwards compatible[11]. Bindings and scope

Names bound by a successful match keep their values after the match statement ends. The reference also warns that a failed match may still bind some names. Do not rely on those bindings, and do not assume that variables are unchanged after a failed match[1,10].

8Pattern kinds

A pattern describes the shape a value must have. The reference defines literal, capture, wildcard, value, group, sequence, mapping and class patterns, which can be combined with OR patterns and AS patterns[1]. The table summarises them, and each one is demonstrated below.

Capture patterns versus value patterns

This distinction causes the most common match bug. A bare name such as RED in a case is a capture pattern: it always succeeds and assigns the subject to that name[1]. It never compares against an existing variable. To compare against a named constant, the name must be dotted, such as Color.RED, so that it is read as a value pattern[3]. A value pattern succeeds when the subject compares equal to the value with ==[1].

Because a bare-name capture matches everything, any case after it could never run. A capture or wildcard pattern without a guard is irrefutable, and a match statement may have at most one irrefutable case block, which must be last[1]. Python rejects the mistake when it compiles the file:

Sequence patterns

Sequence patterns use list or tuple syntax and match by position. PEP 636 builds its tutorial around a text adventure that splits a command into words and matches the resulting list[12]. A pattern such as [action, obj] matches any sequence of exactly two elements, and a starred name such as *objects collects the remaining elements into a list[12]. A sequence pattern may contain at most one starred subpattern[1].

Strings are sequences in most of Python, but not here. A subject of type str, bytes or bytearray never matches a sequence pattern[1]. This stops "ab" from being taken apart into "a" and "b" by accident.

Mapping patterns

Mapping patterns use dictionary syntax. The pattern succeeds when every key it lists is present in the subject and each value matches its subpattern[1]. Unlike sequence patterns, mapping patterns ignore extra keys, and **rest collects whatever keys the pattern did not name[3]. This makes mapping patterns well suited to JSON-like data.

Class patterns

A class pattern such as Point(x=0, y=0) first checks the type with isinstance()[10] and then matches the named attributes. Positional subpatterns such as Point(0, y) rely on the class attribute __match_args__, which lists the attribute names in positional order[3]. A class decorated with @dataclass gets __match_args__ automatically, built from the parameters of its generated __init__()[13]. Patterns can be nested, as the Circle case shows.

A group of built-in types, including bool, int, float, str, bytes, list, tuple, dict and set, handle a single positional subpattern differently: it is matched against the whole subject rather than an attribute[1]. So int(n) means “an int, bound to n”. Order the cases with care, because bool is a subclass of int[4] and True would otherwise land in the int case.

Guards and AS patterns

A guard is an if clause added after a pattern. If the guard is false, matching moves on to the next case block[3]. The guard is checked only after the pattern has matched and its variables have been bound, so it can use them[12]. Guards are evaluated in order, one case at a time, and evaluation stops once a case is selected[1]. A case with a guard is never irrefutable, even when its pattern is[1].

An AS pattern, P as NAME, matches P and binds the whole matched subject to NAME[1]. It is most useful with an OR pattern, where you want to know which alternative matched. Each alternative in an OR pattern must bind the same set of names[1].

10Common pitfalls

  • Overlapping elif conditions in the wrong order. Only the first true branch runs[1], so a broad test placed early hides later branches.
  • x == a or b. This parses as (x == a) or b. Since or returns an operand[7], it yields b whenever x != a, which is usually true. Write x in (a, b). Exercise 2 shows the bug.
  • Using == with None. Use is None[6].
  • Treating 0, "" and None as the same. All three are false[4]. When they mean different things, test for them separately.
  • A bare name in a case. It captures instead of comparing[1]. Use a dotted name such as Color.RED for constants[3].
  • Expecting a string to match [first, *rest]. Strings never match sequence patterns[1].
  • Putting int() before bool() in class patterns. bool is a subclass of int[4], so True is caught by the int case.
  • Relying on variables after a failed match. Their state is not guaranteed[1].
