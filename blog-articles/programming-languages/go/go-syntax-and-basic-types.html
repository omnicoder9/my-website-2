Go Syntax and Basic Types

Variables, constants, primitive types, conversions, operators, comments and code conventions, explained against the language specification.

Go 1.24 · Every listing compiled, run and checked with gofmt and go vet (go1.24.7, linux/amd64) · Outputs shown are the real outputs · October 2026

1. Introduction

Go is a statically typed, compiled language with a deliberately compact specification and a design that deliberately favours explicitness over convenience.[1,2] There are no implicit numeric conversions, no uninitialised variables, no operator overloading, and a single canonical source format enforced by a tool.[1,3,4] Those decisions show up most clearly in the parts of the language covered here: how values are declared, what types they can have, how they combine through operators, and how the code that manipulates them is written down and documented.

The article follows the order of a typical learning path. Each section states the rule, cites where it is defined, and shows a complete program together with the output it actually produces. Where a rule is enforced by the compiler, the real compiler message is shown. Section 13 contains eight exercises with worked solutions.

How to run the examples

Every listing is a complete package main. Save it as main.go and run go run main.go, or paste it into the Go Playground. Outputs that depend on the platform (for example the size of int) were produced on 64-bit Linux.

2. Program structure and tokens

A Go source file starts with a package clause, followed by import declarations, followed by top-level declarations of constants, variables, types and functions.[1] Execution of a program begins in function main of package main.[1] Source text is Unicode encoded in UTF-8.[1,5]

The formal grammar uses semicolons as terminators, but programs rarely contain them: the lexer automatically inserts a semicolon after a line's final token when that token is an identifier, a basic literal, one of the keywords break, continue, fallthrough or return, one of the operators ++ or --, or a closing ), ] or }.[1] A practical consequence is that the opening brace of a function or control structure must sit on the same line as its header.[3] Putting it on the next line inserts a semicolon after main():

Go also refuses to compile a program that imports a package it does not use, or declares a local variable it never reads.[3] The specification permits the latter restriction as an implementation choice, and the standard gc compiler enforces both:[1]

3. Variables and constants

3.1 Variable declarations

A var declaration creates one or more variables, binds identifiers to them, and gives each a type and an initial value.[1] There are three forms: a type with no initializer (the variable receives its zero value, Section 5), an initializer with no type (the type is inferred from the expression), or both. Several declarations can be grouped in parentheses.

FormExampleResulting type
Type onlyvar n intint, value 0
Initializer onlyvar s = "go"inferred: string
Bothvar f float32 = 1float32
Several at oncevar a, b int = 1, 2int, int

When the initializer is an untyped constant, the variable gets the constant's default type: bool, rune, int, float64, complex128 or string, depending on the kind of constant.[1]

3.2 Constants

Constants are values known at compile time. They may be boolean, rune, integer, floating-point, complex or string.[1] Two properties make Go's constants unusual.

Constants can be untyped. A literal such as 3.14, or a constant declared without a type, is untyped: it has a kind (integer, float and so on) but no fixed machine type until it is used in a context that requires one.[1,6] This is why the same constant Pi can initialise both a float32 and a float64 without a conversion.[1,6]

Numeric constants are exact. They represent values of arbitrary precision and do not overflow.[1] Compilers must represent integer constants with at least 256 bits and floating-point constants with a mantissa of at least 256 bits.[1] Overflow is detected only when a constant is converted to a concrete type. 3.3 Enumerations with iota

Inside a parenthesised const block, the predeclared identifier iota represents successive untyped integer constants starting at 0, incrementing by one per constant specification and resetting at each new const keyword.[1] If a specification omits its expression, the previous expression and type are repeated, which is what makes the compact Monday, Tuesday lines work.[1] The ByteSize pattern, which uses a blank identifier to skip zero and shifts by multiples of ten to produce powers of 1024, comes from Effective Go.[3]

Tip

Because iota starts at 0, the zero value of an enumeration type is its first constant. Make that constant a sensible default (or an explicit Unknown) so that an uninitialised variable is meaningful.

4. Short variable declarations

Inside a function, x := expr is shorthand for var x = expr: the type is always inferred from the right-hand side.[1] Because of its brevity, it is used for the majority of local variables.[2] Three rules govern it.

  1. Functions only. Short variable declarations may appear only inside functions; at package level you must use var.[1]
  2. At least one new variable. A short declaration may redeclare variables declared earlier in the same block, with the same type, provided at least one non-blank variable on the left is new. Redeclaration does not create a new variable; it assigns to the existing one.[1] This is what lets successive calls reuse err.[3]
  3. Scope matters. In an inner block, := always declares new variables, which can silently shadow outer ones of the same name.[1]

Violating the first two rules produces these errors:

Pitfall: accidental shadowing

Writing x, err := f() inside an if or for body declares a new err that disappears at the end of the block, leaving the outer err unchanged. Use plain assignment (=) when you mean to update the outer variable. The optional shadow analyser for go vet can flag suspicious cases.[7]

5. Zero values

Go has no uninitialised memory. Whenever storage is allocated for a variable and no explicit initial value is provided, it receives the zero value for its type: false for booleans, 0 for numeric types, "" for strings, and nil for pointers, functions, interfaces, slices, channels and maps. Arrays and structs are zeroed element by element, recursively.[1]

Effective Go recommends designing types so that their zero value is useful without further initialisation, as the standard library does with bytes.Buffer, strings.Builder and sync.Mutex.[3] A lookup in a nil map simply returns the element type's zero value, but assigning to an entry of a nil map causes a run-time panic.[1]

6. Primitive data types

Go's predeclared basic types are the boolean type, the numeric types (integers, floating-point and complex numbers) and the string type.[1] Two further names, byte and rune, are aliases for uint8 and int32.[1]

All sizes and the aliasing of byte and rune are fixed by the specification.[1] To avoid portability problems, all numeric types are distinct (defined) types: int and int64 are different types even on a 64-bit machine, and mixing them requires a conversion.[1]

6.1 Integers

Integer literals can be written in decimal, binary (0b), octal (0o or a leading 0) and hexadecimal (0x), and may contain underscores between digits for readability. The binary and 0o prefixes and digit separators were added in Go 1.13.[1,8]

Signed integers use two's-complement representation.[1] Unsigned arithmetic is performed modulo 2n; signed arithmetic may also overflow, and the result is deterministically defined by the two's-complement representation. In neither case does overflow cause a run-time panic.[1] Integer division truncates toward zero, and the remainder satisfies q*y + r == x with |r| < |y|, so the remainder has the sign of the dividend.[1,2]

The constants math.MaxInt8, math.MaxUint64 and friends are untyped, which is why uint64(math.MaxUint64) needs an explicit conversion before it can be printed: as an int argument it would overflow.[9]

Choosing an integer type

Use int by default; it is the type of len, indices and loop counters.[10] Use sized types when a format or protocol dictates the width, and unsigned types mainly when you need bitwise operations or modular arithmetic. Donovan and Kernighan note that unsigned numbers tend to be used only in those cases, because a quantity like a length decremented past zero wraps to a huge value instead of becoming negative.[2]

6.2 Floating-point numbers

float32 and float64 are the IEEE 754 32-bit and 64-bit binary formats.[1,11] A float32 carries about six significant decimal digits and a float64 about fifteen, so float64 is the usual choice.[2] Untyped floating-point constants default to float64.[1] Literals may use decimal or hexadecimal mantissas; in the hexadecimal form, p introduces a power-of-two exponent, so 0x1p-2 is 0.25.[1,8]

Because binary floating point cannot represent most decimal fractions exactly, results are rounded.[11,12] Go adds an instructive twist: constant expressions are evaluated exactly, so 0.1+0.2 == 0.3 is true when all three are untyped constants, but false when the same values sit in float64 variables.[1,6]

The special values behave as IEEE 754 prescribes: division of a non-zero value by zero gives an infinity, 0/0 gives NaN, NaN is unequal to everything including itself, and negative zero compares equal to zero.[11] The Go specification leaves floating-point division by zero unspecified beyond IEEE 754, and there are no constants for infinity, NaN or negative zero, which is why the program builds them from a variable and from math.Copysign.[1,9] A constant division by zero is a compile-time error:

Comparing floats

Avoid == on computed floating-point values. Compare against a tolerance suited to the magnitudes involved (Exercise 5), and use math.IsNaN to detect NaN.[9,12]

6.3 Complex numbers

Go has built-in complex types: complex64 (two float32 parts) and complex128 (two float64 parts).[1] An imaginary literal is a number followed by i, and untyped complex constants default to complex128.[1] The built-in functions complex, real and imag assemble and disassemble values,[1,10] and package math/cmplx provides functions such as Abs, Sqrt, Exp and Conj.[13]

The last line shows Euler's identity eiπ + 1 = 0 holding to within about 10−16, the rounding error of a float64 approximation of π.[11] Complex values support + - * / and == !=, but not ordering (<), because complex numbers are not ordered.[1]

6.4 Booleans

The type bool has two predeclared constants, true and false.[1] Comparison operators produce untyped boolean results.[1] Unlike C, Go does not treat numbers as truth values: there is no conversion between bool and the numeric types, and an if condition must be a boolean expression.[1]

6.5 Strings

A string is an immutable sequence of bytes; len(s) returns the number of bytes, not characters.[1] Indexing s[i] yields a byte, and taking the address of a string element is illegal.[1] A string can hold arbitrary bytes, but Go source is UTF-8 and string literals (without byte escapes) therefore always contain valid UTF-8.[5,14]

There are two literal forms. Interpreted literals in double quotes process escapes such as \n, \t, \xNN, \uNNNN and \UNNNNNNNN. Raw literals in back quotes contain exactly the characters between the quotes: no escapes, and newlines are kept, which makes them useful for regular expressions, paths and templates.[1]

A for range loop over a string decodes UTF-8 and yields the byte offset and the rune at each position, which is the correct way to iterate over characters.[1,5]

Notice that "héllo, 世界" is 14 bytes long but contains only 9 code points: é occupies two bytes and each Chinese character three, which is why the offsets in the range loop jump from 1 to 3 and from 8 to 11.[14] Strings compare byte-wise (lexically), so "Z" < "a" because 'Z' is 0x5A and 'a' is 0x61.[1] Because strings are immutable, assigning to an element does not compile:

Converting to []byte produces a mutable copy.[1] For building strings piece by piece, strings.Builder minimises memory copying compared with repeated +=.[15]

6.6 Runes and bytes

byte is an alias for uint8, and rune is an alias for int32; the aliases exist to signal intent: a byte of data versus a Unicode code point.[1,5] Because they are aliases rather than new types, a rune can be assigned to an int32 with no conversion, and %T prints the underlying name. A rune literal such as '世' is an untyped constant whose default type is rune.[1]

Converting a string to []rune decodes it into code points; converting to []byte exposes the raw UTF-8 bytes.[1] When a range loop meets an invalid UTF-8 byte, it yields the replacement character U+FFFD and advances by one byte.[1,16] Package unicode/utf8 offers functions such as RuneCountInString, DecodeRuneInString, RuneLen and ValidString, and package unicode classifies runes.[16,17]

Rune is not always "character"

A rune is a Unicode code point. What a reader perceives as one character can be several code points, for example a letter followed by a combining accent. Reversing a string rune by rune (Exercise 2) is correct for most text but can separate such sequences.[5]

7. Type conversions

Go performs no implicit conversions between numeric types. Mixing int and float64 in one expression is a compile-time error, and every conversion is written explicitly as T(x).[1,3]

The specification defines what each numeric conversion does:[1]

  • Between integer types: a signed value is sign-extended, then truncated to the result's size. The conversion always succeeds and keeps the low-order bits, so int8(300) is 44 and uint8(-1) is 255.
  • Float to integer: the fraction is discarded (truncation toward zero). If the value does not fit in the target type, the conversion still succeeds but the result is implementation-dependent.
  • To a floating-point type: the value is rounded to the target precision.

Constant conversions are stricter: the value must be representable exactly in the target type, so int(3.99) and var b byte = 256 are compile-time errors.[1]

Strings and numbers

Converting an integer to a string with string(n) does not produce its decimal digits; it yields the UTF-8 encoding of the code point n, so string(rune(65)) is "A".[1] Since Go 1.15, go vet reports string(x) conversions from integer types other than rune and byte, because they are almost always a bug.[7,18] Use package strconv (Itoa, Atoi, ParseFloat, FormatInt, Quote and so on) or fmt.Sprint for textual conversions.[19]

8. Type aliases and defined types

A type declaration takes one of two forms, and the difference is fundamental.[1]

A type definition creates a new type with the same underlying type and operations as the given type. A named type is always different from any other type, so a Celsius cannot be assigned to a Fahrenheit, even though both are float64 underneath.[1] Conversion between them is permitted because their underlying types are identical.[1] Defined types are how Go attaches methods and meaning to primitive values, and the temperature example is a classic illustration.[2]

An alias declaration binds a new identifier to an existing type; the two names denote the identical type.[1] Aliases were introduced in Go 1.9, primarily to support moving types between packages during large-scale refactoring.[20,21] byte and rune are the built-in examples.[1] Since Go 1.24, aliases may also have type parameters (generic type aliases).[22]

9. Operators

Operators combine operands into expressions. For binary operators the operand types must be identical unless the operation involves shifts or untyped constants.[1]

9.1 Arithmetic operators

OperatorMeaningApplies to

Integer division by a constant zero does not compile; integer division by zero at run time causes a panic.[1] One edge case follows from two's complement: dividing the most negative value of a signed type by −1 overflows and yields the dividend itself, without a panic.[1] The built-in functions min and max were added in Go 1.21.[10,23]

++ and -- are statements, not expressions, so they cannot appear inside another expression and have no prefix form.[1,3]

9.2 Comparison operators

The operators == != < <= > >= compare two operands and yield an untyped boolean.[1] Equality (==, !=) applies to comparable operands: booleans, numbers, strings, pointers, channels, interfaces, and structs or arrays whose fields or elements are comparable. Ordering (< and so on) applies to integers, floats and strings. Slices, maps and functions can be compared only to nil.[1] Two interface values are equal if they have identical dynamic types and equal dynamic values, which is why any(1) == any(int64(1)) is false.[1]

Note that every comparison involving NaN, including nan == nan, is false except !=, as IEEE 754 requires.[11]

9.3 Logical operators

The logical operators && (conditional AND), || (conditional OR) and ! (NOT) apply to boolean operands. && and || short-circuit: the right operand is evaluated only if the left operand does not already determine the result.[1] In the program above, B and D are never evaluated, and the guard p != nil && p.X > 0 is safe precisely because of this rule.

Bitwise operators apply to integers only.[1] Go uses ^x for complement instead of C's ~x, and it adds &^, which clears in the left operand every bit that is set in the right.[1] The shift count must be non-negative (a negative count at run time panics) and has no upper limit. Right shifts are arithmetic for signed operands and logical for unsigned ones.[1] Since Go 1.13 the count may be any integer type, not only unsigned.[8] Combining 1 << iota with a defined type is the idiomatic way to declare bit flags.[2,3]

9.5 Assignment operators

Plain assignment = stores a value in a variable, a pointer indirection, a field, or a slice, array or map element.[1] Every binary arithmetic and bitwise operator has a compound form op=; x op= y is equivalent to x = x op (y) but evaluates x only once.[1] The available compound operators are += -= *= /= %= &= |= ^= <<= >>= &^=.

A tuple assignment such as a, b = b, a proceeds in two phases: first all index expressions and pointer indirections on the left and all expressions on the right are evaluated, then the assignments are carried out left to right.[1] This makes swapping trivial and explains the surprising i, arr[i] = 1, 99 example below, which sets arr[0], not arr[1]; the specification contains the same example.[1] The blank identifier _ discards a value.[1,3]

10. Operator precedence

Unary operators bind tightest. Binary operators have five precedence levels, and operators on the same level associate left to right.[1] Because ++ and -- are statements, they sit outside the hierarchy, so *p++ means (*p)++.[1]

The hierarchy is shorter and clearer than C's,[3] and it differs in ways that matter to programmers coming from C, Java or JavaScript. Shifts are multiplicative and & binds tighter than comparison, so 1 + 2<<3 is 17 (C gives 24) and 5&3 == 1 means (5&3) == 1 (C parses it as 5 & (3==1)). Readability

When an expression mixes bit operations with arithmetic or comparison, add parentheses even where they are redundant. The reader should not need the precedence table to understand your code.

11. Comments and documentation

Go has two forms of comment: line comments, from // to the end of the line, and general comments, from /* to the first following */. A comment cannot start inside a string or rune literal or inside another comment, so comments do not nest.[1] Line comments are the norm; block comments appear mainly in package documentation or to disable large sections of code.[3]

11.1 Doc comments

Go documentation is extracted directly from source. A doc comment is a comment that appears immediately before a top-level package, const, func, type or var declaration with no intervening blank line, and every exported name should have one.[24] The conventions are:[24,25]

  • A package comment begins // Package name ... and gives an overview of the package.
  • Comments are complete sentences that begin with the name being declared and end with a period, for example // Dist returns .... This makes them read well in go doc output.
  • A type's comment explains what each value represents (// A Point is ...); a function's comment says what it returns or does. Boolean functions are conventionally described with "reports whether".
  • A paragraph beginning Deprecated: is a deprecation notice; some tools warn when such identifiers are used, and pkg.go.dev hides their documentation by default.

Since Go 1.19, doc comments support a small markup: headings (# Heading), lists, indented code blocks, URLs and doc links in square brackets such as [Point.Equal] or [strings.Builder]; gofmt also reformats doc comments into a canonical layout.[24,26]

12. Formatting and code conventions

12.1 gofmt

Go settles formatting by machine. The gofmt tool (and go fmt, which runs it on packages) rewrites source into the canonical style: tabs for indentation, blanks for alignment, and a consistent placement of braces and spacing.[3,4] The point is not that this style is the best possible, but that a single style makes code easier to read, write and maintain, removes formatting debates from code review, and makes mechanical source transformations safe.[28] Almost all Go code in the wild uses gofmt.[25]

Useful flags are gofmt -l (list files whose formatting differs), -w (rewrite files in place), -d (show a diff) and -s (also simplify code, for example []T{T{}} to []T{{}}).[4] The related goimports tool additionally adds and removes import lines.[25] Run go vet as well: it reports suspicious constructs that compile but are probably wrong, such as Printf format mismatches and the string(int) conversion from Section 7.[7]

12.2 Naming

  • MixedCaps. Multi-word names use MixedCaps or mixedCaps, never underscores, and the case of the first letter decides visibility.[3,25] Constants follow the same rule: MaxLength, not MAX_LENGTH.[25]
  • Initialisms keep a consistent case: URL, ServeHTTP, appID, not Url, ServeHttp or appId.[25]
  • Package names are short, lower-case, single words with no underscores or mixedCaps, and callers refer to contents through them, so bufio.Reader rather than bufio.BufReader.[3]
  • Getters omit Get: a field owner has a getter Owner() and a setter SetOwner().[3]
  • Short local names. Variable names should be short, especially for locals with limited scope: i, r, buf. The further a name is used from its declaration, the more descriptive it should be. Receiver names are one or two letters reflecting the type, never this or self.[25]

12.3 Other conventions

  • There is no fixed line-length limit; wrap long lines where it aids readability rather than at an arbitrary column.[3,25]
  • Control structures need fewer parentheses than in C: if, for and switch conditions are written without them.[3]
  • Error strings are not capitalised and do not end with punctuation, because they are usually embedded in other messages.[25]
  • Handle errors early and keep the "happy path" at minimal indentation, omitting else after a return.[3,25]

13. Exercises

Try each exercise before opening its solution. Every solution was compiled, vetted and run; the output shown is real.

Exercise 1: Temperature types

Declare defined types Celsius and Fahrenheit (both based on float64) and typed constants for absolute zero (−273.15 °C), freezing and boiling. Write CToF and FToC, print a small table, and convert 98.6 °F. Then confirm that var f Fahrenheit = AbsoluteZeroC does not compile, and explain why.

Show solution

The assignment fails because Celsius and Fahrenheit are distinct defined types (Section 8). FToC(98.6) compiles without a conversion because 98.6 is an untyped constant, which is assignable to any floating-point-based type.

Exercise 2: Bytes, runes and reversal

For s := "Hello, 世界", print the number of bytes and runes, then every rune with its byte offset and encoded length. Write Reverse(s string) string that reverses by runes, so that multi-byte characters stay intact.

Show solution

Reversing the bytes would scramble the three-byte UTF-8 sequences into invalid UTF-8. Converting to []rune decodes the code points first; the tuple assignment r[i], r[j] = r[j], r[i] swaps without a temporary (Section 9.5).

Exercise 3: Permission flags

Define type Perm uint8 with flags Exec, Write and Read declared using iota. Implement Has, Set, Clear and Toggle with bitwise operators, plus a String method that formats the value like ls -l (rwx, r-x, ...).

Show solution

Set uses |=, Clear uses &^= and Toggle uses ^=. The zero value of Perm is a meaningful "no permissions" value. Because Perm has a String method, fmt.Println uses it automatically; printing the number needs uint8(p).

Exercise 4: Detecting overflow

Go integer arithmetic wraps silently. Write AddInt8(a, b int8) (int8, bool) that returns the wrapped sum and whether it is correct. Do not use a wider type.

Show solution

Adding numbers of opposite sign can never overflow. Adding two numbers of the same sign overflows exactly when the result has the other sign, which follows from the two's-complement wrap-around defined in the specification.[1]

Exercise 5: Floating-point accumulation

Add 0.1 ten times in a float64 and in a float32, and compare each result with 1.0. Write ApproxEqual(a, b, tol float64) bool that uses a relative tolerance.

Show solution

0.1 has no exact binary representation, so each addition rounds and the errors accumulate.[12] The relative tolerance scales with the magnitude of the operands, so the same tol works for values near 1 and near 109; the math.Max(scale, 1) term falls back to an absolute tolerance near zero.

Exercise 6: Human-readable sizes

Extend the ByteSize constants from Section 3.3 with TB and give the type a String method that prints values such as 1.50KB and 4.55TB.

Show solution

Inside String, the final case converts b to float64 before formatting. Passing b itself with a %v verb would call String again and recurse forever, a trap described in Effective Go.[3] With %.2f it is safe either way, but the conversion makes the intent explicit.

Exercise 7: Quadratic roots

Write Roots(a, b, c float64) (complex128, complex128) that returns both roots of ax² + bx + c = 0 for any discriminant, using math/cmplx.

Show solution

Promoting the coefficients to complex128 lets cmplx.Sqrt handle negative discriminants. The (2-0i) in the first line is a negative zero imaginary part, a legitimate IEEE 754 value that compares equal to zero.[11]

14. Summary

  • Declare with var at package level or when the zero value is what you want; use := inside functions, and watch for shadowing.
  • Every variable starts at its type's zero value. Design types so that the zero value is useful.
  • Untyped constants are exact and adapt to their context; typed values never convert implicitly.
  • int and float64 are the default numeric types. Integer arithmetic wraps; floating-point arithmetic rounds; NaN is not equal to itself.
  • Strings are immutable byte sequences, usually UTF-8. Index for bytes; range for runes.
  • Conversions are explicit T(x); use strconv for numbers to and from text.
  • type T U creates a new type; type T = U creates another name for the same type.
  • Go has five binary precedence levels; shifts and & bind like multiplication.
  • Document every exported name with a full-sentence comment that begins with the name, run gofmt and go vet, and follow the naming conventions.
