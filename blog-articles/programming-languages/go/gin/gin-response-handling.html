Response Handling in Gin

How a Gin handler turns Go values into HTTP responses: JSON, XML, YAML, plain text and HTML; redirects, raw bytes, file downloads and streams; status codes, headers and cookies; and how to give an API consistent success and error shapes.

Written against Gin v1.12.0 (released 28 February 2026), which requires Go 1.25 or later [1; 2]. The official guide lives at gin-gonic.com [3]; this article cites the source and the in-repository docs for the exact tagged version. Every example in this article was compiled and run against that version, and the outputs shown are what those runs printed. Citations use the Vancouver system: numbers in square brackets point to the numbered reference list at the end.

1How Gin writes a response

Almost every response helper on *gin.Context is a one-line wrapper. c.JSON(code, obj), for example, is literally c.Render(code, render.JSON{Data: obj}) [4]. Knowing what Render does explains most of Gin's response behaviour, including the surprising parts.

// Abridged from gin v1.12.0 context.go
func (c *Context) Render(code int, r render.Render) {
	c.Status(code)

	if !bodyAllowedForStatus(code) {   // 1xx, 204 and 304
		r.WriteContentType(c.Writer)
		c.Writer.WriteHeaderNow()
		return
	}

	if err := r.Render(c.Writer); err != nil {
		_ = c.Error(err)   // pushed onto c.Errors
		c.Abort()
	}
}

A renderer is anything that satisfies a two-method interface [5]:

type Render interface {
	Render(http.ResponseWriter) error       // write the body
	WriteContentType(w http.ResponseWriter) // set Content-Type
}

Four consequences follow from this design.

  1. Content-Type is a default, not an override. Each renderer calls an internal writeContentType helper that only sets the header if it is empty [5]. Setting Content-Type yourself before calling c.JSON wins. That is how you send application/problem+json in section 17.
  2. Status codes that forbid a body skip the body. For 1xx, 204 No Content and 304 Not Modified, Gin writes the headers and stops, even if you passed an object [4]. That matches HTTP semantics, where those responses carry no content [6, §15.2; §15.3.5; §15.4.5].
  3. The first write freezes the status and headers. Gin's ResponseWriter remembers the status until the body is first written. After that, a new WriteHeader call is ignored and only prints a debug warning [7]. Go's own http.ResponseWriter contract says changes to the header map after the header is written have no effect [8].
  4. Calling two renderers concatenates their bodies. Gin does not stop you from writing twice. This handler: 
    r.GET("/twice", func(c *gin.Context) {
	c.String(http.StatusOK, "first")
	c.JSON(http.StatusInternalServerError, gin.H{"oops": true})
})
    200
Content-Type: text/plain; charset=utf-8
first{"oops":true}
    The status stays 200, the content type stays text/plain, and both bodies are sent. Write exactly one response per request, and return right after it.

2Custom HTTP status codes

Every renderer takes the status code as its first argument. Use the named constants from net/http (http.StatusCreated rather than 201) so the intent is readable [8]. HTTP groups codes into five classes: 1xx informational, 2xx success, 3xx redirection, 4xx client error and 5xx server error [6, §15].

r.POST("/users", func(c *gin.Context) {
	c.Header("Location", "/users/2")
	c.JSON(http.StatusCreated, Envelope[User]{Data: User{ID: 2, Name: "Bob", Joined: alice.Joined}})
})

r.DELETE("/users/:id", func(c *gin.Context) {
	c.Status(http.StatusNoContent) // status only, no body
})

r.GET("/abort", func(c *gin.Context) {
	c.AbortWithStatusJSON(http.StatusUnauthorized, gin.H{"error": "missing token"})
})
POST /users     → 201, Location: /users/2, {"data":{"id":2,"name":"Bob","joined":"2024-03-01T00:00:00Z"}}
DELETE /users/1 → 204, no body
GET /abort      → 401, {"error":"missing token"}

The status-only helpers are:

  • c.Status(code) records the code. Nothing is sent until something writes, or the handler chain finishes and Gin flushes the header [4; 7].
  • c.AbortWithStatus(code) records the code, writes the header immediately and stops later handlers from running.
  • c.AbortWithStatusJSON(code, obj) aborts and renders JSON in one call. It is the usual way to reject a request from middleware.

A few codes deserve care. A 201 Created response should say where the new resource lives, usually with Location [6, §15.3.2]. A 204 must not carry content, and Gin enforces this as described in section 1 [6, §15.3.5]. A 405 Method Not Allowed must include an Allow header [6, §15.5.6]. Gin returns 404 for unknown methods unless you set engine.HandleMethodNotAllowed = true [10]. Use 422 Unprocessable Content for a body that parses but fails validation, and 400 Bad Request for one that does not parse [6, §15.5.21].

You can read the status back with c.Writer.Status(), and check whether the body has started with c.Writer.Written(). Middleware uses both, for example an access logger after c.Next() [7].

3Response headers

c.Header(key, value) is a shortcut for c.Writer.Header().Set(key, value). Passing an empty value deletes the header instead [4]. Set replaces existing values. For a header that can repeat, such as Vary or Link, use Add on the underlying http.Header [8].

r.GET("/headers", func(c *gin.Context) {
	c.Header("Cache-Control", "no-store")
	c.Header("X-Request-Id", "abc123")
	c.Writer.Header().Add("Vary", "Accept")
	c.Writer.Header().Add("Vary", "Accept-Encoding")
	c.String(http.StatusOK, "ok")
})
200
Cache-Control: no-store
Content-Type: text/plain; charset=utf-8
Vary: Accept | Accept-Encoding     (two header lines)
X-Request-Id: abc123
Content-Length: 2
Order matters. Set headers before calling any renderer. Once the body starts, the header block has already been sent and further changes are silently lost [8].

Headers you will set most often in an API:

  • Cache-Control controls whether and how long a response can be cached. no-store forbids storing it at all, which suits personal data [11, §5.2.2.5].
  • Vary tells caches which request headers changed the response. It is required for correct caching when you do content negotiation on Accept [6, §12.5.5].
  • Location goes on 201 and 3xx responses [6, §10.2.2].
  • ETag and Last-Modified enable conditional requests and 304 responses [6, §8.8]. c.File already handles Last-Modified for you (section 11).
  • Link carries pagination and related-resource links [12].

Headers that must be computed after the handler runs, such as timing or a body checksum, can be written as HTTP trailers. Declare them in a Trailer header first, or use the http.TrailerPrefix convention described in the net/http documentation [8].

4JSON responses

c.JSON is the workhorse. It accepts any value encoding/json can marshal: structs, maps, slices, or gin.H, which is simply map[string]any [13].

r.GET("/json", func(c *gin.Context) {
	c.JSON(http.StatusOK, alice)
})
r.GET("/json/map", func(c *gin.Context) {
	c.JSON(http.StatusOK, gin.H{"message": "<b>hi</b>"})
})
GET /json      → {"id":1,"name":"Alice","email":"alice@example.com","joined":"2024-03-01T00:00:00Z"}
GET /json/map  → {"message":"\u003cb\u003ehi\u003c/b\u003e"}

Two things in that output come straight from encoding/json. The Password field is missing because of its json:"-" tag. The angle brackets are escaped because Marshal escapes <, > and & by default, so the JSON is safe to embed in an HTML <script> tag [14].

Gin always sends charset=utf-8 with application/json. The JSON specification requires UTF-8 for JSON exchanged between systems and defines no charset parameter for the media type, so the parameter is redundant but harmless [15, §8.1; §11].

The JSON variants

r.GET("/json/pure", func(c *gin.Context) {
	c.PureJSON(http.StatusOK, gin.H{"message": "<b>hi</b>"})
})
r.GET("/json/ascii", func(c *gin.Context) {
	c.AsciiJSON(http.StatusOK, gin.H{"city": "Zürich"})
})
r.GET("/json/secure", func(c *gin.Context) {
	c.SecureJSON(http.StatusOK, []string{"a", "b"})
})
r.GET("/json/indented", func(c *gin.Context) {
	c.IndentedJSON(http.StatusOK, gin.H{"ok": true})
})
r.GET("/jsonp", func(c *gin.Context) {
	c.JSONP(http.StatusOK, gin.H{"ok": true})
})
GET /json/pure          → {"message":"<b>hi</b>"}\n
GET /json/ascii         → {"city":"Z\u00fcrich"}         Content-Type: application/json
GET /json/secure        → while(1);["a","b"]
GET /json/indented      → {
                              "ok": true
                          }
GET /jsonp?callback=cb  → cb({"ok":true});              Content-Type: application/javascript; charset=utf-8
  • PureJSON uses a JSON encoder with SetEscapeHTML(false) [5]. An encoder writes a newline after each value, which is why its output alone ends in \n [14]. Use it when clients compare strings byte for byte and the output never lands inside HTML.
  • AsciiJSON escapes every non-ASCII rune as \uXXXX. It is for clients that mishandle UTF-8.
  • SecureJSON defends against old JSON-hijacking attacks by prefixing top-level arrays with while(1);. Change the prefix with engine.SecureJsonPrefix(")]}',\n") [10; 16]. The client must strip the prefix before parsing.
  • IndentedJSON pretty-prints with four spaces. The source comment recommends it only for development, because it costs more CPU and bandwidth [4].
  • JSONP reads the callback query parameter and escapes it with template.JSEscapeString. With no callback it behaves like c.JSON [4; 5]. JSONP predates CORS, so prefer CORS for new APIs.

Choosing the JSON library

By default Gin's codec is the standard library. At build time you can swap in faster libraries with -tags=jsoniter, -tags=go_json or -tags=sonic [16; 17]. At run time you can assign your own implementation to json.API in the github.com/gin-gonic/gin/codec/json package. Section 16 shows how.

5XML responses

c.XML marshals with encoding/xml and sets application/xml; charset=utf-8 [5], the media type registered for XML [18].

r.GET("/xml", func(c *gin.Context) {
	c.XML(http.StatusOK, alice)
})
<User id="1"><name>Alice</name><email>alice@example.com</email><joined>2024-03-01T00:00:00Z</joined></User>

The XML shape is controlled by struct tags [19]:

  • The root element takes the type's name (User) unless the struct has an XMLName xml.Name field with a tag such as `xml:"user"`.
  • ,attr makes a field an attribute (id="1" above), ,chardata makes it the element's text, and a>b nests it.
  • - skips a field and ,omitempty drops empty values.

gin.H also works with c.XML, because Gin gives it a MarshalXML method. The root element is always <map> and each key becomes a child element [13]. Child order follows Go map iteration, which the language leaves unspecified [20], so the order can change between requests. Use a struct when element order matters to the consumer.

6YAML and content negotiation

c.YAML marshals with the github.com/goccy/go-yaml library and sets application/yaml; charset=utf-8 [5; 21]. application/yaml has been the registered media type since RFC 9512 in 2024 [22].

r.GET("/yaml", func(c *gin.Context) {
	c.YAML(http.StatusOK, alice)
})
id: 1
name: Alice
email: alice@example.com
joined: 2024-03-01T00:00:00Z

Gin also ships c.TOML, c.ProtoBuf (the value must be a proto.Message) and, since v1.12.0, c.BSON [4; 9].

Serving several formats from one handler

c.Negotiate picks a renderer from the request's Accept header [4]:

r.GET("/negotiate", func(c *gin.Context) {
	c.Negotiate(http.StatusOK, gin.Negotiate{
		Offered: []string{gin.MIMEJSON, gin.MIMEXML, gin.MIMEYAML2, gin.MIMEYAML},
		Data:    alice,
	})
})
Accept: application/xml → 200, <User id="1">...
Accept: text/csv        → 406, empty body
Three negotiation details from the source.
  1. gin.MIMEYAML is the legacy application/x-yaml. The registered type application/yaml is gin.MIMEYAML2 [23]. If you offer only MIMEYAML, a client sending Accept: application/yaml gets 406. Offer both, as above.
  2. Gin strips parameters, including q= weights, and walks the client's list in the order it was written [13]. HTTP says quality values express preference [6, §12.5.1], so Accept: application/xml;q=0.1, application/json still gets XML from Gin. If your clients send weights, parse Accept yourself.
  3. When nothing matches, Gin calls c.AbortWithError(406, ...). That writes a 406 with no body [4], which matches the purpose of 406 [6, §15.5.7]. An error middleware (section 17) can turn it into a JSON problem document.

Add Vary: Accept to negotiated responses so caches keep one copy per format [6, §12.5.5].

7String responses

c.String(code, format, values...) writes text/plain; charset=utf-8 [5]:

r.GET("/string", func(c *gin.Context) {
	c.String(http.StatusOK, "hello %s, you are #%d", "Alice", 1)
})
hello Alice, you are #1

When you pass values, Gin calls fmt.Fprintf. When you pass none, it writes the format string unchanged [5]. So c.String(200, userInput) is safe from format verbs, but c.String(200, userInput, x) is not. If the format string contains user text, any % in it is read as a verb [24]. Keep format strings constant.

Plain text responses are not HTML-escaped. That is correct for text/plain, but never serve user-controlled text with Content-Type: text/html through c.String. Use c.HTML, which escapes.

8HTML rendering

Gin renders HTML through Go's html/template. Load templates on the engine once at start-up, then render one by name [10; 16].

{{ define "profile.tmpl" }}<!doctype html>
<title>{{ .Title }}</title>
<h1>Hello, {{ .Name }}</h1>
<p>Member since {{ .Since | year }}</p>{{ end }}
r := gin.New()
r.SetFuncMap(template.FuncMap{"year": func(t time.Time) int { return t.Year() }}) // before loading
r.LoadHTMLGlob("templates/*")

r.GET("/html", func(c *gin.Context) {
	c.HTML(http.StatusOK, "profile.tmpl", gin.H{
		"Title": "Profile", "Name": "<Alice>", "Since": alice.Joined,
	})
})
Content-Type: text/html; charset=utf-8

<!doctype html>
<title>Profile</title>
<h1>Hello, &lt;Alice&gt;</h1>
<p>Member since 2024</p>

The <Alice> input came out as &lt;Alice&gt;. html/template escapes by context: it knows whether a value lands in HTML text, an attribute, a URL or JavaScript, and escapes for that context [25]. Do not convert user input to template.HTML, because that type turns escaping off.

Ways to load templates [10]:

  • LoadHTMLGlob(pattern) and LoadHTMLFiles(files...) read from disk.
  • LoadHTMLFS(fs, patterns...) reads from an http.FileSystem, so http.FS(embeddedFS) lets you build templates into the binary with //go:embed [26].
  • SetHTMLTemplate(t) installs a *template.Template you built yourself.
  • Delims("[[", "]]") changes the action delimiters, which helps when templates also hold a front-end framework's {{ }} syntax. Call it before loading.

In debug mode, the glob, file and FS loaders install an HTMLDebug renderer that re-parses templates on every request, so edits show up without a restart. In release mode they parse once [10]. Because SetFuncMap and Delims are read when templates are parsed, call them first. Templates in subdirectories with the same file name need {{ define "users/index.tmpl" }} blocks so their names are unique [16].

9Redirects

c.Redirect(code, location) delegates to http.Redirect. Gin first checks the code and panics unless it is 201 or between 300 and 308 [5].

r.GET("/old", func(c *gin.Context) {
	c.Redirect(http.StatusMovedPermanently, "/new")
})
r.POST("/login", func(c *gin.Context) {
	// ... authenticate ...
	c.Redirect(http.StatusSeeOther, "/dashboard")
})
GET /old    → 301, Location: /new, small HTML body
POST /login → 303, Location: /dashboard

Choose the code by two questions: is the move permanent, and must the client repeat the same method [6, §15.4]?

CodePermanent?Method on follow-upTypical use
301 Moved Permanentlyyesmay change POST to GET (historical)Old URL for a GET resource
302 Foundnomay change POST to GET (historical)Legacy temporary redirect
303 See Othernoalways GETPost/Redirect/Get after a form submit
307 Temporary Redirectnosame method and bodyTemporary move of an API endpoint
308 Permanent Redirectyessame method and bodyPermanent move of an API endpoint

The method rules come from RFC 9110 sections 15.4.2 to 15.4.9 [6, §15.4.2–15.4.9]. Gin's own docs redirect POSTs with 302 [16], which works in browsers, but 303 states the intent exactly.

Internal redirects. To run another route's handlers without a round trip to the client, rewrite the path and call engine.HandleContext(c) [16]. The client never sees a 3xx.

Open redirects. Never redirect to a URL taken straight from the request, such as ?next=. An attacker can link to your site and bounce victims to a phishing page. Accept only relative paths you recognise, or check the host against an allow-list [27]. Note that //evil.example is a scheme-relative URL, not a path.

10Raw bytes with c.Data

c.Data(code, contentType, bytes) writes a byte slice as it is, with the content type you supply. Since v1.12.0 it also sets Content-Length [5; 9]. Use it for bytes you already have in memory: a generated image, a cached response, or a body produced by another encoder.

r.GET("/data", func(c *gin.Context) {
	c.Data(http.StatusOK, "image/svg+xml", []byte(`<svg xmlns="http://www.w3.org/2000/svg"/>`))
})
200
Content-Type: image/svg+xml
Content-Length: 41
<svg xmlns="http://www.w3.org/2000/svg"/>

For large or unbounded payloads, do not read everything into a slice first. Use c.DataFromReader or c.File (sections 11 and 12).

11File downloads

Gin has three file helpers, all built on net/http [4]:

r.GET("/file", func(c *gin.Context) {
	c.File("files/report.csv") // display inline if the browser can
})
r.GET("/download", func(c *gin.Context) {
	c.FileAttachment("files/report.csv", "Q3 report.csv") // "Save as..."
})
//go:embed assets
var assets embed.FS
r.GET("/logo", func(c *gin.Context) {
	c.FileFromFS("assets/logo.svg", http.FS(assets))
})
GET /file
200
Accept-Ranges: bytes
Content-Length: 16
Content-Type: text/csv; charset=utf-8
Last-Modified: Fri, 30 Oct 2026 13:31:49 GMT

GET /download
200
Content-Disposition: attachment; filename="Q3 report.csv"
(same headers as above)

c.File calls http.ServeFile, so you get a lot for free [8]. It infers Content-Type from the extension, or sniffs the first bytes if the extension is unknown. It sets Last-Modified and answers If-Modified-Since with 304. It serves Range requests with 206 Partial Content, so downloads can resume and media can seek [6, §14].

c.FileAttachment adds Content-Disposition: attachment, which tells the browser to save the file under the given name rather than display it [28]. ASCII names go in a quoted filename= parameter. Non-ASCII names use the extended filename*=UTF-8''... form defined by RFC 8187 [4; 29].

Spaces in non-ASCII file names. Gin encodes the extended form with url.QueryEscape [4], which turns a space into + [30]. In RFC 8187 encoding, + is a literal character and spaces must be %20 [29, §3.2.1]. So "résumé 1.pdf" may be saved as résumé+1.pdf. If that matters, set the header yourself with url.PathEscape, which produces %20, and call c.File.

Path traversal

The net/http documentation is explicit: ServeFile resolves relative paths against the working directory, the name "may ascend to parent directories", and a name built from user input "should be sanitized before calling ServeFile" [8]. Gin passes your path straight through [4]. So this is a vulnerability:

// DON'T: GET /dl?name=../../etc/passwd
c.File("downloads/" + c.Query("name"))

Three safe options:

  • Check the name with filepath.IsLocal, which reports whether a path stays inside its base directory by lexical analysis [31]. Exercise 4 does this.
  • Serve from a confined file system: c.FileFromFS(name, http.Dir("downloads")). http.Dir cleans the name before opening it [8].
  • Use os.Root (Go 1.24+), which also refuses symbolic links that point outside the directory. Lexical checks cannot catch those [32].

Better still, never take file paths from users at all. Look up an ID in your database and map it to a path on the server.

12File streaming

Streaming means sending the body in pieces, without holding it all in memory or knowing its full size up front.

From an io.Reader

r.GET("/reader", func(c *gin.Context) {
	body := strings.NewReader("streamed body") // any io.Reader: S3 object, upstream response, pipe
	c.DataFromReader(http.StatusOK, int64(body.Len()), "text/plain; charset=utf-8", body,
		map[string]string{"Content-Disposition": `attachment; filename="body.txt"`})
})
200
Content-Disposition: attachment; filename="body.txt"
Content-Length: 13
Content-Type: text/plain; charset=utf-8
streamed body

DataFromReader sets Content-Length when the length is zero or more, and leaves it unset for -1 (unknown) [5]. With no length, Go's server switches to chunked transfer encoding on HTTP/1.1 [8]. The extra headers are only applied if the header is not already set, and the body is copied with io.Copy. The Gin docs show it proxying a remote image straight to the client [16]. Remember to close the upstream body.

Step by step with c.Stream

r.GET("/stream", func(c *gin.Context) {
	i := 0
	c.Stream(func(w io.Writer) bool {
		fmt.Fprintf(w, "chunk %d\n", i)
		i++
		return i < 3 // false ends the stream
	})
})

c.Stream calls your function in a loop and flushes after each call, until the function returns false or the client disconnects. Its own return value is true if the client went away [4].

Two things about c.Stream.
  1. It detects disconnects through http.CloseNotifier, which net/http marks deprecated in favour of Request.Context() [4; 8]. Inside a step that blocks (waiting on a channel or a timer), also select on c.Request.Context().Done(), as Exercise 5 does.
  2. httptest.ResponseRecorder does not implement CloseNotifier [33], so testing a c.Stream handler with a recorder panics with "*httptest.ResponseRecorder is not http.CloseNotifier". Test streams against a real httptest.NewServer instead.

Server-Sent Events

r.GET("/sse", func(c *gin.Context) {
	for i := 0; i < 2; i++ {
		c.SSEvent("tick", gin.H{"n": i})
		c.Writer.Flush()
	}
})
Content-Type: text/event-stream;charset=utf-8
Cache-Control: no-cache

event:tick
data:{"n":0}

event:tick
data:{"n":1}

c.SSEvent uses the gin-contrib/sse encoder, which writes the text/event-stream format browsers consume through EventSource [34; 35]. In real handlers, loop until c.Request.Context().Done() fires.

For machine clients, newline-delimited JSON (one JSON value per line, application/x-ndjson) is a common streaming format [36]. Exercise 5 builds one.

13Cookies

c.SetCookie adds a Set-Cookie header [4]:

func (c *Context) SetCookie(name, value string, maxAge int, path, domain string, secure, httpOnly bool)
r.GET("/cookie", func(c *gin.Context) {
	c.SetSameSite(http.SameSiteLaxMode) // applies to SetCookie calls after this on this context
	c.SetCookie("session", "a b&c", 3600, "/", "", true, true)

	// Full control, including Partitioned and Expires:
	c.SetCookieData(&http.Cookie{Name: "prefs", Value: "dark", MaxAge: 86400,
		Secure: true, SameSite: http.SameSiteStrictMode, Partitioned: true})

	c.String(http.StatusOK, "cookies set")
})

r.GET("/logout", func(c *gin.Context) {
	c.SetCookie("session", "", -1, "/", "", true, true) // delete
	c.Status(http.StatusNoContent)
})
GET /cookie
Set-Cookie: session=a+b%26c; Path=/; Max-Age=3600; HttpOnly; Secure; SameSite=Lax
Set-Cookie: prefs=dark; Path=/; Max-Age=86400; Secure; SameSite=Strict; Partitioned

GET /logout
Set-Cookie: session=; Path=/; Max-Age=0; HttpOnly; Secure

How Gin's arguments map to cookie attributes:

  • value is passed through url.QueryEscape, so a b&c becomes a+b%26c. c.Cookie(name) unescapes it when reading [4]. SetCookieData does not escape, so the value must already be a valid cookie value, or Go drops the cookie [8; 37, §4.1.1].
  • maxAge follows http.Cookie.MaxAge: positive means that many seconds, zero means no Max-Age attribute (a session cookie), and negative means delete now, sent as Max-Age=0 [8; 37, §5.2.2].
  • path defaults to / when empty. Gin applies that default in both setters [4].
  • domain left empty makes a host-only cookie, sent only to the exact host that set it. That is the safer default [37, §5.3].
  • secure restricts the cookie to HTTPS [37, §4.1.2.5]. httpOnly hides it from JavaScript, which limits the damage of an XSS bug [37, §4.1.2.6].
  • SameSite is not a SetCookie argument. Set it on the context with c.SetSameSite first, or per cookie with SetCookieData [4]. Lax withholds the cookie from most cross-site requests but sends it on top-level navigations, and Strict withholds it from all cross-site requests. SameSite is defined in the RFC 6265 revision draft, not in RFC 6265 itself [38].
  • Partitioned (CHIPS) is a field on http.Cookie, so use SetCookieData [8].

To delete a cookie, the name, path and domain must match the ones it was set with. Otherwise the browser treats it as a different cookie [37, §5.3]. Each Set-Cookie is its own header line, and Go writes one per call [37, §3].

Sessions. A cookie is client-controlled storage. Put an opaque, random session ID in it, not user data, and keep the data on the server. Or sign it, for example with the gin-contrib/sessions middleware, which the middleware article covers.

14Structured API responses

Clients are easier to write when every response has the same shape. One common pattern is an envelope: successful responses put their payload under data and optional paging under meta, and errors use a separate standard shape (section 17). Go generics make the envelope type-safe:

// Envelope is the shape of every successful API response.
type Envelope[T any] struct {
	Data T     `json:"data"`
	Meta *Meta `json:"meta,omitempty"`
}

type Meta struct {
	Page    int `json:"page"`
	PerPage int `json:"per_page"`
	Total   int `json:"total"`
}

r.GET("/users", func(c *gin.Context) {
	c.JSON(http.StatusOK, Envelope[[]User]{
		Data: []User{alice},
		Meta: &Meta{Page: 1, PerPage: 20, Total: 1},
	})
})
{"data":[{"id":1,"name":"Alice","email":"alice@example.com","joined":"2024-03-01T00:00:00Z"}],
 "meta":{"page":1,"per_page":20,"total":1}}

Design guidelines:

  • Let HTTP carry what HTTP already carries. Do not put a "status": 200 or "success": true field next to a real status code. Clients, proxies and monitoring already read the status line [6, §15].
  • Return objects at the top level, not bare arrays. An object can gain meta later without breaking clients. It also avoids the old array-hijacking issue that SecureJSON exists for (section 4).
  • Put links in headers when they are about the response. A Link: <...>; rel="next" header is a standard way to point to the next page [12]. Exercise 2 adds one.
  • Make empty lists [], not null. A nil slice marshals as null and an empty slice as [] [14]. Initialise with make([]T, 0).
  • Keep response types separate from storage types. A dedicated UserResponse struct stops a new database column, such as a password hash, from leaking into the API by accident.

15Response serialization

Serialization is how Go values become bytes. For JSON, Gin hands your value to the configured codec, which is encoding/json by default [17]. Everything encoding/json documents applies [14]:

`json:"-"`always omitted
`json:",omitempty"`omitted if false, 0, "", nil, or an empty map, slice or array
`json:",omitzero"` (Go 1.24+)omitted if the zero value, or if IsZero() returns true, which works for time.Time and structs

omitempty has no effect on a non-pointer struct such as time.Time, which is the main reason omitzero was added [14]. Large integers are another trap: JSON numbers in JavaScript are IEEE 754 doubles, and RFC 8259 notes that integers beyond 253 may lose precision in other implementations [15, §6]. Send 64-bit IDs as strings with `json:"id,string"`.

Customising a type's encoding

Implement json.Marshaler on the type, or encoding.TextMarshaler for values that are naturally strings. The encoder calls them wherever the type appears, including as map keys for TextMarshaler [14]:

type Money struct {
	Cents    int64
	Currency string
}

func (m Money) MarshalJSON() ([]byte, error) {
	return []byte(fmt.Sprintf(`{"amount":"%d.%02d","currency":%q}`, m.Cents/100, m.Cents%100, m.Currency)), nil
}
// c.JSON(200, gin.H{"price": Money{1999, "EUR"}}) → {"price":{"amount":"19.99","currency":"EUR"}}

Use a value receiver so both Money and *Money pick it up. XML has the matching xml.Marshaler interface [19].

Marshal errors

Some values cannot be serialized: channels, functions, cyclic structures, and NaN or infinite floats all make json.Marshal fail [14]. Gin catches the error in Render, adds it to c.Errors and aborts [4]. The default JSON renderer marshals the whole value before writing, so on failure nothing has been written yet and an error middleware can still send a clean 500. PureJSON streams through an encoder instead, and may have written part of the body before failing [5].

16Custom serializers

There are three levels of customisation, from narrowest to widest.

Level 1: a type's own marshaler

Implement MarshalJSON or MarshalXML on a type, as in section 15.

Level 2: a new renderer for a new format

Any value that implements render.Render can go to c.Render [5]. Here is a CSV renderer. CSV's registered media type is text/csv [40], and Go's encoding/csv handles the quoting [41]:

// CSV is a custom render.Render that writes [][]string as text/csv.
type CSV struct{ Rows [][]string }

func (r CSV) WriteContentType(w http.ResponseWriter) {
	if len(w.Header()["Content-Type"]) == 0 {
		w.Header()["Content-Type"] = []string{"text/csv; charset=utf-8"}
	}
}

func (r CSV) Render(w http.ResponseWriter) error {
	r.WriteContentType(w)
	cw := csv.NewWriter(w)
	if err := cw.WriteAll(r.Rows); err != nil {
		return err
	}
	return cw.Error()
}

r.GET("/csv", func(c *gin.Context) {
	c.Render(http.StatusOK, CSV{Rows: [][]string{{"id", "name"}, {"1", "Alice"}}})
})
Content-Type: text/csv; charset=utf-8
id,name
1,Alice

Follow two conventions from Gin's own renderers. Set the content type only if it is empty, so callers can override it. Return errors rather than writing an error body, so Render can record them in c.Errors [5; 4]. A renderer that writes JSON can reuse Gin's codec through render.WriteJSON(w, v) [5], as the problem renderer in section 17 does.

Level 3: replace the JSON codec

Every JSON renderer, and JSON binding, goes through the package variable json.API in github.com/gin-gonic/gin/codec/json, whose type is the json.Core interface [17]:

type Core interface {
	Marshal(v any) ([]byte, error)
	Unmarshal(data []byte, v any) error
	MarshalIndent(v any, prefix, indent string) ([]byte, error)
	NewEncoder(writer io.Writer) Encoder
	NewDecoder(reader io.Reader) Decoder
}

Assign your implementation before the engine starts serving. The Gin docs show one built on a jsoniter configuration that sorts map keys [16]:

import (
	"io"

	ginjson "github.com/gin-gonic/gin/codec/json"
	jsoniter "github.com/json-iterator/go"
)

var cfg = jsoniter.Config{EscapeHTML: true, SortMapKeys: true}.Froze()

type jsoniterAPI struct{}

func (jsoniterAPI) Marshal(v any) ([]byte, error)              { return cfg.Marshal(v) }
func (jsoniterAPI) Unmarshal(b []byte, v any) error            { return cfg.Unmarshal(b, v) }
func (jsoniterAPI) MarshalIndent(v any, p, i string) ([]byte, error) { return cfg.MarshalIndent(v, p, i) }
func (jsoniterAPI) NewEncoder(w io.Writer) ginjson.Encoder     { return cfg.NewEncoder(w) }
func (jsoniterAPI) NewDecoder(r io.Reader) ginjson.Decoder     { return cfg.NewDecoder(r) }

func main() {
	ginjson.API = jsoniterAPI{} // before gin.New()/Run
	r := gin.Default()
	// ...
}

If you only want a faster library and not custom behaviour, the build tags in section 4 do the same job without code [16]. Either way the swap is process-wide.

17Error responses

Error responses need the same care as success responses. Clients branch on them, and careless ones leak internals. Three ideas work well together.

Use a standard shape: RFC 9457 problem details

RFC 9457 defines a JSON object for HTTP API errors, served as application/problem+json, with these members [42, §3.1]:

  • type: a URI that identifies the kind of problem. It defaults to about:blank, which means "nothing beyond the status code".
  • title: a short, human-readable summary of that kind of problem.
  • status: the HTTP status code, for convenience.
  • detail: an explanation specific to this occurrence.
  • instance: a URI for this occurrence.

You may add extension members, such as per-field validation errors [42, §3.2]. RFC 9457 replaces RFC 7807.

// Problem is an RFC 9457 problem details object.
type Problem struct {
	Type     string            `json:"type"`
	Title    string            `json:"title"`
	Status   int               `json:"status"`
	Detail   string            `json:"detail,omitempty"`
	Instance string            `json:"instance,omitempty"`
	Errors   map[string]string `json:"errors,omitempty"` // extension member
}

func (p Problem) Render(w http.ResponseWriter) error {
	p.WriteContentType(w)
	return render.WriteJSON(w, p) // falls through to Gin's JSON codec
}

func (p Problem) WriteContentType(w http.ResponseWriter) {
	h := w.Header()
	if len(h["Content-Type"]) == 0 {
		h["Content-Type"] = []string{"application/problem+json"}
	}
}

func abortProblem(c *gin.Context, status int, detail string) {
	c.Render(status, Problem{
		Type:     "about:blank",
		Title:    http.StatusText(status),
		Status:   status,
		Detail:   detail,
		Instance: c.Request.URL.Path,
	})
	c.Abort()
}

Report errors from handlers, render them in one place

c.Error(err) appends to c.Errors without writing anything [4]. A middleware placed early in the chain can inspect the errors after c.Next() and write a single, consistent response. It uses errors.Is and errors.As to match wrapped errors [43]. The middleware companion article covers c.Next() in depth.

var ErrNotFound = errors.New("not found")

func errorHandler() gin.HandlerFunc {
	return func(c *gin.Context) {
		c.Next()
		if len(c.Errors) == 0 || c.Writer.Written() {
			return // no error, or the handler already answered
		}
		err := c.Errors.Last().Err
		switch {
		case errors.Is(err, ErrNotFound):
			abortProblem(c, http.StatusNotFound, err.Error())
		default:
			abortProblem(c, http.StatusInternalServerError, "unexpected error") // log err, don't send it
		}
	}
}

r := gin.New()
r.Use(errorHandler())
r.GET("/users/:id", func(c *gin.Context) {
	if c.Param("id") != "1" {
		_ = c.Error(fmt.Errorf("user %s: %w", c.Param("id"), ErrNotFound))
		return
	}
	c.JSON(http.StatusOK, Envelope[User]{Data: alice})
})
r.GET("/boom", func(c *gin.Context) { _ = c.Error(errors.New("db down")) })
GET /users/9
404
Content-Type: application/problem+json
{"type":"about:blank","title":"Not Found","status":404,"detail":"user 9: not found","instance":"/users/9"}

GET /boom
500
Content-Type: application/problem+json
{"type":"about:blank","title":"Internal Server Error","status":500,"detail":"unexpected error","instance":"/boom"}

The c.Writer.Written() check matters. c.AbortWithError(code, err) both records the error and writes the status header straight away [4], so after it the middleware can no longer change the status. It can still append a body to that status. That is also why Gin's own 406 from c.Negotiate arrives with an empty body. If you want middleware to own the response, use c.Error in handlers, not AbortWithError.

Do not leak internals

Send clients a stable, generic message for 5xx errors, and log the real error with a request ID that you also return in a header. Stack traces, SQL and file paths in responses help attackers more than users [44]. Gin's Recovery middleware turns panics into a bare 500. gin.CustomRecovery lets you render a problem document there too [16].

For validation failures from binding, return 400 or 422 with per-field messages in an extension member such as errors. The binding companion article shows how to turn validator.ValidationErrors into that map.

18Testing responses

Handlers can be tested in memory with httptest.NewRecorder. Gin's docs recommend this approach [16; 33]:

func TestGetUser(t *testing.T) {
	gin.SetMode(gin.TestMode)
	r := setupRouter()

	w := httptest.NewRecorder()
	req := httptest.NewRequest(http.MethodGet, "/users/9", nil)
	r.ServeHTTP(w, req)

	if w.Code != http.StatusNotFound {
		t.Fatalf("status = %d, want 404", w.Code)
	}
	if ct := w.Header().Get("Content-Type"); ct != "application/problem+json" {
		t.Fatalf("content-type = %q", ct)
	}
}

Check the status, the headers that matter (Content-Type, Location, Set-Cookie, Cache-Control) and the decoded body, rather than comparing raw body strings. Key order and whitespace differ between JSON codecs. For streaming handlers use httptest.NewServer, as section 12 explains.

19Pitfalls checklist

  • Writing two responses in one handler: the bodies concatenate and the first status wins (section 1).
  • Setting headers or cookies after the body has started: they are silently lost (section 3).
  • Passing a body with 204 or 304: Gin drops it, as HTTP requires (section 1).
  • Offering only gin.MIMEYAML in Negotiate: clients asking for application/yaml get 406 (section 6).
  • Expecting q= weights in Accept to be honoured by Negotiate: they are ignored (section 6).
  • Putting user text in a c.String format string with arguments: % becomes a verb (section 7).
  • Calling c.Redirect with 200 or 404: it panics (section 9). Redirecting to ?next= unchecked: an open redirect (section 9).
  • Building c.File paths from user input: path traversal (section 11).
  • Testing c.Stream with a ResponseRecorder: it panics (section 12).
  • Forgetting Secure, HttpOnly or SameSite on session cookies (section 13).
  • Returning null for empty lists, or 64-bit IDs as numbers (sections 14 and 15).
  • Sending err.Error() from a 500 to the client (section 17).

Exercise 1: One endpoint, three formats

Write GET /books/:id that returns a Book as JSON, XML or YAML depending on Accept, returns 404 for unknown IDs and 406 for unsupported formats, and tells caches the response varies by Accept.

Show solution 
type Book struct {
	ID     int    `json:"id" xml:"id,attr" yaml:"id"`
	Title  string `json:"title" xml:"title" yaml:"title"`
	Author string `json:"author" xml:"author" yaml:"author"`
}

var books = map[string]Book{"1": {1, "The Go Programming Language", "Donovan & Kernighan"}}

func getBook(c *gin.Context) {
	b, ok := books[c.Param("id")]
	if !ok {
		c.Status(http.StatusNotFound)
		return
	}
	c.Header("Vary", "Accept")
	c.Negotiate(http.StatusOK, gin.Negotiate{
		Offered: []string{gin.MIMEJSON, gin.MIMEXML, gin.MIMEYAML2, gin.MIMEYAML},

	})

Offering both YAML constants is the important detail, because MIMEYAML alone matches only application/x-yaml (section 6). With an empty Accept header, Gin picks the first offer, JSON [4].

Exercise 2: Response helpers

func download(c *gin.Context) {
	name := c.Param("name")[1:] // strip the leading "/" of the catch-all

Exercise 5: An NDJSON stream that stops when the client leaves

Write GET /ticks that emits {"n":0}, {"n":1}, {"n":2} as newline-delimited JSON, one line every 10 ms, and stops at once if the request context is cancelled. Encode each line with Gin's configured JSON codec.

Show solution 
import ginjson "github.com/gin-gonic/gin/codec/json"

type ndjsonLine struct{ v any }

func (l ndjsonLine) WriteContentType(http.ResponseWriter) {}
func (l ndjsonLine) Render(w http.ResponseWriter) error {

		return err

	c.Header("Content-Type", "application/x-ndjson")
	c.Header("Cache-Control", "no-store")

		select {
		case <-ctx.Done():
			return false
		case <-time.After(10 * time.Millisecond):
		}

		n++
		return n < 3
	})
}

	if w := do(t, r, "GET", "/books/1", map[string]string{"Accept": "text/csv"}); w.Code != 406 {
		t.Errorf("want 406, got %d", w.Code)
	}
}

	}
}

func TestStreamCSVFlash(t *testing.T) {
	srv := httptest.NewServer(router()) // real server: c.Stream needs CloseNotifier
	defer srv.Close()

		t.Fatal(err)
	}
	body, _ := io.ReadAll(resp.Body)
	resp.Body.Close()
	if string(body) != "{\"n\":0}\n{\"n\":1}\n{\"n\":2}\n" {
		t.Errorf("ndjson: %q", body)
	}

	w := do(t, router(), "GET", "/export.csv", nil)
	if w.Body.String() != "id,title\n1,The Go Programming Language\n" {
		t.Errorf("csv: %q", w.Body.String())
	}

	w = do(t, router(), "POST", "/save", nil)
	if ck := w.Header().Get("Set-Cookie"); w.Code != 303 || !strings.Contains(ck, "flash=Saved%21") {
		t.Errorf("flash set: %d %q", w.Code, ck)
	}
	w = do(t, router(), "GET", "/", map[string]string{"Cookie": "flash=Saved%21"})
	if w.Body.String() != `flash="Saved!"` || !strings.Contains(w.Header().Get("Set-Cookie"), "Max-Age=0") {
		t.Errorf("flash pop: %q %v", w.Body.String(), w.Header())
	}
}

// router() wires every solution:
func router() *gin.Engine {
	r := gin.New()
	r.Use(Problems())
	r.GET("/books/:id", getBook)
	r.GET("/v2/books/:id", func(c *gin.Context) {
		b, ok := books[c.Param("id")]
		if !ok {
			e := *ErrBookNotFound
			e.Detail = "no book with id " + c.Param("id")
			_ = c.Error(&e)
			return
		}
		OK(c, b)
	})
	r.POST("/books", func(c *gin.Context) { Created(c, "/books/2", Book{ID: 2, Title: "Go in Action"}) })
	r.GET("/books", func(c *gin.Context) { Paginated(c, []Book{books["1"]}, Page{Page: 1, PerPage: 1, Total: 3}) })
	r.GET("/downloads/*name", download)
	r.GET("/ticks", ticks)
	r.GET("/export.csv", func(c *gin.Context) {
		c.Render(http.StatusOK, CSV{Filename: "books.csv",
			Rows: [][]string{{"id", "title"}, {"1", "The Go Programming Language"}}})
	})
	r.POST("/save", func(c *gin.Context) { setFlash(c, "Saved!"); c.Redirect(http.StatusSeeOther, "/") })
	r.GET("/", func(c *gin.Context) { c.String(http.StatusOK, "flash=%q", popFlash(c)) })
	return r
}
