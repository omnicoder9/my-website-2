1. Introduction and versions

Almost every HTTP handler does the same three things before any business logic runs: it reads data out of the request, converts that data into typed Go values, and decides whether those values are acceptable. Gin bundles all three steps behind a family of binding methods on *gin.Context. A binding reads from one part of the request (body, query string, path, headers), decodes it into a struct, and then runs the struct through a validator.[1,2]

This article walks through each binding source, the struct tags that steer them, how validation and custom validators work, and the defensive work around them: sanitizing values and limiting how much data a client can send. Routing, handler organisation and middleware design are covered in companion articles, so they appear here only where binding depends on them.

Versions used Gin v1.12.0 (released 28 February 2026) declares go 1.25.0 in its go.mod and depends on github.com/go-playground/validator/v10 v10.30.1 and github.com/goccy/go-yaml v1.19.2.[3] Behaviour described as "in the source" was read from the v1.12.0 tag; links in the references are pinned to that tag so they will not drift.

Install the module with:

go get github.com/gin-gonic/gin@v1.12.0

2. The gin.Context

Each handler in Gin has the signature func(*gin.Context). The context is the single object through which a handler reads the request and writes the response.[4] Its most important exported fields are:

Field / methodWhat it gives you
c.RequestThe underlying *http.Request from net/http: method, URL, headers and the body stream.[4,5]
c.WriterA gin.ResponseWriter, which wraps http.ResponseWriter.[4]
c.ParamsPath parameters captured by the router, such as :id.[4]
c.Keys, c.Set, c.GetA per-request key/value store used to pass data between middleware and handlers.[6]
c.ErrorsErrors attached during the request (for example by the Bind* methods).[6]

Reading single values directly

For one or two values you do not need a struct. The context has direct accessors:[6]

r.GET("/search/:lang", func(c *gin.Context) {
	lang := c.Param("lang")                 // path parameter
	q := c.Query("q")                       // ?q=… ("" if absent)
	page := c.DefaultQuery("page", "1")     // with fallback
	tags := c.QueryArray("tag")             // ?tag=a&tag=b
	reqID := c.GetHeader("X-Request-Id")    // header
	c.JSON(http.StatusOK, gin.H{"lang": lang, "q": q, "page": page, "tags": tags, "id": reqID})
})

For form bodies the equivalents are PostForm, DefaultPostForm, PostFormArray and PostFormMap; QueryMap reads bracketed keys such as ids[a]=1.[6,1] These accessors return strings. Everything after this point is about the better option for real endpoints: binding into typed, validated structs.

Context lifetime

Gin recycles contexts between requests. The source comment on Copy() says it "returns a copy of the current context that can be safely used outside the request's scope" and that this "has to be used when the context has to be passed to a goroutine".[6] Bind the data you need inside the handler, then hand plain values (or c.Copy()) to any background work.

3. Request body parsing

In net/http, Request.Body is an io.ReadCloser: a stream, not a buffer.[5] Once a decoder has read it, it is empty. Gin's documentation states this directly: "The normal methods for binding request body consumes c.Request.Body and they cannot be called multiple times."[1] In our tests, calling ShouldBindJSON twice on one request returned nil and then EOF.

There are three ways to deal with this:

  1. Bind once. Design the request so one struct describes the body. This is the normal case.
  2. Use ShouldBindBodyWith (or its shortcuts ShouldBindBodyWithJSON, …XML, …YAML, …TOML, …Plain). It reads the body into memory, stores the bytes in the context under gin.BodyBytesKey, and reuses them on later calls.[6] The source warns that because it always reads the body first, ShouldBindWith is faster if you only bind once.[6]
  3. Read raw bytes yourself with c.GetRawData(), which is io.ReadAll(c.Request.Body).[6] Use this for signatures (for example webhook HMAC checks) where you need the exact bytes, then decode them yourself.
func Webhook(c *gin.Context) {
	var evt struct {
		Type string `json:"type" binding:"required"`
	}
	// First read caches the body in the context…
	if err := c.ShouldBindBodyWithJSON(&evt); err != nil {
		c.AbortWithStatusJSON(http.StatusBadRequest, gin.H{"error": err.Error()})
		return
	}
	// …so a second, differently shaped bind still sees the data.
	var envelope map[string]any
	_ = c.ShouldBindBodyWithJSON(&envelope)
	c.JSON(http.StatusOK, gin.H{"type": evt.Type, "keys": len(envelope)})
}

How Gin chooses a decoder

c.ShouldBind and c.Bind pick a binding with binding.Default(method, contentType). The rules, read from binding/binding.go, are:[2]

application/x-yaml, application/yamlbinding.YAML

Media-type parameters are ignored, so application/json; charset=utf-8 selects JSON: c.ContentType() strips everything after the first ; or space before matching.[6] Content-Type is the header that tells the server the media type of the body, as defined by HTTP semantics.[7]

GET requests never use the body Because GET always maps to binding.Form, a GET request with a JSON body and a ?q= query string binds the query value, not the JSON value. We confirmed this in testing. RFC 9110 notes that content in a GET request "has no generally defined semantics".[7] Use the query string for GET input.

4. The binding model: Must bind vs Should bind

Gin offers two families of methods that do the same decoding and validation but handle failure differently.[1]

Must bindShould bind
MethodsBind, BindJSON, BindXML, BindQuery, BindYAML, BindTOML, BindPlain, BindHeader, BindUri, MustBindWithShouldBind, ShouldBindJSON, ShouldBindXML, ShouldBindQuery, ShouldBindYAML, ShouldBindTOML, ShouldBindPlain, ShouldBindHeader, ShouldBindUri, ShouldBindWith
On errorCalls c.AbortWithError(400, err).SetType(ErrorTypeBind), so the response status is fixed to 400 (or 413 when the body hit an http.MaxBytesReader limit) and the handler chain stops.[6,1]Returns the error. You choose the status and response body.[1]
Use whenYou are happy with a bare 400 and plain-text body.Almost always: APIs usually need a JSON error body, a 422, or field-level messages.

The documentation warns that after a Bind* failure, trying to set another status produces [GIN-debug] [WARNING] Headers were already written. Wanted to override status code 400 with 422.[1] The rest of this article uses the Should family.

// Must bind: Gin has already written 400 if err != nil.
if err := c.BindJSON(&in); err != nil {
	return
}

// Should bind: you own the response.
if err := c.ShouldBindJSON(&in); err != nil {
	c.AbortWithStatusJSON(http.StatusUnprocessableEntity, gin.H{"error": err.Error()})
	return
}

Every built-in binding finishes by calling binding.Validator.ValidateStruct, so decoding and validation happen in one call. A decoding error (malformed JSON, "abc" for an int) and a validation error (a field fails a binding rule) come back through the same error value; section 17 shows how to tell them apart.[8,9,10]

5. The important methods

The six methods below cover nearly every handler. Their implementations in context.go are short enough to quote, which makes their behaviour easy to reason about.[6]

A single handler commonly combines several of them, because each reads a different part of the request and none of them (other than the body bindings) consumes anything:

type ArticleURI struct {
	ID int64 `uri:"id" binding:"required,gt=0"`
}
type Precondition struct {
	IfMatch string `header:"If-Match" binding:"required"`
}
type ArticlePatch struct {
	Title string `json:"title" binding:"required,max=120"`
}

func UpdateArticle(c *gin.Context) {
	var (
		uri  ArticleURI
		pre  Precondition
		body ArticlePatch
	)
	if err := c.ShouldBindUri(&uri); err != nil {
		c.AbortWithStatusJSON(http.StatusNotFound, gin.H{"error": "no such article"})
		return
	}
	if err := c.ShouldBindHeader(&pre); err != nil {
		c.AbortWithStatusJSON(http.StatusPreconditionRequired, gin.H{"error": "If-Match header required"})
		return
	}
	if err := c.ShouldBindJSON(&body); err != nil {
		c.AbortWithStatusJSON(http.StatusBadRequest, gin.H{"error": err.Error()})
		return
	}
	c.JSON(http.StatusOK, gin.H{"id": uri.ID, "etag": pre.IfMatch, "title": body.Title})
}

Status 428 Precondition Required is defined in RFC 6585 for exactly this case: the server requires a conditional request such as one carrying If-Match.[12]

6. JSON binding

binding.JSON decodes with the JSON codec selected at build time. By default this is the standard library's encoding/json; build tags jsoniter, go_json or sonic swap in alternatives.[13] After decoding it validates the struct.[8] JSON itself is specified by RFC 8259.[14]

type CreateUser struct {
	Name  string `json:"name"  binding:"required,min=2,max=50"`
	Email string `json:"email" binding:"required,email"`
	Age   *int   `json:"age"   binding:"required,gte=0,lte=150"`
	Role  string `json:"role"  binding:"omitempty,oneof=admin editor viewer"`
}

r.POST("/users", func(c *gin.Context) {
	var in CreateUser
	if err := c.ShouldBindJSON(&in); err != nil {
		c.AbortWithStatusJSON(http.StatusBadRequest, gin.H{"error": err.Error()})
		return
	}
	c.JSON(http.StatusCreated, in)
})
$ curl -s localhost:8080/users -H 'Content-Type: application/json' \
       -d '{"name":"Ada","email":"ada@example.com","age":36}'
{"name":"Ada","email":"ada@example.com","age":36,"role":""}

Behaviour worth knowing

  • Unknown fields are ignored by default. A body of {"x":1,"admin":true} binds without error into a struct that has no admin field.[15] Gin exposes gin.EnableJsonDecoderDisallowUnknownFields(), which sets binding.EnableDecoderDisallowUnknownFields = true for the whole process.[8,4] Exercise 8 shows a per-route alternative.
  • Key matching is case-insensitive. encoding/json prefers an exact key match but also accepts a case-insensitive one.[15] {"NAME":"x"} fills a field tagged json:"name".
  • Numbers in any become float64 unless gin.EnableJsonDecoderUseNumber() is called, which makes them json.Number.[8,15]
  • Size-limit errors. With encoding/json, an http.MaxBytesReader error propagates and MustBindWith answers 413. The source notes that the sonic and go-json codecs do not propagate *http.MaxBytesError.[6]

7. XML binding

binding.XML decodes with encoding/xml and is chosen by ShouldBind for application/xml and text/xml.[2] Those two media types are registered for XML by RFC 7303.[16] Use ShouldBindXML to force it.

type CreateUserXML struct {
	XMLName xml.Name `xml:"user"`  // optional: enforce the root element name
	Name    string   `xml:"name"  binding:"required"`
	Email   string   `xml:"email" binding:"required,email"`
	Tags    []string `xml:"tags>tag"`
}

r.POST("/users.xml", func(c *gin.Context) {
	var in CreateUserXML
	if err := c.ShouldBindXML(&in); err != nil {
		c.AbortWithStatusJSON(http.StatusBadRequest, gin.H{"error": err.Error()})
		return
	}
	c.XML(http.StatusCreated, in)
})
<user><name>Ada</name><email>ada@example.com</email>
  <tags><tag>go</tag><tag>web</tag></tags></user>

Without an XMLName field, encoding/xml does not check the root element's name; with one, the element must match.[17] The a>b tag syntax maps nested elements to a single field.[17]

8. YAML binding

binding.YAML is chosen for application/x-yaml and application/yaml.[2] application/yaml is the media type registered by RFC 9512 in 2024.[18] In v1.12.0 the decoder is github.com/goccy/go-yaml.[3,19] Tag fields with yaml:"…".

type Deploy struct {
	Service  string            `yaml:"service"  binding:"required"`
	Replicas int               `yaml:"replicas" binding:"gte=1,lte=50"`
	Env      map[string]string `yaml:"env"`
}

r.POST("/deploys", func(c *gin.Context) {
	var d Deploy
	if err := c.ShouldBindYAML(&d); err != nil {
		c.AbortWithStatusJSON(http.StatusBadRequest, gin.H{"error": err.Error()})
		return
	}
	c.JSON(http.StatusAccepted, d)
})

9. Form binding

HTML forms submit as application/x-www-form-urlencoded or multipart/form-data. Gin has three form bindings, and the differences matter:[9]

BindingSource mapEffect
binding.Formreq.FormCalls ParseForm and, if the body is multipart, ParseMultipartForm. Contains both URL query and body values.
binding.FormPostreq.PostFormBody values only.
binding.FormMultipartmultipart formAlso binds *multipart.FileHeader fields (section 13).

net/http documents that Request.Form includes both the URL query parameters and the POST/PUT/PATCH form data, and that body values take precedence over query values.[5] In testing, POST /fp?a=query with body a=body bound "body". If a value must only come from the body, use ShouldBindWith(&v, binding.FormPost).

type Login struct {
	User     string `form:"user"     binding:"required"`
	Password string `form:"password" binding:"required"`
	Remember bool   `form:"remember"`               // "true"/"1" work; "on" does NOT
}

r.POST("/login", func(c *gin.Context) {
	var in Login
	if err := c.ShouldBind(&in); err != nil { // Content-Type picks Form
		c.AbortWithStatusJSON(http.StatusBadRequest, gin.H{"error": err.Error()})
		return
	}
	// authenticate …
	c.Status(http.StatusNoContent)
})

Form, query, URI and header bindings all share one mapper (binding/form_mapping.go). It converts strings into Go types (all integer and float kinds, bool, string, time.Time, time.Duration, slices, arrays, pointers and nested structs), and it supports these extra tag options:[20,1]

  • form:"name,default=value" fills a default when the key is absent. For slices separate defaults with ;, as in default=a;b.
  • collection_format:"csv" (also multi, ssv, tsv, pipes) controls how one value splits into a slice.
  • time_format:"2006-01-02", time_utc:"1" and time_location:"Europe/Paris" control time.Time parsing; unix, unixmilli, unixmicro and unixnano are accepted as formats.
  • form:"-" skips a field. An untagged exported field is looked up by its Go field name.
  • form:"name,parser=encoding.TextUnmarshaler" decodes the value with the field's UnmarshalText method (section 19).
Checkbox pitfall: "on" is not a bool Booleans are parsed with strconv.ParseBool, which accepts 1, t, T, TRUE, true, True and their false equivalents.[20,21] A browser checkbox without a value attribute submits on, and in testing that made the whole bind fail with strconv.ParseBool: parsing "on": invalid syntax. Give checkboxes value="true".

HTML checkboxes

Several checkboxes with the same name post repeated keys (colors[]=red&colors[]=green). Bind them to a slice whose tag names the key exactly, including the brackets: Colors []string `form:"colors[]"`.[1]

10. Query parameter binding

The query component of a URI is the part after ?, defined by RFC 3986.[22] ShouldBindQuery maps req.URL.Query() only, using the form tag.[1,6] This is the right choice for list and search endpoints.

type ListQuery struct {
	Page    int       `form:"page,default=1"   binding:"gte=1"`
	Size    int       `form:"size,default=20"  binding:"gte=1,lte=100"`
	Sort    string    `form:"sort,default=created_at" binding:"oneof=created_at name"`
	Tags    []string  `form:"tags" collection_format:"csv"`
	Since   time.Time `form:"since" time_format:"2006-01-02"`
	Visible *bool     `form:"visible"`
}

r.GET("/users", func(c *gin.Context) {
	var q ListQuery
	if err := c.ShouldBindQuery(&q); err != nil {
		c.AbortWithStatusJSON(http.StatusBadRequest, gin.H{"error": err.Error()})
		return
	}
	c.JSON(http.StatusOK, q)
})

11. URI parameter binding

Path parameters come from the router (/users/:id, /files/*path). ShouldBindUri copies c.Params into a map and binds fields tagged uri.[6,1] Because path segments arrive as strings, binding is where they become typed and validated.

type UserURI struct {
	ID string `uri:"id" binding:"required,uuid"`
}

r.GET("/users/:id", func(c *gin.Context) {
	var u UserURI
	if err := c.ShouldBindUri(&u); err != nil {
		c.AbortWithStatusJSON(http.StatusBadRequest, gin.H{"error": err.Error()})
		return
	}
	c.JSON(http.StatusOK, gin.H{"id": u.ID})
})

12. Header binding

ShouldBindHeader binds fields tagged header. The binder passes each tag value through textproto.CanonicalMIMEHeaderKey, so header:"x-request-id" and header:"X-Request-Id" behave the same.[11] That matches HTTP, where field names are case-insensitive.[7]

type ClientHeaders struct {
	RequestID string `header:"X-Request-Id" binding:"required"`
	Locale    string `header:"Accept-Language"`
	RateLimit int    `header:"X-Rate-Limit,default=100"`
}

r.GET("/me", func(c *gin.Context) {
	var h ClientHeaders
	if err := c.ShouldBindHeader(&h); err != nil {
		c.AbortWithStatusJSON(http.StatusBadRequest, gin.H{"error": err.Error()})
		return
	}
	c.JSON(http.StatusOK, h)
})
Headers are client-controlled Never bind identity or trust decisions (user IDs, roles, "real IP") from headers the client can set, unless a proxy you control overwrites them. For client addresses use c.ClientIP() together with the engine's trusted-proxy settings, described in the middleware article.

13. Multipart form binding

multipart/form-data, specified in RFC 7578, sends each field as a separate part and is how browsers upload files.[24] When ShouldBind sees this Content-Type it uses binding.FormMultipart, which calls ParseMultipartForm and binds both ordinary fields and file fields.[2,9] File fields use the type *multipart.FileHeader, or a slice of them for repeated parts.[1,25]

type ProfileForm struct {
	Name    string                  `form:"name" binding:"required"`
	Avatar  *multipart.FileHeader   `form:"avatar" binding:"required"`
	Gallery []*multipart.FileHeader `form:"gallery" binding:"max=5"`
}

r.POST("/profile", func(c *gin.Context) {
	var f ProfileForm
	if err := c.ShouldBind(&f); err != nil {
		c.AbortWithStatusJSON(http.StatusBadRequest, gin.H{"error": err.Error()})
		return
	}
	c.JSON(http.StatusOK, gin.H{
		"name":    f.Name,
		"avatar":  f.Avatar.Size,
		"gallery": len(f.Gallery),
	})
})
curl -F name=Ada -F avatar=@me.png -F gallery=@a.jpg -F gallery=@b.jpg localhost:8080/profile

Memory threshold vs size limit

This is the most commonly misunderstood setting in Gin. engine.MaxMultipartMemory (default 32 MiB) is the maxMemory argument passed to Request.ParseMultipartForm.[23] The net/http docs explain that up to maxMemory bytes of file parts are kept in memory and the remainder is written to temporary files on disk.[5] It is not an upload limit. A 2 GB upload is accepted; most of it simply lands on disk. Limit uploads with http.MaxBytesReader (section 21).

Note also that the bound binding.Form/FormMultipart path uses its own fixed 32 MiB constant, while c.FormFile and c.MultipartForm use engine.MaxMultipartMemory.[9,6] Separately, mime/multipart limits a form to 1,000 parts and 10,000 headers in total; these limits can be adjusted with the multipartmaxparts and multipartmaxheaders GODEBUG settings.[25]

14. File uploads

For one or two files without a struct, use the context helpers:[6,1]

  • c.FormFile("file") returns the first *multipart.FileHeader for that key.
  • c.MultipartForm() returns the parsed *multipart.Form, with form.File["files"] for multiple files.
  • c.SaveUploadedFile(fh, dst) copies the upload to dst, creating the directory with mode 0750 unless you pass a different mode.
Do not trust the filename Gin's documentation says plainly that file.Filename "SHOULD NOT be trusted".[1] RFC 7578 requires receivers to strip directory information from the filename, and Go's Part.FileName() runs the value through filepath.Base for that reason.[24,25] In testing, a part named ../../etc/passwd arrived as passwd. Base-naming still leaves you with an attacker-chosen name, so generate your own storage name. OWASP's File Upload Cheat Sheet recommends exactly this, along with an allow-list of extensions, validating the file type, size limits and storing files outside the web root.[26]

A defensive upload handler validates in layers: binding checks presence, the extension is checked against an allow-list, the content is sniffed, and the server picks the filename.

type UploadForm struct {
	Title  string                `form:"title"  binding:"required"`
	Avatar *multipart.FileHeader `form:"avatar" binding:"required"`
}

r.POST("/avatar", func(c *gin.Context) {
	var f UploadForm
	if err := c.ShouldBind(&f); err != nil {
		c.AbortWithStatusJSON(http.StatusBadRequest, gin.H{"error": err.Error()})
		return
	}

	// 1. allow-list the extension
	ext := strings.ToLower(filepath.Ext(f.Avatar.Filename))
	if ext != ".png" && ext != ".jpg" && ext != ".jpeg" {
		c.AbortWithStatusJSON(http.StatusUnsupportedMediaType, gin.H{"error": "png or jpeg only"})
		return
	}

	// 2. sniff the real content type from the first 512 bytes
	src, err := f.Avatar.Open()
	if err != nil {
		c.AbortWithStatus(http.StatusInternalServerError)
		return
	}
	defer src.Close()
	head := make([]byte, 512)
	n, _ := io.ReadFull(src, head)
	ct := http.DetectContentType(head[:n])
	if ct != "image/png" && ct != "image/jpeg" {
		c.AbortWithStatusJSON(http.StatusUnsupportedMediaType, gin.H{"error": "content is " + ct})
		return
	}

	// 3. never use the client's name for the storage path
	dst := filepath.Join("uploads", fmt.Sprintf("%d%s", time.Now().UnixNano(), ext))
	if err := c.SaveUploadedFile(f.Avatar, dst); err != nil {
		c.AbortWithStatus(http.StatusInternalServerError)
		return
	}
	c.JSON(http.StatusCreated, gin.H{"stored_as": dst, "size": f.Avatar.Size, "type": ct})
})

http.DetectContentType implements the WHATWG MIME-sniffing algorithm, considers at most the first 512 bytes, and always returns a valid MIME type, falling back to application/octet-stream.[5] In testing, a file named evil.png containing <script> was detected as text/html; charset=utf-8 and rejected with 415 Unsupported Media Type.[7] Sniffing is a sanity check, not proof the file is safe; for images, decoding and re-encoding them is a stronger defence that OWASP also describes.[26]

The validator normally reads a tag called validate. Gin's default validator calls SetTagName("binding"), which is why Gin examples use binding:"…".[10,27]

Mass assignment Binding copies every matching key into your struct. If the struct also has fields the client must not set (IsAdmin, OwnerID, Balance), a client can set them by adding keys to the request. OWASP calls this mass assignment and recommends binding into a separate input DTO that only contains user-editable fields, or explicitly excluding sensitive fields.[28] Use dedicated request structs, and tag server-owned fields with json:"-" and form:"-" if they must share a type.

16. Required fields

binding:"required" is the most used rule, and also the most misread. The validator documents that required "validates that the value is not the data types default zero value": numbers must not be zero, strings must not be "", and slices, maps, pointers, interfaces, channels and functions must not be nil.[27]

The consequence is that required cannot tell "missing" from "sent as the zero value" on a non-pointer field:

FieldBodyResult
Age int `binding:"required"`{"age":0}Fails: 0 is the zero value
Age *int `binding:"required"`{"age":0}Passes: pointer is non-nil
Age *int `binding:"required"`{}Fails: pointer is nil
OK bool `binding:"required"`{"ok":false}Fails: required on a plain bool means "must be true"

All four rows were checked in the test suite. The rule of thumb is: if zero is a legitimate value, use a pointer, then dereference after validation. Combine with other rules as usual: binding:"required,gte=0,lte=150".

For nested structs, required on a non-pointer struct field is not enforced unless the validator was created with WithRequiredStructEnabled; Gin's default validator is created with plain validator.New().[27,10] Use a pointer to a nested struct when the whole object is required.

Conditional requirements are built in: required_if, required_unless, required_with, required_without and their _all variants, plus excluded_* counterparts.[27]

type Shipping struct {
	Method  string `json:"method"  binding:"required,oneof=pickup delivery"`
	Address string `json:"address" binding:"required_if=Method delivery"`
}

Turning errors into useful responses

A validation failure is a validator.ValidationErrors value, a slice of FieldError. Each one reports the field, the failed tag and its parameter.[27] A decode failure (bad JSON, wrong type) is a different error type. Use errors.As to separate them:

func validationMessages(err error) map[string]string {
	var ve validator.ValidationErrors
	if !errors.As(err, &ve) {
		return map[string]string{"_": err.Error()} // malformed body / wrong type
	}
	out := make(map[string]string, len(ve))
	for _, fe := range ve {
		out[fe.Field()] = fmt.Sprintf("failed %q (param %q)", fe.Tag(), fe.Param())
	}
	return out
}

By default fe.Field() is the Go field name (Age). To report the JSON name instead, register a tag-name function on the engine. This changes names for every validation in the process, so do it once at startup:[27]

v := binding.Validator.Engine().(*validator.Validate)
v.RegisterTagNameFunc(func(f reflect.StructField) string {
	name, _, _ := strings.Cut(f.Tag.Get("json"), ",")
	if name == "-" {
		return ""
	}
	return name
})

For translated, human-readable messages the validator project provides universal-translator integrations; see the package documentation.[27] When binding a slice of structs ([]Item at the top level), Gin validates each element and returns a binding.SliceValidationError listing the failing indexes.[10]

Which status code? 400 Bad Request covers malformed syntax. 422 Unprocessable Content, now part of RFC 9110, is for content that is syntactically correct but cannot be processed, which suits validation failures; both are common in practice.[7]

18. Custom validators

When no built-in tag fits, register your own on the validator engine. Gin exposes it through binding.Validator.Engine(), which returns any and must be asserted to *validator.Validate.[2,1]

Field-level validators

var usernameRE = regexp.MustCompile(`^[a-z][a-z0-9_]{2,15}$`)

var validUsername validator.Func = func(fl validator.FieldLevel) bool {
	s, ok := fl.Field().Interface().(string)
	return ok && usernameRE.MatchString(s)
}

func registerValidators() error {
	v, ok := binding.Validator.Engine().(*validator.Validate)
	if !ok {
		return errors.New("unexpected validator engine")
	}
	return v.RegisterValidation("username", validUsername)
}

type Signup struct {
	Username string `json:"username" binding:"required,username"`
}

Register validators once at startup, before the server accepts requests. RegisterValidation is documented as not thread-safe; it is meant to be called before any validation happens.[27] A tag used in a struct but never registered causes the validator to panic, so a missing registration fails loudly on the first request that uses it.[27]

A validator can also take a parameter. fl.Param() returns the text after = in the tag, so binding:"divisibleby=5" passes "5" to the function.[27]

Struct-level validators

Rules involving several fields that the cross-field tags cannot express belong in a struct-level validator. It runs once for the whole struct and reports errors against specific fields.[27]

type PasswordChange struct {
	Current string `json:"current" binding:"required"`
	New     string `json:"new"     binding:"required,min=12"`
	Confirm string `json:"confirm" binding:"required"`
}

func passwordChangeRules(sl validator.StructLevel) {
	p := sl.Current().Interface().(PasswordChange)
	if p.New != p.Confirm {
		sl.ReportError(p.Confirm, "Confirm", "confirm", "eqfield_new", "")
	}
	if p.New == p.Current {
		sl.ReportError(p.New, "New", "new", "differs_from_current", "")
	}
}

// at startup
v.RegisterStructValidation(passwordChangeRules, PasswordChange{})

Replacing the validator

binding.Validator is a package variable of interface type StructValidator (ValidateStruct(any) error and Engine() any). Assign your own implementation to use a different validation library or to change global options.[2]

19. Custom binding

There are three levels of customisation, from smallest to largest.

a) Custom field types for form, query and URI values

If a field type implements binding.BindUnmarshaler (UnmarshalParam(string) error), the form mapper calls it instead of its built-in conversion.[20,1] Alternatively, tag the field with parser=encoding.TextUnmarshaler to use a type's standard UnmarshalText.[20]

// Cents parses "12.34" into 1234 without floating point.
type Cents int64

func (c *Cents) UnmarshalParam(s string) error {
	whole, frac, _ := strings.Cut(s, ".")
	if len(frac) > 2 {
		return fmt.Errorf("too many decimal places in %q", s)
	}
	frac = (frac + "00")[:2]
	w, err := strconv.ParseInt(whole, 10, 64)
	if err != nil || w < 0 {
		return fmt.Errorf("invalid amount %q", s)
	}
	f, err := strconv.ParseInt(frac, 10, 64)
	if err != nil {
		return fmt.Errorf("invalid amount %q", s)
	}
	*c = Cents(w*100 + f)
	return nil
}

type PriceFilter struct {
	Min Cents `form:"min"`
	Max Cents `form:"max" binding:"omitempty,gtefield=Min"`
}

For JSON, XML and YAML bodies, the decoders' own hooks apply instead: implement json.Unmarshaler, xml.Unmarshaler or the YAML equivalent.[15,17]

b) A new binding.Binding

Any type with Name() string and Bind(*http.Request, any) error is a binding and can be passed to ShouldBindWith.[2] Implement BindBody([]byte, any) error as well if you want it to work with ShouldBindBodyWith. Remember to call the validator yourself, because the built-in bindings do that inside Bind.

// plainLines binds a text/plain body into a []string, one trimmed line per item.
type plainLines struct{}

func (plainLines) Name() string { return "plain-lines" }

func (plainLines) Bind(r *http.Request, obj any) error {
	dst, ok := obj.(*[]string)
	if !ok {
		return errors.New("plain-lines: target must be *[]string")
	}
	b, err := io.ReadAll(r.Body)
	if err != nil {
		return err
	}
	for _, line := range strings.Split(string(b), "\n") {
		if line = strings.TrimSpace(line); line != "" {
			*dst = append(*dst, line)
		}
	}
	return nil
}

r.POST("/lines", func(c *gin.Context) {
	var lines []string
	if err := c.ShouldBindWith(&lines, plainLines{}); err != nil {
		c.AbortWithStatusJSON(http.StatusBadRequest, gin.H{"error": err.Error()})
		return
	}
	c.JSON(http.StatusOK, gin.H{"count": len(lines), "lines": lines})
})

c) A custom form tag name

The form mapper can be pointed at a tag of your choice with binding.MapFormWithTag inside a custom binding, which is useful when existing structs already carry tags for another library.[1,20]

20. Request sanitization

Validation answers "is this acceptable?". Sanitization changes the value so that it is acceptable or canonical. The two are easy to mix up, and doing them in the wrong order lets bad data through.

OWASP's guidance is that input validation is not the primary defence against injection or cross-site scripting; those are prevented by handling data correctly where it is used.[29,30] That gives a clear division of labour:

ConcernWhere to handle it
Canonicalisation (trim whitespace, lower-case emails, normalise Unicode)Right after binding, before validation
Shape and range (lengths, formats, allow-lists)Validator tags and custom validators
SQL injectionParameterised queries (db.Query("… WHERE id = $1", id)), never string building
HTML injection / XSSContextual output encoding, e.g. html/template, which escapes automatically by context[31,30]
Rich HTML input that must keep some markupA dedicated allow-list HTML sanitizer, applied once before storage[30]
File names and pathsServer-generated names; never join client strings into paths[26]

Canonicalising after binding

Because validation runs inside the bind call, a value like " " passes required (it is not empty) unless you check for it. Two practical patterns:

  1. Validate what you mean. Add a notblank validator (see Exercise 3) so whitespace-only strings fail.
  2. Canonicalise, then validate. Bind with a binding that skips validation, clean up, then validate explicitly with binding.Validator.ValidateStruct. The simpler variant shown below cleans up after a validated bind, which is enough when the clean-up cannot make a valid value invalid.
type Sanitizer interface{ Sanitize() }

func (u *CreateUser) Sanitize() {
	u.Name = strings.TrimSpace(u.Name)
	u.Email = strings.ToLower(strings.TrimSpace(u.Email))
}

// BindClean binds, sanitizes, then re-validates the cleaned value.
func BindClean(c *gin.Context, obj any) error {
	if err := c.ShouldBind(obj); err != nil {
		return err
	}
	if s, ok := obj.(Sanitizer); ok {
		s.Sanitize()
		return binding.Validator.ValidateStruct(obj)
	}
	return nil
}

In the test suite, {"name":" Ada ","email":"ADA@Example.com"} came out as "Ada" and "ada@example.com".

Do not "strip dangerous characters" from plain text Removing <, ' or ; from every field corrupts legitimate data (names like O'Brien, maths, code samples) and still misses encodings you did not think of. Store what the user typed, constrain it with validation, and encode it for the context where it is output.[29,30]

21. Request size limits

Gin itself does not cap body sizes. Without a cap, a client can stream gigabytes into io.ReadAll or into the multipart temp directory. Limits belong at several layers.

The body: http.MaxBytesReader

http.MaxBytesReader(w, r.Body, n) wraps the body so that reading past n bytes returns a *http.MaxBytesError; it also tells the server to close the connection after the response.[5] Installed as middleware, it protects every binding underneath it.

func MaxBodyBytes(n int64) gin.HandlerFunc {
	return func(c *gin.Context) {
		// fast path: reject declared-oversize bodies before reading anything
		if c.Request.ContentLength > n {
			c.AbortWithStatusJSON(http.StatusRequestEntityTooLarge, gin.H{"error": "body too large"})
			return
		}
		c.Request.Body = http.MaxBytesReader(c.Writer, c.Request.Body, n)
		c.Next()
	}
}

func statusFor(err error) int {
	var mbe *http.MaxBytesError
	if errors.As(err, &mbe) {
		return http.StatusRequestEntityTooLarge
	}
	return http.StatusBadRequest
}

api := r.Group("/api", MaxBodyBytes(1<<20))   // 1 MiB for JSON APIs
uploads := r.Group("/upload", MaxBodyBytes(20<<20)) // 20 MiB for files

The ContentLength check is only a shortcut; chunked requests have length −1, so the reader limit is what actually enforces the cap. Both paths were tested. 413 Content Too Large is the status RFC 9110 defines for a request body larger than the server will process.[7] Gin's own MustBindWith maps *http.MaxBytesError to 413.[6]

Other limits that already exist

r.Run() uses a server with no timeouts. For production, build the http.Server yourself:

srv := &http.Server{
	Addr:              ":8080",
	Handler:           router,
	ReadHeaderTimeout: 5 * time.Second,  // slow-header (Slowloris-style) protection
	ReadTimeout:       30 * time.Second,
	MaxHeaderBytes:    1 << 20,
}
log.Fatal(srv.ListenAndServe())

Size limits on content (string lengths, number of items) belong in validation: max=500, max=50,dive. The body cap stops a client from sending too many bytes; validation stops a small body from describing too much work.

	Newsletter  *bool  `json:"newsletter" binding:"required"`   // present; may be false
}

On a plain bool, required rejects the zero value false, which here is exactly the rule we want. On *bool, required only rejects nil, so an explicit false passes and a missing key fails.[27] Tested: accept_terms:false → 400; missing newsletter → 400; newsletter:false → 200.

Exercise 3: A custom validator with friendly messages

Create a notblank validator that rejects whitespace-only strings. Use it on a comment body (required, at most 500 characters), return 422 with messages keyed by JSON field name, for example {"errors":{"body":"must not be blank"}}.

Solution 
var notBlank validator.Func = func(fl validator.FieldLevel) bool {
	return strings.TrimSpace(fl.Field().String()) != ""
}

func Register() error {
	v, ok := binding.Validator.Engine().(*validator.Validate)
	if !ok {
		return errors.New("validator engine is not *validator.Validate")
	}
	// report JSON names ("body") instead of Go names ("Body")
	v.RegisterTagNameFunc(func(f reflect.StructField) string {
		name, _, _ := strings.Cut(f.Tag.Get("json"), ",")
		if name == "-" {
			return ""
		}
		return name
	})
	return v.RegisterValidation("notblank", notBlank)
}

type Comment struct {
	Body string `json:"body" binding:"required,notblank,max=500"`
}

func Messages(err error) map[string]string {
	var ve validator.ValidationErrors
	if !errors.As(err, &ve) {
		return map[string]string{"body": "malformed request"}
	}
	out := map[string]string{}
	for _, fe := range ve {
		switch fe.Tag() {
		case "required":
			out[fe.Field()] = "is required"
		case "notblank":
			out[fe.Field()] = "must not be blank"
		case "max":
			out[fe.Field()] = "must be at most " + fe.Param() + " characters"
		default:
			out[fe.Field()] = "is invalid"
		}
	}
	return out
}

func CommentHandler(c *gin.Context) {
	var in Comment
	if err := c.ShouldBindJSON(&in); err != nil {
		c.AbortWithStatusJSON(http.StatusUnprocessableEntity, gin.H{"errors": Messages(err)})
		return
	}
	c.JSON(http.StatusCreated, in)
}

Call Register() once in main before starting the server. Tested responses: {"body":" "} → 422 must not be blank; {} → 422 is required; 501 characters → 422 must be at most 500 characters.

Exercise 5: Per-route body limit

Write middleware LimitBody(n) and a JSON echo handler so that any body over n bytes gets 413 with a JSON error, both when Content-Length is declared and when the body is chunked (unknown length).

Solution 
func LimitBody(n int64) gin.HandlerFunc {
	return func(c *gin.Context) {
		if c.Request.ContentLength > n {
			c.AbortWithStatusJSON(http.StatusRequestEntityTooLarge, gin.H{"error": "body too large"})
			return
		}
		c.Request.Body = http.MaxBytesReader(c.Writer, c.Request.Body, n)
		c.Next()
	}
}

func Echo(c *gin.Context) {
	var m map[string]any
	if err := c.ShouldBindJSON(&m); err != nil {
		var mbe *http.MaxBytesError
		if errors.As(err, &mbe) {
			c.AbortWithStatusJSON(http.StatusRequestEntityTooLarge,
				gin.H{"error": "body too large", "limit": mbe.Limit})
			return
		}
		c.AbortWithStatusJSON(http.StatusBadRequest, gin.H{"error": err.Error()})
		return
	}
	c.JSON(http.StatusOK, m)
}

// r.POST("/echo", LimitBody(64), Echo)

The chunked case is caught by the reader, which returns *http.MaxBytesError carrying the configured Limit.[5] Tested with a 64-byte limit: declared oversize → 413 body too large; chunked oversize → 413 {"error":"body too large","limit":64}.

Exercise 6: Multiple file upload

Accept POST /gallery with one to three files in the photos field. Reject any file over 2 MiB with 413. Use struct binding, not c.MultipartForm().

Solution 
type Gallery struct {
	Photos []*multipart.FileHeader `form:"photos" binding:"required,min=1,max=3"`
}

const maxPhoto = 2 << 20

func GalleryHandler(c *gin.Context) {
	var g Gallery
	if err := c.ShouldBind(&g); err != nil {
		c.AbortWithStatusJSON(http.StatusBadRequest, gin.H{"error": err.Error()})
		return
	}
	names := make([]string, 0, len(g.Photos))
	for _, fh := range g.Photos {
		if fh.Size > maxPhoto {
			c.AbortWithStatusJSON(http.StatusRequestEntityTooLarge, gin.H{"error": fh.Filename + " exceeds 2 MiB"})
			return
		}
		names = append(names, fh.Filename)
	}
	c.JSON(http.StatusOK, gin.H{"received": names})
}

min/max on a slice count elements.[27] Checking fh.Size happens after the whole body was received, so in production also put MaxBodyBytes in front of this route (roughly 3 × 2 MiB plus overhead). Tested: 2 files → 200, 4 → 400 (max), 0 → 400 (required), one 3 MiB file → 413.

Exercise 8: Strict JSON on one route only

A role-change endpoint must reject unknown JSON keys (to stop clients sneaking in "admin":true), but the global gin.EnableJsonDecoderDisallowUnknownFields() would affect every route. Write a custom binding that is strict for this route only and still runs validation.

Solution 
type strictJSON struct{}

func (strictJSON) Name() string { return "strict-json" }

func (strictJSON) Bind(r *http.Request, obj any) error {
	if r == nil || r.Body == nil {
		return errors.New("invalid request")
	}
	dec := json.NewDecoder(r.Body)
	dec.DisallowUnknownFields()
	if err := dec.Decode(obj); err != nil {
		return err
	}
	if dec.More() {
		return errors.New("unexpected data after JSON object")
	}
	return binding.Validator.ValidateStruct(obj)
}

var StrictJSON binding.Binding = strictJSON{}

type RoleChange struct {
	Role string `json:"role" binding:"required,oneof=viewer editor"`
}

func RoleHandler(c *gin.Context) {
	var in RoleChange
	if err := c.ShouldBindWith(&in, StrictJSON); err != nil {
		c.AbortWithStatusJSON(http.StatusBadRequest, gin.H{"error": err.Error()})
		return
	}
	c.JSON(http.StatusOK, in)
}

Decoder.DisallowUnknownFields makes decoding fail on keys that do not match an exported field, and Decoder.More detects trailing values.[15] Tested: {"role":"editor","admin":true} → 400 json: unknown field "admin". This complements, but does not replace, a dedicated input struct against mass assignment.[28]
