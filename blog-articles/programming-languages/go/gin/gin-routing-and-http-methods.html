Routing and HTTP Methods in Gin

A practical guide with runnable examples, exercises and solutions · Verified against Gin v1.12.0 and Go 1.25 · October 2026

Routing is the part of a web framework that decides which code runs for a given request. This article explains how the Gin framework for Go registers and matches routes, how each standard HTTP method should be used, how path, query and wildcard parameters work, how to organise routes with groups, what Gin does when routes conflict, how to customise 404 and 405 responses, and how to design and version a RESTful API. Every behavioural claim about Gin was checked against the v1.12.0 source code and by running the programs shown here.

1. How Gin routes requests

Gin is an HTTP web framework written in Go whose router is derived from Julien Schmidt's httprouter.1,2 Like httprouter, it stores routes in a compressed prefix tree (a radix tree), and it keeps one tree per HTTP method.3,4 When a request arrives, Gin picks the tree for the request method and walks it using the request path. Because each path segment is compared once, lookup cost depends on the length of the path rather than on the number of registered routes.2

Two consequences of this design shape everything in this article:

  • Routes are patterns, not regular expressions. A path is made of static segments, named parameters (:id) and at most one trailing catch-all (*path).2,3
  • Ambiguity is rejected when routes are registered. If two patterns could not be told apart unambiguously by the tree, Gin panics at start-up instead of guessing at request time.3 Section 10 lists exactly which combinations are allowed.

To follow along, create a module and add Gin:

mkdir gin-routing && cd gin-routing
go mod init example.com/gin-routing
go get github.com/gin-gonic/gin@v1.12.0

Gin v1.12.0 declares go 1.25.0 in its go.mod, so a Go 1.25 or later toolchain is needed; recent Go versions download the required toolchain automatically.5,6

2. Route registration

A route binds three things: an HTTP method, a path pattern and a chain of handler functions. Gin offers three ways to register one.7

APIWhat it registers
r.GET(path, h...), POST, PUT, PATCH, DELETE, HEAD, OPTIONSOne route for that method. Each is a shortcut for Handle.
r.Handle(method, path, h...)One route for any method token, including non-standard ones such as WebDAV's PROPFIND. The method must match ^[A-Z]+$, otherwise Gin panics with http method get is not valid.
r.Match([]string{...}, path, h...)The same handlers for a chosen list of methods.
r.Any(path, h...)The same handlers for nine methods: GET, POST, PUT, PATCH, HEAD, OPTIONS, DELETE, CONNECT and TRACE.
package main

import (
	"net/http"

	"github.com/gin-gonic/gin"
)

func requireToken(token string) gin.HandlerFunc {
	return func(c *gin.Context) {
		if c.GetHeader("Authorization") != "Bearer "+token {
			c.AbortWithStatus(http.StatusUnauthorized)
			return
		}
		c.Next()
	}
}

func main() {
	r := gin.Default() // gin.New() plus the Logger and Recovery middleware

	// Shortcut method.
	r.GET("/ping", func(c *gin.Context) {
		c.JSON(http.StatusOK, gin.H{"message": "pong"})
	})

	// Generic form: any upper-case method token.
	r.Handle("PROPFIND", "/dav/*path", func(c *gin.Context) {
		c.Status(http.StatusNotImplemented)
	})

	// Several methods, one handler.
	r.Match([]string{http.MethodGet, http.MethodHead}, "/health", func(c *gin.Context) {
		c.Status(http.StatusOK)
	})

	// A handler chain: middleware first, the final function is the handler.
	r.GET("/admin/stats", requireToken("s3cret"), func(c *gin.Context) {
		c.JSON(http.StatusOK, gin.H{"requests": 42})
	})

	r.Run(":8080") // listens on 0.0.0.0:8080
}

Listing 1. The four registration styles. gin.Default attaches the Logger and Recovery middleware; gin.New attaches none.8

Handler chains

Every route stores a HandlersChain: the middleware of the enclosing group(s) followed by the functions you pass. Gin builds that chain once, at registration time, by copying the group's current middleware into the route.7 Inside a handler, c.Next() runs the rest of the chain and c.Abort() (or AbortWithStatus, AbortWithStatusJSON) stops it.9

Order matters: call Use before registering routes. Because the chain is copied at registration time, middleware added with r.Use after a route is registered does not run for that route. In a test against v1.12.0, a route registered before r.Use(mw) did not see the middleware, while a route registered after it did. The 404 and 405 handlers are the exception: Use rebuilds them, so global middleware always reaches them.4

Seeing what is registered

In debug mode Gin prints each route as it is registered, for example [GIN-debug] GET /ping --> main.main.func1 (3 handlers). Assigning gin.DebugPrintRouteFunc changes that format, and r.Routes() returns a []gin.RouteInfo with the method, path and handler name of every route.4,8 Section 9 uses this for documentation and tests.

3. GET, POST, PUT, PATCH, DELETE, HEAD, OPTIONS

HTTP method semantics are defined by RFC 9110, which obsoletes RFC 7231.10 Two properties matter most when designing routes. A method is safe if it is essentially read-only: the client does not request, and does not expect, any state change on the server. A method is idempotent if sending the same request several times has the same intended effect on the server as sending it once, so a client may retry it automatically after a network failure.10 PATCH is defined separately in RFC 5789.11

MethodPurposeSafeIdempotentTypical success statusSpec
GETTransfer a current representation of the target resourceYesYes200 OKRFC 9110 §9.3.1
HEADSame as GET, but the server must not send contentYesYes200 OK (headers only)§9.3.2
POSTHave the resource process the enclosed representation, for example create a subordinate resourceNoNo201 Created with Location, or 200/204§9.3.3
PUTCreate or replace the target resource's state with the enclosed representationNoYes200 OK or 204 No Content; 201 if it created the resource§9.3.4
PATCHApply a set of changes, described by a patch document, to the resourceNoNot necessarily200 OK or 204 No ContentRFC 5789 §2
DELETERemove the association between the target URI and its current functionalityNoYes204 No Content, 200 OK, or 202 Accepted§9.3.5
OPTIONSDescribe the communication options for the target resourceYesYes200 OK or 204, with Allow§9.3.7

Table 1. Method properties. Safety and idempotency are listed in RFC 9110 §9.2.1–9.2.2; PATCH's lack of guaranteed idempotency is stated in RFC 5789 §2.10,11

GET

Use GET for every read. Because GET is safe, crawlers, prefetchers and caches may issue it freely, so a GET handler must never change state.10 Content in a GET request has no generally defined semantics, so filters belong in the query string (section 5), not in a request body.10

POST

POST asks the target resource to process the request content according to its own semantics. In APIs it most often means "create a new member of this collection". When a POST creates a resource, the server should answer 201 Created and identify the new resource in a Location header.10 POST is not idempotent, so retrying a failed POST can create duplicates.

PUT

PUT sends the complete new state of the resource. Sending the same PUT twice leaves the resource in the same state as sending it once, which is what makes PUT idempotent. If the resource did not exist and PUT created it, the server must answer 201 Created; if it replaced an existing one, 200 OK or 204 No Content.10 When the server, not the client, chooses identifiers (as in this article's example), PUT is used only for replacement and a PUT to an unknown id returns 404.

PATCH

PATCH carries a patch document whose media type defines how to apply the change. RFC 5789 tells servers to answer 415 Unsupported Media Type when they do not support the patch format, and defines the Accept-Patch response header to advertise the formats they do support.11 Two standard JSON formats exist: JSON Merge Patch (application/merge-patch+json), where the body looks like a partial resource and null deletes a member, and JSON Patch (application/json-patch+json), a list of operations such as add, remove and replace.12,13 In Go, a struct of pointer fields is a convenient way to tell "field absent" (nil) from "field set to its zero value".

DELETE

DELETE removes the resource at the target URI. A successful DELETE usually returns 204 No Content; 202 Accepted is appropriate when deletion will happen later.10

HEAD

HEAD is identical to GET except that the server must not send content in the response; it should send the same header fields it would have sent for GET.10

Gin does not answer HEAD automatically. With only r.GET("/items", h) registered, a HEAD /items request gets 404 in Gin v1.12.0 (or 405 if HandleMethodNotAllowed is on), because HEAD has its own route tree.4 Register HEAD explicitly, for example r.HEAD("/items", h) or r.Match([]string{"GET","HEAD"}, ...). Reusing the GET handler is safe with a real server: Go's net/http server discards the body for HEAD requests, and ResponseWriter.Write returns http.ErrBodyNotAllowed when the method does not permit a body.14 This differs from the standard library's own ServeMux, where since Go 1.22 a pattern with the GET method also matches HEAD.14,15 Gin's Static helpers register both GET and HEAD for you.7

OPTIONS

OPTIONS asks what the server supports for a resource; a server that wants to answer should send an Allow header listing the methods.10 Browsers also send OPTIONS as a CORS preflight before cross-origin requests that use non-simple methods or headers.16 Gin does not generate OPTIONS responses (an unregistered OPTIONS request receives 404 in v1.12.0), so either register OPTIONS routes yourself or use the gin-contrib/cors middleware, which answers preflight requests.17

All seven methods on one resource

The following excerpt from the complete example in section 12 registers every method for a books collection and its items. Note the empty relative path "": it registers the group's own path, so books.GET("", ...) handles /api/v1/books without a trailing slash.

const (
	allowCollection = "GET, HEAD, POST, OPTIONS"
	allowItem       = "GET, HEAD, PUT, PATCH, DELETE, OPTIONS"
)

// Register attaches every /books route to the given group.
func (h *BookHandler) Register(rg *gin.RouterGroup) {
	books := rg.Group("/books")
	books.GET("", h.list)
	books.HEAD("", h.list)
	books.POST("", h.create)
	books.OPTIONS("", allow(allowCollection))

	book := books.Group("/:id", h.bookID) // nested group with middleware
	book.GET("", h.get)
	book.HEAD("", h.get)
	book.PUT("", h.replace)
	book.PATCH("", h.patch)
	book.DELETE("", h.remove)
	book.OPTIONS("", allow(allowItem))
}

func allow(methods string) gin.HandlerFunc {
	return func(c *gin.Context) {
		c.Header("Allow", methods)
		c.Status(http.StatusNoContent)
	}
}

Listing 2. Method routing for a collection and an item (from main.go in section 12).

4. Route parameters

A path segment that starts with a colon is a named parameter. It matches exactly one non-empty path segment, that is, everything up to the next / or the end of the path.2,8 Read it with c.Param("name").9

PatternRequest pathResult (Gin v1.12.0)
/user/:name/user/johnMatch, name = "john"
/user/No match (404). A parameter cannot be empty.
/userNo match (404)
/user/john/sendNo match. A parameter never spans a /.

Several parameters may appear in one path (/orgs/:org/repos/:repo), but only one per segment: /f/:a:b panics with only one wildcard per path segment is allowed.3 Parameter values are URL-decoded by default (/f/caf%C3%A9 gives "café").

Validating parameters with ShouldBindUri

c.Param always returns a string. To convert and validate in one step, bind the parameters into a struct with uri tags; Gin applies validation rules from the binding tag using the go-playground validator.8,18

type bookURI struct {
	ID int `uri:"id" binding:"required,min=1"`
}

// bookID validates the :id path parameter once for every item route.
func (h *BookHandler) bookID(c *gin.Context) {
	var u bookURI
	if err := c.ShouldBindUri(&u); err != nil {
		problem(c, http.StatusBadRequest, "invalid book id", err.Error())
		return
	}
	c.Set("bookID", u.ID)
	c.Next()
}

Listing 3. Middleware on the /:id group validates the parameter once, so GET /books/abc returns 400 before any handler runs.

The matched pattern: c.FullPath()

c.FullPath() returns the registered pattern that matched, such as /api/v1/books/:id, or an empty string when nothing matched.8,9 Use it, not the raw path, as a label in logs and metrics: it has a bounded number of values, whereas raw paths contain every id ever requested.

Encoded slashes

By default Gin matches against URL.Path, which Go has already decoded, so /f/a%2Fb is seen as /f/a/b and does not match /f/:name.4,19 Setting r.UseRawPath = true makes Gin match against the encoded path and then unescape the parameter (UnescapePathValues is true by default), so the same request matches with name = "a/b". Both results were confirmed against v1.12.0.

5. Query parameters

The query is the part of a URI after ? and before any #.20 Unlike path parameters, query parameters are not part of route matching: /search?q=go and /search hit the same route. Use them for optional inputs such as filters, sorting and pagination.

MethodReturnsFor ?q=&tag=a&tag=b&f[x]=1&f[y]=2
c.Query("q")The first value, or """"
c.GetQuery("q")Value and whether the key was present"", true (absent would be "", false)
c.DefaultQuery("page", "1")The value, or the default when the key is absent"1"
c.QueryArray("tag")All values for a repeated key[a b]
c.QueryMap("f")Bracketed keys as a mapmap[x:1 y:2]

Table 2. Query accessors on *gin.Context; outputs recorded from Gin v1.12.0.8,9

GetQuery is the only accessor that distinguishes ?q= (present, empty) from no q at all. Note also that DefaultQuery returns the default only when the key is absent, not when it is empty.9

Binding and validating a query struct

For anything beyond one or two values, bind the query into a struct. ShouldBindQuery reads only the query string (never the body), supports defaults through the form tag (form:"page,default=1") and validation through the binding tag.8

type listQuery struct {
	Author string `form:"author"`
	Sort   string `form:"sort,default=id" binding:"oneof=id title year"`
	Page   int    `form:"page,default=1" binding:"min=1"`
	Limit  int    `form:"limit,default=20" binding:"min=1,max=100"`
}

func (h *BookHandler) list(c *gin.Context) {
	var q listQuery
	if err := c.ShouldBindQuery(&q); err != nil {
		problem(c, http.StatusBadRequest, "invalid query", err.Error())
		return
	}

Listing 4. A validated pagination and filter query. GET /api/v1/books?limit=500 returns 400.

Repeated keys (?tag=a&tag=b) bind to a slice field by default; the collection_format tag accepts other encodings such as csv (?tag=a,b).8

6. Wildcard routes

A segment that starts with * is a catch-all parameter. It matches the rest of the path, including slashes, and must be the last element of the pattern.2,3 The value keeps its leading slash.

Pattern /files/*path, requestResult (Gin v1.12.0)
/files/a/b.txtMatch, path = "/a/b.txt"
/files/Match, path = "/"
/files301 redirect to /files/ (trailing-slash redirect, section 10)

Gin enforces these rules at registration:3

  • /f/*p/x panics: catch-all routes are only allowed at the end of the path.
  • A catch-all cannot share its position with any other child. /files/*path plus /files/info panics in either registration order, and so does /*p plus /api/x.
  • The parent path itself may be registered separately: /f and /f/*p coexist.

Gin's own Static(prefix, root) and StaticFS are built on a catch-all: they register GET and HEAD on prefix + "/*filepath".7 This is why r.Static("/assets", ...) conflicts with any other route under /assets/.

Treat catch-all values as untrusted file paths. Gin does not clean the request path by default, so GET /downloads/../../etc/passwd reaches a /downloads/*filepath handler with filepath = "/../../etc/passwd". Validate before touching the file system, for example with fs.ValidPath, which rejects any path containing .. elements, empty elements or a leading slash.21 Exercise 5 builds a safe download handler.

7. Route groups

A RouterGroup holds a path prefix and a list of middleware. r.Group(prefix, middleware...) returns a new group; every route registered on it gets the prefix prepended and the middleware prepended to its handler chain.7,8 The engine itself is the root group, which is why r.GET and group.GET have the same signature.

package main

import (
	"net/http"

	"github.com/gin-gonic/gin"
)

func main() {
	r := gin.Default()

	v1 := r.Group("/v1")
	{
		v1.POST("/login", login)  // POST /v1/login
		v1.POST("/submit", login) // POST /v1/submit
	}

	// Middleware passed to Group runs for every route in the group.
	authorized := r.Group("/admin", gin.BasicAuth(gin.Accounts{"admin": "secret"}))
	authorized.GET("/dashboard", func(c *gin.Context) { // GET /admin/dashboard
		c.String(http.StatusOK, "hello, %s", c.MustGet(gin.AuthUserKey))
	})

	r.Run(":8080")
}

func login(c *gin.Context) { c.Status(http.StatusOK) }

Listing 5. Groups add a prefix and shared middleware. The braces are a visual convention from Gin's documentation; Go treats them as a plain block, and they have no effect on routing.8

group.BasePath() returns the group's absolute prefix, and group.Use(mw) adds middleware later. As with the engine, Use on a group affects only routes registered on it afterwards.7

8. Nested route groups

Groups can be created from groups. A child group's prefix is the parent's prefix joined with its own, and its middleware chain is the parent's chain followed by its own.7 Middleware therefore runs from the outermost group inwards.

func authRequired(c *gin.Context) {
	if c.GetHeader("Authorization") != "Bearer admin-token" {
		c.AbortWithStatusJSON(http.StatusUnauthorized, gin.H{"error": "unauthorized"})
		return
	}
	c.Next()
}

func adminRouter() *gin.Engine {
	r := gin.New()
	api := r.Group("/api")
	v1 := api.Group("/v1")
	v1.GET("/users", func(c *gin.Context) { c.JSON(200, []string{"ana", "bo"}) })

	admin := v1.Group("/admin", authRequired)
	admin.GET("/users", func(c *gin.Context) { c.JSON(200, gin.H{"count": 2}) })
	admin.DELETE("/users/:id", func(c *gin.Context) { c.Status(http.StatusNoContent) })
	return r
}

Listing 6. Three levels of nesting. Only routes under /api/v1/admin require the token.

r                          prefix ""            chain: (none)
└── api                    prefix /api          chain: (none)
    └── v1                 prefix /api/v1       chain: (none)
        ├── GET /users                          → handler
        └── admin          prefix /api/v1/admin chain: authRequired
            ├── GET    /users                   → authRequired, handler

How prefixes are joined

Gin joins prefixes with path.Join and then restores a trailing slash if the relative path ended with one.7,22 Verified results:

  • r.Group("/v1/") + GET("users") registers /v1/users.
  • The same group + GET("/items/") registers /v1/items/, with the trailing slash.
  • Group("/books") + GET("") registers /books.

Pick one style (leading slash, no trailing slash) and use it everywhere; mixing them is the most common source of accidental trailing-slash redirects.

9. Route naming and organisation

Gin has no named routes and no reverse routing: there is no API to give a route a name and later build its URL from that name. The RouteInfo type contains only the method, the path, the handler name and the handler function.4,23 What Gin offers instead is the pattern itself, available as c.FullPath() during a request and through r.Routes() at any time. In practice the following conventions keep a growing route table manageable.

One registration function per resource

Give each feature package a function that takes a *gin.RouterGroup and registers its routes relative to it (Listing 2's Register). The top-level router then reads like a table of contents, and the same module can be mounted under several prefixes, which is exactly how section 13 serves /api/v1 and /api/v2 from one handler type.

	api := r.Group("/api")
	{
		v1 := api.Group("/v1", deprecated(
			time.Date(2026, 6, 1, 0, 0, 0, 0, time.UTC),
			time.Date(2027, 6, 1, 0, 0, 0, 0, time.UTC),
			"/api/v2/books"))
		(&BookHandler{store: store}).Register(v1)

		v2 := api.Group("/v2")
		(&BookHandler{store: store, envelope: true}).Register(v2)
	}

Listing 7. The top-level router composes feature modules.

Naming conventions

  • Paths: plural nouns for collections (/books), an identifier for members (/books/:id), nesting only for real containment (/books/:id/reviews). URIs identify resources; the method says what to do with them.24,25
  • Parameter names: the same name for the same thing everywhere (always :id or always :bookID). Section 10 shows why: two names in the same position panic.
  • Handlers: methods on a handler struct named after the action (list, get, create, replace, patch, remove). Gin reports them as, for example, main.(*BookHandler).list-fm in its debug log, which is more useful than main.main.func7.
  • Shared strings: constants for values used in several places, such as the Allow lists in Listing 2.

Route tables as documentation and tests

r.Routes() lets a test assert that the route table is what you expect, or a command print it. The order follows the internal trees, not registration order, so sort the result before comparing it.4

	r := setupRouter(store)
	for _, ri := range r.Routes() {
		log.Printf("%-7s %s", ri.Method, ri.Path)
	}

10. Route conflicts and precedence

Older Gin versions inherited httprouter's strictest rule: a static segment and a parameter could not share a position, so /users/new and /users/:id could not both exist. Gin v1.8.0 removed that restriction ("Support params and exact routes without creating conflicts").26 The current rules, all verified by registering the routes against v1.12.0, are as follows.

What is allowed and what panics

/users/:id and /users/:id/booksAllowed (same parameter name).

Precedence when matching

When more than one pattern could match, Gin prefers, at each position, a static segment over a named parameter, and a named parameter over a catch-all. Precedence does not depend on registration order.3,8 Since v1.8, the tree can also backtrack: if the static branch fails further down the path, Gin returns to the parameter branch and tries again.3,26

With /user/:name, /user/:name/*action and /user/groups registered (the routes used in Gin's own documentation), v1.12.0 gives:

RequestMatched patternParameters
/user/groups/user/groupsnone
/user/john/user/:namename=john
/user/john//user/:name/*actionname=john, action=/
/user/groups/send/user/:name/*actionname=groups, action=/send
/user/groups/301 redirect to /user/groups

A documentation discrepancy. The comment in Gin's quick-start example says that "routes starting with /user/groups are never interpreted as /user/:name/... routes".8 In v1.12.0 that is not what happens: because of backtracking, /user/groups/send does match /user/:name/*action with name = "groups". Only the exact path /user/groups is reserved by the static route. If a static segment must block a whole subtree, register explicit routes for that subtree.

Trailing slashes and path correction

When no route matches, but the same path with (or without) a trailing slash would, Gin redirects instead of returning 404. This is RedirectTrailingSlash, which is on by default. The redirect is 301 Moved Permanently for GET and 307 Temporary Redirect for every other method,4 because a client may change a POST to GET when following a 301, while a 307 requires it to repeat the same method and content.10

Engine fieldDefaultEffect
RedirectTrailingSlashtrue/items/ → 301 to /items for GET; POST /items/ → 307
RedirectFixedPathfalseCleans the path (../, //) and retries case-insensitively: /USERS/new → 301 to /users/new
RemoveExtraSlashfalseCleans repeated slashes before matching, without a redirect
HandleMethodNotAllowedfalseReturn 405 with an Allow header instead of 404 (section 11)

Comparison with the standard library

Since Go 1.22, net/http.ServeMux also supports methods and wildcards (GET /items/{id}, {path...}). Its precedence rule is "most specific pattern wins", and it panics when two patterns overlap without either being more specific.14,15 The ideas are similar, but the details differ (for example, HEAD handling, and that ServeMux allows /files/{path...} alongside /files/info), so do not assume code moves between the two unchanged.

11. NoRoute and NoMethod handlers

When no route matches, Gin runs the NoRoute chain and, by default, writes 404 page not found as plain text.4 RFC 9110 distinguishes two failures that a router can detect:10

  • 404 Not Found: the server has no current representation for the target resource.
  • 405 Method Not Allowed: the resource exists but does not support the request method. The server must include an Allow header listing the supported methods.

Gin returns 405 only when you opt in with r.HandleMethodNotAllowed = true. Then, when the request path exists in another method's tree, Gin sets Allow to those methods (for example GET, POST) and runs the NoMethod chain, with 405 method not allowed as the default body. If the path exists in no tree, the request falls through to NoRoute.4

NoMethod does nothing on its own. Registering r.NoMethod(h) without setting HandleMethodNotAllowed = true leaves the handler unused: in a v1.12.0 test, POST to a GET-only route still returned the default 404. The source comment says so directly: "NoMethod sets the handlers called when Engine.HandleMethodNotAllowed = true."4

Custom handlers should keep the status code and, for APIs, return a machine-readable error. RFC 9457 defines the application/problem+json format, with members such as type, title, status, detail and instance.27

func problem(c *gin.Context, status int, title, detail string) {
	c.Header("Content-Type", "application/problem+json")
	c.AbortWithStatusJSON(status, gin.H{
		"type":     "about:blank",
		"title":    title,
		"status":   status,
		"detail":   detail,
		"instance": c.Request.URL.Path,
	})
}
	r.HandleMethodNotAllowed = true // required for NoMethod to ever run
	r.NoRoute(func(c *gin.Context) {
		problem(c, http.StatusNotFound, "not found", "no route for "+c.Request.URL.Path)
	})
	r.NoMethod(func(c *gin.Context) {
		// Gin has already set the Allow header at this point.
		problem(c, http.StatusMethodNotAllowed, "method not allowed",
			c.Request.Method+" is not supported; allowed: "+c.Writer.Header().Get("Allow"))
	})

Listing 8. Problem-details 404 and 405 responses. A TRACE /api/v2/books request to the complete example returns 405 with Allow: GET, HEAD, POST, OPTIONS.

Three further details, all from gin.go:4

  • Global middleware from r.Use runs before the NoRoute and NoMethod handlers, so logging and recovery cover unmatched requests too.
  • If your handler writes no body and leaves the status unchanged, Gin still writes its default plain-text body; if the handler writes a response, Gin adds nothing.
  • The trailing-slash and fixed-path redirects are tried before NoMethod and NoRoute.

A common use of NoRoute in single-page applications is to serve index.html for unknown paths so that client-side routing can handle them. Restrict this to GET requests that accept HTML, so that mistyped API calls still receive a 404.

12. RESTful API design

REST (Representational State Transfer) is the architectural style Roy Fielding described in his 2000 dissertation. Its central constraint is a uniform interface: resources are identified by URIs, manipulated through representations, and acted on by a small set of standard methods whose meaning is the same for every resource.24 For HTTP APIs, RFC 9205 (BCP 56) gives the IETF's best-current-practice advice on building protocols on top of HTTP, including using methods and status codes with their defined semantics.25

Table 5. The route design implemented below. Status code meanings: RFC 9110 §15; 422 Unprocessable Content is defined in §15.5.21 for syntactically correct content that cannot be processed.10

Design guidelines applied in the example

  • Nouns in paths, verbs in methods. POST /books, not POST /createBook.24
  • Return the right status, not 200 for everything. Clients, proxies and monitoring tools rely on status classes.10,25
  • Tell clients where new resources live with Location on 201.10
  • Keep reads safe and PUT/DELETE idempotent, so clients can retry them.10
  • Use one error format everywhere, such as RFC 9457 problem details.27
  • Put optional inputs in the query string, cap page sizes, and report the total (here in an X-Total-Count header).

// Command bookstore is a small, complete Gin API that demonstrates
// route registration, every common HTTP method, path and query
// parameters, nested groups, custom 404/405 handlers and URI versioning.
package main

import (
	"errors"
	"log"
	"net/http"
	"path"
	"sort"
	"strconv"
	"strings"
	"sync"
	"time"

	"github.com/gin-gonic/gin"
	"github.com/go-playground/validator/v10"
)

// ---------- Domain and storage ----------

type Book struct {
	ID     int    `json:"id"`
	Title  string `json:"title"`
	Author string `json:"author"`
	Year   int    `json:"year"`
}

// BookInput is the full representation used by POST and PUT.
type BookInput struct {
	Title  string `json:"title"  binding:"required"`
	Author string `json:"author" binding:"required"`
	Year   int    `json:"year"   binding:"gte=0"`
}

// BookPatch uses pointers so "absent" can be told apart from "zero".
type BookPatch struct {
	Title  *string `json:"title"`
	Author *string `json:"author"`
	Year   *int    `json:"year" binding:"omitempty,gte=0"`
}

type Store struct {
	mu     sync.RWMutex
	nextID int
	books  map[int]Book
}

func NewStore() *Store {
	return &Store{nextID: 1, books: map[int]Book{}}
}

func (s *Store) List() []Book {
	s.mu.RLock()
	defer s.mu.RUnlock()
	out := make([]Book, 0, len(s.books))
	for _, b := range s.books {
		out = append(out, b)
	}
	sort.Slice(out, func(i, j int) bool { return out[i].ID < out[j].ID })
	return out
}

func (s *Store) Get(id int) (Book, bool) {
	s.mu.RLock()
	defer s.mu.RUnlock()
	b, ok := s.books[id]
	return b, ok
}

func (s *Store) Create(in BookInput) Book {
	s.mu.Lock()
	defer s.mu.Unlock()
	b := Book{ID: s.nextID, Title: in.Title, Author: in.Author, Year: in.Year}
	s.books[b.ID] = b
	s.nextID++
	return b
}

// Update applies fn to the stored book, if it exists.
func (s *Store) Update(id int, fn func(*Book)) (Book, bool) {
	s.mu.Lock()
	defer s.mu.Unlock()
	b, ok := s.books[id]
	if !ok {
		return Book{}, false
	}
	fn(&b)
	s.books[id] = b
	return b, true
}

func (s *Store) Delete(id int) bool {
	s.mu.Lock()
	defer s.mu.Unlock()
	if _, ok := s.books[id]; !ok {
		return false
	}
	delete(s.books, id)
	return true
}

// ---------- Error responses (RFC 9457 problem details) ----------

func problem(c *gin.Context, status int, title, detail string) {
	c.Header("Content-Type", "application/problem+json")
	c.AbortWithStatusJSON(status, gin.H{
		"type":     "about:blank",
		"title":    title,
		"status":   status,
		"detail":   detail,
		"instance": c.Request.URL.Path,
	})
}

// bindError maps malformed JSON to 400 and failed validation to 422.
func bindError(c *gin.Context, err error) {
	var ve validator.ValidationErrors
	if errors.As(err, &ve) {
		problem(c, http.StatusUnprocessableEntity, "validation failed", err.Error())
		return
	}
	problem(c, http.StatusBadRequest, "malformed request", err.Error())
}

// ---------- Handlers ----------

type BookHandler struct {
	store    *Store
	envelope bool // v2 wraps collections in {"data": ..., "page": ...}
}

const (
	allowCollection = "GET, HEAD, POST, OPTIONS"
	allowItem       = "GET, HEAD, PUT, PATCH, DELETE, OPTIONS"
)

// Register attaches every /books route to the given group.
func (h *BookHandler) Register(rg *gin.RouterGroup) {
	books := rg.Group("/books")
	books.GET("", h.list)
	books.HEAD("", h.list)
	books.POST("", h.create)
	books.OPTIONS("", allow(allowCollection))

	book := books.Group("/:id", h.bookID) // nested group with middleware
	book.GET("", h.get)
	book.HEAD("", h.get)
	book.PUT("", h.replace)
	book.PATCH("", h.patch)
	book.DELETE("", h.remove)
	book.OPTIONS("", allow(allowItem))
}

func allow(methods string) gin.HandlerFunc {
	return func(c *gin.Context) {
		c.Header("Allow", methods)
		c.Status(http.StatusNoContent)
	}
}

type bookURI struct {
	ID int `uri:"id" binding:"required,min=1"`
}

// bookID validates the :id path parameter once for every item route.
func (h *BookHandler) bookID(c *gin.Context) {
	var u bookURI
	if err := c.ShouldBindUri(&u); err != nil {
		problem(c, http.StatusBadRequest, "invalid book id", err.Error())
		return
	}
	c.Set("bookID", u.ID)
	c.Next()
}

type listQuery struct {
	Author string `form:"author"`
	Sort   string `form:"sort,default=id" binding:"oneof=id title year"`
	Page   int    `form:"page,default=1" binding:"min=1"`
	Limit  int    `form:"limit,default=20" binding:"min=1,max=100"`
}

func (h *BookHandler) list(c *gin.Context) {
	var q listQuery
	if err := c.ShouldBindQuery(&q); err != nil {
		problem(c, http.StatusBadRequest, "invalid query", err.Error())
		return
	}
	all := h.store.List()
	filtered := all[:0]
	for _, b := range all {
		if q.Author == "" || strings.EqualFold(b.Author, q.Author) {
			filtered = append(filtered, b)
		}
	}
	sort.SliceStable(filtered, func(i, j int) bool {
		switch q.Sort {
		case "title":
			return filtered[i].Title < filtered[j].Title
		case "year":
			return filtered[i].Year < filtered[j].Year
		}
		return filtered[i].ID < filtered[j].ID
	})
	total := len(filtered)
	start := min((q.Page-1)*q.Limit, total)
	end := min(start+q.Limit, total)
	page := filtered[start:end]

	c.Header("X-Total-Count", strconv.Itoa(total))
	if h.envelope {
		c.JSON(http.StatusOK, gin.H{
			"data": page,
			"page": gin.H{"number": q.Page, "limit": q.Limit, "total": total},
		})
		return
	}
	c.JSON(http.StatusOK, page)
}

func (h *BookHandler) create(c *gin.Context) {
	var in BookInput
	if err := c.ShouldBindJSON(&in); err != nil {
		bindError(c, err)
		return
	}
	b := h.store.Create(in)
	c.Header("Location", path.Join(c.Request.URL.Path, strconv.Itoa(b.ID)))
	c.JSON(http.StatusCreated, b)
}

func (h *BookHandler) get(c *gin.Context) {
	b, ok := h.store.Get(c.GetInt("bookID"))
	if !ok {
		problem(c, http.StatusNotFound, "book not found", "no book with id "+c.Param("id"))
		return
	}
	c.JSON(http.StatusOK, b)
}

func (h *BookHandler) replace(c *gin.Context) {
	var in BookInput
	if err := c.ShouldBindJSON(&in); err != nil {
		bindError(c, err)
		return
	}
	b, ok := h.store.Update(c.GetInt("bookID"), func(b *Book) {
		b.Title, b.Author, b.Year = in.Title, in.Author, in.Year
	})
	if !ok {
		problem(c, http.StatusNotFound, "book not found", "no book with id "+c.Param("id"))
		return
	}
	c.JSON(http.StatusOK, b)
}

func (h *BookHandler) patch(c *gin.Context) {
	switch c.ContentType() {
	case "application/merge-patch+json", "application/json":
	default:
		c.Header("Accept-Patch", "application/merge-patch+json")
		problem(c, http.StatusUnsupportedMediaType, "unsupported patch format",
			"send application/merge-patch+json")
		return
	}
	var p BookPatch
	if err := c.ShouldBindJSON(&p); err != nil {
		bindError(c, err)
		return
	}
	b, ok := h.store.Update(c.GetInt("bookID"), func(b *Book) {
		if p.Title != nil {
			b.Title = *p.Title
		}
		if p.Author != nil {
			b.Author = *p.Author
		}
		if p.Year != nil {
			b.Year = *p.Year
		}
	})
	if !ok {
		problem(c, http.StatusNotFound, "book not found", "no book with id "+c.Param("id"))
		return
	}
	c.JSON(http.StatusOK, b)
}

func (h *BookHandler) remove(c *gin.Context) {
	if !h.store.Delete(c.GetInt("bookID")) {
		problem(c, http.StatusNotFound, "book not found", "no book with id "+c.Param("id"))
		return
	}
	c.Status(http.StatusNoContent)
}

// ---------- Versioning helpers ----------

// deprecated marks every response of a group as deprecated (RFC 9745)
// and announces when it will stop working (RFC 8594).
func deprecated(since, sunset time.Time, successor string) gin.HandlerFunc {
	return func(c *gin.Context) {
		c.Header("Deprecation", "@"+strconv.FormatInt(since.Unix(), 10))
		c.Header("Sunset", sunset.UTC().Format(http.TimeFormat))
		c.Header("Link", "<"+successor+">; rel=\"successor-version\"")
		c.Next()
	}
}

// ---------- Router ----------

func setupRouter(store *Store) *gin.Engine {
	r := gin.New()
	r.Use(gin.Logger(), gin.Recovery()) // global middleware first, routes after

	r.HandleMethodNotAllowed = true // required for NoMethod to ever run
	r.NoRoute(func(c *gin.Context) {
		problem(c, http.StatusNotFound, "not found", "no route for "+c.Request.URL.Path)
	})
	r.NoMethod(func(c *gin.Context) {
		// Gin has already set the Allow header at this point.
		problem(c, http.StatusMethodNotAllowed, "method not allowed",
			c.Request.Method+" is not supported; allowed: "+c.Writer.Header().Get("Allow"))
	})

	r.GET("/healthz", func(c *gin.Context) { c.Status(http.StatusOK) })

	api := r.Group("/api")
	{
		v1 := api.Group("/v1", deprecated(
			time.Date(2026, 6, 1, 0, 0, 0, 0, time.UTC),
			time.Date(2027, 6, 1, 0, 0, 0, 0, time.UTC),
			"/api/v2/books"))
		(&BookHandler{store: store}).Register(v1)

		v2 := api.Group("/v2")
		(&BookHandler{store: store, envelope: true}).Register(v2)
	}
	return r
}

func main() {
	store := NewStore()
	store.Create(BookInput{Title: "The Go Programming Language", Author: "Donovan", Year: 2015})
	store.Create(BookInput{Title: "Concurrency in Go", Author: "Cox-Buday", Year: 2017})

	r := setupRouter(store)
	for _, ri := range r.Routes() {
		log.Printf("%-7s %s", ri.Method, ri.Path)
	}
	log.Fatal(r.Run(":8080"))
}

13. API versioning

Clients depend on the shape of your responses, so breaking changes (removing a field, changing a type, changing what a status code means) need a new version that runs alongside the old one until clients have moved. Additive changes, such as a new optional field or a new endpoint, generally do not.

StrategyExampleStrengthsWeaknesses
URI path/api/v2/booksVisible, easy to route, cache and test in a browser; maps directly onto Gin groupsThe same resource has several URIs
Media type (content negotiation)Accept: application/vnd.bookstore.v2+jsonOne URI per resource; uses HTTP's negotiation mechanismHarder to test by hand; caches need Vary: Accept
Custom header or queryX-API-Version: 2, ?version=2Simple to implementNot standardised; the query form mixes versioning with resource identity

Table 6. Common versioning strategies. Vendor media types (vnd.) are registered under the vendor tree defined in RFC 6838; content negotiation and Vary are defined in RFC 9110 §12.10,28

URI versioning with groups

Listing 7 shows the URI strategy: one group per version, both mounting the same BookHandler type with a flag that changes the collection format (v1 returns a bare array; v2 returns {"data": [...], "page": {...}}). Shared code stays shared, and each version can still get its own handlers where they really differ.

Announcing deprecation

Two standard response headers tell clients that a version is going away. Deprecation (RFC 9745) says the resource is or will be deprecated; its value is a structured-field date such as @1780272000 (Unix seconds).29 Sunset (RFC 8594) gives the HTTP date after which the resource is expected to stop responding.30 A Link header with the successor-version relation (RFC 5829, using the Web Linking syntax of RFC 8288) points to the replacement.31,32 Attach them to the whole v1 group with one middleware:

// deprecated marks every response of a group as deprecated (RFC 9745)
// and announces when it will stop working (RFC 8594).
func deprecated(since, sunset time.Time, successor string) gin.HandlerFunc {
	return func(c *gin.Context) {
		c.Header("Deprecation", "@"+strconv.FormatInt(since.Unix(), 10))
		c.Header("Sunset", sunset.UTC().Format(http.TimeFormat))
		c.Header("Link", "<"+successor+">; rel=\"successor-version\"")
		c.Next()
	}
}

Listing 9. A v1 response then carries Deprecation: @1780272000, Sunset: Tue, 01 Jun 2027 00:00:00 GMT and Link: </api/v2/books>; rel="successor-version" (recorded from the test run).

Media-type versioning, where one Gin route dispatches on the Accept header, is the subject of exercise 8.

A *gin.Engine is an http.Handler, so routes can be tested without opening a port: build a request with httptest.NewRequest, record the response with httptest.NewRecorder, and call r.ServeHTTP.8,33 Keep router construction in a function (setupRouter) so tests and main share it.

package main

import (
	"net/http"
	"net/http/httptest"
	"strings"
	"testing"

	"github.com/gin-gonic/gin"
)

func do(t *testing.T, r http.Handler, method, target, body, ctype string) *httptest.ResponseRecorder {
	t.Helper()
	var req *http.Request
	if body != "" {
		req = httptest.NewRequest(method, target, strings.NewReader(body))
		req.Header.Set("Content-Type", ctype)
	} else {
		req = httptest.NewRequest(method, target, nil)
	}
	w := httptest.NewRecorder()
	r.ServeHTTP(w, req)
	return w
}

	}

}

Exercise 1: A health endpoint (registration, HEAD, OPTIONS, 405)

Create /health that returns {"status":"ok"} for GET and HEAD, answers OPTIONS with 204 and Allow: GET, HEAD, OPTIONS, and returns a JSON 405 for any other method.

Solution 
func healthRouter() *gin.Engine {
	r := gin.New()
	r.HandleMethodNotAllowed = true
	r.NoMethod(func(c *gin.Context) {
		c.JSON(http.StatusMethodNotAllowed, gin.H{"error": "method not allowed"})
	})
	r.Match([]string{http.MethodGet, http.MethodHead}, "/health", func(c *gin.Context) {
		c.JSON(http.StatusOK, gin.H{"status": "ok"})
	})
	r.OPTIONS("/health", func(c *gin.Context) {
		c.Header("Allow", "GET, HEAD, OPTIONS")
		c.Status(http.StatusNoContent)
	})
	return r
}

Match registers HEAD alongside GET, because Gin will not do it for you. HandleMethodNotAllowed must be true for NoMethod to run. For POST /health, Gin sets Allow: GET, HEAD, OPTIONS automatically, built from the methods registered for that path.

Exercise 2: Predict the router (conflicts and precedence)

For each set of GET routes, say whether registration succeeds. If it does, say which pattern handles each request.

  1. /posts/:id, /posts/latest; requests /posts/latest, /posts/7
  2. /posts/:id, /posts/:slug/comments
  3. /static/*file, /static/robots.txt
  4. /posts/:id, /posts/latest, /posts/:id/edit; request /posts/latest/edit
  5. /posts; requests GET /posts/ and POST /posts/ (with a POST /posts route too)
Solution
  1. Succeeds. /posts/latest → /posts/latest (static beats parameter, regardless of order); /posts/7 → /posts/:id.
  2. Panics: ':slug' ... conflicts with existing wildcard ':id'. Use one name for the position.
  3. Panics: a catch-all cannot share its position with a static segment, in either order. Serve robots.txt from the static directory, or move the catch-all to its own prefix.
  4. Succeeds, and /posts/latest/edit → /posts/:id/edit with id = "latest", because the router backtracks from the static branch.
  5. GET /posts/ → 301 to /posts; POST /posts/ → 307 to /posts, which preserves the method and body.

Exercise 3: A validated search query (query parameters)

Implement GET /search with a required q, page (default 1, minimum 1), size (default 10, from 1 to 50) and repeatable tag. Invalid input returns 400.

Solution 
type SearchQuery struct {

Exercise 4: Nested groups with scoped middleware

Build /api/v1/users (public) and /api/v1/admin/users (GET) plus /api/v1/admin/users/:id (DELETE), where only the admin routes require Authorization: Bearer admin-token. Print the route table.

Solution

Exercise 5: A safe download route (wildcards)

Serve files from a directory under /downloads/*filepath. Requests such as /downloads/../../etc/passwd and /downloads/ must return 400.

Solution 
func downloadsRouter(root string) *gin.Engine {
	r := gin.New()
	r.GET("/downloads/*filepath", func(c *gin.Context) {
		rel := strings.TrimPrefix(c.Param("filepath"), "/")
		if rel == "" || !fs.ValidPath(rel) {
			c.JSON(http.StatusBadRequest, gin.H{"error": "invalid file path"})
			return
		}
		c.FileFromFS(rel, http.Dir(root))
	})
	return r
}

The catch-all value starts with /, so trim it first. fs.ValidPath rejects .. and empty elements.21 http.Dir also opens files rooted at its directory, which gives a second layer of defence (symbolic links inside the directory can still point elsewhere).14

Exercise 8: Media-type versioning

Serve GET /books in two formats from one URI: v1 (a bare array) by default or for Accept: application/vnd.bookstore.v1+json, and v2 ({"data": [...]}) for application/vnd.bookstore.v2+json. Unknown versions return 406. Make the response safe to cache.

Solution 
var vendorRe = regexp.MustCompile(`application/vnd\.bookstore\.v(\d+)\+json`)

func byVersion(handlers map[string]gin.HandlerFunc, fallback string) gin.HandlerFunc {
	return func(c *gin.Context) {
		c.Header("Vary", "Accept")
		v := fallback
		if m := vendorRe.FindStringSubmatch(c.GetHeader("Accept")); m != nil {
			v = m[1]
		}
		h, ok := handlers[v]
		if !ok {
			c.AbortWithStatusJSON(http.StatusNotAcceptable, gin.H{"error": "unsupported API version " + v})
			return
		}
		h(c)
	}
}

func versionRouter() *gin.Engine {
	r := gin.New()
	r.GET("/books", byVersion(map[string]gin.HandlerFunc{
		"1": func(c *gin.Context) { c.JSON(200, []string{"Go"}) },
		"2": func(c *gin.Context) { c.JSON(200, gin.H{"data": []string{"Go"}}) },
	}, "1"))
	return r
}

Vary: Accept tells caches that the response depends on the Accept header, so a cached v1 response is never served to a v2 client.10 406 Not Acceptable is the status for a request whose acceptable representations the server cannot produce.10 A production version would also send a matching Content-Type such as application/vnd.bookstore.v2+json.
