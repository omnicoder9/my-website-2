1. Java source is translated into typed executable structure

A Java program begins as Unicode source text. Lexical translation recognizes tokens; grammar organizes tokens into declarations, expressions, and statements; static analysis checks types, scope, reachability, and definite assignment; compilation emits class files for execution by the Java Virtual Machine.

Unicode source text ↓ lexical translation tokens: identifiers, keywords, literals, separators, operators ↓ parsing and static checks compilation units, declarations, expressions, statements ↓ javac .class files ↓ JVM loading, linking, initialization execution

Java is a statically and strongly typed language: types constrain values, supported operations, conversions, and the meaning of expressions. The Java Language Specification defines source-level syntax and semantics independently of one compiler implementation.[1]

Read code at four levels. Ask which tokens are present, how they parse, what static types they have, and in what order they execute.

2. Syntax, lexical grammar, and syntactic grammar

Grammar Java uses a lexical grammar to turn input characters into tokens and a syntactic grammar to form programs from those tokens. The specification uses grammar productions to define valid source constructs.[2]

public final class Greeting {
    public static void main(
            String[] arguments) {

        System.out.println(
            "Hello, Java");
    }
}

Case sensitivity

int count = 1;
int Count = 2;
// Distinct identifiers.

Semicolons and braces

Many statements and declarations terminate with semicolons. Braces delimit class bodies, method bodies, blocks, array initializers, and other constructs. Whitespace usually separates tokens but is otherwise not syntactically significant.

3. Tokens, input elements, and whitespace

The lexical grammar recognizes identifiers, keywords, literals, separators, and operators. Whitespace and comments generally separate tokens and are otherwise discarded, except that documentation comments are available to tooling.[2]

int total = price * quantity;
// tokens include:
// int, total, =, price, *, quantity, ;

Separators

( ) { } [ ] ; , . ... @ ::

Operators

= > < ! ~ ? : ->
== >= <= != && || ++ --
+ - * / & | ^ % << >> >>>
+= -= *= /= &= |= ^= %= <<= >>= >>>=

4. Identifiers, keywords, and naming

An identifier names a declared entity such as a class, method, variable, label, or package. Java identifiers are based on Unicode identifier rules and are case-sensitive. Keywords and restricted identifiers cannot be used in contexts where the grammar reserves them.[2]

int customerCount;
String customerName;
boolean isAvailable;

Conventional names

  • Classes and interfaces: CustomerService.
  • Methods and variables: calculateTotal, orderCount.
  • Constants: MAX_RETRIES.
  • Packages: com.example.orders.

Do not rely on visually confusable names

Unicode permits many letters, but identifiers that look nearly identical across scripts are difficult to review and can create security risk.

5. Literal values

int decimal = 1_000_000;
int hexadecimal = 0xFF;
int binary = 0b1010_0110;
long population = 8_000_000_000L;

double ratio = 0.125;
float probability = 0.75F;

char newline = '\n';
char lambda = '\u03BB';

String message = "Java";
boolean active = true;
Object absent = null;

Java defines integer, floating-point, boolean, character, string, text-block, and null literals. Underscores may improve readability in numeric literals but cannot appear arbitrarily, such as at the beginning or end.[2]

Integer literal type

An integer literal is normally int; the L suffix denotes long. Use uppercase L because lowercase l resembles the digit one.

6. Source files and compilation units

Compilation unit Java source files conventionally use the .java extension and contain package, import, and top-level type declarations. A public top-level type is normally stored in a file of the same name.[3]

src/ └── com/example/app/ ├── Main.java ├── Calculator.java └── package-info.java
package com.example.app;

import java.math.BigDecimal;

public final class Calculator {
    // ...
}

One source file can declare several types

public class Main {
}

final class Helper {
}

Only one public top-level class or interface can correspond naturally to the source file name; keeping one primary top-level type per file is the clearest convention.

7. Compiling and running a basic program

The javac command reads Java source declarations and compiles them into JVM class files. The -d option places output into a separate directory and preserves package structure.[4]

javac \
  --release 25 \
  -d build/classes \
  src/com/example/app/Main.java
java \
  -cp build/classes \
  com.example.app.Main

Entry point

public static void main(
        String[] arguments) {

    System.out.println(
        "Arguments: "
            + arguments.length);
}

The traditional launcher entry point is a public static void main(String[]) method in the selected class.

8. Classes

Type declaration A class declares fields, methods, constructors, nested types, and initialization code. Class instances are objects created at runtime.[5]

public final class Counter {
    private int value;

    public Counter(
            int initialValue) {

        value = initialValue;
    }

    public void increment() {
        value++;
    }

    public int value() {
        return value;
    }
}
Counter counter =
    new Counter(10);

counter.increment();

System.out.println(
    counter.value());

9. Methods

A method declaration has modifiers, optional type parameters, a return type or void, a name, formal parameters, optional checked exceptions, and a body or semicolon where permitted.[5]

static int add(
        int left,
        int right) {

    return left + right;
}

Void method

static void printLine(
        String value) {

    System.out.println(value);
}

Invocation

int sum =
    add(2, 3);

printLine(
    "sum = " + sum);

Arguments are evaluated left to right, and parameter variables receive copies of the resulting values.

10. Statements

Execution unit Statements perform actions and control execution. Java statement forms include blocks, local declarations, expression statements, conditionals, loops, switch, transfer statements, synchronization, try, throw, assertions, and empty statements.[6]

int count = 0;          // declaration statement
count++;                // expression statement

if (count > 0) {        // if statement
    System.out.println(count);
}

return;                 // return statement

Expression statements are restricted

Not every expression can stand alone as a statement. Assignments, increments/decrements, method invocations, and object creation expressions are among the allowed expression-statement forms.

11. Expressions

Value computation An expression denotes a computation that can produce a value, a variable, or no value, and may have side effects. Examples include literals, names, field access, array access, method invocation, object creation, casts, operators, lambdas, and switch expressions.[7]

int result =
    base
        + multiplier * quantity;

boolean accepted =
    active
        && score >= threshold;

String label =
    switch (status) {
        case READY -> "Ready";
        case FAILED -> "Failed";
    };

Evaluation order

Java evaluates operands and arguments left to right, while operator precedence determines grouping rather than evaluation order.

12. Blocks

A block is a sequence of statements and local declarations enclosed in braces. It introduces a scope for local variables declared within it.[6]

{
    int temporary = 10;

    System.out.println(
        temporary);
}
// temporary is out of scope here.

Nested blocks

int value = 1;

{
    int other = 2;

    // Illegal:
    // int value = 3;
    // A local variable cannot be redeclared
    // in an overlapping scope.
}

13. Comments and documentation comments

// End-of-line comment

/*
 * Traditional block comment.
 */

/**
 * Returns the larger argument.
 *
 * @param left first value
 * @param right second value
 * @return the larger value
 */
static int maximum(
        int left,
        int right) {

    return Math.max(
        left,
        right);
}

Traditional and end-of-line comments are discarded during lexical processing. Documentation comments are recognized by documentation tooling when placed before supported declarations.[2]

Comments do not nest

/*
  outer
  /* inner */
  // The first */ ends the comment.
*/

Prefer comments that explain intent, constraints, or non-obvious decisions rather than narrating obvious syntax.

14. Variables

Named storage A variable is a storage location with a type. Java variables include class variables, instance variables, array components, method parameters, constructor parameters, lambda parameters, exception parameters, pattern variables, and local variables.[8]

static int classCount;
int instanceCount;

static void process(
        int parameter) {

    int local = parameter + 1;
}

Type determines permitted values and operations

int count = 10;
// count = "ten"; // Compile-time error.

Variables versus values

A variable has a declared type and mutable storage unless final. An expression can produce a value without introducing a variable.

15. Variable declarations

int count;
String name;
boolean complete;

int width, height;
// Legal, but separate declarations
// are usually clearer.

Declaration with inference

var total =
    new BigDecimal("19.99");

var can be used for local variable type inference when an initializer is present. It is a reserved type name in this context, not dynamic typing, and the variable still has one fixed static type.

Descriptive names

int elapsedMilliseconds;
boolean connectionAvailable;

Names should communicate unit, role, and meaning rather than merely repeat the type.

16. Initialization

int count =
    0;

String greeting =
    "Hello";

List<String> names =
    new ArrayList<>();

Fields receive defaults

class Defaults {
    int number;       // 0
    boolean flag;     // false
    Object reference;// null
}

Local variables do not

int value;

// Compile-time error:
// System.out.println(value);

Fields and array elements receive default values, while local variables require definite assignment before use.[8]

17. Definite assignment

The compiler performs flow analysis to ensure that every local variable and blank final variable is definitely assigned before it is read. The analysis is conservative and based on language rules rather than runtime guesses.[9]

int result;

if (condition) {
    result = 1;
} else {
    result = 2;
}

System.out.println(result);
// Assigned on every path.

Incomplete assignment

int result;

if (condition) {
    result = 1;
}

// Compile-time error:
// System.out.println(result);

18. Scope

Name visibility Scope is the region of source code where a declared name can be used. Scope rules differ for fields, parameters, local variables, labels, type parameters, and pattern variables.[10]

static void example(
        int parameter) {

    int methodLocal = 1;

    if (parameter > 0) {
        int blockLocal = 2;

        System.out.println(
            methodLocal
                + blockLocal);
    }

    // blockLocal is unavailable here.
}

Shadowing fields

class Point {
    private int x;

    Point(int x) {
        this.x = x;
    }
}

The parameter shadows the field; this.x explicitly selects the instance field.

19. Lifetime and reachability

Scope is a source-level name rule; lifetime is a runtime storage concern. A local variable's name can leave scope while an object formerly referenced by it remains reachable through another reference.

List<String> create() {
    List<String> values =
        new ArrayList<>();

    values.add("retained");

    return values;
}
// The local variable ends,
// but the returned list remains reachable.

Primitive local lifetime

Primitive local storage is associated with method execution. Object lifetime is managed by reachability and garbage collection, not lexical scope alone.

Captured variables

Supplier<String> supplier() {
    String value = "captured";
    return () -> value;
}

The lambda can retain the captured value after the method returns.

20. final variables and constants

A final variable can be assigned only once. A final reference cannot be reassigned, but the referenced object can still be mutable.[8]

final int maximumRetries =
    3;

final List<String> values =
    new ArrayList<>();

values.add("allowed");

// Illegal:
// values = new ArrayList<>();

Compile-time constants

static final int
    DEFAULT_PORT =
        8080;

static final String
    SERVICE_NAME =
        "catalog";

A constant variable is a final variable of primitive or String type initialized with a constant expression. Such values can be inlined into client class files, which matters when public constants evolve.

22. byte

byte minimum =
    Byte.MIN_VALUE; // -128

byte maximum =
    Byte.MAX_VALUE; // 127

byte header =
    (byte) 0xFF;

byte is an 8-bit signed two's-complement integer. Arithmetic generally promotes byte operands to int, so a cast can be required to store a computed result back into a byte.[8]

byte left = 10;
byte right = 20;

// Illegal:
// byte sum = left + right;

int sum =
    left + right;

Unsigned interpretation

int unsigned =
    Byte.toUnsignedInt(
        header); // 255

23. short

short minimum =
    Short.MIN_VALUE; // -32768

short maximum =
    Short.MAX_VALUE; // 32767

short is a 16-bit signed integer. Like byte and char, it is promoted to int for most arithmetic expressions.

short first = 1_000;
short second = 2_000;

int total =
    first + second;

Use deliberately

Method-local use rarely saves memory because arithmetic and JVM execution commonly use int-width values. Short is most useful in arrays, binary formats, and APIs whose representation explicitly requires 16 bits.

24. int

int minimum =
    Integer.MIN_VALUE;

int maximum =
    Integer.MAX_VALUE;

int hexadecimal =
    0x7FFF_FFFF;

int is the default type for most integer literals and integral arithmetic. Overflow wraps according to fixed-width two's-complement arithmetic; Java does not automatically throw on ordinary integer overflow.[8]

int overflow =
    Integer.MAX_VALUE + 1;

assert overflow
    == Integer.MIN_VALUE;

Checked arithmetic

int exact =
    Math.addExact(
        left,
        right);

25. long

long large =
    8_000_000_000L;

long nanos =
    System.nanoTime();

long is a 64-bit signed integer. A literal outside int range requires the L suffix.

Promotion

int count = 10;
long multiplier = 1_000L;

long result =
    count * multiplier;

Unsigned utilities

String unsignedText =
    Long.toUnsignedString(
        value);

int comparison =
    Long.compareUnsigned(
        left,
        right);

The underlying primitive remains signed; library operations provide unsigned interpretation where required.

26. float

float ratio =
    0.75F;

float positiveInfinity =
    Float.POSITIVE_INFINITY;

float notANumber =
    Float.NaN;

float implements the 32-bit IEEE 754 binary32 format. Most decimal fractions are approximations in binary floating point.

float value =
    0.1F + 0.2F;

System.out.println(value);

Use cases

Float is useful when storage or bandwidth matters and binary32 precision is sufficient, such as large graphics or scientific arrays. It is not suitable for exact decimal money.

27. double

double pi =
    Math.PI;

double result =
    1.0 / 0.0;
// Positive infinity.

double undefined =
    0.0 / 0.0;
// NaN.

double implements IEEE 754 binary64 and is the default type of floating-point literals. Floating-point division by zero produces infinity or NaN rather than ArithmeticException.[8]

NaN comparison

double value =
    Double.NaN;

assert value != value;

assert Double.isNaN(value);

Exact decimal arithmetic

BigDecimal money =
    new BigDecimal(
        "19.99");

28. char

char is an unsigned 16-bit UTF-16 code unit. It does not necessarily represent a complete Unicode character because supplementary code points use surrogate pairs.[11]

char letter =
    'A';

char lambda =
    '\u03BB';

String rocket =
    "🚀";

assert rocket.length() == 2;

Numeric nature

char digit = '7';

int numericValue =
    digit - '0';

Code-point processing

rocket.codePoints()
    .forEach(
        System.out::println);

29. boolean

boolean enabled =
    true;

boolean accepted =
    score >= minimum
        && accountActive;

boolean has exactly two values, true and false. Java does not convert integers or references to booleans for conditions.[8]

int count = 1;

// Illegal:
// if (count) { }

Prefer positive names

boolean connectionAvailable;
boolean requestValid;

Double negatives such as !isNotReady make control flow harder to read.

30. Primitive conversions and numeric promotion

Java defines widening and narrowing primitive conversions, boxing/unboxing, casting contexts, assignment contexts, invocation contexts, and numeric promotion rules.[12]

Widening conversion

int count = 100;

long largeCount =
    count;

double approximate =
    largeCount;

Narrowing conversion

int value = 300;

byte narrowed =
    (byte) value;
// 44 after low-bit truncation.

Binary numeric promotion

short left = 10;
short right = 20;

int result =
    left + right;
Widening is not always exact. Converting a large integer to float or double can lose precision even though no explicit cast is required.

31. Operators, operands, and result types

Operations Operators combine or transform operands. Their meaning depends on operand types, promotion rules, and evaluation context. Parentheses can make intended grouping explicit.

int total =
    price * quantity
        + shipping;

boolean valid =
    total > 0
        && customer != null;

Side effects inside expressions

int index = 0;

values[index++] =
    compute();

Compact side-effecting expressions can be legal but difficult to audit. Prefer separate statements when order matters.

33. Assignment operators

int count = 10;

count += 5;
count -= 2;
count *= 3;
count /= 4;
count %= 3;

Assignment is an expression

int left;
int right;

left =
    right =
        10;

Compound assignment includes an implicit conversion

byte value = 10;

value += 5;
// Equivalent in effect to:
// value = (byte) (value + 5);

Compound assignment evaluates the left operand once and includes a cast to the left-hand type. This can silently narrow a result.

34. Comparison and equality operators

boolean less =
    left < right;

boolean atLeast =
    score >= threshold;

boolean sameNumber =
    first == second;

boolean different =
    first != second;

Primitive equality

Numeric operands undergo promotion before comparison. Floating-point NaN compares unequal to every value, including itself.

Reference equality

String first =
    new String("java");

String second =
    new String("java");

assert first != second;
assert first.equals(second);

For references, == tests whether both references are null or refer to the same object. Use equals for logical content equality when the class defines it.

35. Logical and conditional boolean operators

boolean both =
    first && second;

boolean either =
    first || second;

boolean opposite =
    !first;

Short-circuit evaluation

if (customer != null
        && customer.active()) {

    process(customer);
}

The right operand of && is evaluated only when the left operand is true; the right operand of || is evaluated only when the left operand is false.

Non-short-circuit boolean operators

boolean result =
    first & second;

boolean other =
    first | second;

boolean exclusive =
    first ^ second;

With boolean operands, & and | evaluate both sides. Use them only when that behavior is intentional.

36. Bitwise operators

int permissions =
    READ
        | WRITE;

boolean canRead =
    (permissions & READ) != 0;

permissions &=
    ~WRITE;

permissions ^=
    EXECUTE;
OperatorIntegral meaning
&Bitwise AND
|Bitwise OR
^Bitwise exclusive OR
~Bitwise complement

Mask constants

static final int READ =
    1 << 0;

static final int WRITE =
    1 << 1;

static final int EXECUTE =
    1 << 2;

Enums and EnumSet are often clearer than exposed integer masks for application-level permissions.

37. Shift operators

int doubled =
    value << 1;

int signedHalf =
    value >> 1;

int unsignedHalf =
    value >>> 1;
OperatorBehavior
<<Left shift, low bits filled with zero
>>Signed right shift, high bits filled with sign bit
>>>Unsigned right shift, high bits filled with zero

Shift distance masking

int same =
    value << 32;
// For int, distance uses low 5 bits;
// equivalent to shift by 0.

For int, only the low five bits of the shift distance are used; for long, only the low six bits are used.

38. The conditional (ternary) operator

String label =
    score >= passingScore
        ? "pass"
        : "fail";

The conditional operator evaluates its boolean first operand and exactly one of its second or third operands. Its result type is determined from the branch expressions and target context.

Nested conditionals

String category =
    score >= 90
        ? "excellent"
        : score >= 70
            ? "pass"
            : "fail";

Deeply nested ternaries are hard to read; use if or switch when branches need names, statements, or complex logic.

39. The instanceof operator

instanceof tests whether a non-null reference value is compatible with a reference type. Pattern matching can perform the test, cast, and local variable declaration together; this form was finalized in Java 16.[13]

if (value
        instanceof String text) {

    System.out.println(
        text.length());
}

Flow-sensitive scope

if (value
        instanceof String text
        && !text.isBlank()) {

    process(text);
}

Null

Object value = null;

assert !(value
    instanceof String);

A null reference never matches a non-null type pattern.

40. Precedence, associativity, and parentheses

int result =
    2 + 3 * 4;
// 14, because multiplication groups first.

int explicit =
    (2 + 3) * 4;
// 20.

Common precedence order, high to low

  1. Postfix and primary expressions.
  2. Unary operators and casts.
  3. Multiplicative, additive, and shifts.
  4. Relational, equality, bitwise, and logical operators.
  5. Conditional ?:.
  6. Assignment and lambda arrow.

Use parentheses whenever the intended grouping is not immediately obvious. Parentheses improve communication even when the grammar already determines the same result.

41. Control-flow statements

Execution order Control-flow statements choose, repeat, or transfer execution. Java conditions require boolean expressions; there is no implicit “truthiness” conversion from numbers, strings, or references.[6]

Selection

if, switch, switch expressions.

Iteration

for, while, do-while, enhanced for.

Transfer

break, continue, return, throw, yield.

Structure

Blocks and labels delimit targets and scopes.

42. if and if-else

if (temperature < 0) {
    state = "freezing";
} else if (temperature < 20) {
    state = "cool";
} else {
    state = "warm";
}

Dangling else

An else is associated with the nearest preceding unmatched if. Braces make intent explicit.

if (first) {
    if (second) {
        action();
    } else {
        alternative();
    }
}

Guard clause

if (request == null) {
    throw new IllegalArgumentException(
        "request");
}

process(request);

43. switch statements

Arrow-label statement

switch (command) {
    case "start" ->
        start();

    case "stop" ->
        stop();

    case "status" ->
        printStatus();

    default ->
        printUsage();
}

Traditional colon labels and fall-through

switch (month) {
    case 12:
    case 1:
    case 2:
        season = "winter";
        break;

    default:
        season = "other";
}

Colon labels permit fall-through until a transfer statement or switch end. Arrow labels do not fall through and are generally safer for one-action-per-case logic.

44. Switch expressions

Switch expressions, finalized in Java 14, compute a value. Arrow arms produce an expression, throw, or block; a block uses yield to provide the value. A switch expression must be exhaustive.[14]

int days =
    switch (month) {
        case APRIL,
             JUNE,
             SEPTEMBER,
             NOVEMBER -> 30;

        case FEBRUARY ->
            leapYear
                ? 29
                : 28;

        default -> 31;
    };

Block arm

String description =
    switch (status) {
        case READY -> "Ready";

        case FAILED -> {
            auditFailure();
            yield "Failed";
        }
    };

45. Pattern matching in switch

Pattern matching for switch was finalized in Java 21. Case labels can use type and record patterns, guarded conditions, and an explicit case null when desired. Pattern switch expressions and pattern switch statements are exhaustive.[15]

static String describe(
        Object value) {

    return switch (value) {
        case null ->
            "null";

        case String text
                when text.isBlank() ->
            "blank string";

        case String text ->
            "string: " + text;

        case Integer number ->
            "integer: " + number;

        default ->
            "other";
    };
}

46. Basic for loops

for (int index = 0;
        index < values.size();
        index++) {

    process(
        values.get(index));
}

A basic for statement contains optional initialization, condition, and update expressions. Initialization runs once; the condition is tested before each iteration; updates run after the body completes normally or through a matching continue.

Multiple expressions

for (int left = 0,
         right = values.size() - 1;
        left < right;
        left++,
         right--) {

    Collections.swap(
        values,
        left,
        right);
}

Infinite loop

for (;;) {
    if (shutdownRequested()) {
        break;
    }

    work();
}

47. while loops

while (!queue.isEmpty()) {
    Task task =
        queue.remove();

    task.execute();
}

A while loop tests its boolean condition before each iteration. The body may execute zero times.

Sentinel loop

String line;

while ((line = reader.readLine())
        != null) {

    process(line);
}

Avoid hidden non-progress

int index = 0;

while (index < values.size()) {
    process(
        values.get(index));

    index++;
}

Every non-intentionally-infinite loop should have a clear progress measure or external termination condition.

48. do-while loops

int attempts = 0;
boolean accepted;

do {
    attempts++;

    accepted =
        tryOperation();
} while (!accepted
        && attempts < maximumAttempts);

A do-while loop evaluates its condition after the body, so the body runs at least once.

Input prompting

String input;

do {
    input =
        promptUser();
} while (input.isBlank());

Use do-while when one initial execution is inherently required; otherwise while often states the condition more directly.

49. Enhanced for

for (String name : names) {
    System.out.println(name);
}

The enhanced for statement iterates over arrays or instances of Iterable. It is concise when an index or explicit iterator operation is unnecessary.[6]

Array iteration

long total = 0;

for (int value : values) {
    total += value;
}

Loop variable assignment does not replace elements

for (String value : values) {
    value =
        value.strip();
    // Collection elements are unchanged.
}

Structural modification

Do not structurally modify an ordinary collection inside enhanced-for traversal. Use removeIf, an explicit iterator, or collect changes separately.

50. break

An unlabeled break exits the innermost switch, while, do, or for statement. A labeled break exits the named enclosing statement.[6]

for (String value : values) {
    if (value.equals(target)) {
        found = true;
        break;
    }
}

Labeled break

search:
for (int row = 0;
        row < matrix.length;
        row++) {

    for (int column = 0;
            column < matrix[row].length;
            column++) {

        if (matrix[row][column]
                == target) {

            foundRow = row;
            foundColumn = column;
            break search;
        }
    }
}

Labels can clarify rare nested-loop exits, but frequent labeled control flow can indicate that logic should be extracted into a method.

51. continue

An unlabeled continue skips the remainder of the current iteration of the innermost loop. A labeled continue advances the named enclosing loop.[6]

for (String line : lines) {
    if (line.isBlank()
            || line.startsWith("#")) {
        continue;
    }

    parse(line);
}

Labeled continue

rows:
for (int[] row : matrix) {
    for (int value : row) {
        if (value < 0) {
            continue rows;
        }
    }

    processValidRow(row);
}

Guard clauses with continue can reduce nesting, but too many transfer points make loop invariants harder to follow.

52. return

A return statement transfers control to the invoker. A method returning a value must return an expression compatible with its return type; a void method uses return; or reaches its closing brace.[6]

static int absolute(
        int value) {

    if (value >= 0) {
        return value;
    }

    return -value;
}

Early return

static Optional<User> findActive(
        UserId id) {

    User user =
        repository.findNullable(id);

    if (user == null
            || !user.active()) {
        return Optional.empty();
    }

    return Optional.of(user);
}

Finally still runs

A pending return can be delayed by a finally block. Returning from finally is dangerous because it replaces an earlier return value or thrown exception.

53. Complete example: command-line statistics program

Source file

package com.example.stats;

import java.util.ArrayList;
import java.util.List;

public final class Statistics {
    private Statistics() {
    }

    public static void main(
            String[] arguments) {

        if (arguments.length == 0) {
            printUsage();
            return;
        }

        List<Integer> values =
            parseValues(arguments);

        if (values.isEmpty()) {
            System.err.println(
                "No valid integers.");
            return;
        }

        Summary summary =
            summarize(values);

        System.out.printf(
            "count=%d min=%d max=%d "
                + "sum=%d average=%.3f%n",
            summary.count(),
            summary.minimum(),
            summary.maximum(),
            summary.sum(),
            summary.average());
    }

    static List<Integer> parseValues(
            String[] arguments) {

        List<Integer> values =
            new ArrayList<>();

        for (String argument
                : arguments) {

            if (argument.isBlank()) {
                continue;
            }

            try {
                values.add(
                    Integer.parseInt(
                        argument));
            } catch (
                    NumberFormatException
                        failure) {

                System.err.println(
                    "Ignoring invalid integer: "
                        + argument);
            }
        }

        return List.copyOf(values);
    }

    static Summary summarize(
            List<Integer> values) {

        if (values.isEmpty()) {
            throw new IllegalArgumentException(
                "values must not be empty");
        }

        int minimum =
            Integer.MAX_VALUE;

        int maximum =
            Integer.MIN_VALUE;

        long sum = 0;

        for (int value : values) {
            if (value < minimum) {
                minimum = value;
            }

            if (value > maximum) {
                maximum = value;
            }

            sum += value;
        }

        double average =
            (double) sum
                / values.size();

        return new Summary(
            values.size(),
            minimum,
            maximum,
            sum,
            average);
    }

    static void printUsage() {
        System.out.println(
            "Usage: Statistics "
                + "<integer>...");
    }

    record Summary(
        int count,
        int minimum,
        int maximum,
        long sum,
        double average) {
    }
}

Compile and execute

javac \
  --release 25 \
  -d build/classes \
  src/com/example/stats/Statistics.java

java \
  -cp build/classes \
  com.example.stats.Statistics \
  10 20 invalid -5 40

Concepts demonstrated

  • A package declaration, imports, one public class, methods, and a nested record.
  • Declarations, initialization, final design, scopes, and primitive numeric types.
  • Enhanced for, ordinary if, continue, return, arithmetic, comparison, assignment, and casting.
  • long accumulation prevents many ordinary int-sum overflows.
  • A cast to double prevents integral division when computing the average.
  • Invalid text is handled without terminating the entire input scan.

54. Testing language-level behavior

Boundary tests

@Test
void summarizesNegativeAndPositiveValues() {
    Statistics.Summary summary =
        Statistics.summarize(
            List.of(
                -5,
                10,
                20));

    assertEquals(
        -5,
        summary.minimum());

    assertEquals(
        20,
        summary.maximum());

    assertEquals(
        25L,
        summary.sum());

    assertEquals(
        25.0 / 3.0,
        summary.average());
}

Operator tests

  • Integer division and remainder for positive and negative values.
  • Overflow boundaries and checked arithmetic.
  • NaN, infinities, positive zero, and negative zero.
  • Short-circuit branches whose right side must not execute.
  • Signed and unsigned right shifts.
  • Narrowing conversions near minimum and maximum values.

Control-flow tests

  • Zero, one, and many loop iterations.
  • Every if/switch branch.
  • Fall-through where intentionally used.
  • Break, continue, and early-return paths.
  • Null and default cases in pattern switches.

56. Production checklist

Source and syntax

  • Source layout mirrors package structure.
  • Public top-level type and file names match.
  • Identifiers are descriptive and visually unambiguous.
  • Comments explain intent rather than obvious mechanics.
  • Blocks and braces make scopes and branch ownership explicit.

Variables and types

  • Every local is definitely assigned before use.
  • Scope is as narrow as practical.
  • final is used for values that should not be reassigned.
  • Object mutability is not confused with reference finality.
  • Primitive width, range, precision, and overflow behavior fit the domain.
  • Character logic chooses UTF-16 units or Unicode code points deliberately.

Operators

  • Numeric promotion and narrowing are understood.
  • Integer division is intentional.
  • Potential overflow uses bounds checks or exact arithmetic.
  • Logical conditions use short-circuit operators where required.
  • Reference identity and logical equality are not confused.
  • Parentheses make non-obvious grouping explicit.

Control flow

  • if handles genuinely binary or ordered conditions.
  • Switch expressions are exhaustive and return one coherent type.
  • Arrow switch labels are preferred unless fall-through is intentional.
  • Loops have clear initialization, progress, and termination.
  • Enhanced for is used when index/iterator control is unnecessary.
  • Break, continue, and return improve clarity rather than fragmenting flow.
  • Preview features are isolated, documented, and compiled/run with matching flags.
Final principle: Java basics are a system of precise rules rather than isolated syntax. Types constrain values, expressions compute in a defined order, scopes constrain names, statements direct execution, and explicit conversions and control flow make behavior predictable.
